# 分治

分治（Divide and Conquer）是一种算法设计思想：将原问题拆成多个规模更小的同类子问题，分别求解，再利用子问题的结果构造原问题的解。

分治本身没有给出某个具体问题的完整求解步骤。确定如何拆分、如何处理基本情形、如何组合结果后，才能形成具体算法，例如归并排序。

## 1. 基本步骤

1. 分解：将当前问题拆成多个规模更小的同类子问题。
2. 求解：继续用相同方法处理子问题；规模足够小时，直接求解。
3. 合并：根据子问题的结果得到当前问题的结果。

合并不一定是复杂操作。例如，快速排序在划分后分别排序两侧区间，通常不需要像归并排序一样再执行一次线性合并；不同算法的主要工作可能发生在不同阶段。

## 2. 示例：归并排序

对数组 `[4, 1, 3, 2]` 升序排序：

1. 分解为 `[4, 1]` 和 `[3, 2]`。
2. 继续拆分，直到每个子数组只有一个元素，单元素数组天然有序。
3. 将 `[4]` 与 `[1]` 合并为 `[1, 4]`，将 `[3]` 与 `[2]` 合并为 `[2, 3]`。
4. 将两个有序数组 `[1, 4]` 与 `[2, 3]` 合并，得到 `[1, 2, 3, 4]`。

合并两个有序数组时，依次比较两侧尚未处理的第一个元素，取较小者；一侧耗尽后，追加另一侧剩余元素。

这里，分治指导整体结构；归并排序则明确了拆分边界、基本情形和合并规则，是具体算法。

## 3. 与递归、迭代的关系

| 概念 | 所属层次 | 关注的问题 |
| --- | --- | --- |
| 分治 | 算法设计思想 | 如何拆分问题，并利用子问题结果构造解？ |
| 递归、迭代 | 计算过程的组织方式 | 如何执行步骤、保存和更新状态？ |
| 归并排序 | 具体算法 | 如何通过拆分与有序合并完成排序？ |

分治常用递归实现，因为子问题可以重复使用相同的求解过程。但分治不要求必须使用语言的递归调用。例如，自底向上的归并排序使用循环，依次合并长度为 1、2、4 等的有序段，同样体现分治思想。

反过来，使用递归也不一定采用分治。例如，递归求和 `S(n) = n + S(n-1)` 每次只需求解一个规模更小的子问题，通常归为减治。

## 4. 与减治、动态规划的区别

- 减治：将当前问题缩小为一个需要继续求解的同类子问题，再由其结果得到原问题的结果。例如，二分查找每次排除一半范围，只继续搜索其中一侧。
- 分治：典型情形需要分别求解多个子问题，再组合结果。例如，归并排序需要分别排好左右两半。
- 动态规划：关注重叠子问题的结果复用，通过合适的状态定义与转移关系组织计算，避免反复求解相同状态。

典型分治中的子问题通常可以分别求解，不需要依赖彼此的求解结果。如果相同子问题反复出现，应进一步考虑缓存或动态规划。这里的“分别求解”不表示代码一定并行执行，也不要求输入数据完全不重叠。

二分查找有时也被归入广义分治；如果区分分治与减治，应按每次实际需要继续求解的子问题数量判断。

## 5. 复杂度分析

若每次将规模为 n 的问题分成 a 个规模约为 n/b 的子问题，分解和合并等额外工作为 f(n)，可以写出递推式：

```text
T(n) = a × T(n/b) + f(n)
```

归并排序每次处理两个约为原规模一半的子问题，合并工作为 O(n)，因此：

```text
T(n) = 2 × T(n/2) + O(n)
     = O(n log n)
```

直观上，拆分层数为 O(log n)，每层所有合并操作的总工作量为 O(n)。对使用共享辅助数组的常见递归归并排序，辅助数组占 O(n)，调用栈占 O(log n)，总辅助空间为 O(n)。

分治并不保证 O(n log n)。复杂度取决于子问题数量、规模、划分是否均衡，以及分解和合并的成本；空间复杂度还需要考虑同时保留的中间结果和调用栈。

## 6. 使用要点

1. 确认子问题仍属于同一类问题，能够复用求解方法。
2. 明确基本情形，并保证子问题规模持续缩小。
3. 证明子问题覆盖了求解原问题所需的信息，组合结果不会遗漏或重复计算。
4. 分析划分是否均衡，以及分解、合并的成本是否抵消了拆分带来的收益。
