# 算法基础

算法基础整理理解、实现和分析算法时需要的通用概念与操作。递归和迭代是组织计算过程的方式，本身并未给出解决某个具体问题的完整步骤，因此不等同于具体算法；划分等操作则可作为具体算法的组成步骤。

## 1. 计算过程的组织方式

- [递归](Recursion.md)：通过直接或间接调用自身，将当前问题转化为同类子问题，并在基本情形处结束展开。
- [迭代](Iteration.md)：重复执行步骤、更新状态，直到达到结束条件，通常通过循环实现。

同一个求解过程可以有递归和迭代两种实现。例如，计算前 n 个正整数之和，既可以求出前 n−1 个数的和后再加 n，也可以从 1 到 n 逐项累加。

## 2. 递归与迭代的比较

| 比较项 | 递归 | 迭代 |
| --- | --- | --- |
| 过程组织 | 展开函数调用，再返回结果 | 重复执行步骤并更新状态 |
| 状态保存 | 通常由调用栈保存各层的参数和返回位置 | 使用变量，必要时维护显式栈、队列等结构 |
| 终止依据 | 到达基本情形，且调用过程持续向它推进 | 循环条件不再满足，或显式结束循环 |
| 常见风险 | 递归过深、重复计算、无法终止 | 状态更新错误、边界错误、无法终止 |

递归可以通过显式保存调用状态改写为迭代，但转换后不一定能减少辅助空间。时间和空间复杂度取决于具体执行的步骤及保存的状态，不能只根据是否使用递归或循环判断。

## 3. 与算法思想和具体算法的关系

- 算法思想关注如何分析问题、构造解法，例如逆向思维、等价转化。
- 递归和迭代关注如何组织计算、保存和更新状态。
- 具体算法给出解决某类问题的明确步骤，例如二分查找、归并排序。

这些概念可以组合使用。例如，二分查找可以用递归或迭代实现；使用递归也不意味着一定采用了动态规划。
