# 记忆化搜索

记忆化搜索（Memoized Search）是一种结合搜索或递归与结果缓存的求解方法。求解某个状态时，先检查是否已有缓存结果；如果有，直接返回；如果没有，则求解该状态，保存结果后再返回。

在动态规划中，记忆化搜索通常用于实现自顶向下的求解：从目标状态出发，按需求解依赖的子问题，并复用重叠子问题的答案。

## 1. 核心流程

1. 用函数参数描述当前状态。
2. 检查当前状态是否已有缓存结果，命中时直接返回。
3. 对于可以直接求解的基本情形，返回对应结果。
4. 根据状态转移关系，递归求解依赖的状态。
5. 汇总结果，写入当前状态的缓存，再返回结果。

初始状态的结果可以预先放入缓存，也可以通过递归边界直接返回。缓存应记录已经完成求解的结果，不能把“正在计算”当作“已经算出答案”。

## 2. 斐波那契数列示例

定义状态参数 `i` 表示数列中的位置，状态值为 `F(i)`：

```text
F(0) = 0
F(1) = 1
F(i) = F(i - 1) + F(i - 2)，i >= 2
```

直接递归计算 `F(5)` 时，求 `F(4)` 和求 `F(5)` 的不同分支都会需要 `F(3)`。记忆化搜索在第一次求出 `F(3)` 后保存结果，再次遇到时直接返回 2，不再展开它的递归分支。

下面使用 Go 实现。由于结果类型为 `int64`，函数仅接受 `0 <= n <= 92`；超出范围时会触发 `panic`。

```go
func FibonacciMemo(n int) int64 {
    if n < 0 || n > 92 {
        panic("n must be between 0 and 92")
    }

    memo := map[int]int64{
        0: 0,
        1: 1,
    }

    var solve func(int) int64
    solve = func(i int) int64 {
        if value, ok := memo[i]; ok {
            return value
        }

        result := solve(i-1) + solve(i-2)
        memo[i] = result
        return result
    }

    return solve(n)
}
```

`memo` 同时保存状态及其答案，`ok` 用来区分“尚未缓存”和“答案恰好为 0”。缓存定义在函数内部，每次调用独立使用，不会复用其他调用的状态。

## 3. 与动态规划、记忆化的关系

动态规划是一种算法设计方法，记忆化搜索是其常见实现方式之一。对于同一个动态规划模型，记忆化搜索与递推填表可以使用相同的状态定义和状态转移方程。

记忆化（Memoization）是更通用的结果缓存技术，也可以用于普通函数计算，不一定涉及搜索。不能因为一段程序使用了缓存，就认定它是动态规划。

记忆化搜索强调按需搜索并复用状态结果，并不专属于动态规划；但在求解重叠子问题的语境下，通常可以将它理解为自顶向下的动态规划。

## 4. 与递推填表的区别

| 对比项 | 记忆化搜索 | 递推填表 |
| --- | --- | --- |
| 求解方向 | 自顶向下，从目标状态出发 | 自底向上，从初始状态出发 |
| 常见实现 | 递归函数与结果缓存 | 循环与状态表 |
| 计算范围 | 按需求解实际依赖的状态 | 通常遍历预先安排的状态范围 |
| 依赖处理 | 递归进入依赖状态后再返回 | 显式安排满足依赖的计算顺序 |
| 额外开销 | 函数调用、递归栈和缓存查询 | 循环控制和状态存储 |

两者都保存并复用中间结果，但通常将按需查缓存称为记忆化，将按依赖顺序计算状态称为递推填表。保存结果这一共同点，不代表两者是同一种实现方式。

## 5. 复杂度分析

在每个状态完成求解后不再重复计算的前提下，时间复杂度通常按“实际求解的状态数量 × 每个状态的转移代价”估算，还需要考虑缓存查询的开销。

对于上述斐波那契数列示例，在将整数运算和哈希表查询视为常数时间操作的前提下：

- 时间复杂度：O(n)，各状态只展开求解一次。
- 缓存空间：O(n)，保存各状态的结果。
- 递归栈空间：O(n)，最深递归路径的长度随 n 增长。

只计算部分状态，并不意味着一定更快或更省空间。如果大部分状态都需要访问，递推填表可能具有更小的常数开销，也更便于使用滚动数组。

## 6. 适用场景与注意事项

- 状态转移容易用递归描述，且存在重复求解的子问题。
- 状态空间较大，但从目标状态出发实际依赖的状态较少。
- 缓存键必须包含影响答案的全部信息，多维状态不能遗漏必要参数。
- 同一状态的结果必须在当前输入和约束下保持一致；输入变化后，应重建缓存或将相关输入纳入缓存键。
- 不应使用合法答案作为“未计算”的标记，例如直接用 0 表示尚未计算方案数。
- 普通图遍历中的“访问过”不等于“该状态的答案已经求出”，不能仅凭访问标记直接返回结果。
- 状态依赖存在环时，单纯缓存已完成结果不能阻止循环递归，需要额外分析和处理。
- 递归深度较大时，应考虑调用栈限制，必要时改用递推填表或显式栈。
