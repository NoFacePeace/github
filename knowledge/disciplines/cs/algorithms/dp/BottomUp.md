# 自底向上

自底向上（Bottom-Up）是一种求解方向：从可以直接求解的基本情形或初始状态出发，按依赖顺序逐步计算其他状态，最终得到原问题的答案。

在动态规划中，自底向上通常通过递推填表实现。计算某个状态时，它所依赖的结果应当已经可用。

## 1. 核心流程

1. 明确状态定义和状态转移关系。
2. 设置初始状态及不可达状态的表示方式。
3. 根据依赖关系确定状态的计算顺序。
4. 按该顺序计算状态值，并保存后续仍需使用的结果。
5. 从目标状态或相关状态的汇总中取出最终答案。

不必保存所有历史状态。只要不覆盖尚未使用的结果，就可以采用滚动数组等方式压缩存储。

## 2. 斐波那契数列示例

定义 `dp[i]` 表示 `F(i)`：

```text
dp[0] = 0
dp[1] = 1
dp[i] = dp[i - 1] + dp[i - 2]，i >= 2
```

求 `F(5)` 时，先设置初始值，再依次计算：

| 步骤 | 使用的结果 | 得到的结果 |
| --- | --- | --- |
| 初始化 | 数列定义 | `dp[0] = 0`、`dp[1] = 1` |
| 计算位置 2 | `dp[1]`、`dp[0]` | `dp[2] = 1` |
| 计算位置 3 | `dp[2]`、`dp[1]` | `dp[3] = 2` |
| 计算位置 4 | `dp[3]`、`dp[2]` | `dp[4] = 3` |
| 计算位置 5 | `dp[4]`、`dp[3]` | `dp[5] = 5` |

最终答案为 `dp[5] = 5`。如果目标为 `F(0)`，直接返回初始值即可，数组实现也只需初始化实际存在的位置。

## 3. 计算顺序由依赖决定

“自底向上”不等于“数组下标从小到大”。这里的“底”指依赖关系中的基本情形，而不是较小的数值下标。

- 斐波那契数列：当前位置依赖前两个位置，可以按下标递增计算。
- 区间动态规划：较长区间依赖较短区间，通常按区间长度递增计算。
- 0/1 背包：二维模型按物品阶段逐行计算；压缩为一维存储后，容量通常需要倒序遍历。

在压缩后的 0/1 背包中，容量倒序是为了保留上一物品阶段的结果，防止同一件物品被重复使用。这并不改变按物品阶段逐步求解的组织方向。

## 4. 与递推填表的关系

自底向上描述求解方向，[递推填表](Tabulation.md)描述一种常见实现方式。后者通常通过循环，按预先确定的依赖顺序计算并保存状态值。

两者经常一起出现，但不是同义词。判断求解方向，应关注是否从基本情形出发推进计算，而不能只看是否使用了循环或数组。

## 5. 适用场景与注意事项

- 状态范围明确，能够方便地确定满足依赖关系的计算顺序。
- 大部分状态都需要求解，希望避免递归调用及调用栈开销。
- 依赖范围有限，希望通过滚动数组减少存储。
- 按固定范围填表可能计算目标并不需要的状态，应结合实际依赖范围评估开销。
- 初始化必须与状态含义一致，尤其要区分合法的零值与不可达状态。
- 若依赖关系存在循环，不能直接套用普通的一次填表，需要重新分析求解方法。
