# 递推填表

递推填表（Tabulation）是动态规划的一种常见实现方式：从初始状态出发，按照满足依赖关系的顺序计算各个状态值，并保存后续仍需使用的结果，最终得到原问题的答案。

它通常采用自底向上的求解方向。在明确讨论动态规划的语境下，可以简称“递推”，但递推这一概念更宽泛，并非所有递推都是动态规划。

## 1. 核心流程

1. 定义状态及状态值的含义。
2. 根据状态转移关系，确定状态依赖哪些其他状态。
3. 设置初始条件，以及不可达状态的表示方式。
4. 安排计算顺序，保证读取某个依赖状态时，其结果已经可用。
5. 按顺序计算并保存状态值，最后读取或汇总目标答案。

“表”不一定是二维表格，也可以是一维数组或其他适合存储状态结果的数据结构。压缩存储后，也不必保留每个历史状态的值。

## 2. 斐波那契数列示例

定义 `dp[i]` 表示第 `i` 个斐波那契数 `F(i)`：

```text
dp[0] = 0
dp[1] = 1
dp[i] = dp[i - 1] + dp[i - 2]，i >= 2
```

每个位置依赖前两个位置，因此可以按下标从小到大计算。求 `F(5)` 时，先设置初始值，再依次算出 `dp[2] = 1`、`dp[3] = 2`、`dp[4] = 3`、`dp[5] = 5`。

下面使用 Go 实现。结果类型为 `int64`，函数仅接受 `0 <= n <= 92`；超出范围时会触发 `panic`。

```go
func FibonacciTab(n int) int64 {
    if n < 0 || n > 92 {
        panic("n must be between 0 and 92")
    }
    if n < 2 {
        return int64(n)
    }

    dp := make([]int64, n+1)
    dp[1] = 1

    for i := 2; i <= n; i++ {
        dp[i] = dp[i-1] + dp[i-2]
    }

    return dp[n]
}
```

Go 创建的整数切片默认值为 0，因此 `dp[0]` 已经满足初始条件。提前处理 `n = 0`、`n = 1`，也避免了在数组长度不足时访问 `dp[1]`。

## 3. 遍历顺序与初始化

填表顺序由状态依赖决定，不是固定按下标递增：

- 线性状态依赖前面的位置时，通常可以从前向后计算。
- 区间状态依赖较短区间时，通常按区间长度递增计算。
- 0/1 背包的二维模型按物品阶段计算；压缩为一维存储后，容量通常需要倒序遍历，避免重复选择同一件物品。

初始化同样必须符合状态含义。例如，“容量不超过 c 的最大价值”允许选择空集，可以将无物品时的结果设为 0；“恰好装满 c 的最大价值”则不能把所有容量都初始化为可达的零值。

不可达状态应单独表示。若用无穷值作为标记，应避免直接参与运算而引发溢出。

## 4. 与记忆化搜索的区别

| 对比项 | 递推填表 | 记忆化搜索 |
| --- | --- | --- |
| 常见求解方向 | 自底向上 | 自顶向下 |
| 计算组织 | 显式安排满足依赖的计算顺序 | 从目标出发，按需递归求解依赖 |
| 结果存储 | 按计算顺序写入状态表 | 查询缓存，未命中时求解并保存 |
| 计算范围 | 通常遍历预先安排的状态范围 | 通常只求解目标实际依赖的状态 |
| 递归栈 | 常见循环实现不需要递归栈 | 需要考虑递归深度和调用栈 |

两者可以使用相同的状态定义和状态转移方程，也都会保存并复用结果。但通常不把递推填表称为记忆化：记忆化强调按需查缓存，递推填表强调按依赖顺序推进计算。

## 5. 复杂度与空间优化

时间复杂度通常按“实际计算的状态数量 × 每个状态的转移代价”估算。空间复杂度取决于实际保存的状态及其他辅助结构。

对于上述斐波那契数列示例，在将固定宽度整数运算视为常数时间操作的前提下：

- 时间复杂度：O(n)，每个位置只计算一次。
- 辅助空间复杂度：O(n)，使用数组保存从 0 到 n 的结果。

由于计算当前位置只依赖前两个结果，可以改为仅保存两个变量，将辅助空间降为 O(1)。这种滚动存储仍按相同的依赖顺序递推，不改变求解方向。

空间优化前，应检查旧结果何时不再需要。若需要还原具体方案，可能还需要保存额外的决策信息，不能只考虑最终数值。

## 6. 适用场景与注意事项

- 状态范围明确，容易安排满足依赖关系的计算顺序。
- 大部分状态都需要求解，希望避免递归调用及调用栈开销。
- 依赖范围有限，适合通过滚动数组减少存储。
- 不要把“已经分配了存储空间”当作“该状态已经正确求解”，尤其要检查默认零值是否符合问题语义。
- 按固定范围填表可能计算目标不需要的状态，应结合实际依赖评估时间与空间开销。
- 普通一次填表要求依赖结果能按确定顺序获得；存在循环依赖时，需要重新分析求解方法。
- 使用固定宽度整数时，应检查答案范围和中间运算是否溢出。
