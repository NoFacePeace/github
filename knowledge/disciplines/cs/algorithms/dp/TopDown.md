# 自顶向下

自顶向下（Top-Down）是一种求解方向：从原问题或目标状态出发，按需展开依赖的子问题，获得所需结果后，再计算当前问题的答案。

在动态规划中，自顶向下通常通过记忆化搜索实现，保存并复用已求解状态的结果。

## 1. 核心流程

1. 从希望求解的目标状态开始。
2. 如果状态结果已经缓存，直接返回。
3. 如果遇到可以直接求解的基本情形，返回对应结果。
4. 根据状态转移关系，求解当前状态依赖的子问题。
5. 利用子问题的结果计算当前答案，保存后返回。

上述流程是结合记忆化的常见实现。自顶向下这一方向本身不要求使用缓存；没有缓存的递归也可能按此方向展开。

## 2. 斐波那契数列示例

已知：

```text
F(0) = 0
F(1) = 1
F(i) = F(i - 1) + F(i - 2)，i >= 2
```

求 `F(5)` 时，不先安排所有状态的计算顺序，而是从目标开始询问依赖：

```text
求 F(5)，需要 F(4)、F(3)
求 F(4)，需要 F(3)、F(2)
求 F(3)，需要 F(2)、F(1)
求 F(2)，需要 F(1)、F(0)
```

若每次先求 `F(i - 1)`，则首次沿 `F(5)`、`F(4)`、`F(3)`、`F(2)` 展开。到达基本情形后，在返回过程中依次求出：

```text
F(2) = 1
F(3) = 2
F(4) = 3
F(5) = 5
```

使用记忆化后，再次需要 `F(2)`、`F(3)` 等结果时直接读取缓存，不再展开相同子问题。

## 3. 展开方向与返回过程

“自顶向下”描述从目标问题出发组织依赖求解的过程，并不表示原问题的答案最先算出。

实际计算仍然要先得到依赖状态的结果。例如，只有得到 `F(4)` 和 `F(3)`，才能计算 `F(5)`。递归返回时的结果汇总方向，与最初展开依赖的方向相反。

通常可以通过递归实现，也可以使用显式栈保存待求解状态和计算阶段；是否使用语言调用栈不是该方向的定义。

## 4. 适用场景与注意事项

- 从目标出发容易描述依赖关系，但不容易直接写出整体填表顺序。
- 理论状态空间较大，而目标实际依赖的状态较少。
- 记忆化只避免同一状态的重复求解，不保证实际需要的状态一定很少；上述斐波那契数列仍然会涉及从 0 到 n 的状态。
- 缓存键需要充分描述子问题，且不能混淆“尚未计算”和合法的零值结果。
- 递归深度较大时，需要考虑调用栈限制。
- 若依赖关系存在循环，单纯缓存已完成的结果不能避免循环递归，需要额外处理。
