# 状态

状态（State）是动态规划中用于描述和区分子问题的一组信息。在问题输入及状态含义固定的前提下，确定一个状态，就应当确定它对应的子问题。

状态描述“要求解哪个子问题”，状态值记录“这个子问题的答案”。

## 1. 状态、子问题与状态值

以求斐波那契数列为例：

| 概念 | 含义 | 示例 |
| --- | --- | --- |
| 子问题 | 需要解决的具体任务 | 求 `F(3)` |
| 状态 | 描述该任务的信息 | `i = 3` |
| 状态值 | 该任务的答案 | `dp[3] = 2` |

动态规划中常说“定义状态 `dp[i]`”，通常是在同时说明状态参数 `i` 和状态值 `dp[i]` 的含义。阅读或编写状态定义时，应明确区分二者。

## 2. 一维状态示例

对于斐波那契数列，可以定义：

```text
状态参数：i，表示数列中的位置，i >= 0
状态值：dp[i]，表示 F(i)
```

这里只需要一个变量 `i` 就能描述子问题，因此称为一维状态。

初始条件和状态转移为：

```text
dp[0] = 0
dp[1] = 1
dp[i] = dp[i - 1] + dp[i - 2]，i >= 2
```

其中，`i`、`i - 1`、`i - 2` 描述不同的子问题，方程则描述这些子问题的答案之间的计算关系。

## 3. 多维状态示例

对于 0/1 背包问题，仅用容量 `c` 还不足以区分所有子问题，因为可使用哪些物品也会影响答案。可以定义：

```text
状态参数：(i, c)
状态值：dp[i][c]
含义：只考虑前 i 件物品，总重量不超过 c 时，能够获得的最大价值
```

例如，`(3, 5)` 表示只考虑前 3 件物品、容量上限为 5 的子问题。它与 `(2, 5)` 的容量相同，但可选物品范围不同，因此不是同一个状态。

这里有两个状态参数，所以称为二维状态。若共有 `n` 件物品、背包容量为非负整数 `C`，则 `i` 的范围为 `[0, n]`，`c` 的范围为 `[0, C]`，状态总数为 `(n + 1) × (C + 1)`。

## 4. 状态设计原则

### 4.1 信息充分

状态需要包含决定子问题答案和合法转移所必需的信息。对于相同输入，若两段历史被归为同一个状态，就应能够使用同一套子问题定义和转移规则，而不必再查询未记录的历史。

例如，在逐件处理物品的背包模型中，只记录容量、不区分已考虑的物品范围，会混淆不同子问题。

### 4.2 避免冗余

不必保存完整的决策历史，只需保留影响后续计算的信息。可以由现有状态参数推导出的信息，通常不需要再增加一个维度。

增加维度会扩大状态空间。设计时应先保证状态正确，再考虑是否可以合并等价状态或删除冗余信息。

### 4.3 明确状态值含义

状态值可以是最优值、方案数或可行性，不一定是数值最大值。相同的状态参数，配合不同的状态值定义，会形成不同的问题模型。

例如，背包中“重量不超过 `c`”与“重量恰好为 `c`”是不同的子问题定义，不能混用初始条件和不可达状态的处理方式。

两个状态的答案碰巧相同，也不意味着它们可以合并；还需要检查它们的约束和转移关系是否等价。

## 5. 状态与存储的区别

状态是对子问题的描述，数组、哈希表等结构是保存状态值的实现方式。记忆化搜索中的函数参数，也可以用来表示状态。

状态维度不等于实现中数组的维度。例如，0/1 背包的二维状态可以通过滚动数组使用一维存储，但物品阶段 `i` 仍然隐含在外层循环中，并没有从问题模型中消失。

压缩存储时，需要保证所读取的值仍然属于转移所需的阶段，不能覆盖尚未使用的结果。
