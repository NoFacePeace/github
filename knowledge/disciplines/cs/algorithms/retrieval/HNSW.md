# HNSW

HNSW（Hierarchical Navigable Small World，分层可导航小世界图）是一种基于分层邻近图的近似最近邻检索算法，常用于向量检索。它通过沿图探索部分节点，减少距离计算，以更低的查询延迟寻找接近查询向量的结果，但不保证返回精确的最近邻。

## 1. 图结构

- 每个向量对应一个节点，节点之间保存邻居连接。
- 底层包含全部节点，越往上节点越少，上层节点同时存在于下层。
- 节点随机获得最高层级，大多数节点只存在于较低层，少数节点进入更高层。
- 上层用于快速接近目标区域，底层通过更充分的局部搜索收集候选。

小世界图中的局部连接与跨区域连接有助于缩短搜索路径。邻居选择不仅考虑距离，也会通过启发式策略保留不同方向的连接，避免连接全部集中在同一小片区域。

## 2. 查询流程

1. 从最高层的入口节点开始，比较查询向量与当前节点及其邻居的距离。
2. 在上层贪心移动到更接近查询的节点，直到找不到更近的邻居，再以当前节点进入下一层。
3. 到达底层后，维护待探索候选与当前较优结果，逐步扩展有希望的邻居，并记录已访问节点。
4. 达到停止条件后，从保留的结果中选出最接近的前若干个节点。

可以类比为先找到目标附近的城区，再逐步缩小到街道和门牌。算法本身通过向量距离导航，并不显式划分这些地理区域。

底层搜索会保留多个候选，避免只沿单一路径贪心前进。扩大搜索候选范围通常可以提高召回率，但也会增加距离计算与查询耗时。

## 3. 索引构建

1. 为新向量随机选择最高层级。
2. 从当前入口开始，在高于新节点最高层的各层中贪心查找合适的进入位置。
3. 在新节点参与的各层中搜索候选邻居，通过启发式策略选择连接。
4. 添加新节点与邻居之间的连接，并在邻居数量超过限制时进行裁剪。
5. 如果新节点的最高层超过现有最高层，则更新入口节点。

HNSW 支持增量插入，但索引质量可能受到插入顺序、随机层级、数据分布与构建参数影响。删除、更新及并发访问的具体能力取决于实现，部分系统采用删除标记并定期重建索引。

## 4. 常见参数

| 参数 | 作用 | 增大后的常见影响 |
| --- | --- | --- |
| `M` | 控制每个节点保留的邻居连接数量 | 改善图的连通性，但增加内存占用及构建成本 |
| `efConstruction` | 控制构建时搜索和选择邻居的候选范围 | 通常改善索引质量，但增加构建耗时 |
| `efSearch` | 控制查询时保留的搜索候选范围 | 通常提高召回率，但增加查询耗时 |

参数名称及各层连接数量限制因实现而异，例如底层可能允许比上层更多的连接。`efSearch` 与最终返回的结果数量不同，通常至少应达到请求的结果数量；不能将它理解为严格的节点访问次数上限。

提高 `efSearch` 可以改善已有索引的搜索效果，但无法保证弥补构建质量不足。参数应结合数据规模、维度、分布及目标延迟进行评估。

## 5. 优势与局限

- 查询性能：在许多数据集上能够以较少的距离计算获得较高召回率，但效果取决于数据和参数，没有对所有查询都成立的快速搜索保证。
- 内存占用：除向量本身外，还需要保存多层图及邻居连接，规模较大时内存成本明显。
- 构建成本：需要反复搜索、选择和更新邻居，构建通常比简单保存向量更昂贵。
- 过滤条件：严格的元数据过滤可能影响图遍历或导致结果不足，需要结合具体实现评估过滤策略。
- 相关性边界：HNSW 近似查找给定向量空间中的近邻，不负责生成语义表示，也不保证近邻内容能回答用户问题。

## 6. 效果评估

可以用精确近邻检索生成基准结果，比较 HNSW 返回的前 $K$ 个结果与精确前 $K$ 个结果的重合比例，即 Recall@K。同时记录查询延迟、吞吐、索引大小和构建耗时。

调优时，可先确定内存与构建预算，再评估 `M`、`efConstruction` 形成的索引质量，最后通过 `efSearch` 调整查询时的召回率与延迟。近邻召回率只衡量对精确向量结果的覆盖，还需单独评估业务相关性。
