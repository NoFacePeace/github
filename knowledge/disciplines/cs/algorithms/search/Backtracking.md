# 回溯

回溯（Backtracking）是一种通过逐步构造候选解来搜索答案的方法。每次作出一个选择，继续探索；当前分支处理结束或无法满足条件时，返回上一步并撤销选择，再尝试其他分支。

## 1. 核心要素

- 路径：当前已经作出的选择，也是正在构造的部分解。
- 可选项：当前状态下可以继续尝试的选择。
- 约束条件：判断某个选择是否合法，或当前分支是否还有可能得到答案。
- 终止条件：判断是否已经构造出完整解，或当前分支需要结束。

通常将候选解组织成一棵搜索树：节点表示部分解，边表示一次选择，从根到当前节点的路径记录已作出的选择。

## 2. 基本流程

```text
搜索当前状态：
    如果当前路径构成完整解：
        保存答案
        返回

    遍历当前状态下的可选项：
        如果选择不合法，或该分支不可能得到答案：
            跳过
        作出选择，更新路径和相关状态
        搜索下一层状态
        撤销选择，恢复路径和相关状态
```

上面的流程适用于到达完整解后无需继续扩展的情况。子集等问题可能在每一层都记录答案，具体记录时机需要根据题意确定。

## 3. 全排列示例

对于互不相同的数字 `[1, 2, 3]`：

1. 选择 `1`，当前路径为 `[1]`。
2. 选择尚未使用的 `2`，路径为 `[1, 2]`。
3. 选择 `3`，得到完整排列 `[1, 2, 3]`，保存答案。
4. 撤销 `3`，返回路径 `[1, 2]`；这一层没有其他选择，继续撤销 `2`。
5. 在路径 `[1]` 后选择 `3`，再选择 `2`，得到 `[1, 3, 2]`。
6. 继续返回并尝试其他分支，直到枚举全部排列。

可以使用访问标记记录哪些元素已在当前路径中。进入分支时设置标记，退出分支时恢复标记，使同一个元素能够参与其他排列。

## 4. 剪枝与去重

- 剪枝：当某个部分解违反约束，或已经不可能扩展成所需答案时，提前结束该分支。剪枝条件必须保证不会遗漏有效解。
- 去重：当输入包含重复元素时，避免不同选择路径生成相同答案。仅用下标访问标记通常只能防止重复使用同一元素，不能自动消除重复结果。

两者目的不同：剪枝减少无需探索的分支，去重避免同一答案被重复记录。

## 5. 与深度优先搜索、递归的关系

回溯通常采用深度优先搜索的顺序遍历候选解空间，重点在于构造解、尝试选择和恢复状态。普通深度优先遍历不一定需要撤销全局访问标记，而回溯中的标记往往只描述当前路径，需要在返回时恢复。

递归是一种实现方式，回溯也可以通过显式栈实现。使用递归并不意味着一定在使用回溯。

## 6. 复杂度与实现注意

时间复杂度取决于搜索树的规模、每次状态操作的成本，以及保存答案的成本。对于 n 个不同元素的全排列，有 n! 个答案，复制并保存全部答案需要 O(n × n!) 时间和结果空间；不计结果，路径、访问标记及递归栈需要 O(n) 辅助空间。

- 撤销操作需要与选择操作对应，恢复所有会影响后续分支的状态。
- Go 中保存切片路径时，应复制当前内容，避免后续修改影响已保存的答案。
- 查找单个答案时，可以在找到后提前结束；枚举全部答案时，需要继续探索其他分支。
- 搜索深度较大时，还需考虑调用栈空间及递归深度。
