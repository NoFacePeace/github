# FIFO

FIFO（First In, First Out，先进先出）用于淘汰时，是指容量不足时优先移除最早进入的数据。它依据进入顺序，访问已有数据不会改变淘汰顺序。

## 1. 核心思路

- 新数据进入队尾。
- 访问已有数据时，保持原有顺序。
- 容量不足时，移除队首数据。

更新已有数据是否重新入队，需要由具体实现约定；常见的按插入顺序实现会保留其原有位置。

## 2. 示例

假设缓存容量为 3，按“最早进入 → 最晚进入”排列：

| 操作 | 缓存内容 | 说明 |
| --- | --- | --- |
| 访问 A | A | 未命中，加载 A |
| 访问 B | A、B | 未命中，加载 B |
| 访问 C | A、B、C | 未命中，加载 C |
| 访问 A | A、B、C | 命中 A，进入顺序不变 |
| 访问 D | B、C、D | 未命中，淘汰最早进入的 A |

这里假设访问未命中的数据后，会将数据加载到缓存中。

## 3. 常见实现

使用队列维护进入顺序；如果还需要按键快速查询，可以配合哈希表保存数据。

在队列入队、出队为 O(1)，哈希表操作平均为 O(1) 的前提下，查询和写入的平均时间复杂度均为 O(1)，空间复杂度为 O(C)，其中 C 为缓存容量。

## 4. 适用场景与局限

FIFO 适合按进入顺序保留最近一批数据，或对实现简单、维护成本低有要求的场景。

它不考虑访问的近期性和频率，因此即使某个数据刚刚被访问或一直被频繁访问，只要它最早进入，仍可能被淘汰。
