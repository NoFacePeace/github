# LFU

LFU（Least Frequently Used，最不经常使用）是一种淘汰算法：容量不足时，淘汰访问次数最少的数据。它关注访问频率，通常通过累计访问次数进行衡量。

## 1. 核心思路

- 为每个数据维护访问次数。
- 数据被访问后，增加对应计数。
- 容量不足时，优先淘汰计数最小的数据。
- 多个数据的计数相同时，需要额外规定选择规则，例如优先淘汰其中最久未使用的数据。

新数据的初始计数、写入是否增加计数，以及计数是否随时间衰减，都需要由具体实现定义。

## 2. 示例

假设缓存容量为 3，插入时计数为 1，之后每次命中增加 1；同频时淘汰最久未使用的数据。

依次访问 A、B、C、A、A、B 后：

| 数据 | 访问次数 |
| --- | --- |
| A | 3 |
| B | 2 |
| C | 1 |

此时访问并加载 D，淘汰访问次数最少的 C。

## 3. 常见实现

使用键到节点的哈希表、按频次分组的双向链表，以及最小频次记录：

- 哈希表用于查找节点及其计数。
- 每个频次对应一条链表，按访问顺序组织同频节点。
- 访问节点时，将其从当前频次链表移到下一频次链表。
- 淘汰时，从最小频次链表中选择最久未使用的节点。

对于不含计数衰减、每次命中仅增加 1 的标准实现，在哈希表操作平均为 O(1) 的前提下，查询和写入的平均时间复杂度均为 O(1)，空间复杂度为 O(C)，其中 C 为缓存容量。

## 4. 适用场景与局限

LFU 适合热点相对稳定、少量数据持续被高频访问的场景。

累计计数可能使过去的热点长期占据缓存，即使它们近期已不再被访问。实际系统可以引入计数衰减或统计时间窗口，使算法适应热点变化，但这些机制会增加实现与维护成本。
