# 插入

LRU 缓存的插入操作通常使用 `Put(key, value)` 接口。键不存在时新增数据；键已存在时更新值。两种情况都会将该键标记为最近使用。

## 1. 操作流程

### 1.1 更新已有键

1. 在哈希表中查找 `key` 对应的节点。
2. 如果存在，更新节点保存的值。
3. 将节点[移到头部](MoveToHead.md)，然后结束操作。

更新已有键不会增加节点数量，即使缓存已满，也不需要淘汰其他节点。应先判断键是否存在，再决定是否需要淘汰。

### 1.2 插入新键

1. 如果容量为 0，直接结束，不保存新数据。
2. 如果当前节点数量已经达到容量，执行[淘汰尾部](EvictTail.md)，摘除最久未使用的数据节点并删除对应的哈希表记录。
3. 创建保存新键和值的节点，将其插入头哨兵之后。
4. 在哈希表中建立新键到新节点的映射。

这里假设容量固定且非负，操作前节点数量不超过容量，因此插入一个新键最多淘汰一个节点。

## 2. 示例

假设容量为 3，链表从头到尾按“最近使用 → 最久未使用”排列：

```text
初始状态：head ⇄ C ⇄ B ⇄ A ⇄ tail
Put(B, 新值)：更新 B 的值，将 B 移到头部
当前状态：head ⇄ B ⇄ C ⇄ A ⇄ tail
Put(D, 值)：缓存已满，淘汰 A，再将 D 插入头部
最终状态：head ⇄ D ⇄ B ⇄ C ⇄ tail
```

更新 B 不会淘汰 A；只有随后插入新键 D 时才需要释放容量。

## 3. 状态维护

- 每个键最多对应一个数据节点，更新时不应重复创建节点。
- 节点需要保存键，便于淘汰时从哈希表中删除对应记录。
- 删除数据时，同时移除链表节点和哈希表记录；新增时，同时建立二者的对应关系。
- 新增或更新成功后，对应节点都位于头部。
- 容量为 0 时，不保留任何数据，也不能尝试淘汰哨兵。

## 4. 复杂度与注意事项

在哈希表操作平均为 O(1) 的前提下，插入或更新的平均时间复杂度为 O(1)，单次操作的额外空间复杂度为 O(1)。整个缓存最多保存 C 个数据节点，总空间复杂度为 O(C)。

并发实现需要同步保护查找、淘汰和插入等步骤，避免重复插入同一个键、超过容量限制，或使链表与哈希表失去对应关系。
