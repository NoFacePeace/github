# 查询

LRU 缓存的查询操作 `Get(key)` 用于读取指定键的值。命中时还会更新访问顺序，使该键成为最近使用的数据。

## 1. 操作流程

1. 在哈希表中查找 `key` 对应的节点。
2. 如果不存在，返回未命中，不修改链表。
3. 如果存在，将节点[移到头部](MoveToHead.md)：先从当前位置摘除，再插入链表头部。
4. 返回节点保存的值。

如果节点已经位于头部，可以跳过移动。移动只调整节点位置，不改变节点数量，也不需要修改哈希表中的映射。

## 2. 示例

假设链表从头到尾按“最近使用 → 最久未使用”排列，已有三个键：

```text
查询前：head ⇄ C ⇄ B ⇄ A ⇄ tail
Get(B)：返回 B 对应的值
查询后：head ⇄ B ⇄ C ⇄ A ⇄ tail
```

随后查询不存在的 D，返回未命中，链表仍为 B、C、A。`Get` 本身不加载或插入 D。

## 3. 返回结果

接口可以用 `(value, found)` 表示查询结果：

- 命中：返回实际值和 `true`。
- 未命中：返回值类型的零值和 `false`，调用方根据 `found` 判断是否命中。

这样可以避免用 `-1` 等特殊值表示未命中时，与合法数据发生冲突。具体题目或接口已经约定返回值时，应遵循其约定。

未命中后，调用方可以从数据库等数据源加载数据，再写入缓存；这属于查询之外的加载流程。

## 4. 复杂度与注意事项

在哈希表查询平均为 O(1) 的前提下，查询的平均时间复杂度为 O(1)，单次操作的额外空间复杂度为 O(1)。

查询命中会修改链表，因此并发访问时需要同步保护。只有未命中时才完全不改变缓存状态；不能因为接口名为查询，就将整个操作视为只读。
