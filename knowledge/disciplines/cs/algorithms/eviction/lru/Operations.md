# 操作

LRU 缓存的基本操作包括查询、写入和淘汰。下面以“哈希表 + 双向链表”的实现为例：哈希表按键定位节点，链表从头到尾按“最近使用 → 最久未使用”排列。

## 1. 状态约定

- 缓存容量为非负整数 `capacity`。
- 哈希表保存 `key → node`，节点包含键、值以及前驱、后继指针；保留键便于淘汰时删除哈希表记录。
- 链表使用头尾哨兵 `head`、`tail`，哨兵不保存业务数据。
- `head.Next` 是最近使用的数据节点，`tail.Prev` 是最久未使用的数据节点；空链表中两个哨兵直接相连。
- 哈希表中的节点与链表中的数据节点一一对应，节点数量不超过容量。

## 2. 查询

[查询](Query.md)操作 `Get(key)` 用于读取指定键的值。命中后将节点移到链表头部，未命中则保持使用顺序不变。

## 3. 插入

[插入](Insert.md)操作 `Put(key, value)` 用于新增数据，也支持更新已有键。新键在容量不足时先触发淘汰；已有键更新值并移到头部，不增加节点数量。

## 4. 淘汰尾部

[淘汰尾部](EvictTail.md)操作 `evictTail()` 摘除尾哨兵之前的数据节点，并删除哈希表中的对应记录，通常在缓存已满且需要插入新键时触发。空链表不执行淘汰。

## 5. 链表辅助操作

### 5.1 摘除节点

对于已经在链表中的数据节点 `node`，先保存前驱 `prev` 和后继 `next`，再设置：

```text
prev.Next = next
next.Prev = prev
```

摘除后可以清空 `node.Prev` 和 `node.Next`。这里只修改链表，是否删除哈希表记录由具体业务操作决定。

### 5.2 插入头部

对于尚未在链表中的数据节点 `node`，先保存 `first = head.Next`，再设置：

```text
node.Prev = head
node.Next = first
head.Next = node
first.Prev = node
```

### 5.3 移到头部

[移到头部](MoveToHead.md)操作 `moveToHead(node)` 先摘除节点，再将它插入头哨兵之后，供查询命中和更新已有键时使用。它只修改链表顺序，保留哈希表映射。

## 6. 复杂度与注意事项

在哈希表操作平均为 O(1) 的前提下，查询、写入和单次淘汰的平均时间复杂度均为 O(1)；摘除节点、插入头部和移到头部均为 O(1)。缓存最多保存 C 个数据节点，总空间复杂度为 O(C)。

查询命中会修改链表顺序，因此并发实现中也需要同步保护。一次操作应协调哈希表和链表的变更，避免其他操作观察到二者不一致的中间状态。
