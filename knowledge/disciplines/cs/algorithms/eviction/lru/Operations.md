# 操作

LRU 缓存的基本操作包括查询、写入和淘汰。下面以“哈希表 + 双向链表”的实现为例：哈希表按键定位节点，链表从头到尾按“最近使用 → 最久未使用”排列。

## 1. 状态约定

- 缓存容量为非负整数 `capacity`。
- 哈希表保存 `key → node`，节点包含键、值以及前驱、后继指针；保留键便于淘汰时删除哈希表记录。
- 链表使用头尾哨兵 `head`、`tail`，哨兵不保存业务数据。
- `head.Next` 是最近使用的数据节点，`tail.Prev` 是最久未使用的数据节点；空链表中两个哨兵直接相连。
- 哈希表中的节点与链表中的数据节点一一对应，节点数量不超过容量。

## 2. 查询

查询操作 `Get(key)` 用于读取指定键的值。

1. 在哈希表中查找 `key`。
2. 如果不存在，返回未命中，使用顺序保持不变。
3. 如果存在，将对应节点移到链表头部，标记为最近使用。
4. 返回节点保存的值。

接口可以用 `(value, found)` 区分命中与未命中，避免某个合法值与未命中标记冲突。

这里的 `Get` 只查询缓存；未命中后是否从其他数据源加载，由调用方或额外的加载逻辑决定。加载成功后可以通过写入操作放入缓存。

## 3. 写入

写入操作 `Put(key, value)` 用于新增数据或更新已有数据。

### 3.1 更新已有键

1. 从哈希表中找到对应节点。
2. 更新节点保存的值。
3. 将节点移到链表头部，标记为最近使用。

更新已有键不会增加节点数量，即使缓存已满，也不需要淘汰其他节点。

### 3.2 插入新键

1. 如果容量为 0，直接结束，不保留新数据。
2. 如果缓存已满，先淘汰最久未使用的数据。
3. 创建保存键和值的新节点，插入链表头部。
4. 在哈希表中记录 `key → node`。

## 4. 淘汰

淘汰操作移除最久未使用的数据，通常在缓存已满且需要插入新键时触发。

1. 取出尾哨兵之前的数据节点 `tail.Prev`。
2. 将该节点从链表中摘除。
3. 使用节点保存的键，删除对应的哈希表记录。

空链表中没有可淘汰的数据，不能删除哨兵。完成淘汰后，链表和哈希表必须同步移除同一个节点。

## 5. 链表辅助操作

### 5.1 摘除节点

对于已经在链表中的数据节点 `node`，先保存前驱 `prev` 和后继 `next`，再设置：

```text
prev.Next = next
next.Prev = prev
```

摘除后可以清空 `node.Prev` 和 `node.Next`。这里只修改链表，是否删除哈希表记录由具体业务操作决定。

### 5.2 插入头部

对于尚未在链表中的数据节点 `node`，先保存 `first = head.Next`，再设置：

```text
node.Prev = head
node.Next = first
head.Next = node
first.Prev = node
```

### 5.3 移到头部

先摘除节点，再将它插入头哨兵之后。节点的键和值不变，哈希表中的映射也不需要改变。如果节点已经位于头部，可以直接跳过。

## 6. 复杂度与注意事项

在哈希表操作平均为 O(1) 的前提下，查询、写入和单次淘汰的平均时间复杂度均为 O(1)；摘除节点、插入头部和移到头部均为 O(1)。缓存最多保存 C 个数据节点，总空间复杂度为 O(C)。

查询命中会修改链表顺序，因此并发实现中也需要同步保护。一次操作应协调哈希表和链表的变更，避免其他操作观察到二者不一致的中间状态。
