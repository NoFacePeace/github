# 淘汰尾部

`evictTail()` 移除 LRU 缓存中最久未使用的数据。它既摘除链表节点，也删除哈希表中的对应记录，通常在缓存已满且需要插入新键时调用。

## 1. 状态约定

- 链表使用头尾哨兵 `head`、`tail`，从头到尾按“最近使用 → 最久未使用”排列。
- 非空链表中，`tail.Prev` 是最久未使用的数据节点。
- 数据节点保存键，哈希表保存键到该节点的映射。
- 空链表中两个哨兵直接相连，此时不执行淘汰，并返回 `false`；成功淘汰时返回 `true`。

## 2. 操作流程

1. 取出候选节点 `node = tail.Prev`。
2. 如果它是头哨兵，说明链表为空，返回 `false`。
3. 保存节点的前驱，将前驱与尾哨兵连接，摘除该节点。
4. 使用节点保存的键，删除哈希表中的对应记录。
5. 清空被移除节点的前驱和后继指针，返回 `true`。

伪代码如下，其中 `entries` 表示哈希表：

```text
evictTail():
    node = tail.Prev
    if node == head:
        return false

    prev = node.Prev
    prev.Next = tail
    tail.Prev = prev
    delete(entries, node.Key)

    node.Prev = nil
    node.Next = nil
    return true
```

## 3. 示例

```text
淘汰前：head ⇄ C ⇄ B ⇄ A ⇄ tail
操作：evictTail()
淘汰后：head ⇄ C ⇄ B ⇄ tail
```

A 是最久未使用的数据，链表中的 A 节点与哈希表中 A 对应的记录被一同移除。

## 4. 注意事项与复杂度

- 不能删除尾哨兵或头哨兵；淘汰对象是尾哨兵之前的数据节点。
- 只有一个数据节点时，淘汰后需要恢复两个哨兵直接相连的空链表状态。
- 如果实现单独维护节点数量，成功淘汰后还需要将数量减一；以哈希表长度计算数量时无需额外计数。
- 更新已有键不增加节点数量，因此不应触发容量淘汰。
- 容量为 0 时，插入流程应直接结束，不能依赖淘汰操作腾出空间。
- 并发实现中，链表摘除和哈希表删除应处于同一次同步保护之内。

在哈希表删除平均为 O(1) 的前提下，单次淘汰的平均时间复杂度为 O(1)，额外空间复杂度为 O(1)。
