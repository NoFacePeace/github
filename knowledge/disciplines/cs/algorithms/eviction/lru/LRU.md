# LRU

LRU（Least Recently Used，最近最少使用）是一种淘汰算法：容量不足时，淘汰最久没有被访问的数据。它依据最后一次访问时间，而不是累计访问次数。

## 1. 核心思路

LRU 假设最近访问过的数据，接下来更可能再次被访问。

- 访问已有数据后，将它标记为最近使用。
- 写入新数据后，将它标记为最近使用。
- 写入已有数据时，通常也更新它的使用顺序。
- 容量不足时，移除最久未使用的数据。

## 2. 示例

假设缓存容量为 3，按“最久未使用 → 最近使用”排列：

| 操作 | 缓存内容 | 说明 |
| --- | --- | --- |
| 访问 A | A | 未命中，加载 A |
| 访问 B | A、B | 未命中，加载 B |
| 访问 C | A、B、C | 未命中，加载 C |
| 访问 A | B、C、A | 命中 A，更新使用顺序 |
| 访问 D | C、A、D | 未命中，淘汰 B 并加载 D |

这里假设访问未命中的数据后，会将数据加载到缓存中。

## 3. 常见实现

使用[哈希表](../../../data-structures/hash-table/HashTable.md)与[双向链表](../../../data-structures/linked-list/DoublyLinkedList.md)配合：

- 哈希表保存键到链表节点的映射，便于快速定位数据。
- 双向链表维护使用顺序，链表头表示最近使用，链表尾表示最久未使用。
- 命中或更新已有数据时，将节点移到链表头。
- 插入新数据时，在链表头添加节点；容量不足时，删除链表尾节点及其哈希表记录。

在哈希表操作平均为 O(1) 的前提下，查询和写入的平均时间复杂度均为 O(1)，空间复杂度为 O(C)，其中 C 为缓存容量。

具体流程见[操作](Operations.md)，包括查询、写入、淘汰及链表辅助操作。

## 4. 适用场景与局限

LRU 适合具有时间局部性的访问模式，即近期访问的数据较可能再次被访问。

大量只访问一次的数据可能将原本常用的数据挤出缓存，这类批量扫描会降低 LRU 的效果。精确维护访问顺序也有额外开销，并发场景下需要处理顺序更新的同步问题。
