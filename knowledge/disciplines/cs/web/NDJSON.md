# NDJSON

NDJSON（Newline Delimited JSON）是一种用换行符分隔 JSON 值的文本格式，常用于逐条传输记录、日志流和批量数据导出，不限于浏览器或 HTTP 场景。

## 1. 格式与媒体类型

每行是一个完整的 JSON 值，通常使用对象；记录之间用换行符分隔，不需要外层数组，也不在记录之间添加逗号。

```text
{"type":"progress","id":"42","percent":80}
{"type":"progress","id":"43","percent":90}
```

使用 UTF-8 编码，每条记录以 `\n` 结束，解析器也应接受 `\r\n`。一条记录不能格式化为多个物理行；字符串中的换行应写成 JSON 转义序列 `\n`。

通过 HTTP 返回时，常用媒体类型为：

```http
Content-Type: application/x-ndjson
```

多条记录组成的响应整体不是单一 JSON 文档，通常不使用 `application/json`，也不能直接将整个响应交给一次 `JSON.parse()`。

## 2. 流式解析

客户端可以边接收边按行解析，不需要等全部记录到齐，但网络读取的数据块不等于一行：

- 一条记录可能分散在多次读取中，需要缓存未结束的行。
- 一次读取可能包含多条记录，需要逐行处理。
- UTF-8 字符也可能跨块，需要使用支持流式解码的解码器。

解析流程为“字节流 → 增量文本解码 → 按换行符切分 → 对每行执行 JSON 解析”。空行是否忽略应明确约定；响应结束时仍有未以换行结束的数据，应按接口约定处理，不能无条件当作完整记录接受。

## 3. 与 SSE 的区别

| 方面 | NDJSON | SSE |
|---|---|---|
| 消息边界 | 每行一个 JSON 值 | 空行结束一个事件 |
| 内容 | 合法 JSON | UTF-8 文本，可以包含 JSON |
| 常用媒体类型 | application/x-ndjson | text/event-stream |
| 事件类型与标识 | 自行定义 JSON 字段 | 定义了 event、id、retry 等字段 |
| 浏览器支持 | 通常用 fetch 读取并解析 | EventSource 可自动解析并重连，也可用 fetch |

两者都可以通过 HTTP 流式返回。NDJSON 不自带自动重连、恢复位置传递或消息补发机制；SSE 的自动重连依赖 EventSource 等客户端实现，历史补发仍需服务端实现。

## 4. 标识与断线恢复

应用可以在 JSON 对象中携带 `id`，客户端保存最后处理的位置，重新请求时通过 `?after=42` 等约定传递给服务端。服务端查找历史记录并继续发送，应用还需要处理去重和历史过期。

仅增加 `id` 字段不会自动启用续传。自行实现这些规则后，NDJSON 也能实现类似 SSE 的恢复能力，差别主要在格式约定和客户端支持。

持续传输 JSON 记录时，NDJSON 简洁直接；需要标准事件字段或浏览器原生事件接收和重连能力时，SSE 更方便。两者都用 fetch 接收时，主要区别是解析规则和事件语义。
