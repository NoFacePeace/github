# 抽象语法树

AST（Abstract Syntax Tree，抽象语法树）用树结构表示源码中的语法构造及其关系。节点通常表示变量、字面量、运算、声明和函数调用等结构，供编译器或代码分析工具继续处理。

## 1. 结构示例

表达式 `a + b * 2` 可以表示为以下简化的 AST：

```text
加法
├── 标识符 a
└── 乘法
    ├── 标识符 b
    └── 整数字面量 2
```

加法节点的右侧子节点是整个乘法表达式，表达了 `b * 2` 作为加法操作数的关系。运算符的优先级已经体现在树结构中。

如果源码是 `(a + b) * 2`，树结构则变为：

```text
乘法
├── 加法
│   ├── 标识符 a
│   └── 标识符 b
└── 整数字面量 2
```

即使树中没有单独的括号节点，括号对表达式分组的影响仍然保留。

## 2. 抽象的含义

“抽象”指省略部分只服务于源码书写的语法细节，突出后续分析需要的结构。例如，分号和部分括号可以不作为独立节点保留，但它们对语句边界或表达式分组的影响会反映在树中。

具体保留哪些节点由实现决定。有些 AST 会保留括号表达式、注释或源码位置，因此 AST 并不是一种节点格式完全统一的数据结构。

## 3. 与 CST 的区别

| 方面 | AST：抽象语法树 | CST：具体语法树 |
| --- | --- | --- |
| 关注点 | 程序的主要语法构造与关系 | 更具体的语法结构 |
| 语法细节 | 通常省略部分分隔符等细节 | 通常保留更多关键字、标点和分隔符 |
| 常见用途 | 语义分析、代码转换和代码生成 | 编辑器支持、源码查询和保留语法细节的处理 |

两者的用途存在交集，实际能力取决于具体实现。Tree-sitter 通常生成 CST，Go 标准库中的 `go/ast` 则提供 Go 的 AST。

语法树也不一定保存原始源码全文。节点可以记录字节范围和行列位置，再由使用方结合原始源码提取文本。

## 4. 用途与能力边界

AST 可以用于识别函数声明和调用、进行静态检查、重构代码，以及支持后续的中间表示构建和代码生成。

但语法结构本身不代表完整的语义信息。例如，调用节点 `SaveOrder(id)` 可以表达被调用名称和参数结构；它对应哪个声明、参数类型是否正确，仍需要名称解析和类型检查等进一步分析。AST 的一些实现会附加这些分析结果。
