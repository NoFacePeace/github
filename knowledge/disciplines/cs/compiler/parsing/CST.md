# 具体语法树

CST（Concrete Syntax Tree，具体语法树）用树结构表示源码的具体语法构造，通常保留运算符、关键字、括号和分隔符等信息。节点体现语法规则及其组成元素，便于工具把语法结构对应到原始源码。

## 1. 结构示例

表达式 `(a + b) * 2` 可以表示为以下简化的 CST：

```text
二元表达式
├── 括号表达式
│   ├── 左括号 (
│   ├── 二元表达式
│   │   ├── 标识符 a
│   │   ├── 运算符 +
│   │   └── 标识符 b
│   └── 右括号 )
├── 运算符 *
└── 整数字面量 2
```

树中既包含表达式的嵌套关系，也保留了括号和运算符。实际的节点名称、层级和可见性由具体解析器及语言语法决定。

## 2. 与 AST 的区别

AST（抽象语法树）通常省略部分具体语法细节，突出操作与结构。上面的表达式可以抽象为：

```text
乘法
├── 加法
│   ├── 标识符 a
│   └── 标识符 b
└── 整数字面量 2
```

这里不再单独保留括号节点，但括号对表达式分组的影响仍然体现在树中。乘法和加法节点也直接表达了操作类型。

CST 和 AST 的区别不能简单理解为“有无源码位置”或“有无括号节点”：AST 也可以保留这些信息。两者主要区别在于抽象程度，具体边界取决于实现。

## 3. 源码保留与位置

具体语法树不一定保存全部空白、注释或原始文本，也不一定单凭树就能逐字还原源码。是否完整保留这些信息，需要检查具体实现。

节点通常可以携带字节范围和行列位置，工具结合原始源码即可提取节点对应的文本。即使某些字符没有独立节点，也可能通过源码范围取得。

## 4. 用途与能力边界

CST 常用于语法高亮、结构化选择、源码查询和代码编辑。保留较多具体语法信息，也有助于代码转换时识别括号、分隔符等位置；保持原有格式还需要额外处理空白和注释。

Tree-sitter 通常生成 CST。其节点可以区分命名节点与匿名节点：标识符、表达式等常作为命名节点，部分标点或关键字作为匿名节点。只查看命名节点时，看到的树会省略一部分具体语法信息。

CST 提供语法结构，本身不自动完成类型检查、跨文件符号绑定或运行时行为分析。错误恢复型解析器也可能为不完整源码生成带错误或缺失节点的树，使用方需要按用途检查这些节点。
