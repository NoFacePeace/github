# 目标漂移

目标漂移（Goal Drift）在本文中指 AI 在对话或任务执行过程中，逐渐偏离当前有效的任务目标、约束或完成标准的现象。它可能表现为回答偏题、遗漏要求、擅自扩大范围，或持续执行中间步骤却没有完成实际交付。

长上下文是可能的诱因之一，但不是定义条件。普通模型问答和多步执行的 Agent 都可能出现目标漂移。

## 1. 定义与表现

判断是否漂移，需要对照当前有效的目标、约束和验收条件，而不能只看回答是否流畅、执行了多少步骤。

| 表现 | 示例 |
| --- | --- |
| 回答偏题 | 用户要求解释错误原因，回答却主要介绍无关背景 |
| 遗漏约束 | 用户要求兼容旧版本，最终方案却依赖新版本特性 |
| 擅自扩大范围 | 用户要求修复登录问题，执行过程中转而重构整个认证模块 |
| 中间步骤取代目标 | 持续读日志和整理计划，却没有实施修复或验证结果 |
| 沿用过期要求 | 用户已经放弃某个方案，后续仍继续按该方案执行 |
| 错用完成标准 | 将“代码已修改”当成“原问题已解决”，未检查实际效果 |

用户明确修改需求后，应以更新后的目标和约束为准。根据新证据调整计划、执行必要的前置步骤或合理停止，并不自动构成目标漂移；关键是这些行为是否仍服务于有效目标。

## 2. 与其他问题的区别

- **AI 幻觉**：关注内容是否真实或得到依据支持；目标漂移关注输出和行动是否符合任务要求。回答可能事实正确却完全偏题，两种问题也可能同时出现。
- **执行失败**：方向正确，但因工具报错、权限不足或外部故障未能完成。失败本身不等于漂移；忽略失败并转而处理无关事项，则可能发生漂移。
- **上下文容量不足**：输入达到窗口限制后，系统可能报错、截断或压缩。目标漂移也可能在未达到容量上限时发生。
- **需求歧义**：缺少判断方向所需的信息，需要澄清。不能仅凭结果与用户预期不一致，就断定模型忘记了目标。

## 3. 产生原因

- **目标与验收标准不清楚**：只给出“优化一下”“继续处理”等要求，缺少具体交付结果。
- **上下文信息混杂**：大量日志、无关资料、旧方案和临时假设混在一起，模型未能正确识别当前有效要求。
- **长上下文利用不足**：即使关键信息仍在输入中，模型也可能未能正确提取或持续遵循它；可接收更多内容不等于能可靠利用所有内容。
- **上下文处理丢失信息**：历史裁剪、截断、摘要或检索遗漏，导致目标、限制和关键决策没有进入后续输入。
- **任务状态维护不足**：未区分已完成、待办、受阻和待验证事项，恢复执行时重复旧步骤或沿用过期状态。
- **缺少结果检查**：系统只检查步骤是否执行，或接受模型自报“完成”，没有对照实际验收证据。

这些原因可能共同作用。不能仅凭对话很长就认定是窗口容量不足，也不能仅凭模型跑偏就排除应用上下文管理的问题。

## 4. 减少目标漂移的方法

### 4.1 明确目标、约束和完成标准

把任务写成可检查的结果，并说明范围。例如：

```text
目标：修复登录接口返回 500 的问题。
约束：保持现有接口兼容，修改限于与故障直接相关的代码。
完成标准：原失败场景恢复正常，相关测试通过，并说明验证结果。
```

用户调整需求后，同步更新这些内容，并标明哪些旧要求已经失效。

### 4.2 维护任务状态

长任务应维护简短、可更新的任务记录，至少包含：

- 当前有效的目标、约束与验收条件。
- 已完成事项及其验证证据。
- 关键决策、失败尝试及原因。
- 待办、阻碍和下一步行动。

记录可以保存在文件、结构化状态或数据库中。恢复执行时，需要把相关状态重新提供给模型；仅保存到外部位置而不读取，无法帮助后续执行。

### 4.3 管理上下文并重新确认任务

通过[上下文管理](../agent/knowledge/context/management/Management.md)选择相关资料、减少重复输出，并保留当前要求和必要证据。

- 日志和文档优先提供与当前问题相关的部分，保留原文位置以便补查。
- 摘要中保留目标、约束、当前进度和验收证据，不只总结讨论过的话题。
- 在阶段切换、摘要压缩或恢复执行后，重新核对任务状态。
- 对相互独立的任务使用不同对话；已有对话反复跑偏时，可核对交接摘要后再开启新对话。

新对话不会自动继承全部历史。摘要中未保留的细节，应通过原始记录或文件重新获取。

### 4.4 检查行动与实际结果

在关键步骤前判断该行动如何服务于目标；阶段结束后，对照验收条件检查剩余工作。最终检查实际产物、测试结果或外部状态，不能仅以“计划执行完毕”作为完成依据。

发现漂移后，暂停无关工作，重新确认有效要求，检查已经产生的改动，再从当前实际状态继续。已产生的错误结果不会因为重新提示目标而自动消失，需要单独纠正。

## 5. 纠偏提示示例

```text
当前有效目标：……
必须遵守的约束：……
完成标准：……
已确认的状态与证据：……
已失效的要求或方案：……

请根据已有记录核对任务状态，区分已完成、待验证和未完成事项。
指出当前工作与目标的偏差，停止无关扩展，并继续下一项必要行动。
结束前对照完成标准验证，说明实际结果和仍未确认的部分。
```

该提示用于重新明确任务，不能代替缺失的事实、工具结果或验证过程。

## 6. 质量归属与能力边界

目标漂移属于 AI 质量与可靠性问题，但具体改进位置取决于原因：

- 目标和约束明确且仍在输入中，模型却未能遵循，主要涉及模型的理解、指令遵循与目标保持能力。
- 应用丢失关键历史、提供过期状态或遗漏必要资料，主要涉及上下文与任务状态管理。
- 需求不明确或相互冲突，需要澄清；系统也应识别歧义，避免未经确认地沿错误方向继续。

评估时可检查验收条件满足情况、约束违反情况、无关行动及重复执行情况，并比较上下文压缩、恢复执行和需求变更前后的表现。需要检查实际输入和执行记录，不能只依靠模型自述来归因。

提示词、状态记录、上下文压缩和更大的上下文窗口可以改善表现，但都不能保证完全消除漂移。用户重申目标是缓解手段，不意味着用户有义务反复提醒，或应承担系统未遵循明确要求的责任。
