# Agent 事件

事件（Event）是 Agent 运行过程中产生的结构化记录，用来描述消息增量、工具执行和任务状态变化等信息。事件流将这些记录按约定的顺序提供给客户端或其他消费者。

## 1. 常见事件

| 类型 | 示例 |
|---|---|
| 消息 | 回答开始、文本增量、回答结束 |
| 工具 | 调用开始、执行输出、调用成功或失败 |
| 任务状态 | 已创建、运行中、等待输入、已完成、失败、已取消 |
| 产物 | 文件生成、结果更新 |

事件名称和结构由应用或平台定义，没有统一的 Agent 事件格式。

## 2. 事件结构与顺序

事件通常包含任务标识、事件标识或序号、类型、时间及数据。会话标识用于关联交互，运行标识用于区分具体执行过程。

```json
{
  "run_id": "run_123",
  "id": 42,
  "type": "tool.completed",
  "data": {
    "call_id": "call_7",
    "result": "订单查询成功"
  }
}
```

应明确编号的唯一性和顺序范围，例如仅保证同一次运行内递增。并行工具调用还需要调用标识进行关联，不能只靠时间戳判断执行依赖。

## 3. 订阅与推送

长任务可以采用以下接口设计：

1. 客户端通过 POST 创建任务，服务端返回运行标识。
2. 后台继续执行任务，保存状态与事件。
3. 客户端通过 GET 接口订阅 SSE 事件流。
4. 补充消息或取消任务通过单独的请求完成。

SSE 是传递事件的 HTTP 机制，事件是传递的内容。也可以通过 WebSocket 推送事件，或在 POST 响应中直接流式返回。

## 4. 断线与恢复

- 后台任务与订阅连接分别管理；订阅断开不应被隐式当作取消任务。
- 服务端保存事件历史，按客户端提供的位置补发，再接续实时事件，避免交接期间遗漏。
- 客户端按事件标识去重；接收事件不自动保证业务处理恰好执行一次。
- 同一个浏览器 EventSource 对象自动重连时，可通过 `Last-Event-ID` 请求头传递最后的事件编号。
- 页面刷新后，应用需自行恢复运行标识和事件位置，例如从本地存储读取，再通过约定的 `after` 参数订阅。
- 若同时支持请求头和查询参数，可约定优先采用请求头，避免自动重连时反复使用 URL 中的旧位置。
- 历史事件过期时，应明确告知客户端，并提供任务当前状态与结果的查询方式。

事件续传解决消息传输恢复；执行进程崩溃后的任务恢复，还需持久化运行状态、检查点及工具操作的幂等控制。
