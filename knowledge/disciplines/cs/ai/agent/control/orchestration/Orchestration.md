# Agent 编排

Agent 编排是将一个目标拆成任务，安排 Agent 与工具执行，并管理任务之间的依赖、数据传递和结果汇总的机制。编排可以控制单个 Agent 的执行流程，也可以协调多个 Agent。

## 1. 核心职责

| 职责 | 需要解决的问题 |
|---|---|
| 任务拆分 | 如何将目标划分为可执行、可验证的子任务 |
| 分工与路由 | 哪个 Agent 或工具适合处理当前任务 |
| 调度 | 哪些任务可以并行，哪些必须等待前置结果 |
| 上下文与数据传递 | 各任务需要什么输入，结果如何交给后续任务 |
| 结果汇总与验证 | 如何合并结果、处理冲突并判断目标是否完成 |
| 生命周期与失败恢复 | 如何处理超时、重试、取消、预算和状态恢复 |

## 2. 常见模式

### 2.1 顺序执行

后续任务依赖前一个任务的输出，例如先检索资料，再分析，最后撰写报告。

```text
检索 → 分析 → 撰写 → 验证
```

### 2.2 并行执行与汇总

将相互独立的任务同时分配给多个 Agent，等待结果后汇总。适用于分析多份文档、检查不同模块等场景。

```text
          ┌→ Agent A ─┐
任务拆分 ─┼→ Agent B ─┼→ 汇总与验证
          └→ Agent C ─┘
```

并行执行需要控制并发数量，并明确共享文件或状态的写入责任，避免相互覆盖。

### 2.3 路由与分支

根据任务类型或中间结果选择执行路径，例如将安全问题交给安全审查 Agent，将部署问题交给基础设施 Agent。

### 2.4 执行与复核循环

一个 Agent 产出结果，另一个 Agent 或确定性检查程序复核；未通过时修订后再次检查。应设置终止条件、最大轮数或预算，避免无限循环。

## 3. 谁控制流程

### 3.1 预先编写的工作流

开发者提前定义步骤、依赖、分支与汇总逻辑，Agent 在指定步骤中处理任务。流程结构主要由程序控制。

### 3.2 Agent 逐步调度

主 Agent 根据任务委派子任务，读取结果后决定下一步，必要时向 [Subagent（子智能体）](Subagent.md) 发送后续要求。主 Agent 持续参与流程决策。

### 3.3 Agent 生成编排程序

主 Agent 根据任务生成工作流程序，再交给执行引擎运行。程序负责调用 Agent、收集输出、传递结果，并执行分支或循环；结束后由主 Agent 读取结果并回复用户。

```text
用户任务
   ↓
主 Agent 生成工作流程序
   ↓
执行引擎运行程序 → 调用多个 Agent
   ↑                      ↓
   └────── 返回子任务结果 ──┘
   ↓
汇总结果 → 主 Agent 回复用户
```

Claude Dynamic Workflows 是这一模式的具体产品实现。其官方文档说明程序由 Agent 生成、服务端后台执行，但未公开完整的底层调度器实现。以下代码仅用于说明通用编排逻辑，不是其官方 API：

```python
results = await parallel([
    run_agent("分析文档 A"),
    run_agent("分析文档 B"),
])
review = await run_agent("复核分析结果", input=results)
return await run_agent("汇总报告", input=review)
```

## 4. 与执行环境的关系

编排层决定谁执行什么、何时执行，以及结果如何流转。执行环境承载命令、文件、浏览器等实际操作，两者可以分别设计。

多个 Agent 可以共享同一个执行环境，也可以使用独立环境。独立对话上下文不等于文件系统或进程隔离；具体隔离边界由运行平台和沙箱配置决定。

## 5. 工程设计要点

- 明确任务输入、输出与完成条件，便于汇总和验证。
- 区分可重试任务与有副作用的操作，避免重复执行导致重复写入。
- 设置并发、时间、Token 和费用限制。
- 记录任务状态、依赖关系和执行事件，支持追踪与恢复。
- 为失败、部分成功、取消和结果冲突定义处理方式。
- 验证最终产物；工作流执行结束不一定意味着任务目标已达成。

## 6. 执行方式与协作结构

### 6.1 执行方式

- [Workflow（工作流）](Workflow.md)：通过显式定义的步骤、依赖和分支组织执行。
- [ReAct（推理与行动）](ReAct.md)：根据观察结果交替推理和行动，逐步决定下一步。
- [Plan-and-Execute（规划与执行）](PlanAndExecute.md)：先生成任务计划，再执行并按需重新规划。
- [Reflection（反思）](Reflection.md)：审查已有结果，根据反馈修正产出或执行方式。

这些方式可以组合：工作流中的某个步骤可以调用采用 ReAct 的 Agent；Agent 可以先生成计划，再在每一步中交替推理和行动，最后反思并修正结果。

Workflow 与 Plan 的主要区别是流程来源：前者强调显式流程结构，后者强调为当前任务制定的具体步骤。工作流可以预先编写，也可以由 Agent 动态生成，因此不能简单按“静态”和“动态”完全区分。

### 6.2 协作结构

- **单 Agent**：由一个 Agent 组织任务并调用工具，也可以采用规划、反思等方式。
- **多 Agent**：多个 Agent 分工，例如规划、执行和审查；可以顺序执行，也可以并行执行。

Agent 的数量与执行方式是不同维度。多 Agent 系统中的各个 Agent 可以分别使用 ReAct 或 Plan-and-Execute；反思也不要求必须由另一个 Agent 完成。
