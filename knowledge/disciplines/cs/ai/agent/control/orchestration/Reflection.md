# Reflection

Reflection（反思）是审查已有产出或执行过程，并根据反馈修正结果、计划或后续行动的机制。通俗理解是“做完检查，发现问题再改”。

## 1. 基本过程

```text
产生结果 → 审查与反馈 → 满足要求：交付
                ↓
            发现问题 → 修正 → 再次审查
```

例如，Agent 修改代码后检查需求是否全部覆盖，再结合测试结果修复遗漏。反馈可以来自自身审查、另一个 Agent、用户或测试等外部检查。

## 2. 与其他执行方式的关系

反思可以叠加在 ReAct、Plan-and-Execute 或工作流上，并不要求单独开启一种互斥的模式，也不要求必须采用多 Agent。

观察工具结果是获取反馈；反思更强调对已有结果进行评价，指出差距并形成修正方向。实际系统中两者可能发生在同一个循环中。

## 3. 使用边界

模型自我评价不保证正确，应尽量结合可验证的证据，例如测试结果、事实来源或明确的验收条件。需要设置最大修正轮数或预算，避免无限重复审查。
