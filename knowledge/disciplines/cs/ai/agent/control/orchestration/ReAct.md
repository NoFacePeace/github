# ReAct

ReAct 将推理（Reasoning）与行动（Acting）结合：Agent 根据当前信息决定行动，获取工具或环境反馈后，再决定下一步。通俗理解是“想一步，做一步，看结果，再继续”。

## 1. 基本循环

```text
分析当前信息 → 选择行动 → 执行工具 → 观察结果
      ↑                               ↓
      └──────── 需要继续时 ─────────────┘
                                      ↓
                                满足结束条件：回复
```

例如，排查登录报错时，Agent 先读取日志；发现数据库连接超时后，再检查连接配置；修改配置后运行验证，再依据结果决定是否继续。

## 2. 与执行模式的区别

Agent / Execute 是用户选择的产品工作模式；ReAct 是内部组织推理与行动的方式。执行模式可以采用 ReAct，但两者不是同义词。

界面不一定展示推理过程，显示“思考中”也不足以证明系统采用了 ReAct。理解这一方式时，重点是行动是否结合环境反馈逐步调整。

## 3. 使用特点

适合需要探索、无法提前确定全部步骤的任务。应通过完成条件、步数、时间或费用预算限制循环；工具失败也需要有重试、调整或停止的处理方式。
