# Workflow

工作流（Workflow）通过显式定义的步骤、依赖、分支和循环组织任务。执行引擎按流程推进，模型或 Agent 可以承担其中的部分步骤。

## 1. 基本过程

```text
收集报错 → 分析原因 → 修改代码 → 运行测试
                                    ↓
                              通过：交付结果
                              失败：返回修改步骤
```

这里不仅定义了要做什么，也定义了执行顺序、失败后的路径和结束条件。工作流不一定是固定的直线流程，可以包含条件分支、并行任务和重试。

## 2. 与 Plan 的区别

| 对比项 | Workflow | Plan |
|---|---|---|
| 主要含义 | 组织执行的显式流程结构 | 针对当前任务制定的具体计划 |
| 常见来源 | 开发者预先编写，也可由 Agent 生成 | Agent 根据需求和调查结果制定，也可由用户提供 |
| 示例 | 规定分析、修改、验证及失败回退路径 | 先查数据库配置，再检查超时处理，最后补充验证 |
| 如何推进 | 执行引擎按照流程规则推进 | 由 Agent 或执行器解释计划并执行 |

两者可以结合：工作流安排“调查 → 规划 → 执行 → 验证”，其中规划步骤针对当前任务生成计划。计划也可以进一步转成可执行的工作流程序。

## 3. 适用场景

适合步骤较稳定、需要重复执行或明确控制分支的任务，例如文档处理、代码检查和审批流程。对于难以预先列举的情况，可以在流程中的某些步骤交给 Agent 动态决策。
