# Agent 工作模式

工作模式是产品提供给用户的操作入口，用于表达希望 Agent 回答问题、制定计划还是执行任务。Ask、Plan、Execute 和 Edit 是常见名称，不同产品的名称与行为可能不同。

## 1. 常见模式

| 模式 | 主要用途 | 常见操作范围 |
|---|---|---|
| Ask（问答） | 解释概念、分析代码、提供建议 | 回答问题，部分产品允许检索或读取项目 |
| Plan（规划） | 调研需求、分析方案、列出实施步骤 | 通常暂不实施改动，部分产品会保存计划文件 |
| Agent / Execute（执行） | 修改文件、运行命令、检查结果 | 在授权和工具能力范围内执行任务 |
| Edit（编辑） | 根据明确要求修改指定内容 | 通常聚焦用户指定的文件或代码范围 |

这些名称不是统一标准。具体能否读写文件、运行命令或自动继续，需要结合产品说明、工具能力和权限设置判断。

## 2. 使用方式

复杂任务可以采用“Ask 理解问题 → Plan 确定方案 → Execute 实施”的过程；需求明确、范围较小的任务也可以直接执行。

例如，修复登录报错时，Ask 用于解释报错，Plan 用于调查原因并提出修复步骤，Execute 用于修改代码和验证结果。

## 3. 与执行方式和权限的区别

Plan 模式通常只要求给出方案；Plan-and-Execute 则包含执行计划的过程。Execute 模式的内部可以采用 ReAct、Plan-and-Execute，也可以组合其他方式。

自动批准与逐次确认决定操作是否需要人工确认；沙箱决定操作可访问的环境和资源。进入执行模式不等于获得不受限制的权限。
