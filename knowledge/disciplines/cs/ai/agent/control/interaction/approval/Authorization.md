# 授权范围

批准产生的授权应明确允许什么操作、针对哪些资源，以及有效多久。授权用于放行当前操作，也可能在满足条件时被后续操作复用。

## 1. 授权对象

| 对象 | 示例 |
| --- | --- |
| 工具调用 | 允许调用某个工具或执行本次调用 |
| 命令 | 允许执行特定程序及参数范围内的命令 |
| 文件资源 | 允许读取或修改指定文件、目录 |
| 网络资源 | 允许指定进程或执行环境访问网络，或连接指定目标 |
| App | 允许 Computer Use 访问指定应用 |

这些对象可能同时受约束。批准工具调用不代表同时允许联网，获得 App 访问授权也不代表其中所有敏感操作都无需确认。

## 2. 有效范围

| 范围 | 含义 |
| --- | --- |
| 单次 | 仅放行指定调用，不能用于后续调用 |
| 当前运行或 Run | 在产品定义的本次执行范围内有效 |
| 当前会话 | 在产品定义的会话范围内有效，可能覆盖多轮消息 |
| 工作区或任务 | 在指定工作区或任务内，按规则复用 |
| 持久授权 | 保存后可跨运行或会话复用，直到失效或撤销 |

以上是可能的设计，不代表所有系统都支持这些范围。Run、会话和工作区的边界需要由产品明确，不能把当前一轮执行等同于整个聊天会话；授权范围也不等同于沙箱边界。

## 3. 匹配与失效

复用授权时，运行时检查本次操作是否符合授权对象、动作、参数、资源范围和有效期。超出范围、授权过期、被撤销或策略要求重新确认时，应重新判断是否需要审批。

恢复执行前还需核对操作与获批内容是否一致，并满足当前其他权限约束。不能仅凭相同工具名，就认为不同参数和目标都已获授权。

## 4. 保存方式

| 范围 | 常见保存位置 |
| --- | --- |
| 单次 | 调用状态，关联调用 ID |
| 当前运行或会话 | 运行状态、会话状态或数据库记录 |
| 持久授权 | 配置文件、规则文件或数据库 |

存入数据库不等于永久有效，授权范围由记录中的约束决定。进程内存中的授权也可能在重启后丢失，需要明确恢复行为。

## 5. 授权与审批日志

授权用于决定当前或后续操作能否执行；审批日志用于记录请求、决定、理由和执行结果。批准和拒绝都可以记入日志，但拒绝不产生允许执行的授权，保存批准日志也不代表一定支持复用。

批准表示允许执行，不代表操作已经执行或执行成功。
