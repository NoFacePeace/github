# 审批规则

审批规则规定哪些操作在什么条件下需要审批。它参与执行前的权限判断；权限规则还可以直接允许或拒绝操作，因此并非所有权限规则都是审批规则。

## 1. 判断结果

系统根据操作、配置规则及已有授权，判断本次操作如何处理：

| 结果 | 处理方式 |
| --- | --- |
| 允许 | 在允许的权限范围内执行 |
| 拒绝 | 不执行该操作 |
| 需要审批 | 创建审批请求，等待决定 |

这里的结果是通用概念，不要求所有系统使用相同字段或取值。多条规则冲突时，如何合并由系统定义；某一层允许不代表其他层的限制也被解除。

## 3. 调用前检查

检查器读取工具名和影响权限的参数，例如文件路径、收件人、命令内容或目标 App，再匹配规则。不需要对所有参数采用相同检查；不同工具可以提取各自的动作和资源，交给统一判断层处理。

命令和脚本可能间接访问文件或网络，调用前检查无法保证提前识别所有行为。执行环境仍需限制实际资源访问；发生越界时，系统可以拒绝操作，或在支持的情况下发起权限申请。

## 4. 与已有授权的关系

规则命中审批条件后，可以检查是否存在覆盖本次操作的有效授权；也可以把这一步合并到权限判断中。若规则要求每次确认，则不能复用之前的批准。

明确禁止且不允许申请例外的操作，应直接拒绝，不能因为创建了审批请求就变为可执行。
