# 审批主体

审批主体是接收审批请求，并作出批准、拒绝或要求修改决定的人或审核组件。它回答“谁来审批”，与决定何时发起审批的规则分开描述。

## 1. 主体类型

| 主体 | 处理方式 |
| --- | --- |
| 用户 | 在交互界面中查看操作并作出决定 |
| 指定人员 | 由管理员、资源负责人等具有审批权限的人员处理 |
| 自动审核器 | 由规则程序或审核 Agent 检查请求并返回决定 |

系统可以按操作、资源或组织要求选择审批主体。工具调用由 Agent 发起，并不意味着该 Agent 有权批准自己的请求。

## 2. 人工审批

人工审批通常暂停待执行操作，展示操作对象、参数、预期影响及申请的授权范围，等待用户或指定人员明确回应。

普通用户交互不一定是审批。例如询问缺失参数是在收集信息，询问是否允许发送邮件才是在请求授权。等待超时或没有答复不代表批准。

## 3. 自动审核

自动审核器可以使用固定规则，也可以调用模型。审核 Agent 通常接收本次请求及必要上下文，返回决定和理由；实际操作仍由执行组件完成。

自动审核仍然可能拒绝请求。审核器无法判断或执行失败时，系统应明确选择转交人工、保持暂停或拒绝，不能把审核失败当作批准。

## 4. 自动审核与自动放行

| 方式 | 是否执行审核 |
| --- | --- |
| 自动审核 | 审核器检查请求，可以批准或拒绝 |
| 自动放行 | 命中特定配置或分支后直接允许，不一定调用审核器 |

产品中的“自动批准”可能指其中任一种，需要依据实际实现区分。要求人工确认的操作不能仅凭自动放行开关跳过。

改变审批主体不会自动扩大文件、网络或 App 访问范围；获批内容仍需由运行时按相应授权机制落实。
