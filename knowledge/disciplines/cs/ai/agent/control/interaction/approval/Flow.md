# 审批流程

审批流程描述一次操作从权限判断、发起审批到执行或拒绝的处理过程。以下是一种典型实现，不同 Agent 系统可以合并或调整其中的步骤。

## 1. 流程概览

```text
操作请求
  ↓
权限与审批策略判断
  ├─ 禁止执行 → 拒绝
  ├─ 允许直接执行 → 执行
  └─ 需要审批
       ↓
     检查已有授权
       ├─ 匹配且有效 → 执行
       └─ 无可复用授权
            ↓
          创建审批请求
            ↓
          审批主体决定
            ├─ 批准 → 按范围保存授权 → 执行
            ├─ 拒绝 → 不执行该操作
            └─ 要求修改 → 调整操作后重新判断
```

检查已有授权可以合并到权限与审批策略判断中。批准后的授权也不一定能够复用：仅本次调用有效的批准可以只用于放行当前调用。

## 2. 处理步骤

### 2.1 权限与审批策略判断

系统检查操作是否允许直接执行、需要审批或被禁止。触发审批的条件可以来自工具策略，也可以来自环境策略，例如工具调用被配置为需要审批，或操作需要超出当前沙箱的权限。

只有允许申请例外的限制，才能通过相应审批流程处理。工具调用获批，不代表可以突破其他环境限制或强制禁止规则。

### 2.2 检查已有授权

系统检查已有授权是否覆盖当前操作，包括工具、参数、目标和有效期。匹配且有效时可以复用；无匹配授权、授权过期或操作超出授权范围时，需要重新审批。

授权可能仅适用于一次调用、当前会话或持久规则，具体范围由系统及批准选项定义。若策略要求每次审批，则不能用之前的批准跳过本次审批。

### 2.3 创建审批请求

系统暂停待审批操作，并提供足够的信息供审批主体判断，通常包括：

- 操作名称、参数和目标。
- 预期影响及申请审批的原因。
- 申请的授权范围和有效期。

### 2.4 审批主体决定

审批主体可以是用户、指定人员或自动审核 Agent，结果可以是批准、拒绝或要求修改。

等待超时或未收到答复，不应视为批准。具体系统可以继续等待或取消请求。

### 2.5 保存授权并执行

批准后，系统按批准范围处理授权：仅本次有效的授权用于当前调用；会话级或持久授权则保存到相应状态或规则中，供后续匹配。

执行前应核对当前操作是否仍与获批内容一致，并满足其他权限约束。批准表示允许执行，不代表已经执行或执行成功；操作完成后还需记录实际结果。

## 3. 授权与审批记录

授权用于决定操作能否执行，审批记录用于追溯请求、决定和执行结果。批准和拒绝都可以记录，但保存了审批日志不代表获得可复用授权。

授权可以保存在调用状态、会话状态、配置文件或数据库中，具体取决于实现及授权范围。
