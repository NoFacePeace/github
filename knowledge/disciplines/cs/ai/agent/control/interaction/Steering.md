# Steering

Steering（引导）指在 Agent 执行任务的过程中，补充要求、纠正方案或调整方向，使后续行为依据新的信息继续进行。它是通用的交互概念；具体接收时机和执行方式取决于产品或框架。

## 1. 使用场景

例如，让编程 Agent 重构模块后，再补充“保留接口兼容性”或“先修复测试失败”。引导应让 Agent 在后续工作中纳入这些要求。

## 2. 实现方式

以下是理解运行中引导的几种方式，并非统一标准：

| 方式 | 处理过程 |
| --- | --- |
| 排队处理 | 在后续步骤或下一轮读取新指令 |
| 生成中接收 | 响应尚未结束时接收新指令，在支持的边界继续处理 |
| 中断并继续 | 停止当前生成或运行，再带着补充要求继续 |

## 3. 执行边界

需要区分消息被接收、模型开始依据消息行动和工具实际执行这几个时刻。引导不应默认理解为取消工具或撤销已完成操作；是否支持这些行为，需要单独确认。

## 4. OpenAI Mid-turn Steering 示例

信息核对日期：2026 年 10 月 9 日。以下依据 OpenAI 官方 API 文档。

通过 Responses API 的 WebSocket 连接，收到 `response.created` 后，可使用响应 ID 发送补充指令：

```json
{
  "type": "response.steer",
  "previous_response_id": "resp_1",
  "input": "保留现有接口，只调整内部实现。"
}
```

`response.steer.accepted` 表示输入已排队，并不表示模型已经执行。服务端完成当前输出项及已运行的托管工具工作后，自动创建带有新指令的继续响应；需要应用提供工具结果或批准时，继续过程会等待相应输入。

该机制不会改写已输出内容、撤销既有动作或取消已启动的工具。文档没有保证已排队但未启动的工具调用会立即暂停，不能将接收引导等同于所有工具立刻停止。

`response.steer` 是 OpenAI 的具体协议接口，不能据此推断所有 Agent 产品采用相同机制。
