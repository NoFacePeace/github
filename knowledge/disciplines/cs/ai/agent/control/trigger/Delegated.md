# 委派触发

委派触发是一个 Agent 将任务交给另一个 Agent，由编排层启动目标 Agent，或向已有 Agent 提交后续工作。常见形式是主 Agent 调用子 Agent 完成范围明确的子任务。

## 1. 执行过程

```text
主 Agent 接收目标
    ↓
拆分任务并选择执行者
    ↓
向子 Agent 提交任务与必要上下文
    ↓
子 Agent 执行并返回结果
    ↓
主 Agent 验证、汇总或继续委派
```

## 2. 常见用途

- 将相互独立的模块交给多个 Agent 并行检查。
- 将安全审查、资料检索等工作交给职责明确的 Agent。
- 让另一个 Agent 复核已有产物，再由主 Agent 汇总意见。

## 3. 委派输入

应提供子任务目标、必要背景、输入材料、允许操作的范围、输出格式和完成条件。子 Agent 未必拥有主 Agent 的完整上下文，需要明确传递完成任务所需的信息。

独立的 Agent 上下文不代表文件系统隔离；多个 Agent 共享工作目录时，应明确文件写入责任，避免相互覆盖。

## 4. 设计要点

- 根据任务依赖决定顺序执行或并行执行。
- 控制并发数量、执行时间和资源预算。
- 定义失败、超时、取消及部分结果的处理方式。
- 主 Agent 对返回结果进行验证，不将子 Agent 的完成状态直接等同于目标达成。
- 是否允许自动委派取决于平台配置和适用指令，不能假定所有 Agent 都会自动创建子 Agent。
