# 事件触发

事件触发是系统收到符合条件的事件后，主动调用 Agent 执行预先定义的任务。需要提前配置事件来源、匹配条件和执行要求。

## 1. 常见来源

| 事件来源 | 触发条件 | Agent 任务 |
|---|---|---|
| 代码托管平台 | 创建或更新 PR | 审查变更 |
| CI 系统 | 构建或测试失败 | 分析失败日志并提出修复 |
| 监控系统 | 告警达到指定级别 | 查询日志、分析故障 |
| 工单系统 | 新建指定类型的工单 | 分类、补充信息或提出处理建议 |
| 业务系统 | 数据更新或流程状态变化 | 分析变化并生成后续建议 |

## 2. 执行过程

```text
CI 测试失败
    ↓
Webhook / 消息队列 / 工作流接收事件
    ↓
校验来源、匹配规则、去重
    ↓
调用 Agent，传入任务要求和失败日志
    ↓
分析原因并按权限执行后续操作
```

接收事件和调用 Agent 的通常是外部服务或工作流。Agent 可以按需启动，不必自己一直运行以等待事件。

## 3. 事件与任务输入

事件用于说明发生了什么，例如事件类型、对象标识和时间；任务要求用于说明 Agent 应做什么。接收端将事件数据与预设任务要求组合后提交给 Agent。

外部事件中的日志、评论和文档可能包含不可信内容，应作为待分析数据处理，不能自动获得修改任务要求或扩大权限的能力。

## 4. 可靠性与循环控制

- 事件可能重复或乱序到达，应按事件标识去重，并检查对象当前状态。
- 接收成功与任务执行成功分别记录；执行失败时按规则重试。
- 对短时间内的大量事件进行合并、限流或排队。
- Agent 的修改可能产生新事件，应避免“修改触发执行、执行再次修改”的无限循环。
- 有副作用的操作需要幂等控制，仅对触发事件去重不足以保证操作只执行一次。
