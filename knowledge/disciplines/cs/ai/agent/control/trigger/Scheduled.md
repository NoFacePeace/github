# 定时触发

定时触发是由调度器在指定时间或周期到达时调用 Agent。用户预先设置执行时间和任务要求，每次到期后由系统发起执行。

## 1. 常见形式

| 形式 | 示例 |
|---|---|
| 一次性时间点 | 明天上午检查发布结果 |
| 固定日历计划 | 每个工作日早上生成日报 |
| 固定间隔 | 每隔十分钟检查一次长任务状态 |

## 2. 执行过程

```text
保存计划与任务要求 → 调度器等待到期 → 调用 Agent → 保存结果并按规则通知
```

可以让每次执行使用独立会话，也可以继续已有会话。固定间隔的起算点应明确，例如从上次启动时间或上次完成时间计算。

## 3. 轮询与事件的区别

每隔一段时间查询构建状态属于定时轮询；构建系统在失败时主动发送通知，再启动 Agent，属于[事件触发](EventDriven.md)。两者都能用于监测变化，但响应时效、调用次数和接入要求不同。

## 4. 设计要点

- 明确时区及夏令时处理方式。
- 定义错过执行时间后是补跑还是跳过。
- 上一次执行尚未结束时，明确跳过、排队或允许并发。
- 为持续检查设置终止条件，例如任务完成、超时或达到预算。
- 根据结果决定是否通知，避免没有变化时反复发送消息。
