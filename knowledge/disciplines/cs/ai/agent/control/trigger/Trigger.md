# Agent 触发机制

触发机制决定何时启动 Agent 执行任务，或向已有会话提交新的任务。触发方需要提供任务要求、必要上下文和执行权限，由运行时创建或恢复执行过程。

## 1. 触发方式

| 方式 | 触发条件 | 示例 |
|---|---|---|
| [手动触发](Manual.md) | 用户明确提交任务 | 在对话中提出需求、执行命令或点击运行按钮 |
| [定时触发](Scheduled.md) | 到达指定时间或周期 | 每天生成报告、每隔一段时间检查任务状态 |
| [事件触发](EventDriven.md) | 收到符合条件的事件 | 创建 PR、CI 失败、收到告警后启动分析 |
| [委派触发](Delegated.md) | 其他 Agent 分配任务 | 主 Agent 将代码审查交给子 Agent |

这些方式按任务的发起条件分类，可以组合使用。例如，用户手动启动主 Agent，主 Agent 再委派子 Agent；定时检查发现异常后，也可以启动后续分析任务。

## 2. 触发与调用

触发条件回答“为什么现在执行”，调用接口回答“如何把任务交给 Agent”。同一个 API、SDK 或命令行入口可以服务于多种触发方式，不应将接口形式与触发条件混为一谈。

```text
用户操作 / 到达时间 / 外部事件 / Agent 委派
                    ↓
             校验条件与组装任务
                    ↓
              调用 Agent 运行时
                    ↓
              执行并记录任务结果
```

Agent 通常不需要始终运行以等待触发；常驻的服务、调度器或事件消费者可以负责接收触发信号，再启动执行。具体部署也可以复用常驻的 Agent 服务。

## 3. 与相关机制的关系

- 交互机制关注用户如何与 Agent 沟通，包括运行中调整方向。
- 编排关注任务分工、执行依赖和结果汇总，委派触发是其中的一环。
- 运行事件记录执行过程中的状态变化；这些事件经过订阅和规则匹配，也可以成为后续任务的触发来源。
- Skill 的选择发生在任务处理过程中，可以由用户显式指定，也可以根据任务匹配；选择 Skill 不等于启动一个新的 Agent。

## 4. 设计要点

- 明确每次触发的任务目标、输入范围和完成条件。
- 明确创建新会话还是继续已有会话，避免上下文混用。
- 校验触发来源和权限，外部事件内容作为输入数据处理。
- 管理重复触发、重试和并发，避免重复写入或任务堆积。
- 记录触发来源、运行标识和结果，便于追踪问题。
