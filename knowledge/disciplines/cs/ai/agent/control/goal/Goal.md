# Agent 目标

目标（Goal）描述 Agent 要达成的结果，例如“修复登录报错，并通过相关测试”。它用于指导行动选择和判断任务是否完成。

## 1. 目标、计划与行动

| 概念 | 回答的问题 | 示例 |
|---|---|---|
| 目标 | 最终要达成什么？ | 登录恢复正常，相关测试通过 |
| 计划 | 准备分几步完成？ | 复现问题、定位原因、实施修复、验证结果 |
| 行动 | 当前具体做什么？ | 读取日志、修改文件、执行测试 |

目标相对稳定，计划和行动可以根据执行结果调整。如果用户修改需求，则目标和完成条件也需要同步更新。

## 2. 目标驱动与持续推进

Goal-driven / Goal-oriented（目标驱动）描述围绕目标选择和调整行动的特征。多数任务型 Agent 都有目标，该名称本身不代表一种与 ReAct、Plan-and-Execute 互斥的算法，也不必然意味着会长期自主运行。

有些产品会保存目标及其进度，在多次执行或恢复后继续推进。界面显示“目标”也可能只是展示当前任务摘要，是否会自动继续需要结合产品行为判断。

## 3. 完成与停止条件

- **完成**：有证据表明满足验收条件，例如问题已解决且相关检查通过。
- **需要输入**：缺少必要信息、授权或关键决策，需要用户参与。
- **受阻或失败**：外部条件阻止推进，或尝试后仍无法完成。
- **预算耗尽或取消**：达到步数、时间、Token、费用限制，或收到停止要求。

停止运行不等于达成目标。Agent 应区分完成、受阻和预算耗尽等状态，并说明已完成的部分与剩余工作。

## 4. 与权限的关系

目标说明期望结果，不会自动授予额外权限。Agent 即使围绕目标持续推进，也仍需遵守授权范围、审批规则和执行环境限制。

## 5. 常见实现

### 5.1 保存目标状态

与计划类似，目标可以保存为结构化状态；计划记录准备执行的步骤，目标记录期望结果、验收条件和当前状态。例如：

```json
{
  "objective": "修复登录报错",
  "acceptance_criteria": [
    "原报错场景可以正常登录",
    "相关测试通过"
  ],
  "status": "active"
}
```

上述字段仅为示意，不存在统一格式。复杂系统还可以记录目标标识、用户约束、关联计划、验收证据、预算、阻碍原因和更新时间。

目标可以保存在内存、文件或数据库中。需要跨进程重启或跨会话恢复时，应持久化保存，而不能只依靠当前对话或内存对象。

### 5.2 围绕目标推进执行

每轮执行时，程序向 Agent 提供目标、当前计划、相关上下文和已有执行结果。Agent 据此决定下一步，程序衔接工具执行并保存结果，再检查是否需要继续。

```text
读取目标与进度 → 制定或更新计划 → 执行 → 检查目标
                       ↑                    ↓
                       └── 未完成且可继续 ───┘
                                            ↓
                                     完成或其他停止状态
```

目标提供判断方向，计划组织步骤，行动产生实际结果。步骤全部执行完毕后仍应检查验收条件；原计划不足以达成目标时，需要调整计划，而不是直接将目标标记为完成。

### 5.3 更新状态与验证完成

Agent 可以通过工具请求更新目标进度、提交验收证据或标记完成。程序负责校验请求、保存状态，并将最新状态提供给后续执行和界面。工具名称和状态转换规则由具体系统决定。

程序可以检查字段是否合法、状态转换是否符合规则，但目标是否实际达成，还需要结合可验证的结果。例如，修复报错时，应检查原场景是否恢复、相关测试是否通过，以及是否满足用户约束。

Agent 声称“完成”是一个判断，不能单独代替验收证据。若只能完成部分验证，应记录已经确认的结果与尚未验证的部分。

### 5.4 控制继续与停止

持续推进需要程序或调度器显式实现控制循环：未完成且具备继续条件时触发下一轮；完成、需要输入、受阻、预算耗尽或取消时进入相应状态。

应将目标状态与单次运行状态区分开。例如，一轮执行结束可能只是交还控制权，目标仍处于进行中；预算耗尽表示本轮或当前预算范围内不能继续，不代表目标已经完成。

具体允许多少轮、何时判断受阻、如何恢复，由系统规则决定。目标本身不会绕过权限限制，也不会自动允许无限重试。

## 6. 跨会话持续推进

支持跨会话继续工作，通常还需要以下机制：

- **持久化目标与进度**：保存目标、计划、执行结果及恢复所需的状态。
- **恢复或唤醒执行**：通过用户恢复、事件通知或定时调度触发后续运行。
- **恢复上下文**：为新一轮执行加载目标、约束、已完成工作和未解决问题。
- **检查外部状态**：确认文件、任务和工具结果是否仍然有效，避免重复产生有副作用的操作。

仅保存一条目标数据不会自动触发执行。持续工作需要目标状态、执行循环以及恢复或调度机制共同配合。
