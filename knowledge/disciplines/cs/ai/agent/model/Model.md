# 模型

[Agent](../Agent.md)

模型为 Agent 提供理解、生成与工具调用决策等能力。本目录整理 Agent 中的模型接入、统一接口与提供商适配。

## 1. 模型与 Agent 的分工

模型根据输入上下文生成回答或工具调用请求。Agent 负责管理执行循环、调用工具、回传结果与决定何时继续或结束。

模型接口返回工具调用，不代表已经执行工具。客户端工具由 Agent 的工具执行模块处理，执行结果通过调用 ID 与模型请求关联。

## 2. 模型接口

统一接口用于隔离不同提供商的请求格式与输出差异，通常包括：

| 定义 | 内容 |
|---|---|
| 消息 | 系统指令、用户输入、助手输出与工具结果 |
| 工具定义 | 工具名称、用途与参数 Schema |
| 工具调用 | 调用 ID、工具名称与参数 |
| [输入](Input.md) | 模型选择、上下文、可用工具、输出限制与取消信号 |
| [输出](Output.md) | 文本增量、完整工具调用、本轮结束状态与用量统计 |

Agent 核心依赖统一接口，具体提供商适配器负责转换协议。提供商的模型专属能力可以通过明确的扩展配置暴露，不能假定所有接口功能完全一致。

## 3. 提供商适配

不同提供商的请求字段、消息结构、工具调用格式和流式事件可能不同，适配层将这些差异转换为内部统一接口。

适配器负责鉴权、请求序列化、响应解析、工具参数分片聚合及错误转换。Agent 核心不应直接读取某家接口的原始字段。

## 4. 流式与事件

内部可以统一使用事件流：流式响应边接收边转换为事件，非流式响应收到后转换为同样的事件。界面及时展示文本，Agent 收集完整工具调用后执行工具。

模型输出事件描述生成过程；Agent 事件 还包括工具执行进度与任务状态，两者属于不同层次。模型流式输出不意味着工具执行结果自动流式化。

参数完整并不等于本轮一定正常结束，还应检查截断、失败与取消状态，避免执行异常中断的调用。

## 5. 相关主题

- 工具：工具定义、执行与结果处理。
- 上下文：组织每轮传给模型的信息。
- 运行时：管理 Agent 执行过程。
