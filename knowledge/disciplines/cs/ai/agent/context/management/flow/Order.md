# 执行顺序

执行顺序描述多种上下文管理操作如何衔接。部分操作存在依赖，其他操作可以按任务和运行时策略调整，没有适用于所有 Agent 的唯一次序。

## 1. 工具结果处理

```text
获取执行状态与结果
→ 检查大小
→ 需要外置时确认内容可恢复
→ 生成片段与读取引用
→ 返回对应的工具结果消息
```

如果需要新保存内容，应先确认保存成功，再替换正文。原文已有可靠来源时，可以直接复用，不必重复保存。确定无须恢复的内容也可以按策略直接截断。

## 2. 整体上下文精简

一种可采用的顺序是：

1. 标记保护对象和必要的调用关联。
2. 去重，并清理已经被有效新状态替代的旧记录。
3. 外置不必常驻的详细内容，或截断适合保留片段的正文。
4. 按消息块裁剪可删除的旧交互。
5. 需要且支持时，用摘要替换旧历史。
6. 检查配对、引用和实际占用，决定继续执行或进入兜底流程。

这不是强制流水线。例如，摘要前可能先保存原始历史；某个阶段已经达到目标时，也可以跳过剩余的有损处理。

## 3. 必须维护的依赖

- 先保留有价值且不可恢复的信息，再删除其原消息。
- 先确认新计划成功覆盖旧状态，再清理旧计划。
- 工具请求和结果应按协议成组处理，不能只删除一方。
- 去重引用的保留结果被后续裁剪时，需要更新引用或调整保留项。
- 生成摘要后，还需要在后续输入中实际替换旧历史，才能减少占用。

## 4. 处理后检查

重新检查预算和结构属于流程的一部分。未达到目标时，可以继续允许的处理、降级或明确报错；不应仅因已执行裁剪就假定请求一定满足限制。
