# 执行时机

执行时机描述运行时在哪个阶段检查或调整上下文。进入某个阶段不代表一定需要精简，还需要判断该操作的触发条件。

## 1. 常见阶段

| 阶段 | 主要工作 |
|---|---|
| 新一轮开始前 | 加载历史和已有摘要，按需处理旧历史，再加入当前输入 |
| 工具调用前 | 设置过滤、字段和分页参数，控制预计返回范围 |
| 工具返回后 | 检查单条结果大小，按需保存全文、返回引用或截断片段 |
| 模型调用前 | 检查整体预算，精简历史并验证消息结构 |
| 任务阶段切换时 | 整理已完成阶段的结论，移出不必常驻的过程记录 |

## 2. Loop 中的位置

```text
模型调用前检查
    ↓
调用模型
    ↓
工具调用前控制范围
    ↓
执行工具
    ↓
工具返回后处理结果
    ↓
下一次模型调用前检查
```

没有工具调用并完成任务时，可以直接结束本轮，不必经过工具相关阶段。

## 3. 摘要时机

摘要可以放在新一轮开始前，也可以在 Loop 内接近预算时执行。选择取决于任务长度、运行时能力和允许的额外调用开销，不应把某一种时机当作摘要压缩的固定定义。

## 4. 处理边界

尽量在大段内容进入模型之前控制输出。内容已经进入历史后，需要运行时实际修改后续请求中的消息，仅保存文件或生成摘要不会自动释放占用。
