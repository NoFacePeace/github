# 工具结果去重

工具结果去重是在多次调用产生重复信息时，保留必要结果，合并或替换冗余正文，以减少后续模型输入占用的方式。

## 1. 识别重复

可以将工具名称、有效参数和结果内容组合为判定依据：

```text
工具名相同
+ 有效参数相同
+ 结果内容相同
→ 重复候选
→ 检查时间、来源和任务用途后决定是否合并
```

参数比较前可以进行规范化，例如统一 JSON 对象键顺序，并按明确规则排除不影响执行的内部元数据。不能随意忽略时间范围、环境、分页、路径等会改变结果的参数。

结果可直接比较，也可以通过内容哈希辅助判断。跨版本、跨环境或不同时间的结果，即使正文相同，也不一定能视为可删除的冗余。

## 2. 选择保留项

- 最新状态查询：通常保留最新结果，同时保留必要的变化记录。
- 相同文件版本：保留完整、覆盖范围合适的一份内容。
- 不变状态轮询：可以合并重复项，保留首次时间、最近时间和重复次数。

需要定位被保留的结果时，可以使用工具调用 ID 或稳定记录标识，避免仅用“参见后文”而无法确定对象。

## 3. 替换旧正文

一种实现是保留原调用与结果消息，只替换旧结果正文：

```text
助手：read("a.go")，调用 ID 为 call_1。
工具：内容与 call_2 的结果重复，请参见 call_2。

助手：read("a.go")，调用 ID 为 call_2。
工具：完整文件内容……
```

这个示例假设两次读取的是同一版本、内容一致的文件。替换正文不会自行删除调用请求或结果消息，后续模型仍能看到调用过程。

也可以删除整组重复交互，但需要维护工具配对；助手消息包含多个调用时，应避免连带删除其他有效调用。

## 4. 后续裁剪

去重后继续删除消息时，应检查重复提示引用的结果是否仍然存在。被引用的正文即将删除时，可以改用可读回的外部记录，或调整保留项，避免出现悬空引用。

去重通常只调整后续模型输入，原始执行日志可以继续保留，不必同步删除。

## 5. 判断边界

- 相同参数不代表相同结果，文件、指标、日志和远程状态都可能变化。
- 相同正文也可能是时间证据，例如多次健康检查证明某状态持续存在。
- 有副作用的调用重复发生，本身可能是重要事实，不能因输出相同就隐藏操作次数。
- 失败与成功结果不能只根据调用参数合并，失败原因可能仍有诊断价值。
- 问答、授权和技能加载等结果应有单独规则，避免丢失约束和用户选择。

这些判定可以由代码完成；只有需要语义判断时，才可能引入模型参与。
