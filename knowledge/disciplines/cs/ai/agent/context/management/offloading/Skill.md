# Skill 外置

Skill 外置是将已经加载到上下文中的完整技能说明，替换为 Skill 标识、资源位置和重新读取提示，需要时再加载原文的管理方式。

Skill 原文通常已经存在于文件或技能服务中，因此不一定需要重新保存副本。这里的外置重点是减少正文在上下文中的常驻占用，同时保留可靠的读取入口。

## 1. 基本流程

1. 确认原 Skill 和资源仍然可访问。
2. 保留加载所需的标识、作用域、资源路径及必要版本信息。
3. 在后续模型输入中，用重读提示替换已经加载的正文。
4. 后续步骤依赖具体说明时，先重新读取对应 Skill。

替换操作由运行时执行；模型不能通过另存文件直接删除已收到的历史正文。如果工具首次返回时就只提供引用，应明确哪些说明需要先加载才能执行。

## 2. 前后示例

```text
外置前：
助手：读取 deploy Skill。
工具：数千字的操作步骤、检查要求和参考说明……

外置后：
助手：读取 deploy Skill。
工具：Skill 正文已移出当前上下文。
      skill_id: deploy
      resource_path: SKILL.md
      需要依据具体步骤操作前，请通过 Skill 读取工具重新加载。
```

这是格式示例，标识字段和读取参数取决于具体工具。实际运行时需要保留原工具调用与结果的关联。

## 3. 与其他操作的区别

- 截断：保留一定长度的原文片段；Skill 外置通常用标识和提示替换完整正文。
- 裁剪：删除消息或交互块；Skill 外置可以保留消息结构，仅替换正文。
- 摘要压缩：生成更简短的说明；重读提示不等于技能说明摘要，不能据此推断完整步骤。

“引用替换”描述的是外置中的具体动作，不必单独作为与外置并列的管理类别。

## 4. 执行要点

- 当前立即需要遵守的关键要求应继续保留，避免在重读前执行操作。
- 引用要足以定位原文，不能只留下含义不明的技能名称。
- 明确读取的是原版本还是最新版本；版本变化可能改变操作要求。
- 原文不可访问时不能只留下无效提示，应保留必要正文或可用副本。
- 是否暂时保留近期 Skill 正文应按预算和任务设置，没有统一固定条数。
