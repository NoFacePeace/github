# 工具结果外置

工具结果外置（Tool Result Offloading）是将较大的工具输出保存在文件或其他外部存储中，只向模型返回必要片段、状态和读取引用的方式。外置的是工具返回的内容，而不是工具定义或调用参数。

## 1. 处理时机

常见方式是在每次工具执行完成后，由工具层或运行时检查结果大小。结果未超过阈值时直接返回；超过时保存详细内容，生成较小的替代结果，再加入模型上下文。

```text
工具执行完成
      ↓
检查输出大小
├─ 未超限 → 原样返回
└─ 超限 → 保存全文 → 生成预览和引用 → 返回模型
```

也可以始终保存结果，只在超限时限制进入上下文的内容。长时间运行的命令可以边执行边将输出写入文件。

这种处理针对单次输出，不需要等整个上下文接近上限。多次小结果仍会累积占用，需要另外管理整体上下文。

## 2. 执行主体

- 工具自身：执行时将全文写入文件，只返回结果说明和路径。
- 运行时：在统一的工具结果处理入口检查大小并保存内容。
- 模型主动调用：模型判断需要保存内容，调用文件写入等工具完成外置。

自动检查大小、保存结果、截取预览和生成固定提示都可以由普通代码完成，不需要额外模型请求。只有需要模型提炼语义摘要时，才可能增加模型调用。

## 3. 返回内容

替代结果通常包含外置提示、读取位置、原文预览和按需读取方式。已有的退出码、执行状态等结构化信息也可以保留，不必先生成语义摘要。

```text
工具输出过长，完整结果已保存至：
/tool-results/call_123.txt

以下为首尾预览：
[开头若干行]
... [省略 N 行] ...
[结尾若干行]

需要更多内容时，使用文件读取工具分段读取，或按关键词搜索。
```

外部位置不一定是文件路径，也可以是调用 ID 或记录标识，但必须有对应的读取工具。替代内容仍应作为原工具调用的结果返回，保留调用与结果的关联。

## 4. 外置与截断

两者可以在同一流程中配合使用，但职责不同：

| 操作 | 作用 |
|---|---|
| 外置 | 将内容保存到上下文之外，支持后续读取 |
| 截断 | 限制直接进入上下文的内容长度 |

仅返回首尾片段而没有可访问的原始记录，只能说明发生了截断。保存全文后再返回片段与引用，才形成可恢复的外置流程。

## 5. 执行要点

- 先确认保存成功，再替换需要外置的内容；保存失败时不能返回无效引用。
- 控制预览长度，明确标注省略或单行截断，避免模型误以为看到全文。
- 读取工具支持分页、范围或搜索，防止一次读取又把全文塞回上下文。
- 明确记录所属任务、可访问范围、保存期限和大小上限；不同结果类型不一定都支持完整保存。
- 优先在输出进入模型之前处理。已经收到的全文即使另存为文件，也不会自动从历史上下文消失，需要运行时调整后续输入。

## 6. 实现示例

不同框架的工具、结果状态和配置可能采用不同阈值，不应把某一种实现当作统一标准。

- LangChain Deep Agents：超大工具结果保存到外部存储，返回首尾预览和读取路径。
- Claude Code：部分 Bash 和 MCP 成功结果超限后返回文件引用；失败结果可能仅截断，具体规则按工具区分。
- Codex：官方指南推荐限制单次工具输出并保留首尾，但该截断建议本身不保证自动保存全文。
