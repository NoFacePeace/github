# 摘要提示词

本文记录摘要压缩请求的组织方式、长度要求和使用前提。

## 1. 组织方式

摘要请求按顺序分为三部分：

1. [待压缩历史](History.md)：本次需要整理为摘要的旧消息。
2. [已有摘要](PreviousSummary.md)：上次压缩的结果，仅在存在时加入。
3. [摘要指令](Instructions.md)：规定摘要目标、保留内容和输出要求。

运行时将以下内容组成一次独立的模型请求，摘要指令放在最后一条 `user` 消息中：

```text
system：## Run 1: 该轮用户输入
user：原用户消息
assistant：原助手回复或工具调用
tool：原工具结果
……
system：## Run N (partial): 该轮用户输入
……该轮需要进入摘要的前半段消息……
system：<previous-summary>
已有摘要（如果有）
</previous-summary>
user：摘要压缩指令
```

每个完整 Run 使用 `## Run N: ...` 标题；只压缩其中一部分时使用带 `(partial)` 的标题。已有摘要仅在存在时加入。历史中的原 `system` 消息不会直接复制进摘要请求。

## 2. 长度要求

- 提示词可以设置目标长度，例如少于 500 个单词，并说明关键内容完整性优先；这不是代码强制检查的长度限制，也不等于中文 500 字。
- 当前项目的摘要请求设置 `MaxTokens: 2048`，限制输出 Token 数量。
- 目标长度、压缩比例和输出语言是不同要求，应分别明确。

## 3. 使用前提

提示词需要与上下文组织方式一致。例如，只有实际提供了独立的文件清单，才能要求摘要省略清单中的信息；只有近期消息确实保留原文，才能降低摘要中近期细节的优先级。

历史放在前面、指令放在末尾时，应使用“以上对话”或明确指定待摘要内容，避免位置描述不一致。
