# 待压缩历史

待压缩历史是本次摘要请求需要处理的旧消息，包括用户输入、助手回复、工具调用及其结果。继续保留原文的近期消息不属于这部分。

## 1. 内容选择

- 根据轮次、消息块或 Token 预算划分历史与近期消息。
- 维护工具调用及结果的完整配对，避免在两者之间切分。
- 明确保留有效用户要求、决策依据和任务状态，供模型提炼。

## 2. 消息组织

当前项目按 Run 顺序组织待压缩消息，为每轮添加 `system` 标题，随后放入该轮原有的用户、助手和工具消息。只压缩某轮的一部分时，标题带有 `(partial)`。

```text
system：## Run 1: 该轮用户输入
user：原用户消息
assistant：原助手回复或工具调用
tool：原工具结果
……
system：## Run 2 (partial): 该轮用户输入
……该轮需要进入摘要的前半段消息……
```

## 3. 预处理

当前项目不会直接复制历史中的原 `system` 消息；助手正文超过 3,000 字节、工具正文超过 2,000 字节时，会先截取开头。必要时还会进一步缩减摘要输入以适配模型窗口。

因此，摘要模型看到的不一定是完整原始记录。预处理阶段丢失的信息，无法仅靠摘要指令恢复。
