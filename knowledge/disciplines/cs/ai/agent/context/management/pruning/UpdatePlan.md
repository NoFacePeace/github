# 计划更新裁剪

计划更新裁剪是保留当前有效计划，从后续模型输入中移除已被新计划替代的旧计划调用及其结果的方式。它依据状态替代关系，不要求新旧计划内容相同，因此归入裁剪，而不是工具结果去重。

## 1. 适用前提

- 计划更新返回或提交的是完整计划状态，而非必须依次应用的增量补丁。
- 新计划已经成功生效，能够覆盖需要保留的当前状态。
- 旧计划中的重要约束、决策依据和未完成事项已在新计划或其他上下文中保留。

仅仅出现较新的调用，不一定代表可以删除旧计划。更新失败时，应保留最后一次有效状态。

## 2. 处理流程

1. 识别同一任务、同一计划的更新调用，例如 `update_plan`。
2. 找到最新且有效的完整计划。
3. 从助手消息中移除已被替代的旧计划调用请求。
4. 删除与这些调用 ID 对应的工具结果消息。
5. 保留其他工具调用和有价值的助手正文，检查剩余消息的配对与顺序。

当助手消息不再包含任何调用时，若正文仍有价值，可以转为普通助手消息保留；没有其他内容时再删除空消息。具体处理应符合模型接口要求。

## 3. 前后示例

```text
裁剪前：
助手：update_plan，调用 ID 为 plan_1。
工具：检查日志待办，验证修复待办。
助手：read，调用 ID 为 read_1。
工具：日志内容……
助手：update_plan，调用 ID 为 plan_2。
工具：检查日志已完成，验证修复待办。

裁剪后：
助手：read，调用 ID 为 read_1。
工具：日志内容……
助手：update_plan，调用 ID 为 plan_2。
工具：检查日志已完成，验证修复待办。
```

旧计划的调用与结果一起移除，最新有效计划和其他交互继续保留。这里调整的是后续模型输入，原始执行记录可以继续保存。

## 4. 与正文精简的区别

工具结果去重可以只把旧结果正文替换为重复提示，仍保留消息结构。计划更新裁剪则直接移除旧计划调用与结果，减少过时状态对模型的干扰。

## 5. 保护边界

- 多个独立计划应分别判断，不能只保留所有计划调用中的最后一条。
- 增量更新应先还原完整状态，不能直接删除重建当前计划所必需的早期更新。
- 取消事项、范围变化和关键决策可能具有持续价值，需要另行保留。
- 计划结果过长时，可以使用其他上下文管理方式处理，不能以裁剪旧计划代替保存当前有效计划。
