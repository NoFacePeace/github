# Skill 保护

Skill 中可能包含当前任务必须遵循的流程、约束和验证要求。上下文精简时，需要保留必要说明，或保留可靠的重新加载线索，避免后续执行在缺少指导的情况下继续。

## 1. 保护内容

- 已加载 Skill 的标识和必要的适用背景。
- 当前步骤必须遵守的有效要求。
- 重新加载所需的作用域、资源路径或其他参数。
- 判断是否需要重新读取的提示，以及必要的版本信息。

## 2. 记录与正文分开处理

保护 Skill 的调用记录，不一定意味着完整正文始终保留在上下文中。可以保留调用及其结果消息，将长篇结果正文替换为简短的重新加载提示。

```text
精简前：
助手：调用工具读取 deploy Skill。
工具：数千字的部署步骤和注意事项……

精简后：
助手：调用工具读取 deploy Skill。
工具：正文已精简。依赖这些说明前，请重新读取 deploy Skill。
      加载标识及资源位置：……
```

这与删除整组消息不同：调用记录及读取线索仍然存在，但模型当前看不到完整说明。

## 3. 重新加载

结果正文被替换后，不能把重新加载提示当作完整 Skill 内容使用。后续步骤需要依据具体流程操作时，应先读取对应说明。

重读所需的标识和参数必须明确且可用。需要复现原版本时，应提供版本定位信息；如果只能读取最新版本，应核对说明是否已经变化。

## 4. 保护边界

- 当前立即需要的关键要求不能只保存在待重读的正文中。
- 保留原文、替换正文和保护整个交互块是不同策略，应分别定义。
- 一条助手消息包含多个工具调用时，保护整个块可能连带保留其他调用，需要明确处理粒度。
- 近期 Skill 正文是否暂时保留、保留多少，应根据预算和任务需要设置，没有统一固定条数。

这些是可采用的保护方式，不代表所有 Agent 都会自动实施相同规则。
