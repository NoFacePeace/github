# 裁剪保护

裁剪保护用于明确上下文精简过程中哪些内容不能直接删除，以及哪些内容允许替换为摘要或可读取引用。保护规则应分别说明适用阶段、保护对象和允许的变更，不能仅用“不删除”概括所有情况。

## 1. 需要保护的内容

| 内容 | 保护目的 |
|---|---|
| 有效系统指令 | 保留角色职责、行为规则和权限约束 |
| 用户要求 | 保留目标、有效约束、授权范围和纠正意见 |
| 最新用户输入 | 保证当前请求完整、可理解 |
| 当前任务状态 | 保留已完成事项、未解决问题和下一步行动 |
| 关键决策及依据 | 避免重复失败尝试或推翻已确认方案 |
| 近期必要交互 | 保留理解当前步骤所需的调用、结果和说明 |
| 不可恢复的证据 | 避免丢失临时故障现场、历史指标或一次性返回值 |
| 外部读取引用 | 使已经移出上下文的内容仍可定位和读取 |

这些是设计保护策略时的候选内容，不代表每个框架都会自动识别并保护全部类别。

## 2. 结构保护

工具调用与结果应遵守模型接口要求的配对和顺序。删除时可以按完整交互块处理；从包含多个调用的助手消息中移除某个调用时，也需要移除对应结果，并保留其他调用的合法关联。

结构合法不等于语义完整。即使调用和结果仍然配对，如果任务背景已经丢失，模型仍可能无法正确解释结果。

## 3. 保护层次

- 保留原文：适用于当前有效指令、最新输入和必须精确使用的数据。
- 保留含义：允许整理成摘要，但应保留约束、状态、决策及其依据。
- 保留可恢复性：正文可以移出上下文，但需要有效引用和读取工具。
- 保留消息块：不整块删除，不一定禁止先精简其中的结果正文。

`system` 角色中的有效指令通常应保护，但有些运行时也用该角色承载历史摘要或资料。是否允许更新，应结合内容用途判断，不能仅依据角色名一概永久保留原文。
