# Agent 会话

会话（Session）是组织 Agent 连续交互及相关状态的逻辑单元，通常通过会话标识关联用户消息、模型输出、工具调用和执行事件。不同平台也可能使用 Conversation 或 Thread 等名称，具体边界以平台定义为准。

## 1. 内容范围

- 会话标识与归属：关联用户、任务和访问权限。
- 消息与事件：保存用户输入、Agent 回复、工具请求、工具结果和状态变化。
- 上下文管理：选择历史消息、摘要和相关信息，组织每次模型调用的输入。
- 状态持久化：保存会话记录和必要状态，支持后续读取、继续或恢复。
- 生命周期：创建、继续、分支、归档、删除和数据清理。

## 2. 会话、运行与上下文

| 概念 | 含义 |
|---|---|
| 会话 | 将一系列交互与状态关联起来的逻辑容器 |
| 运行（Run） | 一次被启动的 Agent 执行过程，可能包含多次模型和工具调用 |
| 模型上下文 | 某次模型调用实际接收到的信息 |

一个会话可以包含多次运行。例如，用户先要求分析文档，Agent 完成后，用户继续要求修改结论，两次执行可以属于同一个会话。

保存完整会话历史不意味着每次模型调用都会读取全部历史。应用可以根据上下文窗口和任务需要，选择部分消息、生成摘要或检索相关记录。

## 3. 与其他机制的关系

- [运行时](../runtime/Runtime.md)：推进会话中的执行过程，管理运行状态及工具结果。
- [记忆](../memory/Memory.md)：从会话等来源提取并维护值得保留的信息，也可以跨会话使用。
- [可观测性](../observability/Observability.md)：通过会话标识关联执行轨迹，帮助定位问题。
- [沙箱](../sandbox/Sandbox.md)：承载需要隔离的实际操作；会话的隔离不自动代表文件系统、进程或网络隔离。

持久保存会话记录也不等于能够从任意中断点恢复执行。恢复通常还需要运行状态、检查点，以及对外部操作是否已完成的确认。
