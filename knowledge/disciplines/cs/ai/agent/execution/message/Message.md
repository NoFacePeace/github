# Agent 消息

[Agent](../../Agent.md)

消息（Message）是对话中组织输入、助手输出与工具结果的数据单元。Agent 保存消息历史，并按模型接口要求组装每轮请求；运行过程中的增量和状态变化则通过事件表达。

## 1. 消息类型

| 类型 | 作用 |
|---|---|
| [System（系统指令）](System.md) | 定义模型的行为约束与任务背景 |
| Developer（开发者指令） | 应用开发者提供的规则与输出要求，部分接口支持 |
| [User（用户消息）](User.md) | 用户问题、要求与补充信息 |
| [Assistant（助手消息）](Assistant.md) | 模型生成的文本与工具调用请求 |
| [Tool（工具结果）](Tool.md) | 程序执行工具后的输出或错误 |

这些是内部建模时的语义分类，不代表每家 API 都有相同的 role。部分接口将系统指令放在顶层参数，将工具结果放在 user 消息内容块或独立 Item 中。

## 2. 内容与工具关联

消息内容可以是文本，也可以由图片、文件引用等内容块组成。助手消息可能同时包含文本和多个工具调用，不能假设每条消息都只有一个字符串。

工具调用至少需要调用标识、工具名称与参数；工具结果通过调用标识关联对应调用。相同工具可以被多次调用，不能仅靠函数名或排列顺序匹配结果。

## 3. 与事件的关系

消息描述对话内容，事件描述生成或执行过程中发生的变化。例如：

```text
文本增量事件 → 聚合成助手消息
工具调用分片 → 聚合成完整工具调用
工具执行结束 → 形成工具结果并加入后续模型输入
```

模型输出中断时可以保留部分文本供界面展示，但是否将其纳入下一轮上下文需要单独决定。消息历史与事件历史用途不同，不应直接将所有运行事件当作模型输入。

## 4. 与模型和上下文的关系

- 模型：定义统一输入输出，并适配各提供商的消息格式。
- 上下文：选择每轮传给模型的消息与其他信息。
- 会话：组织连续交互及其状态。
- 工具：执行模型请求的操作并返回结果。
