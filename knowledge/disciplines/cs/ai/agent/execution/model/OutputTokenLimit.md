# 用户输出限制

用户输出限制是用户或管理员为单次模型调用配置的最大输出 Token 数，用于控制生成长度和消耗。建议用 `outputTokenLimit` 表示，与模型能力上限分别保存。

## 1. 作用范围

该限制按每次模型请求生效，不是整轮任务累计 Token 配额。例如，每次最多输出 8,000 Token，Agent 调用模型十次时，每次都需要单独检查限制，累计输出可能超过 8,000 Token。

Token 上限也不等于可见回答的字数。推理内容是否占用额度取决于接口；如果希望回答简短，还可以在任务要求中指定表达长度。

## 2. 配置语义

| 情况 | 建议处理 |
|---|---|
| 未设置 | 采用应用默认值；没有额外默认策略时再使用模型能力上限 |
| 设置正整数 | 作为单次请求的配置上限 |
| 超过模型能力 | 校验拒绝，或裁定到模型能力上限并展示生效值 |
| 零或负数 | 明确约定为非法值或未设置，不隐式解释为无限制 |

任务级配置、用户偏好和管理员策略可以分层保存，但用户设置不能突破管理员强制上限。界面应区分配置值和最终生效值，避免用户以为更大的填写值一定会被接口接受。

## 3. 最终请求上限

在上下文与任务预算都足够，且没有其他强制限制时，可以按以下逻辑计算。示例假定模型上限已知且配置值已通过正整数校验：

```ts
const effectiveMaxOutputTokens = Math.min(
  modelMaxOutputTokens,
  outputTokenLimit ?? modelMaxOutputTokens,
);
```

实际运行时还需结合应用默认值、管理员上限、模型剩余上下文和任务可用预算裁定。剩余预算不足以发起请求时，应停止或进入收尾，不直接发送零额度请求。

例如，模型输出限制为 128,000 Token，用户设置 8,000 Token，其他约束均满足，则本次请求采用 8,000 Token。若模型生成 500 Token 就结束，实际用量为 500，不会按配置值记录为 8,000。

接口参数可能叫 `max_tokens`、`max_output_tokens` 或使用其他名称，由适配器转换。参数名本身不能说明它来自用户配置、模型能力还是运行时裁定。

## 4. 执行与超限处理

配置应在服务端校验并参与每次请求的计算，不能只依赖界面限制。任务内更换模型或继续执行时，应重新计算生效值。

达到输出上限后检查截断状态，不将不完整产物直接视为成功。继续生成属于新的模型调用，需要重新检查任务剩余预算，不能通过不断续写绕过整轮任务限制。
