# 模型输出限制

模型输出限制是某个模型通过指定服务接口能够生成的最大输出 Token 数，描述模型服务的能力边界。可以用 `modelMaxOutputTokens` 表示。

## 1. 限制来源

上限由模型版本、提供商、接口和调用模式共同决定。同一个模型通过不同托管平台、同步或异步接口调用时，支持的上限可能不同，应按实际调用入口维护能力配置。

本地记录的上限用于请求校验，不能提高服务端实际能力。未知上限应明确标记或采用应用定义的保守策略，不能将未知直接当作无限制。

## 2. 与上下文窗口的关系

最大输出与上下文窗口是两个约束。对于输入、推理与输出共享窗口的模型，本次输出还受剩余窗口空间限制；对于分别限制输入和输出的接口，应按其各自口径检查。

例如，假设模型共享窗口为 128,000 Token，最大输出为 16,000 Token：

| 本次输入 | 按容量计算可容纳的最大输出 |
|---|---:|
| 100,000 Token | 16,000 Token |
| 120,000 Token | 8,000 Token |

以上仅展示容量关系；实际请求还应考虑输入估算误差、接口规则及必要余量。推理 Token 是否包含在输出限制中，需要按提供商定义处理。

## 3. 与配置和实际用量的区别

模型输出上限为 128,000 Token，不意味着每次都应请求生成这么多。调用方可以通过用户输出限制设置更低的上限。

最终请求上限不能超过模型能力，还需要满足上下文容量和任务剩余预算。实际输出数量由本次生成决定，通过用量统计记录，通常可以小于请求上限。

## 4. 超限与截断

- 请求值超过接口支持的上限时，服务端可能拒绝请求，或按其规则处理；适配器应尽可能提前校验。
- 生成达到已接受的上限时，接口可能返回长度截断状态，不一定报错。
- 截断可能导致回答、JSON、代码或工具参数不完整，运行时应检查结束原因和结构完整性。

能力配置应记录模型标识和适用入口，更新模型或接口时同步核对，避免把旧版本的上限直接沿用到新版本。
