# 模型输入限制

模型输入限制是指定模型服务接口能够接受的最大输入 Token 数，可以用 `modelMaxInputTokens` 表示。它描述接口能力，与用户配置的输入上限分别保存。

## 1. 输入范围

输入包括系统与开发者指令、用户消息、历史回答、工具定义、工具结果和其他传入上下文，不能仅统计用户最后一条消息。

图片、音频和文件等按接口规则计量，还可能受到数量、大小、分辨率等独立限制。满足 Token 上限不代表一定满足全部请求限制。

## 2. 与上下文窗口的关系

| 接口口径 | 输入容量的处理方式 |
|---|---|
| 分别限制输入与输出 | 按接口公布的输入上限检查，同时独立检查输出上限 |
| 输入与生成共享窗口 | 输入与预留的生成空间之和不能超过上下文窗口 |

共享窗口的模型不一定单独公布固定的最大输入值，此时应保存上下文窗口和输出规则，按本次请求计算可用输入空间，而不是将窗口大小直接当作可全部使用的输入额度。

例如，假设共享窗口为 128,000 Token，本次为生成预留 16,000 Token，则按容量计算可用于输入的空间为 112,000 Token。实际还需要根据估算误差和接口开销保留余量；推理 Token 按接口规定纳入对应预算，避免重复扣减。

## 3. 能力配置与实际输入

输入能力由模型版本、提供商和调用入口共同决定，应记录适用范围。未知上限不等于无限制，也不能把其他托管平台的配置直接当作当前接口的保证。

`modelMaxInputTokens` 表示已知的固定输入能力上限；`effectiveMaxInputTokens` 可以表示结合配置、生成预留和任务预算后，本次实际允许的输入上限。实际输入用量则通过 `usage.inputTokens` 记录。

这些名称是内部接口设计示例，不代表提供商存在同名参数。输入限制通常需要调用方在发送前校验，不能假定接口会接收一个输入上限参数并自动裁剪。

## 4. 超限处理

调用前估算完整请求的输入用量，超过容量时减少工具定义、选择必要历史、压缩或拒绝调用。要求信息完整的任务应明确哪些内容不能删除。

裁剪需要保留必要指令、当前任务和完整的工具调用与结果关联。不能简单从文本尾部截断，否则可能破坏消息结构或丢失关键要求。

服务端可能因超限拒绝请求。实际用量返回后可校正后续估算，但不能据此保证第一次调用不会超限。
