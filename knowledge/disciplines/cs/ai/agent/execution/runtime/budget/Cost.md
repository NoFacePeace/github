# Agent 费用预算

费用预算（Cost Budget）限制 Agent 完成任务允许产生的成本，可以覆盖模型调用、工具服务和执行环境。它比单纯限制 Token 更直接地表达成本目标。

## 1. 费用范围

| 类别 | 示例 |
|---|---|
| 模型输入 | 普通输入、缓存读取与缓存写入 |
| 模型输出 | 可见回答及按接口规则计费的推理 Token |
| 工具服务 | 搜索、网页抓取、付费数据查询 |
| 执行环境 | 沙箱、远程计算、存储和网络 |

应明确是否包含子 Agent、内部摘要和评审调用，以及哪些费用暂时无法实时统计。

## 2. 计算口径

```text
任务费用 = 各次模型计费项目之和 + 工具费用 + 执行环境费用
```

各模型计费项目按对应 Token 数量乘以单价计算，并换算计价单位。同一 Token 不应在普通输入和缓存输入类别重复计费；推理用量已经包含在输出中时，也不能重复收费。

记录模型标识、价格版本、币种和计费类别。价格调整或多币种结算时，应明确使用调用时价格、结算价格以及汇率口径。

## 3. 调用前预留

1. 读取任务剩余金额，扣除其他并发操作已预留的金额。
2. 根据输入估算、输出上限和工具收费规则预留本次成本。
3. 可用金额不足时缩减允许的消耗，或不发起调用。
4. 完成后按实际费用结算，释放未使用部分。

如果工具价格未知或执行时间无法准确预测，应设置额外约束或保留余量。失败和取消不代表没有费用，无法确认时应保留待结算状态。

## 4. 超限与账本

软预算用于提前收尾，硬上限用于停止新操作。远程调用仍可能继续执行，实际账单也可能延迟到达，因此仅靠本地检查不一定保证最终账单绝不超过目标金额。

账本应区分已结算、已预留和待确认费用，并按调用标识去重。子 Agent 的成本应归入根任务，同时保留各自明细，避免汇总时重复计算。

## 5. 如何设置

依据单次任务的业务价值、成功率和可接受成本设定金额上限，按任务类型调整。模型、价格或工具组合变化后重新测量，不能用固定 Token 数量永久对应固定金额。
