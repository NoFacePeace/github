# Agent 步数预算

步数预算（Step Budget）限制 Agent 在一次任务中推进执行循环的次数，主要用于防止持续循环和反复尝试。

## 1. 一步的定义

一种常见定义是：执行循环调用一次模型算一步。模型返回后可以执行零个、一个或多个工具；携带工具结果再次调用模型，进入下一步。

```text
第 1 步：调用模型 → 执行工具
第 2 步：调用模型 → 执行多个工具
第 3 步：调用模型 → 返回最终回答
```

这个例子执行了三步，工具调用数量不一定是三次。“步数”描述计数，“步长”通常描述每次前进的幅度，两者应区分。

## 2. 计数范围

| 调用来源 | 需要明确的规则 |
|---|---|
| 主执行循环 | 每次模型请求何时扣减一步 |
| 自动重试 | 每次实际请求单独计数，还是仅计一次逻辑步骤 |
| 摘要与内部评审 | 与主循环共用额度，还是设独立额度 |
| 子 Agent | 独立设置子预算，并明确是否计入根任务总调用上限 |
| 暂停与恢复 | 延续已有计数，还是经明确授权开启新的预算周期 |

若限制的是逻辑循环次数，一步内的请求重试仍需独立限制，否则不能据此推导实际模型请求数量。

## 3. 执行与超限处理

1. 调用前检查剩余步数，原子占用本次额度。
2. 持久记录步骤和结果，避免恢复后隐式清零。
3. 接近上限时保留最后若干步用于收尾，必要时禁用工具扩展。
4. 用尽后停止发起调用，说明任务完成还是预算耗尽。

禁用工具只是请求约束，还应检查响应，不能继续执行违反约束的工具调用。重试需要重新检查额度；并发调用也不能分别读取同一份剩余额度后重复使用。

## 4. 局限与设置方法

相同步数的任务可能有不同的上下文规模、输出长度、工具成本和耗时。步数预算不能代替 Token、费用或时间预算。

可以根据代表性任务的成功率、步骤分布和重复尝试情况设定上限，并分别配置主 Agent 与子 Agent。没有适合所有任务的统一步数标准。
