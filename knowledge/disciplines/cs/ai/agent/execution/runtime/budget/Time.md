# Agent 时间预算

时间预算（Time Budget）限制 Agent 或其某项操作能够持续执行的时间，用于控制等待体验、资源占用和长时间无进展的执行。

## 1. 限制层级

| 层级 | 限制对象 |
|---|---|
| 单次模型请求 | 包含重试前后需要明确的请求时间范围 |
| 单次工具执行 | 命令、网络请求或其他工具操作 |
| 子任务 | 子 Agent 从启动到结束的时间 |
| 整轮任务 | 用户任务从启动到完成或停止的时间 |

子操作的有效超时应不超过父任务剩余时间。工具自己的超时设置不能隐式延长整个任务的截止时间。

## 2. 时间口径

- 总历时：从开始到结束经过的时间，可以包含排队、审批和等待用户的时间。
- 活跃执行时间：仅累计系统实际执行的时间，按规则暂停计时。
- 无进展时间：距离上次有效进展的时间，用于识别持续等待或停滞。

需要明确预算采用哪种口径。持续输出日志不一定代表任务取得进展；若使用无进展超时，应定义有效进展的判定方式。

## 3. 执行与传播

```text
确定任务截止时间
    ↓
检查父任务剩余时间
    ↓
设置本次请求或工具的有效超时
    ↓
执行并检查取消信号
    ↓
继续执行 / 收尾 / 超时停止
```

单个进程内测量耗时应优先使用单调时钟。跨进程恢复时持久化截止时间和已消耗时长，并明确重启、暂停和时钟变化的处理方式，不能恢复后自动重新获得完整时限。

## 4. 超时处理

到达软时间预算时开始保存进度和整理结果，保留必要的收尾时间。到达硬上限后停止新操作，向进行中的请求和子任务传播取消信号，并在限定时间内完成清理。

取消请求不保证远程服务立即停止，也不撤销已经完成的外部操作。结果不明的操作应先查询状态，再决定是否重试；不要把超时直接当作操作未执行。

## 5. 并发与设置方法

多个并发子任务共享同一个父任务截止时间，但各自执行时长之和可能大于父任务总历时。若要限制总计算消耗，应另外统计累计执行时长或费用。

根据任务耗时分布、用户可接受等待时间和工具特性设置时限，并观察超时率和成功率。交互任务与后台长任务通常需要不同设置，没有统一的分钟数标准。
