# Subagent

Subagent（子智能体）是由主 Agent 调用或管理、承担部分任务的 Agent。主 Agent 将工作委派给子智能体，接收其结果，并继续协调任务或向用户交付最终产物。

## 1. 与委派的区别

| 概念 | 含义 | 示例 |
|---|---|---|
| Delegate（委派） | 将任务交给其他执行者处理的动作或机制 | 将代码审查交给审查 Agent |
| Subagent（子智能体） | 在主 Agent 协调下承担部分工作的角色 | 接受审查任务、分析代码并返回发现的 Agent |

主 Agent 可以将任务委派给 Subagent，也可以委派给独立 Agent、外部服务或工作流。不同框架可能把 delegate 定义为具体接口，其行为应以框架文档为准。

## 2. 基本协作流程

1. 主 Agent 定义子任务，明确输入、输出、约束和完成条件。
2. 创建或选择子智能体，提供必要的上下文、工具与权限。
3. 子智能体执行任务并返回结果，或报告需要补充的信息。
4. 主 Agent 检查结果，必要时补充要求或安排复核。
5. 主 Agent 汇总结果，继续推进整体任务。

例如，主 Agent 编写功能时，将独立的代码审查交给子智能体；子智能体返回问题列表，由主 Agent 判断并修正。

## 3. 常见设计选择

- 顺序或并行：子任务可按依赖顺序执行，也可并行处理相互独立的工作。
- 通用或专用：子智能体可以处理通用任务，也可以配置为审查、检索等专门角色。
- 模型选择：主 Agent 与子智能体可以使用相同模型，也可以根据任务使用不同模型。
- 上下文传递：可以传递完整历史、摘要或限定的任务材料，具体取决于平台与任务需求。
- 执行环境：多个智能体可以共享文件系统，也可以使用独立环境。

Subagent 不天然意味着并行执行、不同模型或独立沙箱。独立对话上下文也不代表进程、文件和网络已经隔离。

## 4. 工程设计要点

- 按清晰的任务边界委派，避免上下文不足或多个智能体重复工作。
- 对共享文件明确写入责任，防止并行修改相互覆盖。
- 设置时间、调用次数、并发与费用预算，处理超时、失败和取消。
- 检查返回结果及实际产物，不仅依赖子智能体的完成声明。
- 根据任务收益决定是否委派；上下文传递、协调和复核也会增加成本。
