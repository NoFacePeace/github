# 上下文去重

去重（Deduplication）是识别重复信息后，合并、替换或移除冗余内容，以减少上下文占用的操作。它关注信息是否重复，与按长度截取正文的截断不同。

## 1. 常见规则

- [工具结果去重](Tool.md)：工具名、有效参数和结果内容一致时，保留一份正文，其余替换为重复提示。
- 重复检索命中：同一文档版本及相同片段重复出现时，合并来源与必要信息。
- 重叠文件读取：文件版本相同且读取范围重叠时，保留覆盖范围更完整的内容。
- 不变状态轮询：状态连续不变时，合并重复记录，保留首次、最近一次及重复次数等必要信息。

这些规则需要根据任务选择，不代表所有运行时都实现了相同策略。

## 2. 消息处理

可以保留工具调用和结果消息，只把旧结果正文替换为“内容重复，参见后续结果”。也可以删除重复交互，但应维护调用与结果配对；同一助手消息包含多个工具调用时，需要分别处理。

重复提示应能定位仍然保留的结果，避免后续裁剪删除了被引用的正文，留下无法解释的提示。

## 3. 判断边界

- 相同工具和参数不一定产生相同结果，尤其是日志、指标和状态查询。
- 相同结果出现在不同时间也可能有价值，例如证明某状态持续存在。
- 结果哈希可辅助判断内容一致，但仍需考虑来源、版本、时间和任务目的。
- 不应将两次内容相同的用户要求简单视为冗余；重复可能表达强调或纠正。

## 4. 与状态更新的区别

旧计划被新计划替代，属于状态更新后的历史精简，不一定是内容重复。实现中即使统一放在去重流程里，也应分别定义“重复”和“已被替代”的判定规则。
