# 触发条件

触发条件描述满足什么判断后执行某项上下文管理操作。检查可以每次进行，实际处理只在条件满足时发生。

## 1. 常见条件

| 条件 | 可触发的操作 |
|---|---|
| 单条工具结果超过长度上限 | 外置、截断或分段返回 |
| 整体输入占用超过预算阈值 | 去重、裁剪、外置或摘要压缩 |
| 确认信息重复 | 合并重复项或替换旧正文 |
| 新状态成功替代旧状态 | 清理过时计划或状态记录 |
| 子任务完成、任务阶段切换 | 整理结论，精简阶段性过程 |
| 模型接口返回上下文超限错误 | 进一步缩减输入并按策略重试或报错 |

不同操作可以使用不同条件，不必全部等到整体超限才执行。

## 2. 阈值定义

- 明确计量对象：单条结果、消息历史，还是包含工具定义的完整请求。
- 明确计量单位：字节、字符、行数或 Token。
- 明确预算来源：模型窗口、输出预留和其他必要余量。
- 区分本地估算与服务端实际用量，必要时根据实际结果校准估算。

## 3. 高低水位

可以设置较高的触发阈值，以及较低的处理后保留目标，减少连续迭代中反复精简。

例如，超过某个预算比例时开始处理，降到更低比例后停止。也可以以本次处理前或某阶段处理后的体积为基准设置目标，但必须明确基准，不能把不同口径的百分比直接比较。

## 4. 例外与停止条件

需要定义受保护内容、禁止有损处理的任务，以及无法达到目标时的行为。没有可删除内容、引用来源不可用或仍然超预算时，应进入明确的恢复或报错路径，避免无限精简。
