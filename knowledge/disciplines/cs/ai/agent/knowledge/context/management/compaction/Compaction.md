# 上下文压缩

上下文压缩（Context Compaction）是将已有上下文转换为更紧凑表示的过程，目标是在减少 Token 占用的同时，保留后续执行所需的关键信息，使 Agent 能够持续处理较长的对话和任务。

## 1. 保留的信息

- 用户目标、约束和已确认的要求。
- 已完成的工作、关键结论和决策依据。
- 当前任务状态、相关文件和必要的工具结果。
- 尚未解决的问题和下一步行动。

例如，多轮问题排查过程可以整理为：“已确定问题出在登录缓存，修改了两个文件，测试通过，接下来检查退出登录行为。”实际压缩结果也可以采用结构化状态或模型支持的其他紧凑表示，不一定是自然语言摘要。

## 2. 压缩策略

- [摘要压缩](summarization/Summarization.md)：将历史对话和执行过程整理为任务摘要。
- [摘要提示词](summarization/Prompt.md)：摘要压缩请求的组织方式与长度要求。
- 结构化整理：按目标、约束、结论、进度和待办保存状态。
- 冗余消除：合并重复信息，精简冗长的工具输出。

压缩与裁剪、外置可以结合使用。压缩强调用更紧凑的表示承载信息；裁剪强调移除选定内容；外置强调将详细内容保存在外部，并按需读取。三者都属于上下文管理，具体系统中的实现边界可能重叠。

## 3. 运行机制

[运行时](../../../../execution/runtime/Runtime.md)负责将压缩接入 Agent 的执行流程，具体方式取决于框架或服务。

1. 监测上下文占用，或在任务阶段切换时判断是否需要压缩。
2. 调用压缩能力，或通过模型生成任务摘要。
3. 将压缩结果与需要保留的消息组成后续上下文。
4. 继续执行，并在需要时重新读取原始文件或查询资料。

压缩策略关注“压什么、如何表示”；运行机制关注“何时触发、如何调用、压完如何继续”。

## 4. 局限

压缩可能遗漏细节或弱化约束，不能默认等同于完整保留原始记录。关键要求和精确数据应明确保留；影响后续判断的代码、日志和工具结果，可以按需重新读取和核实。

上下文压缩作用于模型后续使用的输入信息，本身不会修改项目文件，也不等于压缩模型参数。
