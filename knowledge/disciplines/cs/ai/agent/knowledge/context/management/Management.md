# 上下文管理

上下文管理（Context Management）是运行时围绕当前任务，选择、组织和调整模型输入的过程。它既包括控制哪些信息进入上下文，也包括处理已经累积的历史。

## 1. 执行阶段

| 阶段 | 主要工作 |
|---|---|
| 工具调用前 | 选择必要工具，设置过滤、分页和返回范围 |
| 工具返回后 | 检查单条结果大小，按需外置或截断 |
| 模型调用前 | 组装消息，检查整体预算，精简历史并维护工具配对 |
| 历史摘要时 | 选择待压缩历史，生成摘要并与近期原文重新组合 |

各阶段是否执行、由谁触发以及使用哪些阈值，取决于具体运行时。摘要可以在新一轮开始前执行，也可以接入执行循环。

## 2. 操作方式

本文将操作方式与执行阶段分开描述，采用以下口径：

| 操作 | 含义 |
|---|---|
| 裁剪 | 选择性删除消息、工具调用或交互块 |
| 截断 | 按长度限制保留正文片段 |
| 去重 | 合并或替换重复内容 |
| 外置 | 将内容保存在外部，上下文保留引用并支持按需读取 |
| 摘要压缩 | 用任务摘要替换详细历史 |

整体处理过程称为“上下文精简”，其中可以组合多种操作。实际框架对 pruning、truncation、compaction 等术语的范围可能有不同约定。

## 3. 基本约束

- 保留有效指令、当前任务要求和必要状态。
- 维护工具调用与结果的关联，避免产生不合法的消息结构。
- 外置后提供可访问的引用及读取方式；仅保存日志不等于完成外置。
- 精简后重新检查占用，为模型输出和后续执行预留空间。
- 区分原始执行记录与实际发给模型的输入；两者可能因截断、裁剪或摘要而不同。
