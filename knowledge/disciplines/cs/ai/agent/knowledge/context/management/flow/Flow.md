# 上下文管理流程

上下文管理流程描述运行时在什么阶段检查和调整模型输入、满足什么条件才执行，以及多种操作之间的顺序。具体阶段与策略由运行时决定，以下是一种可组合的组织方式，不是所有 Agent 必须采用的固定流程。

## 1. 时机、条件与顺序

| 维度 | 回答的问题 | 示例 |
|---|---|---|
| [执行时机](Timing.md) | 在哪个阶段检查或处理 | 工具返回后、模型调用前 |
| [触发条件](Triggers.md) | 什么情况下执行某项操作 | 单条结果超限、整体占用超阈值 |
| [执行顺序](Order.md) | 多项操作如何衔接 | 先保存全文，再用引用替换正文 |

每次进入某个阶段都可以检查条件，但不代表每次都会执行精简。

## 2. 新一轮开始前

1. 读取有效指令、任务状态、已有摘要和需要延续的历史。
2. 确定历史保留范围，并估算组装后的输入占用。
3. 历史过大时，可以先处理旧内容，或生成历史摘要。
4. 将已有摘要、保留的近期原文和当前用户输入组成模型上下文。

摘要压缩可以安排在这一阶段，也可以接入 Loop。已经存在的摘要不需要每轮重新生成。

## 3. 工具调用前

- 选择当前步骤需要的工具和参数。
- 通过过滤、字段选择、行数限制和分页控制返回范围。
- 对预期很大的输出，可以提前设置保存位置，避免先将全文传入模型再处理。

## 4. 工具返回后

1. 获取执行状态和输出，并检查单条结果大小。
2. 不超限时，按工具约定返回结果。
3. 超限且后续可能需要全文时，先确认完整内容已保存或原始来源仍可读取。
4. 生成必要片段、状态和读取引用，作为对应工具调用的结果返回。

只截取片段而不提供可恢复来源，属于截断；保存内容并提供读取入口，才形成可恢复的外置流程。普通代码可以完成这些操作，不一定需要额外模型请求。

## 5. 每次模型调用前

### 5.1 检查预算

估算消息、工具定义等输入占用，并结合模型窗口、输出预算和必要余量判断是否需要处理。可以参考此前模型返回的实际用量校准估算。

### 5.2 精简历史

超过预设阈值时，可以按以下顺序处理：

1. 标记有效指令、当前输入、必要状态和证据等保护对象。
2. 合并确认重复的信息，清理已被有效新状态替代的旧记录。
3. 将不必常驻的详细内容外置，或对适合保留片段的输出做截断。
4. 按完整消息块裁剪可删除的旧交互。
5. 如果运行时支持 Loop 内摘要，可在仍需缩减时压缩旧历史。

这是一种策略顺序，具体实现可以调整。不可恢复且仍有价值的内容，不能未经保留就删除；外置依赖新保存记录时，应先保存成功，再替换正文。

### 5.3 检查处理结果

- 检查工具调用与结果的配对、顺序及消息结构。
- 检查外置引用和去重引用是否仍然有效。
- 重新估算占用，确认是否满足预算。
- 仍然过大时，按策略进一步精简、摘要或明确报错，避免无限处理。

可以设置低于触发阈值的保留目标，一次释放更多空间，减少连续迭代中反复触发精简；目标比例和度量单位需要明确。

## 6. 继续或结束

```text
组装上下文
    ↓
模型调用前检查与精简
    ↓
调用模型
├─ 请求工具 → 控制返回范围 → 执行工具 → 处理结果 → 回到调用前检查
└─ 完成任务 → 保存执行记录和必要状态
```

上下文精简调整的是后续模型输入，不必同步删除原始历史。只把已进入上下文的内容保存到文件，并不会自动消除已有占用，运行时仍需要实际替换或移除后续输入中的正文。
