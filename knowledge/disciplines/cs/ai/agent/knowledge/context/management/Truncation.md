# 上下文截断

截断（Truncation）是按 Token、字符、字节或行数等长度限制，只保留正文片段的操作。本文按上下文管理中的操作口径，将截断与选择性删除消息或交互块的裁剪分开描述。

## 1. 常见方式

| 方式 | 做法 | 适用情况 |
|---|---|---|
| 保留开头 | 超出长度后省略剩余部分 | 重要说明集中在开头的输出 |
| 保留结尾 | 只保留末尾一定长度 | 末尾包含执行结论或错误的日志 |
| 保留首尾 | 展示开头和结尾，中间插入省略标记 | 同时需要启动信息与最终结果的输出 |

截断按位置和长度选取内容，不保证保留所有重要信息。

## 2. 执行阶段

- 工具结果处理：单条输出超限时，截取片段后返回模型。
- 历史上下文精简：整体占用过高时，缩短选定的旧消息正文。
- 摘要输入准备：待摘要历史仍然过大时，进一步限制输入长度。

## 3. 执行要点

- 明确长度单位，不能将字节、字符和 Token 视为等价。
- 按字符边界截取文本，避免破坏 UTF-8 编码。
- 标注省略位置和数量，避免将片段误当成全文。
- 截断结构化结果可能破坏 JSON 等格式；可改用合法的结果封装，明确说明正文只是片段。
- 不修改工具调用标识等协议字段，保持消息关联有效。

## 4. 与外置的区别

截断本身不负责保存被省略的内容。需要恢复全文时，应先确认原文已保存到可访问的位置，再返回片段和读取引用；这时截断与外置共同参与处理。
