# DS Bot

DS Bot 是基于 DeepSeek Harness（DSH）的社区开源 Bot 应用，也可以作为 `ds-bot` 插件安装在 DSH 中。用户可以创建具有角色、模型配置和记忆的 Bot，通过私聊、群聊和任务委派完成工作。项目采用 Apache-2.0 许可证，与 DeepSeek 公司没有隶属、认可或赞助关系。

本文依据项目 README、插件文档与源码整理，核对日期为 2026-11-06；功能说明不代表已经实测其质量与稳定性。项目处于早期版本，接口和数据格式可能变化。

## 1. 系统层次

| 层次 | 作用 |
|---|---|
| 模型 | 理解输入，生成回复和工具调用请求；多个 Bot 可以使用同一个模型 |
| [DeepSeek Harness（DSH）](../deepseek/DSH.md) | 提供模型接入、Agent 执行、会话、工具与插件运行基础 |
| DS Bot | 在 DSH 上组织 Bot 身份、群聊、记忆、权限和任务交接 |
| Bot | 用户持续交互的角色，具有自己的职责、指令、模型配置与工作目录 |
| Session | 承载某个 Bot 在具体聊天场景中的执行上下文与事件记录 |

每个 Bot 可以视为一个 Agent 角色，但 Bot 与底层 Session 不是永久的一对一关系：私聊和不同群聊使用不同会话，同一条长期聊天还可以分成多个 Session。

## 2. Bot 与群聊

### 2.1 角色与管理权限

首次使用时，默认创建主 Bot「Chief」。用户可以通过对话让它配置其他 Bot 和群聊。

| 角色 | 主要权限 |
|---|---|
| 用户 | 配置团队、模型、权限及其他设置 |
| Main Bot | 管理团队中的 Bot 与群聊；可以存在多个 Main Bot |
| 群管理员 | 管理自己负责的群聊，并组织成员回复与任务分工 |
| 普通成员 | 在群中工作、回复和向其他成员委派任务 |

管理 Bot 团队的权限与读写文件、运行命令的执行权限是不同维度。执行权限由用户配置，Bot 不能自行提升。

### 2.2 会话隔离

每个 Bot 在每个群聊中都有独立的成员 Session。群聊本身还有用于组织消息与转发的记录会话，不能把整个群理解成只有一个模型上下文。

例如，研究员与编辑加入项目 A 群后：

| 交互位置 | 执行会话 |
|---|---|
| 用户私聊研究员 | 研究员的私聊会话 |
| 研究员在项目 A 群中工作 | 研究员在项目 A 群的成员会话 |
| 编辑在项目 A 群中工作 | 编辑在项目 A 群的成员会话 |
| 研究员加入项目 B 群 | 研究员在项目 B 群的另一成员会话 |

群会话不会直接把 Bot 的私聊记录作为聊天上下文。不过，会话分离不等于完全没有共享信息：Bot 记忆、团队记忆以及用户主动引用的对话，仍可能提供跨会话背景。

### 2.3 协作与目标执行

群聊默认可以由管理员先回复，再按需调用成员；也可配置成员轮流发言。成员通过 `@` 交接任务，被同时提及的成员可以并行工作。执行过程与结果会回到群聊中。

较大的任务可以使用群聊 Goal：管理员与用户确定完成标准，将工作拆成阶段并分配成员，再根据结果检查进度。这个机制组织执行与验收，不保证模型自动完成所有复杂任务。

## 3. 记忆与能力

### 3.1 记忆范围

| 范围 | 用途 |
|---|---|
| Bot 记忆 | 保存某个 Bot 跨会话需要使用的偏好、决策与事实 |
| 群记忆 | 保存群内背景，供成员在该群的会话中使用 |
| 团队记忆 | 提供整个团队共享的背景信息 |

记忆以 Markdown 保存，包含核心文件和主题文件；用户可以查看和修改。每轮后的记忆审查可更新需要长期保留的条目。长期记忆、原始聊天记录与当前模型上下文属于不同数据层次。

### 3.2 工具与文件处理

- 可以通过 MCP 服务、Skills 和能力包扩展 Bot 工具。
- 支持网页搜索；桌面环境下可提供 Bot 浏览器，交互操作取决于启用的浏览器插件。
- 项目文档说明桌面版集成 Word、Excel 和 PowerPoint 文件创建、修改及渲染检查能力；Web 运行方式的支持范围有所不同。
- 支持定时任务；后台持续工作依赖运行它的电脑或服务器保持在线。
- 用量页按时间、Bot 和模型统计 Token，不能直接把 Token 数视为最终账单金额。

## 4. 部署、数据与权限

| 运行方式 | 说明 |
|---|---|
| 独立桌面应用 | 提供 Windows、macOS 和 Linux 安装包，自带所需的 DSH |
| DSH 插件 | 在已安装的 DSH 中添加 `ds-bot`，使用 DSH 提供的模型与工具 |
| Web / Docker | 可用于服务器、NAS 等常开环境，具体依赖与兼容性见安装文档 |

插件默认将团队数据放在 `$DSH_HOME/bot`，聊天 Session 保存在 DSH 的 `sessions` 目录；独立桌面应用使用自己的数据位置，首次启动可选择。备份时应同时保留团队状态与会话记录，只复制 Bot 配置不能保留全部聊天。

本地保存记录不代表模型推理在本地。接入云端模型时，执行所需的上下文会发往相应服务商，费用使用用户自己的模型额度。

Bot 可配置只读、工作区或完全访问权限。Docker 部署以容器作为隔离边界，挂载进容器的文件仍处于 Bot 可访问范围，需按实际工作配置权限与目录。

## 5. 长会话管理

[上下文管理](ContextManagement.md)记录长聊天的占用监测、上下文管家决策、原地压缩、Session 切换交接与历史检索实现。

同一个 Bot 在界面中的长期聊天，可以由多个底层 Session 连续呈现。切换会话按上下文压力和任务状态触发，不是固定每两轮交接一次。
