# Claude Code 检查点机制

Checkpointing 是 Claude Code 的会话状态管理机制，用于记录文件修改、回退代码与对话，以及将部分对话压缩为摘要。适合尝试不同实现、撤销错误修改和整理冗长的调试过程。本文依据官方文档整理，核对日期为 2026-11-02。

## 1. 检查点的创建与保留

每次用户发送开启新一轮工作的提示词时，Claude Code 都会创建检查点，捕获该轮开始前的代码状态。文件跟踪以 Claude Code 的文件编辑工具为基础，恢复范围受文件是否已被跟踪等条件限制。

- 每个会话保留最近 100 个检查点的文件快照。清理旧检查点时，会删除其他检查点不再引用的快照，但保留每个文件的首份快照，供 VS Code 扩展作为会话差异的基线。
- 检查点随对话保存，恢复会话后仍可使用 `/rewind`。
- 文件快照会按保留策略清理，默认约在会话最后一次保存快照的 30 天后清理；可通过 `cleanupPeriodDays` 调整。快照已被删除时，代码恢复可能失败并提示 `No files were restored`。

## 2. 回退代码与对话

输入 `/rewind`，或在提示词输入框为空时连续按两次 `Esc`，打开回退菜单。菜单列出历史提示词，选中一个位置后可选择以下操作：

| 操作 | 效果 |
|---|---|
| Restore code and conversation | 同时将代码与对话恢复到所选位置 |
| Restore conversation | 回退对话，保留当前代码 |
| Restore code | 恢复文件修改，保留当前对话 |
| Summarize from here | 将所选位置及后续对话压缩为摘要 |
| Summarize up to here | 将所选位置之前的对话压缩为摘要，保留后续消息 |
| Never mind | 返回消息列表，不执行操作 |

只有所选检查点之后存在可恢复的已跟踪文件修改时，菜单才会提供两种代码恢复选项。

### 2.1 输入框与回退后的行为

输入框有文字时，连续两次 `Esc` 会清空文字；清空的内容可通过 `Up` 从输入历史找回。

恢复对话或选择 Summarize from here 后，所选消息的原始提示词会重新填入输入框，便于修改后再次发送。选择 Summarize up to here 后，会停留在对话末尾，输入框为空。

恢复对话后，如果在发送下一条提示词之前退出，重新进入会话时，被回退的消息可能再次出现。可再次执行相同回退，并在退出前发送一条提示词，以保存回退后的对话状态；已恢复的文件不会因此重新改变。

### 2.2 工作期间追加的消息

Claude 仍在工作时追加的消息没有独立检查点，菜单中可能标记为 `No code restore`。若要撤销这条消息之后的文件修改，需要选择开启该轮工作的提示词并恢复代码；这会恢复整轮的文件修改，包括追加消息之前的修改。

## 3. 对话压缩

两种 Summarize 操作都在当前会话内压缩上下文，不修改磁盘文件。原始消息仍保留在会话记录中，压缩位置会显示 Summarized conversation 标记。

用方向键选中某个 Summarize 操作后，可以在 `add context (optional)` 处输入希望摘要关注的内容，再按 `Enter`。直接按对应数字键会立即执行摘要，不经过补充说明步骤。

压缩适合释放上下文空间。若希望保留原会话并另开分支尝试方案，可使用 `/branch` 或 `claude --continue --fork-session`。

## 4. 恢复范围与限制

### 4.1 Bash 与外部修改

仅由 Bash 命令修改、从未被当前对话中的文件编辑工具编辑过的文件，不会被检查点跟踪。文件一旦被 Claude 的文件编辑工具编辑，之后 Bash 对该文件的修改也可以随检查点回退。

手动修改和其他并发会话的修改通常不会被捕获，但如果修改的是当前会话已跟踪的同一文件，也可能受到恢复操作影响。因此，恢复前需要审阅涉及文件的差异。

### 4.2 子 Agent 修改

子 Agent 修改能否恢复取决于运行方式：

- 前台运行且配置 `context: fork` 的 Skill 在当前轮次的工作树中编辑文件，其修改可正常回退；可通过 `background: false` 配置前台运行。
- 其他子 Agent 通常只有对当前对话已经跟踪的文件所做的修改能被恢复；对其他文件的修改会保留。后台 fork Skill 和后台 `/code-review --fix` 也属于此类情况。

### 4.3 符号链接与硬链接

代码恢复会跳过符号链接或硬链接文件，并显示 `Restored the code, but skipped N files`。这些文件保留当前内容，需要手动撤销或要求 Claude 反向修改。

恢复前可运行 `/debug` 开启调试日志，在 `~/.claude/debug/<session-id>.txt` 中查看跳过的路径与原因。

### 4.4 与 Git 的分工

检查点用于会话内快速恢复，Git 用于持久版本历史、分支与协作。对未跟踪文件、子 Agent 修改等超出检查点恢复范围的变化，应结合 Git 等版本管理方式处理。
