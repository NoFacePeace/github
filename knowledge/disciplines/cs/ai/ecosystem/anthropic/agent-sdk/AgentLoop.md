# Agent Loop

Claude Agent SDK 的 Agent Loop 是围绕目标持续调用模型、执行工具并反馈结果的循环。SDK 将 Claude Code 的自主执行循环嵌入应用，调用方可以配置工具、权限、轮次与费用限制，无需自行驱动每次模型和工具之间的切换。本文依据官方文档整理，核对日期为 2026-11-01。

## 1. 执行流程

1. 接收任务，将用户输入、系统提示、工具定义和会话历史提供给模型。
2. 模型输出文本、一个或多个工具调用，或同时输出两者。
3. 运行时检查权限、执行工具，并将工具结果交回模型；Hooks 可以在执行前后介入。
4. 模型结合结果继续下一轮，直到返回不含工具调用的最终回答，或遇到限制、错误等终止条件。
5. SDK 输出最终结果及用量、费用和会话信息。

```text
用户任务 → 模型评估 → 请求工具 → 工具执行 → 结果反馈
              ↑                              │
              └────────── 下一轮 ──────────────┘
              │
              └→ 最终回答 → 运行结果
```

一次模型响应可以包含多个工具调用，因此工具调用次数不等于轮次数。`max_turns` / `maxTurns` 限制轮数，`max_budget_usd` / `maxBudgetUsd` 设置费用阈值；最终纯文本回答也需要一轮，设置轮数时应为其保留空间。

## 2. 消息流与核心循环

| 消息类型 | 用途 |
|---|---|
| `SystemMessage` | 初始化、上下文压缩等会话生命周期事件 |
| `AssistantMessage` | 模型输出的文本或工具调用 |
| `UserMessage` | 工具执行结果，以及执行期间输入的用户消息 |
| `StreamEvent` | 启用部分消息后提供的文本增量、工具参数增量等流式事件 |
| `ResultMessage` | 本次循环的最终结果、状态、用量、费用与会话 ID |

Python 中的 `async for message in query(...)` 用于接收这些消息。模型与工具之间的循环由 SDK 的运行能力自动推进，不需要调用方收到工具调用消息后再手动执行内置工具。

应检查 `ResultMessage.subtype` 判断正常结束、轮次用尽、费用达到阈值或执行错误。结果消息后仍可能有少量系统事件，消费消息流时应迭代至结束。

## 4. 运行能力与源码边界

官方将上述循环作为 Agent SDK 的能力进行说明。Python 与 TypeScript SDK 都捆绑原生 Claude Code 二进制程序，核心运行能力由其提供；Python SDK 通过子进程通信接入，并处理消息、控制协议和回调。

因此，“SDK 包含 Agent Loop 的运行能力”与“Python SDK 仓库未公开核心循环的完整实现”可以同时成立。官方的运行机制文档说明行为和使用方式，不等于公开了对应实现源码。
