# 嵌入模型

嵌入模型（Embedding Model）是将文本、图片等输入编码为数值向量的模型。现代文本嵌入模型通常是经过训练的神经网络，用于让向量之间的关系反映输入在特定任务上的相似性。

## 1. 文本如何转换为向量

常见的文本编码流程为：

```text
文本 → 分词与 token 编号 → 模型编码 → 汇总表示 → 向量
```

1. 分词：通过分词器将文本转换为 token 编号。这里的 token 不一定对应完整的词，也不一定与全文检索的分词结果一致。
2. 编码：模型根据输入及上下文计算 token 的向量表示，常见编码器采用 Transformer 架构。
3. 汇总：通过平均池化、特定 token 表示等方式，形成代表整段文本的固定维度向量；具体方法取决于模型。
4. 后处理：按模型要求执行投影、归一化等处理，得到用于下游任务的向量。

以句向量模型为例，下面的数字仅作示意：

```text
“如何减少内存占用” → 模型 → [0.12, -0.35, 0.81, ...]
“怎么降低内存消耗” → 模型 → [0.14, -0.32, 0.79, ...]
```

向量的每个维度通常没有独立、明确的人类可读含义，多个维度共同表达输入特征。并非所有嵌入模型都输出单个稠密向量，也有输出多个向量或稀疏表示的模型。

## 2. 为什么能表达相似性

模型通过训练学习哪些输入应当接近、哪些输入应当区分。例如，对比学习可以使用相关的查询与文档作为正样本，使用不相关或容易混淆的内容作为负样本，调整它们在向量空间中的关系。

相似性取决于训练目标和数据：适合语义检索的模型，不一定最适合文本去重或分类。向量接近也不代表内容事实一致，例如肯定句与否定句可能因为共享主题而接近。

嵌入向量不是普通哈希值。哈希通常不要求保留语义关系，而语义嵌入的训练目标正是让特定相关性能够通过向量计算体现出来。

## 3. 常见用途

- 语义检索：分别编码查询和候选内容，通过相似度查找相关资料。
- 聚类：将表示相近的内容组织为主题簇。
- 分类：将嵌入向量作为分类器的输入特征。
- 相似内容识别：发现近似文本或重复内容，但是否判定为重复仍需结合任务标准。

## 4. 与生成模型的区别

| 对比 | 嵌入模型 | 文本生成模型 |
| --- | --- | --- |
| 典型输入 | 文本等待编码内容 | 提示、问题与上下文 |
| 典型输出 | 数值向量 | 逐步生成的 token 序列 |
| 常见用途 | 检索、聚类、相似度计算 | 问答、写作、摘要等 |

两者都可以采用神经网络和 Transformer 架构，区别主要在训练目标、输出形式与使用方式。嵌入模型不负责直接生成自然语言答案；生成模型的内部表示也不一定适合直接作为检索向量。

在采用向量检索的 RAG 中，嵌入模型帮助查找资料，生成模型根据检索资料与问题生成回答。RAG 也可以使用不依赖嵌入模型的检索方式。

## 5. 使用关注点

- 向量空间一致性：查询与文档必须使用兼容的编码方式；仅维度相同不足以保证向量可比较。
- 输入格式：遵循模型对查询、文档前缀或指令的要求。部分检索模型使用分别训练且相互对齐的查询编码器与文档编码器。
- 长度限制：检查 token 上限和截断行为，避免关键内容被截断；长文档通常需要先切分。
- 相似度度量：按模型要求选择余弦相似度、内积等度量，并确认是否需要归一化。
- 模型升级：更换模型或编码配置后，已有文档向量通常需要重新生成，不能直接与新查询向量混用。
- 效果评估：根据目标语言、领域和真实查询评估检索或分类质量，同时考虑速度、维度、存储与运行成本；维度更高不保证效果更好。
