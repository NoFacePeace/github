# 检索增强生成

检索增强生成（Retrieval-Augmented Generation，RAG）是在生成回答时，从外部数据源检索相关资料，将资料与用户问题共同提供给生成模型的方法。它让模型能够利用私有资料或更新后的内容，通常不需要为每次资料更新重新训练模型。

RAG 可以通过固定工作流实现，也可以由 Agent 决定检索时机和后续动作，本身不要求具备自主规划或工具选择能力。

## 1. 基本流程

```text
用户问题 → 检索相关资料 → 组织上下文与问题 → 模型生成 → 返回回答与来源
```

1. 检索：根据问题从知识库、数据库、网页等来源查找相关内容。
2. 上下文组织：选择、去重和裁剪资料，保留来源，并与问题、回答要求一起构成模型输入。
3. 生成：模型依据问题及检索资料生成回答；当资料不足或互相冲突时，应明确说明。
4. 结果交付：返回回答及可核验的来源引用。引用是否支持对应结论仍需要检查。

例如，用户询问“公司的住宿报销上限是多少”，系统先查找适用的报销制度，再把相关条款交给模型回答。若适用标准取决于地区、职级或生效日期，需要结合这些条件检索和解释。

## 2. 资料准备与检索

文档型 RAG 通常先完成资料解析、清洗、分块与索引构建，并保留文档标识、来源、版本、时间和权限等元数据。源资料更新或删除时，对应索引也需要同步维护。

检索可以采用全文检索、向量检索或混合检索，必要时增加过滤与重排序。具体组件及工作流程见[检索架构](../../architecture/retrieval/Retrieval.md)。RAG 不强制使用向量数据库，也可以直接查询现有数据库或搜索服务。

分块、召回数量和重排序应结合实际问题评估。片段过短可能缺少上下文，内容过多则可能增加成本、引入干扰或超出模型上下文限制。

## 3. 与 Agent 的关系

### 3.1 固定流程 RAG

由程序预先定义检索与生成步骤，例如每次收到问题都执行一次检索，再调用模型生成回答。这类知识库问答系统无需由模型自主选择工具。

### 3.2 Agentic RAG

[Agentic RAG](AgenticRAG.md) 由 Agent 根据任务及中间结果调整检索行动，适合需要动态选择数据源或补充资料的问题。具体流程、查询规划、停止条件与评估见独立文档。

## 4. 与模型训练的区别

RAG 在生成时提供外部资料，主要改变模型当前可见的上下文，不直接更新模型参数。微调通过训练更新参数，常用于调整任务行为、输出格式或领域能力。

两者可以结合使用。需要频繁更新、追踪来源或按用户权限访问的知识，通常适合通过检索提供；仅使用 RAG 也不意味着模型一定会正确理解或遵循资料。

## 5. 质量与边界

- 资料覆盖：知识库必须包含相关、可信且适用的资料，检索无法凭空补全缺失事实。
- 检索质量：分别检查相关资料能否被召回，以及排名靠前的资料是否足以支持回答。
- 上下文质量：去除重复与无关片段，保留理解结论所需的限定条件，处理版本差异和资料冲突。
- 回答依据：检查生成结论是否被资料支持，引用是否对应正确来源；RAG 可以减少部分幻觉，但不能保证消除幻觉。
- 访问控制：检索、重排序、生成和结果返回均应遵守用户的数据访问权限。
- 外部内容处理：将检索资料作为待分析的数据，避免把其中的指令当作系统要求执行。
- 运行成本：同时评估检索、重排序与生成的延迟、调用成本及索引新鲜度。

评估时应区分检索失败和生成失败：没有找到正确资料，需要改善数据或检索流程；已有足够资料却答错，则需要检查上下文组织和模型生成行为。
