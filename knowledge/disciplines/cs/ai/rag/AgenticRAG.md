# Agentic RAG

Agentic RAG 是由 Agent 根据任务和中间结果，动态决定检索行动的检索增强生成方式。Agent 可以选择数据源、改写查询、检查资料是否足够，并在需要时继续检索，最后依据获取的资料生成回答。

Agentic 是形容词，表示具有自主行动特征或由智能体驱动。这里的自主性受到程序允许的工具、权限和预算约束，不代表系统可以无限执行。

## 1. 与固定流程 RAG 的区别

| 对比 | 固定流程 RAG | Agentic RAG |
| --- | --- | --- |
| 行动选择 | 程序预先定义步骤与分支 | Agent 根据任务及中间结果选择下一步 |
| 检索过程 | 可以预设单轮或多轮检索 | 可以动态决定查询、数据源和是否继续检索 |
| 适用问题 | 检索路径明确、流程较稳定的问题 | 需要探索资料、跨来源补证或动态拆解的问题 |
| 运行控制 | 路径通常更容易预测 | 需要约束调用次数、耗时与停止条件 |

两者都可以使用全文检索、向量检索、混合检索和重排序。检索多次或调用多个模型，并不必然意味着采用了 Agent；关键在于是否根据执行结果动态选择行动。

## 2. 典型流程

```text
用户问题 → 判断资料需求 → 选择数据源与查询 → 调用检索工具
                              ↑                  ↓
                              └── 补充检索 ← 评估资料
                                                ↓
                                         组织上下文 → 回答
```

1. 理解任务：明确需要回答的问题、适用范围及必须确认的事实。
2. 选择行动：决定是否需要外部资料，以及调用哪个检索工具、使用什么查询和过滤条件。
3. 获取资料：执行检索，记录来源、版本、时间及与任务相关的内容。
4. 评估结果：检查资料是否覆盖关键问题，是否存在冲突、歧义或缺失条件。
5. 调整行动：必要时拆分或改写查询、切换来源，或请求用户补充关键条件。
6. 停止并回答：资料足够或达到运行限制后，组织上下文并生成回答，说明来源和未解决的不确定性。

资料是否足够可以由模型结合明确规则判断，但这种判断也可能出错，不能作为事实正确性的保证。

## 3. 查询规划与多轮检索

- 问题拆解：将复杂问题拆成可验证的子问题，分别收集依据。
- 查询改写：根据已有资料中的术语、实体和时间范围，调整后续查询。
- 来源选择：根据问题访问文档、结构化数据库、网页等不同来源。
- 结果补证：发现冲突时，查找适用版本、原始出处或其他证据，而不是直接采纳首个结果。
- 状态记录：保存已经查询的内容、获得的证据和仍待解决的问题，减少重复检索。

例如，调查一次服务故障时，Agent 可以先读取故障报告，发现涉及 Redis，再检索对应配置与变更记录，核对发生时间和版本后形成解释。资料中的时间先后或关联关系本身不足以证明因果，需要区分证据与推断。

## 4. 停止条件与失败处理

- 资料充分：关键结论已有适用资料支持，继续检索的预期收益较低。
- 达到预算：限制工具调用次数、总耗时、模型输入输出或费用，避免无休止循环。
- 无新增信息：连续检索没有补充有效证据时，调整策略或停止。
- 缺少关键条件：需要用户提供时间、环境或对象等信息时，明确询问。
- 工具失败：按照预设策略重试、切换来源或返回部分结果，并说明覆盖范围受限。

达到限制并不意味着问题已经解决。资料不足时应保留不确定性，不能为了结束流程补造结论。

## 5. 运行边界

- 工具范围：由程序限定可调用工具及参数，模型负责在允许范围内选择。
- 权限控制：由执行系统校验访问权限，不能仅依赖模型自行判断。
- 外部内容：将检索资料作为数据分析，避免执行资料中夹带的指令。
- 上下文管理：保留关键证据与来源，去除重复内容，避免多轮累积耗尽上下文。
- 可观察性：记录查询、工具调用、结果来源及停止原因，便于定位遗漏、错误与成本问题。

## 6. 效果评估

使用同一批真实任务，对比固定流程与动态流程的答案正确性、证据支持程度、来源覆盖、延迟、调用成本和失败率。增加自主决策并不保证效果更好。

排查失败时，应区分行动选择错误、检索遗漏、上下文丢失和生成错误。例如，没有调用正确的数据源属于行动选择问题；找到了正确资料却未纳入最终上下文，则属于上下文组织问题。
