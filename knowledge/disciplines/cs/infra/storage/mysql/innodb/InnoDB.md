# InnoDB

InnoDB 是 MySQL 的默认存储引擎，负责表的数据组织、索引访问、事务、并发控制和崩溃恢复，常用于需要持久化和事务保障的业务系统。

## 1. 数据与索引

- [存储格式](storage-format/StorageFormat.md)：表空间、段、区、页、记录，以及 DYNAMIC 等行格式。
- [InnoDB 索引](indexes/Indexes.md)：B+ 树、聚簇索引、二级索引、回表、覆盖索引和联合索引。
- [回表](indexes/TableLookup.md)：通过二级索引取得聚簇索引键，再访问聚簇索引读取记录的流程与成本。

InnoDB 以页为单位管理数据和索引，默认页大小为 16 KiB，并使用 B+ 树组织常见索引。

- **聚簇索引**：通常以主键组织，叶子节点存储完整行数据。没有显式主键时，优先选择第一个所有列都为 NOT NULL 的唯一索引；没有合适的索引时，生成隐藏的行 ID 来组织聚簇索引。
- **二级索引**：叶子节点包含索引列和聚簇索引键；查询需要索引中未包含的列时，通常还要访问聚簇索引，这个过程称为回表。

## 2. 内存缓存

Buffer Pool 缓存数据页和索引页，读取时优先访问缓存，未命中时从磁盘加载。修改数据页后形成脏页，由后台机制刷回磁盘。

Buffer Pool 缓存的是页，不是 SQL 查询结果。

## 3. 事务与并发控制

- [InnoDB 锁](locks/Locks.md)：记录锁、间隙锁、临键锁、意向锁、自增锁及锁等待诊断。

- **事务**：支持提交和回滚，将多个操作组织为一个逻辑单元。
- **锁**：使用记录锁、间隙锁、临键锁和意向锁等机制协调并发访问；实际加锁行为受语句、索引和隔离级别影响。
- **MVCC**：结合 undo log 中的历史版本与 Read View，在 READ COMMITTED 和 REPEATABLE READ 下实现一致性非锁定读。锁定读和写操作使用不同的访问规则。

## 4. 日志与恢复

- [InnoDB 日志](logs/Logs.md)：redo、undo 与数据页、事务恢复及 binlog 的分工。

| 机制 | 主要作用 |
| --- | --- |
| redo log | 记录页修改相关信息，通过预写日志机制支持崩溃恢复；提交后的持久性保障受日志刷盘配置等条件影响。 |
| undo log | 保存撤销修改所需的信息，用于事务回滚，并为 MVCC 提供历史版本。 |
| doublewrite | 在数据页写入最终位置前保留可用于恢复的页副本，应对部分页写入问题。 |

binlog 属于 MySQL Server 层。启用 binlog 时，MySQL 通过内部两阶段提交协调 InnoDB 与 binlog 的事务提交状态。

## 5. 概念与实现的边界

页缓存、B+ 树、事务、锁、MVCC、重做日志和撤销日志都是通用技术概念。本文描述的是 InnoDB 的具体实现，其他存储引擎或数据库的支持程度与实现方式可能不同。
