# InnoDB 插入意向锁

## 1. 定义

插入意向锁（Insert Intention Lock）是插入记录前申请的一种特殊间隙锁，用于协调插入与已有间隙锁之间的冲突。

它表达在某个索引间隙内插入记录的意图，不等于锁住整个间隙、禁止其他事务插入，也不是对尚不存在的新行加记录锁。

## 2. 与 IX 意向锁的区别

| 对比项 | IX 意向锁 | 插入意向锁 |
| --- | --- | --- |
| 层级 | 表级。 | 索引间隙级。 |
| 含义 | 准备在表内获取 X 记录锁。 | 准备在某个间隙内插入记录。 |
| 作用 | 协调表级锁与记录锁。 | 协调插入与间隙锁的冲突。 |

一次插入可以同时涉及表级 IX、插入意向锁和新记录的 X 锁，它们承担不同职责。

## 3. 不同位置的并发插入

假设 users 是 InnoDB 表，id 是主键，当前相邻键为 10 和 20：

```text
已有记录：10 ────────────────── 20
事务 A：         插入 15
事务 B：              插入 18
```

A 和 B 在同一间隙中的不同位置插入，通常不会因为插入意向锁互相阻塞。其他约束检查、自增值分配或其他索引上的冲突仍可能影响实际执行。

如果两个事务都插入主键 15，就不是不同位置的情况，会涉及重复键检查与锁等待，不能同时成功提交相同主键的两条记录。

## 4. 被间隙锁阻塞

如果事务 C 已持有保护 `(10, 20)` 的间隙锁，它会阻止其他事务在该间隙插入新记录。因此，A 插入 15、B 插入 18 都可能等待 C 释放相关锁。

插入意向锁之间可以兼容，不代表它们与阻止插入的间隙锁也兼容。临键锁包含的间隙部分同样可能阻塞相应位置的插入。

例如，在 REPEATABLE READ 下，以下锁定范围查询可以保护相关间隙：

```sql
-- 会话 C；假设相邻主键为 10 和 20。
SET TRANSACTION ISOLATION LEVEL REPEATABLE READ;
START TRANSACTION;
SELECT * FROM users WHERE id > 10 AND id < 20 FOR UPDATE;

-- 会话 A；假设 users 只包含 id 列，或其他列都有默认值。
START TRANSACTION;
INSERT INTO users (id) VALUES (15);
-- 可能等待会话 C 的间隙锁释放。
```

即使范围内没有现有记录，锁定读仍可能保护间隙，阻止插入。实际锁定范围需结合执行计划、索引和版本判断。

## 5. 插入完成后的记录保护

插入流程可以简化为：

```text
获取表级 IX
      ↓
通过插入意向锁机制协调目标间隙的插入
      ↓
插入记录，新记录受到 X 记录锁保护
      ↓
事务提交或回滚
```

插入意向锁协调“能否插入这个位置”，新记录上的 X 锁保护“已插入但事务尚未结束的记录”。

InnoDB 可以通过事务信息以隐式锁形式保护新插入记录，发生冲突时再转换为显式锁。因此，上述逻辑流程不意味着每次无冲突插入都会立即产生所有可观察到的显式锁对象。

## 6. 查看等待

MySQL 8.0 可通过以下信息检查数据锁与等待关系，具体可见性受权限影响：

```sql
SELECT * FROM performance_schema.data_locks;
SELECT * FROM performance_schema.data_lock_waits;
```

插入意向锁等待可能显示 INSERT_INTENTION 等锁模式标记。底层锁对象可以挂在目标间隙的后继记录上，因此显示的 LOCK_DATA 不一定是准备插入的新键值，不能据此认定锁的是后继行本身。
