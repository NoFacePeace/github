# InnoDB 临键锁

## 1. 定义与范围

临键锁（Next-Key Lock）是索引[记录锁](RecordLock.md)与该记录前方[间隙锁（Gap Lock）](GapLock.md)的组合，既保护已有记录，也限制相关间隙中的插入。

假设相邻索引键为 10 和 20，键 20 上的典型临键锁保护 `(10, 20]`：

- `(10, 20)` 是间隙部分，阻止在其中插入。
- `20` 是记录部分，按 S 或 X 模式协调对已有记录的访问。

最后一条记录之后的范围通过特殊上界记录 supremum 表示，相关锁主要体现为尾部间隙保护，不是锁住一个实际业务行。

## 2. 典型场景

REPEATABLE READ 下，锁定范围读取和修改操作通常可能采用临键锁。实际锁定范围由扫描的索引记录及边界处理决定，不一定与 WHERE 的数值范围严格相同。

```sql
-- 假设 users 是 InnoDB 表，age 上有非唯一索引。
SET TRANSACTION ISOLATION LEVEL REPEATABLE READ;
START TRANSACTION;

SELECT * FROM users WHERE age BETWEEN 20 AND 30 FOR UPDATE;

COMMIT;
```

若计划按 age 索引扫描，通常会对相关索引记录及间隙进行锁定，边界处还可能使用纯间隙锁或纯记录锁。非唯一索引存在重复值时，还需考虑聚簇索引键构成的实际顺序。

因此，不能仅从 SQL 的 BETWEEN 端点推断全部锁区间。

## 3. S／X 模式与冲突

临键锁可以使用 S 或 X 模式，主要区别体现在记录部分：不同事务在同一记录上的 S 兼容，X 与 S、X 冲突。

间隙部分用于阻止插入，其兼容性不能简单套用记录部分的规则。例如，其他事务向受保护的间隙插入时，可能因插入意向锁与该间隙保护冲突而等待。

## 4. 与其他类型的区别

| 类型 | 以键 10、20 为例的典型范围 | 主要效果 |
| --- | --- | --- |
| 记录锁 | 仅记录 20。 | 保护已有记录，不保护前方间隙。 |
| 间隙锁 | `(10, 20)`。 | 阻止相关位置插入，不锁定记录 20 本身。 |
| 临键锁 | `(10, 20]`。 | 同时保护记录 20 和前方间隙。 |

临键锁是一种组合保护方式，不代表每次都能观察到两把独立的显式锁对象。

## 5. 隔离级别与例外

完整唯一键等值访问且记录存在时，通常可退化为只锁记录，而无需保护前方间隙。范围访问并不满足这一简单条件。

READ COMMITTED 通常不在普通搜索和扫描中使用间隙锁，因此通常不会采用同样的临键锁范围保护；外键和重复键检查等仍需单独考虑。

普通一致性 SELECT 在常见 READ COMMITTED、REPEATABLE READ 下通常使用 MVCC，而不是获取临键锁。SERIALIZABLE 或显式锁定读可能采用不同规则。

## 6. 生命周期与观察

相关事务锁通常保留到事务结束。锁定访问涉及二级索引时，还可能锁定对应的聚簇索引记录，不能只检查一棵索引树。

MySQL 8.0 可通过 performance_schema.data_locks 查看记录层面的锁。对于普通记录，S 或 X 且没有 GAP、REC_NOT_GAP 等修饰时，通常表示临键锁；supremum 等特殊记录应单独解释。

判断时还应结合 LOCK_DATA、索引名称及 data_lock_waits，而不是仅根据一项模式标记推断全部阻塞原因。
