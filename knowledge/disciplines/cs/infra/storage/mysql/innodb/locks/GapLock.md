# InnoDB 间隙锁

## 1. 定义与范围

间隙锁（Gap Lock）保护索引记录之间的间隙，以及第一条记录之前、最后一条记录之后的间隙，主要用于阻止其他事务在相关位置插入记录。

假设相邻索引键为 10 和 20，纯间隙锁可以保护 `(10, 20)`。它不锁定端点 10 或 20 的记录本身，也不直接阻止对已有记录的读取和修改；这些访问是否被阻塞取决于其他锁。

间隙按实际索引顺序划分。对于非唯一二级索引，相同索引值的记录还由聚簇索引键区分，不能只看业务列值推断所有边界。

## 2. 典型场景

在 REPEATABLE READ 下，锁定范围查询、非唯一索引访问或不存在记录的搜索，可能需要保护间隙，避免相关范围被并发插入。

以下示例假设 users 是 InnoDB 表，id 是主键，当前相邻记录为 10 和 20：

```sql
-- 会话 A。
SET TRANSACTION ISOLATION LEVEL REPEATABLE READ;
START TRANSACTION;
SELECT * FROM users WHERE id = 15 FOR UPDATE;
-- 未找到记录，但可能锁住 15 所在的 (10, 20) 间隙。

-- 会话 B。
START TRANSACTION;
INSERT INTO users (id) VALUES (15);
-- 等待 A 释放相关间隙锁。
```

示例假设 users 只有 id 列，或其他列允许省略。会话 A 结束事务后，B 才能继续相关插入流程；最终结果还取决于其他约束与并发操作。

这类锁保护的是整个索引间隙，可能也阻止向同一间隙插入 12 或 18，并非只保护查询中的值 15。

## 3. 兼容性与插入冲突

纯间隙锁可以带 S 或 X 标记，但其间隙保护效果相同，来自不同事务的纯间隙锁可以共存，不能套用记录锁的 S／X 冲突规则。

插入意向锁用于协调插入，可以被阻止目标位置插入的间隙锁阻塞。因此，间隙锁可以共存，不等于其他事务可以自由插入。

## 4. 隔离级别与限制

READ COMMITTED 通常不对普通搜索和索引扫描使用间隙锁，但外键和重复键检查等仍有例外。

完整唯一键等值搜索且记录存在时，通常只需保护匹配记录，不锁前方间隙；目标不存在、只使用联合唯一键的一部分或采用其他访问路径时，行为可能不同。

普通 MVCC 一致性 SELECT 通常不通过间隙锁实现快照可见性。不能把“防止幻读”理解为所有 SELECT 都会锁住查询范围。

## 5. 生命周期与观察

相关事务锁通常在提交或回滚时释放，实际范围需结合索引、执行计划和隔离级别判断。

MySQL 8.0 可以通过 performance_schema.data_locks 和 data_lock_waits 观察锁与等待。纯间隙锁通常带 GAP 标记，锁信息可能显示该间隙的后继记录键值，而不是准备插入的新值。
