# InnoDB 锁

InnoDB 通过锁协调并发事务对记录和索引范围的访问。锁模式、锁定范围和获取目的属于不同维度，不能把所有锁名称视为互斥的分类。

## 1. 共享锁与排他锁

| 模式 | 含义 |
| --- | --- |
| 共享锁（S） | 允许多个事务共享读取被锁定的记录，与其他事务的排他锁冲突。 |
| 排他锁（X） | 用于修改记录等操作，与其他事务对同一记录的共享锁和排他锁冲突。 |

S、X 描述锁模式，不直接说明锁定的是记录、范围还是表。普通一致性 SELECT 通常不获取记录锁，不会因为其他事务持有 X 记录锁就一律等待。

## 2. 记录锁

- [记录锁](RecordLock.md)：S/X 模式、锁定读、自动加锁场景、锁定范围与等待诊断。

记录锁（Record Lock）锁定索引记录，而不是直接锁定抽象的物理数据行。即使表没有显式索引，InnoDB 也会使用内部聚簇索引实施记录锁。

```sql
-- 假设 users 使用 InnoDB，id 是主键，且记录存在。
START TRANSACTION;
SELECT * FROM users WHERE id = 10 FOR UPDATE;
COMMIT;
```

在常见的唯一键完整等值匹配且记录存在的情况下，可以只锁定匹配记录，而无需锁定前方间隙。记录不存在或访问条件不同时，加锁范围可能不同。

## 3. 间隙锁与临键锁

| 类型 | 保护范围 | 主要作用 |
| --- | --- | --- |
| 间隙锁（Gap Lock） | 索引记录之间、第一条之前或最后一条之后的间隙。 | 阻止在相应间隙插入记录。 |
| 临键锁（Next-Key Lock） | 一条索引记录及其前方间隙。 | 同时保护现有记录和插入范围。 |

例如相邻索引键为 10 和 20，键 20 上的典型临键锁覆盖 `(10, 20]`；间隙部分则是 `(10, 20)`。

在 REPEATABLE READ 下，范围锁定读和修改操作通常可能使用临键锁，避免相关范围出现新的匹配记录。实际锁定范围由索引、访问路径、条件和记录是否存在等决定，可能大于最终返回的记录集合。

READ COMMITTED 通常不对普通搜索和索引扫描使用间隙锁，但外键约束检查和重复键检查等情况仍可能使用。间隙锁主要阻止插入，不同事务的间隙锁可以共存，不能直接套用普通记录 S/X 锁的冲突规则。

## 4. 插入意向锁

插入意向锁是插入前申请的一种间隙锁，用于表达在某个位置插入的意图。

多个事务在同一间隙的不同位置插入时，其插入意向锁可以兼容；若其他事务持有阻止该位置插入的间隙锁，则可能等待。插入仍需执行唯一性检查等其他协调，不能据此认定所有插入都不会冲突。

## 5. 意向锁

意向锁是表级锁，用于协调表级锁与记录锁，避免判断表级锁是否可获取时逐条检查所有记录锁。

- **IS**：事务准备在表中获取共享记录锁。
- **IX**：事务准备在表中获取排他记录锁。

| 已持有／申请 | IS | IX | S 表锁 | X 表锁 |
| --- | --- | --- | --- | --- |
| IS | 兼容 | 兼容 | 兼容 | 冲突 |
| IX | 兼容 | 兼容 | 冲突 | 冲突 |
| S 表锁 | 兼容 | 冲突 | 兼容 | 冲突 |
| X 表锁 | 冲突 | 冲突 | 冲突 | 冲突 |

两个事务都持有 IX 不表示它们修改的记录一定冲突，记录层面还需单独判断。意向锁与插入意向锁是不同机制。

## 6. 自增锁

AUTO-INC 锁是自增值分配机制中可能使用的特殊表级锁，行为受 innodb_autoinc_lock_mode 影响。

不同模式在传统表级锁、轻量同步及并发分配之间有不同取舍。并非每次插入自增列都会持有 AUTO-INC 表锁；需要时，该锁通常持续到语句结束，而非事务结束。

自增值也不保证无间隙，事务回滚等情况可能留下空缺。

## 7. 一致性读与锁定读

| 操作 | 典型行为 |
| --- | --- |
| 普通 SELECT | 在常见的 READ COMMITTED、REPEATABLE READ 下使用 MVCC 一致性非锁定读。 |
| SELECT ... FOR SHARE | 获取相应共享锁；MySQL 8.0 支持该语法。 |
| SELECT ... FOR UPDATE | 获取相应排他锁。 |
| UPDATE、DELETE | 搜索并修改记录时获取相应锁。 |

锁定读应在显式事务中使用，以便在后续操作期间保留锁。普通 SELECT 在 SERIALIZABLE 等条件下可能转为锁定行为，因此不能一概说 SELECT 不加锁。

MVCC 不是锁。它通过版本可见性减少读写阻塞，但不能替代修改操作所需的并发控制。即使不获取记录锁，语句仍可能涉及 Server 层的元数据锁。

## 8. 等待、释放与诊断

事务记录锁通常保留到事务提交或回滚；部分不匹配记录锁等可能根据隔离级别和执行过程提前释放。不同类型锁的生命周期并不完全相同。

锁冲突可能造成等待，多个事务互相等待则可能形成死锁。应用应正确处理死锁或锁等待超时，并依据错误类型和业务语义决定事务回滚与重试。

MySQL 8.0 可通过以下信息查看引擎数据锁和等待关系，具体可见性受权限影响：

```sql
SELECT * FROM performance_schema.data_locks;
SELECT * FROM performance_schema.data_lock_waits;
SHOW ENGINE INNODB STATUS;
```

Server 层的 MDL 应通过 metadata_locks 等信息查看，不属于上述记录锁分类。
