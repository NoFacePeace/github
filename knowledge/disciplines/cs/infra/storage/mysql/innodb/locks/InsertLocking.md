# InnoDB 插入加锁流程

INSERT 的加锁涉及表级意向锁、索引间隙中的插入协调，以及新记录的排他保护。下面以普通 INSERT 为主说明逻辑过程；重复键处理、外键检查和自增值分配会引入额外分支。

## 1. 整体过程

```text
获取或沿用表级 IX 意向锁
        ↓
定位索引插入位置，执行必要的约束检查和冲突检查
        ↓
通过插入意向锁机制协调目标间隙；存在阻塞时等待
        ↓
写入索引记录，新记录受到 X 排他保护
        ↓
事务提交或回滚，释放相关事务锁
```

这是理解各类锁职责的逻辑流程，不是每次 INSERT 的固定内部调用顺序。聚簇索引、二级索引的写入和约束检查可能交错进行，等待后也可能重新检查。

无冲突路径不一定为每一步创建可观察到的显式锁对象，不能把流程理解为“每次都依次新增三个锁对象”。

## 2. 表级 IX 意向锁

对表内记录获取排他锁前，事务需要先取得表级 [IX 意向排他锁](IntentionExclusiveLock.md)，已有适当锁模式时可以沿用。

不同事务的 IX 互相兼容，因此多个事务可以同时向同一张表插入。IX 与其他事务的整表 S、X 锁冲突，用来协调表级访问要求。

IX 只声明记录排他加锁的意向，不负责判断具体插入位置能否使用，也不表示独占整张表。

## 3. 插入意向与间隙冲突

[插入意向锁](InsertIntentionLock.md)是一种特殊间隙锁，用于协调向目标位置插入的操作。如果其他事务持有阻止该位置插入的间隙锁，或者临键锁中的间隙部分，插入可能等待。

假设相邻索引键为 10 和 20：

| 并发情况 | 典型结果 |
| --- | --- |
| A 插入 15，B 插入 18 | 插入意向锁之间不因此互相阻塞。 |
| C 已锁住间隙 (10, 20)，A 插入 15 | A 等待 C 释放相关间隙保护。 |
| C 只持有键 20 的记录锁，A 插入 15 | 该记录锁本身不保护前方间隙，不会仅因此阻止插入 15。 |
| A、B 插入相同唯一键 15 | 需要执行唯一性检查，可能因记录锁等待，不能都成功提交相同唯一键。 |

插入意向锁会等待已有的间隙保护，但间隙锁请求不会仅因已有插入意向锁而等待，这种等待关系不是双向对称的。

## 4. 新记录的排他保护

插入成功写入的新记录受到 X [记录锁](RecordLock.md)的排他保护。这里保护的是索引记录本身，不是自动将相邻整个间隙锁住。

InnoDB 通常先通过记录事务信息等形成隐式 X 保护；其他事务请求不兼容锁时，必要时再转换为显式记录锁并登记等待。

因此，即使锁视图中没有立即显示每条新记录的显式 X 锁，也不能认为这些记录没有受到保护。普通一致性读取则按 MVCC 判断可见性，通常看不到其他事务尚未提交的新记录。

## 5. 约束检查与其他分支

| 场景 | 需要额外考虑的行为 |
| --- | --- |
| 主键或唯一索引冲突 | 重复键检查可能涉及共享锁、记录锁等待或死锁，具体模式取决于索引和语句。 |
| 外键约束 | 检查相关记录时可能获取共享记录锁，形成额外等待。 |
| ON DUPLICATE KEY UPDATE | 冲突后转为更新已有记录，需要相应排他锁，加锁范围可能不同于普通插入。 |
| 自增值分配 | 是否使用 AUTO-INC 表锁取决于 innodb_autoinc_lock_mode 和插入方式。 |
| INSERT ... SELECT | 除目标表插入外，还要考虑源表读取及其加锁行为。 |

READ COMMITTED 通常减少普通搜索中的间隙锁，但重复键检查和外键检查等仍有例外。不能认为切换到 RC 后 INSERT 就不会等待。

## 6. 事务结束与等待处理

表级 IX 和新记录的事务级排他保护通常持续到事务提交或回滚。自动提交模式下，单条成功 INSERT 通常作为独立事务提交；显式事务中，语句结束不代表事务锁全部释放。

需要 AUTO-INC 表锁时，该锁通常按语句释放，与事务级记录保护的生命周期不同。

多行、多索引插入可能在不同位置形成交叉等待，从而产生死锁。应用应区分重复键、死锁和锁等待超时，根据错误类型处理事务状态，并在适当情况下重试。

## 7. 查看锁与等待

MySQL 8.0 可使用以下信息检查当前数据锁与等待关系，具体可见性受权限影响：

```sql
SELECT * FROM performance_schema.data_locks;
SELECT * FROM performance_schema.data_lock_waits;
```

重点结合 TABLE 类型的 IX、RECORD 类型的锁模式、INSERT_INTENTION 标记和等待关系判断阻塞原因。插入意向等待可能登记在间隙后继记录上，显示的 LOCK_DATA 不一定是待插入的键值。

没有看到 INSERT_INTENTION 或显式 X 记录锁，不代表无冲突插入路径没有执行相应的检查或记录保护。
