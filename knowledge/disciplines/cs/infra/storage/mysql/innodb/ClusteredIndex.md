# InnoDB 聚簇索引

## 1. 数据组织

聚簇索引使用 [B+ 树](../../../../data-structures/BPlusTree.md)组织表数据，叶子记录包含完整行数据。一张 InnoDB 表只有一个聚簇索引，数据与聚簇索引是同一套存储结构。

对于页外存储的长字段，叶子记录可能保存指向页外数据的引用，因此“完整行”并不意味着所有字段的全部字节都位于同一个叶子页。

索引中的逻辑顺序由聚簇索引键决定，不表示磁盘上的页必须物理连续。

## 2. 聚簇索引键的选择

InnoDB 按以下顺序选择聚簇索引键：

1. 有显式主键时，使用主键。
2. 没有主键时，使用第一个所有列都为 NOT NULL 的唯一索引。
3. 没有合适的唯一索引时，生成隐藏的 6 字节行 ID，并建立内部聚簇索引。

因此，每张 InnoDB 表都有聚簇索引，即使建表语句没有声明主键。

## 3. 查询示例

```sql
CREATE TABLE users (
    id BIGINT PRIMARY KEY,
    name VARCHAR(100) NOT NULL,
    age INT NOT NULL
) ENGINE = InnoDB;

SELECT name, age FROM users WHERE id = 10;
```

当执行计划使用主键索引时，InnoDB 从根节点向下定位 `id = 10` 的叶子记录，并从该记录读取所需列，无需先经过二级索引。

按主键范围查询时，可以先定位范围起点，再沿叶子记录及叶子页扫描。SQL 结果的顺序仍需通过 `ORDER BY` 明确保证。

## 4. 主键设计的影响

- **长度**：二级索引记录包含聚簇索引键，较长的主键通常使二级索引占用更多空间。
- **稳定性**：修改主键需要调整聚簇索引，并维护关联的二级索引记录。
- **插入顺序**：递增键通常减少随机位置插入，但仍可能产生页分裂和热点竞争；实际效果取决于工作负载。

通常应显式选择短小、稳定的主键，并结合业务的唯一性和访问需求决定键值生成方式。
