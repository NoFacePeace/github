# 聚簇索引叶子记录

## 1. 术语与位置

聚簇索引叶子记录（Clustered Index Leaf Record）是 InnoDB 聚簇索引叶子页中的数据记录，通常也称聚簇索引记录（Clustered Index Record）。它保存业务行数据及必要的内部信息，是表数据在聚簇索引中的存储形式。

“叶子”强调记录在 B+ 树中的位置，“行格式”描述它的编码规则，两者是不同维度。DYNAMIC、COMPACT 等行格式都可以用于聚簇索引叶子记录。

## 2. 记录包含什么

| 组成 | 主要用途 |
| --- | --- |
| 记录头 | 保存记录类型、删除标记及记录链接等管理信息。 |
| NULL 位图与变长字段长度信息 | 在适用格式中描述字段是否为 NULL、变长字段如何解析。 |
| 用户列 | 包含主键及其他列的数据，适用长字段可能使用页外引用。 |
| [DB_TRX_ID](DB_TRX_ID.md) | 记录最近插入或更新该记录的事务 ID，大小为 6 字节。 |
| [DB_ROLL_PTR](DB_ROLL_PTR.md) | 指向相关 undo 记录的回滚指针，大小为 7 字节。 |
| [DB_ROW_ID](DB_ROW_ID.md)（按需存在） | 没有合适主键或唯一非空索引时，用于内部聚簇索引的 6 字节隐藏行 ID。 |

上述是组成说明，不表示实际字节按表中顺序排列。具体字段布局取决于行格式、表定义和版本；DB_ROW_ID 也不是所有表都有。

## 3. DYNAMIC 中的长字段

以包含 id、title 和 content 的表为例，记录可以简化理解为：

```text
记录管理信息
用户列：id、title、content 的值或页外引用
事务内部信息
```

当 content 等适用的长变长字段需要页外存储时，DYNAMIC 可以将字段值整体移到页外，行内保留 20 字节引用。

因此，“叶子记录保存完整行”表示可以通过它取得该行的列值，不代表每个字段的全部字节都位于同一条页内记录中。读取外置字段时可能需要访问其他页。

## 4. 与其他索引记录的区别

| 记录 | 位置与内容 |
| --- | --- |
| 聚簇索引叶子记录 | 位于聚簇索引叶子页，保存行数据及事务内部信息。 |
| 二级索引叶子记录 | 位于二级索引叶子页，包含索引列和聚簇索引键，不保存完整业务行。 |
| 节点指针记录（Node Pointer Record） | 位于非叶子索引页，包含导航键和子页编号。 |

不同类型可以使用相应行格式的基础编码规则，但字段和具体布局并不完全相同，不能把非叶子记录当作完整业务行。

## 5. 源码中的记录类型

在 DYNAMIC、COMPACT 等使用的紧凑记录格式中，源码以 REC_STATUS_ORDINARY 标识普通用户叶子记录，以 REC_STATUS_NODE_PTR 标识非叶子节点指针记录。

ORDINARY 不等于“聚簇索引专用”，二级索引用户叶子记录也使用该类型。页内还存在 infimum、supremum 等特殊记录，不能把叶子页中的所有记录都视为业务行。
