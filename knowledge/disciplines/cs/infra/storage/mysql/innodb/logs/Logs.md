# InnoDB 日志

InnoDB 使用 redo log 和 undo log 支持事务、崩溃恢复及历史版本读取。它们属于存储引擎层，与 Server 层的 binlog 分工不同。

## 1. 日志类型

- [redo log](RedoLog.md)：记录页修改相关信息，通过预写日志机制支持崩溃恢复。
- [undo log](UndoLog.md)：保存撤销修改所需的信息，用于事务回滚，并支持重建历史版本。

## 2. 与数据页的关系

更新通常先修改 Buffer Pool 中的数据页，不必等到事务提交。undo 保存恢复修改前状态所需的信息，redo 则记录相关页修改。

脏页可以在事务提交前写入数据文件，但必须满足相应预写日志规则。崩溃恢复需要重放必要修改，并处理未完成事务，而不是简单地把所有恢复出的修改都视为已提交。

## 3. 与 binlog 的区别

redo 主要服务于引擎崩溃恢复，undo 服务于回滚和历史版本读取，binlog 主要服务于复制及结合备份进行按时间点恢复。

启用 binlog 时，MySQL 通过内部两阶段提交协调 InnoDB 与 binlog 的事务提交状态。日志保留策略也不同：redo 空间可复用，undo 在不再需要时清理，binlog 按相应保留策略管理。
