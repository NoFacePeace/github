# m_low_limit_id

## 1. 含义

m_low_limit_id 是 Read View 中数值较大的不可见性边界。其他事务版本的 ID 大于等于它时，对该视图不可见。

本文采用 MySQL 5.7、8.0 系列 ReadView 类中常见的字段名称，通常可以将它理解为创建视图时事务 ID 分配的边界，具体获取方式需结合目标版本源码。

## 2. 为什么不可见

达到或超过该边界的其他事务 ID 属于视图建立后的新分配范围。即使相关事务随后提交，也不能因此进入原视图的可见范围。

事务 ID 的分配时机不等于事务开始时机，更不等于提交顺序，因此不应只用业务时间先后来替代版本判断。

## 3. 示例

若 m_low_limit_id 为 105：

- 其他事务版本 105、106 等不可见。
- 版本 104 不能仅凭小于 105 就判为可见，还需结合较小边界和活跃集合。
- 创建者自身修改按自身可见性规则处理，不机械套用其他事务的边界结论。

比较包含等号，这是与较小边界的严格小于比较需要区分的地方。

## 4. 与日志及清理的区别

该字段不是 redo 的 LSN，不是时间戳，也不等于名称相近的 m_low_limit_no。后者涉及事务序列与历史清理边界等实现用途，不能因为名称相似就互相替代。
