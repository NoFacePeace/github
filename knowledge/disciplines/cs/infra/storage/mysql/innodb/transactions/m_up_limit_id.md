# m_up_limit_id

## 1. 含义

m_up_limit_id 是 Read View 中数值较小的可见性边界：版本事务 ID 小于它时，通常可以快速判断该版本可见。

本文采用 MySQL 5.7、8.0 系列 ReadView 类中常见的字段名称。虽然名称包含 up，它的数值不大于 m_low_limit_id，不能按英文直觉反向理解。

## 2. 如何确定

活跃集合 m_ids 非空时，通常取其中最小事务 ID；集合为空时，通常取 m_low_limit_id。

它反映视图建立时的活跃事务边界，不是系统中曾经出现过的最小事务 ID，也不是 purge 历史清理的所有判断依据。

## 3. 示例

若活跃集合为 `{100, 102}`，m_low_limit_id 为 105，则 m_up_limit_id 为 100：

- 事务版本 99 小于 100，可以快速判为可见。
- 事务版本 100 不能凭这一比较判为可见，还需要按其他规则判断。
- 事务版本 101 位于边界之间，不在活跃集合，因此仍然可以可见。

所以，大于等于该字段并不直接表示不可见。

## 4. 边界条件

比较使用严格小于号。完整判断还需要处理创建者自身、较大的不可见性边界以及活跃集合，不能只用这一字段替代全部规则。
