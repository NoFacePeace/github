# MySQL Server 层

Server 层负责连接管理、SQL 解析、查询优化和执行调度，提供各存储引擎共用的能力。存储引擎负责具体的数据组织与读写，两层通过存储引擎接口协作。

## 1. 连接与权限管理

客户端通过连接协议访问 MySQL。Server 层负责身份认证、连接状态及会话变量管理，并在执行过程中检查相关操作权限。

## 2. SQL 解析与语义解析

解析器检查 SQL 语法并生成语法结构，后续解析过程识别表、列和表达式，确定查询涉及的对象，为优化和执行提供基础。

## 3. 查询优化

优化器根据查询、统计信息和成本模型选择执行计划，包括表的访问路径、连接顺序以及排序等操作的处理方式。

- [优化器](Optimizer.md)：候选索引、行数估算、成本比较、索引合并与执行计划诊断。
- [执行计划](ExecutionPlan.md)：计划内容、EXPLAIN 字段、访问方式及实际执行信息。

## 4. 执行器

- [执行器](Executor.md)：与存储引擎的分工、查询执行流程、迭代器模型和结果处理。
- [索引条件下推](IndexConditionPushdown.md)：将适用条件交给存储引擎，在回表前过滤索引记录。

执行器按照计划调用存储引擎接口，读取或修改记录，并完成计划中安排的过滤、连接、聚合和排序等操作，将结果返回客户端。部分操作可以下推到存储引擎完成。

InnoDB 的页缓存、索引组织、行锁和 MVCC 属于存储引擎内部机制，不属于执行器本身。

## 5. binlog 与事务协调

binlog 位于 Server 层，记录数据变更，主要用于复制和按时间点恢复。它与 InnoDB 用于崩溃恢复的 redo log 分工不同。

启用 binlog 时，MySQL 通过内部两阶段提交协调 InnoDB 与 binlog 的事务提交状态。

## 6. 查询流程

```text
客户端发送 SQL
      ↓
语法与语义解析、相关权限检查
      ↓
优化器选择执行计划
      ↓
执行器调用存储引擎并处理结果
      ↓
向客户端返回结果
```

此流程为简化描述。预处理语句、不同类型的 SQL 和具体版本可能具有不同处理细节。MySQL 8.0 已移除 Query Cache，不能将其列为现代 Server 层的查询步骤。
