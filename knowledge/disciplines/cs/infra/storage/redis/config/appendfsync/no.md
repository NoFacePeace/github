# no

`no` 是 `appendfsync` 的可选值，表示 Redis 不为常规 AOF 追加写入主动执行 `fsync`，由操作系统决定何时将数据同步到磁盘。

## 1. 同步行为

AOF 仍会记录写操作，写入的数据可能暂存在操作系统页缓存中。`appendfsync no` 不代表关闭 AOF；是否开启 AOF 由 `appendonly` 控制。

客户端收到写操作成功的响应时，对应数据可能尚未同步到磁盘。

## 2. 性能与持久性

减少主动同步带来的开销，但数据何时落盘取决于操作系统和磁盘状态。系统崩溃或断电时，尚未落盘的数据可能丢失，时间窗口比 `everysec` 更不确定。

适合能够接受较大数据丢失风险、希望减少同步开销的场景。

## 3. 配置方式

在已开启 AOF 的实例中设置：

```conf
appendfsync no
```

也可以动态修改：

```redis
CONFIG SET appendfsync no
```

运行时修改不会自动写回配置文件。
