# PX

`PX` 是 `SET` 命令的过期选项，后面跟一个正整数，表示新写入的 key 从设置时起可以存活多少毫秒。

## 1. 使用格式

```redis
SET greeting hello PX 30000
```

将 `greeting` 设置为 `hello`，并赋予 30000 毫秒，也就是 30 秒的有效期。TTL 作用于整个 key，不作用于集合内部的某个成员。

```redis
PTTL greeting
```

`PTTL` 查询剩余毫秒数；返回 `-1` 表示存在但没有过期时间，`-2` 表示 key 不存在。过期后 key 在逻辑上不可再读取，内存回收由 Redis 的过期清理机制处理。

## 2. 与其他过期方式的区别

| 写法 | 含义 |
| --- | --- |
| `SET key value PX 30000` | 写值并设置相对 30000 毫秒有效期。 |
| `SET key value EX 30` | 写值并设置相对 30 秒有效期。 |
| `SET key value PXAT timestampMs` | 写值并指定绝对 Unix 毫秒过期时间。 |
| `PEXPIRE key 30000` | 对已有 key 设置相对 30000 毫秒有效期，不写入新值。 |

`PX` 是选项，`PEXPIRE` 是独立命令。`SET` 的 `EX`、`PX`、`EXAT`、`PXAT`、`KEEPTTL` 不能任意叠加，它们是互斥的过期策略；`PXAT` 从 Redis 6.2 起提供。

## 3. 覆盖与刷新

```redis
SET greeting hello PX 30000
SET greeting world PX 30000
```

第二次成功写入会替换值，并从这次设置重新计算 30 秒期限，而不是在原期限上追加 30 秒。

普通 `SET key value` 成功覆盖已有值时，会清除旧 TTL；如需保留，可按版本支持情况使用 `KEEPTTL`。`GET` 不会刷新 TTL。

## 4. 与条件写入组合

```redis
SET lock:task:123 unique-token NX PX 30000
```

key 不存在时，同时完成写入和过期设置；条件不满足时不修改值，也不刷新原 TTL。

将写值和过期设置放在同一命令中，可以避免分两次调用时中途崩溃，留下没有过期时间的临时 key。

## 5. 有效期边界

- `PX` 需要正整数毫秒数，`0` 或负数会使 `SET` 报错；独立过期命令对非正时间的处理规则不同。
- key 到期不会自动停止客户端进程或回滚已发出的外部操作。
- 毫秒单位不意味着任务调度、故障发现或内存回收具备严格的毫秒实时保证。
- 请求超时不能证明写入未发生，重试时应结合条件、身份 token 和业务幂等分析结果。
