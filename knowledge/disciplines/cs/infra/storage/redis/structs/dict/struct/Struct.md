# Struct

Redis 字典通过桶数组定位键值条目，使用拉链法处理哈希冲突。以下以 Redis 7.2 的普通键值条目为例，省略特殊条目形式和部分辅助字段。

## 1. 字典字段

- [dict](dict.md)：字典类型、桶数组、条目数量及 rehash 状态。

## 2. 桶数组

每套桶数组的类型为 `dictEntry **`，数组元素类型为 `dictEntry *`。也就是说，数组连续保存条目指针，而不是直接连续保存 `dictEntry` 对象。

```text
dict
 ├─ ht_table[0] → 桶数组
 │                [0] → entry A → entry B → NULL
 │                [1] → NULL
 │                [2] → entry C → NULL
 └─ ht_table[1] → 新桶数组（rehash 时使用）
```

一个桶保存对应冲突链的首条目指针，空桶为 `NULL`。`ht_table[2]` 表示两套表的入口，不表示每张表只有两个桶。

## 3. 键值条目

- [dictEntry](dictEntry.md)：键、值联合体与冲突链指针。

## 4. 拉链法与查找

1. 通过 `type` 中的哈希函数计算键的哈希值。
2. 根据当前表的桶数量计算桶下标；桶数量为二的幂时，可以使用位掩码定位。
3. 从桶中的首条目开始，沿 `next` 比较键，直到找到目标或到达链尾。

多个键映射到同一个桶时，仍以各自的条目保存在链中，这就是拉链法，也称链地址法。

哈希分布均匀、负载合理时，查询、插入和删除平均为 `O(1)`；冲突严重时，链式查找可能退化为 `O(N)`。

## 5. 渐进式 rehash

扩缩容时分配新桶数组，分批将旧表中的条目迁移到新表。迁移期间需要按 rehash 状态在新旧两张表中查找，新插入条目通常进入新表。

迁移完成后，新表成为正式表，旧桶数组释放，`rehashidx` 恢复为 `-1`。分批迁移用于分摊搬运成本，但不代表每次操作都严格没有额外开销。
