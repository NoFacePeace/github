# ht_table

`ht_table` 是 Redis 7.2 字典中保存两套桶数组入口的字段，用于正常访问和渐进式 rehash。

## 1. 字段类型

```c
dictEntry **ht_table[2];
```

这是一个长度为 `2` 的数组，每个元素是 `dictEntry **`，指向一套桶数组。桶数组的元素为 `dictEntry *`，指向冲突链的首条目，而不是直接保存条目对象。

```text
ht_table[0] → 桶数组
              [0] → entry A → entry B → NULL
              [1] → NULL
              [2] → entry C → NULL
ht_table[1] → 新桶数组（rehash 时分配）
```

`ht_table[i][j]` 表示第 `i` 张表的第 `j` 个桶。空桶保存 `NULL`，非空桶通过条目的 `next` 串起发生哈希冲突的键值条目。

## 2. 桶数量

`ht_table[2]` 中的 `2` 表示两张表，不是每张表只有两个桶。已分配表的桶数量由 `ht_size_exp[i]` 决定，为 `2^ht_size_exp[i]`。

桶数组连续保存指针，条目可以分散分配。多个条目可以落入同一个桶，因此桶数量、非空桶数量和条目数量是不同概念。

## 3. rehash 期间的变化

正常情况下主要使用 `ht_table[0]`，`ht_table[1]` 尚未分配。扩缩容时，为第 `1` 张表分配新桶数组，再分批迁移第 `0` 张表中的条目。

由于新旧桶数量可能不同，迁移时需要重新确定条目的桶位置，不能仅复制旧桶数组。迁移期间查找需要考虑两张表，新插入条目通常进入新表。

迁移结束后释放旧桶数组，第 `1` 张表接替第 `0` 张表，并将备用表入口重置。
