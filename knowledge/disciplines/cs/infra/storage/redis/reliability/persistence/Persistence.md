# Persistence

持久化将 Redis 内存中的数据保存到磁盘，用于重启或故障后的恢复。数据丢失的范围取决于持久化方式、执行频率及磁盘写入是否成功。

## 1. RDB 快照

[RDB](RDB.md) 保存某个时间点的数据快照，适合备份和恢复。`BGSAVE` 通过子进程生成快照；如果故障发生在下一次快照完成前，上一次快照之后的变更可能丢失。

## 2. AOF 日志

[AOF](AOF.md) 记录修改数据的命令，通过重放日志恢复数据。`appendfsync` 控制同步到磁盘的策略，常见取值为 `always`、`everysec` 和 `no`，需要在性能与数据丢失风险之间权衡。

AOF 重写根据当前数据生成更紧凑的恢复记录，减少历史命令积累带来的体积增长。

## 3. 恢复与备份

- RDB 和 AOF 可以同时启用；两者都启用时，Redis 重启优先使用 AOF 恢复数据。
- 持久化文件仍可能因磁盘故障、误删除等原因丢失，需要额外备份并验证恢复流程。
- 复制不能替代持久化或备份，误删除等操作也可能传播到副本。
