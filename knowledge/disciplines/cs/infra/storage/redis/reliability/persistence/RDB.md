# RDB

RDB（Redis Database）是 Redis 保存数据快照的二进制格式，记录某个时间点的完整数据集，用于重启恢复、备份和迁移。

## 1. 生成快照

| 方式 | 行为 |
| --- | --- |
| `BGSAVE` | 通过子进程在后台生成快照，主进程继续处理请求。 |
| `SAVE` | 在主进程中同步生成快照，期间阻塞其他客户端请求。 |
| `save` 配置 | 满足指定时间与数据变更次数条件时，自动触发后台快照。 |

例如以下配置表示：距离上次成功保存至少经过 60 秒，且累计至少发生 1000 次数据变更时，触发后台保存：

```conf
save 60 1000
```

可以配置多条 `save` 规则，满足任意一条即可触发；`save ""` 用于关闭基于这些规则的自动快照，不禁止手动执行保存。

## 2. 后台保存过程

1. 主进程通过 `fork` 创建子进程，子进程获得创建时的数据视图。
2. 子进程将数据写入临时 RDB 文件，主进程继续接收写入，通过写时复制维持子进程的数据视图。
3. 新快照成功生成后，替换原有的 RDB 文件。

快照反映的是子进程创建时的数据状态，不包含后台保存期间所有后续写入。后台保存仍有开销：`fork` 可能短暂阻塞主进程，写时复制可能增加内存占用，保存文件需要磁盘空间和 I/O。

## 3. 文件与恢复

独立 RDB 文件的常见配置为：

```conf
dir /path/to/data
dbfilename dump.rdb
```

`dir` 指定工作目录，`dbfilename` 指定 RDB 文件名。实际路径取决于实例配置。

未开启 AOF 时，Redis 启动会从配置位置存在的 RDB 文件加载数据。RDB 和 AOF 都启用时，Redis 优先使用 AOF 恢复。

如果故障发生在下一次快照成功完成前，恢复时可能丢失上一次快照之后的变更。

## 4. 备份与迁移

- 定期将成功生成的快照复制到独立存储，并保留多个时间点的版本。
- 误删后，如果仍保留误删前的快照，可以恢复到该时间点，但快照之后的正常写入也不会包含在内。
- 将快照用于迁移时，需要确认目标 Redis 版本兼容，并验证加载结果。

当前 RDB 文件会被后续快照替换，单个不断覆盖的文件不能提供完整的历史恢复能力。

## 5. 与 AOF 的关系

AOF 持续记录写操作，通常能缩小故障时的数据丢失窗口；RDB 提供便于保留和传输的时间点快照。加载 RDB 通常比重放大量 AOF 命令更快，实际取决于数据规模和文件内容。

AOF 也可能保留误删前的数据，但直接加载包含删除操作的完整日志仍会恢复出删除后的状态；能否恢复取决于旧数据是否仍在，以及能否准确定位恢复边界。

现代 AOF 的基础文件也可以采用 RDB 格式，这与单独通过 `save` 规则生成的 RDB 快照属于不同的文件管理流程。
