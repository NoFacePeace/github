# Hybrid Persistence

混合持久化是 AOF 的一种模式，将 RDB 格式的全量基础数据与 AOF 格式的后续增量操作结合，用于恢复数据。

## 1. 数据组成与恢复

```text
RDB 格式的全量基础数据 + AOF 格式的后续增量操作
```

AOF 重写时，根据当前数据生成 RDB 格式的基础内容；之后的写操作继续以 AOF 命令格式记录。重启时先加载基础数据，再重放增量操作。

[RDB](RDB.md) 的二进制快照格式通常比大量命令记录更紧凑，加载也通常更快；增量日志则用于恢复基础数据生成之后的变更。

## 2. 配置方式

```conf
appendonly yes
aof-use-rdb-preamble yes
```

`appendonly` 开启 AOF，`aof-use-rdb-preamble` 决定重写生成的基础内容格式：

| 值 | 基础内容格式 | 后续增量格式 |
| --- | --- | --- |
| `yes` | RDB 格式，即混合持久化。 | AOF 命令格式。 |
| `no` | AOF 命令格式。 | AOF 命令格式。 |

改变 `aof-use-rdb-preamble` 不会立即转换已有文件，需要后续成功重写才会生成采用新格式的基础内容。混合持久化仍使用 `appendfsync` 控制 AOF 同步策略，数据丢失窗口取决于同步策略和实际落盘情况。

## 3. 文件组织

| Redis 版本 | 组织方式 |
| --- | --- |
| Redis 4 至 6 | 同一个 AOF 文件以 RDB 格式内容开头，后面追加 AOF 命令。 |
| Redis 7 起 | RDB 格式基础文件与 AOF 增量文件分开保存，由 manifest 管理有效的文件集合。 |

混合持久化属于 AOF 自己的恢复文件集合，没有独立于 AOF 的另一套混合持久化文件。备份或迁移多文件 AOF 时，需要保留一致且完整的文件集合。

## 4. 与独立 RDB 快照的关系

混合持久化不要求开启独立的 RDB 定期快照，也不会复用独立的 `dump.rdb`。

| 机制 | 文件与用途 |
| --- | --- |
| 混合持久化 | AOF 重写生成自己的 RDB 格式基础内容，与增量日志一起用于 AOF 恢复。 |
| 独立 RDB 快照 | 通过 `save` 规则、`BGSAVE` 等方式生成单独的快照文件，可另行保留用于备份和迁移。 |

两者可以同时开启，分别维护文件。独立 RDB 和 AOF 都启用时，Redis 重启优先使用 AOF 恢复。
