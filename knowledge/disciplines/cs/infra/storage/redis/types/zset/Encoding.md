# Encoding

ZSet 是 Redis 的有序集合类型，底层可以采用不同编码。编码决定成员与分数如何存储，不改变成员唯一、按分数排序等对外语义。

## 1. 编码分类

现代 Redis 中，ZSet 主要使用以下两种编码；较老版本的小集合使用 ziplist，Redis 7.0 起改用 listpack。

| 编码 | 底层结构 | 适用场景 |
| --- | --- | --- |
| `listpack` | [Listpack](../../structs/Listpack.md)：紧凑的连续内存结构，按顺序保存成员与分数。 | 成员较少、成员值较短的小集合。 |
| `skiplist` | [跳表](../../structs/skiplist/Skiplist.md)与[字典（哈希表）](../../structs/dict/Dict.md)的组合。 | 成员较多或成员值较长的集合。 |

`OBJECT ENCODING` 返回的是编码名 `skiplist`，但对应实现同时包含跳表与字典，并非只有跳表。

## 2. listpack

listpack 将成员和分数成对保存，逻辑布局如下：

```text
成员 A | 分数 A | 成员 B | 分数 B | 成员 C | 分数 C
```

成员按分数从小到大排列，分数相同时按成员字节的字典序排列。它没有为每个成员单独维护跳表节点和字典项，因此内存开销较小，连续存储也有利于缓存局部性。

代价是查找可能需要线性扫描，插入和删除还可能移动后续数据。由于这种编码用于受大小阈值限制的小集合，Redis 用这些操作成本换取更紧凑的存储。

## 3. skiplist

这种编码由两个结构共同维护同一组成员：

- **字典**：按成员定位关联分数，支持平均 `O(1)` 的分数查询和成员存在性检查。
- **跳表**：按分数及成员字典序组织节点，支持期望 `O(log N)` 的有序查找，并通过跨度信息支持排名查询。

两者解决的查询方向不同：

| 查询需求 | 主要使用的结构 |
| --- | --- |
| 给定成员，查询分数，例如 `ZSCORE` | 字典。 |
| 按分数查询范围，例如 `ZRANGE ... BYSCORE` | 跳表。 |
| 查询成员排名，例如 `ZRANK` | 跳表，结合分数与成员定位。 |

更新成员分数时，需要维护字典中的关联与跳表中的排序位置。相比 listpack，这种编码占用更多内存，但更适合较大规模的查询与修改。

## 4. 编码选择与转换

Redis 7.0 起的小集合阈值配置包括：

| 配置 | 含义 | 常见默认值 |
| --- | --- | --- |
| `zset-max-listpack-entries` | 使用 listpack 的最大成员数量。 | `128`。 |
| `zset-max-listpack-value` | 使用 listpack 时允许的最大单个成员字节长度。 | `64`。 |

成员数量和成员长度满足阈值、且内部容量限制允许时，可以采用 listpack。集合增长导致不再满足条件时，会转换为跳表与字典的组合。转换需要重建结构，因此也存在一次性的时间与内存开销。

普通删除操作使集合缩小后，不应假定它会自动转回 listpack。具体选择与转换行为受 Redis 版本、配置和命令路径影响，应以实际编码为准。

## 5. 查看实际编码

```redis
ZADD leaderboard 10 alice 20 bob
TYPE leaderboard
OBJECT ENCODING leaderboard
```

`TYPE` 返回逻辑类型 `zset`；`OBJECT ENCODING` 在小集合满足配置条件时可能返回 `listpack`，规模增长后可能返回 `skiplist`。

可读取当前实例的阈值配置：

```redis
CONFIG GET zset-max-listpack-entries
CONFIG GET zset-max-listpack-value
```

## 6. 与命令复杂度的关系

常见的 `ZADD O(log N)`、`ZSCORE O(1)` 等复杂度描述，不能直接当作每一种编码内部操作的统一实现成本。

跳表与字典编码分别提供有序查找和按成员查询；listpack 则可能通过扫描及数据移动完成操作。评估性能时，应结合实际编码、集合规模、返回成员数量和编码转换成本。
