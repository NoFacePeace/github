# Model

Stream 的逻辑结构由消息和可选的消费者组组成。消息保存消息内容，消费者组维护各自的投递进度和待确认状态。

## 1. 整体结构

```text
Stream：orders
├── 消息
│   ├── 1000-0 → order_id=1001, status=created
│   ├── 1001-0 → order_id=1002, status=created
│   └── 1002-0 → order_id=1001, status=paid
└── 消费者组：workers
    ├── 投递进度：1001-0
    ├── 消费者：consumer-A、consumer-B
    └── 待确认列表（PEL）
        ├── 1000-0 → consumer-A
        └── 1001-0 → consumer-B
```

一个 Stream 可以没有消费者组，也可以有多个消费者组。各组独立维护投递进度和待确认状态，共享同一份消息内容。

## 2. 消息

每条消息包含 ID 和一组有序的 field-value 对。消息内容、ID 格式、自动生成与手动指定规则见 [Message](Message.md)。

## 3. 消费者组与投递进度

消费者组通过投递进度确定 `XREADGROUP ... >` 接下来可以获取哪些尚未投递的新消息。组内消费者分担消息；不同组可以分别消费同一条消息。

创建组时，`0` 表示将初始投递位置设为 `0-0`，从最早保留的消息开始消费；`$` 表示将位置设为当前末尾，跳过已有消息。

跳过不等于确认：被跳过的消息没有投递给该组，也没有进入该组的待确认列表。投递进度也不代表它之前的消息都已处理完成。

## 4. 待确认列表

PEL（Pending Entries List）记录消费者组中已投递但尚未确认的消息。默认情况下，通过 `XREADGROUP` 投递消息时会创建待确认记录；使用 `NOACK` 选项时不创建。

PEL 保存消息 ID 和投递信息，不重复保存消息正文。记录内容、状态变化、查看与接管方式见 [PEL](PEL.md)。

## 5. 确认与删除

| 操作 | 消息 | 消费者组状态 |
| --- | --- | --- |
| 普通读取 `XREAD` | 保留 | 不改变组的投递进度或 PEL。 |
| 组内读取新消息 `XREADGROUP ... >` | 保留 | 推进组的投递进度，默认加入 PEL。 |
| 确认 `XACK` | 保留 | 移除指定组中的待确认记录。 |
| 默认删除 `XDEL` 或裁剪 `XTRIM` | 移除对应消息 | 不以消费完成为前提，也不自动清除所有相关 PEL 记录。 |

确认和删除是两个独立操作。同一条消息可以在一个组中已确认，在另一个组中仍待确认；删除或裁剪消息时，需要考虑各组的消费进度。
