# 0

在 `XGROUP CREATE`、`XREAD` 和 `XREADGROUP` 的消息 ID 参数位置，`0` 是 `0-0` 的简写，省略的序号按 `0` 处理。它是参数值，不是选项。

## 1. 作为起始边界

`0-0` 小于所有合法的 Stream 消息 ID，可用作从头读取的起始边界。它不能作为 `XADD` 写入消息时的 ID；合法消息 ID 必须大于 `0-0`。

## 2. 不同命令中的含义

| 命令 | `0` 的作用 |
| --- | --- |
| `XGROUP CREATE orders workers 0` | 将组的初始投递位置设为 `0-0`，后续使用 `>` 从最早保留的消息开始投递。 |
| `XREAD STREAMS orders 0` | 读取 ID 大于 `0-0` 的消息，即从最早保留的消息开始读取。 |
| `XREADGROUP GROUP workers consumer-A STREAMS orders 0` | 读取当前消费者自己的、ID 大于 `0-0` 的待确认消息。 |

这些命令中的 `0` 都可替换为 `0-0`，但命令决定具体读取范围。尤其是 `XREADGROUP ... 0`，不会读取其他消费者的待确认消息，也不会读取组内尚未投递的新消息。

## 3. 与确认状态的关系

`0` 表示 ID 边界，不表示消息已确认或未确认。普通读取不维护待确认状态；消费者组读取自己的待确认消息，是 `XREADGROUP` 的行为。

## 4. 与阻塞时间的区别

```redis
XREAD BLOCK 0 STREAMS orders 0
```

这条命令中两个 `0` 的含义不同：

- `BLOCK 0`：没有可读消息时无限等待。
- `STREAMS orders 0`：读取 ID 大于 `0-0` 的消息。

如果已有符合条件的消息，命令会立即返回，无需等待新消息。
