# XACK

`XACK` 确认消费者组中的消息已经处理完成，将指定消息从该组的待确认列表（PEL）中移除。它不删除 Stream 中的消息正文，也不影响其他消费者组的确认状态。

## 1. 基本用法

```redis
XACK orders workers 1000-0
```

| 参数 | 含义 |
| --- | --- |
| `orders` | Stream 的 key。 |
| `workers` | 消费者组名称。 |
| `1000-0` | 要确认的消息 ID，使用读取消息时返回的实际 ID。 |

一次可以确认多条消息：

```redis
XACK orders workers 1000-0 1001-0
```

命令不需要消费者名称；确认针对该组中的待确认记录，不要求提供当前负责消息的消费者身份。

## 2. 返回值

返回成功移除的待确认记录数，而不是传入的 ID 数量。

| 返回值 | 含义 |
| --- | --- |
| `1` | 成功移除一条待确认记录。 |
| `0` | 没有移除记录，例如消息已确认，或从未进入该组的 PEL。 |
| 大于 `1` | 一次成功移除多条待确认记录。 |

重复确认同一条消息不会重复增加成功数量。对于不存在的 Stream 或消费者组，返回 `0`；key 存在但类型不是 Stream 时返回类型错误。

## 3. 状态变化

```text
Stream：A、B、C
workers 的 PEL：A → consumer-A，B → consumer-B
        ↓ 确认 A
Stream：A、B、C
workers 的 PEL：B → consumer-B
```

确认会移除组及所属消费者中的对应待确认记录，不改变组的新消息投递进度。消息仍保留时，可以通过普通读取或范围查询再次读取正文。

确认与删除相互独立：即使消息正文已被删除，只要该组的 PEL 中仍有对应记录，也可以通过 `XACK` 清除该记录。

## 4. 执行时机

通常按以下顺序执行：

1. 使用 `XREADGROUP` 读取，或通过接管命令获得消息。
2. 完成业务处理。
3. 使用 `XACK` 确认。

如果先确认再处理，处理过程中宕机后，就无法依靠该组的 PEL 恢复任务。如果业务处理完成但确认前宕机，消息可能被重新投递，因此业务需要保证幂等。

Redis 不会验证业务是否真正完成，执行 `XACK` 是应用向消费者组报告处理完成。
