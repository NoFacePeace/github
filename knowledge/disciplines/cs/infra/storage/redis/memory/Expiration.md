# Expiration

过期删除是 Redis 清理过期键的机制。键设置过期时间后，到期即在逻辑上失效，但不一定在到期瞬间完成物理删除和内存释放。

## 1. 设置与查询过期时间

```redis
SET code 123456 EX 60
TTL code
```

该示例将键设置为 60 秒后过期。常见命令如下：

| 命令 | 作用 |
| --- | --- |
| `SET key value EX seconds` | 设置值并指定秒级过期时间。 |
| `SET key value PX milliseconds` | 设置值并指定毫秒级过期时间。 |
| `EXPIRE key seconds` | 为已有键设置秒级过期时间。 |
| `PEXPIRE key milliseconds` | 为已有键设置毫秒级过期时间。 |
| `TTL key` / `PTTL key` | 查询剩余存活时间，分别以秒和毫秒为单位。 |
| `PERSIST key` | 移除键的过期时间，不删除键。 |

`TTL` 和 `PTTL` 返回 `-1` 表示键存在但没有过期时间，`-2` 表示键不存在。

## 2. 惰性删除

客户端访问键时，Redis 检查是否已过期。如果已过期，主节点会清理该键，并按键不存在处理。

例如 `code` 到期后，即使尚未被主动清理，`GET code` 也不会继续返回原值。惰性删除避免为每个键维护独立的准时删除任务，但无人访问的过期键仍需要其他机制清理。

## 3. 主动清理

Redis 主节点周期性执行主动过期清理，检查设置了过期时间的键并删除已过期键。它采用抽样等机制，并控制每轮工作量和时间开销，避免一次清理过多数据长时间阻塞请求。

这不等于每轮扫描全部键，也不保证所有过期键在同一个时间点立即清理。大量键集中到期可能增加清理负担，可根据业务对 TTL 加入随机偏移。

## 4. 内存释放

逻辑过期、从键空间删除和释放数据对象占用的内存是不同环节。启用 `lazyfree-lazy-expire` 时，符合条件的过期对象可以交给后台线程释放，降低主线程释放大对象的开销。

即使 Redis 已释放对象，内存分配器也不一定立即将对应物理内存归还操作系统，因此进程驻留内存不一定同步下降。

## 5. 与内存淘汰的区别

| 机制 | 触发依据 | 处理对象 |
| --- | --- | --- |
| 过期删除 | 设置的过期时间已到。 | 已过期的键。 |
| [内存淘汰](Eviction.md) | 达到内存上限并满足淘汰策略。 | 策略范围内的键，可能尚未过期，部分策略也包含没有 TTL 的键。 |

`noeviction` 只禁止按内存压力淘汰键，不会关闭正常的过期删除。只设置 TTL，也不代表内存不足时该键不会被提前淘汰。

## 6. 使用注意

普通 `SET` 覆盖已有键时默认会移除原有 TTL，需要同时指定新的过期时间，或按需求使用 `KEEPTTL` 保留；`INCR`、`HSET` 等原地修改通常保留键原有的 TTL。

过期处理不能替代业务任务调度，不应假设到期瞬间一定执行某个业务动作。验证码、锁等业务还需根据读取结果和实际有效期处理失效，不能依赖物理删除发生的精确时刻。
