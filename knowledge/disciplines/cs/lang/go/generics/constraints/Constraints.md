# 泛型约束

类型约束规定哪些类型可以作为类型参数，以及泛型代码允许对这些类型执行哪些操作。Go 使用接口描述约束，通过类型集和方法要求筛选类型。

## 1. 常见约束与构造方式

| 形式 | 含义 | 文档 |
| --- | --- | --- |
| `any` | 允许任意类型 | [any](Any.md) |
| `comparable` | 支持相等比较，可作为 map 的键类型 | [comparable](Comparable.md) |
| 方法要求 | 必须提供指定方法 | [方法约束](Methods.md) |
| `int` 等类型项 | 限定为指定类型 | [类型项](TypeTerms.md) |
| `~int` 等近似类型项 | 允许底层类型相同的类型 | [底层类型约束](UnderlyingTypes.md) |
| `A \| B` | 允许多个类型集之一 | [联合约束](Union.md) |
| `cmp.Ordered` | 标准库提供的有序类型约束 | [有序类型约束](Ordered.md) |

这里既有预声明约束、标准库约束，也有构造自定义约束的语法，并不是七种互斥的接口类型。

## 2. 类型集与操作

约束中的类型集描述允许的类型范围。函数体中的运算必须对约束允许的所有类型有效；即使某次传入 int，也不能在 `[T any]` 的函数体中直接计算 `a + b`。

方法调用由约束声明或嵌入的方法决定；需要调用某个方法时，应在约束中明确要求它。

## 3. 组合约束

联合项内部取并集，不同接口元素之间取交集。例如：

```go
type NamedInteger interface {
    ~int | ~int64
    String() string
}
```

满足该约束的类型必须同时符合两个条件：底层类型是 int 或 int64，并提供 `String() string` 方法。

接口也可以嵌入已有约束；如果组合后的类型集为空，就没有类型能够满足它。例如，同时要求底层类型是 int 和 string 的交集为空。

## 4. 约束接口与普通接口

只包含方法要求的接口既可以作为类型约束，也可以声明普通接口变量。

包含 `~`、类型联合等非基本接口元素的接口，以及嵌入 comparable 的接口，只能用于类型约束，不能直接用来声明承载值的普通接口变量。

约束是编译期契约，不是对值范围的校验。例如 `~int` 不会限制整数必须大于零。
