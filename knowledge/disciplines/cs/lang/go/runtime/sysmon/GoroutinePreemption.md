# Go Goroutine 抢占机制

Go 运行时可以暂停长时间执行的 goroutine，让其他 goroutine 或 GC 等运行时工作获得执行机会。理解这个过程，需要区分 Go 调度器、操作系统线程调度、信号与硬件中断。

## 1. 死循环与 CPU 占用

```go
for {
}
```

空循环没有主动等待，会持续消耗 CPU，通常占满一个逻辑 CPU 的执行能力。但持续占用 CPU 不等于无法被抢占：操作系统可以切换线程，Go 运行时也可以暂停当前 G，调度其他 G。

如果没有其他工作，被抢占的 G 后续仍可能继续执行空循环，因此抢占机制不会自动降低它的 CPU 占用。等待事件时，应使用 channel、锁或其他合适的阻塞机制。

`main` 返回时整个进程退出，即使其他 G 仍在死循环，也不会继续执行。

## 2. 两层调度

| 层次 | 调度对象 | 作用 |
| --- | --- | --- |
| 操作系统 | 操作系统线程，即 Go 中的 M | 决定哪个线程获得逻辑 CPU |
| Go 运行时 | goroutine，即 G | 在持有 P 的 M 上选择并执行 G |

内核是操作系统的核心代码，负责管理 CPU、内存与硬件。普通 Go 代码运行在用户态，内核运行在内核态，能够管理线程的执行与切换。

`GOMAXPROCS=1` 表示只有一个 P，限制同时执行普通 Go 代码的数量；它不表示机器只有一个核心，也不表示进程只有一个 M。sysmon 由专门的 M 执行，不需要持有 P。

## 3. Go 如何请求和响应抢占

### 3.1 sysmon 发起请求

sysmon 通过 `retake()` 检查 P 的调度进度。如果同一调度周期持续过久，会通过 `preemptone()` 等路径请求抢占。

常见实现中的 `forcePreemptNS` 为 10 毫秒。这是请求抢占的判断阈值，不是每个 G 的严格时间片：检查存在间隔，多个 G 可能共享调度周期，实际响应也可能延迟。

### 3.2 协作式抢占

运行时设置 G 的抢占标记，并修改用于栈检查的状态。G 执行到具有相应栈检查的函数入口等位置时，发现抢占请求，进入运行时处理路径，让出执行机会。

纯 `for {}` 没有这样的函数调用检查点，因此不能仅依靠这类检查及时响应抢占。

### 3.3 异步抢占

Go 1.14 引入异步抢占，使没有函数调用的循环也能被抢占；是否可用取决于平台支持及运行时状态。

以 Linux 上普通业务 G 因运行过久被抢占为例，流程可概括为：

```text
sysmon 检查到 P 的调度进度长时间未变化
    ↓
设置抢占请求，并通过 preemptM 请求中断对应的 M
    ↓
向指定操作系统线程发送 SIGURG
    ↓
目标线程执行 Go 注册的信号处理逻辑
    ↓
确认当前执行位置和运行时状态允许异步抢占
    ↓
调整保存的执行现场，让返回后的执行流进入 asyncPreempt
    ↓
保存执行状态，进入 Go 调度器
    ↓
原 G 重新等待调度，其他可运行 G 有机会执行
```

信号到达并不保证立即抢占。如果当前位置不是异步安全点，或运行时正在执行不允许抢占的操作，这次请求可能无法完成抢占，需要等待后续机会。

G 后续再次被调度时，从暂停位置继续执行，也可能换到另一个 M 上运行。

普通异步抢占进入调度及重新排队的具体过程参见 [gopreempt_m](../functions/gopreempt_m.md)。

## 4. 信号如何打断正在运行的线程

### 4.1 信号定向发送给 M

Linux 上，Go 使用 `tgkill` 等平台实现向目标 M 的线程 ID 发送抢占信号，可概括为：

```text
tgkill(进程 PID, 目标线程 TID, SIGURG)
```

定向的是操作系统线程，不是 G。信号处理逻辑仍需检查目标线程当时实际执行的 G 及其状态。

`SIGURG` 中的 `SIG` 表示 Signal，`URG` 表示 Urgent，原本用于通知 socket 有紧急数据需要处理。它的默认行为是忽略；Go 运行时注册了相应的信号处理函数，用它触发异步抢占，在此场景中与网络紧急数据无关。

常见平台的编号如下，具体值取决于操作系统和架构，代码应使用 `SIGURG` 常量，不应硬编码数字。

| 平台 | SIGURG 编号 |
| --- | --- |
| Linux x86、ARM | 23 |
| macOS | 16 |

### 4.2 内核安排信号处理函数执行

线程正在执行，不表示它能拒绝被打断。CPU 支持中断、异常及系统调用入口，可以暂停用户态代码，转去执行内核代码；内核不需要等用户线程主动腾出 CPU。

对于未被屏蔽且可以投递的信号，内核在适当的返回用户态路径上保存线程的用户态执行现场，并安排它先执行信号处理函数。

信号处理函数运行在用户态，仍由目标线程执行，原来的业务代码此时暂停。普通信号处理完成后，通过 `sigreturn` 等机制恢复现场，继续原来的代码。

Go 异步抢占利用了这份保存的现场：满足安全条件时，修改恢复位置，让线程先进入 `asyncPreempt`，再转入调度器。

### 4.3 信号处理伪代码

下面用接近 Go 的伪代码说明职责划分，不是可以直接运行的代码。实际实现还包括信号入口汇编、信号栈及平台相关的现场处理。

```go
// 运行时初始化：告诉内核，收到 SIGURG 时调用谁。
注册信号处理函数(SIGURG, Go信号处理函数)

func Go信号处理函数(信号, 内核保存的现场) {
    if 信号 != SIGURG {
        处理其他信号()
        return
    }

    g := 当前线程正在执行的G

    if 存在抢占请求(g) && 当前状态允许抢占(g, 内核保存的现场) {
        // 不在信号处理函数里直接运行其他 G。
        // 修改恢复入口，并保留原位置，以便以后继续执行。
        修改恢复入口(内核保存的现场, asyncPreempt)
    }

    确认本次抢占信号已处理()
    // 返回后，内核按调整后的现场恢复用户态执行。
}

func asyncPreempt() {
    保存寄存器等执行状态()
    进入运行时调度逻辑() // 暂停当前 G，让其他 G 有机会执行。

    // 原 G 以后再次被调度，才会继续到这里。
    恢复寄存器等执行状态()
    返回原来被打断的位置()
}
```

信号处理函数在目标线程上执行；原来的业务代码暂停。对于死循环，完整过程可以理解为：

```text
for {} 执行到位置 A
    ↓ 收到 SIGURG
信号处理函数：检查安全条件，把恢复入口调整为 asyncPreempt
    ↓ 信号处理返回，内核恢复调整后的现场
asyncPreempt：保存状态，进入调度器
    ↓
其他可运行 G 有机会执行
    ↓ 原 G 再次获得执行机会
恢复状态，回到位置 A 继续循环
```

信号处理函数负责检查和调整现场，后续的抢占代码负责进入调度器。如果没有其他可运行 G，原 G 也可能很快继续执行。

### 4.4 信号与硬件中断的区别

| 机制 | 含义 | 在抢占过程中的作用 |
| --- | --- | --- |
| 信号 | 操作系统提供的软件通知，例如 `SIGURG` | 通知目标线程执行 Go 的信号处理逻辑 |
| 系统调用 | 用户态请求内核服务的入口，例如 `tgkill` | 让内核记录并投递信号 |
| IPI | 处理器间中断，属于硬件中断 | 必要时促使另一个逻辑 CPU 进入内核，及时处理通知 |
| 定时器中断 | 硬件定时器触发的中断 | 让内核获得执行机会，检查是否需要调度等 |

发送信号本身不是硬件中断。目标线程正在另一个逻辑 CPU 上运行时，Linux 可能借助 IPI 促使那个 CPU 响应；具体路径取决于内核实现与目标线程状态。

IPI 通常由内核代码发起，但由硬件中断机制投递，因此“软件发起”和“硬件中断”并不矛盾。

## 5. 单核机器如何完成抢占

这里的单核指机器只有一个可执行线程的逻辑 CPU。若一个物理核心支持多个硬件线程，则仍可能同时执行多个指令流。

单逻辑 CPU 上，sysmon 的 M 和业务 M 轮流运行，不需要 IPI：

```text
业务 M 执行 G 的死循环
    ↓ 定时器中断等事件
CPU 进入内核，内核有机会切换线程
    ↓
sysmon 的 M 获得 CPU，调用 tgkill
    ↓
内核为目标业务 M 标记待处理的 SIGURG
    ↓
业务 M 再次获得 CPU，在适当的返回用户态路径上投递信号
    ↓
执行 Go 信号处理逻辑，满足条件时抢占 G
```

定时器中断不是进入内核的唯一方式。网卡、键盘等设备中断，线程发起的系统调用，以及缺页等异常，也可以让 CPU 转入内核；是否切换线程取决于当时的调度条件。

但对于没有系统调用、没有异常的纯空循环，如果也没有其他设备中断，就需要定时器中断等外部事件来打断执行。普通用户态代码无法随意关闭操作系统配置的硬件中断。

操作系统切走业务 M，只表示换了线程；Go 运行时抢占 G，才表示当前 G 让出 Go 的执行资源。这是两个不同层次的切换。

## 6. 源码入口

- `src/runtime/proc.go`：`sysmon()`、`retake()`、`preemptone()` 等请求抢占与调度路径。
- `src/runtime/preempt.go`：安全点检查与异步抢占处理。
- `src/runtime/signal_unix.go`：Unix 平台的抢占信号处理。
- `src/runtime/os_linux.go`：Linux 平台的线程定向信号发送等实现。
- `src/runtime/preempt_*.s`：不同架构的 `asyncPreempt` 汇编实现。

阅读源码时，应切换到实际使用版本的 tag。
