# preemptPark

`preemptPark` 是 Go runtime 响应抢占停止请求的内部函数，定义于 `src/runtime/proc.go`。它在当前 M 的 `g0` 栈上执行，将目标 G 置为 `_Gpreempted` 并进入调度，供运行时后续取得该 G 的暂停控制权。

## 1. 使用场景

运行时需要安全检查某个 G 的栈等状态时，可以通过 `suspendG` 暂停目标 G。例如，GC 扫描正在运行的 goroutine 栈时，需要先让它停止修改栈。

这可以只针对一个 G，不等于暂停整个程序的 STW；`preemptPark` 也不是 GC 专用函数，不能将所有 GC 抢占都归为这一条路径。

## 2. 异步抢占入口

`suspendG` 发现目标 G 正在运行时，会设置 `preemptStop` 等请求标志，并请求目标响应抢占。标志表达停止意图，此时目标 G 仍可能继续运行一段时间。

在支持异步抢占的平台上，信号处理路径确认安全条件后，调整返回现场，使目标 G 执行 `asyncPreempt`，再进入 `asyncPreempt2`：

```go
if gp.preemptStop {
    mcall(preemptPark)
} else {
    mcall(gopreempt_m)
}
```

同一种抢占信号可以服务于不同请求，具体分支由目标 G 的标志决定。`mcall` 保存目标 G 的恢复现场，切换到同一个 M 的 `g0` 栈，再执行 `preemptPark`。

目标 G 如果已不在运行，`suspendG` 可以通过状态控制取得检查权限，不一定需要信号或经过 `preemptPark`。

## 3. 停止与调度

`preemptPark` 协调目标 G 的扫描状态与暂停状态，最终使其处于 `_Gpreempted`，解除它与 M 的执行绑定，再进入 [schedule](schedule.md)。

目标 G 不进入普通可运行队列。它的 `g` 对象、栈和恢复现场仍保留在内存中，运行时通过已有指针和全局 G 集合等引用管理它，无需专门的停止队列。

触发调度表示 M 可以寻找其他工作，不表示目标 G 立即恢复；没有可运行工作时，M 也可能等待。

## 4. 暂停控制与恢复

调用 `suspendG` 的执行方持有目标 G 的指针，等待确认目标已停止后取得其暂停控制权。对于 `_Gpreempted` 路径，`suspendG` 后续会将目标转为受控的等待状态，并通过扫描状态位等机制保护检查过程。

完成栈扫描等工作后，调用方使用 `suspendG` 返回的暂停凭据调用 `resumeG`，释放检查权限；如果目标是由本次请求停止的，恢复其运行资格。若目标原本就在等待，则不会仅因检查结束而把它变成可运行。

发起方与目标是不同的 G。暂停目标不会同时暂停发起方；发起方可以继续完成检查及恢复操作。目标再次被调度后，才从原先的抢占路径恢复执行。

## 5. 与普通抢占的区别

| 函数 | 目的 | 调度前目标 G 的状态 |
| --- | --- | --- |
| `preemptPark` | 停止目标 G，等待运行时取得控制权 | `_Gpreempted` |
| `gopreempt_m` | 让出执行权，重新排队 | `_Grunnable` |

具体状态转换及辅助逻辑以所用 Go 版本为准。
