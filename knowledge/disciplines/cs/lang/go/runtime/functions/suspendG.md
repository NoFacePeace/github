# suspendG

`suspendG` 是 Go runtime 暂停目标 goroutine 并取得其状态检查权限的内部函数，定义于 `src/runtime/preempt.go`。GC 扫描 goroutine 栈等路径会使用它，具体实现以所用 Go 版本为准。

## 1. 职责与调用条件

调用方传入目标 `*g`，`suspendG` 在确认目标不会继续执行、且已取得相应检查权限后返回 `suspendGState`。调用方处理完成后必须通过 `resumeG` 释放权限。

该操作用于安全查看目标的栈等状态，不等于暂停整个程序。运行时要求调用方遵守系统栈等内部调用约束，不能将它当作业务代码暂停任意 goroutine 的公开 API。

## 2. 按目标状态处理

| 目标状态 | 处理方式 |
| --- | --- |
| `_Grunning` | 设置抢占及停止请求，等待目标进入可安全接管的状态 |
| `_Grunnable`、`_Gwaiting` 等可接管状态 | 通过原子状态转换取得扫描权限，阻止检查期间恢复执行 |
| `_Gpreempted` | 接管停止结果，转入受控等待状态并取得扫描权限 |
| `_Gdead` | 记录目标已结束，无需扫描活跃栈 |

遇到其他扫描者持有权限或状态正在变化时，运行时需要等待或重试。实际分支还包括其他状态与一致性检查。

## 3. 正在运行时的停止请求

目标正在运行时，`suspendG` 设置 `preempt`、`preemptStop` 及栈检查相关标志，并在支持的平台上请求异步抢占。标志先表达停止意图，不代表目标当场停止。

异步抢占满足安全条件后，目标执行 `asyncPreempt2`，因为 `preemptStop` 为真，通过 `mcall(preemptPark)` 切到当前 M 的 `g0` 栈，进入 `_Gpreempted` 并转入调度。

调用方确认目标停止后再接管。已不在运行的目标通常无需这一步，也无需发送抢占信号；状态检查和转换会处理期间发生的竞态。

## 4. 暂停凭据与调用方

返回的 `suspendGState` 记录目标 G，以及本次操作是否使它停止、是否已结束等信息，供恢复时使用。它不只是一个“无条件唤醒目标”的指针。

调用方与目标是不同的执行上下文。目标停止后，调用方仍能继续检查并调用 `resumeG`。在 GC 的典型路径中，这些操作通过系统栈执行；同一个 M 同时只能执行一个上下文，不要求再创建一条专门的线程。

## 5. 相关函数
