# P

P 表示执行 Go 代码所需的调度资源，核心结构为 `src/runtime/runtime2.go` 中的 `p`。它连接可运行的 G 与执行它们的 M，并管理本地运行队列和部分运行时缓存。

## 1. 核心职责

- 管理本地可运行 G 的队列及 `runnext` 槽位。
- 保存内存分配缓存等资源，减少共享数据的竞争。
- 与调度器协作完成工作窃取、工作交接及运行时任务。

P 不是操作系统线程，也不对应固定 CPU 核心。普通 Go 代码在持有 P 的 M 上执行，P 可以在不同 M 之间交接。

## 2. 主要字段

以下是常见字段的作用概览，具体定义以所用 Go 版本为准。

| 字段 | 作用 |
| --- | --- |
| `id` | P 的运行时内部编号 |
| `status` | P 的状态 |
| `m` | 当前关联的 M |
| `runq` | 本地运行队列 |
| `runqhead`、`runqtail` | 本地队列的读写位置 |
| `runnext` | 优先考虑执行的 G |
| `mcache` | 内存分配缓存 |

字段属于运行时内部实现。队列组织、容量及缓存布局应以对应版本源码为准。

## 3. GOMAXPROCS

`GOMAXPROCS` 决定 P 的数量，限制同时执行 Go 代码的线程数量。它不限制 goroutine 总数、操作系统线程总数或处于系统调用中的线程数量。

例如，`GOMAXPROCS=2` 时可以有两个 P，同时支持最多两个 M 执行 Go 代码；其他 M 仍可能处于系统调用等状态。

默认值的计算与自动调整行为可能随 Go 版本、CPU 亲和性和容器环境变化。调优应结合实际 CPU 配额、吞吐量、延迟与竞争情况。

## 4. 运行队列

本地队列的结构与操作参见 [p.runq](p.runq.md)。

每个 P 管理本地运行队列，运行时还维护全局运行队列。调度器结合这些队列、网络轮询及计时器等来源寻找可执行工作。

当本地工作不足时，调度器可能从其他 P 窃取工作。它也会周期性检查全局队列以兼顾公平性。`runnext` 是优先调度机制的一部分，不保证相关 G 立即执行。

这些机制不提供严格 FIFO 顺序，程序不能依赖 goroutine 的创建顺序建立同步关系。

## 5. 状态与交接

P 的常见状态包括空闲、运行、系统调用、GC 停止和失效等，具体状态常量定义在 `runtime2.go` 中。

当 M 被系统调用阻塞时，运行时可以让其他 M 获取 P。GC 的 STW 阶段需要协调停止 P 上的普通 Go 代码执行；恢复后再继续调度。

调整 `GOMAXPROCS` 时，运行时会协调 P 数量及相关资源的变化，而非简单创建或删除同等数量的线程。

## 6. 源码入口

- `runtime2.go`：`p` 的结构定义及状态常量。
- `proc.go`：`acquirep()`、`releasep()`、`handoffp()`、`procresize()` 及运行队列相关函数。
- `mcache.go`：内存分配缓存。
