# G

G 是 goroutine 的运行时表示，核心结构为 `src/runtime/runtime2.go` 中的 `g`。它保存栈、执行上下文和调度状态，使 goroutine 能够暂停、等待并恢复执行。

## 1. 核心职责

- 保存 goroutine 栈的边界及栈检查信息。
- 保存切换执行时所需的调度上下文。
- 记录运行状态、等待原因及关联的 M 等信息。
- 配合调度器和 GC 完成抢占、栈扫描与栈调整。

G 不是操作系统线程。大量 G 可以轮流在少量 M 上执行，等待中的 G 通常不需要长期占用一个 M。

## 2. 主要字段

栈、调度状态、执行关系及等待记录的常见字段参见 [G 字段](Fields.md)，具体定义以所用 Go 版本为准。

这些字段属于运行时内部实现，不是应用可依赖的公开 API。Go 没有提供用于业务逻辑的稳定 goroutine ID 接口。

## 3. 生命周期

`go` 语句、G 的复用与分配、入队及首次执行过程参见[G 创建](Creation.md)。

主要状态、转换及等待与抢占停止的区别参见 [G 状态](State.md)。

`go` 语句通过运行时创建新的 G，并将其置为可运行。调度器选中它后，切换到其执行上下文运行。

```text
创建 → 可运行 → 运行 → 等待 → 可运行 → 运行 → 结束
```

这是一条典型路径，实际执行还可能经过系统调用、抢占等状态。被唤醒只表示可以再次执行，不保证立即获得执行机会。

goroutine 结束后，其 `g` 结构等资源可能被运行时复用。对象是否能被 GC 回收则取决于可达性，不能仅由 goroutine 是否结束判断。

## 4. 栈与线程关系

每个普通 goroutine 有自己的栈，运行时可以按需扩容，并在适当时机收缩。栈大小、调整条件及相关实现可能随版本变化。

普通 G 可以在不同 M 上恢复执行。使用 `runtime.LockOSThread()` 可以将调用它的 goroutine 绑定到当前操作系统线程，常用于依赖线程状态的外部库；这不会将 P 固定到该线程。

## 5. 源码入口

- `runtime2.go`：`g`、`gobuf` 及 G 状态常量。
- `proc.go`：`newproc()`、`newproc1()`、`gopark()`、`goready()`、`goexit0()` 等生命周期逻辑。
- `stack.go`：栈分配、增长与收缩。
- `preempt.go`：抢占相关逻辑。
