# m

`m` 是 Go runtime 的 `g` 结构体字段，定义于 `src/runtime/runtime2.go`，类型为 `*m`，用于关联执行这个 G 的操作系统线程的运行时表示。

## 1. 字段含义

```go
// 简化示意，并非完整结构定义。
type g struct {
    m *m
}
```

小写字段 `g.m` 是一个指针；M 是运行时对操作系统线程的抽象。二者不是两个独立的线程，也不是 G 创建时就永久绑定的关系。

## 2. 执行时的关联

调度器选中普通 G 执行时，会建立它与当前 M 的执行关系：`g.m` 指向该 M，`m.curg` 指向当前用户 G。

同一个 M 还通过 `m.g0` 关联自己的系统 G。切到 `g0` 栈执行运行时代码时，需要区分当前使用的执行栈与 `m.curg` 记录的用户 G。

## 3. 挂起与恢复

普通 G 挂起、让出执行权或结束时，运行时可以通过 `dropg` 等路径解除执行绑定，清理 `g.m` 和 `m.curg`。G 对象、栈及等待记录不会因此消失。

再次被调度时，G 可以关联另一个 M。因此，不能在 G 等待期间依赖 `g.m` 找到它上一次执行的线程，也不能认为每个存活 G 都有非空的 `g.m`。

## 4. 系统调用与线程绑定

进入系统调用时，G 与 M 的关系有专门状态协议，M 可能在不持有 P 的情况下继续执行系统调用，不能把所有“不执行普通 Go 代码”的情况都视为已经解除 G 与 M 的关联。

`runtime.LockOSThread()` 的持久线程绑定由 `lockedm`、`lockedg` 等专门字段与协议维护，不能仅靠 `g.m` 表达。绑定线程也不等于固定 P 或 CPU 核心。

具体字段与转换顺序以所用 Go 版本为准，这些内部字段不是业务代码可直接访问的公开 API。
