# 协作式抢占

协作式抢占借助编译器生成的栈检查，让 G 在检查点发现运行时的抢占请求，转入调度或停止路径。具体检查点和实现以所用 Go 版本为准。

## 1. 请求与检查点

运行时设置抢占标志，并将目标 G 的 `stackguard0` 设为 `stackPreempt`。G 执行到具有相应栈检查的函数入口时，检查触发并进入 `morestack`。

不是所有函数都有相同检查，纯空循环也可能没有这类调用检查点，因此不能仅依靠协作式检查保证及时抢占。

## 2. 进入系统栈

`morestack` 保存原 G 的现场并切到当前 M 的 `g0` 栈，调用 `newstack`。`newstack` 判断这是抢占请求还是实际需要扩栈，不能把进入 `morestack` 等同于一定扩容栈。

```text
函数入口栈检查 → morestack → newstack（g0 栈）
    ├── 普通抢占 → gopreempt_m → goschedImpl → schedule
    └── 停止请求 → preemptPark → schedule
```

此时已经在系统栈上，无需再通过 `mcall` 切换一次。

## 3. 暂缓抢占与恢复

`newstack` 仍需检查当前能否安全抢占。不满足条件时，按协议暂缓并恢复原 G，等待后续机会。

普通抢占将 G 重新排队，之后由调度器恢复；停止请求需要运行时取得暂停控制权并按需恢复。具体状态转换与异步抢占的对应后续函数保持一致。
