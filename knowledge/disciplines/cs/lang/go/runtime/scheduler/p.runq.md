# p.runq

`p.runq` 是 P 的本地运行队列，用于保存等待调度的可运行 [G](G.md)。调度器从队列中取出 G，交给持有该 P 的 M 执行。

## 1. 队列结构

P 的本地运行队列通常以固定容量的环形数组实现，相关字段定义在 `src/runtime/runtime2.go` 的 `p` 结构中。

| 字段 | 作用 |
| --- | --- |
| `runq` | 保存可运行 G 的环形数组 |
| `runqhead` | 队列读取位置 |
| `runqtail` | 队列写入位置 |
| `runnext` | 独立于环形队列的槽位，保存优先考虑执行的 G |

`runnext` 不属于 `runq` 数组，但与本地队列共同参与调度。队列容量和具体实现以所用 Go 版本为准。

## 2. 入队与出队

本地队列通常由持有 P 的线程添加和取出工作，其他 P 也可能通过工作窃取获取队列中的 G。因此，队列操作需要使用原子操作等机制协调并发访问。

本地队列空间不足时，运行时会将一部分工作转移到全局运行队列。调度器取本地工作时，还会考虑 `runnext` 中的 G。

G 进入运行队列表示它已具备执行条件，不表示立即运行。处于等待状态的 G 需要先被唤醒，再参与调度。

## 3. 工作窃取与全局队列

当某个 P 缺少工作时，调度器可能从其他 P 的本地队列获取一批 G，以分散负载。这种机制称为工作窃取。

全局运行队列由调度器共享，用于接收本地队列溢出的工作及其他需要全局调度的 G。它与每个 P 的 `runq` 是不同的数据结构。

调度器还会检查网络事件和计时器等工作来源，并周期性检查全局队列以兼顾公平性。不能只根据本地 `runq` 是否为空判断运行时是否没有工作。

## 4. 执行顺序

本地队列、`runnext`、全局队列及工作窃取共同决定后续执行的 G，不提供严格的 FIFO 执行保证。

业务代码应通过 channel、锁等同步机制保证必要的顺序，不能依赖 goroutine 创建或入队顺序。

## 5. 源码入口

- `runtime2.go`：P 的 `runq`、`runqhead`、`runqtail` 和 `runnext` 字段。
- `proc.go`：`runqput()`、`runqget()`、`runqputslow()`、`runqgrab()`、`runqsteal()` 等队列操作。
- `proc.go`：`findRunnable()` 中的工作查找与调度逻辑。
