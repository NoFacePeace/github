# 时间条件触发

时间条件触发是在较长时间没有 GC 时，由运行时请求推进一次垃圾回收的场景，对应常见内部类型 `gcTriggerTime`。具体条件与实现以所用 Go 版本为准。

## 1. 检查条件

sysmon 检查距离上次 GC 是否已超过 `forcegcperiod`。常见实现约为两分钟，但它不是严格的周期定时器，检查间隔、运行时状态及已有 GC 周期都会影响实际响应时间。

检查还受 GC 启用状态和阶段等条件约束。关闭相关自动 GC 策略时，不能假设仍会固定每两分钟运行一轮。

## 2. 检查者与执行者

sysmon 负责发现条件并唤醒后台强制 GC 的 goroutine。常见实现中，该 G 执行 `forcegchelper`，调用 GC 启动路径并使用时间类型触发条件。

sysmon 不亲自执行整轮标记与清扫，也不是给每个标记 worker 直接发送启动通知。

## 3. 调用流程

```text
sysmon 检查到时间条件满足
    ↓ 通过同步协议唤醒
后台强制 GC 的 G
    ↓ gcTriggerTime
gcStart
    ↓ 复查条件并协调启动
准备资源 → 清扫终止 → 并发标记
```

后台 G 被唤醒不表示条件此时必然仍成立，例如其他路径可能已启动 GC。启动流程需要再次检查，避免重复开启同一轮。

## 4. 使用边界

时间条件是运行时的兜底策略，不是业务可依赖的资源释放时限。文件、连接等外部资源仍需显式关闭，也不能假设触发后进程 RSS 必然下降。

## 5. 源码入口

- `src/runtime/proc.go`：sysmon 的时间检查与后台 G 唤醒。
- `src/runtime/mgc.go`：`forcegcperiod`、`forcegchelper`、`gcTriggerTime` 和 `gcStart`。
