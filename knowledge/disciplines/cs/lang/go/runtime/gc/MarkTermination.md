# 标记终止

标记终止（mark termination）是并发标记结束后的 STW 收尾阶段。运行时完成标记结果的收尾与状态切换，准备清扫，再恢复业务执行。具体完成协议和阶段边界以所用 Go 版本为准。

## 1. 进入条件

某个标记 worker 没有工作，不代表整轮标记已经结束。其他 worker、根扫描、标记辅助及写屏障缓冲中都可能存在尚未处理的工作。

运行时通过标记完成协议协调工作者，汇集和检查剩余工作，并在必要时继续并发标记。确认满足完成条件后，才推进标记终止。

## 2. STW 收尾

### 2.1 建立全局停止边界

暂停范围、安全停止及恢复过程参见 [STW](STW.md)。

运行时请求停止普通 Go 执行，并等待各 P 到达安全停止状态。发起 STW 不等于所有 P 已经当场停止，不可安全中断的关键操作需要先完成。

停止业务执行后，不会再由业务指针写入持续产生新的标记工作。运行时仍需完成协议规定的检查，不能单靠“业务停了”就假定所有标记缓冲已经处理完。

### 2.2 完成标记与状态收尾

确认标记工作收敛后，运行时完成必要的标记收尾、统计及后续阶段准备。若完成检查发现遗留工作，必须按协议处理，不能带着未处理的可达对象直接进入清扫。

这不是重新遍历所有对象做一遍完整标记；主要扫描工作已在并发标记期间完成。

## 3. 切换到清扫

运行时退出标记阶段，关闭标记阶段使用的写屏障，更新清扫相关状态，使本轮存活对象的标记结果可供清扫使用。

准备完成后恢复业务执行，进入[并发清扫](ConcurrentSweep.md)，清扫与业务交错推进，回收未标记对象占用的空间。具体哪些准备位于恢复前、哪些工作在恢复后执行，需要结合对应版本源码判断。

```text
并发标记完成协调
    ↓ STW，确认安全停止及标记完成条件
标记终止：收尾、退出标记、准备清扫
    ↓ 恢复业务执行
并发清扫
```

## 4. 对 worker 与业务 G 的影响

后台标记 worker 不会因为本轮标记结束而全部销毁，可以挂起并在后续 GC 中复用。标记辅助也随阶段切换结束本轮相应的辅助职责。

STW 结束后，可运行 G 继续参与调度；原本等待 channel、锁或 I/O 的 G 不会仅因 GC 阶段结束而全部被唤醒。

## 5. 与清扫终止的区别

| 对比 | 清扫终止 | 标记终止 |
| --- | --- | --- |
| 所在边界 | 本轮标记之前 | 本轮并发标记之后 |
| 结束的工作 | 上一轮剩余清扫 | 本轮标记 |
| 主要准备 | 本轮标记状态与写屏障 | 清扫状态及相关收尾 |
| 后续阶段 | 并发标记 | 并发清扫 |

两者都是 STW 边界，但承担不同阶段的交接职责。

## 6. 源码入口

- `src/runtime/mgc.go`：`gcMarkDone`、`gcMarkTermination` 及 GC 状态切换。
- `src/runtime/mgcmark.go`：标记工作处理与相关收尾逻辑。
- `src/runtime/mgcsweep.go`：清扫状态与清扫执行。
