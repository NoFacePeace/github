# 堆增长触发

堆增长触发是 Go runtime 根据堆分配进度请求启动 GC 的主要自动触发场景，对应常见内部类型 `gcTriggerHeap`。具体检查位置与阈值策略以所用 Go 版本为准。

## 1. 触发条件

内存分配相关路径在适当位置检查控制器维护的堆大小估计是否达到 GC 启动阈值。不是每次对象分配都完整检查并启动一轮，也不是发现某个对象不可达就立即回收它。

启动阈值与目标堆大小不同：运行时通常提前启动标记，为标记期间继续发生的分配预留空间。

## 2. 调用流程

```text
内存分配推进堆增长
    ↓ 检查 gcTriggerHeap 条件
gcStart
    ↓ 协调启动并重新检查条件
准备资源 → 清扫终止 → 并发标记
```

多个分配者可以同时发现条件成立，但不能各自独立开启一轮标记。`gcStart` 取得相应启动权限后复查条件，可能发现本次已无需启动。

## 3. 目标与内存限制

`GOGC` 影响堆增长目标，GC 控制器结合分配速度、标记速度和内存软限制等因素计算实际节奏。

`GOMEMLIMIT` 主要通过约束目标和节奏影响这一机制，不是独立于 `gcTriggerHeap`、`gcTriggerTime`、`gcTriggerCycle` 的第四个同级触发类型。

`GOGC=off` 关闭由增长比例驱动的自动 GC，但内存软限制仍可能驱动 GC。堆目标也不是保证永不超过的硬上限，GC 不能回收仍然存活的对象。

## 4. 源码入口

- `src/runtime/malloc.go`：分配相关的触发检查。
- `src/runtime/mgc.go`：`gcTriggerHeap`、触发测试及 `gcStart`。
- `src/runtime/mgcpacer.go`：堆目标、触发阈值与节奏控制。
