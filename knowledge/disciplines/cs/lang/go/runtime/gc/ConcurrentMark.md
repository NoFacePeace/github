# 并发标记

并发标记是 Go GC 确定存活对象的主要阶段。清扫终止完成准备并恢复业务执行后，运行时扫描根和可达对象，标记工作与业务代码交错进行。具体实现以所用 Go 版本为准。

## 1. 主要工作

1. 扫描全局变量、goroutine 栈等根，发现直接可达的堆对象。
2. 将新发现的对象加入标记工作，沿对象中的指针继续扫描。
3. 配合写屏障处理业务执行期间的引用变化，避免漏标存活对象。
4. 协调各类标记工作完成，准备进入标记终止阶段。

标记只确定哪些对象仍然存活，不在这一阶段普遍回收未标记对象的空间；空间回收由后续清扫完成。

## 2. 谁执行标记

### 2.1 后台标记 worker

运行时通过 GC 标记 worker 执行根扫描、对象扫描等工作，并根据 GC 进度与可用执行资源安排运行。

worker 的生命周期参见 [GC 标记 worker](worker.md)，调度器领取可用 worker 的池参见 [gcBgMarkWorkerPool](../variables/gcBgMarkWorkerPool.md)。

“并发”表示标记与业务执行可以交错推进，不保证任意时刻都在不同 CPU 上同时执行。只有一个 P 时，两者也可以通过调度轮换执行。

### 2.2 标记辅助

分配内存的业务 G 可能产生标记辅助债务。当标记进度需要追赶分配时，该 G 会参与标记工作，必要时等待标记进度推进。

因此，即使没有全局 STW，GC 仍可能通过辅助标记、CPU 消耗和调度竞争影响请求延迟。

## 3. 根与对象扫描

### 3.1 根扫描

运行时将根扫描组织为任务，扫描全局根、goroutine 栈等入口，从中发现需要继续追踪的对象。

根引用的来源和引用链示例参见[根对象](roots.md)。

扫描某个 G 的栈时，需要先取得检查权限，保证目标不会同时修改栈。运行时通过 [suspendG](../functions/suspendG.md) 等机制协调，完成后通过 [resumeG](../functions/resumeG.md) 释放权限并按需恢复运行资格。

针对单个 G 的暂停不等于暂停整个程序。已经等待或可运行的 G 与正在运行的 G，也会采用不同的状态协调路径。

### 3.2 堆对象扫描

对于新发现的堆对象，运行时设置标记并扫描其中的指针字段，将尚未处理的可达对象加入后续工作。没有指针的对象不需要继续追踪其内部引用。

对象间即使形成引用环，只要不能从根到达，也不会仅因成环就被视为存活。

## 4. 写屏障的配合

业务代码可以在扫描期间修改对象之间的引用。写屏障与标记算法配合，记录必要的引用变化并产生相应标记工作，防止尚未扫描到的存活对象失去可追踪路径。

写屏障在清扫终止的准备阶段开启，业务恢复前必须建立正确的标记协议。它不等于阻止业务写入，也不是为每个对象加一把互斥锁。

## 5. 何时算完成

某个 worker 的本地队列暂时为空，不代表全局标记结束。其他 worker、根扫描任务、标记辅助或写屏障缓冲中仍可能存在工作。

运行时通过标记完成协议协调工作者、检查和汇集待处理工作，必要时继续标记，最终在确认满足完成条件后进入[标记终止](MarkTermination.md)。相关检查与 STW 收尾的具体边界以所用版本为准。

## 6. 与相邻阶段的关系

```text
清扫终止：完成旧清扫，准备标记并开启写屏障
    ↓ 恢复业务执行
并发标记：根扫描、对象扫描、写屏障及标记辅助
    ↓ 确认标记工作收敛
标记终止：STW 收尾并切换到清扫阶段
```

并发标记期间，栈扫描可能导致单个 G 的短暂停顿；标记终止则是全局协调的 STW 边界，两者需要区分。

## 7. 源码入口

- `src/runtime/mgc.go`：GC 标记 worker、标记完成协调与阶段切换。
- `src/runtime/mgcmark.go`：根扫描、对象标记、标记工作排空及辅助标记。
- `src/runtime/mwbbuf.go`：写屏障缓冲及其处理。
- `src/runtime/preempt.go`：目标 G 的暂停与恢复控制。
