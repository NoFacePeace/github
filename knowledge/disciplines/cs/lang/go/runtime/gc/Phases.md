# GC 阶段

Go 的一轮垃圾回收通常按清扫终止、并发标记、标记终止和并发清扫四个阶段理解。具体实现与辅助逻辑以所用 Go 版本为准；这些概念阶段与源码中的 GC 状态常量并非一一对应。

## 1. 整体流程

| 阶段 | 主要工作 | 是否 STW |
| --- | --- | --- |
| 清扫终止 | 完成上一轮剩余清扫，准备标记并开启写屏障 | 是 |
| 并发标记 | 扫描根与可达对象，确定存活对象 | 否，扫描单个 G 的栈时需暂停该 G |
| 标记终止 | 确认标记完成，执行收尾并切换到清扫阶段 | 是 |
| 并发清扫 | 回收未标记对象占用的空间，供后续分配复用 | 否 |

```text
清扫终止 → 并发标记 → 标记终止 → 并发清扫
  STW                    STW
```

STW（Stop The World）暂停业务 Go 代码的执行，让运行时完成需要全局协调的工作；不是停止所有操作系统线程。

## 2. 清扫终止

执行者、剩余清扫及 STW 协调过程参见 [清扫终止](SweepTermination.md)。

本轮标记开始前，运行时暂停业务执行，确保上一轮需要完成的清扫工作已经结束，准备标记所需状态，并开启并发标记使用的写屏障。

完成准备后恢复业务执行，进入并发标记。清扫终止与标记终止是两个不同的 STW 边界。

## 3. 并发标记

### 3.1 扫描根与可达对象

从全局变量、goroutine 栈等根出发，沿指针引用扫描对象并标记存活对象。后台标记 worker 执行标记工作；分配较快的业务 G 也可能通过标记辅助参与。

### 3.2 写屏障

业务代码继续运行时可能改变指针关系。写屏障记录必要的引用变化，配合标记算法防止漏掉仍然可达的对象。

### 3.3 goroutine 栈扫描

扫描某个 G 的栈需要保证扫描期间该栈不会被目标继续修改。运行时通过 `suspendG` 取得检查权限，完成后通过 `resumeG` 释放权限并按需恢复运行资格。

目标正在运行且走异步抢占停止路径时，可通过 `preemptPark` 提交停止状态。针对单个 G 的暂停不等于全局 STW，也不代表整个并发标记期间业务都停止。

## 4. 标记终止

运行时通过标记完成协议确认后台及辅助标记等产生的工作已经收敛，在 STW 下完成必要的标记收尾和状态切换。

随后关闭标记阶段的写屏障，准备清扫并恢复业务执行。不能仅凭某一个标记队列暂时为空就认为整轮标记已经完成。

## 5. 并发清扫

根据标记结果清扫堆内存，将未标记对象占用的空间回收以便后续分配复用。清扫可由后台任务推进，也可能由后续分配操作按需触发。

清扫不要求移动所有存活对象，也不等于立即把物理内存归还操作系统。空闲物理内存的归还由 scavenger 等机制处理。

## 6. 源码阶段状态

运行时常见的 GC 状态包括 `_GCoff`、`_GCmark`、`_GCmarktermination`。它们表达运行时协议所需的状态，不能直接作为上述四个概念阶段的同名枚举。

例如，并发清扫通常在 `_GCoff` 状态下进行；`off` 不代表此时没有任何垃圾回收相关工作。
