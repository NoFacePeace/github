# mutexWoken

`mutexWoken` 是 Mutex state 的第 1 位，值为 `1 << 1`。它表示已有一个被唤醒或承担自旋竞争的 G，帮助解锁方避免再唤醒额外等待者。以下按 Go 1.26.3 内部实现说明。

## 1. 为什么需要

普通模式下，被唤醒的等待者不立即拥有锁；新来的 G 可能先取得锁并再次解锁。如果每次解锁都再唤醒一个 G，就可能产生不必要的并发竞争。

```text
G1 解锁：设置 woken，唤醒 G2
    ↓
G2 尚未取得锁，新来的 G3 先取得
    ↓
G3 解锁：发现已有 woken 标记，暂不额外唤醒 G4
```

## 2. 谁设置标记

| 路径 | 设置原因 |
| --- | --- |
| 普通模式的解锁慢路径 | 通过 CAS 取得唤醒资格，再释放信号量唤醒等待者 |
| 满足条件的自旋者 | 表示已有 G 主动等待锁，提示解锁方无需额外唤醒 |

自旋者设置还需要当前没有 woken 标记且存在等待者等条件。具体由原子状态更新保证竞争下的协调。

## 3. 谁清除标记

承担该标记的 G 在加锁慢路径中使用局部 awoke 状态记录责任，并在后续 CAS 更新中清除 woken。随后它可能取得锁，也可能重新登记等待。

因此，woken 不是永久状态，也不表示目标 G 一定已经在 CPU 上运行。

## 4. 与锁归属的区别

woken 不表示持有锁，不包含 G 的指针或 ID，也不保证普通模式的唤醒者优先于新竞争者取得锁。它主要控制是否需要再增加一个活跃竞争者。
