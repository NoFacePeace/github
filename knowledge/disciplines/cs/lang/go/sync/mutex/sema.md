# Mutex sema

`sema` 是 Mutex 内部用于等待与唤醒协调的 uint32 字段，名称来自 semaphore，即信号量。它配合运行时信号量机制处理竞争者的等待，不直接表示锁是否被持有。

## 1. 数值与地址

| 内容 | 作用 |
| --- | --- |
| `m.sema` | 保存运行时信号量的令牌计数 |
| `&m.sema` | 作为等待关系的标识，定位运行时等待结构 |

sema 不是 OS 信号量句柄，也不直接保存等待 G 的指针。令牌、semtable 和等待队列的通用机制参见[运行时信号量](../../runtime/semaphore/Semaphore.md)。

## 2. 加锁时的作用

Lock 快路径通过 state 的 CAS 尝试取得锁，无竞争时不需要进入信号量等待。

竞争路径在决定等待后，调用 `runtime_SemacquireMutex(&m.sema, ...)`。运行时尝试取得令牌，必要时按地址登记等待者并挂起 G；如果令牌已经可用，也可能不必真正挂起。

## 3. 解锁时的作用

Unlock 先更新 state，只有需要唤醒或交接时才调用 `runtime_Semrelease(&m.sema, ...)`。运行时释放令牌，并按相应协议查找和唤醒等待者。

普通模式下，信号量等待返回不代表 G 已取得 Mutex，仍可能需要重新竞争；饥饿模式下，则配合交接协议修正锁定位和等待计数。

## 4. 与 state 的分工

state 维护锁归属和竞争模式，sema 负责等待通知的协调。两者属于不同层次，不能把令牌数理解为锁持有者数量，也不能仅根据 sema 判断是否可以进入临界区。

## 5. 地址稳定性

运行时按信号量地址区分等待关系，因此 Mutex 首次使用后不能复制。复制不仅会复制已有锁状态，也会产生不同的 sema 地址，无法继续沿用原地址的等待协议。
