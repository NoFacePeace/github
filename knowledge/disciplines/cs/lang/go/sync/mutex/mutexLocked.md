# mutexLocked

`mutexLocked` 是 Mutex state 的最低位，值为 `1 << 0`，用于表示锁定状态。以下按 Go 1.26.3 内部实现说明。

## 1. 加锁时设置

普通 Lock 快路径执行 `CAS(&state, 0, mutexLocked)`，成功后取得锁。慢路径也可以在允许竞争时通过 CAS 设置 locked 位，保留其他状态信息。

多个 G 不能仅通过普通读取发现 locked 为零后直接进入临界区，必须按原子状态协议竞争。

## 2. 解锁时清除

Unlock 通过 `atomic.AddInt32(&state, -mutexLocked)` 清除锁定位，再根据剩余状态判断是否需要唤醒或交接。

如果原本没有锁定，解锁属于错误使用，会触发运行时致命错误，而不是得到一次无效果操作。

## 3. 不记录持有者

locked 位不包含 G 的身份。Mutex 不依靠它识别递归加锁或验证解锁者身份，因此不可重入，但允许在正确协议下由另一个 G 解锁。

## 4. 与饥饿交接的关系

饥饿模式交接期间，locked 位可以暂时为零，但 starving 位仍阻止新来的 G 抢锁。接收交接的等待者恢复后会补齐锁定位和等待计数。

所以 locked 为零不等价于整个 Mutex 已经完全空闲。
