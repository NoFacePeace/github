# Mutex state

`state` 是 Mutex 内部的 int32 字段，将三个状态位和等待计数编码在一个整数中，通过原子操作协调加锁、解锁和等待。以下按 Go 1.26.3 的内部实现说明。

## 1. 位布局

```text
高位                         低位
等待计数 … | starving | woken | locked
               bit 2    bit 1   bit 0
```

| 内容 | 数值或计算方式 | 作用 |
| --- | --- | --- |
| [mutexLocked](mutexLocked.md) | `1 << 0` | 标记锁已被持有 |
| [mutexWoken](mutexWoken.md) | `1 << 1` | 协调已有竞争者，减少重复唤醒 |
| [mutexStarving](mutexStarving.md) | `1 << 2` | 标记饥饿交接模式 |
| 等待计数 | `state >> 3` | 锁协议维护的等待者数量 |

三个标记可以组合存在，并非互斥的三个枚举值。`mutexWaiterShift` 为 3，增加一个等待者对应加上 `1 << 3`。

## 2. 常见状态

| 示例 | 含义 |
| --- | --- |
| `state == 0` | 没有锁定、唤醒、饥饿标记和等待计数 |
| 只有 locked 位 | 已锁定，尚无其他状态 |
| locked 位加等待计数 | 有 G 持锁，另有等待者 |
| woken 位，locked 位为零 | 已有唤醒者或承担竞争的 G，但尚未设置锁定位 |
| starving 位，locked 位为零 | 可能处于交接阶段，新来的 G 仍不能抢锁 |

不能仅看 locked 位为零就认为当前锁可以自由获取。普通 Lock 的快路径要求整个 state 为零；慢路径和 TryLock 会根据完整状态采用相应规则。

## 3. 与信号量和等待队列的分工

state 维护锁的竞争协议，不保存具体等待 G 的指针。信号量字段及运行时等待结构负责通知与具体等待记录。

state 的等待计数不是信号量令牌数，也不等于某个运行时桶的总等待计数。唤醒和交接期间，各层计数会按各自协议更新。

## 4. 状态更新

Lock 使用 CAS 竞争锁或更新等待状态；Unlock 用原子减法清除锁定位，并按需执行唤醒或交接。状态可能在读取后被其他 G 改变，因此慢路径通过循环和 CAS 失败后的重新读取协调竞争。

这些字段是内部实现，不应由业务代码通过 unsafe 修改或用于判断能否绕过锁访问共享数据。
