# roots

根（GC Roots）是垃圾回收器查找存活对象的起点。通常说的“根对象”，更准确地说是一组需要扫描的引用位置，不一定是某个独立的堆对象。

GC 从根出发，沿指针引用查找堆对象。只要一个对象能从根到达，它就是可达对象，需要保留；无法从根到达的对象可以被回收。

## 1. 根引用来自哪里

### 1.1 全局变量

包级变量中保存的指针引用可以让堆对象保持可达，例如全局缓存或当前用户指针：

```go
var currentUser *User
```

`currentUser` 是保存引用的位置，它指向的 `User` 实例是被引用的对象。变量名本身不是 GC 判断可达性的依据。

### 1.2 goroutine 栈上的活跃引用

goroutine 执行函数时，其栈上的活跃指针也可以作为扫描起点，例如后续仍要使用的局部变量或参数。

```go
func printUser(user *User) {
    fmt.Println(user.Name)
}
```

编译器会提供指针位置和活跃性信息，帮助 GC 扫描栈。变量仍在词法作用域内，不代表它一定保持活跃；如果后续不再使用，编译器可能判断它已不需要保留。

对象也可能被优化为栈上分配，此时不需要作为独立的堆对象清扫。这里的代码用于说明引用关系，实际分配位置取决于编译器优化。

### 1.3 运行时维护的引用

Go runtime 是程序自带的底层支持代码，负责 goroutine 调度、定时器和 GC 等工作。它在管理这些功能时也会保存引用。

并不是每个运行时内部对象都直接属于 GC 根。某些引用作为扫描起点，另一些则通过其他根形成引用链，最终让相关对象保持可达；具体扫描方式取决于运行时实现。

例如，等待执行的定时器需要保留回调，而回调可能引用用户对象：

```go
func scheduleGreeting(user *User) {
    time.AfterFunc(time.Minute, func() {
        fmt.Println(user.Name)
    })
}
```

可以用以下简化的引用链理解其效果：

```text
运行时持有的定时器 → 回调函数 → user 对象
```

只要等待执行的回调仍被保留，回调引用的 `user` 就保持可达。这里的链表示保留关系，不是运行时内部结构的完整布局。

## 2. 如何沿引用链找到对象

以下类型表示用户、个人资料和头像，它们是业务对象示例，不是 Go GC 的专有概念：

```go
type User struct {
    Name    string
    Profile *Profile
}

type Profile struct {
    Avatar *Avatar
}

type Avatar struct {
    URL string
}

var currentUser *User
```

假设三个对象已创建并通过这些字段连接，引用链为：

```text
currentUser → User 对象 → Profile 对象 → Avatar 对象
```

GC 扫描 `currentUser`，找到 `User`，再扫描它的 `Profile` 字段，最后通过 `Avatar` 字段找到头像对象。这三个堆对象都可达，因此会被保留。

一个对象不必直接被根引用；只要能沿引用链找到它，就属于可达对象。

## 3. 什么时候变成不可达

```go
currentUser = nil
```

如果没有其他活跃引用指向上述对象，原来的引用链就不再能从根到达，相关堆对象可以在后续 GC 中被回收。如果局部变量、缓存或回调仍然持有引用，它们仍可能保持可达。

互相引用也不代表对象无法回收：

```text
根引用 → A → B     A、B 可达
         C ↔ D     如果没有来自根的引用，C、D 不可达
```

Go GC 根据可达性判断存活状态，不是根据引用次数。因此，没有根引用能到达的引用环也可以被回收。

## 4. 常见误解

| 误解 | 说明 |
| --- | --- |
| 所有局部变量都是根 | 栈扫描关注编译器识别的活跃指针引用 |
| 所有堆对象都是根 | 堆对象通常通过根及其他对象的引用被发现 |
| 对象之间互相引用就不会回收 | 没有从根出发的引用路径，引用环也可以回收 |
| 将一个指针设为 `nil` 就会立即回收对象 | 还要确认没有其他引用，并等待 GC 回收 |
| GC 回收对象就会及时释放文件或连接 | 这些资源应显式关闭，不能依赖 GC 及时释放 |
