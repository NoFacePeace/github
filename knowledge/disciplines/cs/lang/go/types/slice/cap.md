# 切片 cap

cap 是运行时 slice 结构中的 int 字段，记录从切片起点开始可使用的底层数组范围。业务代码通过内建函数 `cap(s)` 查询。

## 1. 容量与长度

```go
s := make([]int, 2, 5)
// len(s) 为 2，cap(s) 为 5。
```

普通切片满足 `0 <= len(s) <= cap(s)`。容量足够不代表可以直接访问超出长度的下标，必须先合法地重新切片，或通过 append 扩展结果长度。

## 2. 截取后容量如何变化

```go
values := [5]int{10, 20, 30, 40, 50}
s := values[1:3]
// len(s) 为 2，cap(s) 为 4。
```

容量从新切片起点计算，不是整个原数组长度。对切片 a 使用 `a[low:high]`，结果容量通常为 `cap(a) - low`，长度为 `high - low`。

## 3. 完整切片表达式

```go
a := []int{1, 2, 3, 4}
s := a[1:3:3]
// s 包含 [2, 3]，len(s) 和 cap(s) 都为 2。
s = append(s, 9) // 超出 s 的容量，使用新的底层存储。
// a 仍为 [1, 2, 3, 4]。
```

完整切片表达式 `a[low:high:max]` 的容量为 `max - low`，边界需满足相应范围规则。它限制后续重新切片和追加对原存储的使用范围，但没有复制现有元素，也不阻止直接修改共享元素。

## 4. append 与扩容

追加后的长度未超过容量时，append 通常复用现有数组；超出容量时，准备新数组并复制原元素，返回新的容量。

扩容策略不属于语言保证，不能依赖始终翻倍或某个固定阈值。预先估计容量可以减少部分扩容，但也可能增加存储保留量。

## 5. 容量不代表内存释放

限制 cap 不会缩小底层分配，也不会自动释放切片范围之外的数组存储。需要更小的独立存储时，应按需新建并复制。

nil 切片容量为零，但容量为零的切片不一定是 nil。cap 是元素数量，不是字节数或某份独立分配的完整大小。
