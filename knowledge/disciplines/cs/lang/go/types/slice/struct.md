# 切片结构

切片的常见运行时表示由底层数据指针、长度和容量组成。赋值和传参复制这份描述信息，不会自动复制底层数组。以下结构见 Go runtime 的 `src/runtime/slice.go`，具体布局属于实现细节。

## 1. 结构字段

```go
type slice struct {
    array unsafe.Pointer
    len   int
    cap   int
}
```

| 字段 | 作用 |
| --- | --- |
| [array](array.md) | 定位切片关联的底层元素存储 |
| [len](len.md) | 当前可通过下标访问的元素数量 |
| [cap](cap.md) | 从切片起点开始可使用的底层数组范围 |

常见 64 位平台上，这份描述信息占 24 字节，不包含底层元素存储。字段名不是业务代码可通过 `s.array`、`s.len`、`s.cap` 访问的公开属性，长度和容量通过内建函数查询。

## 2. 与底层数组的关系

```text
底层数组：[10][20][30][40][50]
               ↑
切片：array ────┘
      len = 2，可访问 [20, 30]
      cap = 4，可重新切片到 [20, 30, 40, 50]
```

切片起点可以位于数组中间，不一定指向整个数组的起始位置。array 本身不记录完整数组长度，也不能直接用它推断分配位置或生命周期。

## 3. 长度与容量边界

```go
values := [5]int{10, 20, 30, 40, 50}
s := values[1:3]
// len(s) == 2，cap(s) == 4。

// s[2] // 越界：当前长度只有 2。
t := s[:4] // 可以在容量范围内扩展长度。
_ = t
```

容量表示可重新切片或追加时使用的范围，不表示所有容量范围内的元素都能直接按原切片下标访问。完整切片表达式可以限制容量，但不复制底层数据。

## 4. 赋值与共享

```go
a := []int{1, 2, 3}
b := a
b[0] = 99
b = b[:1]
// a[0] 为 99，但 len(a) 仍为 3。
```

复制后，两个描述信息可以关联同一份数据，所以修改共享元素相互可见；改变 b 的长度不会自动改变 a 的长度。

## 5. append 的影响

容量足够时，append 通常复用原存储，返回更新长度的切片；容量不足时，准备更大的底层存储并复制原元素，返回值的数据指针和容量可能改变。

调用方应保存 append 的返回值。局部 append 不会自动更新其他切片变量的描述信息；即使复用了原数组，其他变量的长度也不会自动增加。

## 6. nil 与空切片

nil 切片的描述信息为零值：数据指针为 nil，长度和容量均为零。非 nil 的空切片长度也可以为零，但不能仅通过 len 或 cap 是否为零判断它是否为 nil。

零大小元素的切片可能有特殊存储处理，不能根据不同元素地址是否相同推断它们的逻辑索引相同，也不应依赖内部地址构造业务规则。

## 7. 内存与并发

切片可能保留底层数组，即使当前只暴露其中少量元素。缩短长度或限制容量不等于立即释放其余存储；需要独立小存储时应按需分配并复制。

切片描述信息包含多个字段，不保证整体读写原子性。同一切片变量的并发修改，或共享元素上的冲突访问，需要正确同步。

## 8. 源码入口

- `src/runtime/slice.go`：slice、创建、扩容和复制辅助逻辑。
- `src/cmd/compile/internal`：切片布局、表达式和 append 等操作的代码生成。

业务代码不应通过 unsafe 随意伪造描述信息；类型、范围、存储有效性和 GC 可达性都需要满足相应契约。
