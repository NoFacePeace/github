# 字符串结构

Go 字符串的常见运行时表示由数据指针和字节长度组成。以下按本地 Go 1.26.3 的 `src/runtime/string.go` 说明，这属于实现细节，不是业务代码应直接操作的公开结构。

## 1. 核心字段

```go
type stringStruct struct {
    str unsafe.Pointer
    len int
}
```

| 字段 | 作用 |
| --- | --- |
| [str](str.md) | 指向字符串字节数据 |
| [len](len.md) | 字节数，对应语言层面的 `len(s)` |

在常见 64 位架构中，这份描述信息占 16 字节，不包含它所指向的数据大小。字符串没有切片那样的容量字段，也不要求数据以零字节结尾。

## 2. 描述信息与数据

```text
字符串值
    ├─ str ──→ 字节数据：G o
    └─ len：2
```

字符串变量保存的是描述信息，字节数据可以来自常量存储、运行时分配或其他符合生命周期要求的存储。不能因为内部有指针就把 string 当作 `*byte` 使用。

## 3. 赋值与传参

```go
a := "hello"
b := a
a = "Go"
// b 仍然是 "hello"。
```

赋值复制字符串值，通常不复制全部字节，a 和 b 可以暂时关联同一份不可变数据。重新赋值 a 只是更换它的描述信息，不修改 b 的内容。

## 4. 子串与存储共享

对非空子串，运行时可以通过调整数据指针和长度复用原存储：

```go
s := "hello"
part := s[1:4] // "ell"
```

part 的描述信息可以指向原数据中的偏移位置。小子串因此可能延长较大底层存储的生命周期；需要独立存储时，可根据实际需求使用 `strings.Clone`。具体优化以编译结果为准。

## 5. 长度与编码

len 记录字节数，不记录 rune 数量，也不保存编码类型。例如 `"语言"` 以 UTF-8 编码时有 6 个字节，但只有两个码点。

字符串允许包含无效 UTF-8 和零字节，结构本身不验证文本编码。按码点遍历需要解码，不能仅通过长度字段直接得到字符数量。

## 6. 空字符串与不可变性

空字符串的长度为零，但不应依赖其内部数据指针一定为 nil。语言层面的 string 也不能与 nil 比较。

数据指针不代表业务代码获得修改权限。通过 unsafe 修改字符串可能破坏共享、只读存储及编译器假设；普通字符串操作必须遵守不可变语义。

## 7. 源码入口

- `src/runtime/string.go`：stringStruct 及字符串辅助操作。
- `src/unsafe/unsafe.go`：String、StringData 等底层 API 的契约，使用时必须满足生命周期和不可变性要求。
