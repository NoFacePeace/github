# 字符串 str

`str` 是运行时 stringStruct 中的数据指针字段，类型为 `unsafe.Pointer`，用于定位字符串的字节数据。它是内部表示，不是语言层面可直接访问的 string 字段。

## 1. 指向什么

```text
stringStruct
    ├─ str ──→ 字符串字节数据
    └─ len：字节数量
```

str 只记录数据位置，长度由独立的 len 字段描述。字符串不要求以零字节结尾，也允许数据中间包含零字节，因此不能按 C 字符串的方式仅靠结束符判断范围。

数据可能位于常量存储、运行时分配的存储或其他满足契约的区域。指针类型本身不能说明数据一定在堆上。

## 2. 赋值与子串

字符串赋值和传参复制描述信息，可以共享同一份不可变数据。重新给变量赋值只会改变该变量关联的字符串，不会修改其他变量的内容。

截取非空子串时，新字符串可以将数据指针偏移到原数据内部，并调整长度，不必复制全部字节。因此，小子串可能使原始的大块存储继续存活。

## 3. 指针不代表可修改

str 虽然指向字节数据，但不赋予写入权限。字符串内容在语言层面不可变，通过 unsafe 强行修改可能破坏只读存储、共享数据和编译器假设。

需要修改内容时，通常转换为 `[]byte` 或 `[]rune`，修改后再构造字符串。

## 4. 空字符串

空字符串长度为零，不应依赖其内部 str 一定为 nil。空字符串可能来自零值、字面量或截取等不同路径，语言保证的是内容为空。

`unsafe.StringData` 可取得底层字节指针，但空字符串的返回值未作固定保证，可能为 nil；无论如何都不能通过返回指针修改字符串数据。

## 5. 生命周期

保存普通 string 值时，编译器和运行时负责其关联数据的合法生命周期。若使用 unsafe 从外部内存构造字符串，则调用方必须保证数据在使用期间有效且不被修改。

把地址转为 uintptr 不等于持有一个能让 GC 保持对象存活的普通指针，不能用这种方式随意保存字符串数据地址。
