# Map 删除

`delete(m, key)` 删除 map 中指定键的条目。以下按 Go 1.27.2 的 Swiss Table 实现说明：先定位并比较完整键，找到后清理条目、更新控制信息和计数；未找到则不改变映射内容。

## 1. 基本用法

```go
m := map[string]int{"go": 1, "java": 2}
delete(m, "go")

value, ok := m["go"] // value 为 0，ok 为 false。
_ = value
_ = ok
```

delete 不返回被删除的值，也不返回是否删除成功。若业务需要旧值，可以先查询，但并发场景下“查询后删除”需要整体同步，不能仅依赖两个操作分别执行。

## 2. 先查找目标键

常规路径根据键和哈希种子计算哈希，选择 table，再沿组探测序列匹配 H2 指纹，比较候选槽的完整键。查找机制参见[Map 查找](lookup/Lookup.md)。

删除路径使用相应的查找规则，不意味着一定先调用业务侧 `m[key]` 或单独调用一次 Get，再重新定位删除。实现可以在同一流程中定位并修改条目。

## 3. 清理条目与更新计数

找到键后，运行时按类型和存储规则清理键值数据，避免无意保留已删除条目关联的对象引用，并减少 table.used、Map.used 等对应计数。

删除条目不等于立即释放整个组、表或目录，也不保证底层对象当场被 GC 回收。对象是否仍可达及存储何时回收，需要结合其他引用判断。

## 4. 选择空槽或删除槽

常规表根据目标组原有的控制信息决定如何标记：

| 删除前的组状态 | 标记方式 | 原因 |
| --- | --- | --- |
| 已有空槽 | 标为空槽，并按协议恢复增长额度 | 该组原本就允许未命中查询终止 |
| 没有空槽 | 标为删除槽 | 避免为查找引入新的提前终止位置 |

第一行中，组原本就允许查询在全部候选未命中后终止，因此多增加一个空槽不会改变跨组终止规则。

空槽使用 `0x80`，可以在候选键都不匹配后用于结束查找，具体参见[Map 空槽](lookup/EmptySlot.md)。删除槽使用 `0xFE`，保留继续探测的信息，具体参见[Map 删除槽](lookup/DeletedSlot.md)。

## 5. 小 map 单组路径

`dirLen == 0` 的小 map 直接检查单个 group。它没有跨组探测路径，删除后可以将对应控制字节标为空，无需保留删除槽，同时更新有效条目计数。

不能根据删除后 `len(m) <= 8` 就断定一个常规 map 已经变回单组模式。

## 6. 不存在的键与非法键

删除不存在的键，或对 nil map 删除合法键，不产生效果。键仍需满足类型规则；例如 map[any] 中使用切片作为动态键，删除操作可能 panic。

浮点 NaN 不等于自身，不能期待用同一个 NaN 表达式查找并删除此前保存的 NaN 键。需要移除全部条目时，可以按需求使用 clear。

## 7. 并发与遍历

delete 是写操作，不能与其他 G 的无同步读写同时进行。普通 map 内部的并发检测不是互斥保护，也不保证发现全部数据竞争。

同一 G 在 range 中删除尚未访问的条目时，该条目不会再被遍历到。这个语言规则不授予其他 G 并发删除的权限。

## 8. 源码入口

- `src/internal/runtime/maps/map.go`：删除入口与小 map 路径。
- `src/internal/runtime/maps/table.go`：常规表中的键匹配、删除及计数更新。
- `src/internal/runtime/maps/group.go`：空槽、删除槽控制信息及键值访问。
