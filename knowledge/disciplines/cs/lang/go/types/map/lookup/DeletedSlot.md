# Map 删除槽

Go 1.27.2 的 Swiss Table 实现使用控制字节 `0xFE`，即二进制 `11111110`，表示删除槽，也称墓碑（tombstone）。它不保存有效条目，但保留了查找必须继续探测的信息。

## 1. 为什么需要删除标记

某个键可能因初始组没有空间而被放到后续探测组。如果直接将它之前探测路径上的删除位置标为空，就可能让查找提前终止，遗漏仍存在的键。

```text
目标键的探测路径：组 A → 组 B
                             └─ 目标键在这里

组 A 删除一个条目
    → 需要时保留删除标记
    → 查询仍继续探测组 B
```

只有确认不会破坏探测不变量时，删除位置才可以直接变为空槽。

## 2. 查找时的处理

删除槽不参与占用槽的 H2 指纹匹配，也不能单独用于判定不存在。当前组候选都不命中时，还需要检查是否有真正空槽；没有空槽就继续探测。

删除标记保存的是探测路径信息，不需要保留已删除条目的原始键值来参与比较。

## 3. 为什么是 0xFE

0xFE 是该实现选定的特殊编码，其最高位为 1，与最高位为 0 的占用指纹区分。低 7 位此时不再表示普通 H2。

删除并不天然要求使用 0xFE；采用其他编码需要同步调整状态识别和批量匹配逻辑，不能只修改常量。也不能直接假定 Go 与其他 Swiss Table 实现都采用相同的 0xFF 哨兵机制。

## 4. 插入与清理

插入可以按规则复用删除槽，但需要确认探测序列中没有已有的同一个键，避免产生重复条目。

删除标记会影响增长预算和探测成本。标记积累后，实现可以通过清理、重建或增长等路径重新组织数据。有效条目数量较少，并不保证查找一定只检查很少的槽或组。

## 5. 小 map 的区别

小 map 单组模式没有跨组探测路径，因此不需要通过删除槽维持该路径。删除可按其专用规则清空对应控制信息，不能将常规表的墓碑处理机械套用到小 map。

## 6. 源码入口

- `src/internal/runtime/maps/group.go`：ctrlDeleted 和控制信息匹配。
- `src/internal/runtime/maps/table.go`：删除标记维护、复用与清理。
- `src/internal/runtime/maps/map.go`：小 map 的单组删除路径。
