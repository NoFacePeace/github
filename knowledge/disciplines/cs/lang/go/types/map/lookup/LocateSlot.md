# Map 定位槽位

定位 group 后，运行时通过 H2 指纹筛选组内候选槽位，再比较完整键确认命中。不是继续从哈希中取几位，直接把结果当作最终槽下标。本文按 Go 1.27.2 的常规表查找路径说明。

## 1. 提取 H2 指纹

```go
h2Hash := hash & 0x7f
```

H2 是哈希最低 7 位，取值为 0～127。每个占用槽的控制字节保存对应键的 H2，空槽和删除槽则使用特殊标记。

两种特殊控制状态分别参见[Map 空槽](EmptySlot.md)和[Map 删除槽](DeletedSlot.md)。

## 2. 批量筛选候选槽

假设目标 H2 为 45，当前组的控制信息为：

```text
槽下标：   0    1    2     3     4    5    6    7
控制信息：[空] [12] [45] [删除] [67] [45] [空] [空]
                    ↑               ↑
                  候选 2          候选 5
```

运行时调用 `g.ctrls().matchH2(h2Hash)`，得到表示候选位置的位集合，再从中取出槽下标。

匹配实现可能产生额外候选，最终必须以完整键比较为准。指纹不是键的唯一标识，多个不同键可以拥有相同 H2。

## 3. 访问候选键并比较

核心流程可概括为：

```go
match := g.ctrls().matchH2(h2Hash)
for match != 0 {
    i := match.first()
    // 根据 i 读取槽内键，必要时解引用间接存储。
    // 完整键相等时，取得该槽的值并返回。
    match = match.removeFirst()
}
```

示例先检查候选槽 2，再检查候选槽 5。比较规则由键类型决定，例如字符串按内容比较，指针按指针相等规则比较。

槽下标范围为 0～7。运行时根据 map 类型元数据中的键值偏移和步长，计算该槽的键和值地址，因此可以统一访问交错布局与分离布局。

## 4. 命中后取得值

完整键相等时，运行时读取同一槽位对应的值；若键或值使用间接存储，则按类型元数据处理相应指针。

语言层面 `value := m[key]` 取得值的副本，而不是给业务代码返回可直接取地址的 map 元素。值中包含指针、切片或 map 时，副本仍可能关联共享数据。

## 5. 没有候选命中

| 当前组状态 | 后续动作 |
| --- | --- |
| 找到完整键相等的候选 | 返回对应值，查找成功 |
| 所有候选都不等，且存在空槽 | 返回未找到 |
| 所有候选都不等，且不存在空槽 | 按探测序列检查下一组 |

删除标记不能直接作为查找终点。示例中槽 0、6、7 为空，所以候选 2 和 5 都不命中后即可判定不存在。

这里说明的是查询已有键的过程，不是为新键选择插入位置。插入还需要遵守重复键检查、删除槽复用和增长等规则。

## 6. 源码入口

- `src/internal/runtime/maps/group.go`：matchH2、候选位集合及槽位访问。
- `src/internal/runtime/maps/table.go`：候选遍历、完整键比较及查找终止条件。
- `src/internal/abi`：键值偏移、步长和间接存储标记。
