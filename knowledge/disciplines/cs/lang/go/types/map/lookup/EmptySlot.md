# Map 空槽

Go 1.27.2 的 Swiss Table 实现使用控制字节 `0x80`，即二进制 `10000000`，表示空槽。它不保存有效键值，也不保存 H2 指纹。

## 1. 与占用槽区分

占用槽的控制字节最高位为 0，低 7 位保存 H2，取值范围为 0x00～0x7F。空槽最高位为 1，因此不会被当作普通占用槽的指纹。

控制字节为零表示占用槽的指纹为零，不表示空槽。组初始化需要按内部规则设置控制信息，不能仅把全部字节清零就认为创建好了空组。

## 2. 为什么可以终止查找

常规表查找先比较当前组内所有候选键。候选都不匹配且该组存在空槽时，按照插入和探测维护的不变量，可以判定目标键不存在。

```text
匹配组内指纹，比较候选完整键
    ├─ 命中 → 返回对应值
    └─ 未命中 → 检查空槽
                    ├─ 有空槽 → 返回不存在
                    └─ 没空槽 → 继续探测下一组
```

不能一看到组中某个空槽，就跳过其他候选键比较。组内可能同时存在空槽和目标键。

## 3. 空槽不一定从未使用

空槽表示当前可按探测规则作为空位置处理，不一定从未存放过条目。删除时，如果运行时确认不会截断查找路径，也可以将相应槽标记为空。

因此，终止条件依赖实现维护的探测规则，而不是简单追溯这个槽位是否曾被写入。

### 3.1 删除时组内已有空槽

Go 1.27.2 的常规表找到待删除键后，检查当前组是否已经有空槽。如果有，可以把目标槽直接标为空，并按协议恢复相应增长额度。

```text
删除前：[键 A][空][键 B]……
删除 A：[空]  [空][键 B]……
```

因为该组原本已经允许查找在候选都不命中时终止，多增加一个空槽不会引入新的跨组终止位置。查找始终先检查当前组全部候选，不会遇到第一个空槽就跳过同组的其他键。

### 3.2 删除时组内没有空槽

如果当前组没有空槽，直接制造空槽可能使查询提前结束，遗漏沿同一探测路径放到后续组中的键。因此，常规表会把该位置标为删除槽，保留继续探测的信息。

```text
删除前：组 A 无空槽 → 目标键可能曾被放到后续组
删除后：组 A 保留删除标记 → 后续查询仍可继续探测
```

这是根据当前组控制信息维护查找不变量，不需要每次删除都扫描后续组，验证是否确实存在依赖这条路径的键。

### 3.3 小 map 单组模式

小 map 只检查一个组，不存在跨组查找路径，因此删除可以直接标为空，不需要为后续组保留删除标记。有效条目计数也会同步更新；删除不存在的键不会改变条目数。

## 4. 对插入的意义

插入可以按协议使用空槽，但仍需先处理已有键匹配和表的增长预算。找到空槽不表示可以绕过重复键检查、增长或目录更新。

## 5. 源码入口

- `src/internal/runtime/maps/group.go`：ctrlEmpty 和空槽匹配。
- `src/internal/runtime/maps/table.go`：查找终止、插入和删除时的控制信息维护。
