# Map 清理

Go 1.27.2 的 pruneTombstones 尝试把不再需要的删除标记改为空槽，恢复表的增长预算。它在原存储中处理控制信息，不移动有效元素，不扩大容量，也不是重新分配同容量表的重建。

## 1. 何时尝试清理

常规表插入新键时，如果不能直接复用删除槽，且 growthLeft 为零，就尝试清理。清理恢复预算后继续插入，否则进入表扩容或拆分。

清理不是后台定时任务，也不是每次 delete 后立即执行。更新已有键通常不因新增条目触发这条路径。预算的含义参见[table growthLeft](../structs/growthLeft.md)。

## 2. 两个数量门槛

| 检查 | 条件不满足时 |
| --- | --- |
| 删除槽数量至少达到 table.capacity 的 10% | 直接返回，不扫描探测依赖 |
| 扫描后，可安全清除的删除槽至少达到容量的 10% | 不实际清理，由调用方继续扩容或拆分 |

源码通过整数比较 `数量 × 10 < capacity` 判断不足 10%，不是按整个 map 的条目数量计算。

清理要扫描表并检查探测路径，因此只在能恢复足够预算时才执行，避免付出较大扫描成本却只清掉极少标记，随下一次插入又重复扫描。

## 3. 现有键从哪里来

运行时遍历该 table 的所有 group，从控制信息标记为占用的槽位中取得现有键。若键间接存储，则先取得实际键地址，再结合当前 map 的 seed 重新计算哈希。

这些键是仍然存在的有效条目，不是从删除槽里取回已删除的键，也不需要业务传入全部键的列表。

## 4. 判断哪些组仍需要删除标记

对每个现有键，运行时从其哈希对应的起始组重走探测路径，直到到达键当前所在的组。在此之前经过的组，如果包含删除标记，就记录为仍需保留。

```text
某现有 key 的探测路径：
组 A → 组 B → 组 C（key 当前所在组）
  ↓      ↓
若包含删除标记，保留相关组的标记
```

若贸然把 A 或 B 的标记改为空槽，之后查询可能提前停止，找不到 C 中的键。这里判断的是现有键对探测路径的依赖，不是只看物理上相邻的下一组有没有空槽。

实现通过 needed 位集合按组记录保留要求，并跳过已有空槽的组，避免将这些组误当作待清理候选。对于 NaN 等不等于自身的键，源码有专门处理，不要求保留按相等查找无法命中的路径。

## 5. 统计并清除

扫描后，运行时统计未被排除的候选组中的删除槽。数量达到第二个门槛后，把这些标记逐个从删除改为空：

```text
ctrlDeleted（0xFE） → ctrlEmpty（0x80）
每清除一个标记：growthLeft 加 1
```

有效键值不移动，table.used 和 Map.used 不因清理删除标记而改变。两种槽状态分别参见[Map 空槽](../lookup/EmptySlot.md)和[Map 删除槽](../lookup/DeletedSlot.md)。

## 6. 清理不等于缩容或清空

| 操作 | 有效条目 | 存储容量 |
| --- | --- | --- |
| pruneTombstones 清理 | 保留，不移动 | 不变 |
| clear 清空 | 删除全部条目 | 通常保留 |
| 扩容或拆分 | 迁入新的表布局 | 增加相应容量 |

清理不会直接归还组数组内存，也不会把 map 自动退回小 map 模式。清理与扩容发生在写入路径，仍需要遵守普通 map 的并发同步要求。

## 7. 源码入口

- `src/internal/runtime/maps/table.go`：插入时的清理调用、pruneTombstones、tombstones 与增长预算。
- `src/internal/runtime/maps/group.go`：占用、空槽、删除槽的控制信息匹配。
