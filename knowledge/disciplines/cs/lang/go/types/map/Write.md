# Map 写入

`m[key] = value` 共用一个写入流程：键已存在时更新对应值，不存在时插入新条目。本文按 Go 1.27.2 的 Swiss Table 实现说明一般过程，具体键类型可能有专用快速路径。

## 1. 插入与更新

```go
m := make(map[string]int)
m["go"] = 1 // 插入，len(m) 为 1。
m["go"] = 2 // 更新，len(m) 仍为 1。
```

调用方不需要先决定执行插入还是更新。运行时根据键是否已经存在选择相应分支；对 nil map 赋值会 panic，需要先初始化映射。

## 2. 共同的定位与匹配过程

常规表中，写入根据键与 map 的种子计算哈希，定位 table 和起始 group，再匹配 H2 指纹并比较完整键。定位、探测和键比较的原理参见[Map 查找](lookup/Lookup.md)。

这是写入内部执行的搜索，不表示一定先独立调用一次 Get，或要求业务先执行 `m[key]` 再写入。

```text
计算哈希，定位目标表与组
    ↓
检查候选槽的完整键
    ├─ 已存在 → 返回相应值槽供赋值
    └─ 尚未找到 → 继续探测，或确认不存在
                         ↓
                    安排新槽，必要时清理或增长
```

## 3. 已存在时更新

找到相等键后，使用对应的值存储位置完成赋值，不新增逻辑条目，因此有效元素计数不变。实现也可能根据键类型要求更新保存的键表示，不能将其概括为任何情况下都只改值的字节。

值的赋值遵守 Go 的复制规则：结构体、数组复制其内容，指针、切片、map 等值仍可能关联共享数据。覆盖旧值后，旧值引用的对象是否回收还取决于其他引用。

## 4. 不存在时选择槽位

两种槽位状态及其探测含义参见[Map 空槽](lookup/EmptySlot.md)和[Map 删除槽](lookup/DeletedSlot.md)。

写入必须先按探测规则确认没有相同键，才能安排新条目。它可以记录可复用的删除槽，但不能一遇到删除槽就停止检查后续位置是否存在同一个键。

满足条件时，在空槽或可复用删除槽中准备键值数据，写入 H2 控制信息，并更新 table.used、Map.used 和相关增长预算。复用删除槽与使用新空槽对预算的影响可能不同。

槽位存储、间接分配及赋值的具体顺序由编译器与运行时协作处理。业务层面应理解为一次 map 赋值操作，而不是自行修改内部控制字节。

## 5. 清理、增长与拆分

触发背景及各类结构调整参见[Map 扩容](growth/Growth.md)。

即使发现空槽，也可能因为负载预算等条件需要先处理表结构。删除标记积累后可能清理或重建；需要更多容量时，表可以增长，达到单表上限后则可能拆分并更新目录。

结构调整后，写入路径按新的表和组布局继续处理，不能继续使用失效的旧槽位地址。并非每次插入都会分配内存，也不保证每次增长都只改一个整数容量字段。

## 6. 小 map 路径

小 map 单组模式直接检查一个 group：已有键就更新，有空位就插入；需要容纳更多条目时，转入常规表与目录组织。

小 map 没有跨组探测和删除槽维护，但仍需要完整键比较。键类型专用路径还可能采用不同的候选筛选优化。

## 7. 复合更新与并发

```go
m["count"]++
```

这表示读取、计算并写回，不是保证并发原子的计数操作。普通 map 的赋值、删除与相关读取必须遵守同步协议，内部 writing 检测标记不是互斥锁。

需要“仅当不存在时插入”或“检查旧值后更新”等整体语义时，通常需要覆盖整个操作的锁或其他合适协议，不能只把查询与赋值分别视为安全步骤。

## 8. 源码入口

- `src/internal/runtime/maps/map.go`：写入入口、小 map 与目录处理。
- `src/internal/runtime/maps/table.go`：已有键匹配、槽位选择、增长预算和表结构调整。
- `src/internal/runtime/maps/group.go`：控制信息和组内键值访问。
- `src/cmd/compile/internal`：map 赋值的检查、转换与代码生成。
