# kill

`kill` 用于向进程发送信号，默认发送 `SIGTERM`，请求进程终止。它既可能是 Shell 内置命令，也可能是独立程序；具体选项可以通过 `help kill`（Bash 内置命令）或 `man kill` 查看。

## 1. 基本用法

```sh
# 向指定进程发送 SIGTERM
kill <PID>

# 显式指定信号
kill -s TERM <PID>

# 列出信号
kill -l
```

`<PID>` 是占位符，执行前替换为实际进程 ID。可以通过 `ps -p <PID> -o pid,ppid,comm` 核对进程。

## 2. 常见信号

| 信号 | Linux 编号（x86/ARM） | macOS 编号 | 常见用途 | 说明 |
| --- | --- | --- | --- | --- |
| `SIGTERM` | 15 | 15 | 请求终止 | 进程可以捕获并执行清理，也可以忽略 |
| `SIGKILL` | 9 | 9 | 强制终止 | 无法捕获、阻塞或忽略，进程没有机会执行清理 |
| `SIGINT` | 2 | 2 | 请求中断 | 通常由终端中的 Ctrl+C 触发 |
| `SIGHUP` | 1 | 1 | 通知终端挂断 | 部分服务约定用它重新加载配置，需查服务文档 |
| `SIGSTOP` | 19 | 17 | 暂停进程 | 无法捕获、阻塞或忽略 |
| `SIGCONT` | 18 | 19 | 恢复进程 | 让已停止的进程继续运行 |

信号编号可能因操作系统和处理器架构而异，可通过 `kill -l` 查看当前环境的编号。优先使用信号名称，避免编号差异。

编号写法为 `kill -<信号编号> <PID>`。

## 3. 常用操作

```sh
# 请求正常退出，给进程清理资源的机会
kill -s TERM <PID>

# 正常退出无效时，强制终止
kill -s KILL <PID>

# 暂停与恢复
kill -s STOP <PID>
kill -s CONT <PID>

# 检查目标是否存在且当前用户有权发送信号，不实际发送信号
kill -0 <PID>
```

`kill -0` 成功不代表进程运行健康；失败可能是进程不存在，也可能是权限不足。发送终止信号成功也不代表进程已经退出，需要再次检查进程状态。

## 4. 示例

以下以进程 ID `1234` 为例，执行前应替换为实际目标进程的 ID。

### 4.1 请求正常退出

```sh
kill -15 1234
```

发送编号为 15 的 `SIGTERM`，请求进程正常退出。等价写法为 `kill -s TERM 1234` 或 `kill 1234`，进程可以捕获信号并执行清理。

### 4.2 强制终止

```sh
kill -9 1234
```

发送编号为 9 的 `SIGKILL`，强制终止进程。等价写法为 `kill -s KILL 1234`。进程无法捕获或忽略该信号，也没有机会执行退出清理，可能丢失尚未保存的数据。通常先请求正常退出，无响应时再考虑强制终止。
