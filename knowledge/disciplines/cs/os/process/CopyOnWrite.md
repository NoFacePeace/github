# Copy-on-Write

写时复制（Copy-on-Write，COW）是一种延迟复制机制：先共享数据，等需要修改时，再复制相关部分。它常用于 Linux 的 `fork`，也用于其他需要共享数据并隔离修改的场景。

## 1. 内存页如何复制

以 `fork` 后的普通私有内存为例：

1. 父子进程拥有各自的虚拟地址空间，相关虚拟页最初映射到相同的物理内存页。
2. 操作系统将需要写时复制的映射设为只读；读操作可以继续共享物理页。
3. 一方尝试写入时触发写保护缺页异常，内核在仍需共享时分配新页、复制旧内容，并调整写入方的映射。
4. 写入方修改自己的页，另一方继续读取原来的内容。

如果原页已不需要与其他进程共享，内核可能直接恢复写权限，无需再次复制。显式共享内存的写入语义不同，不适用上述私有内存隔离方式。

## 2. 计数器示例

假设 `fork` 时，某个私有内存页中的 `count = 10`：

| 时刻 | 父进程看到的值 | 子进程看到的值 |
| --- | --- | --- |
| 刚创建子进程 | `10` | `10` |
| 父进程将计数器改为 `11` 后 | `11` | `10` |

子进程不需要判断数据是旧值还是新增值，内存映射和写时复制保证它仍能读取自己的数据视图。

## 3. Redis 后台持久化中的用途

Redis 后台生成 RDB 快照或重写 AOF 时，子进程读取创建时的数据视图，主进程继续接受写入。写时复制让主进程的修改不影响子进程读取的旧内容。

AOF 重写期间的新写操作由主进程记录到增量日志，写时复制本身不负责记录或持久化这些操作。

## 4. 内存开销

复制通常以内存页为单位，并非只复制被修改的一个键。只修改页中的少量数据，也可能导致整个页被复制。

子进程存活期间，被修改的共享页越多，额外内存占用通常越大；反复修改已经私有化的同一页，不会仅因每次写入就持续产生新的副本。评估 Redis 后台持久化内存时，需要预留这部分开销。
