# 三色标记

三色标记（Tri-color Marking）是描述追踪式垃圾回收标记过程的通用模型，不是 Go 特有的算法。它将对象划分为未发现、待扫描和已扫描三种状态，用于解释如何遍历对象引用图，以及并发修改引用时如何避免漏标。

## 1. 可达性与根

垃圾回收器从根（GC Roots）出发，沿指针引用查找可达对象。根通常包括全局变量中的引用、线程或 goroutine 栈上的活跃引用，以及运行时需要扫描的引用位置；具体范围由语言运行时决定。

```text
根 → A → B     A、B 可达，需要保留
     C ↔ D     若没有从根到达它们的路径，C、D 可以回收
```

可达性与引用次数不同。两个对象即使相互引用，只要没有从根到达它们的路径，追踪式 GC 仍能回收它们。

## 2. 三种颜色

| 颜色 | 含义 |
| --- | --- |
| 白色 | 尚未被发现为可达的对象 |
| 灰色 | 已发现可达，但它引用的对象尚未全部扫描 |
| 黑色 | 已发现可达，且它的引用已扫描完成 |

颜色是抽象状态，不要求对象实际保存三种颜色字段。实现可以使用标记位和待扫描工作队列：已标记且等待扫描的对象对应灰色，扫描完成的对象对应黑色。

## 3. 标记过程

先考虑标记期间对象引用关系不变的情况：

1. 初始时将堆对象视为白色。
2. 扫描根引用，将发现的白色对象标记为灰色，加入待扫描集合。
3. 取出一个灰色对象，扫描它的指针，将发现的白色对象标记为灰色。
4. 扫描完成后，将该对象视为黑色。
5. 重复扫描，直到没有灰色对象。

例如 `根 → A → B`：

| 阶段 | A | B |
| --- | --- | --- |
| 初始 | 白色 | 白色 |
| 扫描根 | 灰色 | 白色 |
| 扫描 A | 黑色 | 灰色 |
| 扫描 B | 黑色 | 黑色 |

在正确完成标记后，仍为白色的对象可以被回收。标记只负责识别存活对象；后续可以采用清扫或复制等方式回收空间，三色模型本身不决定回收策略。

## 4. 并发标记与漏标

### 4.1 引用变化带来的问题

并发标记期间，业务代码与 GC 同时执行，对象引用图可能发生变化。考虑以下初始状态：

```text
根 → A（黑色）
根 → B（灰色）→ C（白色）
```

如果业务代码先将 `C` 的引用写入已扫描的 `A`，再删除 `B` 对 `C` 的引用：

```text
根 → A（黑色）→ C（白色）
根 → B（灰色）
```

GC 随后扫描 `B` 时看不到 `C`，而 `A` 已经扫描过。如果没有额外保护，`C` 就可能保持白色而被误回收，尽管它仍然可达。

### 4.2 三色不变式

维护并发标记正确性时，常见的理论约束包括：

- **强三色不变式**：黑色对象不直接引用白色对象。
- **弱三色不变式**：黑色对象引用的白色对象仍受到灰色对象的保护，即存在从某个灰色对象经过白色对象到达它的路径。

这些约束用于保证仍可达的白色对象有机会被扫描。不同收集器使用不同机制维护相应约束，并结合根扫描、对象分配和标记终止规则保证正确性。

### 4.3 写屏障

写屏障是在修改指针时执行的额外操作，可以记录引用变化或触发必要的标记。例如：

- 插入写屏障可以在建立新引用时，将新引用指向的对象标记为待扫描。
- 删除写屏障可以在移除旧引用时，将旧引用指向的对象标记为待扫描。

实际屏障可能带有条件，或采用批量记录再处理的方式；这里描述的是基本思路。写屏障不意味着每次指针修改都暂停整个程序。
