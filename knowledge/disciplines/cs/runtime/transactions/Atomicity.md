# 原子性

## 1. 定义

原子性（Atomicity）要求事务内受保护的修改作为一个整体生效，或在中止时撤销其效果，不留下只完成部分操作的结果。

它描述的是结果保证，不代表整个事务必须由一条 CPU 指令执行，也不表示执行中不存在中间状态。其他事务能否观察到中间状态属于隔离性的问题。

## 2. 示例

转账包括从账户 A 扣款和向账户 B 入账。若入账失败，事务应撤销已完成的扣款，而不是只留下扣款结果。

但错误处理需要遵守系统规则：一条语句失败不一定自动中止整个事务，应用必须根据错误类型和事务状态决定回滚或继续。

## 3. 实现方式

系统可以通过撤销日志回滚已做修改，也可以先将修改保存在私有写集中，验证成功后再发布。具体机制取决于事务系统，不必都采用数据库 undo。

## 4. 保护范围

原子性只覆盖协议支持的资源。数据库回滚通常不能撤回已经发送的邮件或已完成的外部 HTTP 操作，内存事务也不会自动撤销任意 I/O。

补偿可以在业务上修正结果，但不等于从未发生过原操作。
