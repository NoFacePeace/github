# 事务

事务（Transaction）将一组操作组织为一个逻辑单元，并按照系统提供的规则提交或中止。它不只用于数据库，也用于事务内存、消息系统及跨资源协调等场景。

## 1. 边界与生命周期

```text
开始事务
    ↓
读取状态、执行操作
    ↓
检查约束与冲突
    ↓
提交，或中止并执行相应恢复
```

事务边界决定哪些操作受同一套保证保护。恢复可以采用撤销、丢弃未提交写集等方式；并非所有系统都支持任意时刻回滚已经发布的结果。

## 2. 常见性质

- [ACID](ACID.md)：原子性、一致性、隔离性和持久性的定义及保证边界。

| 性质 | 含义与边界 |
| --- | --- |
| 原子性 | 受事务机制保护的操作作为整体生效或中止，具体范围由资源和协议决定。 |
| 一致性 | 正确操作与约束共同维护数据规则，事务机制不能自动修正错误的业务逻辑。 |
| 隔离性 | 规定并发操作的可见性与允许的交错行为，不同系统提供不同程度的隔离。 |
| 持久性 | 提交结果在约定故障模型下保留；内存事务不必承诺断电后保留。 |

ACID 是数据库事务的常用描述框架，不能仅因某个功能称为“事务”，就认定它承诺相同的全部性质。

## 3. 并发

并发事务可能读取或修改相同资源，需要协调冲突及可见性。常见机制包括悲观加锁、乐观验证，以及通过多版本并发控制（MVCC）为读取选择合适版本。

MVCC 属于并发控制机制，可以与锁和验证配合，不是事务的必备组成。具体隔离级别、快照建立时机及冲突处理应由实现文档说明。

事务与锁也不是同义词：锁协调访问，事务还涉及操作边界、提交、中止及恢复；单纯释放锁并不会自动撤销已经完成的修改。

## 4. 不同使用场景

| 场景 | 典型保护范围 |
| --- | --- |
| 数据库事务 | 支持事务的存储资源中的查询与修改。 |
| 事务内存 | 一组内存读写，冲突时可能中止并重试。 |
| 消息事务 | 系统明确支持的消息发布、确认或状态变更。 |
| 分布式事务 | 多个参与资源之间的提交与恢复协调。 |

某个系统的本地事务不会自动覆盖外部 HTTP 请求、邮件或其他资源。跨资源原子性需要参与者与协议支持，补偿操作也不等同于把所有外部影响彻底回滚。

## 5. 错误与重试

语句或操作失败不一定使整个事务自动中止，需要根据接口契约确认当前状态。提交时连接中断，也可能出现“客户端不知道是否提交成功”的不确定结果。

重试前应明确恢复边界，并通过幂等设计、唯一业务标识或结果查询避免重复执行。可重试事务体中若包含不可撤销外部副作用，还需单独协调。

## 6. 范围与成本

事务应覆盖需要共同保护的业务操作，同时避免不必要的长时间等待。长事务可能延长持锁时间、保留历史版本或增加重试成本，具体影响取决于实现。

通用知识描述概念与保证边界，具体产品的语法、隔离规则和恢复实现应保留在相应产品目录中。
