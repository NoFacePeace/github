# 并发

事务并发是指多个事务的执行在时间上重叠，其读取、计算和写入可能交错发生。并发不要求多个操作在不同 CPU 核上同时执行，也可以通过调度交替推进。

## 1. 收益与挑战

并发可以利用等待时间并提高资源利用率，但事务可能访问相同资源或相关状态，需要明确哪些交错结果可以接受。

单次操作原子不等于整个事务没有竞争，修改不同记录也可能共同破坏跨记录业务规则。

## 2. 并发控制

- [并发控制](ConcurrencyControl.md)：悲观控制、乐观并发控制、MVCC 及冲突处理的关系。

并发控制协调访问和提交，隔离性描述对外承诺的可见性与执行结果。具体机制和保证不能简单一一对应。

## 3. 并发问题

- [并发问题](ConcurrencyAnomalies.md)：脏读、不可重复读、幻读、丢失更新和写偏斜等现象。

## 4. 执行成本

并发可能带来锁等待、冲突重试和热点竞争。应结合事务长度、资源访问顺序和业务不变量设计执行过程，而不是单纯增加同时运行的事务数量。
