# 脏读

## 1. 定义

脏读（Dirty Read）是指一个事务读取了另一个事务尚未提交的修改。如果写入事务随后回滚，读取者此前依据的状态可能从未正式生效。

## 2. 示例

| 顺序 | 事务 A | 事务 B |
| --- | --- | --- |
| 1 | 将余额从 100 改为 0，尚未提交。 | |
| 2 | | 读取余额，得到 0。 |
| 3 | 回滚，余额恢复为 100。 | |

即使 A 最终提交，B 在提交之前读取其修改仍属于脏读。是否回滚影响后果，不改变当时读取未提交数据的性质。

## 3. 与其他现象的区别

不可重复读涉及多次读取之间观察到其他事务已经提交的变化；脏读的关键是读取时对方尚未提交，不要求重复读取。

读取事务自己的未提交修改通常属于读己之写，不是这里讨论的跨事务脏读。

## 4. 防范与边界

经典 READ COMMITTED 及更强级别禁止脏读，实现可以通过锁或版本可见性规则完成。禁止脏读不代表也禁止不可重复读、幻读和写偏斜。

若已经根据脏值产生外部副作用，写入事务的回滚不会自动撤销这些副作用。
