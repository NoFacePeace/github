# 丢失更新

## 1. 定义

丢失更新（Lost Update）是指多个事务基于先前读取结果计算并写回同一数据，后续写入覆盖了另一事务已经完成的修改，使其效果丢失。

## 2. 示例

| 顺序 | 事务 A | 事务 B |
| --- | --- | --- |
| 1 | 读取余额 100，准备增加 10。 | |
| 2 | | 读取余额 100，准备增加 20。 |
| 3 | 写入 110 并提交。 | |
| 4 | | 根据旧读取结果写入 120 并提交。 |

最终结果为 120，而业务希望两个增量都生效后得到 130。B 写入时即使等待过 A 的锁，也不一定能纠正其事先计算的陈旧结果。

## 3. 防范方式

- **原子更新**：让系统执行 `balance = balance + delta`，避免应用先读后写绝对值；实际并发语义需结合系统确认。
- **锁定读取**：在读取与后续修改期间持有适当的排他保护。
- **乐观验证**：更新时检查版本号或原值，冲突时不覆盖，并由应用处理失败和重试。
- **更强隔离**：利用具体系统提供的冲突检测或可串行化保证。

## 4. 使用边界

有意采用后写覆盖的业务不一定将其视为错误，但必须明确语义。是否自动检测丢失更新不能仅根据某个隔离级别名称推断。

重试应重新读取并计算，不应无条件重放旧的绝对值写入；还需避免重复执行外部副作用。
