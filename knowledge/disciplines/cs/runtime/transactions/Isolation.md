# 隔离性

## 1. 定义

隔离性（Isolation）规定并发事务可以看到哪些状态，以及允许怎样的操作交错。不同隔离保证在正确性、并发度和实现成本之间有不同取舍。

它不等于所有事务都必须物理串行执行；系统可以并发运行事务，同时限制其可观察结果。

## 2. 常见并发现象

- [并发](Concurrency.md)：事务交错执行、并发控制及并发问题。

- **脏读**：读取到其他事务尚未提交的修改。
- **不可重复读**：同一事务重复读取某条记录，观察到其他事务提交的修改。
- **幻读**：重复执行相同范围查询时，匹配记录集合因其他事务的修改而变化。
- **写偏斜等异常**：事务基于各自读取结果修改不同记录，共同破坏跨记录规则。

是否允许这些现象，需要结合具体隔离模型判断，不能只看是否对同一行写入。

## 3. 隔离级别与机制

- [隔离级别](IsolationLevels.md)：四个常见级别、经典读取现象及快照隔离与可串行化的区别。

数据库常见 READ UNCOMMITTED、READ COMMITTED、REPEATABLE READ、SERIALIZABLE 等级别，但不同产品的实现和保证不一定完全相同。

系统可以通过[锁](../locks/Locks.md)、MVCC、乐观验证或组合机制提供隔离。MVCC 不自动等于可串行化，使用锁也不代表所有事务都串行运行。

## 4. 选择依据

应从业务不变量出发，判断哪些并发结果可以接受，再选择隔离级别、锁定读取、原子更新或重试等策略。

可串行化要求结果等价于某种串行顺序，但不自动要求该顺序符合现实时间先后；更强的实时顺序保证还需要其他条件。
