# 写偏斜

## 1. 定义

写偏斜（Write Skew）是指并发事务基于相关数据作判断，分别修改不同记录，共同破坏跨记录约束。它不要求发生同一行写入覆盖。

## 2. 示例

业务规则要求至少一名医生值班，初始 A、B 都在值班：

| 顺序 | 事务 A | 事务 B |
| --- | --- | --- |
| 1 | 看到 B 在值班，判断自己可以离岗。 | |
| 2 | | 看到 A 在值班，判断自己可以离岗。 |
| 3 | 将 A 设为离岗并提交。 | |
| 4 | | 将 B 设为离岗并提交。 |

在允许这种交错的并发控制下，两个事务分别修改不同记录，都可能成功，最终无人值班。即使读取都来自一致快照，也不能单凭这一点防止问题。

## 3. 与丢失更新的区别

丢失更新通常涉及对同一数据的后写覆盖；写偏斜中，两次修改本身都可以保留，但组合结果违反业务规则。

因此，只检测同一行的写写冲突可能不够，还需要保护读取依赖或跨记录不变量。

## 4. 防范方式

可以评估可串行化、锁定共同依赖的记录或资源，或者将业务规则重构为系统能够可靠执行的约束。

锁定方案需要覆盖相关依赖，包括必要的范围，且遵循一致顺序；仅锁定各自准备修改的一行通常不足以解决示例中的问题。

## 5. 边界

并非所有可重复读实现都具有完全相同的写偏斜行为，是否允许还取决于访问方式和冲突检测。即使采用可串行化，业务仍需正确表达检查逻辑，并处理可能的事务中止与重试。
