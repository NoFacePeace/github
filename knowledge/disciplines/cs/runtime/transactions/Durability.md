# 持久性

## 1. 定义

持久性（Durability）要求系统确认事务提交成功后，其结果在承诺覆盖的故障发生后仍能保留或恢复。

保证必须结合故障模型理解：进程崩溃、操作系统崩溃、断电、磁盘损坏和整机房故障需要不同级别的保护。

## 2. 常见实现方式

系统可以先持久化恢复日志，再逐步写回数据页；也可以结合其他持久化组织方式、冗余存储或复制机制提供保证。

提交成功不一定代表所有数据页已写回最终位置，只要承诺的恢复机制能够恢复结果即可。写入进程缓冲区或操作系统缓存，也不能直接等同于抗断电的持久化。

## 3. 配置与确认时机

同步刷盘、批量提交、异步复制等策略会改变延迟和故障后的丢失风险。是否等待持久化、是否等待副本以及等待哪些副本，都属于提交确认契约的一部分。

设备和操作系统还需要正确执行持久化请求，不能只根据应用调用过写入接口就认定结果已经稳定保存。

## 4. 边界

持久性不等于永久不会丢失数据，也不能替代备份。误操作、软件错误和超出设计范围的设备故障仍可能需要独立恢复方案。

事务内存等系统可能主要承诺内存操作的原子性和隔离性，不承诺断电持久性；应以其明确提供的语义为准。
