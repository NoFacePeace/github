# CAS

CAS（Compare-And-Swap，比较并交换）原子地比较当前位置的值与预期值：相等时写入新值，否则不修改并报告失败。语言接口也常称为 compare-and-exchange，其返回值和比较规则需按具体接口理解。

## 1. 基本语义

```text
CAS(位置, 预期值, 新值)
  当前值 == 预期值 → 更新成功
  当前值 != 预期值 → 更新失败
```

比较与条件更新不可分割，避免普通“先比较，再赋值”之间被其他线程插入修改。CAS 不会自动替应用计算新值或重试。

## 2. 计数器示例

```text
初始计数为 10
A 读取 10，准备写入 11
B 读取 10，准备写入 11
A 执行 CAS(计数器, 10, 11) → 成功
B 执行 CAS(计数器, 10, 11) → 失败
B 重新读取 11，尝试 CAS(计数器, 11, 12)
```

CAS 重试循环通常包含读取、计算和条件更新。计算过程可能反复执行，不宜直接包含不可撤销的外部副作用。单纯计数也可以优先使用接口提供的原子加法。

## 3. ABA 问题

若值从 A 变为 B 又变回 A，仅比较当前值的 CAS 可能成功，但不能证明中间没有变化。

这是否构成错误取决于算法。例如并发链表中，节点被移除后复用可能使相同地址代表不同状态。版本标签可帮助检测变化，安全内存回收还可能需要 hazard pointer、epoch 等机制；版本号溢出也需考虑。

## 4. 与锁、乐观控制的关系

CAS 是原子操作，可以用来竞争锁状态，也可以实现乐观更新；它本身不是锁或完整的并发控制协议。

数据库使用版本号条件执行 UPDATE，具有类似的比较更新思想，但不等于直接执行 CPU CAS 指令，底层仍可能使用事务锁。

## 5. 接口与进展保证

部分语言接口区分强、弱 compare-and-exchange。弱形式可能出现伪失败，通常适合放在重试循环中；接口还可能在失败时更新预期值参数。

CAS 的原子性不自动解决所有内存顺序问题，应按语言接口选择适当的同步保证。高竞争下重试会消耗 CPU，某个线程还可能长期失败。

即使算法使用 CAS，也不能直接认定其无锁或无等待；原子类型本身是否由无锁机器指令实现，也取决于平台和类型支持。
