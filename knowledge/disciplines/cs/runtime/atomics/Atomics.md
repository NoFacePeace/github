# 原子操作

原子操作在其规定的作用范围内不可分割地完成：其他并发执行者不会观察到该操作的部分结果。它是实现并发算法的基础，不等于互斥锁，也不自动使一组操作成为事务。

## 1. 常见操作

| 操作 | 主要用途 |
| --- | --- |
| 原子加载与存储 | 读取或写入受支持的原子对象。 |
| 交换（Exchange） | 原子替换值，并取得旧值。 |
| 获取并加（Fetch-and-Add） | 原子增加数值，并取得操作前的值。 |
| [CAS](CAS.md) | 比较当前值与预期值，相等才执行更新。 |

普通变量的读写是否原子，取决于语言、类型、对齐和平台等条件，不能根据源代码只有一行就判断。

## 2. 原子性与内存顺序

原子性主要约束某个操作不可分割，内存顺序则约束相关读写的可见性与重排。不同语言提供的顺序模型不同，不能认为原子变量更新后，所有其他共享数据都自动安全发布。

例如某些接口提供 relaxed、acquire、release 等选项，另一些接口采用固定保证。应遵循语言内存模型，而不是直接套用某条 CPU 指令的行为。

## 3. 与锁和事务的关系

原子操作可以用于构建锁，也可以用于不持有互斥锁的并发算法。但使用原子操作不保证整个算法具有无锁或无等待进展保证。

对两个变量分别执行原子更新，也不等于二者作为一个整体原子生效。跨字段不变量通常还需要锁、事务或其他正确的协调协议。
