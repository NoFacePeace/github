# 意向锁

意向锁用于多粒度加锁：在锁定下层资源之前，先在上层资源声明加锁意图，以便不同粒度的锁高效判断冲突。它是通用并发控制概念，不属于某个数据库独有的机制。

## 1. IS 与 IX

| 模式 | 含义 |
| --- | --- |
| IS（Intention Shared，意向共享） | 声明准备在下层资源上获取[S 锁](Shared.md)。 |
| IX（Intention Exclusive，意向排他） | 声明准备在下层资源上获取[X 锁](Exclusive.md)。 |

这些模式不直接赋予对所有下层资源的共享或排他访问权。需要访问某个具体资源时，仍须按协议获取相应锁。

## 2. 解决的问题

假设资源层级为“表 → 记录”。事务 A 要修改某条记录，先在表上获取 IX，再在目标记录上获取 X。

此时事务 B 若要获取整张表的 S 锁，只需发现表上已有 IX，就能判断冲突，无需遍历表中所有记录锁。

```text
表：A 持有 IX
└─ 记录 10：A 持有 X

B 申请表级 S → 与 IX 冲突，等待或按实现规则失败
```

意向锁协调不同粒度的加锁，具体记录上的 S/X 锁继续处理同一记录的并发冲突。

## 3. 兼容关系

下表描述同一上层资源、不同持有者之间的基本兼容关系，S、X 在此表示对该上层资源整体加锁。

| 已持有／申请 | IS | IX | S | X |
| --- | --- | --- | --- | --- |
| IS | 兼容 | 兼容 | 兼容 | 冲突 |
| IX | 兼容 | 兼容 | 冲突 | 冲突 |
| S | 兼容 | 冲突 | 兼容 | 冲突 |
| X | 冲突 | 冲突 | 冲突 | 冲突 |

IS 与 IX 可以兼容，两个 IX 也可以兼容，因为相关操作可能访问不同的下层资源。例如两个事务分别修改记录 10 和 20，可以同时持有表级 IX；若修改同一记录，再由记录上的 X 锁判断冲突。

## 4. 层级协议与生命周期

在更深的资源层级中，需要沿祖先层级获取适当的意向模式；只在某个局部节点加锁而忽略层级协议，不能保证正确协调。完整的多粒度协议还可能定义 SIX 等其他模式，本文只介绍 IS、IX。

意向锁通常由支持多粒度锁的系统自动管理，业务不必为每次操作手动声明。获取、升级和释放规则取决于具体实现，不能只根据 IS 或 IX 名称推断生命周期。

## 5. 常见误解

- **IX 不等于整表 X 锁**：IX 允许其他兼容的意向锁共存，不会一律禁止其他执行单元写入不同记录。
- **“意向”不代表异步或尚未持锁**：获取成功的意向锁本身已经是持有的锁，可与下层锁同时存在。
- **意向锁不等于插入意向锁**：前者是多粒度协调模式，后者是具体系统用于插入协调的机制。
- **不是所有运行时锁都提供 IS/IX**：它们常见于数据库等具有资源层级的锁管理系统。
