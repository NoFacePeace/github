# S 锁

S 锁（Shared Lock，共享锁）是一种允许多个持有者共享访问同一资源的锁模式，通常用于保护读取期间的数据不被其他遵守同一锁协议的执行单元修改。

## 1. 兼容关系

| 其他持有者的模式 | 是否兼容 |
| --- | --- |
| S | 兼容，可以共同持有。 |
| X | 冲突，需要按实现的等待、超时或失败规则处理。 |

上述关系以同一资源、不同持有者为前提。实际系统可能提供更多模式，并定义更复杂的兼容规则。

## 2. 典型使用过程

```text
获取资源的 S 锁
      ↓
读取受保护的数据
      ↓
完成需要保持该保护的操作
      ↓
释放 S 锁
```

其他读取者可以同时持有 S 锁，需要 X 锁的修改者则等待。这里的保护依赖统一协议：不申请相应锁的访问，不一定受到阻止。

## 3. 与其他概念的区别

S 描述兼容模式，不描述资源范围；它可以用于不同粒度的对象，而不是只用于一行记录。读写锁的读模式具有类似思想，但重入、公平性和升级规则依实现而定。

读取不一定需要 S 锁，例如基于版本的快照读取可能无需获取相应共享锁。持有 S 锁也不代表一定能安全修改资源，修改前通常需要满足排他访问要求。

## 4. 生命周期与升级

锁释放时机由实现决定，可能由代码作用域、显式调用或事务结束控制，不能仅根据 S 模式判断。

两个持有者各自获得 S 锁后，同时等待升级为 X 锁，可能形成死锁。需要读后修改时，应结合实现选择提前获取 X 锁、专门的升级机制或其他并发控制方式。
