# 锁

锁用于协调并发执行单元对共享资源的访问，避免操作以不符合预期的方式交错。共享资源可以是内存对象、数据记录、文件或元数据；具体语义取决于运行时、操作系统或数据库的实现。

## 1. 基本概念

- **临界区**：需要按照约定受保护的一段操作。
- **获取与释放**：进入临界区前获取适当的锁，完成后释放；其他执行单元按兼容规则进入或等待。
- **保护对象与范围**：锁可以保护一个对象、一组记录或更大的资源范围。
- **锁模式**：描述允许哪些并发访问共存，不等同于锁定范围。

锁只有在参与者遵守一致的访问约定时才能保护资源。获得一个应用锁，并不自动阻止未遵守该约定的代码访问数据。

## 2. 常见机制

| 机制 | 核心用途 |
| --- | --- |
| 互斥锁 | 同一时刻仅允许一个持有者进入受保护的临界区。 |
| 读写锁 | 区分共享读取和排他写入，具体公平性、重入及升级规则依实现而定。 |
| 自旋锁 | 等待者循环检查锁状态，适用于特定的短临界区及调度环境。 |

这些名称不是完全互斥的分类：例如互斥语义可以通过自旋或阻塞等待实现。信号量、条件变量等也用于同步，但不应全部等同于锁。

## 3. 锁模式

- [S 锁](Shared.md)：共享模式、兼容关系、读取保护与升级风险。
- [X 锁](Exclusive.md)：排他模式、兼容关系、保护范围与使用风险。
- [意向锁](IntentionLock.md)：IS/IX 模式、资源层级及多粒度锁之间的协调。

共享（S）与排他（X）是常见的模式：多个共享持有者可以共存，排他模式与其他持有者的共享、排他模式冲突。读写锁具有类似思想，但具体 API 和语义不一定与数据库模式完全一致。

数据库多粒度锁还常使用意向共享（IS）、意向排他（IX）等模式，协调不同层级资源的加锁。它们不是所有程序运行时都提供的通用接口。

锁模式、保护范围与等待方式需要分别理解。例如“记录级”描述范围，“排他”描述模式，“自旋”描述等待方式。

## 4. 生命周期与风险

语言或运行时的锁通常由代码显式释放，或借助作用域机制自动释放；数据库事务锁则可能按语句或事务生命周期释放，不能直接套用同一规则。

常见问题包括死锁、饥饿、竞争和锁粒度不合适。应保持一致的加锁顺序、缩短持锁时间，并依据具体实现处理超时、取消及异常路径。

数据库的 MVCC 不属于锁，乐观并发控制也不一定实际获取锁。它们与悲观加锁是不同的并发协调机制。
