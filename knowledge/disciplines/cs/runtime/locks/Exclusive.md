# X 锁

X 锁（Exclusive Lock，排他锁）是一种排斥其他持有者共享或排他访问同一资源的锁模式，常用于修改共享数据，或在读取后执行依赖该数据不被并发修改的操作。

## 1. 兼容关系

| 其他持有者的模式 | 是否兼容 |
| --- | --- |
| S | 冲突。 |
| X | 冲突。 |

上述关系针对同一资源、不同持有者。持有者自身能否重入、再次获取或升级锁，取决于具体实现。

## 2. 典型使用过程

```text
获取资源的 X 锁
      ↓
读取并检查当前状态
      ↓
修改受保护的数据
      ↓
完成需要保持该保护的操作
      ↓
释放 X 锁
```

获取成功后，其他执行单元不能同时获得同一资源上冲突的 S 或 X 锁。但这不代表任何方式的读取都被禁止，例如版本化系统可能允许读取历史快照。

## 3. 模式与范围

X 描述兼容模式，而不是锁定范围。对一个对象获取 X 锁，不等于锁住所有对象；保护整组资源时需要结合粒度和层级规则理解。

互斥锁与 X 模式具有类似的排他思想，但不能据此认定所有 API 都具有相同的所有权、内存可见性、重入或释放语义。

## 4. 使用与风险

排他访问可能增加等待，应减少不必要的持锁时间，避免持锁期间执行耗时且不相关的工作。涉及多个资源时，应采用一致的加锁顺序，降低死锁风险。

业务失败后的回滚和锁释放是不同操作：普通运行时锁不会自动撤销已经完成的数据修改，事务系统是否回滚则由事务规则决定。

锁的生命周期、超时和异常处理都需要遵循具体实现，不能仅根据 X 模式推断。
