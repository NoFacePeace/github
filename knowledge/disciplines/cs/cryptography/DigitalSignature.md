# 数字签名

数字签名（Digital Signature）是一种使用私钥生成签名、使用对应公钥验证签名的密码学机制，用于验证内容完整性及其与签名密钥的关联。

## 1. 签名与验证

```text
签名：消息 + 私钥 → 签名算法 → 签名值
验证：消息 + 签名值 + 公钥 → 验证算法 → 有效或无效
```

签名算法通常涉及消息哈希，具体计算由算法定义。常见算法包括 RSA-PSS、ECDSA 和 Ed25519。

签名验证通过，说明签名与消息及公钥匹配；在算法安全且私钥未泄露的前提下，可以据此认为签名由持有对应私钥的一方生成。消息被修改后，原签名通常无法通过验证。

## 2. 与加密的区别

数字签名不隐藏内容，消息和签名可以公开。它不是通用意义上的“私钥加密、公钥解密”，应按具体签名算法理解。

| 机制 | 主要目的 |
| --- | --- |
| 加密 | 防止未授权者读取内容 |
| 数字签名 | 检查内容完整性和签名来源 |

公钥验证本身不能证明现实身份，还需要可信方式将公钥与身份绑定，例如证书。私钥泄露后，攻击者也能生成有效签名。

## 3. 在 TLS 中的用途

- **证书签发**：CA 使用自己的私钥对证书内容签名，客户端使用 CA 公钥验证。
- **握手身份认证**：服务器使用证书对应的私钥签署握手上下文，客户端使用证书中的公钥验证 CertificateVerify，确认当前对端持有相应私钥。

这是两组不同的密钥与签名：CA 签署的是证书，服务器签署的是握手上下文。
