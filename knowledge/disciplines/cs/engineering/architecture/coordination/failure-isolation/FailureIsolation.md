# 失效隔离

失效隔离用于阻止已失去执行权的旧持有者继续对受保护资源产生有效操作。本文用它统称针对旧持有者的资源保护机制；这是描述性分类，不代表所有资料都采用同一术语。

## 1. 为什么需要失效隔离

租约到期、锁被释放或角色被撤销，都不会自动终止原进程，也不会撤回已经发出的请求。

```text
A 获得执行权 → A 长时间暂停 → 执行权失效 → B 接管
                                                 ↓
                                      A 恢复，继续发送旧请求
```

接管解决谁获得新的执行权，失效隔离解决资源如何处理旧请求。仅让客户端检查状态或主动停止，无法覆盖进程暂停和请求延迟等情况。

## 2. 两种方式

| 方式 | 资源端的判断依据 | 保证与边界 |
| --- | --- | --- |
| [租约有效性校验](LeaseValidation.md) | 请求的租约 ID 与当前租约匹配，且租约仍有效。 | 在操作生效的原子边界上确认执行权；需要把当前租约状态与资源操作纳入一致的校验协议。 |
| [隔离令牌校验](FencingToken.md) | 请求代次不小于该资源已接受的最大代次。 | 接受新代次后拒绝旧代次；单独使用时不保证租约到期立即拒绝旧请求。 |

租约 ID 只需区分不同授予，可以使用随机值；隔离令牌需要表达授予顺序，必须满足相应范围内的单调递增要求。两种方式可以组合使用。

## 3. 共同要求

- 校验必须覆盖实际受保护的操作；绕过校验的写入不受保护。
- 校验与操作必须处于同一原子边界，或由能提供等价保证的协议连接，避免检查通过后执行权变化。
- 明确资源范围和生效时点：某个资源接受新代次，不代表其他资源也已接受。
- 资源端应拒绝无效凭证；隔离令牌的大小比较本身不负责身份认证或防止伪造。

## 4. 与业务幂等的关系

失效隔离限制旧持有者的操作，业务幂等限制重复请求的效果。当前持有者也可能重试同一请求，因此仍需根据业务使用幂等键、唯一约束或条件更新。

对外部系统已经完成的副作用，事后拒绝本地结果提交不会将其撤销。需要保护哪些副作用，就应让对应资源参与校验或采用其他一致性方案。
