# 隔离令牌校验

隔离令牌（fencing token）是每次授予执行权时发放的单调递增代次。资源端记录已接受的最大代次，拒绝更旧代次的操作，从而隔离旧持有者。

## 1. 与随机租约 ID 的区别

随机租约 ID 表达身份，例如 `abc` 和 `xyz` 可以区分两次授予，但无法依据大小判断哪次更新。

隔离令牌表达顺序，例如同一保护范围内的授予依次获得 `41 → 42 → 43`。它不要求数值连续，但后一次成功授予必须比前一次更大，旧持有者不能自行取得新令牌后继续操作。

## 2. 资源端校验规则

针对同一个受保护资源，资源端执行：

```text
原子执行：
    请求令牌 < 已接受的最大令牌 → 拒绝
    请求令牌 >= 已接受的最大令牌：
        执行受保护操作
        将最大令牌更新为请求令牌
```

校验、更新最大令牌和实际操作必须原子执行，避免旧请求检查通过后，在新请求完成之后才写入。相同令牌允许多次操作，但这些操作之间的业务并发与重复请求仍需另行处理。

## 3. 旧请求被拒绝的示例

```text
A 获取执行权，令牌为 41
    ↓
A 暂停，租约到期
    ↓
B 获取执行权，令牌为 42
    ↓
B 携带 42 写入，资源端记录最大代次 42
    ↓
A 恢复，携带 41 写入 → 41 < 42，拒绝
```

资源端可以根据自身记录完成比较，无需每次查询租约系统。

## 4. 保证的边界

仅发放 `42` 不会自动让资源端知道新代次。在资源端接受 `42` 之前，`41` 仍可能被接受，即使对应租约已经到期。

因此，该机制保证的是资源端接受新代次后不再接受旧代次，而不是实时证明每个请求的租约仍有效。若接管协议要求先建立资源端的隔离边界，可以让新持有者先原子登记新代次，再开始业务操作；该登记本身也必须拒绝代次倒退。

一个资源接受 `42` 不会自动更新其他资源。涉及多个资源时，需要分别建立隔离边界，或由统一协议协调。

## 5. 主动取消执行权

仅依靠“请求令牌不小于最大代次”的规则，无法直接禁用当前代次：它与最大代次相等，仍会被接受。主动取消需要向资源端推进隔离边界，或增加撤销状态。

### 5.1 推进代次但不授予执行者

授权管理方通过可信的代次发放流程取得更大的代次，并在资源端原子登记；如果只是取消，不将该代次授予任何执行者。

```text
A 使用令牌 41，资源端最大代次为 41
    ↓
管理方取得取消代次 42
    ↓
资源端原子地将最大代次推进到 42
    ↓
A 携带 41 操作 → 拒绝
```

登记取消代次不需要产生业务写入，但必须与业务请求使用一致的原子排序规则，且不能使最大代次倒退。后续重新授权应使用更大的代次，例如 `43`，不复用取消代次。

取消代次必须来自与正常授予一致的顺序，不能随意将资源端计数器加一，以免与已发放代次冲突。该方式拒绝的是比取消代次更旧的请求，不会自动拒绝更大的合法代次；并发的新授权与取消应由授权管理协议明确先后及取消范围。

### 5.2 增加撤销状态

也可以在资源端维护“当前代次、是否允许操作”，将当前代次标记为禁用：

```text
取消前：(41, enabled)
取消后：(41, revoked)
携带 41 操作 → 因已撤销而拒绝
```

一种明确的协议是由管理方先登记授权代次和状态，再允许业务请求进入；业务请求只能在令牌等于当前代次且状态为 `enabled` 时操作，不能自行启用已撤销代次。重新授权时，由管理方原子地登记更大的代次并启用。

这是在基本代次比较规则上增加的授权状态协议。不能仍无条件允许“令牌大于等于最大值”的业务请求绕过撤销检查。撤销指定授予时，应检查当前代次是否仍等于预期值，避免迟到的撤销请求禁用后续的新授权。

### 5.3 取消的生效边界

只在发放端生成取消代次或记录撤销意图，不会立即阻止资源端写入。取消需要在受保护资源端登记成功，且登记、状态校验和业务操作必须遵循同一原子协议；在此之前，旧请求仍可能被接受。

取消不会自动停止旧进程，也不能撤回已经完成的操作。涉及多个资源时，需要分别登记或使用统一协调协议；部分资源成功不代表全部资源都已隔离。资源端保存的最大代次和撤销状态也不能因重启或故障恢复而丢失。

## 6. 实现要求

- 发放端需要在授予顺序上保证代次单调递增，故障切换后不能回退或重用旧代次；普通本地计数器不足以自动提供这一保证。
- 资源端的最大代次需要在重启、恢复和故障切换后保持安全，不能丢失记录后重新接受旧请求。
- 所有受保护操作都必须校验，不能存在可绕过的写入路径。
- 令牌应来自可信授予流程；允许请求者随意提交更大数字，会破坏隔离语义并可能阻塞合法持有者。
- 令牌比较范围应覆盖实际冲突的资源；不能直接比较来自无关发放序列的代次。
