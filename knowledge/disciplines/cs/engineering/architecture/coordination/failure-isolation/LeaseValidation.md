# 租约有效性校验

租约有效性校验是在受保护操作生效时，确认请求属于当前仍有效的租约，并拒绝失效持有者的请求。

## 1. 校验条件

针对同一资源，通常需要同时满足：

- 请求租约 ID 与当前租约 ID 一致。
- 租约未到期、未被撤销，业务条件仍允许操作。
- 请求来自被授权的持有者，资源范围匹配。

租约 ID 可以使用 UUID 等随机标识，也可以使用其他唯一标识；关键是不同授予可区分，避免重用后误接受旧请求。它不需要支持大小比较。

## 2. 接管示例

```text
A 获取租约 abc
    ↓
A 暂停，租约到期
    ↓
B 原子地获取新租约 xyz
    ↓
A 恢复，携带 abc 请求写入
    ↓
资源端发现当前有效租约为 xyz，拒绝 abc
```

即使 B 尚未写入，资源端也能依据当前租约拒绝 A。若没有人接管，A 的租约到期后也应被拒绝；仅比较 ID 而不检查有效性不足以提供这一保证。

## 3. 原子性要求

以下是逻辑上的原子操作，不代表可以直接拆成多个独立调用：

```text
原子执行：
    读取当前租约
    校验 ID、有效期及适用条件
    校验失败 → 拒绝
    校验成功 → 执行受保护写入
```

租约状态与业务数据位于同一数据库时，可以结合事务、行锁或条件更新设计实现；还需要明确时间基准和操作生效时点，不能认为放进事务就自动解决全部过期语义。

若租约在 Redis，业务数据在另一个存储中，先查询 Redis 再写业务数据通常不能提供上述原子性：

```text
A 查询租约有效 → A 暂停 → 租约到期，B 接管 → A 恢复并写入
```

此时应由资源端提供原生租约校验，或采用能够协调租约变更与资源操作的一致性协议。把查询移到服务端但仍分步执行，不能消除这一竞争窗口。

## 4. 主动撤销与无期限授权

除等待到期外，也可以主动撤销当前执行权。若完全不设置过期时间，这种机制更接近可撤销的所有权记录，而不是有期限的租约；资源端仍可通过当前授权 ID 是否匹配来隔离旧持有者。

### 4.1 替换 ID

例如资源 `task-123` 当前的授权 ID 为 `abc`，授权管理方可以通过条件更新将它替换为全新的 `xyz`：

```text
原子执行：
    当前 ID == abc → 替换为 xyz
    当前 ID != abc → 不修改，返回冲突
```

替换成功后，携带 `abc` 的旧请求不再匹配；若将 `xyz` 授予新持有者，新持有者可携带它操作。新 ID 必须由受控的授权流程生成和授予，不能让旧持有者读取到当前 ID 后自行继续操作。

条件更新可避免迟到的撤销或交接请求覆盖之后的新授权。ID 不应重用，否则早期的旧请求可能重新匹配。

### 4.2 删除或标记撤销

如果只想取消、不准备立即交给新持有者，可以在当前 ID 仍等于预期旧 ID 时删除授权记录，或将其标记为已撤销。

资源端应同时检查记录存在、ID 匹配且状态允许操作；记录不存在或已撤销时拒绝请求。之后重新授予时，应生成全新 ID。

### 4.3 撤销的生效边界

替换、删除或标记撤销，必须与资源端的“校验并操作”遵循同一原子协议，才能确定操作发生在撤销之前还是之后。不能先读取 ID、再独立写入，否则旧请求仍可能在撤销后生效；若授权记录与业务资源位于不同系统，仅修改授权记录不能自动提供这一保证。

撤销执行权不会自动停止进程，也不会撤回已经完成的操作。可以额外发送取消信号帮助持有者停止，但资源端仍应拒绝失效请求。

没有过期时间就没有超时自动回收能力。持有者宕机或失联后，需要管理方或恢复流程主动撤销；仅因无法联系持有者而无条件覆盖授权，也不能替代受控的交接协议。

## 5. 适用场景与边界

适用于资源端能够可靠获得当前租约状态，并将有效性校验与实际操作一致处理的场景。校验可以使用资源内部维护的状态，不一定每次远程查询独立租约服务。

无法确认租约有效时，若仍要维持这一保证，就应拒绝或延迟操作。已经完成的操作不会因为之后租约到期而自动撤销。
