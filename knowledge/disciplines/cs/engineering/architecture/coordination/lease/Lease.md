# 租约

租约（Lease）是在有限时间内授予某个持有者的权利。持有者在有效期内操作指定资源；需要延长使用时间时申请续约，不能续约则在到期后失去权利。

## 1. 基本要素

| 要素 | 含义 |
| --- | --- |
| 资源范围 | 租约保护的任务、锁或角色，明确权利作用于什么。 |
| 持有者 | 当前获得权利的进程或节点实例。 |
| 租约标识 | 区分每次授予，避免旧请求误操作新租约。 |
| 有效期限 | 由权威端维护的过期时间或剩余有效期。 |
| 校验规则 | 获取、续约、释放和资源访问时需要满足的条件。 |

这些是租约的逻辑要素，不是固定的存储字段，也不要求全部保存在同一条记录中。资源关联和持有者可以由其他记录表达，有效期限也可以由存储系统的 TTL 机制维护。

独占租约要求同一资源同一时刻最多只有一个有效持有者；支持共享访问的租约则需要定义相应的并发范围。

## 2. 与资源、任务的职责边界

租约描述某项权利是否有效，不负责定义资源的业务内容或执行任务。以任务系统为例，可以这样划分职责：

| 角色 | 职责 |
| --- | --- |
| 任务管理逻辑 | 保存任务内容和状态，决定调度、接管与结果处理。 |
| 租约管理逻辑 | 通过权威端授予、续约和释放租约，判断权利是否有效。 |
| Worker | 申请执行资格，确认获取成功后执行任务，并在执行期间续约。 |

任务管理逻辑根据租约状态决定业务动作，租约管理逻辑不需要了解任务具体执行什么。两者可以位于同一模块，也可以依赖独立的协调组件；职责分开不意味着必须部署独立的租约服务。

任务记录与租约占用状态可以分开保存。租约失效表示执行权失效，不代表任务被删除或已经完成；是否重新调度由任务管理逻辑决定。

## 3. 生命周期

```text
申请获取
    ↓
权威端检查条件，授予租约
    ↓
有效期内执行工作
    ├─ 续约成功 → 延长有效期
    ├─ 主动释放 → 提前结束
    └─ 到期或撤销 → 权利失效
```

申请失败时不应以为自己已获得权利；请求超时则可能是结果未知，应按租约标识查询或进行幂等重试。

## 4. 获取与接管

以独占租约为例，权威端需要原子地检查同一资源是否存在有效租约，并在允许获取时授予新租约。不能先查询、再无条件写入，否则多个申请者可能同时认为自己获取成功。

Worker B 找到待接管的任务，只是发现了候选工作，不代表已经取得执行权：

```text
Worker A 失联，无法续约
    ↓
权威端判定旧租约已过期
    ↓
Worker B、C 尝试获取同一任务的租约
    ↓
权威端原子检查并授予
    ├─ B 成功 → 持有新租约，接手任务
    └─ C 失败 → 不执行任务，等待或有界重试
```

失联可能只是暂时的网络故障，不能据此直接删除仍有效的旧租约。接管通常需要等待旧租约过期；若支持提前撤销，则必须遵循撤销协议并处理旧持有者的失效隔离。

获取新租约不要求先物理删除旧记录：可以在原子操作中检查并替换已过期的租约，也可以等待旧占用记录过期删除后，再通过条件创建竞争获取。不能把“读取旧租约、无条件删除、创建新租约”当作三个独立步骤，否则可能删除或覆盖其他申请者刚取得的租约。

## 5. 续约

续约不是无条件修改过期时间。权威端应原子检查：

- 资源、持有者实例和租约标识是否匹配。
- 租约是否仍有效、是否被撤销或替换。
- 业务条件是否仍允许持有，例如任务未被取消。

检查成功后才延长有效期，旧持有者不能通过迟到的续约请求恢复已失效的租约。到期后重新获取应视为新的一次授予。

例如有效期为 30 秒、每 10 秒续约一次：

```text
00 秒获取 → 有效至 30 秒
10 秒续约 → 有效至 40 秒
20 秒续约 → 有效至 50 秒
后续无成功续约 → 50 秒后失效
```

续约间隔应小于有效期，并为网络延迟、重试和进程暂停预留余量。该比例与时间数值需要结合业务确定。

## 6. 续约失败与本地截止时间

应区分明确拒绝和临时错误：

- **明确拒绝**：例如租约已被替换或撤销，应立即视为失去权利。
- **临时错误或响应丢失**：可以在已确认的有效期内重试，但不能自行延长有效期。
- **超过已确认期限**：停止依赖该租约的操作，不能因为续约请求仍在途中就继续认为有效。

在简单的相对 TTL 模型中，本地可保守地从请求发出时计算截止时间，再扣除安全余量，并使用单调时钟。不能从收到响应时才无条件增加完整 TTL，否则会忽略请求耗时。

本地停止只是保护措施；长暂停、失控进程或已发出的外部请求仍可能越过截止时间，因此资源端校验同样重要。

## 7. 释放与失效隔离

主动释放应校验租约标识和实例身份，避免旧持有者删除已经属于新持有者的租约。

租约过期不会自动杀死原进程：

```text
实例 A 暂停 → 租约到期 → 实例 B 获取新租约
                                  ↓
                         A 恢复，可能继续旧操作
```

需要严格保护共享资源时，可使用单调递增的 fencing token。新授予携带更高代次，资源端记录已接受的代次并拒绝更旧的操作。资源端必须实际执行校验，仅生成 token 不能阻止旧写入。

随机租约 ID 可以区分授予并用于匹配校验，但本身不提供新旧代次顺序。

## 8. 与心跳、锁的区别

| 概念 | 核心问题 |
| --- | --- |
| 心跳 | 最近是否收到存活信号。 |
| 租约 | 某项权利是否仍在有效期内。 |
| 锁 | 某项资源是否允许并发访问。 |

一次心跳可以顺便延长存活期限，但心跳续约不应自动延长所有任务的执行权。锁可以用租约限制持有时间，不过仍需处理失效后的旧操作。

## 9. 常见用途与边界

租约常用于任务执行权、主节点角色、服务注册和临时锁。Redis TTL、注册中心或一致性存储都可承载租约，具体正确性取决于其原子性、时间语义、复制与故障切换保证。

租约也不等于业务只执行一次。持有者可能已经完成外部操作，却在保存结果前失联；新持有者重试时仍需依靠业务幂等、去重或条件写入避免重复效果。
