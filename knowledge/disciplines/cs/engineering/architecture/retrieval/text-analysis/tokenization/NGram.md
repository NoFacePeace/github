# n-gram

n-gram 将序列中连续的 n 个单元组成一个片段。单元可以是字符、词等；在检索分词中，常用字符级 n-gram 生成词元，不要求片段构成自然语言中的词。

## 1. 基本示例

### 1.1 字符级 n-gram

窗口通常每次向后移动一个字符，相邻片段可以重叠。例如：

| 方式 | “苹果手机”的切分结果 |
| --- | --- |
| 1-gram | 苹 / 果 / 手 / 机 |
| 2-gram | 苹果 / 果手 / 手机 |
| 3-gram | 苹果手 / 果手机 |

按[字](Character.md)切分是字符级 n-gram 在 n = 1 时的特例，也称字符级 unigram。2-gram 和 3-gram 分别也称 bigram 和 trigram。

### 1.2 词级 n-gram

词级 n-gram 需要先确定词边界，再组合连续的词。例如：

```text
输入词序列：I / like / search / engines
词级二元组：I like / like search / search engines
```

字符级与词级的单位不同，不能仅凭 n 的取值判断切分结果。字符级实现还应明确字符边界，避免将一个字符的编码单元拆开。

## 2. 长度配置与词元数量

可以固定 n，也可以配置最小和最大长度，为同一段文本生成多个长度的片段。例如，“苹果手机”同时生成 1～3 个字符的片段时，共产生 4 + 3 + 2 = 9 个词元。

对长度为 L 的序列，若不添加边界标记、不做过滤或去重，并按步长 1 滑动，固定长度 n 产生的词元数量为 `max(L - n + 1, 0)`。多个长度的数量按长度分别计算后求和。

n 越小，通常覆盖越广，但片段区分能力越弱；n 越大，通常更有区分能力，但无法直接为短于 n 的输入生成片段。配置较宽的长度范围会增加词元和索引开销。

## 3. Edge n-gram

Edge n-gram 只生成输入词元开头的不同长度前缀。例如，对 `search` 生成长度为 1～3 的前缀：

```text
普通 n-gram，n = 3：sea / ear / arc / rch
Edge n-gram，长度 1～3：s / se / sea
```

Edge n-gram 适合前缀搜索和输入联想，本身不覆盖词中间的任意子串。使用时需要明确先按什么规则产生输入词元，以及最短和最长前缀长度。

## 4. 索引与查询的配合

字符 n-gram 可以用于部分匹配，但能匹配什么内容取决于长度配置、文本预处理和查询条件。

- 短查询：索引只保留 2-gram 时，单字查询“苹”无法通过相同规则生成词元，需要额外字段或其他处理策略。
- 连续性：查询“苹果手机”产生“苹果 / 果手 / 手机”后，仅要求三个词元都出现，不保证它们在文档中连续出现。需要连续匹配时，应检查位置与偏移的实现，配置相应约束或回查原文验证。
- 前缀查询：可以在索引阶段生成 Edge n-gram，在查询阶段保留用户输入的前缀，但需验证查询长度是否落在索引覆盖范围内。
- 字符处理：是否保留空格、标点，是否先按单词切开，都会改变窗口能够跨越的边界。

因此，建立 n-gram 索引本身不保证任意子串查询的完整语义，普通短语查询能否提供所需约束也要以具体分词器的位置输出为准。

## 5. 使用与验证

字符 n-gram 不依赖词典，适合缺少词典、需要部分匹配或补充召回的场景，但可能产生没有独立语义的片段。自然语言全文检索可以将它作为补充字段，与按词切分的字段配合使用。

验证时应覆盖短于最小长度、长于最大长度、片段分散出现、标点与空白以及中英文混合等情况，并比较召回、误匹配、索引大小和延迟。
