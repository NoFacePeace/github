# 分词

分词（Tokenization）是将文本切分为可处理单元的过程。在全文检索中，分词器输出词元（Token），经过后续词元处理后，形成用于建立索引或匹配查询的词项（Term）。词元不一定是自然语言中完整的词，具体边界取决于分词规则。

分词属于文本分析中的一个步骤，由分词器（Tokenizer）负责完成。它不是数据结构，分词结果可以用列表或流表示，再由索引构建程序组织为词项字典和倒排表。

## 1. 词元边界

分词器根据配置决定词元的起止位置。例如，中文可以按词切分，也可以按字或连续字符片段切分；英文通常按单词边界切分。业务标识符还可能需要整段保留。

```text
原文：苹果手机
一种按词切分：苹果 / 手机
按字切分：苹 / 果 / 手 / 机
```

边界选择影响哪些查询能够匹配。完整词有助于区分主题，较细的片段可以扩大覆盖，但也可能增加噪声和索引开销。转小写、词干提取和停用词过滤属于后续词元处理步骤。

## 2. 分词结果的表示

分词器通常可以输出词元文本、位置和字符偏移等信息。例如，对 `Redis caches data` 进行保留大小写的单词切分后：

| 词元 | 位置 | 字符范围 |
| --- | --- | --- |
| Redis | 1 | [0, 5) |
| caches | 2 | [6, 12) |
| data | 3 | [13, 17) |

此例位置从 1 开始，字符范围采用从 0 开始的左闭右开区间。具体系统的位置起点和偏移单位可能不同，例如使用字节或 UTF-16 代码单元，需要以实现约定为准。

位置用于短语和邻近查询，字符偏移用于定位原文和高亮。分词结果可以逐个输出并消费，不需要先把整篇文档的结果放进列表，也不一定需要单独持久化。

## 3. 分词方式

常见方式包括基于边界规则、词典、统计与模型的切分，以及字符级 n-gram、整段保留和子词切分。它们可以按语言、字段用途和匹配需求组合使用。

各类方式的原理、示例及适用场景见[分词方式](Methods.md)。

## 4. 索引与查询的边界配合

索引和查询的切分边界需要兼容。例如，索引只保留“苹果手机”时，查询切分为“苹果”未必能通过普通词项匹配命中。

两侧不必输出完全相同的词元集合，但需要明确查询如何使用索引中的词项及位置。切分规则变更后，应检查召回、误匹配和短语查询；影响索引词元或位置的变更通常需要重建已有索引。
