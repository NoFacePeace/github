# 分词方式

分词方式决定如何从文本中产生词元。选择时需要考虑文本语言、字段用途和匹配需求；同一套检索系统可以为不同字段配置不同方式，也可以组合多种方式。

## 1. 基于边界规则切分

根据空格、标点、Unicode 单词边界或业务规则确定切分位置。例如，将 `search engine` 切分为 `search / engine`。

按空格切分实现简单，适合边界明确的文本；自然语言文本通常还需要处理标点、缩写和连字符。中文通常没有显式词间分隔符，仅按空格或标点无法识别多数词语。

常见规则、业务边界及验证要点见[边界规则](BoundaryRules.md)。

## 2. 基于词典切分

通过预先收录的词条匹配文本，采用最长匹配或候选词图与路径选择等方法确定结果。例如，词典包含“搜索引擎”和“技术”时，可以将“搜索引擎技术”切为“搜索引擎 / 技术”。

这种方式方便维护领域术语，但依赖词条覆盖和消歧规则。词条匹配、常见算法及领域词典维护见[词典](Dictionary.md)。

## 3. 基于统计与模型切分

利用词频、上下文概率或模型预测选择词边界。常见方法包括基于词频的路径评分、HMM、CRF 和神经网络序列标注。

统计与模型方法可以处理部分歧义和未登录词，效果依赖语料、训练数据及目标领域。它们与词典方法可以组合，例如先通过词典生成候选词，再用统计信息选择路径，或用模型补充新词识别。

## 4. 字符级 n-gram 切分

将连续的 n 个字符组成词元，不要求片段构成自然语言中的词。例如，按字符生成二元组时，“苹果手机”切分为“苹果 / 果手 / 手机”。按字切分是 n = 1 时的特例。

这种方式不依赖词典，可用于部分匹配，但可能产生无意义片段并增加索引开销。Edge n-gram 则只生成输入词元开头的前缀，适合输入联想。

长度配置、Edge n-gram 以及索引与查询的配合见[n-gram](NGram.md)。

## 5. 整段保留

将整个字段值保留为一个词元，例如把 `ORDER-123` 作为一个整体，适合订单号、标签和其他精确标识符。

如果还需要匹配字段中的部分内容，可以另建使用其他切分方式的字段。大小写转换等归一化规则需单独配置，整段保留本身不规定是否区分大小写。

## 6. 子词切分

[BPE](BPE.md)、WordPiece 等方法将文本表示为子词 token 序列，一个英文单词可能对应多个 token。具体实现可能基于字符或字节，token 也可能包含空格或标点。

这类方法常用于大模型等机器学习模型的输入表示。其目标与全文检索中的词项匹配不同，不能直接假设模型 token 适合作为倒排索引中的检索词项。

## 7. 与检索策略的配合

粗粒度、细粒度描述输出粒度；索引分词、查询分词描述使用阶段，它们与上述实现方式属于不同维度。

选择方式时，应先明确需要完整词、前缀、连续子串还是完整字段匹配，再验证词元、位置和查询条件。例如，可将自然语言按词切分，将编号整段保留，并用单独的前缀字段支持输入联想。

索引与查询的分析规则需要兼容。最终应结合真实查询评估召回、误匹配、索引大小和延迟，而不是仅根据切分粒度选择。
