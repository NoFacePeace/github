# 边界规则

基于边界规则的切分根据空格、标点、字符类别及上下文规则确定词元的起止位置。规则可以来自 Unicode 单词边界规范，也可以针对业务文本制定。

## 1. 基本示例

按空白字符切分时：

```text
原文：search engine
词元：search / engine
```

仅按空白切分通常会保留词元内部和末尾的标点。例如，`hello, world!` 可能得到 `hello, / world!`；若希望得到 `hello / world`，还需要指定标点边界或过滤规则。

## 2. 常见规则

### 2.1 空白与分隔符

把空格、制表符、换行或指定字符作为分隔符，适合边界明确的文本。例如，以逗号切分 `red,green,blue`，得到 `red / green / blue`。

需要明确连续分隔符是否产生空词元，以及分隔符是否保留。对于带引号或转义规则的 CSV 等结构化数据，应先使用相应解析器识别字段，不能简单按字符拆开。

### 2.2 标点与字符类别

通过标点或字符类别变化确定边界，例如按连字符切开 `search-engine`，或将字母和数字之间的边界作为产品型号的切分位置。

规则应按字段用途选择。若直接移除 `C++`、`C#` 中的符号，两者都可能变成 `C`，丢失用于区分技术名称的信息。

### 2.3 Unicode 单词边界

Unicode 单词边界规则根据字符属性和相邻上下文判断边界，比单纯按空格拆分覆盖更多情况，也不等同于遇到任意标点就切开。

实现可以在默认规则上做语言或业务调整，具体行为还受 Unicode 版本和组件配置影响。Unicode 单词边界本身不保证识别中文的自然语言词边界，中文通常仍需词典、模型或其他切分方案。

### 2.4 业务边界

针对邮箱、版本号、错误码和产品型号制定规则。例如，`ERR_CONNECTION_RESET` 可以保留整体，也可以按下划线拆分，以支持对组成部分的查询。

如果同时需要完整值和组成部分匹配，可以使用不同字段分别保留完整值和拆分结果。若在同一字段输出多种词元，应检查重叠词元的位置和偏移是否符合查询需求。

## 3. 切分与归一化

边界规则决定在哪里切开；转小写、全角半角转换和其他归一化处理决定字符如何表示。例如，将 `Redis` 转为 `redis` 本身没有改变词元边界。

某些字符预处理会间接影响边界，例如把连字符替换为空格。应明确处理顺序，并检查原文偏移能否正确用于高亮。

## 4. 使用与验证

这种方式适合空格分词语言、格式明确的文本及业务标识符。规则容易解释和调整，但仅靠显式分隔符难以处理没有词间空格的语言，也可能误拆具有特殊含义的符号。

验证时应覆盖连续空白、不同标点、缩写、连字符、字母数字混合、邮箱和中英文混合文本，并同时检查索引与查询的词元、位置和字符偏移。边界不兼容可能导致漏匹配，过度切分也可能增加误匹配。
