# BPE

BPE（Byte Pair Encoding，字节对编码）是一种通过反复合并相邻单元构建词表的方法，最初用于数据压缩，后来用于自然语言处理中的子词切分。模型使用的 BPE 分词器根据已经学好的合并规则，将文本转换为 token 及其整数编号。

## 1. 训练阶段

训练从字符或字节等基础单元开始，典型过程为：

1. 根据预处理和预切分规则，将训练语料表示为基础单元序列。
2. 统计语料中相邻单元对的出现频率。
3. 选择最常见的一对，合并为新单元，加入词表，并更新语料中的表示。
4. 重复统计和合并，直到达到目标词表大小或其他停止条件。

例如，假设依次学到 `l + o → lo`、`lo + w → low` 两条规则：

```text
l / o / w
    ↓ 合并 l + o
lo / w
    ↓ 合并 lo + w
low
```

此例仅说明合并过程，实际规则及顺序取决于训练语料、基础单元和训练配置。

## 2. 编码阶段

编码使用已经确定的预切分规则、合并优先级和词表，不会针对每条输入重新训练。

典型实现先把输入拆为基础单元，再按训练得到的合并顺序，在允许合并的相邻单元之间逐步合并，直到没有适用规则。最后把得到的 token 映射为整数 ID。

```text
输入文本 → 预切分 → 基础单元 → 按优先级合并 → token ID 序列
```

编码阶段使用的是已学到的优先级，不是重新统计当前输入中哪一对最常见，也不等同于每次查找词表中的最长词。预切分边界通常会限制哪些单元可以合并。

## 3. 字符级与字节级

| 变体 | 基础单元 | 特点 |
| --- | --- | --- |
| 字符级 BPE | 字符 | 先表示为字符序列，再合并相邻片段；未覆盖字符如何处理取决于配置 |
| 字节级 BPE | 字节 | 以字节表示文本，再合并字节片段；以完整字节集合为基础时，可以覆盖 UTF-8 文本中的字节 |

字节级 BPE 中，一个 token 不一定对应完整字符。例如，一个汉字的 UTF-8 字节可能分布在多个 token 中；反过来，一个 token 也可能包含多个字符或空格。

因此，查看单个 token 时应明确它代表的是哪些字节。将完整 token 序列解码回文本，与分别把每个 token 当成独立 UTF-8 字符串解码，可能得到不同效果。

## 4. 与其他切分方式的区别

| 方式 | 切分依据 | 输出特点 |
| --- | --- | --- |
| 边界规则 | 空格、标点、字符属性等规则 | 边界由预设规则决定 |
| 词典分词 | 已收录词语及候选选择规则 | 通常以识别词语为目标 |
| n-gram | 固定长度的连续单元 | 给定 n 后，片段包含固定数量的单元 |
| BPE | 从语料学到的相邻单元合并规则 | 片段长度可变，不要求具有完整词义 |

BPE 也有词表，但词表中的条目可以是子词或字节片段。其合并规则服务于文本表示，不能直接等同于面向自然语言词边界的词典分词。

## 5. 算法与具体编码方案

BPE 描述算法思路；具体编码方案还需要确定基础单元、预切分规则、合并优先级、token ID 映射和特殊 token 等配置。两个方案即使都采用 BPE，也可能对相同文本产生不同的切分结果和 ID。

OpenAI 的[cl100k_base](CL100KBase.md)是采用字节级 BPE 的具体编码方案，可以通过 tiktoken 加载并用于编码、解码和 token 计数。

## 6. 使用场景

BPE 常用于语言模型和嵌入模型的文本输入表示。常见片段可以合并成较长 token，其他文本则可以由更小的单元组合表示，从而在词表规模和序列长度之间进行权衡。

用于全文检索时，需要单独评估它是否满足词项匹配、短语查询和相关性评分的需求。模型能够处理的 token，并不自动成为适合检索的词项。
