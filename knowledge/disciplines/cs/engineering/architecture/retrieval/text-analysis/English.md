# 英文

英文文本分析通常先基于单词边界分词，再进行词元处理。在全文检索中，常见方案是转为小写，并根据检索需求加入词干提取、停用词过滤等步骤。

## 1. 基本流程

英文通常基于[边界规则](tokenization/BoundaryRules.md)切分。空格有助于区分单词，但还需要处理标点和 Unicode 单词边界。字符预处理阶段可以按数据来源清理 HTML 或规范化字符，具体规则按字段选择。例如：

```text
原文：The cats are running.
分词：The / cats / are / running
转小写：the / cats / are / running
```

此例中的转小写发生在分词之后，属于词元处理。仅执行分词时，输出仍然可以保留原始大小写。

## 2. 词元处理选择

英文常见的词元处理选择包括：

- 转小写：使 `Redis` 与 `redis` 有机会匹配同一词项；大小写敏感标识符需单独配置。
- 词干提取：需要覆盖单复数、时态等词形变化时，可以评估英文算法的效果。
- 词形还原：需要结合词性等信息还原基本词形时，评估相应组件与成本。
- 停用词过滤：按需移除 `the`、`are` 等词，同时检查标题、固定短语和否定表达。

这些步骤的原理、执行顺序及位置处理见[词元处理](TokenProcessing.md)。例如，同时配置英文词干提取与停用词过滤后：

```text
输入：the / cats / are / running
一种分析配置的结果：cat / run
```

此例不代表所有英文分析器的默认输出。

## 3. 特殊边界

| 原文 | 可能的处理 | 关注点 |
| --- | --- | --- |
| don't | 保留整体，或拆为 do / n't | 缩写与否定信息 |
| state-of-the-art | 保留整体，或拆为 state / of / the / art | 复合词及其组成部分的匹配 |
| user@example.com | 保留整体，或拆成多个词元 | 完整邮箱查询 |
| C++、C# | 保留符号，或丢弃符号后得到 C | 技术名称区分 |
| v1.2.3、ERR_CONNECTION_RESET | 保留整体，或按符号切分 | 版本号与错误码查询 |

表中列出的是可选策略，不是某个具体分词器的固定输出。技术文档搜索通常需要对标识符设置专门字段或分析规则，并用实际分词结果验证。

## 4. 常见分析器

Lucene 及基于它的搜索系统常提供标准分析器和语言分析器。以 Elasticsearch 的内置分析器为例：

| 分析器 | 主要处理 | 适用起点 |
| --- | --- | --- |
| standard | 按 Unicode 单词边界切分、转小写；默认不过滤停用词，也不做英文词干提取 | 通用文本，希望保留词形差异 |
| english | 标准分词、英语所有格处理、转小写、英文停用词过滤和词干提取 | 英文自然语言文本，希望不同词形能够匹配 |

分析器是组织分词器及其他处理步骤的组件，不能与单独的分词器等同。具体输出应通过所用版本的分析接口验证。

## 5. 选型与验证

通用英文搜索可以从标准单词切分和转小写开始；需要匹配单复数、时态等变化时，再评估英文词干提取。代码、产品型号和错误码等精确内容通常需要额外保留完整值。

验证时应覆盖缩写、所有格、连字符、技术名称和词形变化，并同时检查索引与查询的分析结果。最终根据真实查询的召回率、准确性及延迟选择规则，而不是仅根据切分是否符合直觉。
