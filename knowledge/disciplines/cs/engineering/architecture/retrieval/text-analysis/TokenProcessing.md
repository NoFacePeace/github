# 词元处理

词元处理在分词之后过滤、改写或扩展已有词元，常由词元过滤器（Token Filter）执行。输入和输出是词元流，可以保留、修改、删除或增加词元，并维护相应的位置和字符偏移信息。

## 1. 大小写归一化

将词元统一为指定大小写，例如把 `Redis` 转为 `redis`，使大小写不同的查询有机会匹配同一词项。

转小写本身不负责确定词边界。对于大小写敏感的标识符，应按字段决定是否保留差异；涉及不同语言的大小写规则时，需要验证具体组件的行为。

## 2. 词干提取与词形还原

### 2.1 词干提取

词干提取（Stemming）通过规则去除词缀，让不同词形有机会匹配到同一词项。例如，常见英文算法可将 `cats` 处理为 `cat`，将 `running` 处理为 `run`。

Porter、Snowball 是常见的词干提取算法或算法实现体系。词干不一定是真实单词，也不保证所有含义相关的词都归为同一形式；过度合并可能产生误匹配。应选择适合目标语言的算法，代码、型号等字段通常需要单独处理。

### 2.2 词形还原

词形还原（Lemmatization）结合词典、词性等信息还原基本词形，例如将复数 `cats` 还原为 `cat`。它通常需要更多语言分析，并非所有通用全文检索分析器都默认提供。

## 3. 停用词过滤

按配置移除 `the`、`are`、`的` 等词元，以减少索引词项或降低其影响。停用词表需要按语言和业务选择，不能把所有高频词直接视为无用词。

标题、固定短语、否定表达和单词查询可能依赖这些词。过滤后还需检查词元位置和全停用词查询的行为，避免产生不符合预期的结果。

```text
输入：the / cats / are / running
仅过滤 the、are：cats / running
```

## 4. 同义词处理

将同义表达归一化为统一词项，或展开为其他词项，以覆盖不同表达。例如，可以按领域规则将“内存”和 `RAM` 建立对应关系，但需要确认该关系在目标语境中成立。

同义词可以在索引阶段或查询阶段处理。涉及单词与多词短语的转换时，应检查词元图、位置长度及查询组件的支持情况，不能只比较词项文本。

## 5. 处理顺序与位置

词元过滤器通常按配置顺序执行，前一步的输出会成为后一步的输入。例如，停用词表使用小写时，先转小写再过滤，可以使 `The` 命中表中的 `the`。

配置转小写、停用词过滤和词干提取后，可能得到：

```text
分词结果：The / cats / are / running
转小写：the / cats / are / running
过滤停用词：cats / running
提取词干：cat / run
```

以上步骤按语言和业务选择，不必全部执行。过滤词元通常应保留必要的位置间隔，避免让原本不相邻的词项在短语查询中被误判为相邻。词干变化后，字符偏移仍应能定位原文中的对应范围。

## 6. 使用与验证

索引与查询的词元处理需要兼容。只在一侧转小写或应用不同词干规则，可能造成漏匹配；同义词等处理也可以只在查询侧执行，但应验证展开后的匹配语义。

验证时应覆盖大小写、词形变化、全停用词查询、固定短语和同义表达，并检查处理前后的词元、位置、原文偏移及检索结果。
