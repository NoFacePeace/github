# 字符预处理

字符预处理在分词之前清理、替换或规范化原始文本。输入和输出都是文本，处理结果会影响分词器看到的字符及其边界。

## 1. 常见处理

下表展示可配置的处理规则及其预期结果，具体行为以所用组件为准：

| 处理 | 原文 | 处理后 |
| --- | --- | --- |
| HTML 清理 | `<b>苹果</b>` | `苹果` |
| 全角转半角 | `ＡＢＣ１２３` | `ABC123` |
| 字符映射 | `苹果＆手机` | `苹果和手机` |
| 分隔符替换 | `search-engine` | `search engine` |

HTML 清理适合正文中包含标签的内容；若字段本身保存代码示例，需要按检索用途决定是否处理标签。全角半角转换和字符映射也应按业务配置，避免合并需要区分的内容。

## 2. 对分词边界的影响

字符替换可能间接改变分词结果。例如，先把连字符替换为空格，可以使按空白切分的分词器将 `search-engine` 拆为 `search / engine`。

删除字符和替换为空格的效果不同。若直接删除中间的分隔符，原本分离的字符可能拼接成新的词元；若提前移除 `C++` 中的 `+`，则会丢失技术名称中的信息。

同一处理目的可能有不同实现位置。例如，大小写归一化可以在字符阶段实现，检索系统也常在分词后通过词元过滤器实现。应根据实际操作对象和执行阶段分类。

## 3. 原文偏移与高亮

删除标签或替换不同长度的字符后，处理后文本的位置可能与原文不同。若需要返回原文高亮，组件应能维护必要的偏移修正，或由应用记录处理后文本到原文的映射。

字符偏移和词元位置承担不同职责：字符偏移定位原文范围，词元位置用于短语和邻近查询。字符预处理变更后，两者都应结合后续分词结果检查。

## 4. 使用与验证

字符预处理按字段选择，不必对所有内容启用相同规则。自然语言正文、代码、产品型号和订单号可能需要不同配置。

验证应覆盖标签、空白、全角字符、特殊符号、中英文混合以及长度发生变化的替换，并检查处理后文本、后续词元、查询匹配和原文高亮是否符合预期。
