# 英文分词

英文分词是在英文文本中识别单词等处理单元的过程。在全文检索中，常见方案是基于单词边界切分，再转为小写，并根据检索需求加入词干提取、停用词过滤等处理。

## 1. 基本流程

英文有空格帮助区分单词，但不能只按空格拆分，还需要处理标点和 Unicode 单词边界。例如：

```text
原文：The cats are running.
分词：The / cats / are / running
转小写：the / cats / are / running
```

大小写归一化属于分词之后的文本分析步骤。它可以让 Redis 与 redis 匹配同一词项，但对于大小写敏感的标识符，需要按字段决定是否保留差异。

## 2. 词形与停用词处理

### 2.1 词干提取

词干提取（Stemming）通过规则去除词缀，让不同词形有机会匹配到同一词项。例如，常见英文词干算法可将 cats 处理为 cat，将 running 处理为 run。

Porter、Snowball 是常见的词干提取算法或算法实现体系。词干不一定是真实单词，也不保证所有含义相关的词都归为同一形式；过度合并也可能产生误匹配。

词形还原（Lemmatization）则结合词典、词性等信息还原基本词形，需要更多语言分析，通常不是通用全文检索分析器的默认步骤。

### 2.2 停用词过滤

停用词过滤按配置移除 the、are 等常见功能词，以减少索引词项或降低其影响，但并非所有场景都适合开启。标题、固定短语或包含否定词的查询可能依赖这些词。

```text
输入：the / cats / are / running
一种分析配置的结果：cat / run
```

此例同时使用词干提取与停用词过滤，不代表所有英文分词器的默认输出。

## 3. 特殊边界

| 原文 | 可能的处理 | 关注点 |
| --- | --- | --- |
| don't | 保留整体，或拆为 do / n't | 缩写与否定信息 |
| state-of-the-art | 保留整体，或拆为 state / of / the / art | 复合词及其组成部分的匹配 |
| user@example.com | 保留整体，或拆成多个词元 | 完整邮箱查询 |
| C++、C# | 保留符号，或丢弃符号后得到 C | 技术名称区分 |
| v1.2.3、ERR_CONNECTION_RESET | 保留整体，或按符号切分 | 版本号与错误码查询 |

表中列出的是可选策略，不是某个具体分词器的固定输出。技术文档搜索通常需要对标识符设置专门字段或分析规则，并用实际分词结果验证。

## 4. 常见分析器

Lucene 及基于它的搜索系统常提供标准分析器和语言分析器。以 Elasticsearch 的内置分析器为例：

| 分析器 | 主要处理 | 适用起点 |
| --- | --- | --- |
| standard | 按 Unicode 单词边界切分、转小写；默认不过滤停用词，也不做英文词干提取 | 通用文本，希望保留词形差异 |
| english | 标准分词、英语所有格处理、转小写、英文停用词过滤和词干提取 | 英文自然语言文本，希望不同词形能够匹配 |

分析器是包含分词器及其他处理步骤的完整流程，不能将分析器与单独的分词器等同。具体输出应通过所用版本的分析接口验证。

## 5. 选型与验证

通用英文搜索可以从标准单词切分和转小写开始；需要匹配单复数、时态等变化时，再评估英文词干提取。代码、产品型号和错误码等精确内容通常需要额外保留完整值。

验证时应覆盖缩写、所有格、连字符、技术名称和词形变化，并同时检查索引与查询的分析结果。最终根据真实查询的召回率、准确性及延迟选择规则，而不是仅根据切分是否符合直觉。
