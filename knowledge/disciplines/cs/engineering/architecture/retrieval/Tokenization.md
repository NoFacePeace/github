# 分词

分词（Tokenization）是将文本切分为可处理单元的过程。在全文检索中，分词器输出词元（Token），经过大小写归一化等后续处理后，形成用于建立索引或匹配查询的词项（Term）。词元不一定是自然语言中完整的词，具体边界取决于分词规则。

分词属于文本处理过程，不是数据结构。分词结果可以用列表或流表示，再由索引构建程序组织为词项字典和倒排表。

## 1. 中文分词

中文通常没有空格标记词的边界，需要通过词典、统计规则或模型判断如何切分。常见工程方案是使用成熟分词器，再补充领域词典。方法、工具与选型见[中文分词](ChineseTokenization.md)。

## 2. 英文分词

英文通常基于单词边界切分，再进行大小写归一化，并按需加入词干提取和停用词过滤。缩写、连字符和技术名称需要额外规则。具体流程与分析器选择见[英文分词](EnglishTokenization.md)。

## 3. 分词与文本分析

文本分析的范围比单纯切分更广，常见流程是：

```text
原文 → 字符预处理 → 分词 → 词元过滤与归一化 → 索引词项
```

常见处理包括：

- 大小写归一化：例如将 Redis 转为 redis，使查询不区分大小写。
- 停用词过滤：按配置移除 the、的等词，但可能影响短语匹配或包含否定词的查询。
- 词干提取（Stemming）：按规则去除词缀，结果不一定是真实单词。
- 词形还原（Lemmatization）：结合词典、词性等信息还原基本词形，例如将复数 cats 还原为 cat。
- 同义词处理：将同义表达归一化或展开为其他词项，可以在索引阶段或查询阶段执行。

以上步骤按语言和业务选择，不必全部执行。停用词过滤通常应保留必要的位置间隔，避免让原本不相邻的词项在短语查询中被误判为相邻。

## 4. 分词结果的表示

分词器通常可以输出词元文本、位置和字符偏移等信息。例如，对 `Redis caches data` 分词并转为小写后：

| 词项 | 位置 | 字符范围 |
| --- | --- | --- |
| redis | 1 | [0, 5) |
| caches | 2 | [6, 12) |
| data | 3 | [13, 17) |

此例位置从 1 开始，字符范围采用从 0 开始的左闭右开区间。具体系统的位置起点和偏移单位可能不同，例如使用字节或 UTF-16 代码单元，需要以实现约定为准。

位置用于短语和邻近查询，字符偏移用于定位原文和高亮。分词结果可以逐个输出并消费，不需要先把整篇文档的结果放进列表，也不一定需要单独持久化。

## 5. 与倒排索引的关系

索引构建与查询都会使用文本分析：

```text
索引阶段：文档 → 分词与归一化 → 词项及位置等信息 → 倒排索引
查询阶段：查询 → 分词与归一化 → 查询词项 → 查找倒排表并匹配
```

例如，文档 `Redis caches data` 被分析为 redis、caches、data，索引中就会为这些词项建立到文档的映射。查询 `Redis` 若也被归一化为 redis，即可查到对应候选。

索引与查询的分析规则需要相互兼容，但不要求完全相同。例如，同义词可以只在查询阶段展开。若词边界或归一化规则不兼容，可能导致漏召回或误匹配；修改索引阶段的规则后，通常需要重建受影响的索引才能应用到已有文档。

## 6. 其他切分方式

### 6.1 n-gram 切分

n-gram 将连续的 n 个字符或其他单元组成一个词元，不一定遵循自然语言词边界。例如，按字符生成二元组：

```text
原文：苹果手机
词元：苹果 / 果手 / 手机
```

这类切分可用于部分匹配或缺少词典的场景，但会增加词元数量，也可能产生没有独立语义的片段。是否能完成任意子串查询，还取决于索引与查询策略。

### 6.2 大模型的子词切分

大模型常使用 BPE、WordPiece 等子词方法，将文本转换为 token 序列及编号。一个英文单词可能拆成多个 token，token 也可能包含空格或标点。

这类切分主要服务于模型输入表示，与全文检索中用于词项匹配的分析目标不同，不能直接假设两者输出一致。
