# 稠密检索

稠密检索（Dense Retrieval）将查询和待检索内容表示为稠密向量，再根据向量之间的相似度或距离查找相关内容。“稠密”描述表示方式，通常意味着向量的大多数维度为非零值。

## 1. 稠密向量表示

文本检索通常使用[嵌入模型](../../../ai/models/embedding/Embedding.md)生成固定维度的向量。各维度一般是模型学到的特征，多个维度共同表达内容，通常不能将某个维度直接解释为某个词语。

下面的数值仅作示意：

```text
文档：手机电池消耗过快的处理方法 → [0.12, -0.35, 0.81, ...]
查询：手机掉电快怎么办           → [0.14, -0.32, 0.79, ...]
```

如果模型在相关任务上训练得当，两种措辞可能得到相近的表示。向量是否接近仍取决于模型和度量方式，不能仅根据文字示例保证检索结果。

## 2. 基本流程

1. 文档处理：将内容整理为文档或片段，保留标识、来源、权限等元数据。
2. 文档编码：使用模型生成向量，并保存向量与内容的对应关系。
3. 查询编码：将用户输入转换到与文档兼容的向量空间。
4. 相似度检索：查找得分最高或距离最近的候选，并结合过滤条件返回结果。

```text
文档或片段 → 文档编码 → 文档向量
查询       → 查询编码 → 查询向量 → 相似度检索 → 候选内容
```

查询与文档可以使用同一编码器，也可以使用经过训练、输出空间相互对齐的不同编码器。仅向量维度相同不足以保证可以比较。

## 3. 相似度与索引

常见度量包括内积、余弦相似度和欧氏距离，应按模型训练目标及使用说明选择，并确认是否需要归一化。相似度得分不是相关性概率。

数据量较小时，可以逐个比较查询与全部文档向量，得到精确近邻；规模较大时，通常通过近似近邻索引减少计算，常见方案包括 [HNSW](../../../algorithms/retrieval/HNSW.md)、IVF 和结合乘积量化的方案。

是否使用近似索引不改变表示属于稠密向量这一事实。索引选择需要权衡近邻召回率、延迟、内存、构建成本和更新能力。

## 4. 与其他检索概念的关系

- 向量检索：按向量相似度或距离查找内容，范围还可以包含稀疏表示。工程交流中常用“向量检索”指代稠密向量检索。
- 全文检索：关注文本正文的索引、匹配和排序能力，与稠密或稀疏这种表示维度并非同一分类角度。
- 混合检索：可以组合稠密表示与词项匹配或学习型稀疏表示，再融合候选并按需重排序。

“用嵌入模型将查询和文档转成稠密向量，再比较相似度”就是典型的稠密检索流程。

## 5. 适用场景与局限

稠密检索有助于覆盖词面不同但含义相关的查询，例如同义改写、自然语言提问和跨语言匹配，具体能力取决于模型。

对于错误码、产品型号、数字差异或否定表达，表示接近不一定意味着满足查询条件。需要结合精确过滤、词项匹配或重排序验证，不能将语义相似直接当成事实一致。

## 6. 使用与验证

验证应覆盖不同措辞、领域术语、标识符、否定句和数值条件，并分别评估模型表示质量与近似索引损失。分块方式、截断、查询前缀和模型版本也会影响结果。

更换模型或编码配置后，已有文档向量通常需要重新生成。以真实查询检查相关内容是否进入候选、排序是否合理，并比较延迟、存储和运行成本。
