# 中文分词

中文分词是在没有显式单词分隔符的中文文本中识别词边界的过程。在中文全文检索中，常见工程方案是使用词典与统计方法结合的成熟分词器，并补充领域词典；也可以根据系统能力和检索需求选择模型分词或字符 n-gram。

## 1. 基本示例

```text
原文：我喜欢苹果
分词：我 / 喜欢 / 苹果

原文：南京市长江大桥
分词：南京市 / 长江大桥
```

以上是一种合理切分，不代表所有工具的固定输出。中文存在边界歧义，专业术语、产品名称和新词也可能不在词典中，因此不能只根据空格或标点确定词边界。

## 2. 常见方法

### 2.1 词典与统计方法

词典方法通过已有词条匹配文本，简单实现包括正向或逆向最大匹配。更复杂的方案会生成多种候选切分，再结合词频等统计信息选择结果，也可以使用模型补充未登录词识别。

这类组合方案在工程中很常见：实现和运行成本通常较低，方便通过领域词典补充“倒排索引”等术语。效果依赖词典质量和消歧规则，并非增加词条就一定能改善所有查询。

### 2.2 模型分词

模型可以根据上下文预测字符之间的词边界，常见方法包括隐马尔可夫模型、条件随机场和神经网络序列标注。

模型方法有助于处理歧义和未登录词，但效果取决于训练数据与目标领域的一致性，运行成本也随模型而异。词典和模型并不互斥，实际工具可以同时使用。

### 2.3 字符与 n-gram 切分

这类方式按单字或连续字符片段切分，不要求片段构成自然语言中的词。例如：

```text
原文：苹果手机
单字：苹 / 果 / 手 / 机
二元字符：苹果 / 果手 / 手机
```

它不依赖词典，可用于部分匹配等场景，但可能增加词元数量并降低区分能力。固定长度的 n-gram 对更短查询如何匹配，需要结合查询规则评估，不能直接视为任意子串搜索。

## 3. 常见工具与场景

| 工具或组件 | 常见场景 | 特点 |
| --- | --- | --- |
| jieba | Python 文本处理、自建索引 | 基于词典和词频选择切分路径，可结合 HMM 识别未登录词，支持自定义词典 |
| IK | Elasticsearch、OpenSearch 中文搜索生态 | 常见的第三方中文分析插件，提供不同切分粒度；需选择与搜索引擎版本兼容的发行版 |
| HanLP | 需要中文 NLP 能力的应用 | 提供分词等能力，具体算法、模型和成本依所选组件而定 |
| MySQL ngram 解析器 | MySQL 原生 CJK 全文索引 | 按配置的字符片段长度生成词元，不属于按词典识别中文词边界的方案 |

这些工具没有适用于所有技术栈的统一排名。选择通常先受部署环境限制，再比较领域文本上的效果。

## 4. 切分粒度与领域词典

较粗的切分保留完整术语，有利于区分主题，但可能遗漏对术语组成部分的查询；较细的切分或多粒度输出可以扩大覆盖，也可能带来更多噪声和索引开销。

例如，对“倒排索引”的查询，需要考虑用户是否也会搜索“倒排”或“索引”。是否保留完整词、同时输出组成词，或用不同字段建立多种索引，应由查询需求决定。

领域词典适合维护产品名、业务术语和专有名称。更新词典后，应检查真实分词结果以及词项位置，不应假设仅添加词条就能保证所有上下文中的切分一致。对索引阶段生效的规则变更，通常还需要重建已有索引。

## 5. 选型与验证

通用中文全文检索可以从成熟分词器与领域词典开始；使用 MySQL 原生全文索引时，可以评估 ngram 解析器；对上下文消歧有较高要求时，再比较模型方案的效果与成本。

验证时应覆盖歧义短语、未登录词、中英文混合、产品名和错误码，并检查索引与查询的分析规则是否兼容。以真实查询评估召回、误匹配、短语查询、索引大小和延迟，切分越细不代表结果越好。
