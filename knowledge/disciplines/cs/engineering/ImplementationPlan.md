# 实现计划

实现计划将项目目标拆解为有依赖顺序、可以执行和验证的任务，适用于新项目、功能开发，以及为了学习而实现开源项目精简版（mini）的过程。

计划的基本结构是：目标与范围 → 核心流程 → 实现阶段 → 模块与具体事项 → 阶段验收，并单独记录待确认问题。

## 1. 目标与范围

先明确最终要获得什么成果，以及本次实现的边界：

- 实现目标：项目解决什么问题，最终通过什么示例展示成果。
- 学习目标：如果是 mini 项目，重点理解哪些算法、机制或设计。
- 本次实现：必须支持的操作、行为和运行环境。
- 暂不实现：本轮不涉及的能力，避免范围不断扩大。
- 技术约束：技术栈、兼容要求和必要的资源限制。

实现开源项目的 mini 时，先运行官方示例，阅读 README、快速入门和公开接口，整理输入、输出及行为约定，再确定精简范围。围绕具体问题阅读源码，逐步比较自己的实现与原项目的设计。

## 2. 核心流程

描述一次真实输入到输出的完整路径，用来识别必要模块、模块职责和依赖关系。例如 mini Redis：

```text
客户端请求 → 协议解析 → 命令分发 → 存储操作 → 响应编码 → 返回结果
```

针对每个环节说明输入、输出和职责，并记录会影响实现的关键异常情况。网络模块负责连接和数据收发，协议模块负责请求解析与响应编码，命令模块负责参数检查与操作分发，存储模块负责数据读写。

核心流程应放在阶段划分之前，为任务拆解提供依据。前期可以先实现其中一段可验证的流程，再逐步接通完整路径。

## 3. 阶段、模块与具体事项

### 3.1 按可验证的能力划分阶段

每个阶段都应产出可运行、可验证的成果，按依赖顺序逐步扩展能力。例如：

| 阶段 | 成果 | 验收方式 |
| --- | --- | --- |
| 本地命令可执行 | 在内存中执行 SET、GET、DEL | 本地调用完成写入、读取和删除 |
| 客户端可访问 | 通过 TCP 接收命令并返回结果 | 使用 redis-cli 执行支持的命令 |
| 重启后可恢复 | 保存操作记录并在启动时重放 | 重启后能恢复已确认持久化的数据 |

一个阶段可以涉及多个模块；同一模块也可以在多个阶段逐步完善。

### 3.2 按模块拆分具体事项

采用“阶段 → 模块 → 具体事项”的层级，勾选放在具体事项上。模块负责划分职责，事项描述该阶段需要完成的具体动作。

- 事项应有明确结果，例如“GET 在键不存在时返回空值”。
- 避免“理解核心逻辑”“完善系统”等难以判断完成的表述。
- 任务过大时继续拆分，任务较少时可以省略模块层级。
- 阶段内先完成必要实现，再接通调用关系并验证完整流程。

### 3.3 为阶段定义验收标准

验收标准说明如何判断阶段完成，应包含可复现的操作和预期结果。

除正常流程外，根据该阶段的能力验证必要的边界和异常情况。例如，协议解析需要验证一次读取只有部分请求、一次读取包含多条请求；持久化需要验证重启恢复行为。

## 4. 待确认问题与进度维护

尚未明确的技术问题应单独记录，并写明解决方式和预期产出。例如：“阅读 RESP 文档并通过实验确认消息边界，整理解析规则和请求样例”。影响当前实现的问题优先解决。

进度使用 Markdown 任务清单维护：

- `- [ ]`：待完成，或实现后尚未验证。
- `- [x]`：已完成并验证。

近期任务写细，后续阶段保留轮廓。随着实现补充新任务、调整依赖和范围；如果变更使已完成事项不再成立，应重新打开对应事项。阶段中的任务与验收均完成后，再判断该阶段完成。

## 5. 可复用模板

下面以 mini Redis 为例。实际使用时，按项目目标调整范围、流程和阶段。

```markdown
# Mini Redis 实现计划

## 1. 目标与范围
- 实现目标：支持通过 redis-cli 操作的单机内存数据库。
- 学习目标：理解命令执行、协议解析和网络请求处理。
- 本次实现：单连接，支持 SET、GET、DEL 的基本形式。
- 暂不实现：持久化、复制、集群，以及命令的可选扩展参数。
- 技术栈与运行方式：实施前填写。

## 2. 核心流程
客户端请求 → 协议解析 → 命令分发 → 存储操作 → 响应编码 → 返回结果。

- 网络模块：管理连接，读取请求数据并发送响应。
- 协议模块：解析请求，编码响应。
- 命令模块：检查名称和参数，分发存储操作。
- 存储模块：维护内存键值数据。

## 3. 阶段一：本地命令可执行

### 3.1 存储模块
- [ ] 实现键值写入与覆盖
- [ ] 实现键值读取，区分键不存在与空值
- [ ] 实现键值删除并返回删除结果

### 3.2 命令模块
- [ ] 实现 SET、GET、DEL 的参数检查与分发
- [ ] 处理未知命令和参数数量错误

### 3.3 阶段验收
- [ ] 本地调用完成写入、读取、覆盖和删除，结果符合预期
- [ ] 验证键不存在、未知命令和参数错误时的行为

## 4. 阶段二：客户端可访问

### 4.1 协议模块
- [ ] 解析客户端使用的必要 RESP 请求格式
- [ ] 编码支持命令所需的成功、空值、整数和错误响应
- [ ] 处理不完整请求和连续多条请求

### 4.2 网络模块
- [ ] 启动 TCP 服务并接收连接
- [ ] 接通读取、解析、命令执行和响应发送流程
- [ ] 处理客户端断开并释放连接资源

### 4.3 阶段验收
- [ ] 使用 redis-cli 完成 SET、GET、DEL 操作
- [ ] 拆分或合并发送请求，确认解析与执行结果正确

## 5. 待确认问题
- [ ] 确认 redis-cli 在目标版本下建立连接时使用的命令，确定必要的支持范围

## 6. 交付验收
- [ ] 补充启动方式、使用示例和已知限制
- [ ] 记录模块职责及关键设计取舍
- [ ] 按 README 从零启动并完成演示
```

## 6. 保存位置

知识库保存制定实现计划的通用方法与模板。具体项目的执行计划保存在其代码仓库根目录的 `PLAN.md` 中，随代码实现持续更新。
