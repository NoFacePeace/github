# 全文检索

全文检索（Full-text Search）是一种对文档正文建立索引，并根据查询中的词项查找和排序相关文档的检索技术。它通常包含文本分析、倒排索引构建、查询处理、文档匹配与相关性评分等环节。

## 1. 索引构建

1. 文档接入：读取正文、标题及其他需要检索的字段，为文档分配标识。
2. 文本分析：通过分词、大小写转换等处理，将文本转换为词项。具体处理取决于语言和字段用途。
3. 建立[倒排索引](../../data-structures/inverted-index/InvertedIndex.md)：记录词项到文档的映射，按需保存词频、词项位置等信息。
4. 索引维护：随源文档的新增、修改和删除更新索引。

例如，文档 A 包含“Redis 内存”，文档 B 包含“MySQL 内存”，则“内存”对应的倒排列表包含 A 和 B，“Redis”对应的倒排列表包含 A。

## 2. 查询流程

1. 查询分析：对查询进行与索引分析相兼容的处理，得到查询词项及匹配条件。
2. 候选匹配：读取倒排列表，按照 AND、OR、短语等查询条件确定匹配文档。
3. 评分排序：计算文档与查询的相关性，并结合过滤条件、业务规则等确定结果顺序。
4. 结果返回：返回排名靠前的文档，按需生成摘要或高亮匹配内容。

倒排索引帮助系统快速定位匹配文档，相关性评分决定这些文档如何排序；实际实现可以交错执行匹配和评分，并提前跳过不可能进入前列的候选。

## 3. 相关性评分

- [BM25](../../algorithms/retrieval/BM25.md)：根据词频、逆文档频率与文档长度计算相关性，是全文检索中常见的评分算法。

BM25 是全文检索的评分环节之一。全文检索系统还需要完成文本分析、索引维护、查询执行等工作。

## 4. 设计关注点

- 文本分析：中文分词、同义词和停用词等配置会影响匹配结果；错误码、标识符等内容可能需要保留完整词项。
- 匹配语义：词项匹配、短语匹配和子串匹配的含义不同，全文检索不等同于遍历正文进行子串查找。
- 索引新鲜度：源文档更新到可检索之间可能存在延迟，需要根据业务需求设计更新流程。
- 规模与延迟：数据量较大时，可以通过分片分散存储和查询压力，通过副本提高可用性与查询吞吐。
- 语义补充：仅依赖词项匹配可能遗漏表达不同但含义相近的内容，可以结合向量检索进行混合检索。
