# 向量检索

向量检索（Vector Search）是将查询与待检索内容表示为向量，根据向量之间的相似度或距离查找相关内容的检索方式。文本语义检索通常使用[嵌入模型](../../ai/models/embedding/Embedding.md)（Embedding Model）生成向量，使含义相近的内容在向量空间中更接近。

向量检索也可以用于图片、音频等内容；检索质量取决于向量表示是否能反映任务需要的相关性。

## 1. 索引构建

1. 内容处理：解析源数据，按需要清洗、切分文本，并保留文档标识、来源、权限等元数据。
2. 向量生成：使用嵌入模型将每个检索单元转换为向量。
3. 索引建立：保存向量及其对应的内容标识，根据数据规模和性能要求选择索引结构。
4. 索引维护：随源内容更新，新增、替换或删除对应向量，并同步元数据。

文本分块影响检索粒度。块过大可能稀释主题，块过小可能缺少上下文，需要结合文档结构和实际查询评估。

## 2. 查询流程

1. 查询向量化：使用与内容向量兼容的嵌入模型和处理方式生成查询向量。
2. 近邻查找：根据相似度或距离，从向量集合中找出最接近查询的候选内容。
3. 条件过滤：结合权限、租户、时间等条件限制结果；过滤可以在近邻查找前、过程中或之后执行。
4. 结果排序：按向量得分排序，必要时使用重排序模型进一步评估查询与候选内容的相关性。
5. 内容返回：根据内容标识读取正文、来源等信息，返回给用户或下游系统。

例如，查询“如何降低数据库占用的 RAM”时，即使文档使用“减少数据库内存消耗”的表述，也可能因为语义接近而被召回。

## 3. 相似度与索引

### 3.1 相似度度量

- 余弦相似度：比较向量方向，通常值越大越相似。
- 内积：同时受到向量方向和长度影响，通常值越大越相似。
- 欧氏距离：比较向量之间的直线距离，通常值越小越接近。

度量方式及是否归一化应与嵌入模型的使用要求保持一致。相似度分数不是相关性概率，也不存在适用于所有模型和任务的统一阈值。

### 3.2 精确检索与近似检索

- 精确近邻检索：计算查询与全部候选向量的距离或相似度，再选出最接近的结果，适用于规模较小或要求精确结果的场景。
- 近似近邻检索（ANN）：通过索引减少搜索范围或计算成本，以部分召回损失换取更低延迟和更高吞吐，常见方案包括 [HNSW](../../algorithms/retrieval/HNSW.md)、IVF，以及结合乘积量化（PQ）的方案。

索引选择需要权衡召回率、查询延迟、内存占用、构建成本与更新能力。这里的近邻召回率衡量近似结果对精确近邻的覆盖情况，不等同于业务相关性。

## 4. 设计关注点

- 模型一致性：查询与内容向量必须处于兼容的向量空间；维度相同不代表不同模型生成的向量可以直接比较。部分模型要求查询和文档使用不同前缀。
- 模型升级：更换模型或处理方式后，通常需要重新生成内容向量，并设计索引迁移与查询切换流程。
- 过滤策略：仅在召回后过滤，可能导致最终结果不足；提前或在搜索过程中应用过滤，也可能影响索引效率及召回率，需要评估。
- 权限控制：权限条件必须在结果交付前生效，重排序、生成等下游环节只能接收允许访问的内容。
- 质量评估：使用真实查询评估相关结果的覆盖率、排序质量和延迟，不能仅凭少量语义相似示例判断效果。
- 词项补充：专有名称、错误码和精确标识符可能更依赖词项匹配，可以结合全文检索进行混合检索。

## 5. 在 RAG 中的作用

向量检索可以为 RAG 召回与问题语义相关的资料，但不负责生成回答。系统还需要组织上下文、保留来源并交给大模型生成；向量相近也不保证资料能够回答问题。
