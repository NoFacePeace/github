# Agent 评测

Agent 评测检查从接收问题、调查证据到生成回答的完整过程，用于比较不同工具组合对答案质量与执行成本的影响。

## 1. 输入与输出

- 输入：题目、固定仓库版本、报告要求、可用工具、模型与执行预算。
- 评分资料：参考答案、必要证据及评分规则，对被测 Agent 隐藏。
- 输出：最终回答、工具调用轨迹、评分、耗时、Token 和执行错误。

## 2. 任务与分组

任务可以包含代码机制解释、API 查找、指标归属与异常分析。根据实验目的，分别提供远程源码、本地只读源码、文档与图谱，或组合工具。

需要衡量工具差异时，保持题目、版本、模型和评分规则一致。实际可见工具与执行权限都需要记录，配置了工具名称不代表调用一定可用。

## 3. 执行流程

```text
选择题目与实验组
  → 准备隔离任务环境和工具配置
  → 向 Agent 提供题目及允许的调查入口
  → 运行调查与回答，记录执行轨迹
  → 提取最终回答及实际消耗
  → 按规则检查格式、内容和证据
  → 保存单题结果，汇总多轮实验
```

被测 Agent 的调查环境与评分环境分开。评审者不应自动继承被测 Agent 的全部外部工具权限，也不能将隐藏参考资料注入题面。

## 4. 评分维度

| 维度 | 关注问题 |
| --- | --- |
| 内容与机制 | 解释是否正确，关键条件、分支和限制是否完整 |
| 证据链 | 结论是否能由指定版本的资料支持，有无编造引用 |
| 工具使用 | 是否使用允许工具，调查是否符合任务范围 |
| 输出格式 | 是否满足题目要求的报告结构 |
| 效率 | 质量满足要求时，耗时与 Token 是否合理 |

确定性规则用于格式和可明确检查的事实，模型评审用于语义评价。具体维度、权重与阈值需随任务定义，不把单一总分当作全部解释。

## 5. 结果与复查

每次独立执行保留答案、工具输入输出、模型与配置身份、评分依据和运行状态。重复运行用于观察稳定性，比较平均表现与失败分布。

区分工具故障、执行超时、评审失败和真实答错。未完成评审应明确标记，不能直接解释为内容质量为零；工具调用成功也不证明答案正确。

合成异常任务评估推理与调查能力，不代表完成真实生产故障验证。

## 6. 执行与评分角色

| 角色 | 职责 |
| --- | --- |
| [Harbor](https://harborframework.com/) | 编排任务环境、Agent 执行、并发、超时与 Verifier 调用，保存运行产物 |
| 被测 Agent | 在允许的工具与资料范围内调查问题，输出最终回答 |
| Verifier | 读取回答与执行记录，组织确定性检查和语义评审，汇总评分及依据 |
| 模型 Judge | 根据题目、参考答案、证据与评分标准，评价正确性、机制解释和证据链 |
| [Arize Phoenix](https://github.com/Arize-ai/phoenix) | 接收实验结果，展示回答、评分和可用执行轨迹，支持分组比较 |

Verifier 是验收环节，Judge 是其中负责语义判断的一部分。格式、可明确核验的规则、耗时与 Token 等适合由代码检查或计算，不全部交给模型。

```text
数据集与实验配置
  → Harbor 准备环境并运行被测 Agent
  → 收集回答与执行记录
  → Harbor 启动 Verifier
  → 确定性检查 + 模型 Judge
  → 汇总并保存评分
  → 上传 Phoenix 展示与比较
```

Judge 与答题 Agent 分开执行，即使使用同一种模型，也不能共用未隔离的任务上下文。Judge 只接收评分所需资料，不应通过自由调查改变固定参考范围。

## 7. Judge 一致性与评分波动

不同 Judge 模型、模型版本、提示词和评分标准可能产生不同分数；同一模型重复评分也可能波动。固定 Judge 有助于提高可比性，但不能消除模型偏差。

对照实验需要固定并记录 Judge 的模型身份、提示词、参考答案、评分规则及适用推理参数，区分被测模型配置与评审模型配置。

更换 Judge 或评分规则后，原则上使用新条件统一重评所有待比较的回答，并将结果标记为新的评分版本。保留原始回答，避免为比较 Judge 而无意重新运行答题 Agent、引入另一组变化。

Agent 多轮作答与同一答案多轮评分分别衡量执行波动和评审波动，实验记录应明确区分。分差接近评分波动时，不宜直接断言某个实验组更好。

## 8. 人工复核与评分可信度

抽样检查 Judge 的分数与理由，重点复核高低分样本、组间差异较大的样本、边界答案和明显误判。模型评分应保留可追溯依据，而不只保存总分。

可以使用人工标注或明确的事实检查校准评分尺度。需要多个 Judge 时，预先约定分歧处理与汇总方式，不在看到实验结果后挑选更有利的评审。

Phoenix 展示已有结果，不会自动消除 Judge 偏差；平台记录完整、评审执行成功与评分可信是不同层面的要求。
