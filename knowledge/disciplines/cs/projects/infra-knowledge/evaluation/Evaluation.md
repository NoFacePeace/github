# 评测

评测用于验证知识库提供的文档、图谱、源码和检索能力能否帮助用户与 Agent 准确获取证据、解释实现和分析问题。评测与线上服务分别运行，使用固定任务、版本和评分规则组织可复查的实验。

## 1. 评测目标

- 答案质量：事实与机制是否正确，关键条件是否完整，结论是否有证据。
- 工具效果：不同知识入口是否改善定位、调查与回答过程。
- 检索质量：相关内容能否进入候选，是否排在前面，无关内容是否过多。
- 执行效率：在质量满足要求的前提下比较耗时、Token 和工具调用成本。
- 可靠性：区分服务失败、任务执行失败、评分未完成与真实答案错误。

## 2. 评测类型

| 类型 | 执行对象 | 主要产物 |
| --- | --- | --- |
| [Agent 评测](Agent.md) | 提问后调查、调用工具并回答的完整过程 | 答案、工具轨迹、质量评分和资源消耗 |
| [检索评测](Retrieval.md) | 固定问题与检索服务 | 排名列表、相关内容命中情况和检索指标 |

Agent 任务可以覆盖代码机制解释、接口查找、指标归属和异常分析。合成告警可以用于测试分析能力，但不能据此声称完成真实事故根因验证。

## 3. 实验分组

根据需要设置不同证据入口进行对照：

| 分组 | 可用证据入口 |
| --- | --- |
| 远程源码 | 目录、文件读取及内容搜索 |
| 本地源码 | 固定版本的只读源码副本 |
| 文档与图谱 | 文档检索、关系导航及允许的节点证据 |
| 组合工具 | 文档、图谱与源码能力组合 |

工具权限属于实验变量，应记录实际可见与可执行范围。需要比较工具差异时，尽量保持题目、源码版本、模型、提示要求和预算一致；有意改变的条件应明确标记。

## 4. 执行流程

```text
定义任务、固定版本与参考证据
  → 配置实验组的模型、工具和预算
  → 准备隔离执行环境与题目副本
  → 运行 Agent 或固定检索请求
  → 保存答案、轨迹、排名、耗时和错误
  → 执行质量或检索评分
  → 汇总多轮结果并比较分组
  → 根据失败案例提出改进，再重新验证
```

评分参考和隐藏证据不应泄露给被测 Agent。多次独立运行用于观察波动，不能只挑选最好的一轮代表总体效果。

## 5. 评分与结果解释

Agent 评分可以结合确定性格式检查、证据核对和模型评审。模型评分需保存依据及完成状态，未完成评分不能被当作答案质量为零的同义词。

检索使用明确的相关内容标注，计算 Precision、Recall 和排名相关指标；比较时固定候选单位与 Top K，区分文档、章节和 Chunk。

效率指标与质量指标分别解释，不能仅凭低耗时或低 Token 判断方案更好。工具可用、执行成功和答案正确也属于不同结果。

## 6. 实验资料与边界

建议分别管理任务集、实验配置、运行器与评分代码、原始运行产物和分析报告。每次实验保留版本、模型、配置、评分规则及运行身份，支持复查与比较。

公开记录只使用可分享的题目和通用示例，不包含凭据、内部服务地址、私有源码、未公开参考答案或真实事故资料。工具权限和输入范围的变化需要作为实验条件记录，避免与历史结果直接混比。
