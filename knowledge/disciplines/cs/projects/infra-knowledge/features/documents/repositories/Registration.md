# 仓库登记

仓库登记用于将代码项目纳入 Infra 知识库管理。初期采用手动登记方式，由使用者提交仓库信息和版本跟踪配置；登记后再由系统按配置自动发现版本。本文为设计规划，具体接口与存储结构尚待确定。

## 1. 登记入口

可以通过网页表单或管理 API 提交登记信息。手动登记的是仓库及规则，不需要逐个录入后续提交。

请求职责、处理链路与待明确的接口契约见 [仓库接口设计](../../../design/server/repositories/Repositories.md)。

```text
手动登记仓库
  → 保存版本跟踪配置
  → 自动发现版本
  → 登记版本并创建构建任务
```

自动处理需要启用相应扫描与执行能力；登记成功本身不表示已经开始构建。

## 2. 录入信息

| 信息 | 用途 |
| --- | --- |
| 仓库名称与地址 | 标识项目并定位源码来源 |
| Git 平台项目标识 | 在接入的平台内识别项目，是否必填由平台适配方案决定 |
| 归属、负责人及简介 | 便于检索和维护 |
| [版本跟踪方式](tracking/Tracking.md) | 选择跟踪分支、Tag 或部署版本 |
| 跟踪规则 | 指定分支、Tag 匹配范围或目标环境 |
| [文档生成模式](modes/Modes.md) | 使用 Agent Skills 生成，按配置启用模块文档 |
| 其他生成选项 | 指定文档类型、分析范围和写作要求等 |

凭据通过受控的凭据引用接入，登记记录和文档中不保存明文密钥。

## 3. 输入、处理与输出

| 项目 | 内容 |
| --- | --- |
| 输入 | 仓库信息、跟踪配置和生成选项 |
| 处理 | 校验权限、字段及规则，识别重复或冲突，保存记录 |
| 输出 | 稳定的仓库身份、已保存配置或明确错误 |

处理链路如下：

```text
表单 / API 请求
  → 字段与权限校验
  → 仓库身份与重复检查
  → 创建或更新记录
  → 返回登记结果
```

远端地址可达性与访问权限是否在登记时验证，需要结合网络条件明确；仅保存配置不能视为已验证源码可获取。

## 4. 更新与异常处理

- 重复提交同一仓库时，应复用身份或返回已有记录，避免重复接入。
- 名称或远端身份发生冲突时明确报错，不能覆盖其他仓库。
- 修改跟踪规则只影响后续版本发现，不改写已登记版本的 SHA。
- 修改 Git 地址前应判断是否仍为同一项目；地址相同或名称相似不能单独证明项目身份一致。
- 字段不合法、权限不足或保存失败时，返回可定位原因的错误，避免留下部分更新。

## 5. 登记后的边界

仓库登记完成的是接入配置。版本发现负责找到提交，版本登记负责固定版本身份，构建任务负责安排后续执行。获取源码、生成文档和发布产物不在登记请求中同步完成。
