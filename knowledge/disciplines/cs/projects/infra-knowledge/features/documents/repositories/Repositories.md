# 仓库与版本管理

仓库与版本管理负责记录知识库处理哪些代码仓库，以及每份产物对应的精确源码版本。本文描述 Infra 知识库的设计规划，具体接口、数据结构与表结构尚待确定。

## 1. 核心概念

| 概念 | 含义 | 主要信息 |
| --- | --- | --- |
| 仓库 | 持续维护的代码项目 | 仓库身份、名称、Git 地址、归属与跟踪配置 |
| 版本 | 仓库的一次确定提交 | 所属仓库、完整 Commit SHA、提交说明和来源信息 |

一个仓库可以包含多个版本。分支与 Tag 是查找版本的引用，完整 Commit SHA 用于固定实际处理的源码。

## 2. 仓库登记

具体录入信息与处理流程见 [仓库登记](Registration.md)。

输入仓库地址、名称及跟踪配置，校验后保存为仓库记录，供后续版本发现与源码获取使用。

```text
仓库信息与跟踪配置
  → 校验身份、地址和规则
  → 创建或更新仓库记录
  → 返回登记结果
```

登记仓库只表示将项目纳入管理，不代表已经获取源码或生成文档。凭据应通过受控的凭据管理方式引用，不能将真实密钥写入知识文档。

## 3. 版本登记

版本可以来自自动发现或手动选择。登记时将版本引用解析到完整 SHA，并记录其来源。

```text
仓库身份、完整 SHA 与提交信息
  → 校验提交归属与可获取性
  → 判断版本是否已登记
  → 复用或创建版本记录
```

同一仓库下相同 SHA 应复用版本身份；不同分支或 Tag 指向相同提交时，可以关联多个来源。引用变化不应改写已有版本记录的 SHA。

## 4. 与构建的关系

版本记录回答“处理哪份代码”，构建任务回答“对这份代码执行什么操作”。两者分别管理，一个版本可以关联多次文档或图谱构建尝试。

仓库与版本管理提供稳定身份及元数据；任务创建、领取、并发控制和失败重试由执行流程中的其他环节负责。

## 5. 后续梳理重点

- 仓库登记：输入字段、校验规则、更新语义与错误处理。
- 版本登记：引用解析、版本身份、去重和并发登记。
- 版本查询：提交历史、来源信息及产物关联。
- 数据设计：仓库与版本的关联、约束和生命周期。
