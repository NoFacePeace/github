# 构建领取任务

周期调用 Worker 的 ScanPending 领取入口，将等待中的文档或图谱构建转为实际执行。本文为设计规划。

单轮容量检查、任务领取与启动流程见 [ScanPending](../../worker/ScanPending.md)。

## 1. 输入与输出

- 输入：待执行构建、可用执行容量、Worker 支持的构建类型。
- 输出：已领取并启动的构建尝试，或本轮无可执行任务的结果。

## 2. 单轮流程

```text
检查可用容量
  → 查询候选构建
  → 协调执行归属
  → 领取可启动的任务
  → 启动具体构建
  → 返回本轮领取结果
```

候选查询不等于领取成功；多个 Worker 竞争时，需要由任务管理机制保证执行归属。启动后的构建单独跟踪进度和终态。

## 3. 定时检查与一次性执行

定时任务可以每隔一段时间检查等待队列，具体构建则针对固定仓库版本执行一次。下一轮检查不会自动重新执行已经成功的构建。

领取检查是否等待构建结束、构建并发与领取批量，应分别定义。执行容量不足时，不应无界领取和堆积本地待启动任务。

## 4. 异常与恢复

需要记录领取失败、执行失败和取消的区别。Worker 异常后的接管、过期执行的写入限制及重试条件，由任务管理和执行机制提供。

发布失败或外部调用超时后，重试可能再次产生副作用，不能仅靠定时调度声称执行恰好一次。
