# 构建领取

Claim 负责将候选构建交给一个确定的执行者，取得执行身份与租约后才能启动构建。本文为 Infra 知识库的候选设计，具体接口、锁定粒度和租约参数尚待确定。

## 1. 输入与输出

| 项目 | 内容 |
| --- | --- |
| 输入 | 候选构建标识、执行者能力、领取令牌与租约策略 |
| 前置条件 | 已按约定取得必要的本地与全局执行额度 |
| 成功输出 | 已领取的构建、执行身份和租约信息 |
| 未领取 | 状态变化、其他执行者占用或能力不匹配等结果 |

全局槽位解决并发数量，Claim 解决具体任务归属；取得名额不等于取得任务。

## 2. 原子领取流程

```text
生成本次执行令牌
  → 开始领取事务
  → 锁定约定的互斥对象
  → 重新检查占用及任务状态
  → 写入执行令牌与租约到期时间
  → 提交事务
  → 返回领取结果
```

候选查询结果可能已过期，事务内必须复核。没有更新到符合条件的任务时，不能视为领取成功；未领取或异常返回后，调用方应释放不再使用的执行额度。

## 3. 仓库级互斥

若多个构建共享同一仓库的可变工作目录，可选择仓库级串行执行。所有领取路径先锁同一条稳定的仓库记录，再检查执行占用并写入租约，防止不同版本同时取得工作区。

如果各构建拥有隔离工作区，是否仍需仓库级互斥应重新评估。锁定仓库只是候选方案，不是所有构建系统的必需约束。

仓库行锁仅覆盖领取事务，事务提交后释放；不能把它当作整个构建期间的占用标识。

## 4. 执行身份与租约

执行令牌区分不同领取者和尝试，租约说明当前执行权的有效期限。可将“有执行身份且租约未到期”作为有效占用条件，具体适用状态需在协议中明确。

执行期间按约定续约，更新时检查当前令牌及有效期。续约失败应停止推进并请求取消；过期接管后，旧执行者不能继续覆盖新执行的状态或发布结果。

租约校验需要覆盖受保护的写入，仅在领取时检查一次不足以隔离失效执行者。外部调用与文件写入的重复副作用还需分别处理。

## 5. 数据与并发边界

- [仓库存储](../mysql/Repositories.md)：提供稳定仓库身份；采用仓库级互斥时作为统一协调对象。
- [Commit 存储](../mysql/Commit.md)：确定候选构建的源码版本及仓库归属。
- [Build 存储](../mysql/Build.md)：保存构建尝试、执行状态与归属信息。

领取事务、锁定顺序、时间基准及条件更新需要统一设计。领取成功后进入 [构建执行](../build/Build.md)，维护租约、调用构建组件并记录终态；Claim 本身不完成文档或图谱构建。
