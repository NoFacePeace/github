# LocalSlots

LocalSlots 表示当前 Worker 所在进程实例的执行槽位，用于限制本地同时处理的构建数量。本文为 Infra 知识库的设计规划，具体结构与接口尚待确定。

## 1. 作用范围

本地指当前进程实例，不是整台机器，也不代表整个集群。多个实例各自维护本地槽位，集群总并发另由全局执行槽位协调。

一个槽位表示一个执行名额，不直接代表固定的 CPU、内存或模型 Token 数量。不同构建是否按相同权重计数，需要明确约定。

## 2. 状态与命名

| 状态 | 建议名称 | 含义 |
| --- | --- | --- |
| 槽位上限 | `localSlotLimit` | 本实例允许占用的最大名额 |
| 已占用数量 | `usedLocalSlots` | 已预留或正在执行的名额 |
| 可用数量 | `availableLocalSlots` | 上限减去已占用数量 |

```text
availableLocalSlots = localSlotLimit - usedLocalSlots
```

例如，上限为 2、已占用 1，则最多还能预留 1 个执行名额。状态可保存在进程内存中，访问和修改应受同步保护。

确认存在可用槽位后，查询本轮准备尝试领取的 [候选构建](Candidates.md)，查询数量参考可用槽位数。

## 3. 预留与释放

```text
检查可用数量
  → 在同步保护下确认并预留槽位
  → 尝试领取与启动构建
      ├── 失败：释放预留
      └── 成功：持有至构建结束，再释放
```

只读取可用数量不足以保证并发安全。多个调用可能同时看到空位，必须通过原子的检查与预留操作避免超限。

同一名额应恰好释放一次，覆盖启动失败、正常结束、执行失败和取消路径；重复释放会使计数失真，遗漏释放会导致容量泄漏。

## 4. 与全局槽位的关系

本地槽位保护单实例资源，全局槽位约束多个实例的总执行数。实际执行需同时取得两类额度及任务执行权。

本地预留、全局额度申请与任务领取的具体顺序需统一设计。任一步失败，都应释放此前取得而不再使用的额度，避免持有资源空等。

## 5. 退出与配置变更

服务停止时应停止预留新槽位，等待或取消现有执行。进程退出会丢失本地计数，但不能据此判断其他实例上的构建已经结束。

如果支持运行时降低上限，已占用数量可能暂时高于新上限；此时停止接纳新任务，等待已有执行释放。是否支持动态修改应在实现中明确。
