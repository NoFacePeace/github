# ScanPending

ScanPending 是 Worker 单轮检查和领取待执行构建的入口，由构建领取定时任务周期调用。本文为 Infra 知识库的接口规划，具体签名与实现尚待确定。

## 1. 输入与输出

| 项目 | 内容 |
| --- | --- |
| 调用输入 | 本轮执行的取消与超时上下文 |
| 依赖状态 | 实例执行容量、支持的构建类型、任务存储及全局并发策略 |
| 输出 | 本轮领取结果或错误，包含无任务、容量不足和已启动等情况 |

单轮返回只表示领取检查结束，不表示已启动的构建全部完成。

## 2. 处理流程

```text
检查停止与取消状态
  → 检查实例空闲容量
  → 查询能够执行的候选构建
  → 按需申请全局执行额度
  → 原子领取并确认执行身份
  → 启动具体构建
  → 返回本轮结果
```

查询候选时需要明确范围、筛选条件与返回信息。候选列表不代表执行权，领取成功后才能启动。

## 3. 容量控制

实例额度由 [LocalSlots](LocalSlots.md) 管理，限制本 Worker 正在执行的数量；采用内存计数时，应同步保护计数与启动、退出之间的变化。

全局额度限制多实例合计并发，需由共享协调机制原子分配。具体采用何种机制应独立设计，不能仅通过查询正在运行的记录数保证不超限。

容量不足或没有候选时直接结束本轮，不启动无意义的构建。查询数量应与可用额度匹配，避免无界领取。

## 4. 领取与执行分离

单轮可以启动多个构建，但不需要等待每次执行结束再返回。每个执行应独立跟踪进度和终态，完成后释放实例及全局额度。

定时调用的上下文与已受理构建的生命周期需要分别定义，避免本轮查询结束时误取消仍应继续运行的构建。

## 5. 异常与资源释放

- 竞争领取失败：不启动该构建，释放已申请额度。
- 查询或协调失败：记录错误，按约定结束或继续本轮。
- 领取后启动失败：保存可恢复状态，并清理执行归属与资源。
- 构建完成、失败或取消：记录终态，释放占用，防止容量泄漏。
- 并发扫描及服务退出：需要明确同步规则，避免重复启动或遗漏等待中的执行。

本入口不直接实现源码分析、模型生成或图谱算法，它将确认领取的任务交给相应执行流程。
