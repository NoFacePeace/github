# 请求服务

请求服务（Server）负责接收客户端请求，调用应用能力并返回结果，与定时器或内部事件驱动的后台任务区分。本文为 Infra 知识库的设计规划，具体协议、框架、接口与部署方式尚待确定。

## 1. 职责

- 启动监听并管理请求入口的生命周期。
- 注册路由或协议处理器，将请求分派到对应操作。
- 执行身份验证、权限检查和输入校验。
- 调用应用逻辑，转换结果与错误并返回响应。
- 记录请求日志、耗时及必要的追踪信息。

数据库访问、文档生成和图谱算法由对应模块承担，请求服务负责接入和调用。

## 2. 对外能力

| 类别 | 请求示例 |
| --- | --- |
| 仓库与版本 | 登记仓库、更新配置、查询版本 |
| 构建任务 | 提交构建、查询进度、请求重试 |
| 文档 | 导入、浏览与检索 |
| 代码图谱 | 查询实体、关系和路径 |
| 源码 | 浏览固定版本文件、搜索代码 |

HTTP API 与 MCP 等接入方式可以复用应用逻辑，各自维护输入输出契约。上述为能力范围，具体开放操作需逐项确认。

## 3. 请求处理流程

```text
客户端请求
  → 协议接入与路由
  → 身份、权限及输入校验
  → 调用应用逻辑
  → 转换结果或错误
  → 返回响应
```

耗时构建采用异步受理时，请求返回任务身份与当前状态；客户端再查询进度。请求成功受理不等于构建或产物发布已经成功。

## 4. 与后台任务的关系

请求服务由外部请求触发，后台任务由定时器、队列或内部事件触发。两类入口可以共用业务逻辑和存储，例如都调用任务创建能力。

两者可以运行在同一个进程，也可以分开部署；角色划分不取决于是否使用 goroutine。取消客户端请求是否影响已受理的后台任务，需要明确约定。
