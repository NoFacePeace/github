# 向量检索

向量检索将用户问题转换为向量，在已发布文档的向量索引中寻找语义相近的文本块。它复用文档向量，只在查询阶段生成问题向量。

## 1. 输入与输出

- 输入：查询文本、仓库、固定版本、标签等过滤条件和候选数量限制。
- 输出：候选 Chunk 标识、所属章节标识及向量相关性分数。

## 2. 处理流程

```text
确定发布范围并检查模型配置兼容性
  → 调用 Embedding 模型生成问题向量
  → 加载对应文档向量与 HNSW 检索结构
  → 检查向量维度
  → 搜索近邻并应用范围过滤
  → 按向量相关性返回候选
  → 交给后续融合与章节聚合
```

索引数据的生成方式见 [向量索引构建](../build/documents/index/Vector.md)。问题向量与文档向量需要使用匹配的模型和维度，不能只因维度相同就假定兼容。

## 3. 查询示例

```text
问题：任务失败后如何恢复？
  → 问题向量
  → 搜索相近 Chunk
  → 可能召回“重试”“断点续跑”等用词不同但相关的内容
```

近邻图用于加速定位，不是将源码调用关系用于搜索。语义接近不证明事实正确，仍需保留文档版本、出处和适用条件。

## 4. 超时与降级

向量路径设置独立预算，并响应外层取消。允许的临时不可用或向量超时可以降级为仅全文检索，响应需要标记降级。

模型、维度不兼容或其他不可降级错误应返回失败。外层请求取消也不能解释为正常降级结果。
