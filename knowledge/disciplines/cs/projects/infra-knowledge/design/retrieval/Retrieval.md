# 查询与检索

查询与检索负责从已发布的文档及索引中查找相关内容。它属于发布后的使用阶段，与构建、索引生成和发布流程分别组织。

## 1. 输入与输出

- 输入：查询文本、仓库与版本范围、标签等过滤条件，以及结果数量限制。
- 输出：相关章节、命中文本块、来源信息和检索分数。

## 2. 处理流程

```text
接收并校验查询条件
  → 确定仓库、版本与已发布文档批次
  → 加载匹配的索引，缓存命中时复用
  → 全文召回：查询分词，使用倒排表与 BM25 排序
  → 向量召回：生成查询向量，搜索 HNSW 近邻
  → 融合两路候选结果
  → 按章节聚合，排序并限制返回数量
  → 返回正文、来源及命中证据
```

全文与向量召回使用同一发布范围。查询向量需要与索引的模型及维度兼容，不能混用不同生成配置的向量。

## 3. 模块职责

| 环节 | 职责 |
| --- | --- |
| 范围选择 | 将仓库、版本和过滤条件落实到已发布文档集合 |
| 索引加载 | 读取持久化产物，校验并恢复内存检索结构，管理缓存 |
| [全文检索](Fulltext.md) | 对查询分词，按词查找候选并使用 BM25 评分 |
| [向量检索](Vector.md) | 将查询转换为向量，执行近邻搜索 |
| [结果融合](Fusion.md) | 通过 RRF 合并两路排名，按章节聚合并限制数量 |
| 章节聚合 | 将 Chunk 命中映射到章节，整理完整正文及证据后返回 |

## 4. 存储依赖

- [Commit 存储](../mysql/Commit.md)：确定版本身份及对应已发布批次。
- [文档存储](../mysql/Document.md)：确定可查询文档范围，提供权威正文与来源信息。
- [索引产物存储](../mysql/IndexArtifact.md)：加载全文与向量索引，核对正文哈希和模型配置。

查询加载使用已经保存的索引，不重新对全部文档分词或生成文档向量。用户问题的向量在查询阶段生成。

## 5. 执行边界

查询不触发文档生成或发布。尚未发布的暂存文档与索引不进入默认查询结果，缓存身份需要与选定发布范围一致。

无匹配结果与索引损坏、依赖超时等失败需要区分。允许降级时明确记录原因和适用条件，不能把所有向量错误都静默当作仅全文查询。

检索分数表示匹配程度，不证明内容正确，也不替代来源、版本和适用条件的核查。
