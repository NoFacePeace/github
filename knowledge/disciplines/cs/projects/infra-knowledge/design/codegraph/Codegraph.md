# 图谱查询

图谱查询从已发布的图谱产物中查找代码实体、关系及路径。数据库用于定位和保存版本化图谱，具体查询在加载、解码后的内存图上执行。

## 1. 输入与输出

- 输入：仓库、可选 Commit 或分支选择、查询操作及其参数。
- 输出：解析后的版本、节点、边、路径或统计，以及适用的来源位置、歧义提示和截断信息。

不同操作分别约定方向、关系过滤、深度、数量和输出容量，不能将一种操作的限制直接套用于其他操作。

## 2. 加载与执行流程

```text
接收图谱查询请求
  → 校验仓库、版本选择和操作参数
  → 确定对应的已发布图谱版本
  → 检查内存缓存
      → 命中：使用已加载图结构
      → 未命中：读取 JSON 或内容引用 → 解码并建立内存查询结构 → 缓存
  → 匹配目标节点或搜索候选
  → 执行关系查询或图遍历
  → 整理来源、排序及适用的限制信息
  → 返回查询结果
```

内存查询结构包括节点映射、邻接表及适用的搜索索引。无需对每条边发出 SQL 查询，也不需要在查询时重新运行图谱提取工具。

## 3. 对外能力

| 操作 | 主要职责 |
| --- | --- |
| 节点搜索与详情 | 根据名称、路径等条件定位代码实体，读取属性与来源 |
| 邻居查询 | 读取直接连接的节点与边，标明方向并按关系过滤 |
| 多跳遍历 | 按方向、深度和关系约束扩展节点集合 |
| 路径查询 | 在两个实体之间寻找连接路径 |
| 影响范围 | 沿图关系展开潜在关联对象 |
| 实体解释 | 汇总目标节点及周边结构信息 |
| 社区查询 | 查看所属关联群组及其成员 |
| 高连接节点与统计 | 查看结构枢纽及图谱规模 |

这些操作共用同一版本的图谱，但节点匹配、遍历算法及返回契约不同。

## 4. 邻居查询示例

假设图中有 `CreateOrder → SaveOrder → Database`。定位 `SaveOrder` 后，从双向邻接表读取直接关系：

```text
CreateOrder  ← 入边来源，表示其关联指向 SaveOrder
Database     → 出边目标，表示 SaveOrder 关联指向它
```

返回结果携带相邻节点、方向、关系类型，以及可用的源码位置和置信信息。查“谁调用它”时，需要同时判断入边方向和调用关系，不能把所有邻居都当成调用者。

名称可能对应多个源码位置，应按操作契约报告歧义或提供候选；不能无条件将同名实体视为同一节点。

## 5. 路径查询示例

```text
HTTPHandler → CreateOrder → SaveOrder → Database
```

路径查询先解析起点与终点，再使用 BFS（广度优先搜索）在邻接表中寻找连接。按有向或无向选项决定使用哪些连接，并对结果执行最大跳数检查。

无向路径表示结构连接，不代表请求实际按该方向执行；沿不同关系类型连接起来的路径也不能直接解释为完整调用链。

## 6. 职责与边界

图谱查询属于产物使用阶段，与图谱构建分别组织。查询读取已发布产物，不重新生成图谱，不调用文档生成 Agent。

影响范围、社区与高连接节点是基于静态图的结构分析，不证明运行时调用必然发生或修改一定导致故障。缺失关系也可能来自筛选范围、语言支持及提取能力限制。

缓存身份应包含固定版本及适用的发布信息，避免混用不同图谱。图谱未发布、节点未找到、名称歧义和加载失败需要分别表达。
