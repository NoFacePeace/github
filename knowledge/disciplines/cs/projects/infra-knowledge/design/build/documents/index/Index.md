# 索引构建

索引构建将已暂存的完整 Markdown 转换成用于检索的派生数据。全文与向量两条路径共用同一批文本块，整个文档批次的索引就绪后再进入发布。

## 1. 共用准备

```text
读取并校验文档正文
  → 按 Markdown 标题层级组织 Chapter
  → 将过大的 Chapter 按容量切成 Chunk
  → 分别构建全文和向量索引
  → 校验并保存产物
```

章节组织尽量保留完整父子结构；容量不足时保留较小章节，并尝试合并相邻同级小章节。过大的完整章节在切块阶段采用固定 Token 窗口，块之间不重叠，不保证按句子或代码围栏边界切分。

章节容量与 Chunk 容量分别配置。这里的 Token 由应用的分词规则定义，不能直接等同于模型 tokenizer 的 Token。

## 2. 索引类型

- [全文索引](Fulltext.md)：分词、词频统计、倒排表和 BM25 排序所需统计。
- [向量索引](Vector.md)：Embedding 向量及用于近邻搜索的 HNSW 图。

## 3. 保存与发布

保存方式见 [索引产物存储](../../../mysql/IndexArtifact.md)。一篇文档分别保存全文和向量两种索引产物，每种产物内部可以包含多个 Chunk，不是每个 Chunk 单独一条产物记录。

索引关联原始文档身份、正文哈希和固定配置。恢复执行可以校验并复用已有完整产物；不兼容或不完整的索引不能当作成功结果。

本阶段完成索引准备，后续进入[发布](../Publication.md)，由外层协调批次就绪检查与可见版本切换。
