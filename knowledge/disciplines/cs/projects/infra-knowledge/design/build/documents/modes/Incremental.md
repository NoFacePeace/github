# 增量

增量模式结合当前安全源码、基线源码、已有文档和版本差异，更新各主题文档。请求值为 `incremental`；显式请求后找不到合格基线应返回错误。

## 1. 基线资格

基线需要满足以下条件：

- 属于当前仓库的已发布完整文档批次，具有有效批次标识。
- 对应 Commit 是目标 Commit 的祖先，且与目标版本不同。
- 生成契约与当前兼容。
- 系统设计、API、指标和配置等基础文档齐全。
- 启用模块文档时，还需要可用的模块计划。

是否能够增量不按改动文件数量或变化比例判断。

## 2. 输入

- 当前版本的完整安全源码快照与文件清单。
- 固定基线版本的安全源码。
- 当前主题的基线文档及基线文档目录。
- 版本差异、文件变更清单及固定的前后版本身份。

**增量模式提供当前版本的完整安全源码快照，不是只提供修改文件或差异片段。** 这里的完整指经过既定筛选与脱敏后纳入快照的全部文件，不是未经处理的整个仓库。

Agent 通常从差异入手，再按需读取当前源码、调用方、共用类型、配置或基线源码，确认变化的影响。提供完整源码不要求逐文件全部阅读，也不意味着一次性将全部正文放入模型上下文；未修改文件仍可能因调用关系、配置或依赖变化而需要重新调查。

## 3. 处理流程

```text
查找并校验候选基线
  → 固定实际模式与基线身份
  → 读取基线文档，准备基线安全源码
  → 检查前后源码策略兼容并固定源码指纹
  → 准备当前源码、旧文档、差异与任务参数
  → Agent 执行 Skill 的增量分支，按需查询基线源码
  → 输出完整新版文档
  → 校验后交给索引与发布流程
```

增量最终交付完整新版文档，不仅交付修改片段。Agent 使用已指定的基线，不能自行切换版本或获取未准备的历史源码。

## 4. 失败与恢复

显式请求增量但无合格基线时返回错误；已经开始增量后失败，不自动改为全量重跑。恢复执行需要校验目标版本、模式、生成契约和已固定基线一致，避免输入在重试期间变化。
