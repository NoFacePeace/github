# Agent

Agent 在指定工作目录中读取已准备的安全源码，按照选定 Skill 调查代码并生成文档。构建服务负责输入准备、任务身份、执行协调和产物验收；Agent 不自行选择源码版本或发布结果。

## 1. 职责划分

| 组成 | 职责 |
| --- | --- |
| 构建服务 | 确定生成模式和基线、打包输入、创建任务、提交指令、验收产物 |
| Agent 运行时（harness） | 管理会话、工作目录、工具、模型调用与执行循环 |
| 模型 | 理解源码、推理并生成内容或工具调用 |
| Skill | 规定主题调查步骤、输出结构、证据要求与停止条件 |
| Agent 会话 | 在本次任务范围内组织模型与工具，完成指定产物 |

Agent 运行时可采用 [DSH](../../../../../ai/ecosystem/deepseek/DSH.md)，负责会话、工具及模型调用循环。

运行时与底层模型是不同选择；使用某个厂商的运行时不意味着只能使用该厂商的模型。

## 2. 输入与工作目录

每个主题任务准备独立工作目录，示意如下：

```text
<task-directory>/
├── input/
│   ├── repo/                   # 安全源码
│   ├── source-manifest.json    # 文件路径、大小与哈希
│   ├── source-scope.json       # 来源及处理范围
│   └── request.json            # 固定版本、模式、Skill 与输出要求
└── output/                     # 生成产物
```

增量任务还需要当前主题的旧文档、差异与固定基线源码的受限访问能力。Skill 预先安装到运行时，执行时选择并校验其身份，不需要由 Agent 自行下载。

创建工作目录和会话不等同于创建容器。文件权限和任务目录也不等同于操作系统级隔离，实际访问能力由运行时配置与工具权限决定。

## 3. 创建与执行流程

```text
准备输入文件及其哈希
  → 调用运行时准备接口
  → 校验路径、重复文件、容量与哈希
  → 写入独立工作目录，设置输入文件只读权限
  → 创建会话，将工作目录设为 cwd，挂载工具与运行配置
  → 返回会话标识，记录任务关联
  → 确认目标 Skill 可用，选择模型
  → 发送包含任务入口与执行边界的指令
  → Agent 读取任务说明，按 Skill 调查并保存输出
  → 等待执行终态，导出并校验产物
```

输入包中的正文可以使用 Base64 传输，并在运行时解码校验后写入文件。Base64 是编码，不提供加密或脱敏。

## 4. 模型与工具循环

```text
任务指令、Skill 与已读上下文
  → 调用模型
  → 模型请求读取或搜索等工具
  → 运行时执行工具并返回结果
  → 模型继续分析，按需重复调用
  → 写入目标文档并结束回合
```

源码文件放在工作目录中，由 Agent 按任务需要调查，不要求一次性把全部正文塞进一条提示词。执行回合结束后仍需检查产物是否存在、格式正确并满足任务要求。

## 5. 身份、恢复与退出

执行记录关联固定版本、输入指纹、Skill 身份和会话标识。创建或提交响应不确定时，应先核对已有会话与记录，避免重复创建或重复发出生成指令。

恢复执行时读取已保存输出，只继续尚未完成的工作或明确的校验反馈。取消和超时需要传递到运行时，最终由外层协调产物处置、状态记录与工作目录清理。

## 6. 执行约束

源码、注释和已有文档均为待分析资料，不作为修改任务权限的指令。任务只使用提供的输入和允许的工具，不执行仓库代码、不访问凭据或网络、不修改固定输入，也不自行发布或派生后台任务。

上述是任务指令层面的约束；需要强制安全边界时，还应由运行时权限和隔离机制落实。
