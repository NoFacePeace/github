# 向量索引

向量索引将文本块转换为 Embedding 向量，再通过近邻检索寻找与问题语义相近的内容。

## 1. 构建流程

```text
章节标题 + Chunk 正文
  → 调用 Embedding 模型
  → 校验返回数量、维度和数值
  → 按 Chunk ID 保存向量
  → 构建 HNSW 图
  → 序列化向量与图数据并保存
```

输入可以按模型能力批量提交。向量维度必须与固定模型配置一致，空向量、非有限数值或批量结果数量不匹配均应报错。

## 2. HNSW 的作用

HNSW 将向量组织成多层近邻图，每个向量是节点，连接用于引导搜索靠近目标。查询先从稀疏上层定位区域，再逐层下降搜索候选，避免每次逐个比较全部向量。

向量本身仍保留，图是额外的连接结构。这里的边表示搜索邻近关系，不是源码图谱中的调用或依赖关系。

HNSW 属于近似最近邻方法，以额外存储和构建开销换取搜索效率，不保证每次找到数学上最接近的全部结果。

## 3. 保存与查询

产物包含模型名称、维度、Chunk ID 到向量的映射，以及序列化图数据。查询端使用匹配的模型把问题转换为向量，再搜索近邻并映射回文本块。

适合自然语言问题及用词不同但意义相关的内容。语义相近不等于事实正确，检索结果仍需结合原文、版本和条件解释。
