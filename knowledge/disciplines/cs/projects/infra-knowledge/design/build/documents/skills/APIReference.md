# API 参考 Skill

API 参考 Skill 调查对外接口的注册与处理逻辑，生成供调用方查阅的接口文档。

## 1. 调查重点

- 路由注册、请求方法与路径。
- 显式请求与响应类型，以及解释入口所必需的参数条件。
- 可直接确认的鉴权、代理行为及注册条件。
- 协议、版本、挂载路径和简短用途。

## 2. 输入与输出

输入为当前安全源码、任务说明及清单；增量时补充旧文档与基线差异。输出为完整接口参考，例如 `api/api-reference.md`。

## 3. 证据要求

结合路由、处理函数、数据结构与校验代码确认接口契约。不能只根据函数名推断接口存在，也不能为缺失实现编造响应示例。

## 4. 具体调查步骤

1. 从启动入口发现实际路由、嵌套挂载、RPC、工具注册和代理入口。
2. 累积父级路径前缀，解析注册条件，区分不同版本与挂载位置。
3. 按路由组分批处理，确认方法、完整路径、显式请求响应类型、处理函数和简短用途。
4. 共用中间件调查一次，保留每个入口特有的鉴权、代理与启用条件。
5. 对照注册结果检查遗漏、重复与未解析动态路径，再保存完整目录。

## 5. 输出内容与边界

输出以接口目录表为主，可使用以下列：

| 协议 | 方法 | 完整路径或 RPC 名称 | 请求类型 | 响应类型 | 处理函数 | 简要定义 |
| --- | --- | --- | --- | --- | --- | --- |
| HTTP | POST | `/items` | `CreateItemRequest` | `ItemResponse` | `CreateItem` | 创建条目；仅为格式示例 |

请求与响应列记录代码明确声明的类型名，不展开 DTO 字段、全部参数和错误分支。不为了补齐表格深入重建所有下游业务逻辑；关键成功、重试和部分失败语义由系统设计说明。

仅收录实际注册的入口，排除出站客户端、测试与示例。无法确认的类型标为未知，未解决的动态路由写入限制，不虚构通配接口。

## 6. 保存与完成条件

按组保存，保持目录表连续、每行列数一致，单元格内的竖线需要转义。确认入口身份、显式类型、用途和必要注册条件后停止继续追踪该接口，最终做一次覆盖检查。
