# 模块设计 Skill

模块设计阶段根据已确定的模块任务调查源码，生成指定模块的设计页面。它属于可选模块文档能力。

## 1. 输入

- 当前安全源码及清单。
- 模块任务的标识、范围与输出要求。
- 适用的旧模块文档与增量上下文。

## 2. 调查重点

模块职责、主要结构、对外接口、内部执行链路、状态与数据依赖，以及失败和取消处理。

## 3. 输出与验收

输出指定模块的完整 Markdown 页面。内容与引用应落在任务定义的职责范围内；跨模块关系需要源码证据。

模块计划和页面必须分别验收，不能将成功生成计划当作页面已经完成。

## 4. 具体调查步骤

1. 读取模块任务，确认稳定标识、职责范围、输出位置与固定源码版本。
2. 从模块入口追踪装配、依赖与状态归属，按完整机制保存调查结果。
3. 分析正常路径、完成条件、顺序和并发约束，以及超时、取消和部分失败。
4. 解释恢复、资源放大、配置与观测信号，区分支持的机制和未确认的运行事实。
5. 增量时结合旧页和差异更新事实、引用及缺口，对模块职责做一次覆盖检查。

## 5. 页面内容

建议按以下顺序组织：

1. 职责与边界：稳定标识、归属、排除范围、状态和故障边界。
2. 入口、装配与源码地图：注册、启动及生命周期。
3. 依赖与交互契约：成功、失败、部分副作用、取消与重试。
4. 核心行为、状态与正确性：正常链路、不变量、排序和完成语义。
5. 故障、恢复与竞争解释：可能原因、传播、区分证据及反证。
6. 资源、配置与可观测性：资源需求、控制参数、生效条件、风险和验证。
7. 覆盖范围与知识缺口：缺失源码、外部假设和所需运行证据。

## 6. 输出与完成条件

生成指定模块的完整页面，由外层根据稳定标识安排最终路径和模块索引。模块任务不另建一套索引，也不自行重命名模块。

跨模块共用机制由系统设计统一解释，模块页保留理解自身行为所必需的上下文，不复制完整接口、指标与配置目录。旧文档是更新起点，不是当前源码事实的证据。
