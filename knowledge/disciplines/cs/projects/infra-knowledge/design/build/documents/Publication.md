# 发布

发布将已暂存并完成索引的文档批次切换为对应源码版本的可查询产物。文档正文和索引在此前已经保存，本阶段主要通过数据库事务更新批次关联与状态。

## 1. 发布前提

- 本批次完整文档已保存，内容与清单一致。
- 每篇文档需要的全文及向量索引均已就绪。
- 正文哈希、索引配置与固定批次匹配。
- 当前构建仍持有有效执行身份与租约，允许提交结果。

不满足条件时返回错误，不将部分完成的产物作为完整批次发布。

## 2. 处理流程

```text
索引产物就绪
  → 开启事务并锁定相关归属记录
  → 校验执行身份、批次和索引完整性
  → 更新对应版本的已发布批次关联
  → 更新新批次状态及发布时间
  → 标记被替代产物与适用的旧批次状态
  → 记录构建成功状态
  → 提交事务
```

事务保证数据库中的发布关联与状态一致。构建已经失去归属时，旧执行者不能覆盖新执行者的发布结果。

## 3. 涉及的存储

- [文档存储](../../mysql/Document.md)：保存正文与归属，发布时处理产物可见性及被替代记录。
- [文档生成批次](../../mysql/GenerationBatch.md)：保存发布状态、时间和恢复检查点。
- [索引产物存储](../../mysql/IndexArtifact.md)：提供发布前的完整性与配置校验依据。
- [Commit 存储](../../mysql/Commit.md)：将对应源码版本关联到已发布批次。
- [Build 存储](../../mysql/Build.md)：校验执行归属并记录构建终态。

## 4. 查询可见性

查询端根据仓库、版本与已发布批次选择文档及匹配索引。索引存在或文档暂存成功，不代表该批次已经成为查询入口。

发布切换的是对应版本的文档批次，不等同于部署应用程序，也不表示改变其他源码版本的身份。查询端缓存仍需遵循发布身份，不能混用新旧批次。

## 5. 完成与退出

发布事务提交后返回结果，外层执行流程停止心跳并释放额度、连接和工作区等资源。资源清理与数据库发布是不同阶段，不能因清理失败就假定发布没有发生。

提交响应不确定时应读取持久化状态确认结果，避免无条件重复生成或覆盖已经发布的产物。
