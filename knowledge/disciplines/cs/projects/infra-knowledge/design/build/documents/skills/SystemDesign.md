# 系统设计 Skill

系统设计 Skill 从安全源码中梳理系统用途、架构组成、关键组件及主要执行链路，生成系统设计文档。

## 1. 调查重点

- 程序入口、启动过程和依赖装配。
- 核心组件的职责、边界及调用关系。
- 关键业务链路、状态变化与数据流。
- 外部依赖、持久化、后台任务及失败处理。

## 2. 输入与输出

输入为当前安全源码、任务说明及清单；增量时补充旧文档与基线差异。输出为完整系统设计页面，例如 `design/system-design.md`。

## 3. 证据要求

通过入口与调用链确认实际行为，区分源码事实、推断和未确认内容。引用文件与行号，不将目录名直接等同于运行架构。

## 4. 具体调查步骤

1. 从启动装配、已注册入口、后台任务和状态存储建立初始组件与流程图。
2. 每次沿一条完整链路调查触发条件、参与组件、状态变化和真正的完成条件。
3. 继续追踪超时、取消、重试、部分失败及恢复路径，说明副作用和并发边界。
4. 将资源竞争、配置生效与观测信号放回相关机制，解释相似症状可能对应哪些原因，以及如何区分。
5. 对照已发现的入口和组件检查一次覆盖范围，记录缺失证据，完成文档。

## 5. 输出内容

建议依次组织：仓库摘要、阅读指南、范围与边界、架构与运行拓扑、核心流程与机制、状态与正确性、资源与容量、共用运行控制、可观测性、覆盖范围与知识缺口。

核心流程要同时说明正常行为、分支、失败传播、恢复条件和证据。例如任务服务应解释“提交成功”“领取成功”“执行结束”“结果可见”是否属于不同阶段。

接口、指标与配置仅保留解释机制必需的内容；完整目录由对应主题负责。源码事实、设计陈述、测试代码、运行观测和推断应明确区分，不能把静态分析写成已经完成运行验证。

## 6. 保存与完成条件

尽早保存骨架，按完整流程或共用机制分批保存；恢复执行时读取已有输出，继续尚未完成的部分。覆盖关键入口、执行链路及实质知识缺口后结束，文档长度不是质量目标。
