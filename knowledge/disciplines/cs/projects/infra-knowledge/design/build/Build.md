# 构建执行

构建执行负责处理 Worker 已成功领取的任务，组织源码准备、构建组件调用、结果记录与资源释放。本文为 Infra 知识库的设计规划，具体函数及执行顺序尚待确定。

## 1. 输入与输出

| 项目 | 内容 |
| --- | --- |
| 输入 | 已领取任务、固定源码版本、执行令牌、配置与取消上下文 |
| 执行依赖 | 文档或图谱构建组件、任务存储、执行额度的释放能力 |
| 输出 | 执行终态、错误与进度记录，以及生成或发布的产物关联 |

启动执行前应确认任务仍归当前执行者。产物状态与执行状态需要分别记录，不能只以启动成功判断构建完成。

## 2. 处理流程

```text
接收已领取的构建
  → 启动执行流程
  → 创建可取消的执行上下文
  → 启动租约心跳
  → 调用对应构建组件，由组件内部准备固定版本源码
  → 验收产物并完成约定的索引、发布步骤
  → 记录执行结果
  → 停止心跳并释放执行资源
```

文档与图谱目标是否串行、并行或独立执行，由依赖和工作区隔离要求决定。编排层负责组织调用，具体分析与生成算法由构建组件承担。

- [文档构建](documents/Documents.md)：安全快照读取、Skills 文档生成、校验与检索准备。
- [图谱构建](codegraph/Codegraph.md)：代码实体及关系提取、图谱校验与交付。

## 3. 完成判定

本地执行流程等待构建组件返回结果。组件如果调用外部进程或远程运行时，需要等待终态并验证交付物，或显式进入后续完成确认阶段。

```text
领取检查返回：本轮扫描结束
构建调用返回：对应执行步骤结束
产物校验与发布完成：达到约定的构建成功条件
```

后台执行不意味着无人等待结果；执行 goroutine 仍负责接收返回值、记录终态和清理资源。

## 4. 心跳与取消

续约、取消与退出协调见 [心跳](Heartbeat.md)。

心跳续约与构建执行可以共享可取消的执行上下文：续约失败时请求取消构建，执行结束时停止心跳并等待其退出。

取消是协作信号，构建组件及其外部调用需要响应。超时、失去执行权或取消后，不应继续以过期身份写入状态或发布结果。

## 5. 结果与资源释放

- 正常完成：确认产物与发布条件，保存成功结果。
- 执行失败：保留错误和必要诊断，按约定保留可恢复产物。
- 失去租约：停止推进，不能覆盖新执行者的结果。
- 所有退出路径：释放不再使用的工作区、连接和执行额度，避免重复释放或泄漏。

任务归属清理需校验当前令牌；本地与全局额度应由其持有者释放。清理失败应有独立诊断，不能假设异常退出已经完成全部回收。
