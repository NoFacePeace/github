# 检查

图谱检查在生成后确认输入与产物的一致性，解码图结构并准备统计信息。通过检查后，外层才能组织图谱保存与发布。

## 1. 输入与输出

- 输入：本次图谱 JSON、安全源码执行目录、快照清单与来源信息，以及任务绑定的仓库和版本身份。
- 输出：经过检查并补充来源信息的 JSON、解码后的图结构及节点数、社区数等统计；检查失败返回错误。

## 2. 检查流程

```text
确认生成后的源码目录仍符合快照清单
  → 校验图谱引用与所提供快照的对应关系
  → 为产物记录处理策略和快照身份
  → 核对仓库、项目与 Commit 是否匹配领取的任务
  → 解码 JSON 为图结构
  → 统计节点与社区等信息
  → 交给持久化与发布流程
```

实际检查顺序可以分布在源码适配、解码和应用服务中，不要求全部集中在一个函数。

## 3. 解码的作用

JSON 字节需要转换为程序可以操作的节点、边和属性，才能计算统计并确认产物符合解码契约。格式错误或契约不兼容时，不应直接发布。

解码不等于重新生成图谱，不会自动修正错误的调用关系，也不表示已证明所有边的业务语义。数据库仍可保存完整 JSON，无需因此拆成节点表与边表。

## 4. 发布前检查

持久化时还需要校验当前执行身份与租约，防止失效执行者覆盖新的结果。这是任务归属检查，与 JSON 格式检查分别承担不同职责。

检查通过后的图谱正文、来源版本、统计与发布时间组成发布数据。正文可以直接保存，也可以通过不可变对象存储引用保存。

## 5. 能力边界

源码范围、脱敏及提取工具能力都会影响图谱覆盖度。可解码、引用一致与统计正常，只说明产物满足这些检查条件，不证明关系完备或等同于运行时事实。
