# 图谱构建

图谱构建从固定版本源码提取代码实体与关系，组织可供查询的图谱产物。本文为 Infra 知识库的设计规划，不限定提取工具或存储方式。

## 1. 输入与输出

- 输入：固定版本的安全源码快照、提取范围与规则、执行身份和取消上下文。
- 输出：实体、关系、源码位置组成的图谱产物及分析诊断。

## 2. 处理流程

```text
调用源码准备，获取固定版本的安全快照
  → 检查源码版本、快照完整性与配置
  → 提取代码实体与关系
  → 规范化标识及来源位置
  → 检查节点、边和引用完整性
  → 准备查询所需表示
  → 交付图谱产物及结果
```

共用输入能力见 [源码准备](../source/Source.md)，负责缓存检查、源码获取、筛选、脱敏及快照交付。

关系类型与可信程度需要明确定义。无法确认的静态关系不能自动当作已证明的运行时调用链。

## 3. 构建环节

- [生成](Generation.md)：调用提取工具，从安全源码产生本次执行的图谱 JSON。
- [检查](Validation.md)：校验快照与产物来源，解码图结构并整理统计信息。

生成和检查通过后，还需保存并发布图谱，才能作为查询可用的产物。

## 4. 执行边界

图谱组件响应取消并返回结果，外层管理任务归属和心跳。使用外部工具时，需要等待其终态并验证产物，不能只以进程启动成功判断构建完成。

图谱与文档可以关联同一源码版本，但各自产物与执行结果分别记录。是否共享源码工作区、执行顺序及是否相互依赖，需要在编排方案中明确。
