# 筛选

筛选决定固定版本中的哪些文件可以进入文档与图谱构建。先根据文件树中的路径和类型判断，再读取选中文件的内容，检查大小、编码和测试框架特征。

## 1. 输入与输出

- 输入：固定版本的文件条目、内置默认排除规则、自定义追加排除规则和保留例外。
- 输出：通过筛选的文件及其内容，交给后续脱敏处理；未通过的条目记录跳过原因。

## 2. 处理流程

```text
文件条目
  → 校验路径
  → 检查类型，跳过符号链接和子模块
  → 匹配保留例外与排除规则
  → 获取选中文件内容
  → 检查大小、编码与测试框架特征
  → 交给后续脱敏与写入流程
```

```go
for _, 文件 := range 文件清单 {
    if 路径不安全(文件.Path) {
        return 错误
    }
    if 是符号链接(文件) || 是子模块(文件) {
        记录跳过(文件, "特殊类型")
        continue
    }
    if !是支持的普通文件(文件) {
        return 错误
    }

    例外保留 := 匹配任意规则(文件.Path, 保留例外)
    if !例外保留 && 匹配任意规则(文件.Path, 排除规则) {
        记录跳过(文件, "路径排除")
        continue
    }

    // 能从元信息判断大小时，提前跳过；读取时也限制大小。
    内容, 超限 := 限量读取内容(文件)
    if 超限 {
        记录跳过(文件, "文件过大")
        continue
    }
    if 非UTF8(内容) || 包含NUL字节(内容) {
        记录跳过(文件, "非文本内容")
        continue
    }
    if !例外保留 && 命中测试框架特征(文件.Path, 内容) {
        记录跳过(文件, "测试框架特征")
        continue
    }

    交给后续处理(文件.Path, 内容)
}
```

以上为简化伪代码，实际读取还需要处理访问错误、取消信号和总输入容量限制。

## 3. 筛选规则

内置规则覆盖常见依赖目录、构建产物和测试文件命名。自定义排除规则追加到内置规则中，保留例外用于纠正路径分类。

例如，排除规则为 `vendor` 和 `*_test.go`，保留例外为 `vendor/example.go`：

| 文件路径 | 路径筛选结果 |
| --- | --- |
| `src/main.go` | 允许读取内容，继续检查 |
| `src/main_test.go` | 跳过 |
| `vendor/lib.go` | 跳过 |
| `vendor/example.go` | 例外保留，读取内容继续检查 |

不带 `/` 的模式匹配任意深度的路径段；带 `/` 的模式按完整相对路径匹配，`**` 可以跨越零个或多个路径层级。

保留例外可以覆盖路径排除和测试框架特征筛选，不能绕过路径安全、文件类型、大小与编码检查，也不能绕过后续脱敏。

## 4. 特殊文件类型

- 符号链接：保存目标路径的特殊文件，Git 模式为 `120000`。不跟随链接读取目标内容，避免引入快照目录之外的文件。
- 子模块：主仓库记录另一个仓库的指定 Commit，Git 模式为 `160000`。其源码需要额外获取，不在当前文件筛选流程中递归展开。
- 普通文件：Git 模式为 `100644`；可执行文件为 `100755`，通过其他检查后可继续处理。

## 5. 各项过滤检查

按执行顺序分别说明：

1. [路径校验](PathSafety.md)：检查相对路径、规范化形式和保留路径段。
2. [文件类型](FileType.md)：根据 Git 模式处理普通文件、符号链接和子模块。
3. [路径规则](PathRules.md)：匹配内置与自定义排除规则、保留例外。
4. [文件大小](FileSize.md)：限制单文件字节数，并说明总输入预算。
5. [文本编码](TextEncoding.md)：检查 UTF-8 有效性与 NUL 字节。
6. [测试内容](TestContent.md)：通过正文特征补充测试文件筛选。

文件大小在获取方式允许时提前检查；读取内容后继续进行其余内容检查。

## 6. 后续处理

全部筛选检查通过后，进入[脱敏](../Sanitization.md)，检测并替换敏感内容，复检通过后再交给安全快照写入流程。
