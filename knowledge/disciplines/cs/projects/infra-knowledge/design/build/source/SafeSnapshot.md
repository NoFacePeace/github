# 安全快照

安全快照保存固定源码版本经过筛选和脱敏后的文件，以及用于验证输入范围、来源与完整性的元信息。文档构建和图谱构建消费快照，不直接使用未经处理的原始源码目录。

## 1. 快照内容

| 内容 | 作用 |
| --- | --- |
| 处理后的文件 | 保留仓库相对路径，提供分析和生成所需正文 |
| 文件清单 | 记录路径、文件模式、处理状态、大小与内容哈希 |
| 来源信息 | 标识原始仓库、Commit 与处理策略 |
| 快照指纹 | 校验来源、策略及文件清单的一致性 |

跳过的文件可以在清单中保留处理状态，但不写入对应正文。文件哈希根据处理后的内容计算。

## 2. 生成流程

```text
单个文件脱敏并复检通过
  → 按仓库相对路径写入快照目录
  → 对其他文件重复筛选、脱敏和写入
  → 汇总文件清单，计算大小与内容哈希
  → 生成快照指纹并校验
  → 完成缓存登记，供后续执行复用
```

快照需要完整生成并通过校验后才能作为可复用输入。中途失败不能将未完成的目录当作成功快照交付。

## 3. 缓存与执行副本

缓存身份包含仓库、固定版本和处理策略等信息。处理策略变化后，应重新准备对应快照，避免复用旧策略处理的内容。

缓存命中时先校验完整性；每次构建从快照创建独立执行副本，避免构建修改共享缓存。副本中的来源信息仍指向原始 Commit。

## 4. 交付与读取

交付给构建组件的是独立执行目录的路径。目录内包含处理后的文件、清单和来源信息，消费端据此验证版本、策略、文件大小与哈希，再读取正文。

```text
安全快照缓存
  → 创建独立执行副本
  → 交付目录路径
  → 校验来源与清单
  → 按清单读取并校验文件
  → 文档或图谱构建
```

## 5. 能力边界

“安全”表示输入经过既定筛选与脱敏规则处理，不保证所有秘密都能被发现。内容哈希用于发现文件与清单不一致，不等同于来源签名或身份认证。

快照保留的是处理后的源码视图；脱敏替换可能改变语法与列位置，不能将其直接视为可运行的原始仓库副本。
