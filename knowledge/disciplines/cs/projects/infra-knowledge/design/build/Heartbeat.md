# 心跳

心跳在构建执行期间续约任务执行权，并在失去执行权时通知构建停止。本文为 Infra 知识库的候选设计，具体续约接口、周期与有效期尚待确定。

## 1. 启动位置

领取成功后，由执行编排层创建构建上下文并启动心跳。具体文档或图谱组件接收该上下文，不必重复管理同一份租约。

若多个构建项共用一次执行归属，可以共用心跳；若分别领取和独立执行，应分别管理各自归属。具体执行粒度需明确。

## 2. 续约流程

```text
等待心跳周期
  → 检查构建是否已取消
  → 使用本次执行令牌请求续约
  → 校验执行身份、租约及状态
      ├── 成功：延长有效期，等待下一轮
      └── 失败：请求取消构建并退出
```

续约应使用有超时的存储调用。时间基准、续约周期和租约长度需要统一设计，给正常延迟留出余量；不能无限续约已经失效或被替代的执行。

## 3. 共享取消上下文

心跳与实际构建可共享同一个可取消上下文：续约失败时取消执行，构建完成时取消心跳并等待其退出。

取消只是协作信号，源码获取、模型请求和外部进程等操作需要响应。已失去执行权的调用方还应受到状态写入与发布校验的限制。

## 4. 停止与清理

```text
构建结束或取消
  → 通知心跳停止
  → 等待心跳退出
  → 按执行身份清理归属
```

构建上下文已经取消时，清理可使用独立且有超时的上下文。心跳负责任务续约，与全局槽位的持锁连接检测是不同机制。
