# Build 存储

Build 记录表示针对指定源码版本和构建目标的一次执行尝试，用于追踪等待、执行和结束状态。本文为 Infra 知识库的概念设计，具体表名、字段类型及 SQL 尚待确定。

## 1. 职责

保存执行身份、状态、进度摘要和结果。Build 是一次性构建记录，不是调度器中持续运行的定时任务。

## 2. 逻辑字段

| 信息 | 用途 |
| --- | --- |
| 构建尝试 ID | 标识一次执行 |
| 关联版本 ID | 定位固定源码版本 |
| 构建目标 | 区分文档、图谱等产物类型 |
| 尝试标识 | 区分同一版本和目标的历次执行 |
| 执行状态 | 表示待执行、执行中、成功或失败等阶段 |
| 配置快照或配置版本 | 记录实际采用的生成策略与兼容条件 |
| 执行归属信息 | 支持领取、并发协调与异常恢复 |
| 起止时间和错误摘要 | 支持进度展示及失败诊断 |
| 产物关联 | 追溯该次执行生成的内容 |

详细日志适合独立保存，并关联构建尝试身份，避免将全部事件不断追加到主记录中。

## 3. 记录关系

```text
同一源码版本
  ├── 文档构建：第一次尝试
  ├── 文档构建：失败后的新尝试
  └── 图谱构建：第一次尝试
```

一次尝试只对应明确的版本和目标。版本、目标及尝试标识应能够唯一定位执行记录，重试不覆盖旧尝试。

## 4. 状态变化

```text
待执行 → 执行中 → 成功
               └→ 失败
```

取消、失效接管及失败重试的状态规则需另行明确。执行归属和状态更新应具备并发保护，防止旧执行者覆盖新尝试的结果。

## 5. 创建与发布边界

版本发现或手动请求通过任务创建能力登记 Build，再由 Worker 领取执行。普通重复请求应按有效任务去重；显式重新生成可以按约定创建新尝试。

构建状态与产物发布状态分别管理。生成成功、索引完成和对外发布不是同一时刻，失败尝试的临时产物不应自动成为可见内容。
