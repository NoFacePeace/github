# Commit 存储

Commit 记录表示知识库已登记的某个仓库版本，供文档和图谱等构建关联精确源码。本文为 Infra 知识库的概念设计，具体表名、字段类型及 SQL 尚待确定。

## 1. 职责

保存版本身份、完整 Commit SHA 和提交信息。它记录知识库选择处理的版本，不要求复制 Git 仓库的完整提交历史。

## 2. 逻辑字段

| 信息 | 用途 |
| --- | --- |
| 版本记录 ID | 作为构建与产物关联的稳定标识 |
| 所属仓库 ID | 确定版本归属 |
| 完整 Commit SHA | 固定本次处理的源码内容 |
| 提交标题、说明及时间 | 支持版本展示和历史查询 |
| 版本来源 | 记录分支、Tag、部署观察或手动选择等来源 |
| 登记时间 | 区分系统接入时间与 Git 提交时间 |

同一提交可能有多个来源，来源信息采用关联记录还是其他存储结构，需要在详细设计中明确。

## 3. 唯一性与登记

仓库身份与完整 SHA 共同确定版本，应由数据库约束保障唯一性。

```text
仓库身份 + 完整 SHA
  → 校验版本
  → 查询是否已经登记
      ├── 已存在：返回原版本身份
      └── 不存在：创建版本记录
```

并发请求下不能只依赖插入前查询，需处理唯一性冲突并返回一致结果。重复发现版本本身不应重复发起构建。

## 4. 与构建的关系

版本记录确定“哪份代码”，[Build 存储](Build.md)记录“对这份代码执行哪一次构建”。同一版本可以关联不同目标和多次构建尝试。

如果登记新版本必须同时请求初始构建，应通过事务或可靠交接机制保证两者一致；具体事务边界待实现方案确定。

## 5. 生命周期

引用移动不能改变已登记版本的 SHA。重新生成文档或重试失败任务不创建新的源码版本身份；版本清理则需考虑构建历史、产物和查询引用。
