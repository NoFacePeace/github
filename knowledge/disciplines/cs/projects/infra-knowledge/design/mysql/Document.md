# 文档存储

文档存储保存生成后的完整 Markdown 及其归属信息。一篇文档对应一条产物记录，同一源码版本重新生成时，通过批次区分不同产物。

## 1. 主要信息

| 信息 | 用途 |
| --- | --- |
| 文档标识 | 唯一定位本次生成的文档 |
| 文件名与标题 | 记录相对输出路径和展示名称 |
| 正文或内容引用 | 保存完整 Markdown，或指向不可变对象存储内容 |
| 内容哈希 | 校验读取与索引使用的正文一致 |
| 仓库与 Commit | 标识来源代码项目及固定版本 |
| 版本记录与批次 | 关联版本身份和本次产物集合 |
| 来源与标签 | 记录生成类型和分类信息 |
| 可用状态与删除标记 | 控制查询可见性和历史清理 |

## 2. 正文形式

直接存储时，正文可使用 `LONGTEXT` 保存 Markdown 文本。使用对象存储时，数据库保存带版本的引用与内容哈希，读取方解析引用并验证内容。

正文示例：

```markdown
# System Design: Example

## Architecture

The service accepts requests and executes background tasks.
```

不把每个标题直接作为独立权威文档记录；检索切分形成的派生数据与完整正文分别管理。

## 3. 暂存与发布

生成校验通过后，按批次暂存文档。暂存成功不代表已经可查询，索引就绪并完成发布切换后，才成为对应版本的有效文档集合。

已发布正文应保持不可变，更新通过新批次表达，避免正文和既有索引不一致。
