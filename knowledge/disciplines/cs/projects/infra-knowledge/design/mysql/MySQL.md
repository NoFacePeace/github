# MySQL

本目录整理 Infra 知识库的 MySQL 数据库设计，包括表结构、字段、索引、关联约束与事务。以下先描述需要存储的概念及关系，具体表名和字段尚待确定。

## 1. 核心概念

| 模型 | 表达的对象 |
| --- | --- |
| 仓库 | 纳入管理的代码项目及其接入、跟踪配置 |
| 版本 | 某个仓库的一次确定提交，以完整 Commit SHA 关联源码 |
| 构建尝试 | 针对指定版本和目标的一次执行，记录状态与结果 |
| 构建日志 | 某次构建尝试中的进度、诊断及错误记录 |
| 产物与发布 | 生成的文档、索引或图谱，以及对外可见的批次 |

## 2. 关联关系

```text
仓库
  └── 版本
      ├── 构建尝试
      │   └── 构建日志
      └── 产物与发布记录
```

一个仓库可以登记多个版本，一个版本可以有多个构建目标和多次尝试。产物应记录来源版本及生成尝试，发布状态与执行状态分别表达。

## 3. 设计原则

- 版本身份与执行状态分开：相同源码版本可以失败、重试或重新生成，无需创建新的版本身份。
- 构建尝试保留历史：新尝试不能覆盖前一次执行的错误和结果。
- 仓库与完整 SHA 共同确定版本，分支和 Tag 作为来源引用记录。
- 暂存产物与已发布内容分开，未完成校验的内容不作为默认查询结果。
- 各表后续分别补充字段、索引、约束、状态变化及事务与并发处理规则。

## 4. 存储专题

- [仓库存储](Repositories.md)：仓库登记信息的持久化、唯一性约束及更新事务。
- [Commit 存储](Commit.md)：固定源码版本的身份、来源信息及去重约束。
- [Build 存储](Build.md)：构建尝试、执行状态及其与源码版本的关联。
- [文档存储](Document.md)：完整 Markdown、内容引用及文档归属与可见性。
- [文档生成批次](GenerationBatch.md)：批次身份、恢复检查点、索引配置和发布状态。
- [索引产物存储](IndexArtifact.md)：文档派生的检索数据、模型与切分配置。
- [指标与仓库映射](MetricRepository.md)：从成功发布的指标目录累积关联，支持指标名反查仓库。
