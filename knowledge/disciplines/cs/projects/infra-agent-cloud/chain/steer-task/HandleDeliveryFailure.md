# 处理未送达与不确定结果

Steer 需要区分明确未发送、明确拒绝和可能已经送达，避免重复指令。

## 1. 尚未就绪

远程执行缺少适用控制能力时，保存 queued 指令与适用回执，向渠道返回就绪后可重试的信息。是否以及何时重试由调用方的消息排队与就绪处理协调，不能当作已送达。

## 2. 明确无法接收

引擎明确返回输入不可用错误时，尝试将适用持久化回执改为 next_session，由调用方后续协调转交下一轮。不是每次 Steer 失败都会自动创建新 Session。

## 3. 投递不确定

等待控制回执超时或其他不能证明未送达的错误，可能意味着引擎已经收到输入但回执未被及时读取。按规则记录 uncertain，避免自动重复发送；后续需要结合持久化回执、控制结果与执行结束证据再决定如何处理。

## 4. 状态边界

| 状态 | 含义 |
| --- | --- |
| queued | 等待适用的投递机会 |
| dispatching | 本请求认领并尝试投递 |
| delivered | 回执确认送达 |
| consumed | 回执确认已消费 |
| uncertain | 不能确认投递结果 |
| next_session | 适用消息交给后续轮次协调 |

这些状态分布在投递回执与适用的指令镜像中，不等于 Task 或 Session 的执行状态。已消费也不代表新指令执行完成。
