# 执行中追加指令

任务运行期间，把新输入交给当前 Session 和引擎进程，成功时不创建新平台 Session。需要任务启用 Steer 模式，且执行器、Runner 和引擎支持交互输入。

## 1. 完整流程

从[接收消息并准备追加提示词](PrepareMessage.md)开始，沿后续步骤链接阅读：

```text
接收消息并准备追加提示词
  → 获取 Steer 操作锁
  → 查询任务与追加模式
  → 检查历史投递记录
  → 查询当前执行轮次
  → 检查租约与执行器就绪
  → 认领回执并保存指令
  → 发布追加指令命令
  → Runner 校验控制命令
  → 向 Executor 输入管道写入
  → Executor 调用引擎追加能力
  → 回传追加指令回执
  → Server 保存控制回执
  → 等待回执并确认投递
  → 持续回传执行输出
```

Server 的等待回执与 Runner、Executor 的命令处理并行推进，上述顺序表示消息和回执的传递路径。

## 2. 与其他操作的区别

Continue 创建新的平台 Session，适用时恢复已有引擎对话；Steer 使用当前执行中的 Session 和引擎进程。Stop 终止执行，不负责追加消息。

## 3. 成功与异常边界

命令发布成功、写入 Executor 管道、引擎接受以及指令执行完成是不同阶段。未就绪可排队，明确拒绝可协调下一轮，超时不确定不能盲目重发。详情在对应步骤展开。
