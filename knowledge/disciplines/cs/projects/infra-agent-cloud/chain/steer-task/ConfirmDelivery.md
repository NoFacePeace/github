# 等待回执并确认投递

## 1. 处理内容

Server 发布命令后，每约 100 毫秒查询对应 commandId 的控制回执，最多等待约 30 秒，并校验回执租约与发出命令时一致。

回执有错误时抛出适用错误；成功时校验 mode 与 consumed 等字段。再更新 MySQL 持久化投递回执：consumed 为真时记为 consumed，否则记为 delivered，并保存适用的引擎会话或轮次标识；随后更新 Session 扩展信息镜像。

持久化验收检查点优先于尽力更新的扩展信息镜像。回执确认表示投递结果，不表示追加指令已执行完成。

## 2. 分支处理

未就绪、明确拒绝和超时不确定分别按[处理未送达与不确定结果](HandleDeliveryFailure.md)处理，不能统一立即重发。

## 3. 后续流程

正常路径进入[持续回传执行输出](ContinueOutput.md)。
