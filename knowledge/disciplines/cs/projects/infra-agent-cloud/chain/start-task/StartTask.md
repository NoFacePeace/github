# 发起任务

记录用户通过首次消息创建新任务并启动执行的通用调用流程。

## 1. 入口与分流

用户发送首次消息，提交任务目标及所需配置。服务端校验调用权限，并判断请求是否关联已有任务：

- 未关联已有任务：创建新任务，进入发起任务链路。
- 已关联已有任务：进入继续任务链路。

发送消息是交互动作，发起任务是首次消息触发的业务流程。

## 2. 核心调用链

以下以独立执行节点承载任务的方式说明，描述通用职责，不绑定具体接口或函数名称。

```text
用户发送首次消息
  → 接口层校验权限
  → 任务服务识别为新任务
  → 解析配置并检查授权
  → 保存任务与首轮执行记录
  → 异步启动执行流程
  → 准备执行输入并加入调度队列
  → 调度器分配执行节点
  → 执行节点接收任务并校验执行权
  → 准备凭证、工作目录与隔离环境
  → 执行器启动 Agent 引擎
  → 回传进度与结果
  → 服务端更新状态并保存结果
```

## 3. 各阶段职责

| 阶段 | 主要职责 |
| --- | --- |
| Server | [服务端流程](server/Server.md) 分为提交与调度，负责配置准备、记录保存、入队及 Runner 分配。 |
| 准备环境 | 校验任务归属与租约，准备凭证、工作目录和隔离环境。 |
| 启动引擎 | 执行器生成引擎配置和启动命令，创建实际执行任务的进程。 |
| 回传结果 | 回传执行事件、日志和最终结果，更新任务及本轮执行状态。 |

## 4. 任务与执行轮次

任务表示持续的工作目标，一轮执行表示针对某次输入开展的处理过程。发起任务时，同时建立任务和首轮执行记录；后续交互可基于已有任务继续处理。

阅读调用链时，需要分别跟踪任务标识和执行轮次标识，区分任务级状态与单轮执行状态。

## 5. 异步执行与运行分支

创建记录后，接口可以先返回任务标识、执行轮次标识和当前状态，后台继续调度与执行。接口返回成功仅表示请求已被接收，不表示 Agent 已启动或任务已完成。

排队、准备环境和实际执行属于不同阶段。判断任务进度时，应结合调度状态与执行事件，不宜仅凭任务级状态推断 Agent 是否已经运行。

独立执行节点是其中一种运行方式。本地执行分支可以直接在服务所在环境启动执行器，无需经过远程调度队列。学习时应先读通一个分支，再比较其他分支的差异。
