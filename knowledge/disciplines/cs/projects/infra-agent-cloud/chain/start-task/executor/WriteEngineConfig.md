# 写入引擎配置

MCP Gateway 配置转换完成后，Executor 调用所选引擎适配器，将本轮最终配置转换为引擎识别的本地文件。

## 1. 写入位置

文件写入执行描述指定的 `config/`，使用任务私有目录。目录职责与备份边界见[对象存储 config](../../../storage/object-storage/Config.md)。

Codex 的 `CODEX_HOME` 和 Claude Code 的 `CLAUDE_CONFIG_DIR` 指向该目录，使后续引擎读取本轮配置。

## 2. Claude Code 分支

| 文件 | 内容与条件 |
| --- | --- |
| agent-prompt.md | 存在注入指令快照时写入有效指令，启动参数引用此文件追加系统提示词。 |
| settings.json | 写入运行设置和适用的工具权限限制等。 |
| .claude.json | 写入本轮 MCP 服务配置；没有 MCP 服务时写入空配置。 |

模型、推理设置和适用的认证信息还会通过启动参数或环境变量交给引擎，不能认为全部最终配置都写入同一个 JSON 文件。

## 3. Codex 分支

| 文件 | 内容与条件 |
| --- | --- |
| auth.json | 本轮提供 Codex 认证 JSON 时写入。 |
| model-catalog.json | 模型具有适用的上下文窗口配置时生成模型目录文件。 |
| config.toml | 写入模型、服务提供方、指令和 MCP 等适用的引擎配置。 |

创建配置目录并设置 `0700` 权限，适用配置文件使用 `0600` 权限。模型 API Key 等信息也可能通过环境变量提供，不应默认所有认证均来自 `auth.json`。

## 4. 存储与安全边界

此步骤写 Runner 本地文件，不直接写 MySQL、Redis 或上传对象存储。后续任务备份是否包含某类文件，由备份和清理规则决定。

写入普通配置不等于这些文件都不敏感，例如工具配置可含认证信息。不得将配置文件原文当作普通诊断输出。

## 5. 后续步骤

引擎配置写入后，检查停止信号，再[构建引擎启动命令](BuildEngineCommand.md)。配置写入完成不代表引擎已经启动。
