# 消费 Job

Runner 通过 Redis Stream 消费已派发的作业。正常消费本身不直接访问 MySQL 或对象存储，后续任务处理可触发其他存储操作。

## 1. 消费流程

从[确保消费组存在](EnsureConsumerGroup.md)开始，沿后续链接阅读：

```text
确保 Stream 与消费组存在
  → 检查消费并发空位
  → 查询并尝试接管未确认消息
  → 未接管到：读取新消息
  → 解析并交给处理函数
  → 正常返回后确认消息
```

## 2. 并发方式

当前实现每次取 1 条 Job，逐条调用处理函数；只要未完成处理数低于消费并发上限，就可继续取下一条，因此可同时处理多条消息。

消费处理函数返回不等于 Agent 执行完成，不能将消费并发数直接当成正在运行的 Agent 数量。

## 3. 接单检查

Job 交给 Runner 处理函数后，会在校验目标、范围、截止时间与重复处理情况后，[检查维护状态](../check-maintenance/CheckMaintenance.md)，通过后才接受任务。
