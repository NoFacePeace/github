# 执行收尾

Executor 结束后，Runtime 收齐输出并整理终态，停止日志定时备份、清理执行环境、登记后台文件备份，再发布最终结果事件。本阶段与准备执行环境、启动 Executor 同属 Runtime 生命周期。

## 1. 收尾顺序

```text
等待引擎与 Executor 退出，收齐输出事件
  → 保存待发布的终态结果
  → 停止本轮日志定时备份
  → 按条件回写引擎认证信息
  → 清理执行环境
  → 登记并启动后台备份
  → 检查是否丢失执行租约
  → 发布最终结果事件
  → 关闭租约续期并清除本轮执行跟踪信息
```

非终态事件在执行中持续回传，终态事件由 Runtime 暂存，完成上述适用收尾后再发送。监控异常会尝试停止执行并生成失败结果；执行环境清理失败也会转为相应失败结果。

## 2. 停止定时备份与认证回写

先清除本轮 30 秒日志备份定时器，中止适用的进行中上传并等待处理结束，避免它与后续目录备份重叠运行。

本轮提供了适用的 Codex 认证、Runner 身份有效且租约信号未中止时，尝试从执行环境读取认证信息，经 Server 回写。异常记录告警与回写结果，不等于重新执行任务。

## 3. 清理执行环境

调用 Runtime 的销毁能力，清理进程、隔离环境及适用的临时资源。保留用于备份的任务目录；清理执行环境不等于删除任务的所有文件。

清理失败会记录失败终态。后台 Memory 处理也会依据清理结果决定是否正常完成同步，避免把未正确结束的执行按正常路径处理。

## 4. 后台文件备份

Agent 执行分支在发布终态之前登记后台备份任务。启动备份不代表已经完成上传；终态发布不会等待全部文件备份结束。

### 4.1 备份范围与顺序

1. 存在 Memory 收尾任务时，先处理适用的记忆变更上传与同步。
2. 再备份[对象存储 config](../../../../storage/object-storage/Config.md)。
3. 最后备份[对象存储 session](../../../../storage/object-storage/Session.md)目录。

Memory 的变更与同步规则见[对象存储 memory](../../../../storage/object-storage/Memory.md)。普通任务文件备份不包含 workspace 整体备份。

与运行中的日志定时器不同，这里会备份 session 目录内适用的文件，不只当前 Session 的单个 JSONL 日志。

### 4.2 生命周期与失败处理

后台备份使用 180 秒超时。按任务登记 config、session 备份状态；同一任务继续执行时，可以取消并等待之前的此类备份，避免与下一轮恢复或写入冲突。Memory 有独立跟踪与取消控制。

备份失败记录告警，不因该后台上传失败直接改写已产生的任务结果。因此，收到完成事件不等于全部备份对象已经可读。

## 5. 发布终态与资源释放

后台工作登记完成后，再次检查执行租约；失去执行权时，终态改为租约丢失失败。随后通过 Runtime 事件发送通道发布最终结果，供 Server 消费并更新业务状态。

Runtime 随后关闭本轮租约续期、清除超时定时器和适用的活动执行跟踪。关闭续期与 Server 处理终态后释放共享租约、容量是不同操作。
