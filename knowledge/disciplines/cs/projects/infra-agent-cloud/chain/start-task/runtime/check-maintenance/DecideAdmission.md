# 判断是否接单

综合进程排空状态与 Redis 维护检查结果，决定当前 Job 是否可以进入正常接受流程。

## 1. 拒绝分支

进程正在排空或维护标记存在时，抛出拒绝接单错误，由外层错误处理尝试回传失败事件并清理本地处理登记。本分支不回传正常的 `accepted` 事件，也不继续启动执行环境。

拒绝当前 Job 不等于自动重新加入 Server 的待调度集合，消息确认与任务收尾由相应消费、事件处理流程决定。

## 2. 通过分支

进程未排空且维护标记不存在时，进入[回传 accepted 事件](../ReportAccepted.md)。事件成功发送后才继续准备执行环境。
