# 读取与处理 Job

本轮未接管到遗留消息时，通过 `XREADGROUP` 从当前 Stream 读取新消息；接管到的消息复用相同解析处理逻辑。

## 1. 读取新消息

```text
XREADGROUP GROUP <group> <consumer> COUNT 1 STREAMS <stream> >
```

`>` 表示读取尚未投递给该消费组的新消息。该操作既返回消息，也更新消费组进度并登记待确认状态，不是纯只读查询。

## 2. 解析与处理

从消息字段中取得 `payload`，将 JSON 解析为 Job，交给 Runner 的处理函数校验与安排执行。当前一次取 1 条，但处理流程可在消费并发上限内并发运行。

处理函数在校验目标、范围、截止时间与重复处理情况后，还会[检查维护状态](../check-maintenance/CheckMaintenance.md)，决定是否继续接受任务。

消费循环同时检查公共流与目标流，并轮换检查优先级，避免其中一类消息长期得不到处理。

## 3. 后续步骤

处理函数正常返回后进入[确认与失败处理](AcknowledgeJob.md)。如果处理函数已安排后台执行，Agent 可以在消息确认后继续运行。
