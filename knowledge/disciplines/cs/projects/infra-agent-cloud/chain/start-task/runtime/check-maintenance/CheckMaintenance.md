# 检查维护状态

Runner 在接收 Job 的处理函数中，完成目标、范围、截止时间和重复处理检查后，判断是否允许继续接单。

## 1. 检查方式

从[检查进程排空状态](CheckDraining.md)开始，沿后续链接处理：

```text
检查进程排空标记
  → 已排空：拒绝接单，不查询维护 key
  → 未排空：查询 Redis 维护标记
      → 标记存在：拒绝接单
      → 标记不存在：继续接受任务
```

维护检查本身只读 Redis，不直接查询 MySQL 或请求 Server。

## 2. 处理分支

- 进程正在排空，或 Redis 中存在维护标记：拒绝当前任务，不进入正常的接受与环境准备流程。
- 两项均未阻止接单：继续接受任务，回传 `accepted` 事件，再准备执行环境。

拒绝不等于把原 Job 自动退回 Server 等待队列；具体失败事件和任务状态由后续处理流程负责。

## 3. 标记来源

维护标记由运维动作设置，不是每次收到 Job 时创建。设置入口和恢复条件见[维护与恢复](ManageMaintenance.md)。
