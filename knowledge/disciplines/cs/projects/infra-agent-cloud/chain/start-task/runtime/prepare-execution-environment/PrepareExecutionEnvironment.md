# 准备执行环境

Runner 成功回传 `accepted` 后，将 Job 中的配置与资源引用转换为可运行的执行环境，最后启动 Executor。

## 1. 处理顺序

从[协调任务启动](CoordinateTaskStartup.md)开始，沿后续链接处理：

```text
等待同一 Task 的启动与清理操作
  → 初始化并检查运行状态
  → 领取执行凭证
  → 启动租约续期
  → 恢复任务文件
  → 准备 Agent 版本资源
  → 准备 Memory
  → 启动 Executor
```

## 2. 停止与失败

准备过程多次检查停止、关闭和租约失效信号；取消或失败时按对应分支停止准备并释放适用的本地处理状态。Memory 初始化失败可告警后继续，不代表其他准备失败也能忽略。

## 3. 存储边界

本流程会与 Server 的凭证、资源等接口交互，读取 Git 或对象存储资源，并写入任务私有文件目录。Runner 不直接访问 MySQL 业务表，服务端接口可在内部校验数据库与 Redis 状态。
