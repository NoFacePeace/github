# 接管未确认消息

有消费空位时，优先检查曾被投递但尚未确认的消息，恢复因消费者中断而遗留的处理。

## 1. 查询与接管

通过 `XPENDING` 查询当前 Stream 消费组中的未确认记录，排除当前进程仍在处理的消息，再通过 `XCLAIM` 尝试将满足最小空闲时间的消息转交当前消费者。

当前 Job 消费每次最多尝试接管 1 条。最小空闲时间默认 30 秒，可配置；查询到未确认消息不意味着一定能立即接管。

`XPENDING` 是查询，`XCLAIM` 会更新消费者归属与投递信息。这里的 Pending 不同于 Server 的待调度集合，表示消息已经投递而未确认。

## 2. 后续分支

接管到消息时，使用[读取与处理 Job](ReadAndProcessJob.md)中的解析处理流程，不再为当前 Stream 读取一条新消息；未接管到时，进入同一步骤读取新消息。

恢复可能带来重复投递，执行层仍需校验租约及重复执行状态，不能只凭接管成功就重复启动 Agent。
