# 确认与失败处理

消费确认表示本条消息的处理函数已经正常返回，不等于 Agent 的整轮执行完成。

## 1. 正常确认

```text
XACK <stream> <group> <stream-message-id>
```

从消费组的待确认列表中移除消息。`XACK` 不删除 Stream 消息本体；使用的是 Stream 消息 ID，不是 Job 的业务 `messageId`。

## 2. 异常处理

- `payload` 无法解析：尝试写入死信流，再确认原消息并报告错误。
- 处理函数抛出异常：通过 `XPENDING` 查询投递次数；达到上限时尝试转入死信流并确认，否则保持未确认，供后续接管重试。

投递次数上限默认 5 次，可配置。死信 key 为 `<原 Stream key>:dlq`，类型为 Stream，保存原消息、错误摘要与失败时间。

死信写入失败会报告异常；当前实现仍可能继续确认原消息，不能认为所有失败消息都一定已持久化到死信流。

## 3. 执行与确认边界

Runner 的处理函数可以先完成接受与启动安排，再让执行在后台继续；成功返回后即可确认消息。后续执行失败通过执行事件处理，不一定重新投递原 Job。
