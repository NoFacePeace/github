# 维护与恢复

维护操作用于让 Runner 停止接收新任务，为部署或运维腾出窗口。

## 1. 设置入口

- Server 管理接口：管理员提交 `drain` 请求与原因，Server 写入维护标记，来源为 `admin`。
- Runner 所在 VM 的命令：部署脚本或人工命令执行 `drain`，写入来源为 `vm` 的维护标记。

部署通常先设置维护，再等待已有任务退出，之后执行升级和验证。维护标记本身不是立即终止所有现有任务的命令。

## 2. 持久保留

维护标记不设置 TTL。进程退出、部署失败或维护超过预期时间时，不会因为标记过期而自动重新接单。

## 3. 恢复

维护结束后执行 `resume`。恢复会核对维护标识、Runner 实例、版本及健康状态，并检查活跃任务与有效容量预留是否归零。通过后原子删除维护标记，再由生命周期流程恢复在线接单。

管理员入口不能直接覆盖或解除 VM 来源的维护，应由对应 VM 运维流程处理。
