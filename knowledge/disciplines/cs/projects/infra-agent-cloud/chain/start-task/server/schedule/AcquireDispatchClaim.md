# 获取调度处理权

遍历待调度的 Session UUID 时，先尝试取得当前项的调度处理权，避免多个 Server 同时处理同一条调度记录。

## 1. 尝试获取

生成随机令牌，以 `SET NX` 和 30 秒有效期写入 Redis 的[调度处理权](../../../../storage/redis/DispatchClaim.md)。

- 写入成功：当前处理流程取得该项的调度处理权。
- key 已存在：不等待，跳过当前项，继续遍历其他项。

## 2. 续期与受控写入

取得处理权后，每 10 秒尝试续期。续期前比较 key 中的令牌，仅当前持有者可以续期，避免旧处理流程延长新持有者的处理权。

更新调度记录时也会检查令牌；处理权过期或被替换后，旧处理流程不能继续提交受该令牌保护的状态写入。

## 3. 释放

处理结束时停止续期，并比较令牌后删除 claim key。不能直接无条件删除，以免误删其他处理流程后来取得的处理权。

若进程退出或无法续期，key 可通过 TTL 自动过期，后续调度器可重新尝试获取。

## 4. 后续步骤

持有处理权后，进入[检查调度记录](check-dispatch-record/CheckDispatchRecord.md)，读取该 Session 的记录，检查状态及排队超时，再尝试分配 Runner。

这里保护的是调度记录的处理过程，不是 Runner 的执行归属；Runner 执行租约属于后续步骤。
