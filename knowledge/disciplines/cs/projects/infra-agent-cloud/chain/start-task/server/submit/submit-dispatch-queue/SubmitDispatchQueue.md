# 提交调度队列

登记执行回调后，将执行请求保存为待调度记录，加入等待队列，并通知调度器尝试分配 Runner。

## 1. 提交流程

```text
构建调度记录
  → 加密执行输入
  → 保存调度记录并加入等待队列
  → 唤醒调度器
```

- [保存调度记录](SaveDispatchRecord.md)：记录任务身份、排队状态与加密执行输入。
- [加入等待队列](EnqueuePending.md)：将 Session 加入待调度集合。
- [唤醒调度器](WakeScheduler.md)：发布通知，提示调度器检查队列。

## 2. 存储边界

入队本身使用 Redis，不直接写 MySQL 或对象存储。保存调度记录与加入等待队列在同一 Lua 脚本中完成，避免只完成其中一项。

## 3. 后续步骤

入队成功表示调度系统已接收请求，不代表已分配 Runner。接下来进入[调度](../../schedule/Schedule.md)，由调度器检查候选节点和容量，完成分配与任务下发。
