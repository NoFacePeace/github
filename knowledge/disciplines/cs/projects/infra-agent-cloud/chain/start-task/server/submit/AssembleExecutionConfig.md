# 组装执行配置

确定 Agent 版本后，将版本配置、用户设置、本次请求及平台提供的运行上下文组织为本轮执行所需的配置。

## 1. 读取版本配置

读取选中版本的执行引擎、模型、推理设置、提示词、工具、技能和插件配置，作为本次配置准备的输入。

版本查询结果并非最终执行配置，用户设置与请求参数仍可能影响本次实际使用的配置。

## 2. 合并配置

按各字段的规则处理配置来源：

- 版本配置：提供可复用的默认行为和能力。
- 用户设置：提供个人模型、引擎或凭证使用方式等选择。
- 本次请求：提供任务专属参数及额外配置。
- 平台上下文：提供运行所需的标识、工具与环境信息。

不同字段可能采用覆盖、合并或保留平台值等规则，不能假设所有字段都按同一优先级处理。敏感值与受保护配置应按权限控制，不能由请求任意覆盖。

## 3. 准备执行资源

根据运行方式准备技能、插件及其他所需文件或制品引用，组织工具连接配置，并注入运行上下文。

此阶段以配置与资源准备为主，尚未启动 Agent 引擎。执行节点收到任务后，仍需完成本地工作目录、凭证交付和隔离环境的准备。

## 4. 检查授权

检查当前执行引擎、模型与工具所需的凭证和权限。缺少启动必需的授权时，应返回明确的补充授权要求；允许按需授权的能力可在实际使用时再请求授权。

插件和技能的加载配置不能代替访问授权。

## 5. 交给记录创建阶段

配置准备与启动前检查完成后，进入[创建 Task](CreateTask.md)，随后创建首个 Session，记录所选版本及本轮输入，再异步提交。

需要新生成任务标识才能确定的上下文，可在标识生成后补齐；执行配置不等于将全部内容原样写入任务表，尤其不能把敏感值写入普通日志或公开结果。
