# 调度

调度器属于 Server 内部逻辑，负责处理已入队的请求，分配 Runner 并下发执行作业。

## 1. 阶段边界

本阶段以读取等待队列和调度记录为起点，以分配执行节点、下发作业并更新调度状态为主要目标。

多个 Server 实例可能同时参与调度，需要通过共享协调机制避免重复处理同一调度记录。

## 2. 待读步骤

从[读取等待队列](ReadPendingQueue.md)开始，取得待处理的 Session UUID。

后续依次梳理调度处理权、排队超时检查、Runner 候选与容量、执行租约、作业下发及调度结果确认。

调度处理权用于避免多个调度器重复处理；执行租约用于约束 Runner 的执行归属，两者需要分别理解。
