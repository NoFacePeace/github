# 准备派发

调度记录仍为 `queued` 且未超过排队截止时间时，准备目标 Runner、执行租约与可下发的作业信息。

## 1. 处理顺序

从[解密执行输入](DecryptExecutionInput.md)开始，沿后续链接阅读：

```text
解密执行输入
  → 检查并清理遗留租约
  → 选择 Runner，预留容量并确定执行归属
  → 签发执行授权
  → 保存派发信息
```

## 2. 阶段边界

准备成功后，调度记录变为 `dispatching`，包含目标 Runner 和租约信息，但 Job 尚未在本步骤下发。

容量不足或调度 claim 争用等可恢复情况，可保留请求等待后续处理；其他错误按调度失败流程处理。不能将所有“没有可用 Runner”的情况都视为继续排队。
