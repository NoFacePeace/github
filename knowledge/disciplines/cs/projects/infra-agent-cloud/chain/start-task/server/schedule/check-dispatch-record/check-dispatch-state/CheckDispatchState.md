# 检查调度状态

读取记录后，根据 `state` 确定本次处理分支。不能把等待集合中的所有记录都当作尚未派发的新请求。

## 1. 排队状态

状态为 `queued` 时，先将当前排队状态同步给业务处理层，再重新读取记录，确认状态仍为 `queued`。

该分支从[查询 Session](QuerySession.md)开始，沿各步骤的后续链接处理。

再次确认用于处理并发变化，例如业务同步期间任务被取消。若状态已改变，结束本次处理，避免按旧状态继续派发。

## 2. 其他状态

派发中、已派发、失败或取消等状态不进入新请求的排队超时与准备分配分支，需按对应状态进行后续恢复、通知或确认处理。

因此，记录仍留在等待集合中不一定表示它还处于 `queued`，也可能是后续状态尚未确认完成。
