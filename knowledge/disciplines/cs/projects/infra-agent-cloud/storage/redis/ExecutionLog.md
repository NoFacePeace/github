# 执行日志

按 Task 和 Session 保存引擎输出日志，供执行日志查询和历史对话解析使用。

## 1. Key 与类型

```text
<namespace>:<scope>:runner:events:{<taskUuid>:<sessionUuid>}:log
```

类型为 String，内容是连续追加的日志文本，通常包含逐行 JSON。它与不带 `:log` 后缀的事件回放 Sorted Set 是不同 key。

## 2. 写入时机与内容

Server 消费、校验输出事件后，从 `stdout`、`stderr` 提取日志文本，优先使用字符串类型的 `payload.logData`，否则使用 `payload.data`。空日志内容不追加。普通事件写入通过 Lua 脚本按序去重，并在同一处理过程中保存适用的回放与状态。

日志主要来自引擎输出，包括助手回复、工具调用及参数、工具结果和错误。适用的专门入口还可以追加平台工具元数据。它不是仅包含用户和助手文本的对话列表。

## 3. 读取与持久化边界

日志查询通过 `GET` 读取字符串，按需从中解析助手文本或完整交互内容。远程沙箱分支读不到缓存时，尝试读取对象存储中的日志。

此处是 Server 保存的 Redis 日志缓存。Executor 写入 Runner 本地日志，以及 Runtime 备份文件到对象存储，是另外的操作，不是 Server 每追加一段 Redis 日志就同步上传文件。

## 4. 容量与有效期

单 Session 日志上限为 8 MiB，包含截断提示。达到限制后追加一次截断提示并停止继续追加，不因日志超限本身中断执行；事件回放积压超限则有独立处理规则。

正常事件写入设置恢复有效期，未完成恢复保留期为 24 小时，活跃执行可续期。业务终态提交后使用完成日志缓存保留策略，具体时长可配置。Redis 日志不是永久历史。
