# Runner 容量集合

按 Runner 保存已预留的执行名额，用于限制并发准入。它与按 Session 保存的执行租约是两个独立 key。

## 1. Key 与类型

以下使用通用命名空间：

```text
<namespace>:<runnerScope>:runner:{<runnerScope>}:capacity:<runnerId>
```

类型为 Sorted Set。同一 Runner 的不同执行预留共享此集合。

## 2. 成员与分数

- 成员：`leaseId`。
- 分数：租约截止时间的毫秒时间戳。

示例：

```text
lease-A → 1800000060000
lease-B → 1800000070000
```

这些示例表示该 Runner 有两份执行预留，不代表引擎进程都已启动。

## 3. 预留名额

在同一 Lua 脚本中完成以下操作：

1. 校验 Runner 心跳、在线状态与维护状态，并确认本轮没有已有租约。
2. 用 `ZREMRANGEBYSCORE` 移除已到期的容量成员。
3. 用 `ZCARD` 统计占用，结合节点并发上限和适用的动态准入限制判断容量。
4. 容量允许时创建执行租约，并用 `ZADD` 加入其 `leaseId`。
5. 根据集合中最晚的租约截止时间设置整个 key 的过期时间。

容量不足时，不为本次请求新增预留。

## 4. 释放与过期

释放执行租约时，在校验租约身份后用 `ZREM` 移除对应成员。集合为空则删除 key；仍有成员则按最晚截止时间调整 key 的过期时间。

Sorted Set 成员没有独立 TTL，分数只是截止时间。过期成员需要由协调逻辑清理，不能将分数理解为 Redis 自动删除成员的设置。
