# 事件字节计数

保存执行事件 Stream 中现有 `payload` 的字节总量，用于限制事件积压，不表示 Redis 实际内存占用。

## 1. Key 与类型

以下使用通用命名空间：

```text
{<namespace>:<replyTo>:runner:events}:bytes
```

类型为 String，值为非负字节计数。花括号包围完整的事件 Stream key 字符串，使两个 key 可在同一哈希槽内执行原子脚本。

## 2. 查询与更新

发布事件时读取计数；如果不存在，通过遍历现有 Stream 消息的 payload 重建计数。

写入新事件前检查当前计数加新事件大小是否超过限制。允许写入时，追加事件并同步增加计数；Server 成功处理并删除相应事件时，按对应逻辑减少计数。

## 3. 示例

队列中两条事件分别为 200 和 300 字节，则计数为 500。准备追加 400 字节事件时，预计变为 900；若限制为 800，则先等待消费者释放空间，不立即追加。

这是异步背压，会延后当前事件发送；超过配置的等待时限则报错。
