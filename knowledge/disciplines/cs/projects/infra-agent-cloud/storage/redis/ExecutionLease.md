# 执行租约

记录一轮执行预留的 Runner 与执行权，用于执行归属校验和容量协调。它不同于保护调度过程的 claim。

## 1. Key 与类型

以下使用通用命名空间：

```text
<namespace>:<scope>:runner:{<runnerScope>}:lease:<sessionUuid>
```

类型为 String，值为序列化 JSON。

## 2. 保存内容

| 字段 | 含义 |
| --- | --- |
| taskUuid | 所属任务。 |
| sessionUuid | 本轮执行。 |
| runnerScope | Runner 资源池范围。 |
| runnerId | 预留的执行节点。 |
| leaseId | 本次租约的唯一标识。 |
| createdAt | 租约创建时间。 |
| expiresAt | 租约截止时间。 |
| lastSeq | 协调层记录的事件序号，初始为 0。 |

## 3. 创建时机

选择候选 Runner 后，在预留执行名额时创建。Lua 脚本原子检查节点状态、已有租约与容量，全部通过后，通过带有效期的 `SET` 保存租约，并同步登记容量占用。

先前的查询不能替代写入时的原子检查，否则多个 Server 可能重复预留。

## 4. 读取与遗留预留

准备派发时，先按 Session 标识读取该 key，并检查 `expiresAt` 是否仍有效。正常首次准备时通常没有旧租约。

若此前已预留名额、后续准备却中断，重试时可能发现遗留租约。核对任务身份并确认当前调度处理权后，释放旧预留，再重新准备派发。

## 5. 释放

释放时原子比较 `leaseId`，匹配后删除租约 key，并从对应 Runner 的容量集合移除该租约成员，避免误删后来创建的新租约。

租约 key 设置有效期，不应将其与调度记录确认后的 24 小时保留时间混为一谈。
