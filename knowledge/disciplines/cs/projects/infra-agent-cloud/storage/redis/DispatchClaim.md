# 调度处理权

保存单条调度记录的临时处理权，避免多个 Server 同时进行冲突的调度处理。

## 1. Key 与类型

以下使用通用命名空间：

```text
<namespace>:<scope>:runner:{<runnerScope>}:dispatch:session:<sessionUuid>:claim
```

这是独立于调度记录的 key，命名是在对应调度记录 key 后追加 `:claim`。

类型为 String，值为当前处理流程生成的随机 UUID 令牌。该值用于校验持有者，不是任务输入或 Runner 标识。

## 2. 获取与有效期

使用带 30 秒 TTL 的 `SET NX` 获取：仅在 key 不存在时写入。获取失败则跳过当前项，不阻塞等待。

处理期间每 10 秒比较令牌并续期，将有效期重新设为 30 秒。进程退出或续期停止后，key 可自动过期。

## 3. 写入保护与释放

更新调度记录时检查 claim 令牌，只允许当前持有者提交对应的受控写入。

释放时先校验令牌再删除 key，避免旧处理流程误删后来持有者的 key。比较与更新、比较与删除应通过原子操作完成。

## 4. 与其他状态的区别

- 调度记录保存输入及调度状态，TTL 按调度阶段设置。
- claim key 保存短期调度处理权，有效期为 30 秒并按需续期。
- Runner 执行租约约束作业实际执行的归属，与调度处理权分别管理。
