# 执行事件状态

按任务与执行轮次保存事件处理状态。本篇先记录提交调度前使用的回调标记。

## 1. Key

以下采用通用命名空间，不记录内部项目的实际前缀：

```text
<namespace>:<scope>:runner:events:{<taskUuid>:<sessionUuid>}:state
```

- `scope`：隔离不同运行范围。
- `taskUuid`、`sessionUuid`：定位任务和本轮执行。
- 花括号是 key 的实际组成部分，可作为 Redis Cluster 的 hash tag，使相关 key 落入同一哈希槽。

## 2. 类型与字段

Redis 类型为 Hash。

| 字段 | 含义 |
| --- | --- |
| [callbacks](Callbacks.md) | 本轮是否注册了服务端执行回调。 |

该 key 是执行事件状态容器，不应理解为永远只有 `callbacks` 一个字段。

## 3. 写入与有效期

提交调度前登记回调标记时，将整个 key 的有效期设为 24 小时。后续事件处理操作可以刷新有效期，字段没有独立的过期时间。

## 4. 使用目的

事件处理层根据标记决定是否保留供回调消费的回放输出。标记本身不包含回调函数、外部通知 URL 或页面 SSE 连接信息，也不控制任务是否执行。
