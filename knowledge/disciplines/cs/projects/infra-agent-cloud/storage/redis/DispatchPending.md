# 待调度集合

保存等待调度的 Session，按排队时间组织。

## 1. Key 与类型

以下使用通用命名空间：

```text
<namespace>:<scope>:runner:{<runnerScope>}:dispatch:pending
```

类型为 Sorted Set。

## 2. 成员与分数

- 成员：Session UUID。
- 分数：排队时间的毫秒时间戳。

调度器从集合中取得 Session UUID 后，再读取对应调度记录。集合本身不保存配置或凭证。

## 3. 写入

入队使用 `ZADD`，与调度记录的保存位于同一 Lua 脚本。集合按时间排序不代表已经获得执行节点或一定按此顺序启动。

## 4. 清理与有效期

集合本身未设置 TTL，成员也没有独立的 Redis 过期时间。

请求已派发、失败或取消，且对应业务状态同步成功、调度结果被确认后，通过 `ZREM` 移除对应 Session 成员。同一确认操作还会为该 Session 的调度记录设置 24 小时 TTL，不会为整个等待集合设置 TTL。

排队是否超时由调度记录的 `deadline` 判断，不能依赖集合成员自动过期。
