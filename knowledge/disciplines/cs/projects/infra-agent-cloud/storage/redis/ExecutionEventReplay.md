# 执行事件回放

按任务与执行轮次保存供服务端回调读取的事件，与 Runner 写入的原始事件 Stream 是不同 key。

## 1. Key 与类型

以下使用通用命名空间：

```text
<namespace>:<scope>:runner:events:{<taskUuid>:<sessionUuid>}
```

类型为 Sorted Set。成员是事件 JSON，分数是事件序号 `seq`。

## 2. 写入与读取

Server 消费原始事件并校验执行归属后，按顺序去重保存；是否保留回放受执行事件状态中的回调标记控制。

持有回调的 Server 按任务和执行轮次，读取游标之后的事件，调用本地回调，再确认已交付序号。发布回放时设置恢复有效期，活跃执行的恢复扫描可续期相关事件存储。

## 3. 确认清理

通过序号范围移除已交付成员，并扣减执行事件状态 Hash 中的回放字节计数。

这不是原始 Stream 的 `XACK`；也不是原始 Stream 的独立 `:bytes` key。回放会被确认删除且有容量、有效期限制，不是完整永久历史或多订阅者广播队列。

## 4. 多实例示例

```text
Runner → 原始事件 Stream → Server B 校验并保存回放
                                      ↓
                         Server A 读取回放并执行回调
                                      ↓
                              A 的 SSE → 前端
```
