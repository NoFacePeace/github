# SecretGrant

SecretGrant 表保存指定执行作业领取凭证与资源的授权记录。签发时新增记录，将敏感输入加密保存，并向 Job 提供授权引用。

## 1. 主要字段

| 字段 | 含义 |
| --- | --- |
| id | 授权记录主键。 |
| secret_ref | 授权唯一编号，作为 Job 中的 `secretRef`。 |
| binding | JSON 格式的执行绑定信息，包括范围、Runner、实例、Job、Task、Session 和租约标识，以及适用的资源授权信息。 |
| credential_data | 经密钥管理服务信封加密后的凭证快照，可包含模型凭证及资源准备所需的敏感输入。 |
| expires_at | 凭证领取截止时间，签发时设为当前时间加 5 分钟。 |
| created_at / updated_at | 记录创建与更新时间。 |

## 2. 签发过程

确定目标 Runner 与执行租约后，生成授权编号，组织执行绑定信息，将凭证快照加密，再插入本表。

随后将授权编号和凭证服务地址加入 Job。普通作业消息携带的是授权引用，不直接携带全部凭证明文。

## 3. 领取校验

Runner 请求领取时，服务端校验调用身份，通过 `secret_ref` 查询记录，核对执行绑定及有效租约，并检查领取截止时间。仅持有授权编号不能直接获取凭证。

## 4. 有效期与撤销

`expires_at` 是应用校验的截止时间，不是 MySQL 自动删除记录的 TTL。后续流程可按规则续期或撤销；撤销会删除对应授权记录。

本表管理执行凭证的受控领取，与用户角色授权、Redis 调度 claim 和 Runner 执行租约分别承担不同职责。
