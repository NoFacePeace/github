# 远程执行恢复

Server 每 30 秒执行一次恢复扫描，处理远程执行中的状态缺失或中断。运行中或已关闭的恢复流程不会在同一实例重复进入。

## 1. 扫描范围

唤醒调度队列，并查询仍为运行状态的 [Session](../../../storage/mysql/session/Session.md)。仅处理回复范围属于当前 Server 范围、且关联远程 [Task](../../../storage/mysql/task/Task.md) 的记录。

## 2. 检查调度状态

读取[调度记录](../../../storage/redis/dispatch-record/DispatchRecord.md)。如果存在且尚未为 `dispatched`，同步其业务状态并交给相应调度恢复路径处理；仍在排队时发出适用的排队恢复通知，本轮不直接判定为租约失效。

## 3. 检查租约与已保存结果

读取[执行租约](../../../storage/redis/ExecutionLease.md)：

- 有效：刷新执行事件存储的有效期；若已有停止请求，再尝试停止。
- 无效：读取已保存的最后事件。若它是已经校验并保存的终态事件，重试业务落库，而不是直接判失败。

若尚无已投影到业务记录的执行序号，且 Session 创建未满 5 分钟，给予启动宽限，暂不标记失败。

## 4. 结束失效执行

没有有效租约、没有可补交的终态结果且不再处于启动宽限内时，在事务中锁定 Session，重新检查其状态和租约。

确认仍应结束后，将 Session 标记为失败；若已有停止请求则标记为停止。记录退出信息和租约过期原因，同步 Task 状态，再完成事件存储收尾与终态通知。

停止续租到故障被识别之间存在延迟，不能仅因 Runner 暂时没有回传事件就立刻判定其失败。
