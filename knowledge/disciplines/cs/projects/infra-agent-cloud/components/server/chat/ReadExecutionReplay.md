# 读取执行回放

发起远程执行时，聊天适配器注册处理输出、进度及完成等事件的本地回调，执行服务为该轮启动回放监听流程。

## 1. 读取来源

按 Task UUID 和 Session UUID 从 Redis 的[执行事件回放](../../../storage/redis/ExecutionEventReplay.md)读取尚未交付的事件，而不是再次竞争原始事件 Stream 的消费权。

正常等待时每 500 毫秒轮询一次；有积压时可立即继续读取。已交付序号保存在监听流程中，用于继续读取与确认。

## 2. 回调与完成

普通输出按事件类型调用回调，交付后按序号确认回放数据。终态回调需等待业务结果已提交，不能仅凭读取到完成事件就提前通知完成。

因此原始事件即使被另一 Server 消费，持有聊天回调的实例仍可从共享回放读取。

## 3. 后续步骤

回调内容进入[推送聊天回复](PushReply.md)，发送给当前连接。
