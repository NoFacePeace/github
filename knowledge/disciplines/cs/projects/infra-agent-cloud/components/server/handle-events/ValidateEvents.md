# 校验执行事件

Server 检查事件回复范围是否属于自己，再通过[执行租约](../../../storage/redis/ExecutionLease.md)校验执行归属。

## 1. 校验内容

核对任务、Runner 范围、Runner ID 与租约 ID，确认租约未过期，并检查事件序号是否超过租约中已经接受的序号。

不匹配、租约失效或已经处理的事件不会按正常的新事件继续接受，避免旧执行或重复消息覆盖当前状态。

## 2. 持久化与序号

业务事件处理成功后，才推进租约中的事件序号；终态事件则按校验结果释放租约与容量占用。相关写入需要比较当前租约，处理并发变化。

业务事件存储自身也需要幂等和顺序检查，不能仅依赖一次读取租约消除所有并发重试。

## 3. 后续步骤

校验与持久化流程配合执行，事件内容交给[保存事件与结果](PersistEvents.md)处理。
