# 保存事件与结果

Server 将通过执行归属校验的事件写入按任务与执行轮次组织的 Redis 事件存储。

## 1. 普通事件

`accepted`、进度与输出等非终态事件主要更新 Redis 的[执行事件状态](../../../storage/redis/execution-event-state/ExecutionEventState.md)及适用的日志、回放数据。

是否保留供回调消费的输出受回调标记控制。收到 `accepted` 不等于直接将 MySQL 中的 Session 更新为某个接受状态，Session 的主状态仍可能为 `running`。

适用的事件保存在[执行事件回放](../../../storage/redis/ExecutionEventReplay.md)，供持有回调的 Server 读取；原始 Stream 消费确认清理后，回调仍可读取尚未确认的回放成员。

## 2. 从输出事件保存日志

日志主要来自 Claude Code 或 Codex 引擎进程的标准输出、标准错误。Executor 每读取一行，先经过适用的过滤器写入本地日志，再通过自身标准输出管道发出协议事件；Runtime 接收后写入原始事件 Stream。

Server 消费 Stream、校验归属后，在保存事件的过程中提取日志：

1. 仅当事件类型为 `stdout` 或 `stderr`，且 `payload.data` 是字符串时，进入普通输出日志提取分支。
2. `payload.logData` 是字符串时使用它，否则使用 `payload.data`。
3. 将非空内容按事件顺序追加到 Redis 的[执行日志](../../../storage/redis/ExecutionLog.md)。事件序号去重可避免重试时重复追加。

`logData` 表示 Executor 过滤后的日志内容。它为空字符串时，不追加本行；不能因为它为空就回退到原始 `data`。例如，部分流式增量片段只用于实时处理，不进入保存的日志。

```text
引擎输出一行
  → Executor 写本地日志并发出 stdout / stderr 事件
  → Runtime 写入事件 Stream
  → Server 消费并校验
  → 事件 JSON 保存为适用的回放成员
  → 提取日志文本追加到独立的 String
```

回放保存和日志追加在同一个 Redis Lua 写入流程中处理，上图最后两项表示两类保存内容，不是两个独立传输阶段。关闭回调保留时，可以跳过回放成员保存，但仍按规则保存输出日志。

### 2.1 日志保存什么

日志可以包含助手文本、工具调用名称与参数、工具结果或错误，以及引擎输出的执行信息。具体内容取决于引擎输出格式和日志过滤规则；日志不是只有用户与助手的纯文本聊天。

平台也可以通过专门的日志追加入口补充工具等元数据。用户原始输入主要从 Session 的 `prompt` 获取，不能假定每条用户输入都完整存在于引擎输出日志。

### 2.2 与 SSE 事件回放的区别

| 对比 | 事件回放 | 执行日志 |
| --- | --- | --- |
| 类型 | Sorted Set | String |
| 内容 | 结构化事件，含类型、序号、标识和 payload | 从输出事件提取的引擎日志文本及适用元数据 |
| 事件范围 | 按回调策略保留的进度、输出和终态等事件 | 普通提取分支仅保存 stdout、stderr 的适用内容 |
| 用途 | 持有回调的 Server 读取事件并推送 SSE | 查询日志、解析历史对话 |

二者来源有重叠，内容与格式都不同。`completed` 等事件不会因为被保存为回放，就自动作为一行普通输出日志追加；Redis 日志还可能过滤掉事件中携带的原始输出片段。

### 2.3 通用示例

引擎输出助手工具调用的一行 JSON，Executor 发出类似事件：

```json
{
  "type": "stdout",
  "payload": {
    "data": "{\"type\":\"assistant\",\"message\":{\"content\":[{\"type\":\"tool_use\",\"id\":\"call-1\",\"name\":\"Read\",\"input\":{\"file_path\":\"README.md\"}}]}}\n"
  }
}
```

示例省略事件标识等公共字段。没有 `logData` 时，日志追加的是 `data` 内部那一行引擎 JSON，而不是外层 `stdout` 事件外壳。随后引擎输出工具结果、助手回复时，也按同样规则处理。

### 2.4 历史对话读取

获取任务对话时，查询 Task 及按时间排列的 Session，从 Session 读取用户输入，再逐轮读取日志并提取助手文本。远程沙箱分支优先读取 Redis 日志，不可用时回退到对象存储。

因此，历史对话接口返回的助手文本只是日志的一种提取结果，不代表日志中没有工具调用和工具结果。该接口读取历史数据；实时回复通过事件回放和 SSE 推送。

## 3. 终态事件

`completed`、`failed`、`stopped` 等结果进一步更新 [Session](../../../storage/mysql/session/Session.md) 和 [Task](../../../storage/mysql/task/Task.md)，记录状态、结果、退出信息和适用的统计或产物引用。

更新在事务中检查执行状态与已处理序号，避免重复或延迟结果覆盖已结束的执行。

终态处理还涉及执行租约及容量释放，并按规则撤销执行授权。若输出存储超限，可能进入拒绝、停止执行等异常分支，不能按普通事件直接确认成功。

## 4. 后续步骤

处理成功后进入[确认与清理事件](AcknowledgeEvents.md)；失败时通过消费层重试与异常策略处理，不能提前推进为正常成功。
