# 处理执行事件

Runner 将执行事件写入 Redis 后，Server 异步消费，校验事件归属并保存适用的执行状态和结果。

## 1. 处理顺序

从[消费执行事件](ConsumeEvents.md)开始，沿后续链接阅读：

```text
消费事件 Stream
  → 按执行归属分组
  → 校验租约与事件序号
  → 保存事件并处理业务结果
  → 确认、删除消息并扣减字节计数
```

## 2. 职责边界

该流程由 Server 处理，不是 Runner 直接写 MySQL。普通事件主要进入 Redis 执行事件存储，终态结果才进一步更新任务与执行业务记录。

事件消费与提交、调度是不同处理入口，可以在任务实际执行期间持续发生。
