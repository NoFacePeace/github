# ARP 协议

ARP（Address Resolution Protocol，地址解析协议）用于在同一 IPv4 链路上，根据下一跳的 [IP 地址](ip/IP.md)查询对应的 MAC 地址，从而发送以太网帧。本知识库将 ARP 归入[数据链路层](DataLinkLayer.md)。

## 1. 与 IP 的关系

IP 地址用于网络层寻址，MAC 地址用于以太网链路上的帧传输。发送设备确定下一跳 IP 地址后，需要知道其 MAC 地址，才能将 IP 数据包封装到对应的以太网帧中。

ARP 报文直接封装在以太网帧中，EtherType 为 `0x0806`，不由 IP 承载，也不使用 TCP 或 UDP 端口。

```text
地址解析：以太网帧 [ ARP 报文 ]
数据发送：以太网帧 [ IP 首部 | IP 数据 ]
```

ARP 连接网络层地址和链路层地址。部分教材因其服务于 IP 地址解析而将其归入网络层；这里按其本地链路工作方式归入数据链路层。

## 2. 解析过程

例如，主机 `192.168.1.10/24` 要向同一以太网局域网中的 `192.168.1.20` 发送 IP 数据包：

1. 主机先检查 ARP 缓存中是否已有 `192.168.1.20` 对应的 MAC 地址。
2. 如果没有可用记录，就发送 ARP 请求，询问谁拥有 `192.168.1.20`。请求通常使用以太网广播地址 `ff:ff:ff:ff:ff:ff`。
3. 拥有该 IP 地址的设备通常单播回复 ARP 应答，提供自己的 MAC 地址。
4. 主机缓存映射关系，将待发送的 IP 数据包封装为以该 MAC 地址为目的地址的帧。

ARP 请求中的目标是 IP 地址；以太网广播使同一广播域中的设备能够收到请求。

## 3. 跨网络通信

如果目标地址位于其他网络，主机通常根据路由表选择网关作为下一跳，并通过 ARP 查询网关的 MAC 地址，而不是远端目标的 MAC 地址。

例如，主机访问远端服务器时，IP 数据包的目的地址是服务器的 IP 地址，第一跳以太网帧的目的地址则是网关的 MAC 地址。

路由器不会转发 ARP 广播请求。后续路由器在自己的出站以太网链路上需要解析下一跳地址时，会独立执行 ARP。

## 4. ARP 缓存

ARP 缓存保存近期学习到的 IP 地址与 MAC 地址映射，避免每发送一个数据包都重新广播查询。动态记录通常会随时间失效，具体维护方式取决于操作系统。

ARP 本身不提供身份认证，伪造的 ARP 报文可能造成错误映射，即 ARP 欺骗或 ARP 缓存投毒。

## 5. 与 IPv6 的区别

IPv6 不使用 ARP，而是通过基于 ICMPv6 的邻居发现协议（NDP，Neighbor Discovery Protocol）完成地址解析等功能。
