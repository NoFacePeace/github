# 304 Not Modified

`304 Not Modified` 表示条件 GET 或 HEAD 请求对应的资源表示未发生需要重新传输的变化，客户端可以复用已有缓存内容。

## 1. 触发条件

客户端需要验证缓存时，可以发送 `If-None-Match` 或 `If-Modified-Since`。对于原本会返回成功响应的 GET 或 HEAD 请求，实体标签匹配，或表示未在指定时间之后修改时，服务器返回 304。

请求同时包含两个条件字段时，服务器优先判断 `If-None-Match`，忽略 `If-Modified-Since`。

## 2. 响应示例

```http
HTTP/1.1 304 Not Modified
Date: Tue, 15 Nov 1994 08:12:31 GMT
ETag: "v1"
Cache-Control: max-age=60
```

304 响应不包含报文体。缓存根据响应更新相关首部信息，再复用已保存的内容。新的有效期仍需结合响应年龄和缓存指令判断；如果有 `no-cache`，后续复用前仍必须验证。

## 3. 与 200 的区别

- 304：验证通过，不重新发送资源内容，客户端复用缓存。
- 200：条件未阻止正常处理时，GET 通常直接返回最新内容，客户端更新缓存，无须再发送一次请求。

虽然 304 属于 3xx 类别，但它用于缓存验证，不是通过 `Location` 跳转到另一个地址。
