# Keep-Alive

HTTP Keep-Alive 指持久连接机制：完成一次请求与响应后，可以复用同一连接处理后续请求，减少重复建立连接的开销。

## 1. 不同版本的行为

- HTTP/1.0：默认不保持连接，部分实现通过 `Connection: keep-alive` 扩展支持持久连接。
- HTTP/1.1：默认使用持久连接，通常无须显式发送 `Connection: keep-alive`；`Connection: close` 表示完成当前请求与响应后关闭连接。
- HTTP/2 与 HTTP/3：支持连接复用和多路复用，禁止使用 `Connection` 和 `Keep-Alive` 等连接专用首部。

## 2. 连接的生命周期

持久连接不保证永久保持打开。服务器可能因空闲超时、重启或资源限制关闭连接，网络故障也可能导致连接断开。客户端需要检测连接是否可用，必要时重新建立连接。

## 3. 连接正在处理请求时

HTTP/1.1 客户端通常等待当前响应完成，或使用连接池中的其他连接。连接池达到上限时，请求通常排队等待；超过等待时间可能超时。HTTP/1.1 虽支持流水线，但响应必须按顺序返回，实际使用较少。

HTTP/2 与 HTTP/3 可以通过多个流在同一连接上并发处理请求。达到并发流上限时，客户端通常等待可用流，或根据实现建立其他连接。

## 4. 相关术语

- `Connection: keep-alive`：HTTP/1.x 中表达保持连接意图的首部取值。
- `Keep-Alive` 首部：部分 HTTP/1.x 实现用于提供超时、请求数量等连接参数的扩展首部，不保证对端遵循。
- TCP Keepalive：底层 TCP 的连接探测机制，与 HTTP 持久连接不同。
