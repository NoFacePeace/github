# 请求方法

HTTP 请求方法用于表达客户端希望对目标资源执行的操作，具体目标由[请求目标](../messages/RequestTarget.md)指定。

## 1. 常见方法

| 方法 | 含义 |
| --- | --- |
| [GET](GET.md) | 获取目标资源的表示 |
| HEAD | 获取与 GET 相同的响应头，但不返回响应体 |
| [POST](POST.md) | 让目标资源处理请求体中的数据 |
| PUT | 用请求中的表示创建或替换目标资源的状态 |
| PATCH | 对目标资源进行部分修改 |
| DELETE | 请求删除目标资源与其当前功能之间的关联 |
| OPTIONS | 查询目标资源支持的通信选项 |
| CONNECT | 建立到目标服务器的隧道 |
| TRACE | 执行请求消息的回环测试 |

## 2. 方法对比

### 2.1 PUT 与 POST

PUT 表示用提交的表示创建或整体替换指定资源的状态；POST 表示让目标资源按其自身语义处理提交的数据，并不只用于创建资源。

| 对比 | PUT | POST |
| --- | --- | --- |
| 常见用途 | 创建或整体替换指定资源 | 创建资源、提交表单、执行操作 |
| 目标地址 | 通常由客户端指定，如 `/users/123` | 创建时通常提交到集合，如 `/users`，由服务器分配新资源地址 |
| 幂等性 | 幂等：重复相同请求，预期最终效果相同 | 不保证幂等：重复请求可能创建多个资源或重复执行操作 |

例如，`PUT /users/123` 将用户 `123` 的状态设为提交的内容；目标资源不存在时也可以创建。`POST /users` 则让服务器处理提交的数据，常用于创建用户并分配 ID。

幂等不代表每次响应都相同，也不排除服务器记录日志等附带行为。POST 可以通过幂等键等应用机制避免重复处理，但协议本身不保证其幂等。

局部修改通常使用 PATCH，而不是将 PUT 当作部分字段更新。具体 API 应明确约定各方法的行为。

### 2.2 GET 与 POST

GET 用于获取目标资源的表示；POST 用于让目标资源处理提交的数据。应根据操作语义选择方法，而不是只根据参数放在哪里选择。

| 对比 | GET | POST |
| --- | --- | --- |
| 操作语义 | 获取资源，不应请求改变服务器业务状态 | 提交数据，常用于创建资源或执行操作 |
| 安全性语义 | 安全方法：客户端不要求改变服务器状态 | 不是安全方法 |
| 幂等性 | 幂等 | 不保证幂等 |
| 参数位置 | 通常使用 URL 查询字符串 | 通常使用请求体，也可以包含查询字符串 |
| 缓存 | 响应通常可缓存，仍需遵守缓存规则 | 满足显式新鲜度及同目标 URI 的 `Content-Location` 等条件时，响应可供后续 GET／HEAD 复用，不能直接满足再次 POST；实际支持较少 |

例如，`GET /users?page=1` 用于获取用户列表；`POST /users` 通常通过请求体提交用户数据，创建新用户。

“安全方法”是协议语义，不表示数据传输更安全，也不排除日志记录等附带行为。POST 请求体不出现在 URL 中，但并不因此获得加密保护；GET 和 POST 都应通过 HTTPS 保护传输中的敏感数据。敏感信息应避免放入 URL，因为 URL 可能进入浏览器历史和访问日志。

GET 请求体没有通用定义的语义，部分实现会拒绝或忽略，不应依赖它传递参数。POST 不仅能发送表单，也能发送 JSON、文件等内容。

HTTP 规范没有统一规定 GET 或 POST 的最大数据长度；URL、请求体的实际限制取决于浏览器、代理、服务器和应用配置。
