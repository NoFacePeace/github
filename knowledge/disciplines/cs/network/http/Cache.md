# HTTP 缓存

HTTP 缓存保存响应及其相关信息，在满足复用条件时用于后续请求，减少网络传输和服务器处理开销。

## 1. 缓存类型

- 私有缓存：服务于单个用户，例如浏览器缓存。
- 共享缓存：服务于多个用户，例如代理或 CDN 缓存。

## 2. 新鲜度与验证

缓存通常先匹配请求方法、目标 URI 及 `Vary` 指定的请求字段，再判断响应是否可复用。

- 新鲜响应：满足缓存指令时，可以直接复用，不必访问源服务器。常被称为“[强缓存](StrongCache.md)”。
- 过期响应：通常需要向服务器验证。客户端携带 `If-None-Match` 或 `If-Modified-Since` 发起条件请求；表示未变化时，服务器可以返回 `304 Not Modified`，缓存更新相关信息后复用已保存的内容。常被称为“[协商缓存](NegotiatedCache.md)”。

过期并不意味着内容已经变化。特定缓存指令也可以允许在限定条件下复用过期响应。

## 3. 常见字段

| 字段 | 用途 |
| --- | --- |
| Cache-Control | 控制存储、复用、验证和新鲜度 |
| Expires | 指定响应的过期时间 |
| Date | 表示报文生成时间，参与响应年龄计算 |
| Age | 表示缓存估算的响应年龄，单位为秒 |
| ETag | 标识资源表示的版本，用于条件请求 |
| Last-Modified | 表示资源表示的最后修改时间，用于条件请求 |
| Vary | 指定选择缓存响应时需要匹配的请求字段 |

## 4. 常见 Cache-Control 指令

| 指令 | 含义 |
| --- | --- |
| max-age=60 | 指定新鲜度上限为 60 秒，复用时需考虑响应当前年龄 |
| s-maxage=300 | 为共享缓存指定新鲜度上限，覆盖 `max-age` 和 `Expires`，并要求过期后验证 |
| no-cache | 可以存储，但复用前必须成功验证 |
| no-store | 不得存储该请求或响应 |
| private | 响应只能由私有缓存存储 |
| public | 显式允许共享缓存存储响应，仍需遵守其他缓存规则 |
| must-revalidate | 响应过期后，复用前必须成功验证 |

`no-cache` 不等于禁止存储；禁止存储使用 `no-store`。响应同时包含 `max-age` 和 `Expires` 时，`max-age` 优先。

## 5. 有效期优先级

| 缓存类型 | 有效期依据，从高到低 |
| --- | --- |
| 私有缓存，如浏览器缓存 | `max-age` → `Expires` |
| 共享缓存，如 CDN 缓存 | `s-maxage` → `max-age` → `Expires` |

高优先级的有效指令覆盖低优先级字段，不取两者中更早的过期时间。例如，即使 `Expires` 已经过期，有有效的 `max-age` 时仍按 `max-age` 计算新鲜度。

`Expires` 指定绝对时间，`max-age` 指定新鲜度期限，不能直接比较数值。缓存使用 `max-age` 时，需要扣除响应当前年龄，而不是从每次收到响应时重新计时。

仅存在 `Cache-Control` 并不一定覆盖 `Expires`。例如 `Cache-Control: private` 只限制共享缓存存储，私有缓存仍可通过 `Expires` 判断有效期。如果没有显式有效期，缓存可能根据协议规则计算启发式有效期。

## 6. 什么时候需要验证

以下规则适用于已匹配且允许缓存的响应，并且没有其他请求指令要求验证的通常情况。

| 情况 | 行为 |
| --- | --- |
| 缓存未过期，没有 `no-cache` | 通常直接复用，不发送请求 |
| 缓存已过期 | 通常先验证；没有验证标识则重新获取完整响应 |
| 响应有不带字段名的 `no-cache` | 即使未过期，复用前也必须成功验证 |
| 响应有 `no-store` | 不允许存储该响应 |

过期表示缓存不再新鲜，不代表内容已经变化，也不意味着立即删除。除允许复用过期响应的特定情况外，缓存需要先验证或重新获取。

`ETag` 和 `Last-Modified` 只提供验证依据，本身不会触发验证。缓存未过期且允许直接复用时，即使存在这些字段，也不需要因此向服务器验证。

`Cache-Control` 可以包含多个逗号分隔的指令，它们共同决定缓存行为，并不是按出现顺序覆盖。例如：

```http
Cache-Control: private, max-age=60
```

表示只允许私有缓存存储，新鲜度期限为 60 秒。而下面的响应虽然指定了有效期，仍要求每次复用前验证：

```http
Cache-Control: no-cache, max-age=3600
```

`no-cache` 与 `Expires` 同时存在时也一样，即使过期时间尚未到达，复用前仍必须验证。

## 7. 条件请求与验证结果

| 响应中的验证标识 | 后续验证请求携带 |
| --- | --- |
| ETag | If-None-Match |
| Last-Modified | If-Modified-Since |

两种验证标识都存在时，客户端可以同时发送两个条件字段；服务器优先判断 `If-None-Match`，忽略 `If-Modified-Since`。浏览器通常自动保存验证标识并发送条件请求，手写客户端则需要自行实现。

对于通常的条件 GET 或 HEAD 请求：

- 表示未变化：返回 `304 Not Modified`，客户端复用已保存的内容，并根据响应更新缓存信息。
- 表示已变化：同一次请求通常直接返回 `200 OK` 和最新表示；GET 响应包含新内容，HEAD 响应没有报文体。客户端不需要再发送一次请求来获取验证结果对应的新内容。

如果既没有 `ETag`，也没有 `Last-Modified`，需要验证时通常只能重新获取完整响应。`no-cache` 并不要求一定存在 `ETag`。

## 8. 强缓存与协商缓存配合

服务器可以同时提供有效期和验证标识：

```http
Cache-Control: max-age=60
ETag: "v1"
```

缓存仍新鲜且允许复用时直接使用，属于强缓存；过期后携带 `If-None-Match: "v1"` 验证，属于协商缓存。两者可以作用于同一份缓存，在不同条件下使用。

如果响应同时带有 `no-cache`，则每次复用前都必须验证，即使 `max-age` 或 `Expires` 表明缓存尚未过期。
