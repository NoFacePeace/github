# HTTP 版本

HTTP 版本（HTTP Version）标识使用的 HTTP 协议版本。不同版本保留了方法、[状态码](../status-codes/StatusCode.md)等核心语义，但报文格式和传输机制有所不同。

## 1. 常见版本

| 版本 | 主要特点 |
| --- | --- |
| [HTTP/0.9](0.9.md) | 早期形式，只有简单 GET 请求，响应没有状态行和首部 |
| [HTTP/1.0](1.0.md) | 使用文本报文，默认不保持连接 |
| [HTTP/1.1](1.1.md) | 使用文本报文，默认持久连接，支持分块传输编码 |
| [HTTP/2](2.md) | 使用二进制帧，在一条 TCP 连接上多路复用多个流，使用 HPACK 压缩首部 |
| [HTTP/3](3.md) | 基于 QUIC，使用 QPACK 压缩首部，减少不同流之间因丢包导致的传输阻塞 |

## 2. 各版本新增特性

以下按版本演进列出主要变化，不是所有特性的完整清单。新版本通常保留方法、状态码等核心语义，但不一定沿用前代的报文格式或连接管理机制。

| 版本 | 相较前代的主要新增或变化 |
| --- | --- |
| HTTP/0.9 | 建立最初的简单请求与响应机制：GET 加资源路径，响应直接返回 HTML 内容，通过关闭连接结束传输 |
| HTTP/1.0 | 引入请求中的版本字段、响应状态行、请求与响应首部；支持 HEAD、POST、媒体类型、内容长度以及基于修改时间的条件请求和缓存有效期 |
| HTTP/1.1 | 默认持久连接；要求 `Host` 首部；引入分块传输编码、流水线、`Cache-Control`、实体标签验证；标准化范围请求和更多请求方法等机制 |
| HTTP/2 | 改用二进制帧；在单条 TCP 连接上多路复用；使用 HPACK 压缩首部；引入流优先级和服务器推送机制，减少 HTTP/1.1 在 HTTP 层的队头阻塞 |
| HTTP/3 | 将传输从 TCP 改为 QUIC；使用 QPACK 压缩首部；减少丢包引起的跨流传输阻塞；依托 QUIC 获得集成 TLS 1.3、连接迁移及适用条件下的低延迟连接建立能力 |

HTTP/1.0 的部分实现已提供持久连接等扩展；HTTP/1.1 将持久连接变为默认行为，因此这里的“新增”也包括标准化和默认行为的变化。

HTTP/2 的原始流优先级方案已被弃用，现代实现可采用可扩展优先级机制；服务器推送虽属于协议能力，但主流浏览器已普遍停止支持。HTTP/3 的连接迁移、0-RTT 等能力来自 QUIC，并不表示每次连接都会使用它们。

## 3. HTTP/1.x 中的表示

HTTP/1.x 在请求行末尾显式写出版本：

```http
GET /users HTTP/1.1
```

其中 `HTTP/1.1` 是版本字段，位于请求目标之后。响应报文的状态行也包含版本字段。

## 4. HTTP/2 与 HTTP/3

HTTP/2 与 HTTP/3 没有文本请求行，也没有对应的版本伪首部。协议版本在建立连接时确定，例如通过 ALPN 协商 `h2` 或 `h3`。
