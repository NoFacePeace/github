# Connection

`Connection` 是 HTTP/1.x 的连接专用首部，可用于请求和响应，说明当前连接的管理意图，以及仅适用于当前连接的首部字段。

## 1. 常见取值

| 取值 | 含义 |
| --- | --- |
| `close` | 完成本次请求与响应后关闭连接 |
| [`keep-alive`](KeepAlive.md) | 请求保持连接，常用于 HTTP/1.0 的持久连接扩展 |

```http
Connection: close
```

HTTP/1.1 默认使用持久连接，通常不需要显式发送 `Connection: keep-alive`。持久连接允许复用同一连接完成多次请求与响应，但不保证连接一直保持打开。

## 2. close 的请求与响应行为

`Connection: close` 可以出现在请求头或响应头中。任意一方发送 `close`，当前连接就不应再用于后续请求；另一方的 `keep-alive` 不能覆盖这个关闭意图。

- 请求带 `close`：客户端声明不再复用连接。服务器发完该请求的最终响应后应主动关闭连接；客户端读完最终响应后也应关闭连接。
- 响应带 `close`：服务器声明发完当前响应后会关闭连接；客户端读完响应后也应关闭连接。

因此，请求方发送 `close` 不表示只有请求方负责关闭。双方都需要配合，在正常完成当前响应后关闭连接，而不是发送首部后立即中断响应传输。

## 3. 与请求方法的区别

请求方法说明对目标资源执行什么操作，`Connection` 首部说明如何管理当前连接。`CONNECT` 是建立隧道的请求方法，与 `Connection` 首部是不同概念。

`Connection` 不表示底层 TCP 的实际连接状态，也不会使 HTTP 从无状态协议变成有状态协议。

## 4. 逐跳语义

`Connection` 的作用仅限于当前通信链路。代理转发报文前，必须移除 `Connection` 首部，以及它列出的首部字段。

## 5. HTTP/2 与 HTTP/3

HTTP/2 与 HTTP/3 禁止使用 `Connection` 首部，通过协议自身的流和连接管理机制控制通信，例如使用 `GOAWAY` 通知对端停止在当前连接上创建新请求流。
