# 传输层

传输层（Transport Layer）负责端系统中应用进程之间的数据传输。它在[网络层](NetworkLayer.md)提供的主机间通信基础上，使用端口区分应用，并根据协议提供可靠传输、流量控制和拥塞控制等能力。

## 1. 所在层级

| 网络模型 | 所在层级 |
| --- | --- |
| OSI 七层模型 | 第 4 层：传输层 |
| TCP/IP 四层模型 | 传输层 |

在 TCP/IP 模型中，传输层位于[应用层](ApplicationLayer.md)和网络层之间。应用数据由传输层封装为 TCP 报文段或 UDP 数据报，再交给 IP 传输。

## 2. 核心职责

- **进程寻址与复用、分用**：使用端口号标识通信端点，将多个应用的数据交给网络层，并把收到的数据交给对应应用。
- **数据封装**：为应用数据添加传输层首部；TCP 还会将字节流划分为报文段。
- **可靠传输**：TCP 通过序列号、确认和重传等机制，向应用提供可靠、有序的字节流。
- **流量控制**：TCP 根据接收方的接收能力限制发送量，避免接收缓冲区被耗尽。
- **拥塞控制**：TCP 根据网络状况调整发送速率，缓解网络拥塞。

这些能力取决于具体协议，并非所有传输层协议都提供可靠传输、流量控制或拥塞控制。

## 3. 常见协议

| 特性 | [TCP](tcp/TCP.md) | UDP |
| --- | --- | --- |
| 连接方式 | 面向连接，传输前需要建立连接 | 无连接，无需建立连接 |
| 数据形式 | 字节流，不保留应用消息边界 | 数据报，保留消息边界 |
| 可靠性与顺序 | 提供可靠、有序的传输 | 不保证到达、顺序或不重复 |
| 流量控制与拥塞控制 | 提供 | 协议本身不提供 |
| 常见用途 | HTTP/1.1、HTTP/2、SSH | DNS 查询、实时音视频等 |

UDP 的首部和协议机制较简单，但不意味着所有场景下都更快。应用可以在 UDP 之上实现额外能力，例如 HTTP/3 使用的 QUIC 基于 UDP，提供可靠传输和拥塞控制。

## 4. 端口与通信端点

TCP 和 UDP 的端口号都是 16 位，取值范围为 `0`～`65535`，其中端口 `0` 为保留端口。TCP 和 UDP 使用各自独立的端口空间，同一个数字可以分别用于 TCP 和 UDP 服务。

IP 地址用于网络层寻址，端口号用于区分传输层的应用端点。一条 TCP 连接通常由源 IP、源端口、目的 IP、目的端口这四个值标识。

例如，浏览器访问 HTTPS 服务时，可能从本机临时端口连接服务器的 TCP `443` 端口；使用 HTTP/3 时，则通常连接服务器的 UDP `443` 端口。

## 5. 与相邻层的区别

| 层级 | 主要职责 | 常见协议 |
| --- | --- | --- |
| 应用层 | 定义应用消息的格式与交互规则 | HTTP、DNS、SMTP |
| 传输层 | 提供应用进程之间的数据传输 | TCP、UDP |
| 网络层 | 提供跨网络的寻址与数据包转发 | IP、ICMP |

例如，HTTP/1.1 定义请求和响应的含义，TCP 将这些数据作为字节流传输，IP 负责把承载数据的数据包送往目标地址。
