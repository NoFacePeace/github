# IP 数据包

IP 数据包（IP Packet）是 IP 协议在网络层传输和转发的数据单位，由 IP 首部以及承载的数据组成。IPv4 和 IPv6 都可以使用“数据包”这一名称。

## 1. 术语

| 术语 | 中文名称 | 常见用法 |
| --- | --- | --- |
| IP Packet | IP 数据包 | 可用于 IPv4 和 IPv6 |
| IP Datagram | IP 数据报 | 常用于描述 IPv4 的数据单位 |

本知识库统一使用“IPv4 数据包”和“IPv6 数据包”。“数据报”也用于 UDP，因此阅读时需要结合协议名称判断所指的数据单位。

## 2. 基本结构

IPv4 数据包的基本结构为：

```text
IPv4 首部 | 数据
```

IPv6 数据包的基本结构为：

```text
IPv6 基本首部 | 可选的扩展首部 | 数据
```

首部提供源地址、目的地址、上层协议标识和存活跳数限制等信息。数据部分可以承载 TCP 报文段、UDP 数据报或 ICMP 报文等内容。

## 3. IPv4 包格式

IPv4 首部最小为 20 字节，包含选项时最大为 60 字节。下图中固定首部的每一行表示 32 位，字段宽度以标注为准：

```text
┌────────┬────────┬──────────────┬──────────────────┐
│版本 4位│首部长度│ DSCP / ECN   │   总长度 16位    │
│        │  4位   │    8位       │                  │
├────────┴────────┴──────────────┼───┬──────────────┤
│          标识 16位            │标志│ 片偏移 13位 │
│                               │3位│              │
├──────────────┬────────────────┼───┴──────────────┤
│   TTL 8位    │   协议 8位     │ 首部校验和 16位 │
├──────────────┴────────────────┴──────────────────┤
│                  源 IP 地址 32位                 │
├──────────────────────────────────────────────────┤
│                 目的 IP 地址 32位                │
├──────────────────────────────────────────────────┤
│               可选选项与填充（0～40字节）         │
├──────────────────────────────────────────────────┤
│                      数据                        │
└──────────────────────────────────────────────────┘
```

下表按字段在首部中的出现顺序排列，每组固定字段合计 32 位（4 字节）：

| 首部位置 | 字段及长度 |
| --- | --- |
| 第 1 个 32 位 | 版本（4 位）、首部长度（4 位）、DSCP（6 位）、ECN（2 位）、总长度（16 位） |
| 第 2 个 32 位 | 标识（16 位）、标志（3 位）、片偏移（13 位） |
| 第 3 个 32 位 | TTL（8 位）、协议（8 位）、首部校验和（16 位） |
| 第 4 个 32 位 | 源 IP 地址（32 位） |
| 第 5 个 32 位 | 目的 IP 地址（32 位） |
| 可选部分 | 选项与填充（0～40 字节） |
| 首部之后 | 数据 |

- **版本**：值为 `4`。
- **首部长度（IHL）**：以 4 字节为单位，取值为 `5`～`15`，用来确定数据部分从哪里开始。
- **DSCP / ECN**：分别用于服务质量分类和显式拥塞通知。
- **总长度**：包含 IPv4 首部和数据，以字节为单位，最大为 65535 字节。
- **标识、标志、片偏移**：用于分片控制和重组；标志包含 DF（禁止分片）和 MF（后面还有分片），片偏移以 8 字节为单位。
- **TTL**：限制数据包的存活跳数，每次路由转发递减。
- **协议**：标识承载的数据类型，例如 ICMP 为 `1`、TCP 为 `6`、UDP 为 `17`。
- **[首部校验和](HeaderChecksum.md)**：只覆盖 IPv4 首部，不覆盖数据部分。

## 4. IPv6 包格式

IPv6 基本首部固定为 40 字节，之后可以接扩展首部和上层数据。下图前两行各表示 32 位，源地址和目的地址各占 128 位；字段宽度以标注为准：

```text
┌────────┬──────────────┬───────────────────────────┐
│版本 4位│ 流量类别 8位 │         流标签 20位       │
├────────┴──────────────┼─────────────┬─────────────┤
│    载荷长度 16位     │下一首部 8位 │跳数限制 8位 │
├──────────────────────┴─────────────┴─────────────┤
│                 源 IP 地址 128位                 │
├──────────────────────────────────────────────────┤
│                目的 IP 地址 128位                │
├──────────────────────────────────────────────────┤
│                  可选的扩展首部                  │
├──────────────────────────────────────────────────┤
│                      数据                        │
└──────────────────────────────────────────────────┘
```

字段排列如下：

| 首部位置 | 字段及长度 |
| --- | --- |
| 第 1 个 32 位 | 版本（4 位）、流量类别（8 位）、流标签（20 位） |
| 第 2 个 32 位 | 载荷长度（16 位）、下一首部（8 位）、跳数限制（8 位） |
| 接下来 128 位 | 源 IP 地址（128 位） |
| 接下来 128 位 | 目的 IP 地址（128 位） |
| 基本首部之后 | 可选的扩展首部与上层数据 |

- **版本**：值为 `6`。
- **流量类别**：包含 DSCP 和 ECN，用于服务质量分类和拥塞通知。
- **流标签**：用于标识数据流，便于网络设备对同一流的数据包进行处理。
- **载荷长度**：以字节为单位，包含扩展首部和上层数据，不包含 40 字节基本首部。普通数据包的载荷最大为 65535 字节；巨型载荷有专门的扩展机制。
- **下一首部**：标识紧随其后的扩展首部或上层协议。例如 TCP 为 `6`、UDP 为 `17`、ICMPv6 为 `58`。
- **跳数限制**：每次路由转发递减，对应 IPv4 的 TTL 功能。

IPv6 基本首部没有首部校验和，也没有 IPv4 的分片字段。需要分片时，由发送方使用分片扩展首部，路由器不执行 IPv6 分片。

## 5. 与其他层数据单位的关系

| 协议或层级 | 常见数据单位名称 |
| --- | --- |
| TCP | 报文段（Segment） |
| UDP | 数据报（Datagram） |
| IP | 数据包（Packet），也称数据报（Datagram） |
| 数据链路层 | 帧（Frame） |

例如，TCP 数据通过以太网发送时，封装关系为：

```text
以太网帧 [ IP 首部 | TCP 首部 | TCP 数据 ]
```

其中，TCP 首部和 TCP 数据组成 TCP 报文段；IP 首部和它承载的 TCP 报文段组成 IP 数据包；外层以太网首部、数据与可能的填充、帧校验序列组成以太网帧。
