# 首部校验和

首部校验和（Header Checksum）是 IPv4 首部中的一个 16 位字段，用于检测首部在传输中是否发生错误。它覆盖整个 IPv4 首部，包括选项和填充，但不覆盖数据部分。IPv6 基本首部没有这个字段。

## 1. 计算方法

发送方计算首部校验和时：

1. 将首部中的校验和字段暂时置为 `0`。
2. 将整个首部按 16 位分组，按网络字节序解释每组数值。
3. 使用反码加法累加各组：将超出 16 位的进位加回低 16 位，若仍有进位则继续折叠。
4. 将最终的 16 位结果逐位取反，写入校验和字段。

这里的“反码加法”不是简单地丢弃溢出的高位，而是将进位加回低位。

## 2. 运算示例

下面用三个 16 位数演示运算规则，并非完整的 IPv4 首部：

```text
分组数值：0x4500、0x003C、0xFFFE
相加结果：0x1453A
折叠进位：0x453A + 0x0001 = 0x453B
逐位取反：~0x453B & 0xFFFF = 0xBAC4
```

因此，这组数据对应的校验和为 `0xBAC4`。将校验和也加入反码求和后，结果为 `0xFFFF`。

## 3. 接收方校验

接收方对整个首部进行相同的反码求和，这次包含收到的校验和字段。正常结果应为 `0xFFFF`；如果再取反，则应得到 `0x0000`。

如果校验失败，数据包会被丢弃。校验成功只表示未检测到错误，不能保证首部绝对没有错误。

## 4. 路由转发时的更新

路由器转发 IPv4 数据包时会递减 TTL，因此首部内容发生变化，必须更新首部校验和。实现可以重新计算整个首部，也可以根据字段变化进行增量更新。

分片或地址转换等操作修改首部时，也需要更新校验和。

## 5. 功能边界

- 只检测 IPv4 首部，不检查数据部分。
- 不负责修复错误或重传数据包。
- 不是加密或身份认证机制，不能防止恶意篡改。
- 与以太网 FCS、TCP 和 UDP 校验和的覆盖范围不同，不能相互替代。
