# IPv4 协议

IPv4（Internet Protocol version 4）是 [IP 协议](IP.md)的第 4 个版本，属于网络层，使用 32 位地址进行逻辑寻址和跨网络的数据包转发。

## 1. 地址表示

IPv4 地址通常采用点分十进制表示：将 32 位分为 4 组，每组 8 位，取值范围为 `0`～`255`，例如 `192.168.1.10`。

32 位地址理论上共有 `2^32` 个组合，但其中一部分用于私有网络、组播及其他特殊用途，不能全部作为公网单播地址使用。

## 2. 子网与 CIDR

IPv4 地址由[网络部分](NetworkPart.md)和[主机部分](HostPart.md)组成。CIDR（无类别域间路由）使用前缀长度表示地址中有多少位属于网络部分，例如 `192.168.1.10/24`。

- `/24` 表示前 24 位是网络部分，剩余 8 位是主机部分。
- 对应的[子网掩码](SubnetMask.md)为 `255.255.255.0`。
- 所属网络为 `192.168.1.0/24`，广播地址为 `192.168.1.255`。
- 在这个普通子网中，通常可分配给主机的地址为 `192.168.1.1`～`192.168.1.254`。

传统 A、B、C 类地址划分已被 CIDR 取代。判断网络范围时应使用前缀长度，而不是仅看地址的第一个数字。

## 3. 常见地址范围

| 地址或范围 | 用途 |
| --- | --- |
| `10.0.0.0/8` | 私有地址 |
| `172.16.0.0/12` | 私有地址，即 `172.16.0.0`～`172.31.255.255` |
| `192.168.0.0/16` | 私有地址 |
| `127.0.0.0/8` | 回环地址，常用 `127.0.0.1` 访问本机 |
| `169.254.0.0/16` | 链路本地地址 |
| `224.0.0.0/4` | 组播地址 |
| `255.255.255.255` | 有限广播地址 |

私有地址可在不同私有网络中重复使用，不在公共互联网中直接路由。私有网络访问 IPv4 互联网时通常通过 NAT 转换地址。

## 4. 数据包首部

IPv4 数据包由首部和数据部分组成。首部最小为 20 字节，包含选项时最大为 60 字节。

| 字段 | 作用 |
| --- | --- |
| 版本 | 标识协议版本，IPv4 的值为 `4` |
| 首部长度 | 表示首部长度，以 4 字节为单位 |
| 总长度 | 表示整个 IP 数据包的字节数，包含首部和数据 |
| 标识、标志、片偏移 | 用于分片控制与重组 |
| TTL | 每经过一次路由转发递减，耗尽时丢弃数据包，避免无限循环 |
| 协议 | 标识承载的上层协议，例如 TCP 为 `6`、UDP 为 `17`、ICMP 为 `1` |
| 首部校验和 | 检查首部错误，不覆盖数据部分 |
| 源地址、目的地址 | 标识发送方和接收方的 IPv4 地址 |

## 5. 分片与重组

### 5.1 分片条件与规则

当 IPv4 数据包超过出站链路的 [MTU（最大传输单元）](../MTU.md)，且允许分片时，发送主机或路由器可以将其拆分为多个 IP 分片。每个分片都有自己的 IP 首部，总长度不能超过出站链路 MTU，并分别封装到链路层帧中发送。

如果设置了 DF（Don't Fragment，禁止分片）标志，路由器无法转发过大的数据包时会将其丢弃，并通常通过 ICMP 报告需要分片及下一跳的 MTU。路径 MTU 发现可以利用这些信息调整发送大小。

分片的数据容量需要扣除该分片的 IP 首部长度。除原始数据包的最后一个分片外，分片数据长度必须是 8 字节的整数倍；不含选项、首部为 20 字节时，通常按下面的公式计算每个非末尾分片的数据容量：

```text
分片数据容量 = floor((MTU - 20) / 8) × 8
```

分片使用相同的标识，片偏移记录其数据在原始 IP 数据部分中的位置，单位为 8 字节。各分片的总长度和首部校验和需要按实际内容重新计算。分片还可以在后续较小 MTU 的链路上再次分片，偏移仍相对于原始 IP 数据部分。

### 5.2 分片示例

假设原始 IPv4 数据包共 4000 字节，其中首部为 20 字节、数据为 3980 字节，出站链路 MTU 为 1500 字节，且允许分片。

每个分片最多携带 `1500 - 20 = 1480` 字节数据。除最后一片外，分片数据长度必须是 8 字节的整数倍，因为片偏移以 8 字节为单位。

| 分片 | 原始 IP 数据中的字节范围 | 数据长度 | 分片总长度 | 片偏移 | MF |
| --- | --- | --- | --- | --- | --- |
| 第 1 片 | 0～1479 | 1480 | 1500 | 0 | 1 |
| 第 2 片 | 1480～2959 | 1480 | 1500 | 185 | 1 |
| 第 3 片 | 2960～3979 | 1020 | 1040 | 370 | 0 |

三个分片使用相同的标识（Identification）。MF（More Fragments）为 `1` 表示后面还有分片，为 `0` 表示这是最后一片。第二、第三片的片偏移分别为 `1480 / 8 = 185` 和 `2960 / 8 = 370`。

目的主机结合源地址、目的地址、协议和标识识别同一组分片，并根据偏移重组。缺少分片且重组超时后，整组数据会被丢弃，IP 本身不会重传。

### 5.3 目的主机重组

分片可以独立传输，并可能乱序到达。重组由目的主机完成，中间路由器通常只负责转发或再次分片。

接收方根据片偏移放置数据，并通过最后一片的偏移和长度确定原始数据的总长度。只有全部数据收齐后，才能将完整的数据交给上层协议。

## 6. 传输特点

IPv4 提供无连接、尽力而为的传输服务，不保证数据包可靠、有序或不重复地到达。可靠传输通常由 TCP 等上层协议实现。
