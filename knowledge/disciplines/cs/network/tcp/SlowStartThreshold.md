# TCP 慢启动阈值

慢启动阈值（ssthresh，Slow Start Threshold）是 TCP 发送方维护的拥塞控制状态，用于决定拥塞窗口（cwnd）采用慢启动还是拥塞避免的增长方式。

## 1. 与拥塞窗口的关系

在经典 TCP 拥塞控制规则中：

```text
cwnd < ssthresh：使用慢启动
cwnd > ssthresh：使用拥塞避免
cwnd = ssthresh：允许使用其中任一种
```

慢启动通常增长较快，拥塞避免则更加谨慎。ssthresh 是增长方式的分界，不是发送量的硬上限：进入拥塞避免后，cwnd 仍可以继续增长并超过它。

```text
示意，单位为 MSS：

ssthresh = 8
cwnd：1 → 2 → 4 → 8 → 9 → 10 → …
      慢启动阶段       拥塞避免阶段
```

该示例使用理想化增长模型，实际窗口变化取决于 ACK、应用供给和拥塞控制算法等因素。

## 2. 初始值

连接建立时，发送方通常还没有本次连接的拥塞反馈。经典规则允许将初始 ssthresh 设置得较高，以便先通过慢启动探测网络容量；实现也可能结合缓存的路径信息等选择初始值。

初始 ssthresh 不等于初始 cwnd，也不一定存在一个适用于所有系统和路径的固定数值。

## 3. 检测到丢失后的调整

经典 Reno 模型在重传超时或进入由三个重复 ACK 触发的丢失恢复时，通常根据在途数据量（FlightSize）设置阈值：

```text
ssthresh = max(FlightSize / 2, 2 × MSS)
```

FlightSize 指已发送但尚未被累计确认的数据量。它不一定等于 cwnd，例如应用没有足够数据时，实际在途数据可能远小于允许的窗口。

```text
cwnd       = 20 MSS
FlightSize = 12 MSS

新的 ssthresh = max(12 / 2, 2) = 6 MSS
```

这是经典模型中的常见取值规则，其他拥塞控制算法可能使用不同的降低比例或状态管理方式。

## 4. 阈值调整后如何发送

超时与快速重传之后，即使 ssthresh 使用类似的计算方式，cwnd 的处理也不同。

- **重传超时**：经典 Reno 通常把 cwnd 降到 `1 MSS`，重新慢启动，接近阈值后转入拥塞避免。
- **快速重传与快速恢复**：经典 Reno 在恢复期间临时调整 cwnd；收到确认全部恢复数据的 ACK 后，将 cwnd 设为 ssthresh，并继续拥塞避免。

因此，降低 ssthresh 不等于立即把 cwnd 设为相同值，也不意味着所有丢失都会重新从 `1 MSS` 开始。

## 5. 与其他窗口的区别

| 状态 | 作用 |
| --- | --- |
| ssthresh | 决定拥塞窗口采用哪种增长方式 |
| cwnd | 限制发送方允许保持的在途数据量 |
| rwnd | 接收方通告的接收窗口，限制发送量以适应接收能力 |

ssthresh 和 cwnd 是发送方内部状态，不通过 TCP 首部中的窗口字段发送；窗口字段携带的是接收窗口信息。
