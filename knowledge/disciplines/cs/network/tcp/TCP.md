# TCP 协议

TCP（Transmission Control Protocol，传输控制协议）是[传输层](../TransportLayer.md)的核心协议之一，在 [IP](../ip/IP.md) 提供的尽力而为传输基础上，为应用提供面向连接、可靠、有序的双向字节流传输。

TCP 的传输单位称为 [TCP 报文段（Segment）](Segment.md)，由 TCP 首部和数据部分组成。

## 1. 传输特点

- **面向连接**：通信双方在传输数据前建立连接，维护序列号、窗口等状态。
- **可靠、有序**：通过序列号、确认和重传等机制处理丢失、重复和乱序，按顺序向应用交付数据。
- **字节流**：不保留应用消息边界，一次发送的数据可能被分多次读取，多次发送的数据也可能被一次读取。
- **全双工**：连接双方可以同时发送和接收数据，两个方向分别维护传输状态。

可靠传输不代表连接永远不会失败。如果网络长期不可用，TCP 可能超时并向应用报告错误；TCP 确认也不代表对端应用已经处理了数据。

## 2. 连接与端口

一条 TCP 连接通常由源 IP、源端口、目的 IP、目的端口组成的四元组标识。服务器通常监听固定端口，客户端通常使用临时端口发起连接。

例如，客户端 `192.168.1.10:53000` 可以连接服务器 `192.168.1.20:443`。同一个服务器端口可以同时服务多条连接，因为各条连接的四元组不同。

## 3. 连接的建立与关闭

### 3.1 三次握手

常见的连接建立过程如下：

1. 客户端发送 `SYN`，携带客户端的初始序列号。
2. 服务器发送 `SYN + ACK`，确认客户端的序列号，并携带服务器的初始序列号。
3. 客户端发送 `ACK`，确认服务器的序列号，完成连接建立。

握手用于同步双方的初始序列号，并交换窗口、最大报文段长度等参数。

### 3.2 连接关闭

TCP 的两个传输方向分别关闭。发送方使用 `FIN` 表示该方向没有更多数据，接收方使用 `ACK` 确认；另一方向仍可继续发送，直到它也发送 `FIN`。

因此，正常关闭常被称为“四次挥手”，但确认和关闭报文可以合并，实际报文数量不一定是四个。`RST` 则用于复位连接，与正常关闭不同。

## 4. 可靠传输机制

- **序列号**：对字节进行编号，帮助接收方排序并识别重复数据。
- **确认号**：通常表示接收方下一步期望收到的字节序列号，累计确认此前连续收到的数据。
- **[重传](Retransmission.md)**：发送方在重传定时器超时或检测到丢失时重发数据。
- **[校验和](Checksum.md)**：检测报文在传输中发生的损坏，不提供加密或身份认证。

接收方可以缓存乱序到达的数据，等待缺失部分补齐后再按顺序交付给应用。双方支持选择性确认（SACK）时，接收方还能报告已经收到的不连续数据范围，帮助发送方减少不必要的重传。

## 5. 流量控制与拥塞控制

| 机制 | 解决的问题 | 主要依据 |
| --- | --- | --- |
| [流量控制](FlowControl.md) | 避免发送量超过接收方的接收能力 | 接收方通告的接收窗口（rwnd） |
| 拥塞控制 | 根据网络状况调整发送量，缓解拥塞 | 发送方维护的拥塞窗口（cwnd）等状态 |

发送方能够保持在途、尚未确认的数据量同时受到接收窗口和拥塞窗口的限制。慢启动、拥塞避免等算法用于逐步探测和调整网络可承受的发送量，具体行为取决于采用的拥塞控制算法。

## 6. 常见用途

HTTP/1.1、HTTP/2 和 SSH 等协议通常使用 TCP。应用需要自行定义消息边界，例如使用固定长度、长度字段或分隔符；需要加密与身份认证时，可以在 TCP 之上使用 TLS 等安全协议。
