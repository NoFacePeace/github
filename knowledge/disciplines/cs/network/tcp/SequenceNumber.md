# TCP 序列号

序列号（Sequence Number，常记为 Seq）是 TCP 首部中的 32 位字段，用于标识发送方向上的字节位置，帮助接收方排序数据、识别重复数据并发现缺口。

## 1. 按字节编号

TCP 对字节流中的每个字节编号，而不是给每个报文段分配一个递增编号。普通数据报文段的序列号表示其第一个数据字节的编号。

```text
报文段 A：Seq=1001，数据长度=100
          字节编号 1001～1100

报文段 B：Seq=1101，数据长度=200
          字节编号 1101～1300

下一个新数据字节的序列号：1301
```

重传相同位置的数据时，仍使用对应的字节序列号；报文段边界可以变化，不会给重传的数据重新分配字节编号。

## 2. 初始序列号

连接建立时，双方分别选择初始序列号（ISN，Initial Sequence Number），通过 SYN 报文段交换。两个传输方向各自维护独立的序列号空间。

SYN 占用一个序列号。例如，客户端发送 `SYN, Seq=1000`，其第一个数据字节的序列号为 `1001`。

抓包工具可能显示相对序列号，把初始序列号显示为 `0`，便于观察连接中的字节位置；这不表示实际 TCP 首部中的初始序列号就是 `0`。

## 3. 序列号的消耗

```text
序列空间长度 = 数据字节数 + SYN 占用的 1 + FIN 占用的 1
```

只有设置了 SYN 或 FIN 时才计入对应的 `1`。不携带数据且没有 SYN、FIN 的纯 ACK 报文段不占用序列号；ACK 标志本身也不会额外消耗序列号。

例如，`FIN, Seq=1301` 不携带数据时，对方收到后确认 `1302`，表示该方向的结束标记也已被接收。

## 4. 回绕与排序

序列号取值范围为 `0`～`2^32 - 1`，按模 `2^32` 运算，到达最大值后会回绕到 `0`。

因此，TCP 判断序列号先后时需要采用序列空间中的比较规则，不能直接把普通整数的大小关系当作传输顺序。接收窗口等限制使接收方能够在有效范围内区分新数据、旧数据和重复数据。
