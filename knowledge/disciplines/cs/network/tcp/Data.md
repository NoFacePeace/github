# TCP 数据

TCP 数据（TCP Data，也称负载 Payload）是 TCP 报文段中位于首部之后的部分，用于承载应用交给 TCP 传输的字节，不包含 TCP 首部和 IP 首部。

## 1. 所在位置

```text
TCP 报文段
├── TCP 首部       20～60 字节
└── TCP 数据       长度可变，可以为空
```

TCP 首部中的数据偏移字段以 4 字节为单位表示首部长度，用于定位数据部分的起点。TCP 首部没有单独的数据长度字段，接收方根据 IP 层确定的 TCP 报文段总长度减去 TCP 首部长度，得到数据长度。

## 2. 数据内容

TCP 把应用数据视为字节流，不解释其中的业务含义。数据可以是文本、二进制文件、应用协议消息，也可以是 TLS 等上层协议封装后的内容。

```text
应用生成消息 → 转换或封装为字节 → TCP 传输 → 对端应用解析
```

字符编码、消息格式、加密和业务处理规则由上层协议或应用决定，TCP 本身不提供数据加密。

## 3. 数据长度与分段

单个报文段的数据长度受对端通告的 MSS、路径 MTU、可用发送窗口等条件限制。应用一次写入的数据可以拆成多个报文段，多次写入的数据也可能合并到同一个报文段中。

例如，实际每段最多承载 1460 字节数据时，3000 字节应用数据可以拆为：

```text
报文段 A：1460 字节数据
报文段 B：1460 字节数据
报文段 C：  80 字节数据
合计：    3000 字节数据
```

这只是可能的分段方式。实际分段取决于发送时机、窗口大小和协议实现等因素。

## 4. 字节流与消息边界

TCP 不保留应用消息边界。接收方的一次读取可能只得到一条消息的一部分，也可能得到多条消息的数据。

```text
发送方写入： [消息 A][消息 B]
接收方读取： [A 的前半段][A 的后半段 + B]
```

应用需要通过长度字段、分隔符、固定长度等方式识别完整消息，不能把一次读取或一个报文段当作一条完整消息。

## 5. 空数据与可靠交付

数据部分可以为空，例如常见的纯 ACK 报文段。没有数据不等于没有作用：报文段仍可携带确认、窗口更新和连接控制信息。

TCP 使用序列号对数据字节编号，接收方处理乱序与重复数据后，按顺序向应用交付字节流。TCP 确认表示对端 TCP 已接收对应数据，不代表对端应用已读取、处理或持久化数据。
