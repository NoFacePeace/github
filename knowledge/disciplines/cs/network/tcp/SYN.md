# SYN 标志

SYN（Synchronize，同步）是 TCP 首部中的一个控制标志，用于在建立连接时同步初始序列号。SYN 置为 `1` 时，报文段的序列号字段表示发送方的初始序列号（ISN，Initial Sequence Number）。

## 1. 在三次握手中的作用

常见的连接建立过程如下：

```text
客户端                                  服务器
  | ---- SYN, Seq=1000 ----------------> |
  | <--- SYN + ACK, Seq=5000, Ack=1001 -- |
  | ---- ACK, Seq=1001, Ack=5001 -------> |
```

客户端和服务器分别通告自己的初始序列号，并确认对方的初始序列号。两个传输方向使用独立的序列号空间，不需要选择相同的初始值。

## 2. 占用一个序列号

SYN 即使不携带数据，也占用一个序列号。因此，初始序列号为 `1000` 时，对方确认 `1001`，该方向的第一个数据字节也从 `1001` 开始编号。

```text
SYN 的序列号：      1000
第一个数据字节：    1001
```

SYN 不是应用数据字节，但需要被可靠确认。SYN 或其确认丢失时，发送方可能重传 SYN；同一次连接尝试中的重传不会因此换一个新的初始序列号。

## 3. SYN 与 SYN + ACK

单独设置 SYN 通常用于主动发起连接。`SYN + ACK` 同时表示同步自身的初始序列号，以及确认对方的序列号。

SYN 和 ACK 是两个独立标志，并没有一个单独的“SYN-ACK 标志位”。`SYN-ACK` 是同时设置这两个标志的报文段的常用名称。

## 4. 建立连接时的选项

携带 SYN 的报文段可以通过 TCP 选项通告 MSS、窗口扩大、SACK 许可和时间戳等参数或能力。不同选项的通告、协商规则不同，不一定形成一个双方共用的数值。

MSS 和窗口扩大选项只在携带 SYN 的报文段中发送；支持这些选项时，通常在客户端 SYN 和服务器 SYN + ACK 中分别携带。

## 5. SYN 与数据

常见的三次握手示例中，SYN 不携带应用数据，但协议允许某些场景中的 SYN 携带数据。例如，TCP Fast Open 在满足相应条件时允许在 SYN 中携带应用数据。

因此，SYN 置位不意味着数据部分一定为空。SYN 本身占用一个序列号，若同时携带数据，数据字节从初始序列号之后开始编号。
