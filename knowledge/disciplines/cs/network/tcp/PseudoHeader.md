# TCP 伪首部

TCP 伪首部（TCP Pseudo Header，也称 IP 伪首部）是计算 TCP 校验和时使用的一组辅助信息，包含 IP 地址、协议标识和 TCP 长度等内容。它由通信双方根据 IP 层信息等构造，不是实际 TCP 首部的一部分，也不会作为额外首部随报文发送。

## 1. 为什么需要伪首部

TCP 首部携带端口，但不携带源 IP 和目的 IP。把地址、协议和长度信息纳入校验和，可以把 TCP 报文段与网络层的传输信息关联起来，帮助检测地址等信息损坏造成的误投递。

```text
实际传输：
[ IP 首部及可能的扩展首部 ][ TCP 首部 ][ TCP 数据 ]

校验和计算输入：
[ 构造的伪首部 ][ TCP 首部 ][ TCP 数据 ]
```

伪首部不等于完整 IP 首部。例如，TTL 或跳数限制不参与 TCP 校验和计算，否则路由器每次转发并修改这些字段时，都需要重新计算 TCP 校验和。

## 2. IPv4 伪首部

IPv4 伪首部共 12 字节，每行 32 位：

```text
+-------------------------------+-------------------------------+
|                    Source IPv4 Address (32)                   |
+-------------------------------+-------------------------------+
|                 Destination IPv4 Address (32)                 |
+---------------+---------------+-------------------------------+
|   Zero (8)    | Protocol (8)  |        TCP Length (16)        |
+---------------+---------------+-------------------------------+
```

| 字段 | 长度 | 含义 |
| --- | --- | --- |
| 源 IPv4 地址 | 32 位 | 发送方地址 |
| 目的 IPv4 地址 | 32 位 | 接收方地址；使用源路由时应取最终目的地址 |
| 零 | 8 位 | 填写为零 |
| 协议号 | 8 位 | TCP 的协议号为 `6` |
| TCP 长度 | 16 位 | TCP 首部与数据的总长度，不包含 IP 首部 |

例如，TCP 首部为 20 字节、数据为 100 字节时，伪首部中的 TCP 长度为 `120` 字节。伪首部自身的 12 字节不计入这个长度。

## 3. IPv6 伪首部

IPv6 伪首部共 40 字节：

```text
+---------------------------------------------------------------+
|                    Source IPv6 Address (128)                  |
|                           16 bytes                            |
+---------------------------------------------------------------+
|                 Destination IPv6 Address (128)                 |
|                           16 bytes                            |
+---------------------------------------------------------------+
|                 Upper-Layer Packet Length (32)                |
+-----------------------------------------------+---------------+
|                   Zero (24)                   |Next Header (8)|
+-----------------------------------------------+---------------+
```

| 字段 | 长度 | 含义 |
| --- | --- | --- |
| 源 IPv6 地址 | 128 位 | 发送方地址 |
| 目的 IPv6 地址 | 128 位 | 通常为 IPv6 目的地址；存在路由首部时使用最终目的地址 |
| 上层报文长度 | 32 位 | TCP 首部与数据的总长度，不包含 IPv6 首部和扩展首部 |
| 零 | 24 位 | 填写为零 |
| 下一首部 | 8 位 | 标识 TCP，值为 `6` |

存在 IPv6 扩展首部时，IPv6 基本首部的“下一首部”可能指向扩展首部，而伪首部中的“下一首部”仍填写 TCP 的协议标识 `6`。

## 4. 计算与验证

发送方构造伪首部，将它与 TCP 首部、数据一起计算校验和，把结果写入 TCP 首部。接收方根据收到的 IP 信息等构造对应的伪首部，再验证校验和。

因此，抓包中不会出现单独的“伪首部字节区”。如果 NAT 改写了 IP 地址或 TCP 端口，就需要相应调整 TCP 校验和，以反映变化后的计算输入。

## 5. 能力限制

伪首部扩大了校验和的覆盖范围，但不会使 TCP 校验和成为安全认证机制。攻击者仍可修改报文并重新计算校验和；伪首部也不提供数据加密。
