# TCP 四次挥手

四次挥手是 TCP 正常关闭连接的常见过程，英文常称 Four-Way Handshake 或 Four-Way Termination。TCP 的两个传输方向分别关闭，双方各发送 FIN 表示结束自己的发送方向，并由对方确认。

## 1. 关闭过程

下面以客户端主动关闭、服务器随后关闭为例。假设 FIN 不携带数据，服务器在两次关闭之间也没有发送额外数据；客户端和服务器下一个可用的序列号分别为 `1001` 和 `5001`。

```text
客户端                                          服务器
ESTABLISHED                                     ESTABLISHED
  |                                                |
  | ---- FIN + ACK, Seq=1001, Ack=5001 ------------> |
FIN-WAIT-1                                         |
  |                                              CLOSE-WAIT
  | <--- ACK, Seq=5001, Ack=1002 ------------------- |
FIN-WAIT-2                                         |
  |                                                | 应用决定关闭
  | <--- FIN + ACK, Seq=5001, Ack=1002 ------------- |
  |                                              LAST-ACK
  | ---- ACK, Seq=1002, Ack=5002 ------------------> |
TIME-WAIT                                       CLOSED
  |
等待 2×MSL
  |
CLOSED
```

### 1.1 第一次：主动关闭方发送 FIN

客户端发送 FIN，表示自己没有更多数据要发送，并进入 FIN-WAIT-1。客户端仍可接收服务器的数据。

### 1.2 第二次：对方确认 FIN

服务器收到 FIN 后确认，进入 CLOSE-WAIT。客户端收到对自己 FIN 的确认后，进入 FIN-WAIT-2。

服务器的发送方向尚未关闭，仍可继续发送数据。CLOSE-WAIT 表示等待服务器应用关闭自身的发送方向，不表示服务器必须马上发送 FIN。

### 1.3 第三次：对方发送 FIN

服务器应用完成发送后，服务器发送自己的 FIN，并进入 LAST-ACK，等待客户端确认。

### 1.4 第四次：主动关闭方确认 FIN

客户端确认服务器的 FIN，进入 TIME-WAIT。服务器收到有效确认后进入 CLOSED；客户端等待 TIME-WAIT 到期后再进入 CLOSED。

## 2. 为什么通常是四次

TCP 是全双工通信，两个方向可以分别结束。收到对方的 FIN 只表示对方停止发送，不表示自己也没有数据要发送，因此确认对方和关闭自身通常分开进行。

如果接收 FIN 的一方也已准备好关闭，可以把 ACK 和自身的 FIN 合并，实际关闭过程可能只有三个报文段。双方同时关闭时，还可能经过 CLOSING 状态，因此上述四步不是所有连接的唯一关闭路径。

## 3. FIN 与序列号

FIN 沿用当前连接已有的序列号，不会重新选择随机初始值。它即使没有数据，也占用一个序列号；ACK 标志本身不占用序列号。

```text
初始序列号：1000
SYN：       1000，占用一个序列号
数据：      1001～1100，共 100 字节
FIN：       1101
对方确认：  Ack=1102
```

如果 FIN 与数据一起发送，数据先占用对应的字节编号，FIN 占用数据之后的一个序列号。无回绕时，对全部数据和 FIN 的确认号为 `Seq + 数据长度 + 1`；实际按模 `2^32` 运算。

双方分别维护独立的序列号空间，所以双方 FIN 的序列号取决于各自已经发送的数据量，不要求相同。

## 4. TIME-WAIT 的作用

常见关闭流程中，主动关闭方发送最后的 ACK 后进入 TIME-WAIT，继续保留连接状态，主要有两个作用。

### 4.1 应对最后的 ACK 丢失

如果最后的 ACK 丢失，服务器无法确认自己的 FIN 已被接收，会重传 FIN。客户端保留状态后，可以再次回复 ACK。

```text
服务器 → FIN → 客户端
服务器 ← ACK ← 客户端  （ACK 丢失）
服务器 → 重传 FIN → 客户端
服务器 ← 再次 ACK ← 客户端
```

符合条件的重传 FIN 到达后，TIME-WAIT 定时器会重新启动。

### 4.2 减少旧报文对新连接的干扰

网络中可能还存在旧连接的延迟或重复报文。如果相同的源 IP、源端口、目的 IP、目的端口立即被用于新连接，旧报文可能到达新连接的处理逻辑。

序列号检查通常可以拒绝旧报文，但仍需考虑序列号范围重叠等情况。TIME-WAIT 暂时限制同一四元组的复用，让旧报文有时间失效，降低误接受的风险；这不表示同一个本地端口不能服务其他四元组的连接。

## 5. 等待时间与其他关闭方式

TIME-WAIT 的经典等待时间为 `2×MSL`。MSL（Maximum Segment Lifetime）表示报文段在网络中可能存活的最长时间，具体取值由系统实现决定，不能统一认为所有系统都等待相同秒数。

任意一方都可以主动关闭，并非只有客户端会进入 TIME-WAIT；同时关闭时双方也可能进入该状态。

RST 用于复位连接，属于中止或拒绝等处理，不执行上述正常 FIN 关闭过程。FIN 确认也不代表对端应用已经完成业务处理，业务完成情况仍需应用协议确认。
