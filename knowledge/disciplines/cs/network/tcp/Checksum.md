# TCP 校验和

TCP 校验和（TCP Checksum）是 TCP 首部中的 16 位字段，用于检测报文在传输中发生的损坏。发送方计算并填写校验和，接收方重新验证；验证失败的报文段会被丢弃。

## 1. 计算范围

TCP 校验和的计算范围包括 [IP 伪首部](PseudoHeader.md)、[TCP 首部](Header.md)和全部 [TCP 数据](Data.md)。

```text
参与校验和计算的内容
├── IP 伪首部       由 IP 信息等构造，不属于实际 TCP 首部
├── TCP 首部        包括选项和填充
└── TCP 数据        可以为空
```

IP 伪首部用于把 TCP 报文段与网络层的地址、协议和长度信息关联起来，帮助检测误投递等错误。IPv4 和 IPv6 的伪首部格式不同。

### 1.1 IPv4 伪首部

IPv4 伪首部共 12 字节：

| 字段 | 长度 | 含义 |
| --- | --- | --- |
| 源 IPv4 地址 | 32 位 | 发送方地址 |
| 目的 IPv4 地址 | 32 位 | 接收方地址 |
| 零 | 8 位 | 填写为零 |
| 协议号 | 8 位 | TCP 的协议号为 `6` |
| TCP 长度 | 16 位 | TCP 首部与数据的总长度，不包含 IP 首部 |

### 1.2 IPv6 伪首部

IPv6 伪首部共 40 字节：

| 字段 | 长度 | 含义 |
| --- | --- | --- |
| 源 IPv6 地址 | 128 位 | 发送方地址 |
| 目的 IPv6 地址 | 128 位 | 通常为 IPv6 目的地址；存在路由首部时使用最终目的地址 |
| 上层报文长度 | 32 位 | TCP 首部与数据的总长度，不包含 IPv6 首部和扩展首部 |
| 零 | 24 位 | 填写为零 |
| 下一首部 | 8 位 | 标识 TCP，值为 `6` |

## 2. 计算过程

TCP 使用 16 位反码校验和（One's Complement Checksum）：

1. 将 TCP 首部中的校验和字段暂时置为 `0`。
2. 将伪首部、TCP 首部和数据按网络字节序划分为 16 位字。
3. 如果总长度为奇数字节，在末尾补一个零字节，仅用于计算，不作为额外数据发送。
4. 使用反码加法累加所有 16 位字：把高于 16 位的进位加回低 16 位，直到没有进位。
5. 对结果逐位取反，写入校验和字段。

```text
示例：仅演示两个 16 位字的运算

相加：0xFFFF + 0x0001 = 0x10000
回卷：0x0000 + 0x0001 = 0x0001
取反：~0x0001 & 0xFFFF = 0xFFFE
```

实际 TCP 校验和必须覆盖完整的伪首部、首部和数据，不能只计算示例中的两个字。

## 3. 接收方验证

接收方使用相同的伪首部与计算规则，把收到的校验和字段也参与累加。正确报文的最终反码和应为 `0xFFFF`，全部位为 `1`；如果再取反，则结果为 `0x0000`。

校验失败时，TCP 丢弃该报文段，不会通过损坏的数据推进确认号。发送方可能随后因超时或丢失检测重传相应数据。

## 4. 能力与限制

- **检测损坏**：可以发现许多传输错误，但只有 16 位，不能保证检测所有错误。
- **不提供安全认证**：它不是密码学哈希、消息认证码或数字签名，攻击者可以修改数据并重新计算校验和。
- **不提供加密**：校验和不会隐藏数据内容；需要保密性和身份认证时，应使用 TLS 等安全协议。

IPv4 首部校验和只覆盖 IPv4 首部，TCP 校验和则覆盖 TCP 首部、数据和伪首部，两者作用不同。IPv6 基本首部没有首部校验和，TCP 校验和仍然需要计算。

## 5. 抓包中的校验和卸载

网卡可以代替操作系统计算发送报文的 TCP 校验和，这称为校验和卸载（Checksum Offload）。本机抓包可能发生在网卡填写最终校验和之前，因此抓包工具有时会显示校验和错误或尚未验证。

这种显示不一定意味着线上实际发送的报文损坏，需要结合抓包位置、网卡卸载设置以及对端抓包结果判断。
