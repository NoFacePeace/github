# TCP 初始序列号

初始序列号（ISN，Initial Sequence Number）是 TCP 建立连接时为一个发送方向选择的起始[序列号](SequenceNumber.md)，通过 SYN 报文段通告给对方。它是一个 32 位值，客户端和服务器分别选择自己的 ISN。

## 1. 是否随机

ISN 通常以难以预测的方式生成，不一定是直接生成一个纯随机数。现代实现通常结合随时间变化的值、连接四元组和带密钥的函数，使初始值既随连接变化，也难以被外部猜中。

一种标准化的生成思路可以概括为：

```text
ISN = M + F(源 IP, 源端口, 目的 IP, 目的端口, 密钥)
      按模 2^32 运算

M：随时间变化的计数值
F：带密钥的函数，输出难以预测的连接相关值
```

具体算法、密钥管理和更新方式取决于操作系统实现，不能假设每个系统都采用完全相同的公式细节。

## 2. 为什么需要这样的初始值

- **区分连接实例**：同一组地址和端口可能被再次使用，需要结合序列号等机制减少旧连接延迟报文对新连接的干扰。
- **降低伪造风险**：如果初始值很容易预测，攻击者更容易构造可能被接受的伪造 TCP 报文。

ISN 的生成并不能单独解决旧报文问题，TCP 还依赖状态检查、序列号窗口、TIME-WAIT 等机制。难以预测的 ISN 也不等于身份认证，更不能替代 TLS 等安全协议。

## 3. 在握手中的作用

假设客户端选择 `1000`，服务器选择 `5000`，握手报文均不携带数据：

```text
客户端 → 服务器：SYN，Seq=1000
服务器 → 客户端：SYN + ACK，Seq=5000，Ack=1001
客户端 → 服务器：ACK，Seq=1001，Ack=5001
```

两个方向拥有独立的序列号空间，初始值不需要相等，也不要求存在特定差值。示例中的 `1000` 和 `5000` 只是为了方便阅读，并非固定值。

## 4. 后续序列号如何推进

SYN 占用一个序列号，因此该方向的第一个数据字节从 `ISN + 1` 开始编号。连接建立后，数据按字节推进序列号，不会为每个报文段重新选择随机值。

```text
ISN = 1000
SYN：               Seq=1000，占用 1 个序列号
第一段 100 字节：   Seq=1001，字节编号 1001～1100
下一段数据：        Seq=1101
```

重传相同位置的数据仍使用对应的字节编号。同一次连接尝试中重传 SYN，也不会因此重新选择 ISN。

## 5. 回绕与抓包显示

ISN 和后续序列号都按模 `2^32` 运算，超过 `4294967295` 后回绕到 `0`。例如 ISN 为 `4294967295` 时，不携带数据的 SYN 对应确认号为 `0`。

抓包工具可能采用相对序列号，把初始序列号显示为 `0`，把首个数据字节显示为 `1`。这只是显示方式，不表示实际报文中的 ISN 就是零；查看原始序列号才能看到首部中的实际值。
