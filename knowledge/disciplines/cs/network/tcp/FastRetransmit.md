# TCP 快速重传

快速重传（Fast Retransmit）利用重复确认推断数据可能丢失，不必等到重传定时器到期。经典算法在收到三个重复 ACK 后触发重传。

它是 [TCP 重传](Retransmission.md)的一种方式。

## 1. 过程示例

假设每段携带 100 字节数据，接收方下一步期望收到序列号为 `1001` 的字节：

```text
发送方                              接收方
  | ---- Seq=1001, Len=100 --------X  |  数据丢失
  | ---- Seq=1101, Len=100 --------> |
  | <----------- ACK=1001 ---------- |  重复 ACK 1
  | ---- Seq=1201, Len=100 --------> |
  | <----------- ACK=1001 ---------- |  重复 ACK 2
  | ---- Seq=1301, Len=100 --------> |
  | <----------- ACK=1001 ---------- |  重复 ACK 3
  | ---- 重传 Seq=1001, Len=100 ----> |
  | <----------- ACK=1401 ---------- |  缺口补齐，累计确认
```

## 2. 重复确认与丢失推断

这里假设接收方此前已发出 `ACK=1001`，并缓存了随后到达的乱序数据。重复 ACK 表示累计确认号没有前进；它也可能由乱序引起，因此快速重传依据的是丢失推断，不是确定的丢失通知。

## 3. 适用限制

如果丢失的是最后一个报文段，或后续数据不足以产生三个重复 ACK，经典快速重传可能无法触发，需要依赖超时重传或其他丢失检测机制。

快速重传用于重新发送疑似丢失的数据；快速恢复（Fast Recovery）则是配套调整拥塞窗口的机制，两者含义不同。
