# TCP 窗口

TCP 首部中的窗口字段（Window）是一个 16 位字段，用于通告接收窗口（rwnd，Receive Window），表示发送该报文的一方允许对端继续发送的字节范围大小。它是 TCP 流量控制的依据。

## 1. 窗口表示什么

窗口大小以字节为单位，不表示报文段数量，也不表示应用消息数量。窗口与确认号一起描述当前允许接收的序列号范围。

忽略序列号回绕时：

```text
接收范围：[确认号, 确认号 + 接收窗口)

确认号 = 1001
接收窗口 = 3000 字节
允许接收的字节序列号：1001～4000
```

双方分别通告自己的接收窗口，两个传输方向的窗口可以不同。接收窗口通常与接收缓冲区的可用空间相关，但还受操作系统的缓冲区管理和窗口更新策略影响。

## 2. 字段值与窗口扩大

未启用窗口扩大时，窗口字段直接表示接收窗口大小，范围为 `0`～`65535` 字节。

建立连接时，双方可以通过窗口扩大选项（Window Scale）交换缩放因子，以表示更大的接收窗口：

```text
实际接收窗口 = 窗口字段值 × 2^缩放因子

窗口字段值 = 32768
缩放因子   = 4
实际窗口   = 32768 × 16 = 524288 字节
```

缩放因子最大为 `14`，双方可以使用不同的值。只有双方都发送了窗口扩大选项时才启用该机制；携带 SYN 的报文段自身的窗口字段不进行缩放。

## 3. 滑动窗口

随着接收方连续收到数据并发送确认，确认号前进，窗口覆盖的序列号范围也可以向前移动。

```text
第一次通告：ACK=1001，rwnd=3000 → 范围 1001～4000
随后通告：  ACK=2001，rwnd=3000 → 范围 2001～5000
```

发送方可以连续发送窗口允许范围内的数据，不必每发一个报文段就等待一次确认。但已经发送、尚未确认的数据也占用窗口，不能把每次收到的窗口值直接当作额外可发送的数据量。

## 4. 零窗口

窗口为 `0` 表示接收方暂时无法接收更多普通新数据，不表示连接已经关闭。常见原因是应用读取较慢，接收缓冲区暂时没有可用空间。

接收方释放空间后可以通告非零窗口。发送方使用持续定时器安排零窗口探测，获取当前窗口信息，避免因窗口更新丢失而一直等待。

## 5. 与拥塞窗口的区别

| 窗口 | 维护方 | 含义 | 是否由 TCP 窗口字段携带 |
| --- | --- | --- | --- |
| 接收窗口 rwnd | 接收方 | 限制对端发送量，反映接收能力 | 是，可能需要按缩放因子解释 |
| 拥塞窗口 cwnd | 发送方 | 根据网络状况限制在途数据量 | 否，是发送方内部状态 |

实际发送量同时受到两者约束。在常见的简化模型中，允许在途的数据量约为 `min(rwnd, cwnd)`；继续发送新数据前，还需扣除已经在途的数据量。
