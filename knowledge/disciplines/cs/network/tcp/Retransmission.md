# TCP 重传

TCP 重传（TCP Retransmission）是 [TCP](TCP.md) 实现可靠传输的机制之一。发送方保留尚未确认的数据，在重传定时器超时或根据确认信息判断数据可能丢失时，重新发送对应的数据。

TCP 使用[序列号](SequenceNumber.md)标识数据的字节位置，使用[确认号](AcknowledgmentNumber.md)表示接收方下一步期望收到的位置，为重传提供依据。

## 1. 为什么需要重传

网络可能丢失承载数据的 IP 数据包，也可能丢失接收方返回的确认报文。发送方无法仅凭“没有收到确认”确定是哪一种情况，因此需要通过定时器和确认信息决定是否重传。

如果原始数据已经到达，只是确认丢失，重传可能产生重复数据。接收方利用序列号识别重复字节，避免向应用重复交付。

## 2. 超时重传

[超时重传（Timeout Retransmission）](TimeoutRetransmission.md)指重传定时器到期后，发送方重传最早尚未确认的数据。重传超时时间（RTO）根据往返时间及其波动估计，并在超时后采用指数退避。

## 3. 快速重传

[快速重传（Fast Retransmit）](FastRetransmit.md)利用重复确认推断数据可能丢失，不必等到重传定时器到期。经典算法在收到三个重复 ACK 后触发重传。

## 4. 选择性确认与丢失检测

选择性确认（SACK，Selective Acknowledgment）允许接收方在累计确认之外，报告已经收到的不连续数据范围。发送方可以据此识别缺口，优先重传缺失数据，减少对已收到数据的不必要重传。

SACK 本身是确认信息，不是一种单独的重传触发方式。实际 TCP 实现还可能使用基于时间的 RACK 等丢失检测机制，因此并非所有重传都严格由“三个重复 ACK”触发。

## 5. 与分段、分片的关系

TCP 重传针对字节序列中的数据，重传时的报文段边界不一定与原始发送相同，实际分段仍受 MSS、路径 MTU 等限制。

如果一个 IP 数据包被分片，而其中某个分片丢失，目的主机无法完整重组该数据包，TCP 也就收不到其中的报文段。TCP 可以重传对应的数据，但不能只要求重传某个 IP 分片。

## 6. 与拥塞控制的关系

重传用于恢复可能丢失的数据，拥塞控制用于调整发送量。TCP 通常把丢失视为可能的拥塞信号，在超时或快速重传时相应调整拥塞窗口；具体调整方式取决于拥塞控制算法。

重传不保证无限等待后一定成功。当连接长期无法取得进展时，TCP 可能超时并向应用报告错误。
