# TCP 标志

TCP 标志（TCP Flags，也称控制标志）是 TCP 首部中的一组位，用于表示连接建立、确认、关闭、复位和拥塞通知等信息。多个标志可以同时设置，每个标志按其含义参与报文处理。

## 1. 常见标志

| 标志 | 英文名称 | 作用 |
| --- | --- | --- |
| [SYN](SYN.md) | Synchronize | 同步初始序列号，用于建立连接 |
| [ACK](ACK.md) | Acknowledgment | 表示确认号字段有效 |
| FIN | Finish | 表示发送方在该方向没有更多数据要发送 |
| RST | Reset | 复位连接，例如拒绝某些无对应连接的报文或中止连接 |
| PSH | Push | 提示接收方及时向应用交付数据 |
| URG | Urgent | 表示紧急指针字段有效 |
| ECE | ECN-Echo | 在经典 ECN 中用于反馈拥塞，也参与建立连接时的 ECN 能力协商 |
| CWR | Congestion Window Reduced | 在经典 ECN 中表示发送方已响应拥塞通知，也参与 ECN 能力协商 |

以上列出常见标志。协议扩展还可能定义额外标志或改变部分位的解释方式，具体含义需要结合双方协商的能力判断。

## 2. SYN 与 ACK

常见的三次握手使用以下标志组合：

```text
客户端                           服务器
  | ---------- SYN ------------> |
  | <------- SYN + ACK --------- |
  | ---------- ACK ------------> |
```

SYN 表示同步序列号，ACK 表示确认号有效。ACK 标志本身只是一个位，不能与确认号的数值混为一谈。例如 `ACK=1101` 通常是在描述确认号，而不是 ACK 标志的取值。

连接建立后的报文段通常设置 ACK 标志，确认信息也可以与本方向的数据一起发送。

## 3. FIN 与 RST

FIN 用于正常关闭一个传输方向。发送 FIN 的一方表示自己没有更多数据，但仍可接收另一方向的数据，直到对方也关闭其发送方向。

RST 用于复位连接，属于中止或拒绝等处理，不执行正常的 FIN 关闭过程。接收方是否接受一个 RST，还取决于连接状态、序列号等校验条件。

SYN 和 FIN 各占用一个序列号；ACK 标志本身不占用序列号，纯 ACK 报文段在没有数据、SYN 和 FIN 时不推进发送序列号。

## 4. PSH 与 URG

PSH 提示接收方及时将数据交付给应用，但不定义应用消息边界，也不保证应用立即运行或读取数据。应用仍需按自己的协议解析字节流。

URG 表示紧急指针有效。紧急机制用于标记字节流中的紧急数据边界，不等于网络优先级，也不是 TCP 提供的一条独立传输通道；现代应用较少使用这一机制。

## 5. ECE 与 CWR

显式拥塞通知（ECN，Explicit Congestion Notification）允许网络设备通过 IP 层的拥塞标记反馈拥塞，而不必仅依靠丢包。

经典 ECN 中，接收方通过 ECE 向发送方反馈拥塞，发送方调整拥塞窗口后通过 CWR 表示已作出响应。SYN 阶段的 ECE、CWR 组合则用于协商能力，不能直接按数据传输阶段的含义解释。

## 6. 标志与数据的关系

标志不决定数据部分一定为空。报文段可以同时携带数据与控制信息，例如 `ACK + PSH` 携带应用数据，`FIN + ACK` 也可能携带该方向最后的数据。

```text
SYN + ACK：同步自身序列号，同时确认对方
ACK + PSH：确认收到的数据，并提示交付本段数据
FIN + ACK：结束自身发送方向，同时确认对方
```

标志的组合需结合连接状态解释，并非任意组合在任意状态下都有效。
