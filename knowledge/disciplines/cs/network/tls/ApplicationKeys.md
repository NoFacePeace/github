# 应用密钥

应用密钥是 TLS 1.3 中用于加密应用数据记录的对称密钥，例如保护 HTTP 请求和响应。它与保护握手消息的握手密钥分开派生和使用。

## 1. 派生方式

TLS 1.3 由 Handshake Secret 进一步派生 Master Secret，并结合从 ClientHello 到服务端 Finished 为止的握手记录哈希，派生初始应用流量秘密：

| 方向 | 流量秘密的派生标签 |
| --- | --- |
| 客户端 → 服务端 | `c ap traffic` |
| 服务端 → 客户端 | `s ap traffic` |

再从每个方向的应用流量秘密使用 HKDF-Expand-Label，以 `key` 和 `iv` 为标签，分别派生实际加密密钥和 IV。参与派生的握手记录是消息内容的哈希，不是加密密文，也不包含客户端 Finished。

## 2. 加密与解密

| 传输方向 | 加密方 | 解密方 | 使用的密钥 |
| --- | --- | --- | --- |
| 客户端 → 服务端 | 客户端 | 服务端 | 客户端发送方向的应用密钥 |
| 服务端 → 客户端 | 服务端 | 客户端 | 服务端发送方向的应用密钥 |

双方按相同规则在本地派生密钥，无需直接传输密钥。每条记录的 nonce 由该方向的 IV 与记录序号组合得到，配合 AES-GCM 或 ChaCha20-Poly1305 等认证加密算法保护数据并检测篡改。

## 3. 使用时机与更新

客户端验证服务端 Finished 并发送自己的 Finished 后，就可以发送由应用密钥保护的数据，无需再等服务端回复。客户端 Finished 自身仍使用握手密钥加密。

应用通信期间，KeyUpdate 可以从当前应用流量秘密派生下一代秘密，再生成新的加密密钥和 IV。客户端发送和服务端发送两个方向独立更新。
