# 证书

数字证书是一份将身份信息与公钥绑定的凭证。TLS 通常使用 X.509 证书；在常见的 HTTPS 场景中，服务器证书将域名与服务器公钥关联起来。

## 1. 证书内容

| 内容 | 作用 |
| --- | --- |
| 主体及域名信息 | 标识证书主体；网站域名通常记录在 Subject Alternative Name（SAN）扩展中 |
| 主体公钥 | 用于验证主体使用对应私钥生成的签名等 |
| 有效期 | 限定证书的有效时间范围 |
| 颁发者 | 标识签发该证书的 CA |
| 用途与约束 | 限定公钥用途、是否能作为 CA 签发证书等 |
| 颁发者签名 | 保护被签名的证书内容，并关联到颁发者密钥 |

证书不包含主体私钥。证书内容可以公开，签发是对内容进行数字签名，而不是将整张证书加密。

## 2. 在 TLS 中的作用

客户端需要确认当前对端有资格代表所访问的域名：

1. 验证证书是否可信、是否匹配访问域名，并检查有效期与用途等。
2. 使用证书中的公钥验证握手中的 CertificateVerify 签名，确认对端持有相应私钥。

仅出示证书不够，因为证书可以被复制；对端还必须证明自己持有私钥。普通域名验证证书主要证明域名身份，不一定证明背后的具体个人或公司。

## 3. 与公钥和数字签名的关系

证书可以简化理解为“身份、公钥、有效期等信息 + 颁发者对这些信息的数字签名”。[数字签名](../../../cryptography/DigitalSignature.md)提供私钥签名、公钥验证的机制。

浏览器预先信任的通常是根 CA 及其公钥，而不是每个网站的公钥。服务器需要发送自己的证书以及通常所需的中间 CA 证书，供客户端建立验证路径；根证书通常无需发送。

证书中的身份公钥与 Hello 中 ECDHE 的临时密钥交换公钥用途不同：前者用于验证身份签名，后者用于计算共享秘密。应用数据由派生的对称密钥加密。
