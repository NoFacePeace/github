# TLS 协议

TLS（Transport Layer Security，传输层安全协议）用于为应用程序之间的通信提供加密、完整性校验和身份认证。HTTPS 就是通过 TLS 保护的 HTTP 通信方式。

## 1. 核心作用

- [证书](certificates/Certificate.md)：身份、公钥与信任链。

- **加密**：防止旁观者直接读取传输内容。
- **完整性校验**：检测传输中的数据是否被篡改。
- **身份认证**：通常通过服务器证书验证服务器身份，也可以使用客户端证书进行双向认证。

TLS 保护通信连接，不能保证通信对端提供的内容本身可信。

## 2. 协议分层

TLS 没有严格对应 OSI 模型的某一层。按功能通常类比为表示层，也涉及会话层功能；在 TCP/IP 模型中，通常归入[应用层](../ApplicationLayer.md)。名称中的“传输层安全”不代表它属于 TCP/IP 模型的传输层。

传统 TLS 位于应用协议与可靠传输协议之间，例如基于 TCP 的 HTTPS：

```text
HTTP
  ↓
TLS
  ↓
TCP
  ↓
IP
```

HTTP/3 使用 QUIC，QUIC 集成 TLS 1.3 的握手和密钥派生机制，并由自身机制保护数据包，底层通过 UDP 传输。

## 3. 握手与数据传输

详细流程见 [TLS 握手](Handshake.md)。

以常见的基于证书认证的 TLS 1.3 完整握手为例：

1. 客户端与服务器协商 TLS 版本、密码套件等参数，并交换密钥协商所需的信息。
2. 服务器提供证书和签名，客户端验证证书信任链、域名匹配情况等，并验证服务器持有对应私钥。
3. 双方派生会话密钥，并通过 Finished 消息验证握手完整性。
4. 使用协商出的对称密钥保护应用数据。

证书主要用于身份认证；应用数据使用对称加密保护。会话恢复等场景的握手流程可能有所不同。

## 4. 与 HTTP、HTTPS 和 SSL 的关系

| 名称 | 作用 |
| --- | --- |
| HTTP | 定义请求与响应的语义 |
| TLS | 为通信提供安全保护，也可以用于其他应用协议 |
| HTTPS | 通过 TLS 保护的 HTTP 通信方式 |
| SSL | TLS 的旧版前身，已淘汰；日常所说的“SSL 证书”通常指用于 TLS 的证书 |

TLS 本身没有统一的默认端口，使用哪个端口由应用协议和服务配置决定。例如 HTTPS 默认使用 443 端口。
