# 共享密钥与共享秘密

在 TLS 1.3 的 ECDHE 密钥交换中，双方计算出的共同秘密通常称为**共享秘密（Shared Secret）**。口语中也会称为共享密钥，但它是密钥派生的输入材料，不直接作为握手或应用数据的加密密钥。

## 1. 生成方式

双方各自生成临时私钥和公钥，通过 ClientHello 与 ServerHello 交换公钥形式的密钥份额，私钥保留在本地：

```text
客户端私钥 + 服务端公钥 → 共享秘密 S
服务端私钥 + 客户端公钥 → 相同的共享秘密 S
```

这里的“+”表示参与 ECDHE 计算，不表示简单拼接或相加。双方无需传输私钥或共享秘密，旁观者仅凭公钥难以算出该秘密。

## 2. 用于密钥派生

TLS 1.3 将共享秘密纳入 HKDF 密钥调度，结合其他材料，生成 Handshake Secret，并进一步派生握手和应用流量秘密及其密钥。

```text
共享秘密等材料 → Handshake Secret → 握手流量秘密 → 握手密钥
                         ↓
                    Master Secret → 应用流量秘密 → 应用密钥
```

上图是简化的依赖关系。ECDHE 共享秘密、Handshake Secret 和最终的记录加密密钥是不同的材料，不能混为一谈。

## 3. 与方向密钥的区别

ECDHE 共享秘密在双方相同，没有客户端发送和服务端发送之分。后续派生流量秘密时，才结合方向标签生成两个方向不同的密钥。
