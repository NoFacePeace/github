# ICMP 协议

ICMP（Internet Control Message Protocol，互联网控制报文协议）属于[网络层](NetworkLayer.md)，用于报告网络错误和提供诊断信息。ICMP 报文由 [IP 协议](ip/IP.md)承载，不使用 TCP 或 UDP 端口。

## 1. 与 IP 的关系

IP 负责寻址和数据包转发，ICMP 负责反馈网络运行情况，例如目的不可达、数据包的存活跳数耗尽等。ICMP 需要通过 IP 将这些信息发送给目标设备。

协议的层级按职责划分，并不是仅按封装顺序划分。同一层的协议也可以相互封装：ICMP 服务于网络层的控制与诊断，因此与 IP 同属网络层。

以 IPv4 为例，封装结构如下：

```text
数据链路层帧 [ IPv4 首部 | ICMP 首部 | ICMP 数据 ]
```

IPv4 首部的协议字段值为 `1` 时，表示其承载 ICMP。IPv6 使用 ICMPv6，对应的下一首部值为 `58`。

## 2. 常见报文

| 报文 | 用途 |
| --- | --- |
| 回显请求与回显应答 | 检查目标是否响应，并测量往返时间 |
| 目的不可达 | 报告无法到达目的网络、主机或端口等情况 |
| 超时 | 报告 TTL 或跳数限制耗尽，也可报告分片重组超时 |

ICMP 错误报文通常携带触发错误的原始数据包的一部分，帮助发送方判断哪次通信出现了问题。具体报文类型和格式在 ICMPv4 与 ICMPv6 中有所区别。

## 3. 常见应用

### 3.1 ping

`ping` 通常发送 ICMP 回显请求，并根据回显应答判断目标是否响应、统计往返时间和丢包情况。

没有收到应答并不一定说明目标宕机，也可能是防火墙过滤、限速或网络丢包。

### 3.2 traceroute

`traceroute` 通过逐步增加探测数据包的 TTL 或跳数限制，利用沿途路由器返回的 ICMP 超时报文观察路径。

探测数据包可以使用 UDP、ICMP 或 TCP，取决于工具和运行方式；并非所有探测都直接发送 ICMP。

## 4. 功能边界

ICMP 提供反馈信息，不负责可靠传输，不会替 IP 重传丢失的数据包。ICMP 报文本身也可能丢失、被过滤或受到限速，发送方不能假定每个网络错误都会收到通知。
