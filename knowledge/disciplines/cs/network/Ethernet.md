# 以太网

以太网（Ethernet）是一组常见的有线局域网技术，主要由 IEEE 802.3 标准定义，涉及数据链路层和物理层。设备通过以太网帧在链路上传输 IP 数据包、ARP 报文等数据。

## 1. 所在层级

| 层级 | 以太网的功能 |
| --- | --- |
| 数据链路层 | MAC 寻址、帧格式、介质访问控制和帧校验 |
| 物理层 | 传输介质、接口、信号编码和传输速率等规范 |

讨论以太网帧、MAC 地址和 MTU 时，通常关注数据链路层功能；讨论网线、光纤和信号时，通常关注物理层功能。在 TCP/IP 四层模型中，这些功能都属于网络接口层。

## 2. 帧结构

常见的 Ethernet II 帧结构如下，不含 VLAN 标签：

```text
目的 MAC | 源 MAC | EtherType | 数据与填充 | FCS
 6 字节     6 字节    2 字节      46～1500 字节  4 字节
```

| 字段 | 作用 |
| --- | --- |
| 目的 MAC 地址 | 指定接收接口，或使用广播、组播地址 |
| 源 MAC 地址 | 标识发送接口 |
| EtherType | 标识承载的协议，例如 IPv4 为 `0x0800`、ARP 为 `0x0806`、IPv6 为 `0x86DD` |
| 数据与填充 | 承载上层数据，数据不足最小长度时添加填充 |
| FCS（Frame Check Sequence） | 使用 CRC 检测帧在传输中是否发生错误 |

上述普通帧从目的 MAC 到 FCS 的长度为 64～1518 字节。前导码、帧起始定界符和帧间间隔不计入这个长度。加入一个 802.1Q VLAN 标签会额外增加 4 字节。

## 3. MAC 寻址与交换

以太网通常使用 48 位 MAC 地址，例如 `00:1a:2b:3c:4d:5e`。以太网广播地址为 `ff:ff:ff:ff:ff:ff`。

交换机根据收到帧的源 MAC 地址学习接口位置，并根据目的 MAC 地址转发帧。广播帧和目的 MAC 尚未学习到的单播帧通常会被泛洪到同一 VLAN 内除入站端口以外的可转发端口。

现代交换式以太网通常使用全双工链路，不使用传统共享式、半双工以太网的 CSMA/CD 冲突检测机制。

## 4. MTU 与 IP 分片

普通以太网的 [MTU（Maximum Transmission Unit，最大传输单元）](MTU.md)通常为 1500 字节，表示可承载的网络层数据包大小，不包含以太网首部和 FCS。

例如，承载 IPv4 时，1500 字节包含 IPv4 首部和 IP 数据。如果 IPv4 首部为 20 字节，则最多承载 1480 字节的 IP 数据。

超过链路 MTU 的 IPv4 数据包在允许分片时可以由发送主机或路由器分片，每个分片再分别封装成以太网帧。以太网本身不会将过大的 IP 数据包拆分为 IP 分片。

部分网络支持更大的巨型帧（Jumbo Frame），但需要沿途设备和链路配置支持，不能假定所有以太网链路都支持相同的 MTU。

## 5. 与 IP 和 ARP 的关系

IP 负责跨网络寻址和转发，以太网负责当前链路上的帧传输。ARP 在 IPv4 以太网链路上查询下一跳 IP 地址对应的 MAC 地址。

主机向远端服务器发送数据时，IP 数据包的目的地址是服务器的 IP 地址，第一跳以太网帧的目的 MAC 地址通常是网关的 MAC 地址。路由器转发时，会根据出站链路重新封装帧。

以太网 FCS 只能用于差错检测，不能保证可靠交付。校验失败的帧通常被丢弃，丢失的数据可以由 TCP 等上层协议恢复。
