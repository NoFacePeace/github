# 瑞士表

瑞士表（Swiss Table）是一类基于开放寻址的哈希表设计。它将槽位分组，为每个槽位维护紧凑的控制信息，批量筛选可能匹配的键，从而减少完整键比较和不必要的数据访问。

## 1. 与拉链法的区别

| 方案 | 条目组织 | 冲突处理 |
| --- | --- | --- |
| 拉链法 | 桶关联多个条目，常用链表等结构 | 在桶关联的结构中查找或插入 |
| 瑞士表 | 条目保存在表内槽位，槽位分组 | 按探测序列检查其他组中的槽位 |

瑞士表不会因为哈希冲突就为该桶挂上一条键值链表。它属于开放寻址设计，但具体分组大小、探测规则和底层布局因实现而异。

## 2. 分组与控制信息

每组包含若干槽位及对应的控制信息，可以概念性地表示为：

```text
控制信息：[空][指纹 A][删除][指纹 B]……
键值槽位：     key A          key B
```

控制信息用于表示槽位为空、已删除或占用；占用状态还携带来自哈希值的一段短指纹。控制信息比完整键值紧凑，因此可以先批量检查，再访问少量候选条目。

经典设计通常使用 7 位哈希指纹；具体组宽度和比较方式应以实际实现为准。

## 3. 查找过程

Go 等实现使用的递增步长与覆盖性质参见[三角数探测](TriangularProbing.md)。

查找时，将哈希值用于定位初始组和生成指纹，再按以下流程处理：

```text
计算键的哈希值
    ↓
定位探测序列中的一个组
    ↓
批量比较组内控制信息与目标指纹
    ↓
仅比较指纹匹配槽位中的完整键
    ├─ 找到相等键 → 返回对应值
    └─ 没找到
         ├─ 组中存在真正空槽 → 按探测规则判定不存在
         └─ 没有空槽 → 继续探测下一组
```

指纹只负责筛选，两个不同键可以有相同指纹，所以仍必须比较完整键。真正空槽可以作为查找终止依据，删除标记通常不能直接当作空槽。

## 4. 插入与删除

插入沿探测序列检查候选键，已存在则更新；不存在时，在满足规则的空槽或可复用删除槽中写入条目并更新控制信息。不能遇到删除槽就无条件立即插入而忽略后面可能存在的同一个键。

删除时，如果直接把槽位标为空可能截断其他键的探测路径，就需要保留删除标记。某些情况下可以安全标为空，具体由实现维护的探测不变量决定。

删除标记过多会增加探测成本，因此实现可能在扩容、重建或清理过程中重新组织条目。

## 5. 性能特点

- 批量比较控制信息，减少逐个访问完整键的开销。
- 槽位和元数据组织紧凑，通常有较好的缓存局部性。
- 一些实现使用 SIMD，另一些使用普通机器字操作完成并行匹配，不能认为都依赖同一种指令。
- 高负载、删除标记过多或哈希分布较差仍会增加探测成本，平均常数时间不等于最坏情况保证。

这套设计仍需要合适的哈希函数、负载控制、扩容和删除协议，并非只增加一个指纹字段就完成实现。

## 6. Go map 中的应用

Go 从 1.24 开始采用基于 Swiss Table 的 map 实现。其常规分组包含 8 个槽位，通过控制信息和哈希指纹筛选候选键；大 map 还结合目录与多个表管理增长，不能简单理解为只有一个持续扩大的数组。

Go 的具体布局、增长策略和小 map 优化属于版本相关实现，应结合 `src/internal/runtime/maps` 阅读，不能直接套用旧版 map 的桶与溢出桶结构。
