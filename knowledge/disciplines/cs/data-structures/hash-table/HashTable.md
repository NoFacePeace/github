# Hash Table

哈希表通过哈希函数将键映射到桶，以支持快速查找、插入和删除。它可以实现字典（键到值的映射），也可以实现集合；字典还可以由树等其他结构实现，因此字典与哈希表并不等同。

## 1. 基本组成

| 组成 | 作用 |
| --- | --- |
| 桶数组 | 提供可按下标访问的位置，保存条目、条目指针或其他冲突处理结构。 |
| 哈希函数 | 根据键生成哈希值，再映射到桶下标。 |
| 条目 | 保存键以及可选的值或辅助状态。 |
| 冲突处理机制 | 处理不同键映射到相同位置的情况。 |

键相等时必须得到相同的哈希值；哈希值相同不代表键相等，仍需比较键。键存入表后，不应直接修改影响哈希或相等比较的内容，否则可能无法通过正常查找定位它。

## 2. 哈希冲突

- [冲突](Collision.md)：不同键映射到同一位置时，使用拉链法或开放寻址法等机制保留并区分条目。

## 3. 操作复杂度

| 操作 | 通常的平均复杂度 | 说明 |
| --- | --- | --- |
| 查询 | `O(1)` | 依赖哈希分布、负载和冲突处理方式。 |
| 插入 | 均摊 `O(1)` | 扩容时可能需要迁移已有条目。 |
| 删除 | `O(1)` | 某些实现还需维护探测路径或触发缩容。 |
| 遍历全部条目 | 通常为 `O(B + N)` | `B` 为桶或槽位数量，`N` 为条目数量；容量与条目数同阶时可写作 `O(N)`。 |

上述估算通常将哈希计算与键比较视为常数成本。对于长字符串等键，还需计入处理键内容的成本。普通链式或探测式实现遇到严重冲突时，单次操作可能退化为 `O(N)`，具体最坏情况取决于实现。

## 4. 负载因子与扩缩容

```text
负载因子 = 条目数量 / 桶或槽位数量
```

拉链法中，一个桶可以保存多个条目，负载因子可以超过 `1`。开放寻址法需要保留空槽以保证探测效率，通常在表填满前扩容；删除标记也会影响探测成本。

容量变化后，同一哈希值可能映射到不同桶，需要重新安排条目位置，这通常称为 rehash。迁移可以一次完成，也可以分批进行；分批迁移期间需要处理新旧表的查找与写入。

## 5. 适用场景与边界

哈希表适合按键精确查找、去重和计数。普通哈希表不保证按键或值排序，不擅长直接执行有序范围查询、排名或查找前驱后继。

需要有序访问时，可以评估平衡树、B+ 树或跳表；也可以组合哈希表与有序结构，分别支持精确查询和范围访问。
