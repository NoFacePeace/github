# Open Addressing

开放寻址法（Open Addressing）将条目保存在哈希表自身的槽位中，发生冲突后按探测序列寻找其他槽位，而不是将条目挂到桶外链表中。

分组探测与控制信息筛选的实际设计参见[瑞士表](SwissTable.md)。

## 1. 基本流程

条目保存在表内槽位中。目标位置冲突时，按探测规则寻找其他位置，例如线性探测或双重哈希。

删除时不能简单清空槽位并让后续查找立即停止，否则可能切断探测路径；常见做法包括删除标记或重排相关条目。

查找必须使用与插入一致的探测规则。遇到匹配键时返回；遇到真正从未占用的空槽时通常可以判定不存在，遇到删除标记则需要继续探测。实现还应限制探测步数，避免表满时无限循环。

## 2. 探测方式

| 方法 | 常见形式 | 特点 |
| --- | --- | --- |
| 线性探测 | `(h(key) + i) mod B` | 依次检查相邻槽，局部性好，但容易形成连续聚集。 |
| [二次探测](QuadraticProbing.md) | `(h(key) + c1*i + c2*i²) mod B` | 使用变化的偏移，减轻主聚集；可达槽位依赖容量与参数。 |
| 双重哈希 | `(h1(key) + i*h2(key)) mod B` | 用第二个哈希函数决定步长；步长应非零，并与容量互质以覆盖所有槽位。 |

其中 `B` 为槽位数，`i` 为探测次数。不同实现会采用不同公式与容量约束，不能只替换公式而忽略可达性。

## 3. 删除处理

删除标记表示此处曾保存条目，后续探测可能仍有目标键，因此不能当作普通空槽停止查询。插入时可以复用删除标记，但仍需按实现规则检查后续位置是否已有相同键。

另一类做法是在删除后重排相关条目，例如部分线性探测实现采用后移删除。具体策略必须与探测规则匹配。

## 4. 负载与复杂度

条目数不能超过可用槽位数，通常应在接近填满之前扩容。负载升高或删除标记积累会增加探测长度，即使有效条目数不多，也可能需要整理或重新建表。

哈希分布和负载合理时，查询、插入和删除通常具有平均或均摊 `O(1)` 成本；严重冲突或高负载时，单次操作可能退化为 `O(N)` 量级的探测。

## 5. 优缺点

槽位布局通常较紧凑，有利于缓存局部性，也可减少链表指针开销；代价是对负载更敏感，删除和扩容更复杂。扩容或重排还可能移动条目，持有条目地址的调用方需要遵守实现约束。
