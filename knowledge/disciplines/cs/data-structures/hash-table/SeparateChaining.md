# Separate Chaining

拉链法（Separate Chaining，也称链地址法）将映射到同一桶的条目组织在桶内的链表等结构中，解决哈希冲突。

## 1. 基本结构

桶保存冲突条目的集合，常见实现用链表串联：

```text
桶数组
[0] → 条目 A → 条目 B → NULL
[1] → NULL
[2] → 条目 C → NULL
```

查找时先定位桶，再比较桶内的键。桶数组可以连续保存链首指针，条目本身不必连续分配。具体实现也可能在桶内使用树或其他结构。

## 2. 操作流程

- 查询：计算桶下标，沿冲突链比较键，直到找到目标或到达链尾。
- 插入：先按需要检查键是否已存在；新键创建条目并加入对应桶，已有键则更新值。
- 删除：找到条目并从链中解除连接，更新桶入口或前驱条目的指针。

## 3. 负载与复杂度

设条目数为 `N`、桶数为 `B`，负载因子为 `α = N / B`。哈希分布均匀且键比较成本视为常数时，链式查找平均成本为 `O(1 + α)`；控制负载后通常按平均 `O(1)` 描述。

一个桶可以保存多个条目，因此负载因子可以超过 `1`。严重冲突导致大量条目集中到同一条链时，查找和按键删除可能退化到 `O(N)`。

## 4. 优缺点

实现直观，删除不需要维护开放寻址的探测路径，但普通链表条目需要额外指针和分配开销，访问分散条目也可能降低缓存局部性。

扩容并重新分配桶可以降低平均链长；某些实现会将长链转换为树，以控制严重冲突的查找成本。这些优化取决于具体实现，并非所有拉链哈希表都具备。
