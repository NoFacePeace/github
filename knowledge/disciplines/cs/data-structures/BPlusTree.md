# B+ 树

B+ 树是一种多路平衡搜索树，常用于数据库索引和文件系统。它通过较大的分支数量降低树高，并通过有序叶子节点支持范围扫描。

## 1. 核心结构

- **内部节点**：保存分隔键和子节点引用，用于导航；不保存完整的数据记录。
- **叶子节点**：保存所有数据条目，按键有序排列。条目的载荷可以是数据记录，也可以是指向其他记录的键或引用。
- **平衡性**：所有叶子节点位于同一层，查找路径的长度较稳定。
- **叶子链**：叶子节点通常通过链接串联，便于顺序遍历和范围扫描；实现可以使用单向或双向链接。

下面是简化示意图，内部节点的 `20` 和 `40` 用于划分子树范围：

```text
                 [20 | 40]
                /    |    \
               ▼     ▼     ▼
          [5, 10] [20, 30] [40, 50]
              └────→ └────→
                 叶子节点有序链接
```

## 2. 查找与范围扫描

### 2.1 等值查找

从根节点开始，根据分隔键选择子节点，逐层向下，直到叶子节点，再在叶子中查找目标键。

### 2.2 范围查找

先查找范围的起点，再沿叶子链读取后续条目，直到超过终点。无需为每个结果重新从根节点定位。

例如查询 `[20, 45]` 时，可以定位到包含 `20` 的叶子，依次读取 `20`、`30` 和 `40`，遇到 `50` 后停止。

## 3. 插入与删除

### 3.1 插入

先定位目标叶子并插入条目。节点容量不足时可以分裂，并向父节点更新或增加分隔键；父节点也可能继续分裂，根节点分裂时树高增加。

### 3.2 删除

删除条目后，若节点低于实现要求的占用率，可以从相邻节点重新分配条目，或合并节点并调整父节点。根节点收缩时树高可能降低。

具体数据库可能采用延迟清理、不同的分裂策略和合并阈值，不必与教科书算法逐步一致。

## 4. 为什么适合页式存储

节点通常可以对应一个存储页。内部节点只保存导航信息，同一页中可以容纳较多分隔键与子页引用，形成较大的扇出，减少逐层访问的页数。

树高大致随数据量的对数增长。范围扫描在定位起点后主要访问相关叶子页；实际性能还受页大小、键长度、缓存命中率和数据分布影响。

叶子节点的逻辑顺序不要求磁盘页物理连续，数据库返回结果的顺序也应通过 SQL 的 ORDER BY 明确指定。

## 5. 与 B 树的区别

| 对比项 | B 树 | B+ 树 |
| --- | --- | --- |
| 数据条目位置 | 可以位于内部节点和叶子节点。 | 全部位于叶子节点，内部节点用于导航。 |
| 等值查找 | 可能在内部节点找到数据后结束。 | 最终到达叶子节点。 |
| 范围遍历 | 可以通过树的有序遍历完成。 | 通常利用叶子链顺序扫描。 |
| 内部节点扇出 | 同时存储数据载荷时，可能容纳较少子节点。 | 相同页大小和键长度下，通常能容纳更多子节点引用。 |

## 6. InnoDB 中的应用

InnoDB 的常规索引使用 B+ 树，但叶子记录的内容取决于索引的组织方式：

- **聚簇索引**：叶子记录包含完整行数据，长字段可能通过引用保存在页外。
- **二级索引**：叶子记录包含索引列和聚簇索引键，读取其他列时可能需要回表。

B+ 树是通用数据结构，聚簇索引与二级索引的上述记录组织方式属于 InnoDB 的具体实现。
