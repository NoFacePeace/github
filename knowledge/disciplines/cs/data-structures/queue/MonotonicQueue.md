# 单调队列

单调队列（Monotonic Queue）是一种维护候选元素单调顺序的队列使用方式，通常用双端队列实现。它既能从队头移除过期元素，又能从队尾移除不再可能成为最优答案的元素，适合维护滑动窗口中的最大值或最小值。

## 1. 单调顺序与状态

本文统一按“从队头到队尾”的方向描述元素值的顺序：

- 维护最大值：使用单调递减队列，可以根据重复值处理规则允许相等，最大值位于队头。
- 维护最小值：使用单调递增队列，可以根据重复值处理规则允许相等，最小值位于队头。

实现时通常保存数组下标，下标从队头到队尾递增。这样既能通过原数组比较值，也能判断元素是否已经离开窗口。队列只保存可能成为后续答案的候选，不需要保留窗口中的所有元素。

## 2. 维护窗口最大值

对于长度为 k 的窗口，扫描到下标 i 时，窗口范围为 `[i-k+1, i]`：

1. 从队头移除所有小于 `i-k+1` 的下标，它们已经离开窗口。
2. 如果队尾对应值小于或等于当前值，则将其移除，持续处理直到队列为空或队尾对应值更大。
3. 将当前下标 i 加入队尾。
4. 当 `i >= k-1` 时，窗口已形成，队头对应值就是当前窗口最大值。

```text
遍历每个下标 i：
    当队列非空且队头下标已过期：
        移除队头
    当队列非空且队尾对应值 <= 当前值：
        移除队尾
    当前下标入队
    如果窗口长度已达到 k：
        记录队头对应值
```

## 3. 为什么可以移除队尾

设已有候选下标 j 小于当前下标 i，且 `nums[j] <= nums[i]`。在今后任何同时包含两者的窗口中，i 对应的值都不小于 j，且 i 比 j 更晚过期，因此 j 不会再成为必须保留的最大值候选。

这也是相等元素可以移除旧下标、保留新下标的原因。如果需要保留相等最大值中最早出现的位置，则应调整比较规则，例如仅在队尾值严格小于当前值时移除它。

## 4. 示例

```text
nums = [3, 1, 2, 4]，k = 3
```

以下队列以“下标:值”表示：

| 当前下标 | 处理后的候选队列 | 窗口最大值 |
| --- | --- | --- |
| 0 | `[0:3]` | 窗口尚未形成。 |
| 1 | `[0:3, 1:1]` | 窗口尚未形成。 |
| 2 | `[0:3, 2:2]` | 3；下标 1 被更大的新元素淘汰。 |
| 3 | `[3:4]` | 4；下标 0 过期，下标 2 被新元素淘汰。 |

最终结果为 `[3, 4]`。

## 5. 复杂度与注意事项

对于 n 个元素，每个下标最多入队一次、出队一次。在双端队列两端操作为 O(1) 或摊还 O(1) 的前提下，总时间复杂度为 O(n)。窗口长度为 k 时，候选队列最多包含 k 个下标，逻辑辅助空间为 O(k)，不计输出。

- 需要保证 `1 <= k <= n`，或在接口中明确非法窗口长度的处理方式。
- 查询窗口答案前，必须清除过期下标。
- 队尾移除无用候选时需要持续检查，通常使用循环而非单次判断。
- 用 Go 切片和递增队头下标实现时，如果不回收已出队空间，底层数组可能累计占用 O(n) 空间；要使实际存储保持 O(k)，可以使用容量为 k 的循环双端队列。
