# 双向链表

双向链表（Doubly Linked List）是一种每个节点同时保存前驱和后继指针的链表。它支持双向遍历，并能在已知节点的情况下，通过调整前后链接完成 O(1) 的删除或移动。

## 1. 基本结构

每个节点通常包含三个字段：

- `Val`：节点保存的数据。
- `Prev`：指向前一个节点。
- `Next`：指向后一个节点。

不使用哨兵节点的非循环双向链表可以表示为：

```text
      head        tail
       ↓           ↓
nil ←  A  ⇄  B  ⇄  C  → nil
```

对于相邻节点 A 和 B，需要同时满足 `A.Next == B` 和 `B.Prev == A`。空链表的头尾指针均为空，只有一个节点时，头尾指针指向同一节点。

## 2. Go 节点表示

```go
type DoublyListNode struct {
    Val  int
    Prev *DoublyListNode
    Next *DoublyListNode
}
```

链表通常还会保存头尾指针，必要时保存节点数量。头尾指针可以使两端的插入和删除不需要遍历。

## 3. 插入与删除

### 3.1 插入节点

在相邻节点 A、B 之间插入一个尚未属于任何链表的节点 X：

```text
插入前：A ⇄ B
插入后：A ⇄ X ⇄ B
```

需要设置 `X.Prev = A`、`X.Next = B`，再将 `A.Next` 和 `B.Prev` 改为 X。实际操作前应先保存 B，避免修改链接后丢失原来的后继节点。

### 3.2 删除节点

删除 A、B 之间的节点 X：

```text
删除前：A ⇄ X ⇄ B
删除后：A ⇄ B
```

将 `A.Next` 改为 B，将 `B.Prev` 改为 A，最后可以清空 X 的前驱和后继指针，避免保留无用引用。删除要求 X 是当前链表中的数据节点。

### 3.3 边界与哨兵

以上步骤假设操作位置两侧的节点均存在。不使用哨兵时，插入或删除首尾节点需要单独处理空指针，并更新头尾指针。

也可以设置不保存业务数据的头尾哨兵：

```text
headSentinel ⇄ A ⇄ B ⇄ C ⇄ tailSentinel
```

空链表时，头尾哨兵直接相连。每个数据节点始终有前驱和后继，因此可以统一插入、删除逻辑；哨兵不参与业务遍历，也不能作为数据节点删除。

## 4. 常见操作与复杂度

设链表包含 n 个数据节点，且维护头尾指针或头尾哨兵：

| 操作 | 时间复杂度 | 条件与说明 |
| --- | --- | --- |
| 按值查找 | O(n) | 需要遍历节点。 |
| 按下标访问 | O(n) | 可从较近的一端开始，但最坏情况仍为 O(n)。 |
| 头部或尾部插入、删除 | O(1) | 直接调整两端链接。 |
| 在已知节点之前或之后插入 | O(1) | 不包含定位节点的成本。 |
| 删除已知节点 | O(1) | 通过前驱和后继直接调整链接。 |
| 将已知节点移到头部或尾部 | O(1) | 先摘除，再插入目标位置。 |

存储 n 个节点需要 O(n) 空间；相较于单向链表，每个节点多保存一个前驱指针。

## 5. 适用场景与限制

- 需要从两端遍历或操作的动态序列。
- 已通过其他索引定位节点，需要频繁删除或调整位置的场景。
- LRU 缓存：哈希表定位节点，双向链表维护使用顺序，命中后将节点移到头部，淘汰时删除尾部节点。

双向链表不支持高效的随机访问。节点分散存储会影响缓存局部性，维护两个方向的链接也增加了内存开销和出错机会。修改时应保持前驱、后继关系一致，并正确处理空链表、单节点和首尾节点等边界。
