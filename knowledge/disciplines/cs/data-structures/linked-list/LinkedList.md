# 链表

链表（Linked List）是一种通过节点之间的链接组织元素的线性数据结构。每个节点保存数据及指向其他节点的指针或引用，节点不要求在内存中连续存放。

## 1. 基本结构

- 头节点：链表的第一个数据节点，通常通过 `head` 保存其位置。
- 后继指针：指向下一个节点；非循环链表的尾节点后继为空。
- 哨兵节点：不保存实际业务数据的辅助节点，可用于统一头部插入、删除等边界处理；并非所有实现都需要。

单向链表示例：

```text
head → 1 → 2 → 3 → nil
```

## 2. 常见类型

- 单向链表：节点保存后继指针，只能沿后继方向遍历。
- [双向链表](DoublyLinkedList.md)：节点同时保存前驱和后继指针，可以双向遍历；修改链接时需要维护两个方向。
- 循环链表：尾节点连接回头节点或哨兵节点，遍历时不能仅以空指针作为结束条件。

按节点的排列顺序，还可以区分有序链表与无序链表；[有序链表](SortedLinkedList.md)介绍顺序约束、插入、查找和合并操作，与上述链接形式的分类相互独立。

## 3. 常见操作与复杂度

设链表包含 n 个节点：

| 操作 | 时间复杂度 | 条件与说明 |
| --- | --- | --- |
| 按下标访问或按值查找 | O(n) | 通常需要从头逐个遍历。 |
| 头部插入 | O(1) | 调整头部链接。 |
| 尾部插入 | O(1) 或 O(n) | 维护尾指针时为 O(1)，否则通常需要遍历。 |
| 在已知节点之后插入 | O(1) | 已定位插入位置。 |
| 单向链表删除节点 | O(1) 或 O(n) | 已知前驱时可在 O(1) 内修改链接；否则通常需要先寻找前驱。 |
| 双向链表删除已知节点 | O(1) | 已知节点且可维护头尾指针时，直接调整前后链接。 |

插入、删除的 O(1) 只描述已定位操作位置后的链接调整，不包含查找位置的成本。存储 n 个节点需要 O(n) 空间，并有指针和节点分配的额外开销。

## 4. Go 节点表示

```go
type ListNode struct {
    Val  int
    Next *ListNode
}
```

空链表可以用 `nil` 表示。修改节点链接时，需要先保存后续仍要访问的节点，避免丢失剩余链表。

## 5. 适用场景与限制

链表适合在已知位置频繁插入、删除，或通过节点链接组织动态序列。它不支持高效的随机访问；相比连续数组，节点分散存储通常也会降低缓存局部性。选择链表时，应同时考虑查找成本、内存开销和访问方式。
