# ripgrep

ripgrep 是使用 Rust 编写的跨平台命令行文本搜索工具，命令名为 `rg`，可用于 Linux、macOS 和 Windows。ripgrep 是工具名称，`rg` 是调用入口，`rg -n 'TODO' .` 是一次具体的命令调用。

## 1. 基本使用

```bash
# 搜索当前目录及子目录，显示行号
rg -n 'TODO' .

# 按普通字符串搜索，不解析正则语法
rg -Fn 'config.json' settings.txt

# 只搜索 Python 文件中的内容
rg -n -g '*.py' 'TODO' .

# 列出默认搜索范围内的文件路径
rg --files
```

搜索模式默认匹配文件内容，`-g` 用于筛选文件路径，`--files` 用于列出文件。文件范围筛选和内容匹配是两个不同步骤。

## 2. 文件筛选

搜索目录时，ripgrep 默认递归遍历，遵守 `.gitignore`、`.ignore`、`.rgignore` 等忽略规则，并跳过隐藏文件。Git 忽略规则默认与仓库上下文有关，具体行为可通过参数调整。

```bash
# 包含隐藏文件，仍遵守忽略规则
rg --hidden 'TODO' .

# 不使用忽略文件中的规则，仍跳过隐藏文件
rg --no-ignore 'TODO' .

# 同时包含隐藏文件并关闭忽略规则
rg --hidden --no-ignore 'TODO' .
```

ripgrep 默认也会对二进制文件进行特殊处理；包含隐藏文件和关闭忽略规则并不等于把所有文件都当普通文本搜索。

## 3. 实现原理与性能

### 3.1 匹配引擎

ripgrep 默认使用 Rust 正则库，可以根据模式选择固定字符串搜索、字面量预筛选或基于有限自动机的正则匹配等方式。具体算法取决于模式、选项和版本。

默认正则引擎不支持反向引用、环视等部分语法。构建包含 PCRE2 支持时，可以通过 `-P` 切换到 PCRE2 引擎，以使用这些语法。

### 3.2 多文件搜索

在代码仓库中，性能通常来自多个环节：

- 文件筛选：跳过被忽略的目录和文件，减少遍历与读取量。
- 并行处理：支持使用多个线程搜索不同文件。
- 匹配优化：利用字面量预筛选等手段减少完整正则匹配的工作量。

### 3.3 与 GNU grep 的关系

两者的整体流程相似：读取文本、匹配模式、输出结果。GNU grep 主要使用 C 编写，使用自己的匹配实现，也会针对固定字符串和正则表达式选择不同算法。

GNU grep 和 ripgrep 都可能使用有限自动机和字符串搜索优化，因此不能简单理解为两者采用完全不同的搜索原理。常见的 GNU grep 通常逐个处理文件，ripgrep 则支持多文件并行搜索，两者的默认文件筛选规则也不同。

ripgrep 并非在所有场景下都更快。搜索单个文件、特定模式或不同存储介质时，性能关系可能变化，应在相同搜索范围和匹配语义下比较。
