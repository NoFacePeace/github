# LXCFS

LXCFS（Linux Containers Filesystem）是基于 FUSE（Filesystem in Userspace，用户态文件系统）的工具，可以根据容器的资源限制和用量，为容器提供相应的系统资源视图。

## 1. 解决的问题

容器通过 cgroup 限制 CPU、内存等资源，但容器内读取的部分 `/proc` 文件仍可能反映宿主机的资源信息。应用如果根据这些信息配置堆内存、线程池或缓存，可能高估可用资源。

例如，宿主机有 256 GiB 内存，容器的内存上限为 4 GiB。默认情况下，容器读取 `/proc/meminfo` 可能仍看到宿主机的内存总量；配置 LXCFS 后，该文件可以呈现基于容器限制生成的内存信息。

## 2. 工作原理

LXCFS 通常运行在宿主机上，通过 FUSE 提供虚拟文件，再将这些文件绑定挂载到容器内对应的位置。容器读取这些文件时，LXCFS 根据访问进程所属的 cgroup 等信息生成内容。

```text
容器内程序读取 /proc/meminfo
        ↓
读取绑定挂载的 LXCFS 虚拟文件
        ↓
LXCFS 根据进程所属的 cgroup 获取资源限制与用量
        ↓
返回适用于该容器的内存信息
```

常见处理对象包括 `/proc/meminfo`、`/proc/cpuinfo`、`/proc/stat` 和 `/proc/uptime`。具体支持的文件、CPU 视图的计算方式及行为取决于 LXCFS 版本和配置。

## 3. 与 cgroup、容器运行时的关系

| 组件 | 主要作用 |
| --- | --- |
| [cgroup](../../disciplines/cs/os/cgroup/Cgroup.md) | 由 Linux 内核执行资源限制，并提供资源统计。 |
| LXCFS | 根据资源限制和用量，生成供容器读取的系统资源视图。 |
| 容器运行时 | 创建和管理容器运行环境，配置 cgroup、挂载等。 |

LXCFS 本身不执行 CPU、内存限制，也不是容器运行时。虽然名称中包含 LXC，但也可以配合 Docker、Kubernetes 等使用，需要相应的部署和挂载配置。

CPU 配额限制的是一定周期内可消耗的 CPU 时间，不等于独占或绑定特定的 CPU 核。即使 LXCFS 展示了相应的 CPU 数量，也不能据此推断容器获得了独占 CPU。

## 4. 适用场景与边界

- 应用依赖 `/proc` 判断资源容量时，LXCFS 可以帮助其根据容器资源限制配置内存、并发度等。
- 应用或运行时已经能够直接识别 cgroup 限制时，应结合其版本和资源探测方式判断是否需要 LXCFS。
- LXCFS 只调整其覆盖文件的内容，不会让所有系统接口都自动呈现一致的容器资源视图。
- 使用 LXCFS 不会增加容器的资源额度，也不能避免应用超出内存限制而触发 OOM。
