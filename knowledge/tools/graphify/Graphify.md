# Graphify

Graphify 是 Graphify Labs 提供的开源知识图谱工具，可以把代码库及相关文档、配置、SQL Schema、PDF 等资料组织为节点与关系，供用户或编程助手查询、追踪关联和可视化浏览。

## 1. 核心用途

- 理解项目结构：查看代码中的概念、模块及它们之间的联系。
- 追踪依赖：沿调用、导入、继承等关系查找相关代码，辅助分析改动影响。
- 关联代码与资料：将文档等内容中的概念与代码组织到同一图谱中。
- 为编程助手提供上下文：根据问题查询图谱，获得相关节点、关系和来源，再回到源文件核实细节。

例如，源代码及配置中包含以下关系时，图谱可以将其组织为：

```text
订单服务 ──调用──→ 支付服务 ──使用──→ Redis
```

这个例子表达图谱的组织方式，不代表工具能在所有语言、框架和动态运行场景中自动准确识别这些关系。

## 2. 工作原理

### 2.1 代码结构提取

根据项目 README，代码主要通过 tree-sitter 的抽象语法树（AST）在本地进行确定性解析，提取符号及调用、导入、继承等关系。代码结构提取本身不需要大模型。

图中的连接标记为 `EXTRACTED` 或 `INFERRED`，用于区分从源内容直接提取的关系与经过解析推导的关系。推导关系不等于一定由大模型生成，仍需结合来源与解析方式理解。

### 2.2 非代码资料的语义提取

文档、PDF、图片等内容可以使用编程助手的模型或配置的模型后端进行语义提取，再纳入图谱。因此，“代码解析在本地进行”不等于所有输入都始终在本地处理，具体取决于输入类型和所选后端。

### 2.3 图谱查询

Graphify 的核心是图结构及图遍历，不依赖嵌入向量或向量数据库。它可以查询问题相关的子图、解释节点，以及查找两个节点之间的连接路径。

向量检索主要根据表示的相似性查找内容，图谱查询则根据显式组织的实体与关系查找关联。两者可以在更大的系统中结合，但不能把 Graphify 直接等同于向量检索或完整的 RAG 系统。

## 3. 基本使用

以下命令依据 2026-10-25 查阅的项目 README，要求 Python 3.10+，并使用 uv 或 pipx 安装。

```bash
uv tool install graphifyy
graphify install
```

PyPI 包名是 `graphifyy`，安装后的命令名是 `graphify`。`graphify install` 用于检测编程助手并注册技能；具体平台支持与配置以项目文档为准。

在支持该技能的编程助手中执行：

```text
/graphify .
```

典型输出位于 `graphify-out/`：

| 文件 | 用途 |
| --- | --- |
| `graph.html` | 交互式图谱，可浏览、搜索和筛选节点 |
| `GRAPH_REPORT.md` | 图谱概览、关键概念与关联报告 |
| `graph.json` | 持久化图谱，供后续查询与集成使用 |

也可以通过 CLI 查询已构建的图谱，例如：

```bash
graphify explain "APIRouter"
graphify path "FastAPI" "ModelField"
graphify query "How is routing connected to validation?"
```

## 5. 使用关注点

- 图谱完整性：语言、框架、动态调用和配置方式会影响关系解析效果，关键依赖需要回到源码验证。
- 更新维护：图谱对应构建时的资料状态，代码或文档变更后需要更新，避免使用过期关系。
- 数据处理：非代码资料的语义提取可能调用外部模型，应按实际后端确认处理位置与调用成本。
- 来源核验：保留源文件、位置和关系类型，区分直接提取与推导，避免把图中的连接当作已验证事实。
- 效果评估：结合实际问题检查相关节点与路径是否准确、有用，不直接套用项目宣传中的效率指标。
