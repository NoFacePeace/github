# 模块设计

## 1. 职责与实施阶段

以下名称表示职责边界，实施时再确定具体 Go 包路径；不要求每项单独创建包。

| 模块 | 负责事项 | 不承担的事项 | 首次交付阶段 |
| --- | --- | --- | --- |
| 配置与应用装配 | 默认值、加载、校验、依赖注入、启动关闭 | 业务状态转换 | 01 |
| 领域模型 | Task、Run、Workspace、状态和标识 | HTTP 协议、数据库访问 | 01 |
| 存储 | 迁移、查询、条件更新、业务事务 | 调用模型和执行工具 | 01 |
| 模型适配 | 消息协议、工具定义、模型能力、输出和用量 | Task 生命周期与审批 | 02 |
| Agent Loop | 模型／工具循环、消息追加、步数、执行结束原因 | 查业务表、工作区选择、Run 租约 | 03 |
| 工具注册与实现 | 工具定义、参数 Schema、风险声明、具体操作 | 用户审批记录与 Run 状态编排 | 03、05 |
| 工具执行器 | 查找工具、校验参数、策略评估、授权复用、执行 | 模型请求循环 | 03、06 |
| 任务服务与执行协调 | 创建、启动、取消、恢复、登记、退出清理、租约 | 供应商协议转换 | 04、08 |
| 记录适配 | 将 Loop 和工具事实保存为日志、事件及状态 | 独立决定审批策略 | 04 |
| HTTP API | 参数绑定、错误映射、鉴权入口、事件传输 | 直接操作执行 map 或数据库 | 04 |
| 工作区与文件访问 | 路径解析、读写授权、冲突检查、文件历史 | 模型推理 | 05 |
| 命令执行与沙箱 | 子进程、工作目录、环境、输出限制、隔离与终止 | 审批 UI 与授权持久化 | 05 |
| 安全策略与授权 | 配置规则、风险决定、授权匹配和审批需求 | 直接运行工具 | 05、06 |
| 审批与输入 | 等待请求、批准／拒绝、输入提交、失效和恢复触发 | 模型内部循环 | 06 |
| 上下文构建 | 系统指令、历史、附件、检查点、运行输入 | 推进工具执行 | 04、07 |
| 上下文裁剪与摘要 | 请求估算、校准、消息裁剪、历史摘要 | 修改 Run 的业务关系 | 07 |
| Agent 与委派 | 角色、工具范围、子 Run 预算、父子结果与取消 | 复制一套独立执行引擎 | 09 |
| 外部扩展与管理 | Skills、MCP、搜索、记忆、调度、管理 UI | 绕开统一权限和记录链路 | 10 |

## 2. 依赖方向

```text
HTTP API → 任务服务 → 上下文构建 → Agent Loop
              │                      │
              │                      ├→ 模型接口 → 供应商适配
              │                      ├→ 工具执行接口 → 工具执行器
              │                      └→ 记录接口 → 记录适配
              │                                        │
              └→ 存储接口 ←─────────────────────────────┘

工具执行器 → 安全策略／审批授权 → 存储接口
工具执行器 → 工具注册表 → 文件访问层／命令沙箱／外部连接器
```

存储和供应商的具体实现由应用入口注入。Loop 使用接口接收本次运行的模型、工具执行和记录能力，不依赖 Task 的数据库实现。委派通过任务编排能力创建子 Run，沿用同一执行链路。

## 3. 关键数据边界

| 数据 | 所属职责 | 核心约定 |
| --- | --- | --- |
| Task | 任务服务 | 一项持续任务，可包含多次根 Run |
| Run | 任务服务 | 一次执行，保存输入、模型选择、状态和父子关系 |
| execution | 执行协调 | 本进程活动执行，持有取消函数、退出通知和可选租约 |
| 租约 | 执行协调与存储 | 通过 Owner、Epoch、过期时间约束执行器写入 |
| 消息与工具事实 | 执行记录 | 使用稳定的 Run ID、工具调用 ID 和记录标识，支持还原与去重 |
| 业务事件 | 事件存储 | 用于查询和客户端展示，可从持久化事实及状态进行修复 |
| 审批请求 | 审批模块 | 表示待决定、已批准、已拒绝或已失效，绑定具体调用 |
| 可复用授权 | 授权模块 | 表示已授予的能力，分别匹配工具、网络和路径范围 |
| 检查点 | 上下文模块 | 摘要加原文保留游标，不删除作为事实来源的原始记录 |

## 4. 跨模块约束

- 暂停和完成使用明确的执行结果或必达记录表达，不能让调用者仅凭 `nil` 错误猜测状态。
- 存储层对状态转换使用条件更新；最终状态、请求失效等需要一致的业务修改放在同一数据库事务。
- JSONL 与数据库分别提交时定义记录顺序、去重标识和修复流程，不将部分成功当成完整成功。
- 参数中的路径和授权中的路径统一规范化；路径锁只能协调本进程，不能承诺阻止外部编辑器或任意 Shell 修改。
- 跨进程协调、远程取消路由和沙箱后端选择属于显式部署能力，在相应阶段验收后启用。
