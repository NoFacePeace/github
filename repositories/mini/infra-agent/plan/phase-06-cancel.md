# 阶段 06：取消执行与清理

## 1. 业务流程

```text
POST /v1/runs/{id}/cancel → 查询 Run 并协调启动／退出
→ 有 execution：发出取消 → 模型／工具停止 → 状态与资源收尾
→ 无 execution：条件更新 cancelled
→ 受理返回 202，客户端继续查询最终状态
```

依赖阶段 02、04、05，完成 M2。首版请求固定到同一执行器，不引入跨进程取消轮询。

## 2. 接收请求

- [ ] P06-01 【API】注册取消接口，传递 Run ID，区分不存在、状态冲突与内部错误。
- [ ] P06-02 【任务服务】已结束 Run 幂等返回；状态结束但执行仍未退出时，也通知其停止。
- [ ] P06-03 【执行协调】与启动、恢复及退出协调，避免查不到 execution 后另一边又启动。

## 3. 停止活动执行

- [ ] P06-04 【Registry】标记用户取消并调用 cancel，不直接等待完整退出。
- [ ] P06-05 【Loop／模型／工具】响应 Context，退出网络调用、工具等待及命令执行。
- [ ] P06-06 【任务服务】由 launch 更新 cancelled，执行恰好暂停或正常返回时不能漏掉已受理取消。
- [ ] P06-07 【执行协调】有序停止后台协程、释放资源、注销对应执行并通知 done，不重复关闭通道。

## 4. 取消非活跃运行

- [ ] P06-08 【存储】无 execution 且运行未结束时按原状态更新 cancelled，不覆盖其他终态。
- [ ] P06-09 【存储】区分用户控制与执行器写入，后续启用租约后仍可取消已释放租约的 Run。
- [ ] P06-10 【任务服务】条件更新不匹配时重新核对，不把未生效的取消当成成功。

## 5. 返回与验收

- [ ] P06-11 【Handler】受理返回 202，明确请求受理与执行停止的区别，查询可看到最终状态。
- [ ] P06-12 【验收】覆盖启动前、模型等待、工具运行、完成边界及重复取消。
- [ ] P06-13 【验收】并发启动、取消和退出无重启、状态回退与残留进程，运行竞态检测。
- [ ] P06-14 【验收】已取消 Run 不能再启动；审批和输入请求失效随阶段 07 接入。
