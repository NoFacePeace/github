# 阶段 08：故障恢复与执行协调

## 1. 目标与前置

依赖阶段 04、06、07，交付 M4。先保证单进程重启可恢复，再按部署需求启用多执行器接管。

## 2. 执行登记与租约

- [ ] P08-01 校验执行登记、重复启动保护、按实例身份注销及 done 通知的生命周期。
- [ ] P08-02 定义 Run 租约的 Owner、Epoch、ExpiresAt，并实现原子获取、续约、释放。
- [ ] P08-03 租约获取或接管时递增 Epoch，续约和释放只能作用于匹配凭证。
- [ ] P08-04 续约失败立即取消执行；失效执行器不能继续记录工具事实、更新状态或提交结果。
- [ ] P08-05 数据库写入在同一操作内校验凭证和有效期；文件日志写入设计对应的锁与凭证检查，避免“先验证、后写入”的并发空隙。
- [ ] P08-06 区分用户取消等控制操作与执行器写入，限制可绕过租约检查的调用入口。

## 3. 崩溃恢复

- [ ] P08-07 启动时扫描未结束运行，结合租约、JSONL 和数据库事实分类，不抢占仍然有效的执行。
- [ ] P08-08 已有工具结果直接复用；没有开始记录的调用可重新进入审批和执行；已开始但无结果的调用标记结果未知。
- [ ] P08-09 对结果未知的有副作用工具默认不自动重放；仅在工具提供幂等键或明确恢复协议时重试。
- [ ] P08-10 处理日志尾部不完整、重复记录及事件缺失，建立可重复执行的修复过程。
- [ ] P08-11 恢复前还原审批状态和消息配对，等待中的 Run 不误变成执行中。

## 4. 部署与关闭

- [ ] P08-12 定义单实例请求路由约束；启用多执行器后选择 owner 路由或持久化取消请求，不能只查本地 map。
- [ ] P08-13 服务关闭时停止接收新任务，通知活动执行退出，等待有界时间并释放资源。
- [ ] P08-14 对租约丢失后仍在运行的外部进程采取终止措施，明确租约不能撤销已经发生的外部副作用。

## 5. 验收事项

- [ ] P08-15 在工具开始前、执行中、结果写入后、状态提交前分别注入进程中断。
- [ ] P08-16 两个执行器竞争同一 Run，只有一个取得权限，旧 Epoch 的写入被拒绝。
- [ ] P08-17 验证续约失败、网络延迟、重复恢复、日志损坏和取消到达错误实例的处理。
- [ ] P08-18 对执行登记、启动／取消竞争及收尾流程运行竞态检测。
