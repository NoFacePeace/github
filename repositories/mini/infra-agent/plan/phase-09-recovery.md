# 阶段 09：故障恢复与执行协调

## 1. 业务流程

```text
服务重启／执行中断 → 扫描未结束 Run → 还原事实和权限状态
→ 区分已完成、未开始与结果未知调用 → 恢复或明确失败
→ 多执行器启用后先获取租约，再沿用正常执行流程
```

依赖阶段 06～08，完成 M4。先验证重启恢复，再按部署需求接入多执行器租约。

## 2. 崩溃恢复

- [ ] P09-01 【恢复】启动时扫描未结束运行，结合租约、JSONL 和数据库事实分类，不抢占仍然有效的执行。
- [x] P09-02 【恢复】已有工具结果直接复用；没有开始记录的调用可重新进入审批和执行；已开始但无结果的调用标记结果未知。
- [x] P09-03 【恢复】对结果未知的有副作用工具默认不自动重放；仅在工具提供幂等键或明确恢复协议时重试。
- [ ] P09-04 【恢复】处理日志尾部不完整、重复记录及事件缺失，建立可重复执行的修复过程。
- [ ] P09-05 【恢复】恢复前还原审批状态和消息配对，等待中的 Run 不误变成执行中。

## 3. 执行登记与租约

- [x] P09-06 【执行协调／租约】校验执行登记、重复启动保护、按实例身份注销及 done 通知的生命周期。
- [ ] P09-07 【执行协调／租约】定义 Run 租约的 Owner、Epoch、ExpiresAt，并实现原子获取、续约、释放。
- [ ] P09-08 【执行协调／租约】租约获取或接管时递增 Epoch，续约和释放只能作用于匹配凭证。
- [ ] P09-09 【执行协调／租约】续约失败立即取消执行；失效执行器不能继续记录工具事实、更新状态或提交结果。
- [ ] P09-10 【执行协调／租约】数据库写入在同一操作内校验凭证和有效期；文件日志写入设计对应的锁与凭证检查，避免“先验证、后写入”的并发空隙。
- [ ] P09-11 【执行协调／租约】区分用户取消等控制操作与执行器写入，限制可绕过租约检查的调用入口。

## 4. 部署与关闭

- [ ] P09-12 【部署与关闭】定义单实例请求路由约束；启用多执行器后选择 owner 路由或持久化取消请求，不能只查本地 map。
- [ ] P09-13 【部署与关闭】服务关闭时停止接收新任务，通知活动执行退出，等待有界时间并释放资源。
- [ ] P09-14 【部署与关闭】对租约丢失后仍在运行的外部进程采取终止措施，明确租约不能撤销已经发生的外部副作用。

## 5. 验收事项

- [ ] P09-15 【验收】在工具开始前、执行中、结果写入后、状态提交前分别注入进程中断。
- [ ] P09-16 【验收】两个执行器竞争同一 Run，只有一个取得权限，旧 Epoch 的写入被拒绝。
- [ ] P09-17 【验收】验证续约失败、网络延迟、重复恢复、日志损坏和取消到达错误实例的处理。
- [x] P09-18 【验收】对执行登记、启动／取消竞争及收尾流程运行竞态检测。
