# 阶段 04：调用模型并完成运行

## 1. 业务流程

```text
运行输入 → 调用模型 → 保存助手回复与用量
→ 无工具调用：更新 completed → 客户端查询答案
```

依赖阶段 03，完成 M1。先打通纯文本回答；工具执行分支在阶段 05 接入，不能把工具调用当成最终答案标记完成。

## 2. 发起请求

- [x] P04-01 【Loop／模型适配】在实际调用点定义请求、响应和模型接口，Loop 不解析供应商配置。
- [ ] P04-02 【模型适配】接入一家供应商，完成文本编解码、模型能力及用量映射。
- [ ] P04-03 【模型适配】传递 Context 和超时，处理鉴权、限流、网络失败与非法响应。
- [ ] P04-04 【模型适配】限定重试条件和次数，防止已经产生输出后无条件重试；缺失用量不伪造为实测值。
- [ ] P04-05 【配置】加入实际需要的请求超时、输出上限，并按模型能力规范化请求。

## 3. 保存并结束

- [ ] P04-06 【记录适配】保存助手消息及用量，写入失败不得返回运行完成。
- [ ] P04-07 【任务服务】明确结束契约，回答完成更新 completed，故障更新 failed，并沿用退出清理。
- [ ] P04-08 【事件存储】保存开始、回答、完成和失败事件，需要一致的数据库状态与事件在同一事务提交。
- [ ] P04-09 【记录】定义 JSONL 与数据库部分提交的去重标识和修复入口，不视为同一事务。

## 4. 查询结果

- [ ] P04-10 【API】任务详情可定位最终答案，增加任务列表和 `GET /v1/tasks/{id}/events` 游标查询。
- [ ] P04-11 【API】增加 `GET /v1/runs/{id}/log` 日志读取，保证事件排序与资源访问权限。

## 5. 验收事项

- [ ] P04-12 【验收】通过 HTTP 创建任务并启动，真实模型回答后可以查询最终答案。
- [ ] P04-13 【验收】使用可控 HTTP 测试端验证成功、限流、损坏响应、超时与取消。
- [ ] P04-14 【验收】重启后可读取答案和事件；未收尾 Run 不自动视为成功，也不盲目重放。
- [ ] P04-15 【验收】注入记录和数据库故障，确认部分提交可定位，错误不会被静默吞掉。
