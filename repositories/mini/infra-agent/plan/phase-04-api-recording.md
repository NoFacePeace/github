# 阶段 04：执行记录与对外接口

## 1. 目标与前置

依赖阶段 01～03，交付 M1。客户端能创建并运行任务、查看结果与过程、取消执行。

## 2. 任务服务与执行协调

- [ ] P04-01 实现工作区解析、Run 创建、模型选择、系统与用户消息准备，实际注入 Loop 所需依赖。
- [ ] P04-02 创建独立执行 Context，登记取消函数和退出通知；拒绝同一 Run 重复登记。
- [ ] P04-03 实现启动、运行、完成、失败和取消收尾，外层执行 goroutine 设置 panic 边界并保证清理。
- [ ] P04-04 首版固定请求路由到持有执行的服务实例；协调启动、取消与退出，避免取消后又启动。
- [ ] P04-05 活跃 Run 通知 Context 取消，非活跃且未结束 Run 条件更新取消；重复取消幂等，不等待整个执行退出。

## 3. 执行记录与事件

- [ ] P04-06 实现 JSONL 追加与读取：用户消息、模型回复、tool_started、tool_result 和运行结束记录。
- [ ] P04-07 明确关键记录的落盘策略，保证工具开始前的事实已按约定可靠保存。
- [ ] P04-08 实现任务侧记录适配器，连接 JSONL、业务事件与 Run 状态，不让 Loop 绑定具体存储。
- [ ] P04-09 为事件定义 Run／Task 关联和稳定顺序；提供可重读的游标查询，实时推送使用同一批持久化事件。
- [ ] P04-10 数据库事务内完成应保持一致的状态与事件修改；定义 JSONL 已写入但事件写入失败时的去重和修复入口。

## 4. HTTP API

| 方法与路径 | 功能 |
| --- | --- |
| `POST /v1/tasks` | 创建任务，明确是否同时启动首个 Run |
| `GET /v1/tasks` | 查询任务列表 |
| `GET /v1/tasks/{id}` | 查询任务及当前运行信息 |
| `POST /v1/tasks/{id}/messages` | 发送新消息并启动新根 Run |
| `GET /v1/tasks/{id}/events` | 按游标读取执行事件 |
| `POST /v1/runs/{id}/cancel` | 请求取消，受理成功返回 202 |
| `GET /v1/runs/{id}/log` | 读取或下载持久化执行记录 |

- [ ] P04-11 实现上述路由和 Handler，定义请求／响应类型及参数校验。
- [ ] P04-12 区分不存在、状态冲突、参数错误与内部错误；按实际部署场景加入身份与资源访问校验。

## 5. 验收事项
