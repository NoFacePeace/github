# Agent 实现计划

## 1. 目标与范围

规划一个支持任务编排、模型调用、工具执行、审批恢复和上下文管理的 Go Agent 服务。本文从目标能力出发制定计划，不按当前 `server` 的完成情况倒推；事项默认未完成，实施时核对代码和验收证据后再勾选。

首个里程碑是完成“创建任务 → 调用模型 → 执行工具 → 保存结果 → 查询过程 → 支持取消”的闭环。后续逐步补齐实际文件操作、审批恢复、长上下文、故障恢复和委派能力。

| 阶段 | 优先级 | 主题 | 前置依赖 | 主要验收结果 |

| 01 | P0 | [基础模型与存储](phase-01-foundation.md) | 无 | 核心数据、配置、迁移和状态约束可用 |
| 02 | P0 | [模型接入](phase-02-model.md) | 01 | 一家模型供应商支持文本、工具调用、用量及取消 |
| 03 | P0 | [最小执行循环](phase-03-loop.md) | 01、02 | 用简单工具完成多轮模型与工具交互 |
| 04 | P0 | [执行记录与对外接口](phase-04-api-recording.md) | 01～03 | 通过 API 执行任务、查看过程、取消和读取历史 |
| 05 | P0 | [文件与命令工具](phase-05-tools.md) | 04 | 在明确授权范围内完成代码修改与命令执行 |
| 06 | P1 | [审批与暂停恢复](phase-06-approval.md) | 04、05 | 审批、输入、拒绝、取消和恢复形成完整链路 |
| 07 | P1 | [上下文管理](phase-07-context.md) | 04、06 | 历史、附件、裁剪和摘要支持长任务 |

## 3. 模块与事项组织

模块边界、依赖关系及跨阶段职责见 [模块设计](modules.md)。各阶段文档按模块划分事项，使用 `P阶段号-事项号` 作为稳定编号。

| 标记 | 含义 |
| --- | --- |
| `- [ ]` | 待实现或尚未完成验收 |
| `- [x]` | 已有实现，并有对应验收证据 |
| P0 | 跑通首版实际执行链路所必需 |
| P1 | 暂停恢复、长任务和可靠运行所必需 |
| P2 | 多 Agent 与产品扩展，按需求交付 |

实施时一次选取一个阶段内可独立验证的事项或一组紧密关联事项。提交说明记录事项编号和验证结果，不以“接口已定义”代替“能力可用”。

## 4. 里程碑

| 里程碑 | 覆盖阶段 | 演示场景 |
| --- | --- | --- |
| M1：最小服务 | 01～04 | HTTP 创建任务，模型调用简单工具后回答，过程可查询，运行可取消 |
| M2：实际任务执行 | 05 | 在临时工作区读取、修改文件并运行测试，产物可查看 |
| M3：可交互长任务 | 06、07 | 审批暂停后继续，支持补充输入和附件，长上下文可裁剪和摘要 |
| M4：可靠执行 | 08 | 执行中重启、重复启动、租约丢失等情况可正确处理 |
| M5：委派与扩展 | 09、10 | 主 Agent 委派子任务，并按需使用外部工具和管理界面 |

## 5. 贯穿各阶段的约定

- 模型输出的工具调用先持久化，再启动工具；结果先可靠保存，再进入下一轮模型调用。
- 数据库负责业务状态、审批与授权、可查询事件；JSONL 负责消息与工具执行事实。明确关联标识和顺序，不假设两者能在同一事务内提交。
- 工具调用与结果按调用 ID 配对；等待审批不是执行结果，拒绝则需要形成可反馈模型的结果。
- 用户控制操作与执行器写入分别授权；租约启用后，执行器写入必须检查持有者、版本及有效期。
- 文件和联网的实际限制落实在访问层与沙箱中；Shell 工具随沙箱一起交付。
- 状态更新、取消、恢复及启动必须考虑并发；终态不能被旧执行恢复为运行中。
- 配置表区分已实现值和建议值；[配置文档](../configuration.md) 中的规划值不自动视为已经生效。
- 各阶段提供最小端到端验证，并对错误、取消和中断路径补充有意义的测试。
