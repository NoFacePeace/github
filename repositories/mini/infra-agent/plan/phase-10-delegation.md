# 阶段 10：多 Agent 委派

## 1. 业务流程

```text
父模型请求 delegate → 解析目标 Agent → 创建子 Run
→ 沿用启动／执行流程 → 等待子任务 → 返回结果给父模型
```

依赖阶段 07～09，交付 M5 的委派部分。Agent 配置、父子关系和并发限制随实际委派链路引入。

## 2. 解析目标 Agent

- [ ] P10-01 【Agent 选择】定义 Agent ID、名称、描述、角色提示词、模型偏好、允许工具及委派能力。
- [ ] P10-02 【Agent 选择】在系统提示词提供可用 Agent 清单，明确 ID 解析、未知 Agent 和未指定 Agent 的处理。
- [ ] P10-03 【Agent 选择】默认 Agent 使用确定的配置；若增加模型路由选择，单独实现并记录选择依据，不将空 ID 等同于智能选取。

## 3. 创建并执行子 Run

- [ ] P10-04 【委派编排】定义 `delegate` 的 start、status、cancel 参数以及目标、背景、Agent ID、子 Run ID。
- [ ] P10-05 【委派编排】子 Run 关联父 Run、根 Run 和深度，通过现有任务执行入口启动。
- [ ] P10-06 【委派编排】明确子 Run 的初始上下文和可访问工作区，不无条件复制父级全部历史或扩大授权。
- [ ] P10-07 【委派编排】配置深度、并发子任务数、总子任务数、最大时长及子任务步数和 Token 预算。
- [ ] P10-08 【委派编排】首版 start 等待子任务结束，返回结果摘要及子 Run 标识；独立委派可在并发上限内同时执行。
- [ ] P10-09 【委派编排】用父 Run 和工具调用 ID 防止恢复时重复创建子任务；子任务超时、失败和等待审批有明确传播规则。
- [ ] P10-10 【委派编排】取消父 Run 时先通知子孙停止，再完成父级收尾，防止父任务结束后子任务继续失控运行。

## 4. 文件与结果隔离

- [ ] P10-11 【工作区／结果】明确共享目录与独立工作目录策略；多 Agent 同时写代码时优先独立 worktree 或目录。
- [ ] P10-12 【工作区／结果】结果通过可追踪引用或摘要汇总；需要合并文件时提供冲突处理流程。

## 5. 验收事项

- [ ] P10-13 【验收】两个独立子任务并行完成，主 Agent 基于结果给出最终回复。
- [ ] P10-14 【验收】验证深度超限、并发超限、重复委派、子任务失败和父级取消。
- [ ] P10-15 【验收】子任务权限不超过其获得的授权，独立目录中的修改不会直接覆盖其他任务。
