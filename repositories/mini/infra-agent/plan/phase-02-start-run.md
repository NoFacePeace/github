# 阶段 02：创建并启动 Run

## 1. 业务流程

```text
POST /v1/tasks/{id}/messages → 查询 Task 与当前 Run → 校验能否启动
→ 创建 Run 并更新任务关联 → 登记 execution → 启动后台执行 → 返回 Run ID
```

依赖阶段 01。先用可控后台执行函数验证生命周期，真实上下文和模型在阶段 03、04 接入。

## 2. 接口与创建条件

- [ ] P02-01 【API】定义发送消息接口，接收本轮用户输入并返回新 Run 信息。
- [ ] P02-02 【任务服务】查询 Task，不存在则拒绝；首次需要时定义 Run 及 pending、running、completed、failed 状态。
- [ ] P02-03 【任务服务】明确根 Run 并发规则，首版仅在前一根 Run 结束后允许创建下一次运行，历史使用确定排序。
- [ ] P02-04 【存储】在同一事务内创建 Run、保存输入并更新 Task 当前 Run，失败完整回滚。

## 3. 启动与登记

- [ ] P02-05 【执行协调】登记取消函数和 done 通知，拒绝同一 Run 重复登记。
- [ ] P02-06 【任务服务】实现 launch，创建独立后台 Context，先登记后执行，启动失败清理资源。
- [ ] P02-07 【存储】按原状态条件更新 pending → running，条件不匹配不能继续执行。
- [ ] P02-08 【执行协调】设置执行 goroutine 的 panic 边界，退出时按实例身份注销并关闭 done，失败按约定更新状态。
- [ ] P02-09 【应用装配】服务关闭时停止接受新执行并进行有界清理，请求结束不误取消后台任务。

## 4. 返回与查询

- [ ] P02-10 【API】受理后返回 Run ID 和状态，任务详情可查询当前 Run，状态冲突返回 409。
- [ ] P02-11 【执行协调】建立供启动、后续取消及恢复共用的协调边界，终态不允许重新启动。

## 5. 验收事项

- [ ] P02-12 【验收】一次请求仅启动一次 Run，请求断开后后台执行按约定继续。
- [ ] P02-13 【验收】并发启动、事务失败、登记失败和执行 panic 不会遗留错误关联或活动登记。
- [ ] P02-14 【验收】可控执行函数成功、失败和退出时，状态与 done 通知符合预期。
