# 阶段 01：基础模型与存储

## 1. 目标与前置

建立可持久化的任务与运行模型，使用 Go、SQLite 和本地数据目录交付首版。暂无前置阶段。

## 2. 配置与应用装配

- [ ] P01-01 确定应用数据目录、配置文件位置、默认值和覆盖优先级，校验非法值。
- [ ] P01-02 实现 HTTP 地址、数据目录、模型连接、超时和步数等首批配置；密钥不进入普通日志和配置查询响应。
- [ ] P01-03 建立应用启动、依赖装配、信号处理和有超时的优雅关闭入口。

## 3. 领域模型

- [ ] P01-04 定义 Task、Run、Workspace、消息、工具调用及统一标识生成规则。
- [ ] P01-05 区分任务、多次根运行与委派子运行，预留父 Run 关系，不混用“上一次运行”和“父运行”。
- [ ] P01-06 定义 pending、running、waiting_for_approval、waiting_for_input、completed、failed、cancelled，以及合法状态转换。
- [ ] P01-07 约定同一任务启动新根 Run 的条件和历史排序，明确是否允许并发根 Run。

## 4. 数据持久化

- [ ] P01-08 定义最小 Store 接口，实现 SQLite 连接、迁移版本、索引和唯一约束。
- [ ] P01-09 实现 Task／Run 的创建、按 ID 查询、列表与条件更新；列表使用确定排序。
- [ ] P01-10 在同一事务中创建 Run 并更新任务当前 Run，失败时完整回滚。
- [ ] P01-11 为消息及工具执行事实确定 JSONL 路径、记录格式、版本和稳定记录标识，供后续持久化接入。

## 5. 验收事项

- [ ] P01-12 数据库关闭并重开后，任务及运行仍可读取。
- [ ] P01-13 两次并发状态更新中，原状态不匹配的一方不会覆盖新状态；终态不能重新变成 running。
- [ ] P01-14 验证事务失败无半条任务关系、非法配置无法启动、查询排序稳定。

## 6. 交付边界

本阶段交付实际存储，不以空接口或返回固定成功的实现作为完成依据。审批表、授权表及租约字段随对应阶段迁移引入。
