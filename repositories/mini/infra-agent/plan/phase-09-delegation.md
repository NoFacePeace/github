# 阶段 09：多 Agent 委派

## 1. 目标与前置

依赖阶段 06～08，交付 M5 的委派部分。主 Agent 可以交出子目标，由受控子 Run 返回结果。

## 2. Agent 配置

- [ ] P09-01 定义 Agent ID、名称、描述、角色提示词、模型偏好、允许工具及委派能力。
- [ ] P09-02 在系统提示词提供可用 Agent 清单，明确 ID 解析、未知 Agent 和未指定 Agent 的处理。
- [ ] P09-03 默认 Agent 使用确定的配置；若增加模型路由选择，单独实现并记录选择依据，不将空 ID 等同于智能选取。

## 3. 委派编排

- [ ] P09-04 定义 `delegate` 的 start、status、cancel 参数以及目标、背景、Agent ID、子 Run ID。
- [ ] P09-05 子 Run 关联父 Run、根 Run 和深度，通过现有任务执行入口启动。
- [ ] P09-06 明确子 Run 的初始上下文和可访问工作区，不无条件复制父级全部历史或扩大授权。
- [ ] P09-07 配置深度、并发子任务数、总子任务数、最大时长及子任务步数和 Token 预算。
- [ ] P09-08 首版 start 等待子任务结束，返回结果摘要及子 Run 标识；独立委派可在并发上限内同时执行。
- [ ] P09-09 用父 Run 和工具调用 ID 防止恢复时重复创建子任务；子任务超时、失败和等待审批有明确传播规则。
- [ ] P09-10 取消父 Run 时先通知子孙停止，再完成父级收尾，防止父任务结束后子任务继续失控运行。

## 4. 文件与结果隔离

- [ ] P09-11 明确共享目录与独立工作目录策略；多 Agent 同时写代码时优先独立 worktree 或目录。
- [ ] P09-12 结果通过可追踪引用或摘要汇总；需要合并文件时提供冲突处理流程。

## 5. 验收事项

- [ ] P09-13 两个独立子任务并行完成，主 Agent 基于结果给出最终回复。
- [ ] P09-14 验证深度超限、并发超限、重复委派、子任务失败和父级取消。
- [ ] P09-15 子任务权限不超过其获得的授权，独立目录中的修改不会直接覆盖其他任务。
