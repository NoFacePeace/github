# 阶段 03：最小执行循环

## 1. 目标与前置

依赖阶段 01、02。用无外部副作用的简单工具跑通多轮交互，不先接入任意命令执行。

## 2. Agent Loop

- [ ] P03-01 定义运行输入：已经组装的消息、工具定义、模型输出限制和最大步数。
- [ ] P03-02 定义模型调用、工具执行、过程记录三个边界，Loop 不直接查询 Task 数据库。
- [ ] P03-03 实现“检查取消 → 调用模型 → 保存回复 → 执行工具 → 追加结果 → 再调用模型”。
- [ ] P03-04 按工具调用 ID 构造一条调用对应一条结果的消息，保留模型返回的调用顺序。
- [ ] P03-05 明确完成、暂停和故障的返回约定，让外层可准确判断结束原因。
- [ ] P03-06 按模型调用次数计算步数，最后一步禁止新工具调用；无法收敛时给出可解释错误。

## 3. 工具注册与执行

- [ ] P03-07 定义工具名称、描述、参数 Schema、风险评估和执行方法，注册时拒绝重名。
- [ ] P03-08 使用成熟 JSON Schema 库校验参数，首版不自动修复有歧义的参数。
- [ ] P03-09 实现简单工具，例如固定时间查询或受限计算，用于端到端验证。
- [ ] P03-10 先串行执行一批工具；未知工具和普通工具错误作为结果反馈模型，基础设施故障使运行失败。

## 4. 验收事项

- [ ] P03-11 模拟模型先请求工具、再基于结果回答，验证完整消息顺序。
- [ ] P03-12 覆盖多个工具、无效参数、未知工具、工具错误、取消和耗尽步数。
- [ ] P03-13 验证未成功记录的模型调用不会开始执行工具，结果记录失败后不会继续下一轮模型调用。

## 5. 交付边界

本阶段可用内存记录适配器验证调用契约，可靠落盘和业务状态接入在阶段 04 完成。
