# 阶段 07：审批、输入与恢复

## 1. 业务流程

```text
需要审批／输入 → 保存请求并暂停 Run → 用户提交决定／回答
→ 校验请求与 Run 状态 → 保存决定 → 恢复剩余调用 → 继续模型循环
```

依赖阶段 05、06，按实际等待和恢复流程引入策略、授权及审批数据。

## 2. 判断是否需要审批

- [ ] P07-01 【策略／授权】定义工具审批要求、用户工具策略、联网策略、路径策略以及人工／策略／自动审批模式。
- [x] P07-02 【策略／授权】统一先评估禁止规则，再合并工具要求和资源权限，禁止决定不能被自动审批或复用授权覆盖。
- [ ] P07-03 【策略／授权】用结构化权限需求表达工具授权、联网和路径读写，避免从风险原因字符串推断审批类型。
- [x] P07-04 【策略／授权】定义工具匹配键与单次／Run／工作区范围；网络按 Run 授权，路径按目录覆盖和读写授权。
- [ ] P07-05 【策略／授权】分别满足本次实际缺少的权限，已有工作区基础权限不重复审批，工具授权不能代替缺少的联网或路径授权。
- [ ] P07-06 【策略／授权】明确自动审批例外，默认保留未授权联网的人工确认；配置和 UI 说明保持一致。

## 3. 保存请求并暂停

- [ ] P07-07 【审批存储】持久化审批请求、决定、原因和范围，以 Run ID、工具调用 ID 关联并避免重复创建。
- [ ] P07-08 【审批存储】条件提交待决定请求，在同一事务内保存决定、生成授权和记录业务事件，禁止重复决定覆盖。
- [ ] P07-09 【审批存储】实现 `ask_user` 请求、用户回答及输入等待状态。
- [ ] P07-10 【审批存储】取消或终态转换时使未完成请求失效；审批、输入和恢复接口拒绝继续已取消 Run。

## 4. 提交决定并恢复

- [ ] P07-11 【API／恢复】实现审批决定、运行输入提交和继续执行接口，协调重复提交与同时恢复。
- [ ] P07-12 【API／恢复】等待时不产生伪造工具结果；恢复时重建消息并定位未完成调用。
- [x] P07-13 【API／恢复】批量工具调用按顺序推进：保留已完成结果，在等待项处暂停，后续调用留待恢复。
- [ ] P07-14 【API／恢复】拒绝工具生成带调用 ID 的拒绝结果，再按批量策略处理剩余调用；批准后再次检查必要权限与参数有效性。

## 5. 验收事项

- [ ] P07-15 【验收】覆盖单次批准、授权复用、拒绝、自动审批、审批过期和存储失败。
- [ ] P07-16 【验收】一个批次有多个待审批调用时，多次恢复均不丢失或重复执行工具。
- [ ] P07-17 【验收】审批与取消、审批与恢复并发时，已取消 Run 不重新运行，决定不会被重复消费。
