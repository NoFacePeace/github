# Watch 客户端实现计划

## 1. 目标与范围

在 Controller 中实现 HTTP Watch 客户端。每次连接后接收全量快照，随后处理增量事件。运维事件接入健康管理器的 `SubmitEvent`，集群配置事件先接测试接收方，待资源调谐模块具备接收能力后再联调。

使用 Go 标准库的 `net/http`、`encoding/json` 和 `context`，以本地模拟 HTTP 服务验证客户端。本轮范围包括流式解码、事件分发、偏移量去重、心跳超时和退避重连。服务端实现、慢连接隔离、断点续传和偏移量持久化留待后续。

## 2. 核心流程

Controller 启动 Watch 客户端 → 发起 HTTP GET → 逐条解码响应流中的 JSON → 接收并分发全量快照 → 按类型过滤和分发增量事件。

- 全量事件包含运维状态、集群配置及两类偏移量。快照分发成功后，将偏移量作为本次连接的起点。
- 运维增量交给 `SubmitEvent`。集群配置增量交给配置接收方。每类事件独立比较和推进偏移量，跳过小于或等于已接收偏移量的增量。
- 心跳刷新当前连接的最近心跳时间。连接断开或心跳超时后，释放响应流并按退避策略重连。新连接从新的全量快照开始。

## 3. 模块划分

| 模块 | 职责 |
| --- | --- |
| Watch 客户端 | 建立连接、读取事件、维护心跳和偏移量、执行重连 |
| 健康管理器 | 接收节点和 Pod 异常，沿用现有策略与动作流程 |
| 集群配置接收方 | 接收全量配置或增量变更。本轮用测试接收方验证分发 |
| Controller 入口 | 加载 Watch 配置，启动各模块并传入共同的退出 context |
