# 实现计划

## 1. 组织方式

按“核心链路 → 实施阶段 → 具体事项”组织：

- 链路说明要实现的业务能力及与其他链路的依赖。
- 阶段说明本次能够运行到哪里，每阶段交付一条可验证的完整路径。
- 事项按模块拆分，明确输入、输出、实现内容和验收条件。

每阶段只补齐运行所需的协议与基础能力，不单独安排只有接口定义、无法执行的阶段。

## 2. 核心链路

| 链路 | 范围 | 计划 |
| --- | --- | --- |
| 任务执行 | 从独立引擎执行逐步扩展到远程调度、停止恢复、会话续接和页面展示 | [任务执行链路](./task-execution/README.md) |

Agent 配置发布、授权管理、技能与插件管理等链路后续分别制定，本次只展开任务执行。

## 3. 编写与实施约定

- 按通用任务执行平台的职责划分和调用链制定目标方案，不以当前项目代码状态推断进度，不限定现有包结构或实现语言。
- 所有事项初始为未完成；只有完成实现并通过对应验收后才标记完成。
- 区分目标行为和待验证假设，产品能力以实现及验收结果为准。
- 文档仅保存通用协议、设计和验收场景，不保存真实凭据、内部服务信息、部署地址或实际资源标识。
- 开发阶段可采用受控的直接执行环境；接入真实远程部署和不可信任务前，必须满足对应授权与隔离条件。
- 共用能力在首次需要的阶段实现，后续阶段复用，不按链路重复建设。

## 4. 既有文档

本目录原有顶层计划和专题文档保留为早期讨论记录。新的任务执行实施顺序以本目录下的链路总览及阶段文档为准；早期文档中的实现现状、文件位置和参数不自动成为新计划的约束。
