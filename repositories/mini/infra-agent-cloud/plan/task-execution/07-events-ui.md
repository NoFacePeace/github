# 事件展示与页面恢复

## 1. 阶段目标

在已有事件入库和结果查询基础上，实现任务页面、实时输出、历史恢复和跨连接重订阅。执行中刷新页面后，历史和后续输出都能正确展示。

## 2. 可运行链路

```text
Runner 事件 → Server 校验与业务提交
  → 有序事件缓存 / 日志缓存 / DB 状态
  → SSE history_sync + event_delta + session_end → 页面

刷新 → 同一 Task 权限校验 → 历史快照和当前执行水位
     → 重新订阅后续事件 → 持续展示
```

## 3. 依赖与边界

- 依赖前面阶段已有的真实事件消费、终态幂等、结果查询和日志归档，不重新建设任务执行流程。
- 历史重建和后续事件订阅分别验收，历史加载成功不等于已完成刷新后的持续订阅。
- SSE 仅管理展示连接，不承担执行授权；页面关闭、重连或历史查询不创建执行、不停止 Runner。
- MCP 工具接入和 steer 操作不作为本阶段前置条件，预留消息展示与控制事件扩展点。

## 4. 模块实现事项

### 4.1 事件缓存与日志查询

- [ ] 入口 Stream、Session 事件 ZSet、日志 String、状态 Hash 分别定义职责，不混用传输 ID、Seq 和日志字节 offset。
- [ ] 同一次执行可批量校验；写入时剔除重复前缀，对未写入事件检查连续性，序号缺口有补齐或明确失败策略。
- [ ] 保留执行绑定、缓存水位、终态提交状态、字节数、截断状态和完成状态，TTL 分开配置。
- [ ] 定义多连接重放策略：单个 SSE 连接推进游标不删除所有订阅者仍需要的事件；使用有界保留和超窗重同步。
- [ ] Server 优先读取日志缓存，缺失或截断时按归档完成状态回退对象存储；归档延迟不冒充空回复。
- [ ] Task 历史通过 DB 查询 Sessions，按顺序读取提示词、状态及各轮日志，不扫描 Redis 全部 key。
- [ ] 两种引擎的 JSONL 分别解析为统一展示消息；无引擎日志的排队失败或取消也能正确显示。

### 4.2 SSE 服务与快照衔接

- [ ] 校验任务访问权限，并从共享存储确定当前执行，不依赖创建任务的 Server 实例内存回调。
- [ ] 对外事件 ID 使用非授权用途的业务执行标识和 Seq，不暴露租约凭据。
- [ ] 建立与事件水位 S 对齐的历史快照，再从 Seq 大于 S 继续读取；明确日志片段与事件水位之间的对应关系。
- [ ] 在历史异步加载期间保留新增事件，不采用先读日志再跳到最新 Seq 的方式遗漏中间输出。
- [ ] DB 终态提交成功后再发送 session_end，缓存先写入终态不等于可提前向前端确认完成。
- [ ] 每个连接独立维护游标，重连到其他 Server 也可恢复；游标过期、缓存缺失或执行变化时触发显式重同步。
- [ ] 设置 SSE 心跳、代理缓冲策略、写入超时和慢客户端上限，断开时清理本连接资源。

### 4.3 Client

- [ ] 提供任务创建、状态与轮次列表、实时消息、停止和继续任务操作。
- [ ] 区分运行中、停止请求处理中、已结束等展示状态，命令已接受不显示为进程已退出。
- [ ] history_sync 替换对应快照，event_delta 按执行和 Seq 去重追加，session_end 与最终业务状态一致。
- [ ] 页面刷新保留 Task 定位，建立新连接恢复历史并订阅当前执行，不自动重复提交原提示词。
- [ ] 对断线、日志截断、归档暂缺、恢复窗口过期提供明确展示及重新同步行为。
- [ ] 历史分页或按需加载，不在每次打开页面时无限量读取所有轮次和日志。

## 5. 验收场景

- [ ] 执行中持续看到输出和最终结果，失败及停止均有准确展示。
- [ ] 历史加载时同时产生输出和终态，不丢片段、不重复消息、不提前确认完成。
- [ ] 页面刷新、短时断线、切换 Server 和多个页面同时打开，当前执行继续且各连接互不影响。
- [ ] Redis 日志过期后可恢复已成功归档历史；归档缺失明确可见。
- [ ] 游标超出保留窗口后显式重同步，慢连接不会无限积压内存。
- [ ] 新 Session 开始后正确切换执行游标，旧执行的迟到事件不混入新一轮。
- [ ] 未授权用户无法通过任务 ID、SSE 游标或归档定位读取输出。

## 6. 交付物

可操作的任务页面、SSE 与历史查询接口、双引擎历史解析、缓存和归档保留策略，以及刷新和并发输出竞争场景的端到端验证。
