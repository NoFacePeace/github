# 单节点远程闭环

## 1. 阶段目标

客户端调用 Server 创建任务，任务通过 Redis 交给指定的远程 Runner，执行事件回到 Server，最终结果和状态可查询。

## 2. 可运行链路

```text
提交请求 → Server 保存 Task / Session / 调度输入
  → 固定执行消息与基础租约 → Job Stream
  → 单个 Runner → Runtime → Executor
  → Event Stream → Server 保存 Session 结果 → 查询接口
```

## 3. 依赖与边界

- 依赖阶段二，新增数据库、Redis 和最小客户端访问权限。
- 只连接一个预先指定的 Runner，不实现完整多节点选择策略，但保留稳定执行身份和发布幂等。
- Agent 管理暂由固定测试配置代替，提交时解析成确定的执行快照。
- 在受控环境联调；真实远程部署必须具备身份校验、受限凭据交付和对应的隔离措施。

## 4. 模块实现事项

### 4.1 Server 业务与持久化

- [ ] 定义创建任务、查询任务、查询 Session 和结果的最小接口，校验访问权限。
- [ ] 保存 Task、Session、执行配置快照及来源版本；Session 业务运行状态覆盖排队和执行阶段。
- [ ] 使用数据库约束或事务保护活跃 Session，避免同一 Task 同时创建竞争轮次。
- [ ] 保存可恢复的调度输入或提交意图，入队失败有明确失败收尾或待补偿记录，不仅保存在请求内存中。
- [ ] 定义调度状态与业务状态的同步入口，排队取消和调度失败不伪造 Runner 事件。
- [ ] 以数据库事务保存引擎会话 ID、结果、用量、错误和终态，重复终态幂等应用。

### 4.2 Transport 与执行租约

- [ ] 定义 Job、Runner 事件和执行身份之间的映射；进程事件 Seq 与 Runner 对外事件 Seq 分别管理。
- [ ] 实现 Redis Stream 发布、消费者组读取、Ack、未确认消息重读及不可解析消息隔离。
- [ ] 提交后固定 MessageID、ExecutionID、目标 Runner 和执行消息，结果不确定时复用相同消息重试。
- [ ] 以原子操作完成发布去重标记和消息写入，禁止依次执行存在性判断与发布造成重复。
- [ ] 创建有限期的基础执行租约，Runner 启动前首次确认，执行期间持续续约；拒绝或本地到期后停止执行。
- [ ] 续约接口校验当前执行归属和 Session 状态，不让旧 Job 恢复已失效授权。
- [ ] Stream 消费确认含义固定：Runner 启动确认与 Server 终态持久化是不同阶段；若 Job 启动后即可 Ack，后续故障由租约和恢复记录追踪，不能再依赖 Job 留在未确认列表。

### 4.3 Runner 与凭据交付

- [ ] 将远程 Job 消费接入已有 SessionExecution，执行去重独立于 Stream 确认状态。
- [ ] 通过受限接口领取本轮执行所需敏感配置，Runner 节点身份和有效执行租约都要校验。
- [ ] 任务消息只携带执行引用及普通元数据，secrets 不进入普通 Job Stream；由 Runtime 通过 stdin 交付 Executor。
- [ ] 在同一次执行内串行回传事件，回传失败有界重试，不能直接丢弃终态。

### 4.4 Server 事件处理

- [ ] 校验 Runner、Session、执行归属、授权有效期和 Seq；按执行分组有序处理。
- [ ] 普通输出写入有界事件缓存和日志缓存，结果与终态保存到 DB，支持基础结果查询。
- [ ] 业务保存成功后再推进处理进度或释放租约，最后确认入口事件消费；部分成功允许幂等重试。
- [ ] 租约自然过期后到达的事件按明确策略处理，禁止旧执行更改新执行状态；已持久化终态的重放可完成剩余收尾。

## 5. 验收场景

- [ ] 通过 Server 提交一次真实任务，Runner 执行，查询接口返回同一 Session 的结果。
- [ ] 引擎启动或执行失败能通过事件回到 Server，业务状态不会误记为成功。
- [ ] Job 重复投递和事件重复消费不重复执行、不重复应用结果。
- [ ] Redis 暂时失败时提交状态明确，不能返回成功后丢失所有调度依据。
- [ ] 非授权节点、错误执行绑定和错误任务归属不能领取敏感配置或更新业务状态。
- [ ] 执行租约明确失效后 Runner 停止，协议输入与输出不暴露执行凭据。

## 6. 交付物

可在两个独立进程或节点上运行的 Server 与 Runner、最小数据库模型、消息与租约实现，以及创建到结果查询的联调流程。多节点调度和完整故障恢复分别进入后续阶段。
