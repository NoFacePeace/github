# 任务执行链路

## 1. 目标与范围

从命令行执行一次真实引擎任务开始，逐步实现远程任务提交、容量调度、停止恢复、会话续接和页面展示。

按服务端、执行节点、执行编排、运行环境、执行程序和引擎适配划分职责。本计划从目标行为出发，不复用当前项目的完成状态，也不要求沿用其接口或数据存储安排。

## 2. 完整调用链

```text
Client 提交任务
  → Server 创建 Task / Session 并入队
  → 调度器选择 Runner，预占执行租约和容量
  → Job 通道投递固定执行消息
  → Runner 接收 Job，SessionExecution 管理本轮执行
  → Runtime 准备环境，启动独立 Executor
  → Executor 选择 Engine，启动 Codex / Claude Code
  → 引擎输出 → Executor 进程事件 → Runner 执行事件
  → Server 校验、保存业务结果并释放执行占用
  → Client 查询结果或订阅 SSE
```

## 3. 模块职责

| 模块 | 职责 |
| --- | --- |
| Protocol | 版本化执行清单、敏感输入、进程事件、Job、命令、Runner 事件和心跳契约 |
| Server 业务服务 | Task / Session 创建、固定配置版本、停止意图、业务终态和查询 |
| Server 调度与协调 | 持久调度记录、节点发现、调度锁、执行租约、容量、投递去重和恢复 |
| Transport | Redis Stream 发布、消费、确认、未确认消息接管和失败隔离 |
| Runner 控制面 | 身份与心跳、Job / 命令消费、本地准入、事件回传 |
| SessionExecution | 本轮执行登记、准备、续约、超时、停止、事件消费和唯一终态编排 |
| Runtime | 执行目录、进程启动句柄、隔离、停止、销毁和残留进程恢复 |
| Executor | 独立 CLI、输入解析、公共引擎执行流程和统一进程事件 |
| Engine | 各引擎配置生成、启动命令、会话标识、进度和结果解析 |
| 日志与归档 | 本地日志、Server 热缓存、Runner 上传、历史查询及保留策略 |
| Client | 任务操作、状态展示、历史恢复和 SSE 增量消费 |

Runner 不访问业务数据库。Runtime 不解析引擎业务输出，Executor 不参与服务端调度和租约决策。任务编排通过 Runtime 返回的进程句柄读取版本化事件。

## 5. 跨阶段约束

- Task 表示持续任务，Session 表示一次业务轮次，ExecutionID 表示一次确定的执行，不能与消息 ID 或租约授权凭据混用。
- 同一 Task 的共享工作区和引擎上下文避免并发修改；新轮次不仅检查业务状态，还需确认上一轮实际执行已结束或完成隔离。
- Session 的运行状态可以覆盖排队、准备和执行；实际启动进度由调度状态和执行事件表达。
- 调度锁控制 Server 处理权，执行租约控制 Runner 执行资格，两者生命周期和续约分别管理。
- 固定执行身份和消息内容后重试投递，不因响应不确定就创建新执行；协议默认允许重复，业务处理必须幂等。
- Executor 的 stdout 只承载进程协议，stderr 输出诊断；敏感输入不进入命令行或普通任务消息。
- 任务输入和输出可能包含敏感业务内容，查询、SSE、日志及归档均沿用任务访问权限。
- 开发用直接执行模式不提供生产隔离承诺；不可信任务开放前落实目录权限、资源限制、网络边界及进程回收。
- 不承诺自动切换节点恢复完整工作区；日志或会话备份不等于完整 workspace 备份。

## 6. 与其他链路的依赖

| 外部能力 | 本链路使用方式 |
| --- | --- |
| Agent 配置发布 | 早期使用固定测试配置，后续接入不可变版本快照，不在本链路实现完整草稿发布界面 |
| 授权管理 | 开发阶段显式注入测试凭据；远程部署接入受限执行凭据接口，不实现完整用户授权产品流程 |
| MCP、技能、插件 | 本链路预留引擎配置扩展点，独立制定工具适配计划 |
| steer | 预留输入模式与控制协议版本，基础链路稳定后单独扩展，不默认作为本次阶段验收条件 |
| 平台运维与评测 | 输出必要健康、故障和性能指标，完整运营、评测及部署管理另行规划 |
