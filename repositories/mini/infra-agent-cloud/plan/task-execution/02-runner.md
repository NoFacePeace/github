# Runner 节点执行

## 1. 阶段目标

通过本地测试入口向 Runner 提交一条 Job，Runner 启动独立 Executor，接收事件并获得结果；执行中可停止，结束后完成资源清理。

## 2. 可运行链路

```text
本地测试 Job → Runner → SessionExecution
  → Runtime.start() → Executor → 引擎
  → ExecutionHandle.stdout → 事件回调 → 本地结果
```

## 3. 依赖与边界

- 依赖阶段一的 Executor 和进程协议，暂不需要业务数据库和消息队列。
- 开发阶段先交付直接执行 Runtime；Linux 隔离能力在开放不可信任务前验收，不与业务编排耦合。
- 测试入口复用正式执行编排，不另建一套仅用于演示的执行流程。

## 4. 模块实现事项

### 4.1 Runtime

- [ ] 定义 preflight、recover、start、stop、destroy 的职责和错误语义。
- [ ] 定义 ExecutionHandle：执行 ID、PID、stdout、stderr、等待退出和可选的控制输入写入能力。
- [ ] 准备 Task 与 Session 的目录、临时清单和权限；共享工作区与本轮临时文件分开。
- [ ] 启动独立 Executor，通过管道发送 secrets；启动成功返回句柄，不阻塞等待整轮完成。
- [ ] 普通模式写完 secrets 后关闭 stdin；stdout、stderr 保留给执行编排消费。
- [ ] 启动失败回收已创建资源；stop 先温和终止再强制清理，destroy 清理本轮临时资源并保留约定文件。
- [ ] 记录并核对执行进程身份，恢复时避免仅凭已复用 PID 误杀其他进程。
- [ ] 预留隔离 Runtime：在执行前完成 cgroup 归属、只读程序挂载、工作区和网络边界，失败不得静默降级。

### 4.2 SessionExecution

- [ ] 将 Job 映射为执行规格，登记执行句柄和取消入口，维护执行中、收尾中和已结束等本地阶段。
- [ ] 同一执行重复提交复用已有处理结果或拒绝重复启动；检查本地并发容量及同一 Task 工作区竞争。
- [ ] 逐行解析 Executor stdout，校验版本、ExecutionID、连续 Seq 和终态之后不得再输出的约束。
- [ ] 单独消费 stderr 诊断，限制缓存大小；两条输出流均及时读取，避免管道写满阻塞。
- [ ] 处理超时、取消、协议错误和输出回调失败，停止 Executor 并等待必要的输出排空。
- [ ] 终态先暂存，核对进程退出和读取结果后再对外确认；无终态或协议损坏明确报错。
- [ ] 完成后注销执行并销毁资源；主流程取消不跳过有界收尾。

### 4.3 Runner

- [ ] 提供本地测试 Job 入口、事件接收器和停止入口，调用同一个 SessionExecution。
- [ ] 启动时完成环境探测和残留执行恢复；退出时停止接收新任务并处理活跃执行。
- [ ] 本地运行诊断关联执行标识，不打印执行敏感配置。

## 5. 验收场景

- [ ] 本地提交 Job，收到开始、输出、终态，Runner 可继续接受下一条任务。
- [ ] 同一执行重复提交不会启动第二个引擎；达到本地容量上限时行为明确。
- [ ] 运行中停止或执行超时，整个执行进程树被回收，临时文件清理且任务文件保留。
- [ ] Executor 异常退出或输出错误协议时，Runner 返回失败并清理执行登记。
- [ ] 强制结束 Runner 后重启，残留执行可恢复处理，其他无关进程不受影响。
- [ ] 启用隔离后在目标 Linux 环境单独验证目录、资源和网络约束；本地直接执行测试不能替代该验收。

## 6. 交付物

可运行的 Runner 本地执行入口、Runtime 接口与实现、统一执行编排，以及节点启动、停止和清理验证说明。
