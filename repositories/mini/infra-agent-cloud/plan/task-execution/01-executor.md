# 独立 Executor 执行

## 1. 阶段目标

独立启动 Executor 程序，使用一种真实编程引擎完成任务，流式输出事件并返回可识别的结果。首次选择 Codex 或 Claude Code 之一，不同时建设两套适配。

## 2. 可运行链路

```text
CLI run → 执行清单和 stdin secrets
        → 公共执行流程 → Engine 适配器 → 引擎进程
        → stdout JSONL 事件 → 终态与程序退出码
```

## 3. 依赖与边界

- 只需本机具备选定引擎及测试凭据，不依赖 Server、Redis 或 Runner。
- 本阶段不实现 steer、MCP 网关、完整授权流程和沙箱。
- 在受控测试目录执行，不能据此允许多租户不可信任务。

## 4. 按核心流程实施

从一次命令行调用开始，沿实际执行路径逐段实现和验证。结构、接口和校验随使用点确定，不以现有 main、Spec、Secrets、Event、Result 或 Executor 接口为前提；本阶段所有事项重新按运行结果验收。

### 4.1 从命令行进入一次执行

- [ ] **CLI**：提供 run 入口，读取执行清单路径，运行命令能进入一次任务执行流程。
- [ ] **CLI**：读取清单并取得本次使用的引擎、提示词、执行目录和必要配置；在读取处确定最小输入结构及版本校验。
- [ ] **CLI**：从 stdin 取得本次引擎需要的敏感配置；普通模式明确以 EOF 结束，缺少输入、超限或读取超时立即失败。
- [ ] **CLI → Executor**：校验本次执行的必要输入和归属后，调用执行入口，传入取消信号和事件接收能力；函数签名随实际调用确定。

验证点：一条测试命令能读取输入并进入执行入口，输入失败时返回明确错误，不再以完成结构定义作为这一步的交付。

### 4.2 选择引擎并准备启动条件

- [ ] **Executor**：选择首个实际接入的引擎，确认程序可用；未支持的引擎在启动前明确拒绝。
- [ ] **Executor / Engine**：检查并准备工作目录、配置和本轮输出位置，路径使用前完成必要校验。
- [ ] **Engine**：把模型、系统提示词和认证方式转换为该引擎实际需要的配置、命令参数和环境变量。
- [ ] **Executor → Engine**：围绕这些真实调用提取适配边界，不要求保留现有 Codex.Run 或其他接口形式。

### 4.3 启动引擎并取得输出

- [ ] **Executor**：启动真实引擎子进程，设置工作目录和输入输出管道，并取得等待退出的能力。
- [ ] **Executor**：启动成功后及时并发消费 stdout/stderr，不等待退出才读输出。
- [ ] **Engine**：按所选引擎的实际格式识别输出、进度和会话信息，原始日志与解析结果分别处理。
- [ ] **Executor**：启动失败或任一输出处理失败时，进入同一条执行失败与清理路径。

### 4.4 将执行输出发送给调用方

- [ ] **Executor → CLI**：沿输出回调形成统一进程事件，按实际传输需要补齐协议版本、执行 ID、Seq、时间、类型和内容。
- [ ] **Executor**：同一次执行由一个发布器递增 Seq，stdout 和 stderr 不独立计数，保留开始与输出的确定顺序。
- [ ] **CLI**：将事件编码为 stdout JSONL，诊断只写 stderr；输出写入失败必须反馈给执行流程。

验证点：通过 CLI 执行简单真实任务，进程未结束时外部已能逐行读到其输出。

### 4.5 等待退出并确认执行结果

- [ ] **Executor**：等待引擎退出、排空本轮输出，再执行结果解析。
- [ ] **Engine**：从本轮真实输出和必要文件提取结果文本、引擎会话 ID、可获取用量及失败原因；在此处确定结果结构，不沿用未经调用验证的字段。
- [ ] **Executor → CLI**：将退出信息和解析结果组装为唯一终态事件，最后映射为程序退出码。
- [ ] **Executor**：引擎失败、解析失败和输出失败均明确报错，不将未完成的事件传输或缺少终态当作成功。

### 4.6 从取消信号完成进程收尾

- [ ] **CLI**：接收 SIGINT / SIGTERM，通过执行取消入口通知公共执行流程。
- [ ] **Executor**：请求引擎退出，超时后清理进程组，等待子进程退出再返回，不遗留后台进程。
- [ ] **Executor → CLI**：正常退出、失败和取消竞争时只生成一个逻辑终态，完成有界输出、信号监听释放和临时资源清理。

### 4.7 完成辅助命令与阶段验证

- [ ] **CLI**：未知命令和缺少参数返回非零退出码；preflight 检查真实引擎环境，version 输出程序版本。
- [ ] **CLI / Executor**：逐项验证版本、输入、目录、启动、读取、退出和取消错误，确认各调用点的校验与资源收尾完整。
- [ ] **CLI / Executor**：检查命令参数、事件和诊断不包含敏感配置，输入失败不回显敏感内容。
- [ ] **CLI**：提供一套独立运行示例，以真实引擎验证正常、失败和取消场景后再更新阶段进度。

## 5. 验收场景

- [ ] 执行简单真实提示词，运行中能读到增量事件，最后收到结果和正确退出码。
- [ ] preflight 报告程序与引擎可用状态，version 可独立运行。
- [ ] manifest 不存在、版本不支持、secrets 无效、输入不结束等情况明确失败，错误不回显敏感输入。
- [ ] 引擎启动失败、运行失败、输出解析异常可区分，不能将缺少终态当作成功。
- [ ] 运行中发送退出信号，Executor 和引擎子进程在限定时间内结束。

## 6. 交付物

可独立分发的 Executor 程序、版本化输入输出契约、单引擎适配器，以及包含正常、失败和取消场景的本地运行说明。
