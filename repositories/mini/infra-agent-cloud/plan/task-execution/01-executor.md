# 独立 Executor 执行

## 1. 阶段目标

独立启动 Executor 程序，使用一种真实编程引擎完成任务，流式输出事件并返回可识别的结果。首次选择 Codex 或 Claude Code 之一，不同时建设两套适配。

## 2. 可运行链路

```text
CLI run → 执行清单和 stdin secrets
        → 公共执行流程 → Engine 适配器 → 引擎进程
        → stdout JSONL 事件 → 终态与程序退出码
```

## 3. 依赖与边界

- 只需本机具备选定引擎及测试凭据，不依赖 Server、Redis 或 Runner。
- 本阶段不实现 steer、MCP 网关、完整授权流程和沙箱。
- 在受控测试目录执行，不能据此允许多租户不可信任务。

## 4. 模块实现事项

### 4.1 Protocol

- [ ] 定义 ExecutionSpec：协议版本、ExecutionID、引擎、提示词、工作目录、配置目录、会话目录和可选恢复会话 ID。
- [ ] 定义 ExecutionSecrets，与普通执行清单分开，包含版本、执行绑定及引擎所需敏感配置。
- [ ] 定义进程事件：版本、ExecutionID、Seq、时间、类型、payload；类型至少覆盖开始、输出和终态。
- [ ] 定义终态结果：退出信息、结果文本、引擎会话 ID 和可获取的用量；字段缺失与零值区分。
- [ ] 明确路径和输入校验、输入大小与等待上限、未知版本和畸形 JSON 的处理。

### 4.2 Executor CLI

- [ ] 支持 run、preflight、version 三个命令；未知命令、缺少必要参数返回非零退出码。
- [ ] run 读取 manifest 文件并解析执行规格，普通模式从 stdin 读取到 EOF 后解析 secrets。
- [ ] 校验 spec 与 secrets 的执行绑定；禁止将 secrets 写入 stdout 或诊断信息。
- [ ] 注册退出信号，并把取消传入执行流程；无 EOF 或输入超限时有界失败。
- [ ] 将事件编码为 JSONL 写入 stdout，诊断写 stderr；关闭时等待已产生事件写出。

### 4.3 公共执行流程与 Engine

- [ ] 定义引擎适配接口，包含配置生成、命令生成、会话 ID、进度和结果解析。
- [ ] 公共流程负责启动进程、并发读取 stdout/stderr、等待退出和清理，适配器只表达引擎差异。
- [ ] 引擎原始输出放在统一事件的 payload 中；引擎日志与统一事件格式分别管理。
- [ ] 多来源输出经过同一事件发布器分配 Seq，写入失败向执行流程传播，不静默忽略。
- [ ] 取消时先请求引擎退出，超时后清理进程组，等待退出后返回。
- [ ] 保证唯一逻辑终态，先排空输出再发送终态；异常退出时给出明确失败结果。

## 5. 验收场景

- [ ] 执行简单真实提示词，运行中能读到增量事件，最后收到结果和正确退出码。
- [ ] preflight 报告程序与引擎可用状态，version 可独立运行。
- [ ] manifest 不存在、版本不支持、secrets 无效、输入不结束等情况明确失败，错误不回显敏感输入。
- [ ] 引擎启动失败、运行失败、输出解析异常可区分，不能将缺少终态当作成功。
- [ ] 运行中发送退出信号，Executor 和引擎子进程在限定时间内结束。

## 6. 交付物

可独立分发的 Executor 程序、版本化输入输出契约、单引擎适配器，以及包含正常、失败和取消场景的本地运行说明。
