# 多引擎与会话续接

## 1. 阶段目标

补齐另一种引擎适配，使 Codex、Claude Code 均可在同一 Task 下进行多轮执行，每次继续创建新 Session，恢复原引擎上下文和任务文件。

## 2. 可运行链路

```text
继续任务 → 查询 Task 与上一轮执行结果
  → 确认旧执行已结束，使用原配置版本和节点绑定
  → 创建新 Session，携带恢复会话 ID
  → Runner 恢复必要文件 → Executor 使用引擎原生续接
  → 新一轮输出和结果 → 保存新的引擎会话信息
```

## 3. 依赖与边界

- 依赖阶段五的执行收尾和新轮次准入保护。
- 继续任务复用固定配置版本，不读取 Agent 最新草稿替代原版本；显式切换版本另行设计。
- 工作区默认保持节点亲和。会话备份恢复不等于支持完整工作区迁移。
- 继续提交新提示词、自动恢复未完成任务和执行中 steer 是不同操作，本阶段只实现新轮次续接。

## 4. 模块实现事项

### 4.1 Engine 与 Executor

- [ ] 按同一适配接口接入第二种引擎，公共进程、取消和事件流程保持复用。
- [ ] 分别实现两种引擎的配置、命令、原始输出、会话 ID 和结果解析。
- [ ] 根据非空恢复会话 ID 使用对应原生恢复机制，为不支持恢复或会话不存在提供明确错误。
- [ ] 两种引擎原始日志分别解析，统一输出外层执行事件和业务结果。
- [ ] 引擎版本与会话格式兼容性通过探测和真实续接验证，不只根据文件存在判断成功。

### 4.2 Server 续接与绑定

- [ ] 继续入口读取 Task、固定版本及上一轮 Session，明确没有历史会话时的首次执行规则。
- [ ] 将引擎会话 ID、配置版本和节点归属持久化，复制的是确定的续接信息，不复制上一轮租约授权。
- [ ] 原子保护新 Session 创建，检查上一轮实际执行是否结束，不仅检查业务状态。
- [ ] 新轮次生成新执行身份和消息 ID，同时保留 Task 身份及约定的工作区和引擎上下文。
- [ ] 上轮排队取消或从未执行时，记录其输入是否已被引擎接受；不把未执行提示词伪装成已存在于模型历史。

### 4.3 文件与归档

- [ ] 明确 workspace、引擎配置、引擎会话文件、输出日志和临时文件的分类与生命周期。
- [ ] Runner 周期上传日志，执行结束后备份约定的会话文件，敏感认证文件单独处理，不随普通归档扩散。
- [ ] 同一任务备份串行化或带版本，避免旧上传覆盖较新的会话；记录备份成功与覆盖范围。
- [ ] 恢复时校验任务归属、路径和文件完整性；只恢复约定内容，不从归档覆盖任意宿主路径。
- [ ] 原 Runner 暂时不可用、会话备份缺失或 workspace 丢失时明确返回环境不可恢复，不自动声称已迁移成功。

## 5. 验收场景

- [ ] 两种引擎分别完成至少两轮任务，第二轮能读取上一轮创建的文件和引擎上下文。
- [ ] 并发继续请求只允许一个新活跃轮次，上一轮尚未退出时不能竞争同一工作区。
- [ ] 用户停止后等待实际退出再继续，新执行不受上一轮迟到命令和事件影响。
- [ ] 上一轮未执行即取消时，历史展示和续接输入不会误认为提示词已被引擎处理。
- [ ] 删除可恢复的引擎会话文件后从成功备份恢复，真实引擎续接通过；完整工作区缺失场景明确失败。
- [ ] Agent 发布新版本不改变已有 Task 的执行版本。

## 6. 交付物

双引擎适配、继续任务入口、会话与节点绑定持久化、会话文件备份恢复，以及各类文件的保留和恢复边界说明。
