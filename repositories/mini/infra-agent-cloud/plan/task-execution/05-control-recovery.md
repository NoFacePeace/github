# 控制与故障恢复

## 1. 阶段目标

停止、网络中断、消息重投、节点失联或服务重启后，远程执行、Session 状态和容量能够最终收敛，不依赖单次请求或通知必达。

## 2. 可运行链路

```text
停止请求 → 保存停止意图 → 取消排队 / 发送停止命令
  → Runner 匹配执行 → Runtime.stop() → 实际退出
  → 终态处理 → 资源释放

失联 / 重启 → 周期扫描与消息接管
  → 核对调度、租约、已接收终态和业务状态 → 补偿收尾
```

## 3. 依赖与边界

- 依赖阶段四的调度状态、独立调度锁和执行租约，以及阶段二的进程清理能力。
- 分开记录停止意图和实际执行结果，明确两者的状态转换与并发处理规则。
- 不将租约过期当作远程进程已被同步杀死，不自动迁移工作区重跑原执行。

## 4. 模块实现事项

### 4.1 Server 停止入口

- [ ] 提供 Session 停止入口，事务读取最新业务状态并保存停止意图，重复请求幂等。
- [ ] queued 通过原子取消使旧调度者不能继续保存；进入投递阶段后按当前执行发布停止命令。
- [ ] 停止命令具有稳定命令 ID、目标执行、Runner 和有效期，重复发送复用相同逻辑身份。
- [ ] 停止意图进入执行授权校验，后续续约明确拒绝，同时保留追踪退出或到期所需信息。
- [ ] API 返回说明请求已接受，不能把命令发布成功表述为进程已退出。

### 4.2 Runner 控制与续约

- [ ] 命令消费与 Job 消费分开，按具体执行匹配句柄，命令重复或迟到不影响后续执行。
- [ ] 执行登记前的停止保留为待处理意图；准备中和进程启动后的停止都能接入同一取消链路。
- [ ] 租约首次确认后持续续约，使用本地保守期限；临时通信失败允许期限内重试，明确拒绝或到期取消执行。
- [ ] 取消时 Runtime 清理整个执行进程树，等待退出后进行有界终态回传和资源销毁。
- [ ] 进程已退出但仍在收尾时避免重复终止，唯一终态与停止请求竞争有确定规则。

### 4.3 恢复与跨存储补偿

- [ ] Server 定时分页扫描业务恢复候选，逐条复查最新 Session、调度记录、租约及已接受的终态。
- [ ] 尚未完成调度的任务交回调度器，已投递无有效执行且超过宽限期时按条件收敛失败。
- [ ] 优先重放已可靠接收但尚未持久化的终态，不能直接因租约已过期而覆盖为超时失败。
- [ ] 已有停止意图且执行仍有效时允许补发停止命令；无租约时完成业务收尾，重复补偿幂等。
- [ ] DB 已提交但租约释放、缓存 finish 或消息确认失败时保留可恢复进度，重放只完成未完成步骤。
- [ ] 接管未确认消息前核对执行身份，Job 重新送达不自动触发第二次真实执行。
- [ ] 执行进程恢复核对登记身份和隔离资源，避免 PID 复用造成误杀，处理残留 cgroup、网络及临时文件。
- [ ] 单条恢复失败记录后继续其他候选；循环异常有界退避并受服务退出控制。

### 4.4 故障观测

- [ ] 区分排队超时、调度锁失效、执行租约失效、协议错误、引擎失败和存储暂时不可用。
- [ ] 观测排队时长、预占数、续约失败、事件积压、终态补偿和残留进程，使用非敏感执行标识关联。
- [ ] 明确 Redis 持久化与备份边界；底层状态丢失不能仅靠重试假装具备完整恢复保证。

## 5. 验收场景

- [ ] 在排队、预占后、发布中、准备中和引擎运行中分别停止，最终状态和资源均正确。
- [ ] 停止命令重复、丢失或迟到时，续约兜底和恢复补偿仍能收敛，不停止新执行。
- [ ] Runner 短暂断网可在有效期限内恢复；持续失联后本地停止，Server 最终结束业务会话。
- [ ] 在预占、固定消息、发布、DB 终态提交和租约释放后分别注入进程退出，重启可恢复。
- [ ] 一个恢复候选持续报错，不阻塞其他任务调度和收尾。
- [ ] 新轮次准入同时检查上一轮有效执行，不能因业务状态先结束就立即竞争同一工作区。

## 6. 交付物

停止 API、命令消费、执行续约、恢复扫描和补偿机制，以及覆盖关键崩溃位置的故障注入验证说明。
