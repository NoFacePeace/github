# Infra Agent Cloud 实施计划

## 1. 目标与范围

完成以下闭环：创建 Agent → 发布版本 → 提交任务 → 分配 Runner → 执行任务 → 查看日志和结果。

在基础闭环之后补齐停止、超时和继续任务。先使用内存存储和模拟 Executor 验证逻辑，再接入真实 Codex，最后验证 Server 与 Runner 分进程远程运行。

当前状态：已初始化 Go module，创建 `server`、`runner`、`executor` 三个包，Go 文件仅包含包声明，业务能力尚未实现。

### 1.1 组织约定

- 保留现有三个包，不继续拆分业务模块；Runtime 放在 `runner` 内。
- 数据访问接口使用 `Store` 命名，定义在 `server/store.go`。
- 各包按职责定义接口，避免循环依赖；Executor 不依赖 Server 或 Runner，Runner 不依赖 Server 的业务实现。
- 模拟阶段通过接口连接组件；远程阶段使用 HTTP 传输任务、指令、心跳和事件，暂不引入消息中间件。
- 第一阶段只支持一种真实引擎 Codex，不同时扩展多种引擎。
- 开发阶段使用 direct 执行环境；Linux 沙箱隔离作为后续工作，不作为初版已具备的能力。

### 1.2 暂缓事项

数据库持久化、前端控制台、用户权限、技能与插件市场、MCP 接入、定时任务、文件云备份、跨 Runner 工作区迁移和生产级隔离暂不纳入基础闭环。内存存储的数据在 Server 重启后丢失，初版不承诺重启恢复。

## 2. 核心模型与约束

### 2.1 模型

| 模型 | 关键字段 | 所在位置 |
| --- | --- | --- |
| Agent | ID、名称、描述、当前发布版本 ID、时间戳 | `server/agent.go` |
| AgentVersion | ID、Agent ID、版本号、引擎、模型、系统提示词、时间戳 | `server/agent.go` |
| Task | ID、Agent ID、版本 ID、Runner ID、状态、时间戳 | `server/task.go` |
| Session | ID、Task ID、父 Session ID、提示词、状态、引擎会话 ID、退出码、错误、时间戳 | `server/task.go` |
| Runner | ID、实例 ID、在线状态、引擎能力、容量、活跃执行数、最近心跳时间 | `server/runner.go` |
| ExecutionAssignment | Session ID、Runner ID、实例 ID、租约 ID、租约过期时间 | `server/runner.go` |
| ExecutionEvent | 事件 ID、执行归属标识、序号、事件类型、内容、时间 | 在使用侧定义并映射为传输结构 |

Task 表示整件事，Session 表示其中一轮执行。继续任务时创建新的 Session，通过父 Session ID 连接到前一轮。初版将 Task 固定到原 Runner，以复用工作区。

### 2.2 状态与一致性

- Session 状态：`pending → running → completed / failed / stopped`；启动失败可由 `pending` 直接进入 `failed`，排队取消可直接进入 `stopped`。
- 超时和执行失联暂归为 `failed`，通过错误原因区分；停止请求只在进程退出确认后收敛为 `stopped`。
- Task 状态反映最近一轮 Session 的状态；继续任务时重新进入 `pending`，历史 Session 保留。
- 同一个 Task 同时最多存在一个待执行或运行中的 Session。
- 同一个 Session 同时最多存在一个有效执行归属；任务领取、容量预留和归属创建需要原子处理。
- 已发布 AgentVersion 不修改；Task 绑定具体版本，继续任务仍使用该版本。
- 事件必须校验 Runner 实例 ID 和租约 ID，拒绝旧执行更新状态；事件 ID 用于去重，序号用于保持顺序。
- 已结束的 Session 不被迟到日志或重复终态重新改为运行中。

## 3. 分阶段实施

### 3.1 阶段一：模型与内存存储

- [ ] 在现有文件中定义核心模型、状态和错误类型。
- [ ] 在 `server/store.go` 定义 Store 接口，新增 `server/memory_store.go` 实现并发安全的内存存储。
- [ ] 支持创建 Agent、发布版本、查询 Agent 和版本。
- [ ] 支持创建及查询 Task、Session，存储执行事件。
- [ ] 实现任务串行、版本不可变和执行归属更新约束。

验收：可以创建 Agent、发布两个版本，并证明已有 Task 的版本不随新发布变化；并发提交同一 Task 的执行时最多接受一轮。

### 3.2 阶段二：模拟执行闭环

- [ ] 在 `executor/executor.go` 定义执行输入、事件及执行接口，实现可控的模拟 Executor。
- [ ] 在 `runner/runtime.go` 定义环境准备与回收接口，提供开发用 direct 实现。
- [ ] 在 `runner/runner.go` 实现接收任务、容量控制、执行管理和事件回传。
- [ ] 在 `server/service.go` 实现 Runner 选择、容量预留和执行归属创建。
- [ ] 将事件写入 Store，驱动 Session 和 Task 状态更新。
- [ ] 保留任务工作区，执行结束后释放本轮占用和临时资源。

验收：使用模拟 Executor 完成创建 Agent、发布版本、提交任务、输出日志和查询最终结果；模拟失败可以得到失败原因；重复投递不会重复执行，容量耗尽时任务保持等待。

### 3.3 阶段三：停止、超时与继续

- [ ] Server 按执行归属向实际 Runner 路由停止指令；排队任务支持直接取消。
- [ ] Runner 通过取消信号终止执行，区分用户停止、超时和正常结束。
- [ ] Runtime 管理执行进程及子进程，确保停止后资源与并发占用被释放。
- [ ] 已结束 Task 支持创建后续 Session，复用原工作区和引擎会话 ID。
- [ ] 原 Runner 不可用时，继续请求明确返回不可用，不创建空工作区冒充恢复成功。

验收：长任务可停止，超时任务自动失败，停止与完成竞争时仅保留一个终态；继续任务生成新 Session 并保留前一轮记录。

### 3.4 阶段四：真实 Codex 执行

- [ ] 在 `executor/codex.go` 接入 Codex CLI，先确认目标 CLI 的输入、流式输出和恢复参数。
- [ ] 将配置、提示词及工作目录映射到实际调用，解析引擎会话 ID、日志、结果及退出状态。
- [ ] 凭证通过受控输入提供，不写入普通事件、命令参数或日志。
- [ ] 验证真实进程的停止、超时、子进程回收和会话继续。
- [ ] 对 CLI 不存在、启动失败及输出格式异常返回明确错误。

验收：在测试工作区执行一个创建文件的任务，查询日志与结果并核对文件内容；继续任务可以使用已有上下文修改该文件。真实验证需要本机已安装并配置 Codex CLI。

### 3.5 阶段五：远程进程闭环

- [ ] 增加 Server 和 Runner 的独立启动入口，不增加新的业务模块。
- [ ] 提供 HTTP 接口：创建 Agent、发布版本、提交及查询任务、查询事件、停止与继续任务。
- [ ] Runner 主动注册、上报心跳、领取任务与控制指令、回传事件并续租，避免要求 Server 直接访问 Runner。
- [ ] 使用版本化传输结构，携带任务 ID、Session ID、Runner 实例 ID、租约 ID与事件 ID。
- [ ] 初版使用配置的共享令牌验证 Runner 请求；远程连接使用 HTTPS，令牌通过请求头传递。
- [ ] Server 根据自身时间维护心跳和租约有效期，离线 Runner 不再接收新任务。
- [ ] HTTP 事件回传失败时在有界缓冲区内重试；Server 按事件 ID 去重，终态确认后才释放对应归属。
- [ ] Runner 续租持续失败并接近本地租约期限时停止执行；Server 租约到期后标记执行失联，不自动重复运行原任务。
- [ ] 优雅退出时停止接单，处理或停止活跃执行，并尽力上报终态。

验收：Server 与 Runner 分别作为独立进程运行，可经网络完成完整闭环；两个 Runner 能按能力和容量接单；旧租约事件被拒绝，网络重试不重复创建执行或事件。断连超过租约期限后任务明确失败，不宣称故障执行已迁移。

## 4. 验证与交付

### 4.1 核心验证

- [ ] 模型及存储测试：版本快照、并发创建、任务串行和执行归属唯一性。
- [ ] 模拟集成测试：成功、失败、停止、超时和继续。
- [ ] 通信测试：重复投递、重复事件、迟到事件、旧实例事件和租约过期。
- [ ] 真实执行验证：Codex 创建文件、停止进程和继续会话。
- [ ] 并发相关实现完成后运行 `go test -race ./...`。

- Server、Runner 启动入口与最小配置示例。

- 记录实际验证结果，以及内存存储、direct 环境、文件本地保留和故障恢复的限制。
