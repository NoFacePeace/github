## 1. MCP 工具

以下按知识库和运维场景整理只读 MCP 工具的职责，作为接口设计参考。具体能力和启用条件由实际实现决定。

| 类别 | 工具 | 用途 | 启用条件 |
| --- | --- | --- | --- |
| 仓库发现 | `list_repos` | 按名称、服务归属和描述发现仓库，返回仓库元数据和近期版本 | 接入仓库目录服务 |
| 仓库发现 | `find_repos_by_metric` | 按完整指标名精确查找候选仓库 | 接入文档服务 |
| 文档 | `list_documents` | 列出指定仓库、版本的文档元数据和摘要 | 接入文档服务 |
| 文档 | `get_document` | 按文档标识读取完整正文和元数据 | 接入文档服务 |
| 文档 | `search_documents` | 通过关键词与向量混合检索章节，支持游标续页 | 接入检索服务 |
| 文档 | `get_chapter` | 按章节标识读取正文，超长章节支持游标续页 | 接入检索服务 |
| 代码图谱 | `query_codebase` | 查询节点、关系、路径、遍历和影响范围 | 接入图谱服务 |
| 代码图谱 | `read_code_node` | 按源码版本和节点标识读取有界源码上下文 | 图谱、源码服务及脱敏机制可用 |
| 源码 | `list_repo_files` | 列出仓库目录项 | 接入代码托管服务 |
| 源码 | `find_repo_files` | 按路径或通配规则递归查找文件 | 接入代码托管服务 |
| 源码 | `read_repo_files` | 在同一版本下批量读取文件或片段，保留逐项错误 | 接入代码托管服务 |
| 源码 | `search_repo_code` | 通过字面量或正则表达式搜索源码，支持多查询和游标续查 | 接入代码托管服务 |
| 日志 | `query_logs_dedup` | 按服务标识查询日志并去重、聚合 | 接入日志数据源 |
| 指标 | `query_metrics` | 执行 PromQL 即时或区间查询，支持批量 | 接入指标数据源 |
| Trace | `search_trace` | 搜索调用链、调用片段或操作名称 | 接入链路追踪数据源 |
| Trace | `trace_detail` | 按链路标识获取单条调用链的详情 | 接入链路追踪数据源 |
| 告警 | `get_alert_detail` | 查询告警事件、触发规则、指标数据源和候选仓库 | 接入告警与指标数据源 |
| 部署 | `get_service_deployments` | 按服务标识查询运行部署和源码版本 | 接入部署信息数据源 |

文档、图谱和源码查询按仓库及版本限定范围，文档与章节也可按各自标识读取。日志、指标和链路查询使用对应的服务或数据源标识。批量读取和分页查询应保留逐项错误、截断信息和后续游标。

## 2. 配置

HTTP 监听地址通过命令行参数指定；业务配置通过 Go 配置结构体向构造函数传参，尚未接入配置文件或环境变量加载。

| 分类 | 配置项 | 默认值 | 说明 |
| --- | --- | --- | --- |
| 服务 | `-addr` | `:8080` | HTTP 监听地址，例如 `127.0.0.1:8081` |
| 仓库 | 自动描述 Token 上限 | `200` | 自动摘要的长度预算，按 tokenizer 计数；超限时截取前缀并优先在句子边界结束。配置字段及生成逻辑待接入 |
| 索引 | `BuildConfig.Split.ChapterMaxTokens` | `512` | 章节合并的词元预算；单个超长小节保持完整，交给后续文本块切分。传入 `0` 时使用默认值 |
| 索引 | `BuildConfig.Split.ChunkMaxTokens` | `512` | 每个文本块的词元上限，按固定窗口切分且块之间不重叠。传入 `0` 时使用默认值 |
| 全文索引 | `BuildConfig.Fulltext` | 空结构体 | 切块使用公共 `Split` 配置；分词规则当前固定在实现中，尚未开放专属配置字段 |
| 全文索引 | 中文字符 N-gram 的 `n` | `1` | 每个常用汉字作为一个词元（Unigram）；当前为固定规则，配置字段待接入 |
| 向量索引 | `BuildConfig.Vector` | 空结构体 | 切块使用公共 `Split` 配置，尚未开放专属配置字段 |
| 检索 | `RetrieveConfig.DefaultLimit` | `10` | 请求未指定结果数量时使用的返回上限，实际不超过 `MaxLimit` |
| 检索 | `RetrieveConfig.MaxLimit` | `100` | 请求允许指定的最大返回上限 |
| 检索 | `RetrieveConfig.CandidateMultiplier` | `3` | 全文和向量检索各自的候选数量相对于返回数量的倍数 |
| 检索 | `RetrieveConfig.MinBranchCandidates` | `50` | 每路候选数量下限；实际候选数量为 `max(结果数量 × CandidateMultiplier, MinBranchCandidates)` |
| 排名融合 | `RetrieveConfig.RRFK` | `60` | 倒数排名融合的平滑参数，融合逻辑待实现 |

| 配置规则 | 说明 |
| --- | --- |
| 构建配置入口 | [BuildConfig](knowledge/indexer.go) 通过 `NewIndexer(config, store, embedder)` 传入 |
| 检索配置入口 | [RetrieveConfig](knowledge/service.go) 通过 `NewService(store, indexer, embedder, config)` 传入；各字段传入非正数时使用默认值 |
| 公共切分 | `BuildConfig.Split` 控制两种索引共用的章节组织与文本块大小；词元按项目自身的分词规则计数，与外部向量模型的词元计数不一定相同 |
| 全文分词 | 倒排索引使用 `splitTokenSpans` 分词；分词器选择、分词规则版本等尚未配置化，与已有的章节、文本块大小配置分别说明 |
| 构建指纹 | 全文和向量索引的指纹均包含公共切分配置及各自专属配置，指纹计算逻辑待实现 |
| 依赖注入 | `store` 和 `embedder` 由调用方提供，分别实现 `Store` 和 `Embedder` 接口 |
| 后续配置 | 服务监听、存储连接和外部数据源配置在对应实现接入后补充 |

## 4. 本地运行

### 4.1 启动服务

在当前项目目录执行：

```bash
go run ./cmd/server
```

默认监听 `:8080`。也可以指定地址：

```bash
go run ./cmd/server -addr 127.0.0.1:8081
```

当前入口使用 Gin，提供进程健康检查；数据库、模型及业务接口后续接入。

### 4.2 健康检查

```bash
curl http://127.0.0.1:8080/healthz
```

成功返回 HTTP `200` 和 `{"status":"ok"}`，只表示 HTTP 服务存活。

### 4.3 停止服务

按 `Ctrl+C` 或向服务进程发送 `SIGTERM` 后停止接收新请求，最多等待 10 秒让存量请求完成；超时后强制关闭连接。
