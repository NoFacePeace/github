# Infra 知识库实现计划

## 1. 计划说明

本计划为 `infra-knowledge` 整理一套从零建设的实施路线，暂不受其现有目录和接口约束。

本计划存放于 `infra-knowledge/plan`。这里的阶段和待办描述目标能力，不代表当前已完成情况。本次只整理计划，不修改业务代码、数据库或对外接口。

- 编制日期：2026-11-15。
- 技术路线：Go 模块化单体、MySQL、Vue Web、REST 和只读 MCP。
- 第一版范围：完成阶段 1—4，打通仓库注册、文档导入、混合检索和仓库发现。
- 后续范围：源码查询、持久化构建、自动文档生成、代码图谱和运行时排障。
- 完成标记：表格首列 `☐` 表示未完成，`☑` 表示已完成；阶段内全部事项完成且阶段验收通过后，再勾选该阶段。
- 事项状态：所有事项初始为待开始；执行时将表格状态更新为进行中、已完成或阻塞，完成时同步勾选首列，并记录验证证据。
- 排期方式：先按依赖推进，确认人员、外部接口和模型资源后，再估算工期。

## 2. 模块与职责

以下目录表达职责归属，只有出现实际用例时才创建对应包，不提前建立空目录或占位类型。

| 模块 | 建议位置 | 负责事项 | 边界 |
| --- | --- | --- | --- |
| API | `internal/api` | REST/MCP、鉴权、请求校验、DTO 转换、错误映射 | 不实现业务规则；写操作通过 REST/UI |
| 仓库与构建 | `internal/build`、`internal/task/build` | 仓库注册、版本登记、构建请求、发现扫描、调度和租约 | 不拥有文档正文、索引和图谱正文 |
| Knowledge | `internal/knowledge` | 文档、标签、内容引用、暂存与发布、指标归属 | 不实现分词、向量召回和图查询 |
| Retrieval | `internal/retrieval` | 章节与分块、索引生命周期、全文/向量召回、融合和章节结果 | 索引是派生数据，不替代权威文档 |
| Source | `internal/source` | 固定 SHA 的目录浏览、路径查找、文件读取和代码搜索 | 不依赖文档生成或图谱构建 |
| Codegraph | `internal/codegraph`、`internal/task/codegraph` | 图谱产物、图谱版本、关系查询、影响分析、节点源码读取 | 与普通文档检索独立 |
| Runtime | `internal/runtime` | 日志、指标、Trace、告警和当前部署证据查询 | 不登记版本、不执行构建、不拥有部署状态 |
| Adapter | `internal/adapter` | MySQL、Git、模型、对象存储、图谱工具和外部平台接入 | 转换外部类型，不承载领域规则 |
| Platform / App | `internal/platform`、`internal/app` | 文件配置、日志、观测、生命周期和依赖组装 | 不承载领域状态或可复用业务编排 |
| Web | `web` | 仓库管理、导入、阅读、搜索、构建和排障页面 | 产品界面文字使用英文，与接口契约同步 |

领域内部采用 `domain / application / port` 分层。接口由消费方按真实用例定义；跨模块通过 port 与 adapter 衔接，领域层不依赖基础设施，实施时在本项目记录对应架构决策。

文档必须归属已注册仓库；非 Git 文档由内置虚拟仓库承载。不新增独立 `project` 实体或通用 `shared` 包。

## 5. 阶段 2：文档导入与发布模型

目标：明确文档事实、请求幂等和发布边界；本阶段不把未建索引的暂存内容当作导入成功。

| 完成 | 编号 | 模块 | 具体事项 | 验收标准 | 状态 |
| --- | --- | --- | --- | --- | --- |
| ☐ | S2-01 | Knowledge | 定义 Document、Tag、内容引用、仓库归属和领域校验 | 无效标题、正文或仓库归属返回稳定错误；时间与 ID 可注入 | 待开始 |
| ☐ | S2-02 | Knowledge / API | 定义导入 DTO、字段规范化规则及幂等请求指纹 | 明确参与指纹的字段；相同规范化请求复用同一文档，内容变化创建新文档 | 待开始 |
| ☐ | S2-03 | Adapter | 保存正文、元数据、标签、暂存状态和发布批次信息 | MySQL 保存权威数据；不单独创建 Chapter/Chunk 业务表 | 待开始 |
| ☐ | S2-04 | Knowledge | 实现暂存、失败保留、发布与软删除用例 | 目录和读取只返回有效已发布文档；失败可追踪、可重试 | 待开始 |
| ☐ | S2-05 | Application / Adapter | 定义导入编排与索引消费接口，避免 Knowledge 直接依赖 Retrieval 实现 | 索引完成前不可发布；发布失败不暴露半成品 | 待开始 |
| ☐ | S2-06 | API / Web | 实现导入、目录、详情、标签筛选与 Markdown 阅读 | API 明确区分暂存、失败和已发布；页面显示实际处理结果 | 待开始 |

阶段验收：通过边界测试验证重复请求、失败重试和暂存不可见；阶段 3 接入真实索引后再完成端到端导入验收。

## 6. 阶段 3：文档索引与检索

目标：打通手动上传到可检索章节的完整闭环。

| 完成 | 编号 | 模块 | 具体事项 | 验收标准 | 状态 |
| --- | --- | --- | --- | --- | --- |
| ☐ | S3-01 | Retrieval | 识别 Markdown 标题层级，建立 Chapter，再按固定无重叠窗口建立 Chunk | 标题路径和正文可还原；保留完整章节；明确大章节、代码块及空正文规则 | 待开始 |
| ☐ | S3-02 | Retrieval / Adapter | 实现中英文 tokenizer、倒排统计和 BM25 | 英文/数字连续串转小写，中文按单字即 unigram（n=1），查询与建索引使用同一规则 | 待开始 |
| ☐ | S3-03 | Retrieval / Adapter | 实现 Embedding port、模型适配器、批次与超时预算、向量索引 | 每个 Chunk 对应向量；校验维度和模型 profile，失败不生成假向量 | 待开始 |
| ☐ | S3-04 | Retrieval / Adapter | 持久化不可变文档索引，按发布范围重建内存缓存 | 重启加载已保存的词项、向量和章节信息，不重新调用 Embedding | 待开始 |
| ☐ | S3-05 | Retrieval | 实现仓库、已解析版本和标签过滤；并行全文/向量召回，RRF 融合 | 先融合 Chunk，再按 Chapter 聚合，以最佳 Chunk 得分排序，最后应用章节数量限制 | 待开始 |
| ☐ | S3-06 | Retrieval / API | 返回完整章节、父标题、相邻摘要、命中证据及分页 cursor | 按完整 JSON 限制响应大小；cursor 绑定查询范围和发布快照，快照失效明确报错 | 待开始 |
| ☐ | S3-07 | Knowledge / Retrieval | 接通真实索引与发布；实现缓存失效和直接章节读取校验 | 全文和向量索引均就绪才发布；同 Commit 换批次和删除后不读取旧缓存 | 待开始 |
| ☐ | S3-08 | Retrieval / Platform | 实现查询期向量故障的显式全文降级，记录耗时、候选数与错误 | 响应标识降级；导入索引失败仍保持未发布，不混用查询降级规则 | 待开始 |
| ☐ | S3-09 | API / Web | 实现文档目录、详情、检索、章节读取的 REST/MCP 和搜索页 | 四个文档 MCP 可用；页面按章节展示结果，并能进入文档阅读 | 待开始 |

阶段验收：上传中英文 Markdown，检索关键词与语义问题，读取完整章节；重复上传不重复生成兼容索引，重启后仍可查询。

## 7. 阶段 4：仓库发现与第一版交付

目标：用户不知道仓库名时，也能从业务或功能描述进入文档检索。

| 完成 | 编号 | 模块 | 具体事项 | 验收标准 | 状态 |
| --- | --- | --- | --- | --- | --- |
| ☐ | S4-01 | Build / Adapter | 定义仓库搜索用例与消费方 port，加载有效仓库描述向量缓存 | 启动可加载缓存；缺失或变化项有明确补建策略 | 待开始 |
| ☐ | S4-02 | Build / Adapter | 查询前同步轻量元数据，仅刷新新增、变更和删除的仓库 | 新注册、描述修改、软删除无需重启即可反映在搜索中 | 待开始 |
| ☐ | S4-03 | Build | 实现名称精确、前缀、包含、拆词和简单近似匹配，以及服务路径匹配 | 名称匹配优先、服务信息次之；匹配规则和排序可用固定样例解释 | 待开始 |
| ☐ | S4-04 | Build / Adapter | 查询向量只生成一次，与所有有效仓库缓存向量计算余弦相似度 | 描述语义候选默认阈值 0.45；名称命中不排除其他相关语义候选 | 待开始 |
| ☐ | S4-05 | Build / API | 综合评分后分页；Embedding 失败降级关键词；接入 `list_repos` | 明示 `hybrid` 或 `keyword_fallback`；不传 query 时浏览目录；附最近登记版本 | 待开始 |
| ☐ | S4-06 | Web / API | 完成发现仓库到搜索文档的导航、接入说明及第一版故障验证 | 业务描述 → 候选仓库 → 文档搜索 → 章节阅读可连续完成 | 待开始 |

第一版发布条件：阶段 1—4 全部通过；重复导入、索引失败、查询模型不可用、重启恢复、鉴权与软删除均有验证记录。自动生成、图谱和运行时查询不作为第一版依赖。

## 8. 阶段 5：源码查询

目标：直接查询注册仓库的指定源码版本，不要求先生成文档或图谱。

| 完成 | 编号 | 模块 | 具体事项 | 验收标准 | 状态 |
| --- | --- | --- | --- | --- | --- |
| ☐ | S5-01 | Source / Adapter | 实现注册身份读取、Git provider 和版本解析 | 接受有效完整 SHA；分支解析一次后返回 SHA，后续请求固定该版本 | 待开始 |
| ☐ | S5-02 | Source | 实现目录列表、路径发现、过滤及 provider 分页 | 不暴露任意 Git 地址访问能力；空页推进、路径和扫描上限明确 | 待开始 |
| ☐ | S5-03 | Source | 实现同 SHA 的批量文件或片段读取 | 一次 1—20 项，结果保序、逐项报错，共享截止时间和响应预算 | 待开始 |
| ☐ | S5-04 | Source | 实现 literal/RE2 搜索、最多 8 个 OR 查询及 continuation cursor | 扫描与输出有界；续页不会依赖服务端临时会话 | 待开始 |
| ☐ | S5-05 | Adapter | 接入保留行号的源码脱敏与策略指纹 | Gate 缺失或失败时拒绝返回源码正文，不将原始敏感内容输出到日志 | 待开始 |
| ☐ | S5-06 | API / Web | 发布四个源码 REST/MCP 及浏览搜索页面 | 未登记到版本账本但 Git 中存在的完整 SHA 可经 API 查询；结果明确版本 | 待开始 |

阶段验收：同一查询链路读取多个文件并续页，仓库分支更新不会改变已固定 SHA 的内容。

## 9. 阶段 6：持久化构建与版本发现

目标：先建设可靠调度，再接入长时间运行的生成器。

| 完成 | 编号 | 模块 | 具体事项 | 验收标准 | 状态 |
| --- | --- | --- | --- | --- | --- |
| ☐ | S6-01 | Build / Adapter | 定义 Repo Commit、producer 尝试、build 和 build_log 账本 | 文档与图谱分别记录状态和历史；生命周期为 pending/running/failed/succeeded | 待开始 |
| ☐ | S6-02 | Build / API | 手动请求只登记 pending，按仓库、SHA 和 producer 去重 | 重复请求返回已有状态；不在 handler 中直接启动生成协程 | 待开始 |
| ☐ | S6-03 | Task / Adapter | 实现数据库轮询、Repo 锁、租约、心跳和 token/attempt fencing | 无内存待执行队列；同仓库串行、跨仓库受控并发；使用数据库时钟判定租约 | 待开始 |
| ☐ | S6-04 | Task | 实现异常退出接管、正常停止、失败重试与显式重新构建 | 旧 token 无法续租、更新进度或发布；重试一项不破坏另一项成功结果 | 待开始 |
| ☐ | S6-05 | Task / Adapter | 分离 Branch、Tag 和部署版本发现，只登记完整 SHA | 并发扫描不重复登记；Tag 版本按规则比较；仅注册与冻结设置被遵守 | 待开始 |
| ☐ | S6-06 | Platform / Task | 定义实例额度、扫描开关、超时、错误分类和故障让位 | 任务禁用时不暗中恢复；外部失败与取消有明确区别，失败有日志和指标 | 待开始 |
| ☐ | S6-07 | API / Web | 构建列表、详情、日志、重试和重建入口 | 页面展示实际 producer 尝试和错误；显式区分已登记版本与已发布文档版本 | 待开始 |

阶段验收：以受控测试 producer 验证双实例竞争、租约过期、旧实例迟到写入、进程重启和单项失败恢复，再接入真实生成器。

## 10. 阶段 7：自动文档生成

目标：从不可变源码快照生成文档，校验和索引完成后整批发布。

| 完成 | 编号 | 模块 | 具体事项 | 验收标准 | 状态 |
| --- | --- | --- | --- | --- | --- |
| ☐ | S7-01 | Knowledge / Adapter | 生成输入固定到完整 SHA，构造脱敏快照并校验路径、大小和摘要 | 模型只读取受控不可变快照；输入与脱敏策略可追溯 | 待开始 |
| ☐ | S7-02 | Knowledge / Adapter | 接入 Agent Skills、manifest、模板和结果 checker | 固定输出系统设计、接口、指标、配置、代码导航五类文档；有基准时单独生成版本变化 | 待开始 |

阶段验收：分别注入生成失败、检查失败、索引失败和发布冲突；已有文档始终可读，索引重试不产生额外生成调用。

## 13. 接口交付清单

MCP 保持只读。REST 承担仓库维护、文档导入与删除、构建和重试等写操作。工具只在相应能力已实现且启用时注册。

| 阶段 | MCP 工具 | 关联 REST / Web 能力 |
| --- | --- | --- |
| 3 | `list_documents`、`get_document`、`search_documents`、`get_chapter` | 文档导入、目录、阅读和章节检索 |
| 4 | `list_repos` | 仓库注册、维护、发现和分页 |
| 5 | `list_repo_files`、`find_repo_files`、`read_repo_files`、`search_repo_code` | 源码浏览、文件读取和代码搜索 |
| 6 | 不新增写入型 MCP | 版本列表、构建请求、日志、重试和重建 |
| 7 | `find_repos_by_metric` | 指标归属查询、生成进度、索引重试与重建 |
| 8 | `query_codebase`、`read_code_node` | 图谱版本、关系查询和节点源码 |
| 9 | `query_logs_dedup`、`query_metrics`、`search_trace`、`trace_detail`、`get_alert_detail`、`get_service_deployments` | 外部证据与版本关联 |

接口统一区分 `repository`（仓库名）、`commitSha`（Git SHA）、`repoCommitId`（版本账本 ID）。已登记版本、文档发布版本、图谱版本和当前部署版本不能相互替代。

## 14. 配置与数据约定

以下是目标配置需求，不表示当前已有同名可配置字段。实际字段名、边界和默认值在所属阶段实现时确认。

| 分类 | 事项 | 计划约定 | 所属阶段 |
| --- | --- | --- | --- |
| 基础 | 服务、数据库、鉴权、日志 | 从 YAML 加载并校验，真实值只放受控配置或被忽略的本地文件 | 1 |
| 索引 | Chapter 组织、Chunk 窗口、索引格式版本 | 明确计量单位、大章节规则；索引语义纳入 profile | 3 |
| 全文索引 | 中文 n-gram | 首版支持 n=1；建索引与查询一致；变更分词语义需重建索引 | 3 |
| 向量索引 | provider、模型、维度、批量、超时 | 维度随模型校验；端点与凭据变化不等同于模型语义变化 | 3 |
| 检索 | 召回量、RRF、结果与 JSON 预算 | RRF k 默认参考 60；章节 limit 与 Chunk 召回量分开 | 3 |
| 仓库发现 | 语义阈值、缓存刷新、分页 | 语义阈值默认参考 0.45；先排序再分页 | 4 |
| 源码 | 文件数、行数、扫描量、cursor 和超时 | 读取与搜索均有界，脱敏失败拒读 | 5 |
| 构建 | 轮询、并发、租约、心跳、重试 | 开关显式；等待任务保存在数据库 | 6 |
| 生成 | 模型、专题预算、纠错和快照限制 | 生成预算与租约时长分开 | 7 |
| 仓库摘要 | 自动摘要 token 上限 | 默认 200，使用 cl100k_base；按 token 序列截断并保证文本有效 | 7 |
| 图谱 / Runtime | 运行时版本、查询预算、平台连接 | 能力独立启用，平台实现可替换 | 8、9 |

MySQL 是权威存储；正文和文档级索引首版存库，进程内检索缓存可重建。后续确有容量需求时，再通过 adapter 将正文或索引产物外置到对象存储，数据库保留引用、摘要和版本信息。首版不引入 Elasticsearch 或独立图数据库作为前置依赖。

数据库最终结构只维护在 `deploy/sql/db.sql`；不按事项累计迁移 SQL，不在应用启动时自动升级数据库。发版确需升级时，再按实际来源版本与目标结构统一生成、审查并执行迁移。

## 15. 测试、发布与事项完成标准

每个事项只有在行为、验证和必要文档同步完成后，才标记为已完成。测试描述对外行为和真实失败风险，不编写仅复述实现的测试。

| 验证层次 | 重点 | 执行时机 |
| --- | --- | --- |
| 领域与用例 | 校验、幂等、状态机、过滤、排序、版本和发布可见性 | 对新增行为先写失败测试，再实现 |
| 适配器集成 | MySQL 事务、唯一约束、Git、模型错误、超时与取消 | 对应 adapter 接入时 |
| 检索质量 | 中英文、符号、路径、关键词、语义问题和章节完整性 | 阶段 3 建立固定样例集，排序变化时复验 |
| 并发与故障 | 双实例竞争、租约过期、发布冲突、迟到写入、重启恢复 | 阶段 6—8，按影响运行 race 等检查 |
| 端到端 | 注册 → 导入 → 发现 → 检索 → 阅读，以及构建与重试 | 每个里程碑交付前 |
| 文档与运维 | 配置示例、API/MCP、用户指南、部署步骤、告警与回退 | 与对应功能同批交付 |

阶段交付还须满足：

- 运行受影响包测试和适用的格式、静态检查；跨模块变化再扩大验证范围。
- 用户可见能力、限制和工作流变化，同步双语 MCP Guide、双语 User Guide 及相关验证；本计划本身不改变当前产品指南。
- 生成、图谱等运行时依赖以固定版本交付；版本变更遵守运行时基础镜像规则。
- 日志包含请求、仓库、版本和构建尝试标识，避免真实凭据及未脱敏正文。
- 发版说明列明数据库前置操作、功能开关、依赖配置、失败恢复与回退办法。
- 跨领域依赖或架构决策变化先更新 ADR；保持 domain 无 I/O、SDK 和配置依赖。

## 16. 设计依据与执行记录

### 16.1 设计依据

本项目入口：[README](../README.md)。本计划采用以下设计原则，具体契约在对应阶段实现时记录于本项目文档。

- 模块边界：文档事实、索引检索、源码查询、代码图谱和运行时证据各自独立。
- 依赖方向：领域层保持纯业务逻辑，用例通过消费方接口访问外部能力，适配器负责具体实现。
- 数据与发布：权威数据持久化，索引可恢复，暂存内容不可见，发布按批次原子切换。
- 构建可靠性：任务持久化、租约接管、执行令牌校验和独立重试。
- 接口契约：区分仓库、源码版本、发布版本和部署证据，统一错误、分页及资源限制。
