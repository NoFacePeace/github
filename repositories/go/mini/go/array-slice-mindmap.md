# Go 数组与切片

## 数组

- 长度固定
- 元素连续存储
- 大小在编译期确定
- 常作为切片的底层存储

## 切片本质

- 动态数组视图
- 由连续的底层数组和运行时描述符组成
- 运行时描述符
  - Data：指向首元素
  - Len：当前元素数量
  - Cap：可扩展容量
- 多个切片可能共享同一个底层数组
- 修改元素可能影响其他共享该底层数组的切片

## 初始化

### 下标创建

- 从数组或切片中取得区间
- 不复制底层元素
- 创建新的切片描述符

### 字面量

- 推断底层数组大小
- 初始化数组元素
- 取得整个数组的切片

### make 创建

- 校验长度不大于容量
- 小且不逃逸
  - 底层数组可位于栈
- 逃逸或较大
  - 调用 runtime.makeslice
  - 通过 mallocgc 分配连续内存

## 访问元素

### len 和 cap

- 读取切片描述符字段
- 编译器可以直接优化

### 下标访问

- 计算元素地址
- 读取或写入底层数组

### range

- 编译器将其转换为更简单的循环

## append 追加

### 容量足够

- 直接写入原底层数组
- 更新 Len

### 容量不足

- 调用 growslice
- 分配新底层数组
- 复制旧元素
- 返回新的 Data、Len 和 Cap

### 使用建议

- 接收 append 的返回值
- 扩容后新旧切片可能不再共享底层数组

## 扩容策略

### 目标容量超过原容量两倍

- 采用目标容量

### 小切片

- 容量通常翻倍

### 大切片

- 容量逐步增长

### 内存对齐

- 按元素大小计算字节数
- 向分配器规格向上取整
- 实际容量可能大于预期容量

## copy 拷贝

### 拷贝数量

- 取源切片和目标切片长度中的较小值

### 实现

- 编译器可以直接生成内存复制
- 运行时场景调用 slicecopy
- 最终使用 memmove

### 特性

- 复制元素内容
- 不创建共享关系

## 实战记忆

- 切片赋值通常共享底层数组
- 切片取区间通常共享底层数组
- copy 会复制数据
- append 只有容量不足时才分配新数组并迁移数据

## 源码复刻说明

### 编译期间

- 编译器展开 make 创建切片的过程
- 编译器展开 append 的长度计算和容量判断
- 编译器决定是否尝试栈分配
- 编译器生成 makeslice 和 growslice 的调用

### 运行期间

- runtime makeslice 分配底层数组
- runtime growslice 计算新容量
- runtime 分配新的底层数组
- runtime 复制旧元素并返回新的切片描述符

### 无法完整复刻的逻辑

- 逃逸分析由编译器根据完整调用关系完成
- 真实栈分配由编译器生成栈帧和机器码
- 垃圾回收协作依赖 runtime 的对象类型信息和写屏障
- 内存分配器的规格对齐和复用无法用普通 Go 函数完全还原
