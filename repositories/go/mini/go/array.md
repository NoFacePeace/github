
## 8. 数组底层实现

### 8.1 内存布局

`[N]T` 是一个完整的值，数组元素在内存中连续排列，元素数据直接内联在数组中，不像切片那样通过指针引用独立的底层数组。因此，数组赋值和按值传参会复制整个数组，除非编译器能够将复制优化掉。

### 8.2 分配位置

数组并不固定分配在栈或堆上，具体位置由声明位置、逃逸分析、对象大小和编译器优化共同决定：

- 不逃逸的局部数组通常分配在 goroutine 栈上，也可能被 SSA 优化为寄存器或常量，不产生实际内存对象。
- 如果数组在当前函数之外仍然可达，例如返回局部数组的指针，逃逸分析会将其标记为 `EscHeap`，由运行时堆分配器分配。
- 取地址或使用 `new([N]T)` 不代表必然分配到堆；只要指针没有逃逸，对象仍可以分配在栈上。
- 过大的局部数组即使没有逃逸，也会为了限制栈帧大小而改为堆分配。当前 Go 1.28 开发版编译器的默认上限为：显式局部变量 128 KiB，`new([N]T)` 和 `&[N]T{}` 等隐式对象 64 KiB。这是编译器实现策略，不是 Go 语言规范的保证。
- 包级数组是静态存储对象：零初始化数据通常位于 `.bss`，非零初始化数据通常位于 `.data`，既不属于函数栈，也不是通过 `mallocgc` 动态分配的普通 Go 堆对象。

可以使用下列命令查看具体程序的逃逸分析结果：

```bash
go build -gcflags='-m=2' .
```
