# 操作系统基础

操作系统为应用程序提供统一的运行环境和系统接口，负责管理处理器、内存、文件、设备以及进程等资源。本章从系统接口开始，理解应用程序如何通过系统调用与内核交互。

## 1. 系统接口

系统接口是应用程序与操作系统交互的总称，系统调用是其中直接请求内核服务的一类接口。

| 接口类型 | 性质 | 常见接口 | 所在层次或特点 |
| --- | --- | --- | --- |
| POSIX 接口 | 标准规范 | `open()`、`read()`、`pthread_create()`、`socket()` | 规定 Unix-like 系统中常用接口的名称和基本行为，强调可移植性 |
| C 库接口 | 用户态库函数 | `printf()`、`malloc()`、`fopen()`、`read()` | 由 glibc 等库提供，负责用户态处理和系统调用封装 |
| 系统调用 | 内核服务入口 | `read()`、`write()`、`mmap()`、`fork()`、`execve()` | 应用请求内核服务的正式入口，涉及用户态与内核态切换 |
| Linux 特有接口 | 平台扩展 | `epoll`、`signalfd`、`eventfd`、`inotify`、`io_uring` | Linux 提供的扩展能力，功能更强但移植性较弱 |

进程管理、文件与目录、内存管理、网络 I/O 和设备控制属于按功能领域划分的接口分类，不与上表的层次分类并列。

## 2. 中断机制

### 2.1 中断的概念

中断是一种让硬件或软件通知 CPU 处理特定事件的机制。当中断发生时，CPU 暂停当前正在执行的程序，保存必要的执行现场，转而执行操作系统预先注册的中断处理程序；处理完成后，再恢复现场并继续执行原来的程序。

中断使 CPU 不需要持续检查设备状态。例如，键盘按键、网卡收包、磁盘 I/O 完成以及定时器到期等事件，都可以通过中断及时通知操作系统。

### 2.2 中断的分类

| 类型 | 触发来源 | 常见示例 |
| --- | --- | --- |
| 硬件中断 | 外部硬件设备 | 键盘输入、网卡收包、磁盘读写完成、定时器到期 |
| 软件中断 | 软件主动触发 | 系统调用、调试请求 |
| 异常 | CPU 执行指令时检测到特殊情况 | 除零、非法指令、缺页异常 |

### 2.2.1 硬件中断

硬件中断由处理器外部的硬件设备或设备控制器产生，通常与当前程序执行的指令无关，因此具有异步性。设备在事件发生后向 CPU 发出中断请求，操作系统再根据中断号找到对应的中断处理程序。

常见的硬件中断包括：

- 键盘或鼠标产生输入事件。
- 网卡收到数据包。
- 磁盘完成一次读写操作。
- 系统定时器到期，触发时钟中断。

硬件中断可以避免 CPU 不断轮询设备状态。对于多个设备同时产生中断的情况，系统还可以结合中断优先级和中断屏蔽机制决定处理顺序。

### 2.2.2 软件中断

软件中断由程序主动执行特定指令触发，通常用于让用户程序请求操作系统服务，或进入调试和管理流程。与硬件中断不同，软件中断通常发生在当前程序执行到特定指令时，因此具有同步性。

系统调用是软件中断的重要应用场景。例如，应用程序调用 `read()`、`write()` 或 `fork()` 时，C 库函数可能通过系统调用指令进入内核态，由内核完成相应操作后再返回用户态。

不同处理器架构对软件中断和系统调用的具体实现可能不同。现代处理器通常提供专门的系统调用指令，但从操作系统功能上看，它们都承担了从用户态进入内核态的作用。

### 2.3 中断处理流程

一次典型的中断处理过程如下：

1. 设备或软件产生中断请求。
2. CPU 响应中断，暂停当前程序的执行。
3. CPU 保存程序计数器、处理器状态等必要的执行现场，并切换到内核态。
4. CPU 根据中断号查询中断向量表，找到对应的中断处理程序。
5. 操作系统处理中断事件，例如读取设备状态、复制数据或唤醒等待中的进程。
6. 恢复被暂停程序的执行现场，返回原来的执行位置继续运行。

中断处理程序应尽快完成必要的工作。对于耗时较长的任务，操作系统通常会先在中断处理程序中完成紧急处理，再将后续工作延迟到合适的内核执行上下文中，以减少对其他任务的影响。

### 2.4 中断相关概念

- **中断请求**：设备或软件向 CPU 发出的处理请求。
- **中断号**：标识中断来源的编号，CPU 可以据此找到对应的处理程序。
- **中断向量表**：保存中断号与中断处理程序入口地址映射关系的数据结构。
- **中断处理程序**：操作系统针对某类中断编写的处理代码，也称为中断服务程序。
- **中断屏蔽**：暂时禁止响应某些中断，避免关键代码执行过程中被打断。
- **中断优先级**：多个中断同时到来时，操作系统或硬件决定处理顺序的规则。

### 2.5 中断与轮询、系统调用的区别

**轮询**是 CPU 主动反复检查设备状态；**中断**则是设备在事件发生后主动通知 CPU。轮询实现简单，但可能浪费 CPU 时间；中断可以减少无效检查，更适合处理不确定时间发生的 I/O 事件。

**系统调用**是应用程序主动请求操作系统提供服务，例如读取文件或创建进程；**中断**是通知 CPU 处理事件的底层机制。系统调用通常通过专门的陷阱指令或系统调用指令进入内核，而设备 I/O 的完成则经常通过硬件中断通知操作系统。
