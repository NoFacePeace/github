# 进程与线程

进程是资源分配和隔离的基本单位，线程是进程内执行工作的基本单位。学习时先理解进程，再理解线程，最后比较两者在资源、通信、切换和使用场景上的差异。

建议按照以下顺序学习：

1. 进程基础：进程定义、程序与进程的区别，以及进程拥有的资源。
2. 进程生命周期：进程状态、父子进程、僵尸进程和孤儿进程。
3. 进程的创建与执行：`fork`、`exec`、`waitpid`、`exit` 以及命令行执行过程。
4. 进程关系与资源：进程组、会话、文件描述符继承、环境变量继承和写时复制。
5. 进程间通信：管道、信号、消息队列、共享内存和 Socket。
6. 线程基础：线程模型、共享资源、线程栈、线程创建与结束。
7. 线程间通信：共享数据、互斥锁、条件变量、信号量和原子变量。
8. 进程与线程对比：资源隔离、通信方式、切换开销、故障影响和适用场景。
9. Linux 实践：使用 `ps`、`pstree`、`/proc` 以及 POSIX API 观察和验证相关机制。

## 1. 进程基础

### 1.1 进程是什么

- 进程是程序的一次执行实例。
- 程序是静态的代码和数据，进程是程序运行后的动态实体。
- 进程拥有独立的虚拟地址空间，以及文件描述符、信号处理配置等内核资源。

### 1.2 进程拥有的资源

进程通常拥有或管理以下资源：

- 虚拟地址空间，包括代码段、数据段、堆和用户栈。
- 打开的文件描述符，例如普通文件、管道和 Socket。
- 当前工作目录、根目录和环境变量。
- 信号处理配置、用户身份和权限信息。
- 一个或多个线程，以及进程的退出状态。

进程之间默认相互隔离，一个进程不能直接读取或修改另一个进程的普通内存。

## 2. 进程生命周期

### 2.1 进程状态

重点理解进程从创建到结束的状态变化：

1. 创建：父进程通过 `fork`、`vfork` 或其他接口创建子进程。
2. 就绪：进程已经具备运行条件，等待调度器分配 CPU。
3. 运行：进程正在 CPU 上执行。
4. 阻塞：进程等待 I/O、锁、信号或其他事件。
5. 终止：进程执行结束，释放资源并保存退出状态。

进程在就绪、运行和阻塞状态之间切换，具体切换由调度器、系统调用和外部事件共同触发。

### 2.2 父子进程

创建子进程后，父进程和子进程拥有不同的进程控制块和虚拟地址空间，但子进程通常会继承父进程的部分属性，例如文件描述符、当前工作目录和环境变量。

父子进程可以独立运行，也可以通过等待、信号或进程间通信进行协作。

### 2.3 僵尸进程与孤儿进程

- **僵尸进程**：子进程已经退出，但父进程尚未通过 `wait` 或 `waitpid` 回收退出状态。僵尸进程不再运行，但仍保留少量内核信息。
- **孤儿进程**：父进程先于子进程退出，子进程会被系统重新托管，之后由新的父进程负责回收。

## 3. 进程的创建与执行

### 3.1 `fork`：创建子进程

`fork` 创建一个与父进程近似相同的子进程。调用成功后，父进程和子进程都会从 `fork` 返回的位置继续执行。

```c
pid_t pid = fork();

if (pid == -1) {
    // 创建失败
} else if (pid == 0) {
    // 子进程
} else {
    // 父进程，pid 是子进程 PID
}
```

返回值具有区分父子进程的作用：

- 返回 `-1`：创建失败，只在调用进程中返回。
- 返回 `0`：当前代码运行在子进程中。
- 返回大于 `0`：当前代码运行在父进程中，返回值是子进程的 PID。

子进程最初拥有父进程地址空间的逻辑副本，通常通过写时复制避免立即复制全部物理内存。

### 3.2 `exec`：加载新程序

`exec` 不会创建新进程，而是用新的程序映像替换当前进程的代码、数据、堆和栈。进程的 PID 通常保持不变。

`exec` 成功后不会返回，只有加载失败时才会返回错误。因此常见写法是在失败后打印错误并退出子进程：

```c
execlp("ls", "ls", "-l", NULL);
perror("execlp");
_exit(127);
```

### 3.3 `wait` 和 `waitpid`：等待并回收

父进程可以使用 `wait` 或 `waitpid` 等待子进程结束，并取得子进程的退出状态。

- `wait`：等待任意一个子进程。
- `waitpid`：等待指定的子进程，也可以选择不阻塞。
- 回收退出状态可以避免子进程长期处于僵尸状态。

### 3.4 `exit` 和 `_exit`：进程退出

- `exit` 结束进程，并执行用户态退出处理，例如刷新标准 I/O 缓冲区和调用退出处理函数。
- `_exit` 直接进入内核退出流程，常用于 `fork` 后的子进程在 `exec` 失败时退出，避免重复刷新父进程继承的缓冲区。

### 3.5 命令行执行 `ls`

从命令行执行 `ls` 时，Shell 通常会经历类似流程：

```text
用户输入 ls
    ↓
Shell 解析命令，查找 ls 的路径
    ↓
Shell fork 创建子进程
    ├── Shell 父进程 wait，等待子进程结束
    └── 子进程 exec 加载 /bin/ls
          ↓
        ls 执行并输出目录内容
          ↓
        子进程退出，Shell 回收退出状态并显示新的提示符
```

Shell 通常保留在父进程中，通过子进程执行外部命令，这样命令结束后还能继续接受用户输入。对于 `cd` 这类 Shell 内建命令，通常由 Shell 自己执行，因为子进程中修改的工作目录不会影响父 Shell。

## 4. 进程关系与资源

### 4.1 进程组与会话

多个相关进程可以组织成进程组，多个进程组又可以组成会话。Shell 使用这些关系管理前台任务、后台任务和终端信号。

### 4.2 文件描述符继承

`fork` 后，子进程会继承父进程打开的文件描述符。父子进程可以通过关闭不需要的描述符，把管道或重定向连接起来。

例如，Shell 执行管道命令 `cat file | grep key` 时，可以创建两个子进程，并通过管道连接前一个命令的标准输出和后一个命令的标准输入。

### 4.3 环境变量和工作目录继承

子进程通常继承父进程的环境变量、当前工作目录和根目录。子进程之后的修改不会反向改变父进程的这些状态。

### 4.4 写时复制

`fork` 后父子进程逻辑上拥有相同的地址空间，但物理页面通常先由双方共享。任一进程尝试写入共享页面时，内核才复制该页面，这就是写时复制。

## 5. 进程间通信

不同进程通常拥有相互隔离的地址空间，需要借助内核提供的通信机制交换数据或传递事件。常见方式有五类：

1. **管道**：以字节流的形式传递数据，包含匿名管道和命名管道。
2. **信号**：传递简单的异步事件通知。
3. **消息队列**：以消息为单位交换数据，保留消息边界。
4. **共享内存**：让多个进程访问同一段内存，通常需要配合同步机制。
5. **Socket**：支持本机或跨网络的双向通信。

选择通信方式时，需要同时考虑数据量、是否需要保留消息边界、通信方向、同步要求、通信范围、生命周期和故障隔离。

### 5.1 管道

管道通过内核缓冲区传递字节流，数据从写端进入，从读端取出。学习管道时，建议先理解匿名管道，再学习命名管道，最后对比两者的使用场景和生命周期。

#### 5.1.1 管道的基本特性

管道通常具有以下特性：

- 以字节流传输数据，不保留应用层消息边界。
- 读端没有数据时可能阻塞，写端没有空间时也可能阻塞。
- 所有写端关闭后，读端读取到 EOF。
- 匿名管道通常是单向通信；需要双向通信时，通常创建两条管道。
- 管道容量有限，写满后阻塞模式下的写操作会等待。

#### 5.1.2 匿名管道

匿名管道通常用于具有父子关系的进程之间。可以通过 `pipe()` 或 Linux 的 `pipe2()` 创建：

```c
int pipefd[2];

if (pipe(pipefd) == -1) {
    perror("pipe");
}
```

创建成功后，`pipefd[0]` 是读端，`pipefd[1]` 是写端。常见使用流程是先创建管道，再调用 `fork()` 创建子进程。父子进程会继承管道的文件描述符，然后分别关闭不需要的一端。例如，父进程只写，子进程只读。

Shell 中的管道符 `|` 也使用匿名管道：

```bash
cat file.txt | grep error
```

这条命令会将 `cat` 的标准输出连接到 `grep` 的标准输入。

- 匿名管道没有文件系统路径。
- 父子进程通常通过 `fork()` 继承管道文件描述符。
- 所有文件描述符关闭后，管道随之释放。

#### 5.1.3 命名管道

命名管道也叫 FIFO，是一种在文件系统中拥有路径的管道。可以通过 `mkfifo()` 或命令行工具 `mkfifo` 创建：

```bash
mkfifo mypipe
```

然后，两个没有父子关系的进程也可以通过这个路径通信：

```bash
# 终端 1：读取
cat mypipe

# 终端 2：写入
echo "hello" > mypipe
```

命名管道不是普通的磁盘文件，路径只是进程发现和打开它的入口。命名管道还具有以下特点：

- 命名管道可以被没有父子关系的进程打开，使用结束后需要删除路径。

#### 5.1.4 匿名管道与命名管道的区别

| 对比项 | 管道 | 命名管道 |
| --- | --- | --- |
| 创建接口 | `pipe()` / `pipe2()` | `mkfifo()` |
| 是否有路径 | 没有 | 有 |
| 典型进程关系 | 通常是父子进程 | 可以是任意进程 |
| 生命周期 | 文件描述符关闭后释放 | 路径需要显式删除 |
| 常见场景 | Shell 管道、父子进程通信 | 独立进程之间的简单通信 |

选择管道还是命名管道时，主要看通信双方是否需要通过文件系统路径发现彼此，以及是否存在父子进程关系。

### 5.2 消息队列

消息队列是由内核维护的消息列表，发送进程将一条完整消息放入队列，接收进程再按消息取出。它和管道的主要区别是：管道传递连续的字节流，而消息队列保留每条消息的边界。

```text
发送进程
    ↓ 发送消息
内核消息队列：[任务 1] [任务 2] [任务 3]
    ↓ 接收消息
接收进程
```

#### 5.2.1 消息队列的特点

- 以消息为单位传递数据，接收方不需要自行拆分字节流。
- 发送方和接收方不必同时运行，消息可以暂时保存在内核队列中。
- 队列为空时，接收操作可能阻塞。
- 队列已满时，发送操作可能阻塞。
- 消息队列容量有限，需要考虑单条消息大小和队列总容量。
- 消息通常可以携带类型或优先级，接收方可以按条件选择消息。

#### 5.2.2 常见接口

Linux 中常见两套消息队列接口：

- **POSIX 消息队列**：`mq_open`、`mq_send`、`mq_receive`、`mq_close` 和 `mq_unlink`。
- **System V 消息队列**：`msgget`、`msgsnd`、`msgrcv` 和 `msgctl`。

POSIX 消息队列通常通过名称访问，System V 消息队列通常通过系统分配的标识符访问。学习时先掌握消息模型，再根据实际项目选择接口。

#### 5.2.3 发送与接收流程

发送方和接收方的基本流程如下：

```text
发送方打开或创建消息队列
    ↓
发送一条完整消息
    ↓
接收方打开同一个消息队列
    ↓
按顺序或按类型取出消息
    ↓
通信结束后关闭并删除队列
```

消息内容可以是文本，也可以是经过序列化的结构化数据。多个进程共享消息队列时，需要约定消息格式、类型、版本和错误处理方式。

#### 5.2.4 适用场景

消息队列适合传递任务、事件和结构化消息，例如：

```text
[发送邮件] [生成报表] [处理订单]
```

如果需要传输连续数据流，可以优先考虑管道；如果需要多个进程共享大量数据，则通常考虑共享内存；如果需要跨主机通信，则通常考虑 Socket。

## 6. 线程基础

### 6.1 线程是什么

线程是进程内独立调度的执行流。同一进程中的多个线程共享进程资源，但每个线程拥有自己的执行上下文：

- 共享：虚拟地址空间、代码段、堆、全局变量、打开的文件描述符和信号处理配置。
- 独立：线程栈、程序计数器、寄存器状态、线程局部存储和调度状态。

### 6.2 线程的创建与结束

以 POSIX 线程为例：

- `pthread_create` 创建线程并开始执行指定函数。
- `pthread_join` 等待目标线程结束，并回收相关资源。
- `pthread_detach` 将线程设置为分离状态，结束后由系统自动回收资源。
- 线程函数返回或调用 `pthread_exit` 可以结束当前线程。

线程创建后，多个线程可能同时访问共享数据，因此线程生命周期必须和资源所有权、退出流程一起设计。

## 7. 线程间通信

同一进程中的线程可以直接通过共享变量交换数据，但共享数据必须建立明确的同步规则。常见方式包括：

- 共享内存加互斥锁。
- 条件变量配合状态检查。
- 信号量控制资源数量。
- 原子变量处理简单的无锁状态更新。

线程间通信速度通常较快，但共享地址空间也意味着一个线程的错误可能影响整个进程。

## 8. 进程与线程的对比

| 对比项 | 进程 | 线程 |
| --- | --- | --- |
| 地址空间 | 通常相互隔离 | 同一进程内共享 |
| 资源拥有 | 拥有独立进程资源 | 使用所属进程的资源 |
| 创建与切换 | 成本通常较高 | 成本通常较低 |
| 通信方式 | 需要 IPC 机制 | 可直接访问共享数据，但需要同步 |
| 故障影响 | 通常限制在单个进程 | 可能影响整个进程 |
| 适用场景 | 隔离性要求高、独立服务 | 共享数据、并行执行、提高响应能力 |

“线程切换一定比进程切换快”不是绝对规则。实际开销还取决于地址空间切换、缓存、TLB、内核实现和运行时负载。

## 9. Linux 实践

建议按照以下顺序练习：

1. 使用 `ps`、`pstree` 和 `/proc` 观察进程层级、状态、地址空间和文件描述符。
2. 编写程序验证 `fork`、`exec`、`waitpid` 和退出状态。
3. 观察父子进程的写时复制行为。
4. 使用管道连接两个命令，观察文件描述符继承和标准输入输出重定向。
5. 分别使用管道、共享内存和 Socket 完成进程间通信。
6. 使用 POSIX 线程 API 创建、等待和结束线程。
7. 使用互斥锁和条件变量解决生产者消费者问题。
8. 对比多进程和多线程程序的资源占用、故障隔离和执行开销。

## 10. 常见问题

- `fork` 后父子进程拥有不同的地址空间，修改普通变量不会直接修改对方的数据。
- `exec` 替换的是当前进程映像，不是创建一个新的 PID。
- `waitpid` 回收的是子进程的退出状态，不是重新启动子进程。
- 线程共享地址空间不代表访问共享数据就是安全的，仍然需要正确的同步。
- 进程退出后，父进程没有及时回收退出状态可能产生僵尸进程。
- 线程结束后，未正确 `join` 或 `detach` 可能造成线程资源没有被回收。
