# 文件描述符

文件描述符（File Descriptor，FD）是操作系统分配给进程的非负整数，用于表示一个已经打开的 I/O 资源。应用程序通过文件描述符调用 `read`、`write`、`close` 等接口，而不需要直接管理内核中的资源对象。

## 1. 文件描述符的作用

文件描述符是进程访问 I/O 资源的句柄。它可以指向：

- 普通文件
- 管道和命名管道
- 终端
- Socket
- 设备文件
- `epoll` 等内核 I/O 对象

这些资源的底层实现不同，但都可以通过统一的文件描述符接口进行部分操作。这是 Unix-like 系统“很多对象都可以像文件一样操作”的重要基础。

文件描述符本身不是文件，也不是资源对象，而是进程文件描述符表中的索引。内核根据这个索引找到对应的打开文件对象，再执行具体的读写或控制操作。

## 2. 标准文件描述符

进程启动时通常已经打开三个标准文件描述符：

| 编号 | 名称 | 默认用途 |
| --- | --- | --- |
| `0` | 标准输入 `stdin` | 从终端或重定向输入读取数据 |
| `1` | 标准输出 `stdout` | 向终端或重定向目标输出数据 |
| `2` | 标准错误 `stderr` | 输出错误和诊断信息 |

Shell 可以通过重定向改变它们指向的资源：

```text
command < input.txt
command > output.txt
command 2> error.log
```

重定向的本质是让标准文件描述符指向另一个打开的资源。

## 3. 基本操作

程序通常通过系统调用或 C 库接口操作文件描述符：

| 接口 | 作用 |
| --- | --- |
| `open`、`socket`、`pipe` | 创建或打开资源并返回文件描述符 |
| `read` | 从文件描述符对应的资源读取数据 |
| `write` | 向文件描述符对应的资源写入数据 |
| `close` | 关闭文件描述符 |
| `fcntl` | 查询或修改文件描述符属性 |
| `dup`、`dup2`、`dup3` | 复制文件描述符 |

以普通文件为例：

```c
int fd = open("data.txt", O_RDONLY);
if (fd == -1) {
    // 处理打开失败
}

ssize_t n = read(fd, buffer, sizeof(buffer));
close(fd);
```

成功打开资源后，`open` 返回当前进程中尚未使用的文件描述符编号；失败时通常返回 `-1`，并通过 `errno` 表示原因。

## 4. 文件描述符与内核对象

可以将关系简化为：

```text
进程
  ↓
文件描述符表
  ↓
文件描述符
  ↓
打开文件对象
  ↓
文件、管道、Socket 或其他内核资源
```

文件描述符表属于进程。打开文件对象由内核维护，通常保存文件偏移量、访问方式和状态标志等信息。

两个文件描述符可能指向同一个打开文件对象。例如，`dup` 复制出的描述符会共享文件偏移量：

```c
int fd2 = dup(fd);
```

此时通过 `fd` 读取数据后，使用 `fd2` 读取会从更新后的偏移量继续。关闭其中一个描述符不会立即释放底层对象，只要仍有其他引用存在，资源就可能继续保持打开状态。

## 5. 继承与生命周期

### 5.1 `fork` 继承

调用 `fork` 创建子进程后，子进程会继承父进程的文件描述符。父子进程中的对应描述符通常指向相同的打开文件对象，因此可以共享文件偏移量和管道等资源。

Shell 创建管道命令时，就会利用文件描述符继承连接进程：

```text
command1 的标准输出 → 管道写端
command2 的标准输入 ← 管道读端
```

### 5.2 `exec` 与关闭

调用 `exec` 替换进程映像时，文件描述符默认会继续保留。对于不希望泄露到新程序的描述符，可以设置 close-on-exec 标志，例如使用 `O_CLOEXEC` 或 `FD_CLOEXEC`。

不再使用文件描述符时应及时调用 `close`。长期不关闭文件、Socket 或管道描述符，可能导致文件描述符耗尽，表现为后续打开资源失败。

## 6. 与其他章节的关系

- **I/O**：文件描述符是各种 I/O 操作的统一入口，本章的主要归属。
- **进程与线程**：补充文件描述符的继承、共享和线程间使用。
- **文件系统**：关注普通文件、目录、inode 和持久化；文件描述符只是访问普通文件的接口之一。
- **I/O 多路复用**：`select`、`poll` 和 `epoll` 都通过文件描述符等待多个资源的就绪事件。

## 7. 实践方向

- 查看进程的文件描述符目录，例如 `/proc/<pid>/fd`。
- 使用 Shell 重定向观察标准文件描述符的变化。
- 使用管道观察父子进程如何继承和关闭文件描述符。
- 使用 `dup2` 实现输出重定向。
- 使用 `lsof` 查看进程打开的文件、管道和 Socket。
