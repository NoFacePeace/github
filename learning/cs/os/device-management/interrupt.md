# 中断管理

操作系统使用中断响应硬件事件，并将不适合在硬件中断上下文中完成的工作延后处理。Linux 中常见的处理层次包括硬中断、softirq、`ksoftirqd` 和 workqueue。

## 1. 硬中断

硬件设备通过中断通知处理器，例如网卡收到数据、磁盘 I/O 完成或定时器到期。硬中断处理程序应尽快完成必要工作，避免长时间占用处理器。

典型流程如下：

```text
硬件设备产生中断
    ↓
处理器进入硬中断处理程序
    ↓
完成紧急处理，并安排后续工作
    ↓
返回被中断的执行流
```

硬中断上下文通常不能睡眠，也不适合执行大量计算或复杂 I/O。

## 2. softirq

`softirq` 是 Linux 内核中的软中断机制，用于延后处理不必立即完成的内核工作。网络收包、定时器和块设备 I/O 等子系统都可能使用 softirq。

softirq 与处理器指令触发的“软件中断”不是同一个概念：

- 软件中断通常指程序执行特定指令，进入预定义的处理入口。
- softirq 是 Linux 内核内部安排和执行延后工作的机制。

softirq 处理函数仍然不能睡眠，因此如果后续工作需要睡眠或执行较长时间，通常应继续交给 workqueue 等机制。

网络设备的 NAPI、RX Ring 和 Packet Descriptor 见[网络设备收包](network-receive.md)。

## 3. `ksoftirqd`

### 3.1 作用

`ksoftirqd` 是 Linux 为每个 CPU 创建的内核线程，用来处理没有在当前上下文中及时完成的 softirq。线程名称通常类似：

```text
ksoftirqd/0
ksoftirqd/1
```

数字表示关联的 CPU。

softirq 通常会在硬中断返回前或其他合适的内核路径中尽快处理。如果待处理的 softirq 数量较多，或者处理时间超过限制，内核会唤醒对应 CPU 的 `ksoftirqd`，让它以可调度的内核线程身份继续处理。

```text
硬件中断
    ↓
产生 softirq
    ├── 立即处理
    └── 处理量过大或未及时完成 → ksoftirqd
```

### 3.2 高 CPU 占用的含义

如果 `ksoftirqd/N` 长时间占用较高 CPU，通常表示 CPU `N` 上存在较多软中断工作，常见原因包括：

- 网络收发包速率较高
- 网络包处理或协议栈开销较大
- 定时器事件过多
- 块设备 I/O 或其他内核子系统产生大量 softirq

排查时应结合每个 CPU 的软中断统计、网卡收发包速率、I/O 负载和中断亲和性一起分析，不能只根据线程名判断具体原因。

## 4. workqueue

workqueue 用于将内核工作交给内核工作线程执行。与 softirq 相比，workqueue 更适合执行可能阻塞、需要睡眠或耗时较长的工作。

| 机制 | 执行主体 | 是否可以睡眠 | 适合处理 |
|---|---|---|---|
| 硬中断 | 硬中断处理程序 | 否 | 紧急、少量处理 |
| softirq | softirq 处理函数 | 否 | 高性能、可延后的内核工作 |
| `ksoftirqd` | 每 CPU 内核线程 | 处理函数本身仍受 softirq 约束 | 消化积压的 softirq |
| workqueue | 内核工作线程 | 通常可以 | 需要睡眠或较长时间的工作 |

## 5. 与计算机组成原理的边界

处理器如何响应中断、中断向量如何定位以及硬件中断控制器如何工作，属于计算机组成原理的中断机制。`softirq`、`ksoftirqd` 和 workqueue 则是 Linux 操作系统对中断后续工作的管理和实现。
