# Agent

Agent（智能体）是能够感知任务上下文、进行决策并采取行动的系统。它通常以大语言模型或其他推理模型为核心，通过工具、记忆和外部环境完成单轮问答难以独立完成的任务。

Agent 不等同于“调用一次模型”：

- **模型**负责理解输入、推理和生成下一步决策。
- **工具**负责访问外部系统、执行代码、查询数据或改变环境状态。
- **状态**保存当前任务的上下文、历史结果和中间产物。
- **控制循环**根据观察结果决定继续思考、调用工具还是结束任务。

## 1. 核心组成

| 组成 | 作用 | 常见实现 |
| --- | --- | --- |
| 模型 | 理解任务、生成计划和工具调用参数 | 大语言模型、视觉语言模型 |
| 指令 | 约束角色、目标、输出格式和行为边界 | 系统提示词、任务提示词 |
| 工具 | 连接外部能力和真实世界 | 搜索、数据库、浏览器、代码执行、业务 API |
| 工作记忆 | 保存当前任务所需的上下文 | 对话历史、任务状态、工具结果 |
| 长期记忆 | 保存可跨任务复用的信息 | 用户偏好、知识库、向量检索 |
| 环境 | Agent 观察和操作的对象 | 文件系统、网页、代码仓库、业务系统 |
| 评测与防护 | 检查质量、权限和风险 | 轨迹评测、权限控制、人工确认 |

## 2. 运行循环

一个基本的 Agent 循环可以抽象为：

```text
接收任务
  ↓
理解目标与约束
  ↓
制定下一步行动
  ↓
调用工具或生成结果
  ↓
观察工具结果和环境变化
  ↓
判断是否完成
  ├─ 未完成：继续循环
  └─ 已完成：校验并返回结果
```

实现时需要明确以下问题：

1. **目标是什么**：完成条件是否可观察、可验证。
2. **下一步如何选择**：由模型自由决策，还是使用固定工作流。
3. **工具如何调用**：参数格式、超时、重试、幂等性和错误处理。
4. **何时停止**：成功、失败、达到步数上限或需要人工确认。
5. **如何恢复**：进程中断、工具失败或上下文过长时如何继续任务。

## 3. Agent 与工作流

固定工作流适合步骤明确、分支有限且结果要求稳定的任务；Agent 适合目标明确但路径不确定、需要根据中间结果动态选择行动的任务。

| 方式 | 优势 | 风险 | 适用场景 |
| --- | --- | --- | --- |
| 固定工作流 | 可预测、易测试、成本稳定 | 灵活性有限 | 审批流程、数据同步、标准化流水线 |
| 单 Agent 循环 | 实现简单、适应性较强 | 轨迹可能不稳定，容易循环或误调用工具 | 信息检索、代码修改、个人助理 |
| 多 Agent 协作 | 可拆分专业角色和并行任务 | 协调成本高，状态与权限更复杂 | 复杂研究、长流程项目 |

工程上应先使用最简单、可验证的流程；只有当固定流程无法覆盖任务变化时，再引入 Agent 的自主决策。

## 4. 工具、记忆与上下文

### 4.1 工具设计

工具是 Agent 连接外部世界的接口，应像设计普通 API 一样设计：

- 输入参数使用明确的类型、枚举和约束。
- 返回结构包含成功结果、错误信息和必要的状态。
- 对有副作用的操作区分预览、确认和执行。
- 为写操作设置权限、超时、重试策略和幂等键。
- 返回完成任务所需的信息，避免无关内容挤占上下文。

### 4.2 记忆设计

记忆不只是保存全部对话历史，而是根据用途选择合适的存储方式：

- **短期记忆**：当前任务的消息、计划、工具结果和中间状态。
- **摘要记忆**：压缩较长历史，保留目标、结论、未完成事项和约束。
- **检索记忆**：从文档或知识库中按需获取相关事实。
- **用户记忆**：保存经过授权且长期稳定的偏好或配置。

写入长期记忆前应考虑来源、时效性、隐私、可删除性和错误传播。

## 5. 可靠性与安全

Agent 的风险来自模型输出、工具权限和环境副作用的组合，不能只依赖提示词约束。

- 对工具实行最小权限和资源隔离。
- 对删除、发送、发布、转账等高风险操作要求人工确认。
- 校验模型生成的参数、文件路径、SQL、命令和外部内容。
- 限制最大步数、调用预算、并发度和单次执行时间。
- 记录输入、决策、工具调用、结果和最终输出，支持审计与复盘。
- 防范提示注入、越权访问、敏感信息泄露、工具误用和无限循环。
- 对关键结果进行独立校验，不把模型自述当作事实证明。

## 6. 评测方法

评测不应只看最终答案，还要观察 Agent 的执行过程：

| 维度 | 关注点 |
| --- | --- |
| 任务成功率 | 是否满足任务目标和验收条件 |
| 结果正确性 | 事实、计算、代码和引用是否正确 |
| 工具使用 | 是否选择正确工具，参数和调用顺序是否合理 |
| 效率 | 步数、延迟、Token 消耗和工具成本 |
| 稳定性 | 相同输入下结果是否可接受，失败后能否恢复 |
| 安全性 | 是否越权、泄露信息或执行未授权副作用 |

应使用代表性任务集、失败案例和回归测试持续评估，并保留完整执行轨迹。

## 7. 学习顺序

1. 理解语言模型的上下文、结构化输出和工具调用。
2. 实现一个只有一个工具的最小 Agent 循环。
3. 增加状态管理、超时、重试、预算和停止条件。
4. 学习检索增强生成（RAG）、上下文压缩和长期记忆。
5. 对工具权限、提示注入和高风险操作增加安全防护。
6. 建立任务集、轨迹记录和自动化评测。
7. 对比固定工作流、单 Agent 和多 Agent 方案的成本与收益。

后续可分别记录模型调用、工具协议、RAG、Agent 编排、评测和安全等专题。
