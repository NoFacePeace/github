# MCP

## 1. Events

### 1.1 概念

MCP Events 提供事件订阅与通知机制，使外部系统发生变化时可以触发 Agent 工作，例如新消息、文档评论或状态更新。本文介绍 ChatGPT 对草案 MCP Events 规范的集成。

它属于协议与运行系统的能力。事件负责通知，运行系统启动后续处理，模型判断下一步，工具执行具体操作。

### 1.2 与工具调用的区别

| 机制 | 交互方向 | 示例 |
| --- | --- | --- |
| MCP 工具调用 | Agent 主动请求服务 | 查询文档的评论 |
| MCP Events | 服务按订阅推送变化 | 新评论产生后通知 Agent |

事件通知通常还需配合工具调用。收到评论后，Agent 可以读取文档，再按用户要求处理；事件本身不是业务操作的执行结果。

### 1.3 工作流程

1. MCP 服务公布事件类型和过滤条件。
2. 用户指定监听对象与后续处理要求。
3. ChatGPT 建立订阅，提供 webhook 回调地址与签名密钥。
4. 服务将匹配的事件发送到回调地址。
5. ChatGPT 在订阅的聊天中接收事件，按用户指令继续处理。

例如，“关注产品反馈频道，出现问题反馈时分析原因并准备修复提案”，可由消息事件触发，再调用读取信息和处理代码的工具。

### 1.4 核心接口与接入要求

| 方法 | 用途 |
| --- | --- |
| `events/list` | 列出事件及过滤条件 |
| `events/subscribe` | 创建或续期订阅 |
| `events/unsubscribe` | 停止订阅 |

ChatGPT 集成要求 MCP 2.0，协议版本为 `2026-07-28`。服务需要持久化订阅，并能通过 HTTPS 向回调地址发送通知。当前支持 webhook 交付和回调验证，不支持该集成中的轮询、流式交付及草案的 `gap`、`terminated` 控制通知。

### 1.5 本地与云端支持范围

官方列出的支持范围是 ChatGPT 网页的 Work 聊天、桌面应用选择 Cloud 的 Work 聊天，以及 Dots；没有列出本地执行模式。桌面应用中的云端聊天仍属于受支持场景，不能将“桌面”直接等同于“本地执行”。

需要区分服务与 Agent 的部署位置：

- **本地 MCP 服务接入 ChatGPT**：需满足云端可访问、协议和插件接入要求，并能向云端回调发送事件。仅有本地进程或 localhost 地址不足以完成云端接入。
- **自行运行本地 Agent**：可以自行实现事件接收、任务调度和模型调用。这是架构方案，不代表 ChatGPT 官方本地模式已经支持 MCP Events。
