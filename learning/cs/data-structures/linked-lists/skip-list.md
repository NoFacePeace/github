# 跳表

## 1. 基本概念

跳表（Skip List）是一种基于有序链表的数据结构，通过多层索引加速查找。它可以看作有序链表的增强版，属于链表类数据结构，不属于树。

普通有序链表查找元素时，需要从头逐个遍历，时间复杂度为 O(n)。跳表允许从高层索引跨过一批节点，再逐层向下定位，查找、插入和删除的期望时间复杂度均为 O(log n)。其中 n 为元素数量。

本文介绍使用随机层高的经典跳表，示例默认键唯一且按升序排列。

## 2. 结构与多层索引

```text
第 2 层：head ───────────────────→ 30 ───────────→ 50 → nil
第 1 层：head ────────→ 10 ──────→ 30 ───────────→ 50 → nil
第 0 层：head → 5 ───→ 10 → 20 ─→ 30 → 40 ─────→ 50 → nil
```

- 第 0 层是底层，包含全部元素，构成完整的有序链表。
- 上一层的节点一定出现在下一层，越高的层通常节点越少。
- 每一层都按相同的键顺序连接节点。
- `head` 是头哨兵，提供每一层的访问入口，不保存业务元素。
- `nil` 表示该层链表的末尾。

图中相同键在不同层的出现，可以理解为同一个节点在不同高度的连接。常见实现让节点保存一个前向指针数组 `forward`：`forward[0]` 指向底层后继，`forward[1]` 指向第 1 层后继，以此类推。向下走通常只是减小数组下标，不一定需要单独的向下指针。

### 2.1 头哨兵与空跳表

`head` 是一个不保存业务数据的辅助节点，各层共用同一个 `head`，通过不同的 `forward` 下标访问对应层。即使跳表为空，通常也会保留它，此时所有前向指针均为 `nil`：

```text
空跳表：head → nil              元素数量为 0
有数据：head → 10 → 20 → nil    元素数量为 2
```

即使节点结构包含 `key`、`value` 字段，头哨兵的这些字段通常也不使用，`head` 不计入元素数量。

### 2.2 最大层数与当前有效层数

常见实现会在初始化时为 `head.forward` 分配最大层数 `MaxLevel` 的指针空间。需要区分预留容量与实际使用的层数：

| 概念 | 含义 | 示例 |
| --- | --- | --- |
| `MaxLevel` | 允许的最大层数，也是头哨兵预留的指针数量 | 32，对应下标 0～31 |
| `currentLevel` | 当前实际使用的层数，空表通常保留 1 层 | 2，查找从第 1 层开始 |
| 节点层高 | 该节点参与的层数，不超过 `MaxLevel` | 3，参与第 0、1、2 层 |

未启用的高层指针均为 `nil`。新节点超过当前有效层数时，可以直接使用 `head` 已预留的高层指针，无需再创建一个头哨兵。也有实现会动态扩展头哨兵的指针数组，预分配最大层数并不是跳表的强制要求。

## 3. 查找过程

### 3.1 查找规则

从头哨兵的最高有效层开始，重复以下操作：

1. 如果当前层的下一个节点存在，且键小于目标，就向右移动。
2. 如果下一个节点不存在，或键大于等于目标，就下降一层。
3. 到达底层后，检查当前节点的下一个节点：键等于目标则找到，否则目标不存在。

这种写法会停在目标的前驱节点处，方便复用到插入和删除操作。

### 3.2 查找 40 的示例

沿用上图：

1. 在第 2 层从 `head` 移动到 30；下一个节点是 50，超过 40，下降一层。
2. 在第 1 层，30 的下一个节点仍是 50，继续下降。
3. 在第 0 层，30 的下一个节点是 40，检查后确认命中。

如果查找 35，最终也会停在底层的 30。因为后继为 40，不等于 35，所以查找失败。

### 3.3 查找伪代码

```text
find(key):
    current = head
    for level from currentLevel - 1 down to 0:
        while current.forward[level] != nil
              and current.forward[level].key < key:
            current = current.forward[level]

    candidate = current.forward[0]
    if candidate != nil and candidate.key == key:
        return candidate
    return nil
```

`currentLevel` 表示当前有效层数，层下标从 0 开始。

## 4. 插入与删除

### 4.1 插入

1. 按查找流程定位插入位置，并使用 `update[level]` 记录每一层最后经过的、键小于目标的节点。
2. 如果键已经存在，按约定更新值或拒绝重复插入。
3. 随机生成新节点的层高。如果超过当前有效层数，对每个新增层设置 `update[level] = head`，因为这些层还没有业务节点；随后将有效层数更新为新节点的层高。
4. 在新节点参与的每一层修改连接。

每层的指针修改方式与普通单链表插入相同：

```text
newNode.forward[level] = update[level].forward[level]
update[level].forward[level] = newNode
```

例如插入 25，随机得到层高 2，表示参与第 0、1 层：

```text
第 1 层：10 → 30       变为 10 → 25 → 30
第 0 层：10 → 20 → 30  变为 10 → 20 → 25 → 30
```

第 1 层的前驱是 10，第 0 层的前驱是 20，所以需要分别记录各层前驱。

`update` 是本次操作临时使用的前驱记录数组，数组中的每一项都指向对应层的前驱节点。设置 `update[level] = head` 只是记录前驱；真正建立连接的是后续对 `forward` 的修改。

例如，原表只有 2 层，插入层高为 3 的节点 30：

```text
插入前：
第 1 层：head ─────→ 20 → nil
第 0 层：head → 10 → 20 → nil

记录前驱：update[0] = 20，update[1] = 20，update[2] = head
有效层数：currentLevel 从 2 变为 3

插入后：
第 2 层：head ────────────→ 30 → nil
第 1 层：head ─────→ 20 ──→ 30 → nil
第 0 层：head → 10 → 20 ──→ 30 → nil
```

新增第 2 层时，先令 `newNode.forward[2] = head.forward[2]`（此时为 `nil`），再令 `head.forward[2] = newNode`，这一层才真正连接到新节点。

### 4.2 删除

1. 查找目标，同时记录每一层的前驱节点。
2. 如果底层后继不是目标，直接返回未找到。
3. 对于指向目标的每一层，让前驱跳过目标，直接指向目标在该层的后继。
4. 如果删除后最高层为空，降低有效层数，通常至少保留底层。

```text
if update[level].forward[level] == target:
    update[level].forward[level] = target.forward[level]
```

删除必须移除目标在所有相关层的连接，不能只删除底层节点。

## 5. 随机层高与效率

### 5.1 如何决定层高

新节点一定参与底层，然后以固定概率 p 继续增加一层，直到停止或达到最大层数。例如 p = 1/2，可以理解为连续抛硬币，每次正面就增加一层，遇到反面停止。

忽略最大层数限制时：

| 参与的层 | 概率 | 该层期望节点数 |
| --- | --- | --- |
| 第 0 层 | 1 | n |
| 第 1 层 | p | np |
| 第 2 层 | p² | np² |
| 第 k 层 | pᵏ | npᵏ |

因此节点数随高度大致按几何级数减少。这里描述的是概率和期望，并不要求每隔固定数量的节点建立一个索引。

### 5.2 为什么期望是 O(log n)

对于固定的 p，跳表的典型高度为 O(log n)。随机分层使查找在每一层需要横向经过的节点数在期望上保持常数量级，因此总查找时间为 O(log n)。

插入和删除首先查找位置，再修改相关层的指针，所以期望时间同样为 O(log n)。这些结论要求层高独立随机生成，且最大层数足以支持预期数据规模。若层数上限过低，数据持续增大后查找效率会下降。

随机化不能提供单次操作的最坏对数时间保证。如果节点都只有底层，结构就退化成普通有序链表。

### 5.3 空间开销

单个节点的期望指针数量为：

```text
1 + p + p² + ... = 1 / (1 - p)
```

当 p = 1/2 时，每个节点期望持有 2 个前向指针，因此总空间期望为 O(n)。设置最大层数 L 后，最坏指针空间为 O(nL)；若将 L 视为固定常数，则为 O(n)。

## 6. 复杂度与结构对比

| 操作 | 期望时间复杂度 | 最坏时间复杂度 |
| --- | --- | --- |
| 查找 | O(log n) | O(n) |
| 插入（包含定位） | O(log n) | O(n) |
| 删除（包含定位） | O(log n) | O(n) |
| 范围查询，返回 k 个元素 | O(log n + k) | O(n + k) |

表中按常规层高配置分析；范围查询先定位起点，再沿底层依次读取，直到超出范围。

| 数据结构 | 查找 | 插入、删除 | 主要特点 |
| --- | --- | --- | --- |
| 有序单链表 | O(n) | 定位通常为 O(n)，已知前驱后修改连接为 O(1) | 结构简单，缺少快速定位能力 |
| 跳表 | 期望 O(log n) | 期望 O(log n) | 通过随机层高维护索引，便于按序和范围遍历 |
| [红黑树](../trees/red-black-tree.md) | 最坏 O(log n) | 最坏 O(log n) | 通过旋转和颜色约束维护平衡，提供最坏时间保证 |
| 有序数组 | 二分查找 O(log n) | 通常为 O(n) | 存储紧凑，更新可能需要移动大量元素 |

## 7. 常见理解误区

- **跳表是树吗？** 不是，它基于多层有序链表组织节点。
- **底层是无序链表吗？** 不是，各层都必须按相同规则有序，否则无法根据键大小跳过节点。
- **每层节点数严格减半吗？** 不是，p = 1/2 时只是在期望上减半。
- **查找一定是 O(log n) 吗？** 不是，经典随机跳表提供期望复杂度，最坏可能退化。
- **上层必须复制整份业务数据吗？** 不需要，同一节点可以通过多个前向指针参与不同层。
- **普通跳表能直接快速查第 k 个元素吗？** 不能仅凭前向指针保证对数时间；通常需要额外维护每条连接跨过的底层元素数量，即跨度（span）。
