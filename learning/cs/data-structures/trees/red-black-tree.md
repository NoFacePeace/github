# 红黑树

## 1. 基本概念

红黑树（Red-Black Tree）是一种自平衡二叉搜索树。它按键值大小组织节点，并通过颜色约束、旋转和重新着色，将树高保持在 O(log N)，其中 N 为节点数。

“自平衡二叉搜索树”包含三个方面：

- **二叉树**：每个节点最多有两个子节点，分别为左子节点和右子节点。
- **搜索树**：节点按键值的大小关系组织。以不含重复键的情况为例，左子树中所有键都小于当前节点的键，右子树中所有键都大于当前节点的键。查找时比较目标键与当前键，就能决定继续搜索左子树还是右子树；如果相等，则找到目标。重复键需要另行约定处理策略。
- **自平衡**：插入或删除后，算法自动维护颜色约束，必要时通过旋转和重新着色调整树，避免树退化为链表。

每个节点带有红色或黑色标记。颜色用于维护平衡，不影响节点存储的数据和查找时的大小比较，也可以在调整过程中改变。插入或删除破坏约束时，算法会自动修复，使查找、插入和删除的最坏时间复杂度保持为 O(log N)。

## 2. 解决的问题

普通二叉搜索树只维护键值的大小关系，不会自动调整树的高度。例如，依次插入 `1、2、3、4` 时，每个新节点都会成为前一个节点的右子节点：

```text
1
 \
  2
   \
    3
     \
      4
```

此时树退化为链表。查找最大值或某些不存在的键时，需要沿路径检查所有节点，最坏时间复杂度为 O(N)。

红黑树解决的是这种高度失控的问题：插入、删除后自动维护平衡约束，使树高保持在 O(log N)，从而保证查找、插入和删除的最坏时间复杂度均为 O(log N)。它不要求树完全对称，而是限制路径长度，避免操作效率随着树的倾斜而退化。

## 3. 基本性质

红黑树满足二叉搜索树的有序关系，并额外满足以下约束：

1. 每个节点是红色或黑色。
2. 根节点是黑色。
3. 所有空叶子节点（NIL）视为黑色，这里的叶子指空指针对应的概念节点。
4. 红色节点的子节点都是黑色，即不能出现相邻的红色节点。
5. 从任一节点到其所有后代 NIL 节点的路径，包含相同数量的黑色节点。

黑色节点数量相同，加上红色节点不能相邻，使最长路径不会超过最短路径长度的两倍。红黑树不要求每个节点的左右子树高度完全相同。

## 4. 基本操作

### 4.1 查找

从根节点开始，将目标键与当前节点的键比较：

1. 相等则找到目标。
2. 目标键较小，则进入左子树。
3. 目标键较大，则进入右子树。
4. 到达 NIL 仍未找到，说明目标不存在。

查找不改变节点关系或颜色，不会破坏红黑树性质，因此不需要平衡调整。

### 4.2 插入

先按二叉搜索树的规则找到插入位置，再维护红黑树性质：

1. 从根节点开始比较键值，找到新节点应当占据的空位置。
2. 插入新节点，通常将其设为红色，左右子节点为 NIL。插入红节点不会增加路径上的黑节点数量。
3. 如果父节点也是红色，就违反了红节点不能相邻的规则，需要进行平衡修复。
4. 修复完成后，保证根节点为黑色。

如果插入的是根节点，将其设为黑色即可；如果父节点是黑色，通常不需要进一步调整。重复键按事先约定的策略处理。

### 4.3 删除

先找到目标节点，再按二叉搜索树的规则移除：

1. 没有非空子节点时，直接用 NIL 替代目标节点。
2. 只有一个非空子节点时，用该子节点接替目标节点的位置。
3. 有两个非空子节点时，可以用中序后继（右子树中键最小的节点）的键和值替换目标内容，再从后继的原位置删除后继。后继最多只有一个非空子节点，因而转化为前两种情况。

以复制后继内容的实现方式为例，是否需要修复取决于最终从树中移除的节点的颜色，而不是最初目标节点的颜色。移除红节点不会减少路径上的黑节点数量；移除黑节点可能使部分路径少一个黑节点，需要修复。如果接替它的是红节点，可以将接替节点染黑；其余情况需要根据兄弟节点及其子节点的颜色进一步处理。

插入和删除中的具体平衡修复会使用下一节介绍的旋转与重新着色。

## 5. 平衡维护

插入和删除可能破坏红黑树性质，下面先介绍旋转与重新着色，再说明如何利用它们完成修复。

### 5.1 旋转

旋转局部调整节点的父子关系，改变树的形状，同时保持二叉搜索树的有序关系。

- **左旋**：让某个节点的右子节点上升，原节点成为它的左子节点。
- **右旋**：让某个节点的左子节点上升，原节点成为它的右子节点。

下面展示以 x 为中心左旋的过程，反方向就是以 y 为中心右旋。A、B、C 表示子树，也可以为空。

```text
       x                     y
      / \                   / \
     A   y      左旋 →     x   C
        / \               / \
       B   C             A   B
```

旋转前后的中序遍历顺序都是 `A → x → B → y → C`，因此不会破坏键值顺序。旋转本身不改变颜色，也不保证单独执行一次就能恢复所有红黑树性质。

### 5.2 重新着色

重新着色改变节点的红黑标记，不改变节点的键值或父子关系。它通常与旋转配合，用于恢复颜色约束。

例如，插入红节点后，如果父节点和叔节点（父节点的兄弟）都是红色，可以将父节点和叔节点染黑，将祖父节点染红。这样消除了当前的红色父子冲突，并保持经过该局部子树的黑节点数量不变，但祖父节点可能与它的父节点形成新的冲突，需要继续向上修复；最后保证根节点为黑色。

具体使用旋转还是重新着色，取决于插入或删除后的局部结构与颜色。并不是每次修改都需要旋转，也不能任意改变颜色。

### 5.3 插入后的平衡修复

新节点设为红色，因此不会改变路径上的黑节点数量。主要需要处理的是它与父节点同时为红色的冲突。

记当前修复节点为 Z，父节点为 P，祖父节点为 G，叔节点（P 的兄弟）为 U。Z 最初是新插入的节点，向上修复时可能变成祖先节点。NIL 按黑色处理。

如果 Z 是根节点，将它染黑并结束；如果 P 是黑色，无需修复。下面讨论 P 为红色的情况，此时 G 存在且为黑色。

例如，向空树插入 `10`，将新节点从 `10红` 染成 `10黑` 即可；向只有 `10黑` 的树插入 `5红`，父节点为黑色，直接结束。以下图中省略的子节点均为黑色 NIL。

**情况一：叔节点 U 为红色。**

将 P、U 染黑，将 G 染红，再把 G 作为新的 Z，向上继续检查。这消除了当前的红色父子冲突，且经过该局部子树的路径仍有相同数量的黑节点；但 G 可能与上层红色节点发生冲突。

例如，在根为 `10黑`、左右孩子为 `5红` 和 `15红` 的树中插入 `1红`：

```text
插入后：          局部重新着色：       根染黑后：
     10黑              10红              10黑
    /    \            /    \            /    \
  5红    15红       5黑    15黑       5黑    15黑
 /                 /                 /
1红               1红               1红
```

这里 P = 5、U = 15、G = 10。局部调整后把 10 作为新的 Z；因为它已经是根，将它染黑，修复结束。如果 G 不是根，则继续检查它与上层父节点是否冲突。

**情况二：叔节点 U 为黑色，Z、P、G 呈折线。**

例如 P 是 G 的左子节点，Z 是 P 的右子节点，形成“左右”形态。先对 P 左旋，转成“左左”直线形态，再按情况三处理。对称的“右左”形态先对 P 右旋。旋转后应按新的父子关系识别情况三中的 P 和 G。

例如依次插入 `3、1、2`，叔节点为 NIL：

```text
插入后：          对 1 左旋：         按情况三修复：
     3黑              3黑                2黑
    /                /                  /   \
  1红              2红                1红   3红
    \             /
    2红          1红
```

第一次左旋不改颜色，只把折线转为直线，红色相邻仍然存在。接着将 2 染黑、3 染红，对 3 右旋，才完成修复。

**情况三：叔节点 U 为黑色，Z、P、G 呈直线。**

对于“左左”形态，将 P 染黑、G 染红，再对 G 右旋；对于“右右”形态，将 P 染黑、G 染红，再对 G 左旋。调整后局部规则恢复，修复结束。

例如依次插入 `3、2、1`，最后一次插入形成“左左”冲突，叔节点是黑色 NIL：

```text
      3黑                  2黑
     /                    /   \
   2红       修复 →     1红   3红
  /
1红
```

这里先将 2 染黑、3 染红，再对 3 右旋。整个插入修复完成后，统一保证根节点为黑色。

#### 5.3.1 插入修复口诀

> 父黑停，叔红变色向上走；叔黑折变直，直线旋祖父。

- **父黑停**：父节点为黑色时，没有红色父子冲突，无需修复。
- **叔红变色向上走**：父节点和叔节点均为红色时，将父、叔染黑，祖父染红，再从祖父向上检查。
- **叔黑折变直**：父红、叔黑且呈折线时，先旋转父节点，转成直线形态。
- **直线旋祖父**：父红、叔黑且呈直线时，将父染黑、祖父染红，再旋转祖父，完成修复。

折线转换后，按新的父子关系识别父节点和祖父节点；左右对称情况互换旋转方向。最后统一保证根节点为黑色。

### 5.4 删除后的平衡修复

删除需要关注的是实际移除节点原来的颜色。如果使用复制后继内容的方式，只复制键和值，不复制颜色；后续修复针对后继被移除的位置。

先处理可以直接结束的情况：

- 实际移除的是红节点：没有减少黑节点数量，无需修复。
- 实际移除的是黑节点，接替它的是红节点：将接替节点染黑，补上少掉的黑色，结束修复。
- 实际移除的是黑节点，接替位置是黑节点或 NIL：该位置所在的路径少一个黑节点，需要继续处理。刚删除时常见的是 NIL，向上传递后也可能是非空黑节点。

将带有黑色缺额的当前位置记为 X，其父节点为 P，兄弟节点为 S。“双黑”是修复算法对这个缺额的记账方式，不是节点真的具有第三种颜色。若 X 已是根，所有路径共同减少一个黑节点，可以结束；否则根据兄弟一侧调整。

三个简单例子可以帮助区分入口情况：

```text
删除红叶：             黑节点由红孩子接替：       删除唯一的根：
    10黑                      10黑                    10黑
   /                         /
  5红                       5红

删除 5 → 只剩 10黑     删除 10 → 将 5 染黑       删除 10 → 空树
无需修复               补足黑色后结束            直接结束
```

下面用 `NIL*` 表示带有黑色缺额的空位置；星号只是说明修复位置，不是一种颜色。

下面统一假设 **X 是 P 的左子节点**，S 因而位于右侧。S 的左子节点称为近侄节点，右子节点称为远侄节点。X 在右侧时，交换下面的左右方向即可。

**情况一：兄弟 S 为红色，先转换为黑兄弟情况。**

将 S 染黑、P 染红，对 P 左旋。X 仍在原来的 P 下方，重新取得 X 的兄弟，此时新兄弟为黑色，再进入下面三种情况之一。这一步只是转换结构，尚未补上黑色缺额。

例如从下面的树中删除 `5黑`：

```text
删除前：           删除后：            情况一转换后：
     10黑              10黑                  20黑
    /    \            /    \                /    \
  5黑    20红       NIL*   20红           10红    25黑
        /    \            /    \         /    \
      15黑   25黑       15黑   25黑    NIL*   15黑
```

原兄弟 20 染黑、父节点 10 染红，再对 10 左旋。X 的新兄弟是 15黑，它的两个孩子都是 NIL，因此继续进入情况二：将 15 染红、10 染黑即可结束。最终 20黑的左子树为 `10黑 → 右孩子 15红`，右孩子为 25黑。

**情况二：兄弟 S 为黑色，两个侄节点都为黑色。**

将 S 染红，使兄弟一侧也少一个黑节点。两侧现在一致，但以 P 为根的整个子树相对外部少一个黑节点，因此将缺额向上传给 P：

- P 原来是红色：将 P 染黑即可补足，修复结束。
- P 原来是黑色：把 P 作为新的 X，继续向上检查。
- 缺额传到根：直接结束，因为所有根到 NIL 的路径仍然一致。

例如删除 `5黑`，兄弟 `15黑` 的两个孩子均为 NIL：

```text
删除前：          删除后：          将兄弟染红后：
     10黑              10黑              10黑
    /    \            /    \            /    \
  5黑    15黑       NIL*   15黑        NIL    15红
```

将 15 染红后，两侧黑节点数量相同，缺额传给 10。因为 10 是根，直接结束。若相同局部结构的 P 是红色，则将 P 染黑吸收缺额；若 P 是非根黑节点，则继续向上处理。例如在根 `20黑` 下，左子树为 `10黑(5黑, 15黑)`、右子树为 `30黑(25黑, 35黑)`，删除 5 后先将 15 染红，缺额传给 10；再将它的兄弟 30 染红，缺额传到根 20 后结束。

**情况三：兄弟 S 为黑色，近侄为红色、远侄为黑色。**

将近侄染黑、S 染红，对 S 右旋。重新取得 X 的兄弟后，转化为“黑兄弟、红远侄”的情况四。这一步也只是转换，随后还要继续修复。

例如从根为 `10黑`、左孩子为 `5黑`、右子树为 `15黑 → 左孩子 12红` 的树中删除 5：

```text
删除后：          对兄弟调整后：      按情况四修复：
     10黑              10黑                12黑
    /    \            /    \              /    \
 NIL*    15黑      NIL*    12黑          10黑   15黑
         /                   \
       12红                  15红
```

先将 12 染黑、15 染红，再对 15 右旋。新兄弟为 12黑，远侄为 15红，于是进入情况四：12 继承 10 的黑色，将 10、15 染黑，对 10 左旋，修复结束。

**情况四：兄弟 S 为黑色，远侄为红色，近侄颜色不限。**

让 S 继承 P 原来的颜色，将 P 和远侄染黑，再对 P 左旋。调整后，X 一侧的黑色缺额得到补偿，两侧的黑节点数量恢复一致，修复结束。

例如删除下面的 `5黑`，其原位置变为 NIL，此时兄弟 `15黑` 的远侄 `20红` 满足情况四：

```text
删除前：             删除后待修复：           修复后：

      10黑                 10黑                 15黑
     /    \               /    \               /    \
   5黑    15黑           NIL   15黑           10黑   20黑
             \                   \
             20红                20红
```

让 15 继承 10 的黑色，将 10 和 20 染黑，再对 10 左旋，即可恢复各条路径的黑节点数量一致。

删除修复的关键是：有时可以在局部补足黑色缺额，有时只能将缺额向上传递。情况一、三用于转换结构，情况二可能向上传递，情况四直接完成修复。

#### 5.4.1 删除修复口诀

> 兄红先转黑，两侄黑往上推；近红转远红，远红旋转收尾。

- **兄红先转黑**：兄弟为红色时，先旋转并重新着色，转换为黑兄弟的情况。
- **两侄黑往上推**：兄弟为黑色且两个侄节点都为黑色时，将兄弟染红，把黑色缺额向父节点传递；父节点为红色时染黑即可结束，缺额到根时也可结束。
- **近红转远红**：兄弟为黑色、近侄红而远侄黑时，先旋转兄弟并重新着色，转为远侄红的情况。
- **远红旋转收尾**：兄弟为黑色且远侄为红色时，旋转父节点并重新着色，完成修复。

近侄、远侄以缺额位置 X 为参照；X 在右侧时，将左侧示例中的左右方向互换。

以上采用经典红黑树的修复分类。参考：[Dartmouth 红黑树插入与删除讲义](https://www.cs.dartmouth.edu/~thc/cs10/lectures/0519/0519.html)。
