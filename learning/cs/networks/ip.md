# IP

IP（Internet Protocol，网际协议）是 TCP/IP 协议体系中的网络层协议，负责使用 IP 地址标识主机或网络接口，并将数据包从源主机转发到目标主机。

## 1. IP 分片与重组

当 IP 包大于出口链路的 MTU 时，网络层需要对过大的数据包进行处理。现代网络通常通过 TCP MSS 和路径 MTU 发现等机制尽量避免 IP 分片，但在发送方不知道完整路径 MTU、路由发生变化、使用 UDP 发送较大数据报或隧道增加额外头部等情况下，仍可能出现超过 MTU 的 IP 包。

数据链路层不会直接分割 IP 包。网络层完成分片后，每个分片都会被当作一个独立的 IP 包，分别封装到数据链路层帧中：

```text
原始 IP 包
    |
    | 网络层分片
    v
IP 分片 1    IP 分片 2    IP 分片 3
    |            |            |
    | 数据链路层分别封装       |
    v            v            v
以太网帧 1   以太网帧 2   以太网帧 3
```

### 1.1 IPv4 分片

IPv4 路由器收到以太网帧后，会去掉当前链路的帧头和帧尾，取出 IPv4 包并查询路由。当 IP 包长度超过出口链路 MTU 时，处理方式取决于 IPv4 首部中的 DF 标志：

- `DF = 0`：发送主机或中间路由器可以对 IP 包进行分片。
- `DF = 1`：禁止分片。路由器丢弃该包，并通过 ICMP 通知发送方需要减小数据包。

IPv4 路由器进行分片时，会把原始 IP 载荷拆成多段，为每段添加独立的 IPv4 首部，然后将每个分片分别封装到出口链路的数据链路层帧中：

```text
收到：
[以太网头][一个较大的 IPv4 包][FCS]

路由器分片后发送：
[新以太网头][IPv4 首部][分片数据 1][FCS]
[新以太网头][IPv4 首部][分片数据 2][FCS]
[新以太网头][IPv4 首部][分片数据 3][FCS]
```

如果收到的 IPv4 包本身已经是分片，而某个分片仍然超过出口 MTU，路由器可以继续拆分该分片，通常不会先重组整个原始 IP 包。

### 1.2 IPv4 分片字段

IPv4 分片相关字段位于 IPv4 首部，而不是以太网帧头或 TCP、UDP 首部：

```text
IPv4 首部（不含可选字段时为 20 字节）

字节位置
0       Version + IHL
1       DSCP + ECN
2～3    Total Length
4～5    Identification
6～7    Flags + Fragment Offset
8       TTL
9       Protocol
10～11  Header Checksum
12～15  Source Address
16～19  Destination Address
20...   数据
```

其中，字节 4～7 的结构如下：

```text
|              Identification：16 bit                 |
| 保留：1 bit | DF：1 bit | MF：1 bit | Offset：13 bit |
```

- Identification：同一个原始 IP 包的所有分片使用相同的标识值。
- DF（Don't Fragment）：表示是否禁止对该 IP 包进行分片。
- MF（More Fragments）：`1` 表示后面还有分片，`0` 表示这是最后一个分片。
- Fragment Offset：表示该分片的数据在原始 IP 载荷中的位置，单位为 8 字节。
- Total Length：表示当前分片的 IPv4 首部与分片数据的总长度。

除最后一个分片外，每个分片的数据长度通常需要是 8 字节的整数倍，以便使用 Fragment Offset 表示下一个分片的位置。

### 1.3 重组

IP 分片可以经过不同路径并以任意顺序到达。最终目标主机的网络层会根据源 IP、目标 IP、Protocol 和 Identification 等信息，将属于同一个原始 IP 包的分片归入同一个重组队列。

目标主机根据 Fragment Offset 将各分片的数据放到对应位置，并通过 `MF = 0` 的分片确定原始数据的结束位置。当所有位置的数据都已到达后，目标主机重组出完整的 IP 包，再将其交给 TCP、UDP 等上层协议。

```text
到达顺序：分片 3 -> 分片 1 -> 分片 2
重组顺序：分片 1 -> 分片 2 -> 分片 3
```

中间路由器通常不负责重组，重组只在最终目标主机进行。如果某个分片丢失，目标主机无法完成整个 IP 包的重组；重组计时器超时后，已经收到的相关分片也会被丢弃。

### 1.4 IPv6 分片

IPv6 中间路由器不允许对数据包进行分片。路由器发现 IPv6 包超过出口链路 MTU 时，会丢弃该包并返回 ICMPv6 `Packet Too Big` 消息，由发送主机减小后续数据包。

如果确实需要分片，只能由 IPv6 发送主机添加 Fragment 扩展首部并完成分片，最终仍由目标主机负责重组。
