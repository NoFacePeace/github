# 计算机网络

学习计算机网络的核心概念、协议与通信过程，理解数据如何在不同主机与网络之间传输。

## 1. 学习内容

- 网络体系结构：OSI 七层模型、TCP/IP 模型、封装与解封装。
- 数据链路层：以太网、MAC 地址、交换机、VLAN 与 ARP。
- 网络层：IPv4 / IPv6、子网划分、路由、ICMP 与 NAT。
- 传输层：TCP、UDP、连接管理、可靠传输、流量控制与拥塞控制。
- 应用层：DNS、HTTP / HTTPS、DHCP 与常见应用协议。
- 网络安全：TLS、证书、防火墙与 VPN。
- 网络性能：带宽、吞吐量、延迟、丢包与 MTU。
- 网络排查：使用 ping、traceroute、dig、ss、tcpdump 与 Wireshark 分析问题。

## 2. 基础

### 2.1 带宽

带宽用于描述通信通道在单位时间内传输数据的能力。在计算机网络中，带宽通常表示链路的理论最大数据传输速率，单位是 bit/s，常见单位包括 Mbps 和 Gbps。

例如，100 Mbps 表示理论上每秒最多传输 100 兆比特。由于 1 Byte = 8 bit，其理论最大下载速度约为：

```text
100 Mbps / 8 = 12.5 MB/s
```

换算时需要区分比特、字节以及十进制和二进制单位：

- 小写 `b` 表示 bit（比特），大写 `B` 表示 Byte（字节），`1 B = 8 b`。
- `KB`、`MB` 和 `GB` 是十进制单位，相邻单位按 1000 换算。
- `KiB`、`MiB` 和 `GiB` 是二进制单位，相邻单位按 1024 换算。

```text
1 MB = 1000 KB = 1,000,000 B
1 MiB = 1024 KiB = 1,048,576 B
1 MiB ≈ 1.049 MB
```

网络带宽通常使用十进制单位，因此 12.5 MB/s 等于 12,500 KB/s。部分操作系统或软件可能按照二进制计算容量或速度，却仍使用 `KB`、`MB` 等十进制单位名称显示，阅读时需要确认其实际换算方式。

可以把网络比作公路：带宽类似公路的宽度，决定单位时间内最多可以通过多少车辆；延迟表示车辆从起点到终点需要多长时间；吞吐量则表示实际通过的车辆数量。

带宽不等于实际传输速度。实际吞吐量通常低于带宽，并受到以下因素影响：

- 运营商套餐规定的速率上限。
- 光纤、网线和无线信道等传输介质的能力。
- 光猫、路由器、交换机和网卡等设备的端口速率。
- Wi-Fi 信号强度、距离、障碍物和无线干扰。
- 多台设备或多个程序同时使用网络造成的拥塞。
- 目标服务器的处理能力、出口带宽或限速策略。
- 协议开销、丢包和重传。

端到端通信会经过多段链路和多个设备，整体可用带宽通常由其中能力最低的环节限制。例如，千兆宽带连接到只支持百兆的路由器端口时，经过该端口的传输速率最多只能接近 100 Mbps。

## 3. 物理层

### 3.1 带宽的物理限制

物理层负责在传输介质上发送和接收比特。网线、光纤和无线信道都会受到材料、制造规格、传输距离、信号衰减、噪声和干扰等因素影响，因此能够承载的数据传输速率存在上限。

“带宽”在不同语境下有两种常见含义：

- 信号带宽：信号占用的频率范围，单位是 Hz，主要用于通信和信号处理领域。
- 网络带宽：链路理论上每秒能够传输的数据量，单位是 bit/s。

信号带宽会影响信道能够达到的数据传输速率，但两者不是同一个量，不能直接把 Hz 与 bit/s 等同。实际链路速率还取决于编码方式、调制方式、信噪比以及设备支持的网络标准。

因此，线路和设备都会限制网络带宽。即使传输介质能够支持更高速率，如果网卡、交换机端口或路由器只支持较低速率，整条链路仍会受较慢设备限制；反过来，高速设备连接到规格较低或质量不佳的线路时，也无法发挥设备的全部能力。

## 4. 数据链路层

### 4.1 以太网

以太网（Ethernet）是一套用于有线局域网通信的技术和协议标准，主要由 IEEE 802.3 定义。它同时涉及 OSI 模型中的两个层次：

- 物理层（第 1 层）：规定传输介质、接口、信号、编码方式和传输速率等。
- 数据链路层（第 2 层）：规定以太网帧格式、MAC 地址和介质访问方式等。

通常所说的“以太网协议”主要指数据链路层的以太网帧协议，但完整的以太网标准还包括物理层规范。因此，以太网不是单一协议，而是一整套局域网通信标准。

每个直接接入以太网的网络接口都需要实现相应的以太网功能，主要包括：

- 网卡：收发物理信号，封装和解析以太网帧，并使用 MAC 地址识别网络接口。
- 交换机：学习源 MAC 地址，并根据目标 MAC 地址转发以太网帧。
- 路由器的以太网接口：接收和发送以太网帧，并在不同网络之间转发其中的 IP 包。
- 网卡驱动和操作系统：配置网络接口，并参与协议栈处理。

设备不一定都直接实现以太网接口。例如，手机通过 Wi-Fi 接入网络时使用的是 IEEE 802.11 无线局域网技术；同时具有网口和无线功能的路由器，则会分别实现以太网和 Wi-Fi。

#### 4.1.1 封装与路由转发

发送数据时，网络接口会把上层交付的 IP 包作为载荷，添加以太网帧头和帧尾，组成以太网帧，再由物理层将其转换成信号发送。接收数据时执行相反的过程：

```text
发送：IP 包 -> 以太网帧 -> 比特流 / 物理信号
接收：物理信号 / 比特流 -> 以太网帧 -> IP 包
```

路由器收到以太网帧后，会去掉当前链路使用的帧头和帧尾，取出 IP 包，根据目标 IP 地址和路由表选择出口，然后使用出口链路的数据链路层格式重新封装。

以以太网接口为例：

```text
进入路由器：
[源 MAC = 主机 A][目标 MAC = 路由器入口][IP 包]

离开路由器：
[源 MAC = 路由器出口][目标 MAC = 下一跳][IP 包]
```

因此，数据每经过一个路由器，二层帧通常都会被解封装并重新封装，源 MAC 和目标 MAC 也会随当前链路改变。IP 包的源 IP 和目标 IP 通常保持不变，但 TTL 会减 1；如果路由器执行 NAT，IP 地址或 TCP、UDP 端口也可能发生变化。

#### 4.1.2 以太网帧格式

常见的 Ethernet II 帧格式如下：

```text
| 前导码 | 帧开始符 | 目标 MAC | 源 MAC | 类型 |      数据       | FCS  |
| 7 字节 | 1 字节   | 6 字节   | 6 字节 | 2 字节 | 46～1500 字节 | 4 字节 |
```

各字段的作用如下：

- 前导码（Preamble）：帮助接收端进行时钟同步。
- 帧开始符（SFD）：表示以太网帧即将开始。
- 目标 MAC：标识当前链路上的接收接口。
- 源 MAC：标识当前链路上的发送接口。
- 类型（EtherType）：表示载荷使用的上层协议，例如 `0x0800` 表示 IPv4，`0x86DD` 表示 IPv6。
- 数据：承载 IP 包等上层数据，不足 46 字节时需要填充。
- FCS：4 字节的帧校验序列，使用 CRC 检测传输过程中是否出现比特错误。

通常计算以太网帧长度时，不包含前导码和帧开始符。因此，不带 VLAN 标签的普通以太网帧长度为 64～1518 字节：

```text
帧头 14 字节 + 数据 46～1500 字节 + FCS 4 字节
```

其中，14 字节帧头由 6 字节目标 MAC、6 字节源 MAC 和 2 字节类型字段组成。携带 IEEE 802.1Q VLAN 标签时，帧中会额外增加 4 字节。

#### 4.1.3 帧间间隔

相邻的两个以太网帧之间存在帧间间隔（Inter-Packet Gap，IPG）。标准以太网规定的最小帧间间隔是 96 比特时间，相当于发送 12 字节所需的时间：

```text
[以太网帧] -> [至少 96 比特时间的空闲间隔] -> [下一个以太网帧]
```

帧间间隔不是以太网帧的一部分，也不是在帧后插入 12 个有效数据字节，而是链路保持空闲的一段时间。链路速率越高，96 比特所需的实际时间越短：

| 链路速率 | 最小帧间隔时间 |
| --- | --- |
| 100 Mbps | 0.96 μs |
| 1 Gbps | 96 ns |
| 10 Gbps | 9.6 ns |

#### 4.1.4 转义与帧边界

转义是指数据内容与协议使用的特殊控制标记相同时，发送端将该内容替换或编码，接收端再将其还原，从而避免把普通数据误认为控制信息。

例如，某协议使用 `0x7E` 作为帧分隔符，当载荷中也出现 `0x7E` 时，就需要对它进行转义。

以太网帧不需要这种字节转义。以太网不依靠某个特殊字节值分隔帧，而是由物理层信号、编码和链路状态等机制确定帧边界。因此，以太网帧的载荷中可以出现任意字节值，不会因为与某个分隔字节相同而产生歧义。

#### 4.1.5 MTU

MTU（Maximum Transmission Unit，最大传输单元）表示数据链路层一次能够承载的上层数据的最大长度。普通以太网的 MTU 通常是 1500 字节，即一个以太网帧最多承载 1500 字节的 IP 包：

```text
[以太网帧头 14 字节][数据最多 1500 字节][FCS 4 字节]
                       <---- MTU ---->
```

MTU 不包含以太网帧头和 FCS，因此普通以太网帧的最大长度通常为：

```text
14 + 1500 + 4 = 1518 字节
```

如果 IP 包超过链路 MTU：

- IPv4 可能由发送端或中间路由器进行分片，但也可以通过设置 DF 标志禁止分片。
- IPv6 中间路由器不对数据包分片，需要发送端根据路径 MTU 调整数据包大小。

MTU 与完整以太网帧的最大长度不是同一个概念。前者只描述帧所能承载的上层数据大小，后者还包括以太网帧头、FCS，以及可能存在的 VLAN 标签。

### 4.2 VLAN

VLAN（Virtual Local Area Network，虚拟局域网）是一种在同一个物理交换网络中划分多个逻辑局域网的二层技术，主要由 IEEE 802.1Q 定义。

例如，可以在同一组交换机上划分两个 VLAN：

```text
VLAN 10：研发部门
VLAN 20：财务部门
```

属于同一 VLAN 的接口处于同一个二层广播域；属于不同 VLAN 的设备即使连接到同一台交换机，默认也不能直接进行二层通信。不同 VLAN 之间需要通过路由器或三层交换机进行三层转发。

VLAN 可以用于：

- 隔离不同部门、业务或安全级别的网络。
- 缩小广播域，减少广播流量的影响范围。
- 在不改变物理布线的情况下灵活划分逻辑网络。
- 让多个 VLAN 共享交换机之间的同一条物理链路。

VLAN 与以太网关系密切，但不是 IEEE 802.3 基础以太网标准本身。基础以太网主要由 IEEE 802.3 定义，VLAN 标签和相关交换规则则由 IEEE 802.1Q 定义，两者都工作在数据链路层。

#### 4.2.1 802.1Q 帧格式

IEEE 802.1Q 会在源 MAC 和原 EtherType 字段之间插入一个 4 字节的 VLAN 标签：

```text
普通 Ethernet II 帧：
| 目标 MAC | 源 MAC | EtherType |     数据      | FCS    |
| 6 字节   | 6 字节 | 2 字节    | 46～1500 字节 | 4 字节 |

带 802.1Q 标签的帧：
| 目标 MAC | 源 MAC | TPID   | TCI    | EtherType |     数据      | FCS    |
| 6 字节   | 6 字节 | 2 字节 | 2 字节 | 2 字节    | 46～1500 字节 | 4 字节 |
```

因此，普通 Ethernet II 帧头为 14 字节，带一个 802.1Q 标签的帧头为 18 字节：

```text
普通帧头：
目标 MAC 6 + 源 MAC 6 + EtherType 2 = 14 字节

带 VLAN 标签的帧头：
目标 MAC 6 + 源 MAC 6 + VLAN 标签 4 + EtherType 2 = 18 字节
```

在普通 1500 字节 MTU 不变的情况下，带 VLAN 标签的以太网帧最大长度通常从 1518 字节增加到 1522 字节。VLAN 标签增加的是二层头部开销，不会占用 IP 包的 1500 字节 MTU。

#### 4.2.2 VLAN 标签字段

4 字节 VLAN 标签由 TPID 和 TCI 两部分组成：

```text
| TPID：16 bit | PCP：3 bit | DEI：1 bit | VID：12 bit |
|<-- 2 字节 -->|<------------- TCI：2 字节 ----------->|
```

- TPID（Tag Protocol Identifier）：标签协议标识，常见值为 `0x8100`，表示这是一个 IEEE 802.1Q VLAN 标签。
- PCP（Priority Code Point）：3 bit 的流量优先级，取值为 `0～7`。
- DEI（Drop Eligible Indicator）：表示发生拥塞时，该帧是否可以被优先丢弃。
- VID（VLAN Identifier）：12 bit 的 VLAN 编号。取值 `0` 和 `4095` 有特殊用途，通常可配置的 VLAN ID 为 `1～4094`。

接收带标签帧的交换机可以读取 VID，并只在属于相应 VLAN 的端口之间转发该帧。

#### 4.2.3 Access 与 Trunk

交换机端口常见的 VLAN 工作模式包括 Access 和 Trunk：

- Access 端口：通常连接电脑、打印机等终端设备，只属于一个 VLAN。终端收发的普通以太网帧通常不携带 VLAN 标签，由交换机在内部将其关联到该端口所属的 VLAN。
- Trunk 端口：通常用于连接交换机、路由器或虚拟化主机，可以承载多个 VLAN 的流量。交换机通过 802.1Q 标签区分帧所属的 VLAN。

一个典型的转发过程如下：

```text
终端 A
  |
Access 端口（VLAN 10）
  |
交换机添加或关联 VLAN 10 信息
  |
Trunk 链路（帧携带 VLAN 10 标签）
  |
另一台交换机
  |
Access 端口（VLAN 10）
  |
终端 B
```

Access 端口和 Trunk 端口的具体标签处理方式取决于交换机配置。Trunk 链路还可能配置 Native VLAN，其帧是否携带标签需要根据设备实现和配置判断。

## 5. 网络层

### 5.1 NAT

NAT（Network Address Translation，网络地址转换）是在网络边界修改数据包 IP 地址的技术，通常由连接内网和公网的路由器、网关或防火墙实现。

NAT 主要工作在网络层（第 3 层），因为它会修改 IP 地址。常见的 NAPT / PAT 还会修改 TCP 或 UDP 端口，因此也涉及传输层（第 4 层）。

NAT 的主要用途包括：

- 让使用私有 IPv4 地址的多台内网设备共享一个或少量公网 IPv4 地址访问互联网。
- 隐藏内网地址结构，使外部网络不能直接使用私有地址访问内网设备。
- 通过地址或端口映射，将公网流量转发到指定的内网服务。

家庭路由器通常使用 NAPT / PAT，通过不同的公网端口区分内网连接。例如，内网主机发起请求时：

```text
转换前：192.168.1.10:5000 -> 8.8.8.8:443
转换后：203.0.113.5:60001 -> 8.8.8.8:443
```

路由器会记录对应的 NAT 映射：

```text
203.0.113.5:60001 <-> 192.168.1.10:5000
```

服务器的响应到达 `203.0.113.5:60001` 后，路由器查询 NAT 映射表，将目标地址和端口还原为 `192.168.1.10:5000`，再把数据包转发给对应的内网主机。

两台内网设备即使使用相同的源端口，路由器也可以为它们分配不同的公网端口：

| 公网地址与端口 | 内网地址与端口 |
| --- | --- |
| `203.0.113.5:60001` | `192.168.1.10:5000` |
| `203.0.113.5:60002` | `192.168.1.11:5000` |

转换数据包时，NAT 设备通常会执行以下操作：

1. 修改源 IP、目标 IP，或者 TCP / UDP 端口。
2. 维护内外地址和端口之间的映射关系。
3. 重新计算 IP、TCP 或 UDP 校验和。
4. 在连接结束或映射超时后删除相关记录。

常见的 NAT 类型包括：

- SNAT：修改源地址，常用于内网设备访问互联网。
- DNAT：修改目标地址，常用于端口转发，将公网请求转发给内网服务。
- 静态 NAT：一个内网地址固定映射到一个公网地址。
- 动态 NAT：从公网地址池中临时选择地址进行映射。
- NAPT / PAT：同时转换地址和端口，使多台内网设备共享同一个公网地址。

NAT 可以缓解 IPv4 公网地址不足的问题，但它不等同于防火墙，也会增加点对点通信和从公网主动访问内网服务的难度。

## 7. 常用网络设备及其所在层

网络设备通常按照 OSI 七层模型划分。设备所处的层表示它主要依据该层的信息处理和转发数据，但部分设备可能同时工作在多个层。

| 网络设备 | 主要所在层 | 主要作用 |
| --- | --- | --- |
| 中继器（Repeater） | 物理层（第 1 层） | 放大或再生信号，延长网络的传输距离。 |
| 集线器（Hub） | 物理层（第 1 层） | 将收到的信号转发到所有端口，不识别 MAC 地址。 |
| 调制解调器（Modem） | 物理层（第 1 层） | 在数字信号与适合传输介质的信号之间进行转换。 |
| 网桥（Bridge） | 数据链路层（第 2 层） | 根据 MAC 地址连接和隔离局域网网段。 |
| 交换机（Switch） | 数据链路层（第 2 层） | 根据 MAC 地址表转发以太网帧，连接同一局域网中的设备。 |
| 无线接入点（AP） | 数据链路层（第 2 层） | 连接无线终端与有线局域网，转发无线帧和以太网帧。 |
| 网卡（NIC） | 物理层和数据链路层（第 1、2 层） | 连接传输介质，并负责信号收发、帧处理和 MAC 地址识别。 |
| 路由器（Router） | 网络层（第 3 层） | 根据 IP 地址和路由表在不同网络之间转发数据包。 |
| 三层交换机 | 数据链路层和网络层（第 2、3 层） | 同时提供二层交换和基于 IP 的三层路由能力。 |
| 防火墙（Firewall） | 网络层至应用层（第 3～7 层） | 按照 IP、端口、连接状态或应用内容过滤网络流量。 |
| 四层负载均衡器 | 传输层（第 4 层） | 根据 IP、TCP 或 UDP 端口将连接分发到后端服务器。 |
| 七层负载均衡器 | 应用层（第 7 层） | 根据域名、URL、HTTP 请求头等应用层信息分发请求。 |
| 代理服务器（Proxy） | 应用层（第 7 层） | 代表客户端或服务端转发应用层请求，例如 HTTP 代理和反向代理。 |
| 网关（Gateway） | 取决于具体功能 | 连接使用不同协议或体系的网络，可能在网络层、传输层或应用层完成协议转换。 |

判断网络设备所在层时，可以观察它转发数据所依据的信息：

- 依据信号和比特工作，通常属于物理层。
- 依据 MAC 地址和帧工作，通常属于数据链路层。
- 依据 IP 地址和路由表工作，通常属于网络层。
- 依据 TCP、UDP 端口或连接状态工作，通常属于传输层。
- 依据域名、URL 或应用协议内容工作，通常属于应用层。

## 8. 学习方式

- 按分层模型整理协议的职责、报文结构与交互流程。
- 通过抓包观察 DNS 查询、TCP 握手与 HTTP 请求等通信过程。
- 结合实际问题分析网络连通性、名称解析与传输性能。
