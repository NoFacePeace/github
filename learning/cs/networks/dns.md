# DNS

建议按照下面的顺序学习 DNS：

1. **基础概念**：理解 DNS 的作用、域名层级和 FQDN。
2. **域名空间与资源记录**：掌握 `A`、`AAAA`、`CNAME`、`NS`、`MX`、`TXT`、`PTR` 和 `SOA` 等记录。
3. **域名解析过程**：理解客户端、递归 DNS、根名称服务器、顶级域名称服务器和权威名称服务器之间的关系。
4. **DNS 查询类型**：区分正向查询、反向查询、递归查询和迭代查询，了解 UDP 与 TCP 的使用场景。
5. **DNS 服务器**：理解 Stub Resolver、递归 DNS、权威 DNS 和根名称服务器各自的职责。
6. **DNS 缓存**：掌握 TTL、缓存命中、负缓存和记录变更的生效时间。
7. **DNS 安全**：了解 DNSSEC、DoT、DoH，以及 DNS 欺骗、缓存投毒和 DNS 劫持等风险。
8. **常用排查命令**：使用 `dig` 验证记录、指定 DNS 服务器查询，并通过 `+trace` 观察完整解析链路。

学习时可以先掌握“域名如何找到 IP 地址”这条主线，再逐步补充记录类型、服务器角色、缓存和安全机制。

## 1. 基础概念

DNS（Domain Name System，域名系统）负责将便于人类记忆的域名转换为 IP 地址，也可以保存邮件服务器、服务别名等信息。

```text
www.example.com -> 93.184.216.34
```

DNS 使用分层的域名空间。域名从右向左逐级细分：

```text
www.example.com.
└─ 主机名
    └─ 二级域名
        └─ 顶级域名
            └─ 根域
```

域名末尾的 `.` 表示根域，完整域名称为绝对域名或 FQDN（Fully Qualified Domain Name）。

## 2. 域名空间与资源记录

DNS 数据以资源记录（Resource Record，RR）的形式保存。常见记录如下：

| 类型 | 作用 | 示例 |
| --- | --- | --- |
| `A` | 将域名映射到 IPv4 地址 | `example.com -> 192.0.2.1` |
| `AAAA` | 将域名映射到 IPv6 地址 | `example.com -> 2001:db8::1` |
| `CNAME` | 设置域名别名 | `www.example.com -> example.com` |
| `NS` | 指定域的权威名称服务器 | `example.com -> ns1.example.net` |
| `MX` | 指定邮件交换服务器 | `example.com -> mail.example.com` |
| `TXT` | 保存文本信息，常用于验证与邮件安全 | SPF、域名所有权验证 |
| `PTR` | 将 IP 地址反向映射到域名 | `192.0.2.1 -> example.com` |
| `SOA` | 保存区域的权威信息与计时参数 | 主名称服务器、序列号、刷新时间 |

`CNAME` 是别名记录，查询别名时通常还需要继续查询其目标记录。根域名不能同时作为其他记录的 `CNAME`，因为它还需要保存 `NS`、`SOA` 等记录。

根区域和顶级域区域也有自己的 DNS 记录。根区域保存 `.com`、`.org`、`.cn` 等顶级域的 `NS` 委派信息；顶级域区域则保存 `example.com` 等下一级域的 `NS`、`DS` 和必要的胶水记录。具体的 `www.example.com` 地址记录通常保存在 `example.com` 的权威 DNS 中。

## 3. 域名解析过程

以访问 `www.example.com` 为例，客户端通常按以下步骤完成解析：

1. 应用向操作系统发起域名解析请求。
2. 操作系统先检查本地缓存和 `hosts` 文件。
3. 若本地没有结果，客户端向配置的递归 DNS 服务器发送查询。
4. 递归服务器检查自身缓存；命中时直接返回，未命中时向自己已知的上一级或权威名称服务器查询。
5. 如果没有可用的委派信息，递归服务器从根名称服务器开始查询。
6. 根服务器返回 `.com` 顶级域名称服务器的信息，`.com` 服务器再返回 `example.com` 的权威名称服务器信息。
7. 权威名称服务器返回 `www.example.com` 的最终记录。
8. 递归服务器缓存结果，并将 IP 地址返回给客户端。

缓存未命中且没有可用委派信息时，典型链路如下：

```text
客户端
  -> 递归 DNS 服务器
      -> 根名称服务器
          -> 顶级域名称服务器
              -> 权威名称服务器
      <- www.example.com 的记录
  <- IP 地址
```

## 4. DNS 查询类型

### 4.1 正向查询

正向查询根据域名查询 IP 地址，通常查询 `A` 或 `AAAA` 记录。

### 4.2 反向查询

反向查询根据 IP 地址查询域名，IPv4 使用 `in-addr.arpa`，IPv6 使用 `ip6.arpa`，通常查询 `PTR` 记录。例如，查询 `192.0.2.1` 时，DNS 会查询 `1.2.0.192.in-addr.arpa` 的 `PTR` 记录。

反向查询的典型过程如下：

```text
客户端
  -> 本地 DNS 解析器
      -> 递归 DNS
          -> 反向 DNS 权威服务器
      <- PTR 主机名
  <- 查询结果
```

本地解析器和递归 DNS 会先检查缓存。缓存未命中时，递归 DNS 查询反向 DNS 区域的权威服务器，由其返回 `PTR` 记录。并非所有 IP 地址都配置了 PTR 记录，查询不到时可能返回 `NXDOMAIN` 或空结果。

### 4.3 递归查询

递归查询请求 DNS 服务器代替请求方完成后续查询，并返回最终结果或错误。通常由本地 DNS 解析器向递归 DNS 发起。

DNS 查询报文中的 `RD`（Recursion Desired）标志表示客户端是否请求递归服务；服务器可以通过 `RA`（Recursion Available）标志表示自己是否支持递归。

### 4.4 迭代查询

迭代查询中，被询问的服务器只返回自己知道的记录，或返回下一步应查询的名称服务器信息。通常由递归 DNS 向根、顶级域和权威 DNS 发起。

“递归”强调 DNS 服务器是否代替请求方继续完成查询；“迭代”强调查询方根据返回的线索，逐级询问下一台 DNS 服务器。严格来说，任意 DNS 客户端也可以直接发起迭代查询，但日常网络访问中通常由递归 DNS 服务器完成这部分工作。

### 4.5 DNS 传输协议

DNS 通常优先使用 UDP 的 `53` 端口。查询发起方负责选择传输协议；如果 UDP 响应过大，服务器会设置 `TC`（Truncated）标志，发起方收到后再通过 TCP `53` 端口重试。区域传送（如 `AXFR`、`IXFR`）通常由辅助 DNS 主动通过 TCP 向主 DNS 请求。现代 DNS 还可以基于 HTTPS 或 TLS 传输，以减少明文查询暴露。

## 5. DNS 服务器

### 5.1 Stub Resolver

Stub Resolver 通常位于操作系统或应用中，负责检查本地缓存和 `hosts` 文件，并向上游 DNS 服务器发起查询。它通常不保存完整的 DNS 数据，也不负责从根服务器开始逐级查询。

### 5.2 递归 DNS 服务器

递归 DNS 服务器接收客户端请求，代替客户端查询其他 DNS 服务器，并缓存查询结果。家庭路由器、企业 DNS 和公共 DNS 通常提供递归服务。

### 5.3 权威 DNS 服务器

权威 DNS 服务器保存某个区域的正式记录，并直接回答该区域内域名的查询。域名注册商配置的 `NS` 记录决定了一个域由哪些名称服务器负责。

### 5.4 根名称服务器

根名称服务器不保存所有域名的最终地址，主要负责告知查询方对应顶级域的名称服务器，例如 `.com`、`.org` 或国家和地区顶级域。

## 6. DNS 缓存

DNS 记录中的 TTL（Time To Live）决定递归 DNS 服务器可以缓存该记录多长时间。TTL 较大可以减少查询次数，但记录变更传播得更慢；TTL 较小有利于快速切换，但会增加 DNS 查询压力。

递归 DNS 也会缓存顶级域或权威名称服务器的委派信息。因此，即使目标记录未命中，后续迭代查询也不一定需要从根名称服务器开始。

常见缓存位置包括：

- 浏览器缓存；
- 操作系统缓存；
- 本地网络或路由器缓存；
- 递归 DNS 服务器缓存。

修改权威 DNS 记录后，旧记录可能仍存在于各级缓存中。因此，变更不会一定立即对所有客户端生效。

当查询失败时，递归 DNS 服务器也可能短暂缓存否定结果，例如域名不存在或记录不存在，这称为负缓存。

## 7. DNS 安全

### 7.1 DNSSEC

DNSSEC 为 DNS 数据提供数字签名，用于验证响应是否来自正确的 DNS 数据源，以及数据在传输过程中是否被篡改。DNSSEC 主要解决数据真实性和完整性问题，不负责加密查询内容。

### 7.2 加密 DNS

传统 DNS 查询通常以明文传输，网络观察者可能看到查询的域名。常见的加密 DNS 方式包括：

- **DoT（DNS over TLS）**：通过 TLS 连接传输 DNS，通常使用 `853` 端口。
- **DoH（DNS over HTTPS）**：将 DNS 查询封装在 HTTPS 中，通常使用 `443` 端口。

加密 DNS 可以保护客户端到 DNS 服务之间的查询内容，但 DNS 服务提供商仍可能看到查询记录。

### 7.3 常见风险

- **DNS 欺骗**：攻击者伪造 DNS 响应，将域名指向错误地址。
- **缓存投毒**：攻击者向递归服务器注入伪造记录。
- **DNS 劫持**：解析请求被重定向到攻击者控制的 DNS 服务。
- **开放递归**：服务器为任意互联网客户端提供递归服务，可能被用于放大攻击。
- **区域传送泄露**：错误开放 AXFR 等区域传送能力，可能暴露整个域的记录。

防护措施包括启用 DNSSEC、限制递归访问范围、保护区域传送、及时更新 DNS 软件，以及监控异常查询和响应。

## 8. 常用排查命令

```bash
# 查询 A 记录
dig example.com A

# 查询 AAAA 记录
dig example.com AAAA

# 查询邮件服务器
dig example.com MX

# 查询权威名称服务器
dig example.com NS

# 反向查询
dig -x 192.0.2.1

# 指定 DNS 服务器查询
dig @1.1.1.1 example.com

# 查看完整解析链路
dig +trace example.com
```

排查 DNS 问题时，可以依次确认客户端配置、本地缓存、递归 DNS 可用性、权威服务器响应、记录内容和 TTL。`SERVFAIL` 通常表示服务器处理查询时遇到错误，`NXDOMAIN` 表示被查询的域名不存在，二者含义不同。
