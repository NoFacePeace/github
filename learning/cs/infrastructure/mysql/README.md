# MySQL 学习

记录 MySQL 的 SQL 使用、架构设计、数据存储、索引、事务与运维实践，逐步深入底层实现与源码。

## 1. 学习主线

- **官方文档**：[MySQL Reference Manual](https://dev.mysql.com/doc/refman/8.4/en/)。
- **源码入口**：[mysql/mysql-server](https://github.com/mysql/mysql-server/tree/8.4)。

按“基本使用 → 执行流程 → 数据存储 → 索引 → 事务 → MVCC → 锁 → 日志与崩溃恢复 → 性能优化 → 复制与备份 → 源码阅读”的顺序学习。

已熟悉 SQL 的部分可以通过实验快速复习；事务、MVCC 和锁需要结合双会话实验反复验证。

## 2. 学习顺序

### 2.1 SQL 基础与表设计

- 数据库、表、行与列，常用数据类型、NULL、字符集与排序规则。
- 建表与增删改查，连接查询、聚合、子查询及窗口函数。
- 主键、唯一约束、外键，以及范式与适度冗余的取舍。
- **实践**：设计用户、商品、订单与订单明细表，完成订单查询、销售统计和分页查询。

### 2.2 架构与 SQL 执行流程

- 客户端连接、认证、会话与连接池的关系。
- Server 层与存储引擎的职责，解析、优化、执行与存储引擎接口。
- 分别梳理一条 SELECT 和一条 UPDATE 的执行路径，后续逐步补齐索引、锁和日志环节。
- **目标**：能够说明 SQL 从客户端发送到返回结果的主要步骤。

### 2.3 数据存储

- 表空间、段、区、页与记录之间的关系。
- 数据页与行格式，页内记录组织、页目录和溢出页。
- Buffer Pool、脏页与刷盘，理解内存中的修改如何进入磁盘。
- **目标**：能够从“读一行数据”解释到“访问索引页和数据页”。

### 2.4 B+ 树与索引

- B+ 树的查找、插入、页分裂，以及适合范围查询的原因。
- 聚簇索引、二级索引、回表与覆盖索引。
- 联合索引、最左前缀、索引下推，以及排序、范围条件对索引使用的影响。
- 索引选择性、主键设计，以及索引带来的写入和空间成本。
- **实践**：为订单查询设计联合索引，用 `EXPLAIN` 比较访问方式、使用的索引和预估扫描行数。

### 2.5 事务

- 学习事务边界、ACID、提交与回滚，以及隔离级别的并发语义。
- 详细内容与实验见 [MySQL 事务](transaction.md)。

### 2.6 MVCC

- 先理解 undo 保存历史版本的作用，为版本链学习做准备；完整日志机制见 2.8。
- 隐藏字段、undo 版本链、Read View 与可见性判断。
- RC 和 RR 下快照建立时机的差异，以及事务自身修改的可见性。
- 长事务对历史版本保留与清理的影响。
- **目标**：画出版本链和事务执行时序，解释[事务实践](#34-实践)中每次快照读取的结果。

### 2.7 锁与并发控制

- 共享锁、排他锁、意向锁，以及记录锁、间隙锁和 next-key lock。
- 普通 SELECT、锁定读、UPDATE 和 DELETE 的并发行为。
- 索引、查询条件与隔离级别如何影响加锁范围。
- 元数据锁（MDL）、锁等待、死锁检测，以及应用侧事务重试。
- **实践**：复现行锁等待、范围查询阻塞插入和死锁，结合实际执行计划分析加锁原因。

### 2.8 日志与崩溃恢复

- undo log、redo log 与 binlog 的职责和区别，串联事务回滚、历史版本、持久化和复制。
- WAL、检查点、脏页刷盘与崩溃恢复。
- InnoDB 与 binlog 之间的两阶段提交，以及事务提交过程中的日志写入与持久化。
- **目标**：沿一条 UPDATE 梳理数据、锁和日志的变化，解释“主动回滚”和“崩溃恢复”的区别。

### 2.9 查询优化与问题排查

- 阅读执行计划，理解访问方式、连接顺序、估算行数、排序与临时表。
- 统计信息与优化器成本估算，分析“存在索引但未使用”的原因。
- 慢查询日志、Performance Schema 与锁等待信息的使用。
- 深分页、批量写入、隐式类型转换与大事务等典型问题。
- **实践**：针对一条慢 SQL，保留优化前后的执行计划、耗时、扫描行数与数据规模，验证改进效果。

### 2.10 复制、备份与恢复

- 基于 binlog 的复制流程、中继日志、GTID 与复制延迟。
- 基于 binlog 的 [CDC（变更数据捕获）](cdc.md)，以及全量快照与增量同步的衔接。
- 异步复制、半同步复制，以及故障切换和读写分离中的一致性问题。
- 逻辑备份、物理备份，以及使用备份和 binlog 进行时间点恢复的思路。
- **实践**：在本地实验环境搭建复制，观察延迟，并完成一次备份恢复和数据校验。

### 2.11 源码阅读与专题深入

- 先固定与实验环境对应的源码 tag 或 commit，再沿具体 SQL 的调用链阅读；不直接以持续更新的分支作为可复现的源码基线。
- 建议顺序：SQL 执行入口 → 存储引擎接口 → B+ 树查找 → 行读取与 MVCC → 加锁 → 更新与日志 → 提交与恢复。
- 根据问题继续研究 Buffer Pool 管理、刷脏、purge、在线 DDL 和复制执行。
- **产出**：每个专题整理一张调用流程图、一组关键数据结构和一个可复现实验。

## 3. 阶段验收

| 阶段 | 完成后应能回答的问题 |
| --- | --- |
| 基础与架构（2.1–2.3） | 一条 SQL 如何执行？一行数据如何组织和读取？ |
| 索引（2.4） | 为什么选择这个联合索引？是否需要回表？写入成本是什么？ |
| [事务](transaction.md) | 如何划定事务边界？提交与回滚有什么作用？隔离级别规定什么行为？ |
| MVCC 与锁（2.6–2.7） | MVCC 如何决定版本可见性？为何发生锁等待？ |
| 日志与恢复（2.8） | 三种日志各自负责什么？事务回滚与崩溃恢复有何区别？ |
| 优化与运维（2.9–2.10） | 如何用证据定位慢查询？复制延迟如何影响读取？备份能否真正恢复？ |
| 源码（2.11） | 能否把实验现象对应到具体数据结构和调用路径？ |

## 4. 笔记约定

- 默认以 MySQL 8.4 LTS 和 InnoDB 为学习基线；涉及其他版本或存储引擎时，明确注明差异。
- 每篇笔记围绕一个具体问题，按“问题 → 原理 → 实验 → 结论”组织。
- 实验开始时执行 `SELECT VERSION();`，记录完整补丁版本、表结构、索引、隔离级别与相关配置。
- 参考其他版本的资料时，以学习基线对应的文档和实验结果核对语法、配置、默认值与实现差异。
- 并发实验按会话列出 SQL 执行顺序，明确事务开始、提交和回滚的位置。
- 性能结论注明数据量、数据分布和执行计划，避免仅凭单次耗时判断。
- 引用源码时注明版本、文件与函数；区分实现事实、个人理解和实验结论。
