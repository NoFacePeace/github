# 存储模型

块存储、文件存储和对象存储是三种常见的存储访问模型，不是云存储专属概念。它们既可以部署在本地，也可以由云服务商以存储服务的形式提供。

## 1. 块存储

块存储将数据划分为固定大小的数据块，并向上层提供类似磁盘的块设备。操作系统通常需要在块设备之上创建文件系统后，才能以文件和目录的方式使用它。

- **访问单位**：数据块。
- **使用方式**：格式化后挂载，或由数据库直接管理。
- **常见场景**：服务器系统盘、数据库磁盘、虚拟机云硬盘。
- **本地实现**：HDD、SSD、SAN LUN。
- **云端实现**：云硬盘、弹性块存储。

块存储通常具有较低的访问延迟和较好的随机读写能力，但文件组织、目录管理和权限控制通常由上层文件系统负责。

## 2. 文件存储

文件存储以文件和目录为基本组织形式，通过文件系统提供创建、读取、修改和删除等操作。

- **访问单位**：文件和目录。
- **使用方式**：通过本地文件系统或网络文件协议访问。
- **常见场景**：共享目录、用户家目录、团队文件、容器共享卷。
- **本地实现**：本地文件服务器、NAS。
- **常见协议**：NFS、SMB。

文件存储便于多个客户端共享数据，但性能和扩展能力通常受目录结构、元数据服务和网络访问路径影响。

## 3. 对象存储

对象存储将数据作为对象保存。每个对象通常包含数据本身、唯一标识符和元数据，通过接口访问，而不是通过操作系统挂载的目录访问。

- **访问单位**：对象。
- **使用方式**：通过 HTTP API、SDK 或命令行工具访问。
- **常见场景**：图片、视频、日志、备份、安装包和数据归档。
- **本地实现**：MinIO、Ceph Object Gateway。
- **云端实现**：云对象存储服务。

对象存储通常具有较强的水平扩展能力和较高的持久性，适合保存海量非结构化数据，但不适合直接替代低延迟的本地磁盘。

## 4. 三者对比

| 类型 | 抽象形式 | 典型访问方式 | 适合场景 | 是否云专属 |
| --- | --- | --- | --- | --- |
| 块存储 | 磁盘或块设备 | 读写数据块 | 操作系统、数据库、虚拟机磁盘 | 否 |
| 文件存储 | 文件和目录 | 文件系统、NFS、SMB | 共享文件、用户目录、容器卷 | 否 |
| 对象存储 | 对象和元数据 | HTTP API、SDK | 图片、备份、日志、归档 | 否 |

## 5. 与操作系统的关系

这三类存储和操作系统的关系不同：

- 块存储通常由操作系统识别为块设备，再由文件系统进行管理。
- 文件存储直接向应用提供文件和目录语义，操作系统通过本地文件系统或网络文件系统访问。
- 对象存储通常绕过传统文件系统，由应用通过 API 或 SDK 访问。

因此，操作系统学习中可以关注块设备、文件系统、VFS、挂载和 NFS；基础设施学习中则可以关注 NAS、SAN、对象存储系统及其扩展、复制和一致性机制。
