# 内存管理

## 1. 概念边界

内存管理负责处理程序运行期间内存的申请、使用、释放，以及对象生命周期管理。

从职责上看，内存管理可以分为两层：

- **操作系统内存管理**：虚拟内存、分页、页表、进程地址空间和物理内存分配。
- **语言运行时内存管理**：堆分配、对象生命周期、内存分配器和垃圾回收。

本文主要记录语言运行时相关内容，并关注它与操作系统内存管理之间的联系。

## 2. 手动内存管理

手动内存管理要求程序员显式控制内存生命周期。

- `malloc`：申请一块堆内存。
- `free`：释放此前申请的堆内存。
- 使用已释放内存：产生 use-after-free。
- 重复释放同一块内存：产生 double free。
- 忘记释放不再使用的内存：产生内存泄漏。

手动管理通常具有较高的控制力，但需要程序员严格维护所有权和生命周期。

### 2.1 C 库内存管理接口

`malloc`、`free` 等接口由 C 库提供，不是操作系统系统调用。C 库内部可能通过 `brk`、`mmap` 等机制向操作系统申请和归还内存。

| 接口 | 函数原型 | 参数说明 | 头文件 | 作用 | 标准 |
| --- | --- | --- | --- | --- | --- |
| `malloc` | `void *malloc(size_t size)` | `size`：申请的字节数 | `<stdlib.h>` | 申请一块未初始化的连续内存 | ISO C |
| `calloc` | `void *calloc(size_t nmemb, size_t size)` | `nmemb`：元素数量；`size`：每个元素的字节数 | `<stdlib.h>` | 申请内存，并将内容初始化为 0 | ISO C |
| `realloc` | `void *realloc(void *ptr, size_t size)` | `ptr`：原内存地址；`size`：调整后的字节数 | `<stdlib.h>` | 调整已分配内存的大小，必要时移动数据 | ISO C |
| `free` | `void free(void *ptr)` | `ptr`：待释放的内存地址，可以为 `NULL` | `<stdlib.h>` | 释放由分配接口申请的内存 | ISO C |
| `aligned_alloc` | `void *aligned_alloc(size_t alignment, size_t size)` | `alignment`：对齐字节数；`size`：申请的字节数，必须是 `alignment` 的整数倍 | `<stdlib.h>` | 按指定对齐边界申请内存 | C11 |
| `posix_memalign` | `int posix_memalign(void **memptr, size_t alignment, size_t size)` | `memptr`：用于写入内存地址的指针；`alignment`：对齐字节数；`size`：申请的字节数 | `<stdlib.h>` | 按指定对齐边界申请内存 | POSIX |
| `memcpy` | `void *memcpy(void *dest, const void *src, size_t n)` | `dest`：目标地址；`src`：源地址；`n`：复制的字节数，区域不可重叠 | `<string.h>` | 将一段内存复制到另一段内存 | ISO C |
| `memmove` | `void *memmove(void *dest, const void *src, size_t n)` | `dest`：目标地址；`src`：源地址；`n`：移动的字节数，区域可以重叠 | `<string.h>` | 移动内存，支持源区域和目标区域重叠 | ISO C |
| `memset` | `void *memset(void *s, int c, size_t n)` | `s`：目标地址；`c`：要填充的字节值；`n`：填充的字节数 | `<string.h>` | 按字节填充一段内存 | ISO C |
| `memcmp` | `int memcmp(const void *s1, const void *s2, size_t n)` | `s1`、`s2`：待比较的内存地址；`n`：比较的字节数 | `<string.h>` | 比较两段内存的内容 | ISO C |

其中，`malloc`、`calloc`、`realloc` 和 `free` 负责内存生命周期；`memcpy`、`memmove`、`memset` 和 `memcmp` 负责已分配内存中的数据操作。

## 3. 自动内存管理

自动内存管理由语言运行时负责识别和回收不再使用的对象。

### 3.1 垃圾回收

Garbage Collection（GC）通过分析对象之间的引用关系，识别无法继续访问的对象，并回收其占用的内存。

GC 通常从一组根对象（GC Roots）开始，例如栈上的局部变量、全局变量、寄存器中的引用和运行时对象，然后沿着引用关系遍历对象图。无法从根对象到达的对象，就被认为是不可达对象，可以回收。

#### 3.1.1 GC Roots

GC Roots（垃圾回收根）是 GC 遍历对象图时的起点。GC 会从这些根出发，沿着对象之间的引用关系寻找所有可达对象。

常见的 GC Roots 包括：

- 当前线程栈中的局部变量
- 全局变量和静态变量
- CPU 寄存器中的对象引用
- 正在运行的线程对象
- 运行时内部保存的引用
- JNI、反射或 native 代码持有的引用

例如：

```text
GC Roots → A → B
         └→ C
```

A、B、C 都可以从 GC Roots 访问到，因此属于存活对象。无法从 GC Roots 到达的对象，才可能被 GC 回收。

#### 3.1.2 引用计数

每个对象维护一个引用计数，记录当前指向它的引用数量：

1. 新增一个引用时，计数加一。
2. 删除一个引用时，计数减一。
3. 计数变为零时，立即释放对象。

优点：

- 回收时机确定，通常可以立即释放。
- 不需要长时间暂停程序。
- 实现相对直观。

缺点：

- 无法处理循环引用。例如对象 A 引用 B，同时 B 引用 A，但外部已经无法访问它们。
- 每次引用变化都需要维护计数，可能带来额外开销。
- 多线程环境下需要处理计数更新的同步问题。

#### 3.1.3 标记-清除

标记-清除是典型的追踪式 GC，分为两个阶段：

1. **标记**：从 GC Roots 开始遍历对象，将所有可达对象标记出来。
2. **清除**：遍历堆，回收没有被标记的对象。

它可以处理循环引用，但清除后可能留下许多不连续的空闲区，形成内存碎片。此外，标记和清除阶段通常需要暂停应用程序，或者使用更复杂的并发算法降低暂停时间。

#### 3.1.4 标记-整理

标记-整理先执行标记，然后将存活对象移动到连续区域，最后一次性回收剩余空间。

优点：

- 能够消除内存碎片。
- 后续分配可以使用连续空间，分配速度较快。

缺点：

- 移动对象需要更新所有相关引用。
- 整理过程可能消耗较多 CPU，并造成较长暂停。

#### 3.1.5 复制回收

复制回收将堆划分为两个区域，每次只使用其中一个区域：

1. 从当前区域中找出存活对象。
2. 将存活对象复制到另一个区域。
3. 复制完成后，直接回收整个旧区域。

复制回收不需要逐个清理死对象，也可以自然地消除碎片。但它需要预留额外空间，并且复制大量存活对象时成本较高。因此，它通常适合对象存活率较低的区域。

#### 3.1.6 分代回收

分代回收基于一个经验：**大多数对象的生命周期很短，少数对象会长期存活**。因此，GC 会将对象按存活时间划分为不同代：

- **新生代**：新创建的对象，回收频率较高，通常使用复制算法。
- **老年代**：经过多次回收仍然存活的对象，回收频率较低，通常使用标记-清除或标记-整理。

分代回收可以减少每次扫描的对象数量，但需要维护对象晋升、跨代引用和写屏障等机制。

#### 3.1.7 增量式 GC

增量式 GC 将一次完整回收拆成多个较小的阶段，在应用程序运行过程中逐步完成。

优点是可以缩短单次暂停时间，适合对延迟敏感的程序。缺点是实现复杂，需要使用写屏障记录应用程序在回收期间对对象图的修改。

#### 3.1.8 并发 GC

并发 GC 允许应用程序线程和 GC 线程同时运行，减少因 GC 导致的停顿。

并发执行会带来对象图变化问题：应用程序可能在 GC 扫描期间新增、删除或修改引用。因此，运行时通常需要使用写屏障、读屏障或重新扫描等机制保证正确性。

并发 GC 的目标通常是降低延迟，但它会消耗额外的 CPU 和内存，并增加运行时实现的复杂度。

#### 3.1.9 常见组合

实际的 GC 往往不是只使用一种算法，而是组合多种策略，例如：

- 新生代使用复制回收，老年代使用标记-整理。
- 使用分代回收减少扫描范围。
- 使用增量或并发标记缩短暂停时间。
- 在内存碎片严重时执行整理或压缩。

### 3.2 GC 的代价

GC 降低了手动释放内存的负担，但会引入额外开销：

- 回收过程需要消耗 CPU。
- 某些回收阶段可能暂停应用程序。
- 运行时需要维护对象、引用和堆的额外信息。
- GC 策略会影响延迟、吞吐量和内存占用。

## 4. 堆与内存分配器

堆是动态分配内存的主要区域。语言运行时或 C 库通常通过内存分配器管理堆空间。

分配器需要处理：

- 内存块的申请与释放
- 空闲内存复用
- 内存对齐
- 内存碎片
- 并发访问
- 向操作系统申请和归还大块内存

`malloc/free` 通常属于 C 库提供的接口，而不是操作系统直接提供的系统调用。C 库内部可能通过 `brk`、`mmap` 等机制向操作系统申请内存。

## 5. 与操作系统的关系

语言运行时负责管理对象和堆内存，操作系统负责提供进程可用的地址空间和底层内存机制。

典型关系如下：

```text
程序
  ↓
语言运行时 / C 库分配器
  ↓
系统调用（如 mmap、brk）
  ↓
操作系统虚拟内存管理
  ↓
物理内存
```

因此，GC、`malloc/free` 和堆分配器主要归入语言运行时内存管理；虚拟内存、页表和地址转换则归入操作系统内存管理。

## 6. 常见问题

### 6.1 GC 和 `free` 的区别

- `free` 由程序员显式调用。
- GC 由运行时自动执行。
- `free` 直接释放指定内存块。
- GC 根据对象是否仍然可达来决定是否回收。

### 6.2 内存泄漏

手动内存管理中，内存泄漏通常是因为程序丢失了仍然占用内存的指针。

使用 GC 的语言也可能发生逻辑上的内存泄漏，例如对象仍被全局变量、缓存或集合引用，导致 GC 无法回收。
