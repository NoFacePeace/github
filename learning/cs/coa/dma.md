# DMA

DMA（Direct Memory Access，直接内存访问）是一种让 I/O 设备在 DMA 引擎的控制下直接读写主机内存的机制。

这里的“直接”不是说设备完全绕过 CPU、总线或操作系统，而是说：

> 大量数据的实际搬运不需要 CPU 执行一条条加载、存储指令。

CPU 仍然需要配置传输、分配和管理缓冲区、处理完成事件，并把数据交给文件系统或网络协议栈。

## 1. DMA 解决什么问题

如果没有 DMA，设备传输一批数据时，可以由 CPU 反复执行类似下面的操作：

```text
读取设备寄存器
    ↓
CPU 取得一小段数据
    ↓
CPU 将数据写入内存
    ↓
重复上述过程，直到传输完成
```

这种方式会占用大量 CPU 执行时间。使用 DMA 后，流程变为：

```text
CPU 配置 DMA
    ↓
设备或 DMA 控制器自动在设备和内存之间传输数据
    ↓
设备报告传输完成
    ↓
CPU 处理传输结果
```

DMA 的收益主要是减少 CPU 搬运数据的工作量，但 DMA 本身也需要总线带宽、内存带宽和设备控制逻辑。对于很小的数据，配置 DMA 的开销可能不值得。

## 2. DMA 涉及哪些部件

### 2.1 CPU 和设备驱动

CPU 通常通过设备驱动完成以下工作：

- 分配或准备 DMA 缓冲区；
- 将缓冲区映射为设备可以访问的 DMA 地址；
- 设置源地址、目标地址、传输长度和控制选项；
- 准备 DMA 描述符并通知设备开始工作；
- 在传输完成后检查状态、回收缓冲区并处理数据。

CPU 负责“安排和管理”传输，不负责执行每一次数据读写。

### 2.2 设备和 DMA 引擎

DMA 引擎可以位于不同位置：

- 独立的 DMA 控制器；
- 网卡、磁盘控制器、显卡等设备内部；
- SoC 中集成在外设控制器附近的 DMA 模块。

例如，普通网卡通常在网卡控制器内部集成 DMA 引擎：

```text
网线
  ↓
网卡控制器中的 DMA 引擎
  ↓
主机内存
```

### 2.3 内存和互连

设备通过内存总线或 I/O 互连访问主机内存。服务器网卡通常通过 PCIe 连接到主机，因此网卡 DMA 访问内存时会经过 PCIe 和主机的 I/O 内存控制路径。

DMA 不等于设备和内存之间有一根独立的专用数据线。设备通常仍然需要通过共享的总线或互连竞争带宽。

### 2.4 IOMMU

IOMMU（I/O Memory Management Unit）可以为设备提供类似 MMU 的地址转换和访问控制能力：

- 将设备使用的 DMA 地址转换为物理内存地址；
- 限制设备只能访问分配给它的内存；
- 支持虚拟机将设备安全地分配给虚拟机；
- 在设备只能访问连续地址时，帮助组织分散的物理页。

因此，驱动使用的 CPU 虚拟地址、CPU 看到的物理地址和设备使用的 DMA 地址可能不是同一个数值。

### 2.5 中断控制器和完成队列

设备完成 DMA 后，通常会更新描述符或完成队列，并通过中断通知 CPU。常见的中断方式包括传统硬件中断、MSI 和 MSI-X。

高性能设备也可能使用轮询、批量完成和中断合并，减少中断次数。相关的 CPU 中断处理流程见[中断](interrupt.md)。

## 3. 一次 DMA 传输的基本流程

一次典型的 DMA 传输可以拆成以下步骤：

### 3.1 准备缓冲区

驱动为设备准备一块或多块内存，作为 DMA 缓冲区。例如：

```text
内核内存中的缓冲区
┌──────────────────────────────┐
│ 可供设备读写的数据空间        │
└──────────────────────────────┘
```

这块内存可能来自连续的物理页，也可能由多个分散的物理页组成。

### 3.2 建立 DMA 地址映射

设备不能直接使用普通的用户态虚拟地址。驱动需要通过操作系统提供的 DMA API 建立映射，得到设备可以使用的 DMA 地址。

概念上可以表示为：

```text
CPU 虚拟地址 ──页表──> 物理地址
                         ↑
设备 DMA 地址 ──IOMMU───┘
```

具体是否有 IOMMU、DMA 地址是否等于物理地址，取决于平台和配置。驱动不能仅凭数值相等来假设两者一定相同。

### 3.3 填写 DMA 描述符

设备通常不是只接收一个“起始地址加长度”的命令，而是使用一个或多个 DMA 描述符（descriptor）：

```text
描述符：
┌──────────────┬──────────────┬──────────┬──────────┐
│ DMA 地址      │ 数据长度      │ 控制信息  │ 状态      │
└──────────────┴──────────────┴──────────┴──────────┘
```

描述符可能还包含首尾标志、校验和、分段信息、所有权标志和下一个描述符的位置。

多个描述符通常组成环形队列（ring）。驱动和设备分别维护生产者、消费者位置，用于持续提交和回收多个 I/O 请求。

### 3.4 通知设备开始传输

CPU 将描述符地址或队列位置写入设备寄存器，然后通过写寄存器、doorbell 等方式通知设备：

```text
CPU 写设备寄存器
    ↓
设备读取 DMA 描述符
    ↓
设备执行传输
```

### 3.5 设备执行 DMA

设备根据描述符发起内存读写请求：

- 接收数据时：设备把数据写入内存；
- 发送数据时：设备从内存读取数据；
- 某些 DMA 控制器也支持内存到内存的复制。

这段数据传输由设备中的 DMA 引擎完成，CPU 不需要逐字节参与。

### 3.6 报告完成并回收

完成后，设备会更新描述符状态或写入完成队列，然后通过中断或其他完成通知机制让驱动处理：

```text
设备更新完成状态
    ↓
触发中断，或等待 CPU 轮询发现
    ↓
驱动检查结果
    ↓
处理数据并回收、复用 DMA 缓冲区
```

## 4. 数据到底从哪里搬到哪里

### 4.1 设备到内存

这是网卡收包、磁盘读和声卡采集等场景：

```text
设备内部数据
    ↓ DMA 写入
内核管理的内存缓冲区
```

例如网卡收到一个以太网帧后，网卡通过 DMA 将帧数据写入主机内存。

### 4.2 内存到设备

这是网卡发包、磁盘写和声卡播放等场景：

```text
内核或应用准备的数据
    ↓ DMA 读取
设备内部缓存或发送队列
```

例如网卡发送数据时，网卡 DMA 引擎从主机内存读取待发送的数据，再通过网口发出。

### 4.3 内存到内存

部分 DMA 控制器支持内存到内存复制：

```text
内存缓冲区 A
    ↓ DMA
内存缓冲区 B
```

不过，是否使用内存到内存 DMA 要看平台和工作负载。CPU 使用高效的批量复制指令时，小块复制可能更快。

## 5. DMA 描述符和环形队列

### 5.1 为什么需要描述符

描述符把“数据在哪里、长度是多少、当前由谁处理”等信息交给设备。这样驱动可以提前准备多个请求，设备也可以连续处理它们，而不必每传输一小块数据就等待 CPU 配置一次。

### 5.2 环形队列

以网卡接收队列为例，驱动可以预先放置一批空闲缓冲区：

```text
RX Ring
┌────┬────┬────┬────┬────┬────┐
│  0 │  1 │  2 │  3 │  4 │  5 │ ...
└────┴────┴────┴────┴────┴────┘
  ↑                          ↑
设备处理位置              驱动回收位置
```

网卡收到数据后，选择一个可用描述符，把数据 DMA 到对应缓冲区，并把描述符标记为完成。驱动发现完成后，把数据交给网络协议栈，再补充新的空闲缓冲区。

真实设备通常还会区分设备拥有的描述符和驱动拥有的描述符，避免双方同时修改同一个描述符。

## 6. 网卡接收数据的完整路径

网络编程中，网卡收包可以简化为：

```text
网线
  ↓
网卡接收数据
  ↓
网卡 DMA 写入内核内存
  ↓
网卡驱动处理 RX 描述符
  ↓
IP/TCP/UDP 协议栈
  ↓
对应 socket 的内核接收队列
  ↓ recv() / read()
用户空间缓冲区
```

### 6.1 网卡 DMA 到哪里

网卡 DMA 通常写入驱动预先准备的内核内存。驱动通过 RX 描述符告诉网卡：

```text
这块缓冲区对应的 DMA 地址是 X，最多可以写入 N 字节。
```

网卡收到数据后，将数据写到这块内存，并更新描述符的长度和完成状态。

### 6.2 谁把数据交给 socket

不是用户程序直接从网卡读取数据，而是 CPU 执行内核中的以下代码路径：

1. 网卡驱动发现 DMA 完成；
2. 驱动取得数据包对应的内核缓冲区；
3. 网络协议栈处理以太网头、IP 头和 TCP/UDP 头；
4. 根据目的地址和端口找到对应 socket；
5. 将数据包挂到 socket 的接收队列，并更新缓存占用；
6. 唤醒等待数据的进程。

### 6.3 socket 缓冲区是什么

socket 有接收缓存和发送缓存，例如可以通过 `SO_RCVBUF` 和 `SO_SNDBUF` 查看或调整相关参数。

但 socket 缓冲区通常是内核管理的**队列、容量限制和数据包引用**，不一定是一块独立、连续的数据内存。底层数据可能仍然存放在网卡 DMA 使用的内存页或由内核重新组织的数据结构中。

因此下面两句话都需要准确理解：

- socket 缓冲区属于内核空间；
- socket 缓冲区不一定意味着数据已经被复制出一份全新的内存。

### 6.4 `read` 或 `recv` 时是否还会复制

普通 socket 编程中，应用提供的接收缓冲区位于用户空间。调用 `read` 或 `recv` 时，内核通常执行一次从内核空间到用户空间的复制：

```text
网卡 --DMA--> 内核接收内存
                 ↓
          socket 接收队列
                 ↓ recv/read
          用户空间缓冲区
```

这次复制通常由 CPU 执行，不是 DMA。`mmap`、AF_XDP、DPDK、RDMA 以及某些 io_uring 使用方式可以减少或绕过部分复制，但它们需要特定的内存管理和编程模型，不能代表普通 socket 的默认行为。

## 7. 网卡发送数据的完整路径

发送路径大致与接收相反：

```text
用户空间缓冲区
  ↓ send() / write()
内核 socket 发送队列
  ↓
网卡 TX 描述符
  ↓
网卡 DMA 从内存读取
  ↓
网卡发送队列
  ↓
网线
```

发送时，驱动通常将待发送数据的 DMA 地址和长度写入 TX 描述符。网卡通过 DMA 读取这些数据，发送完成后更新描述符状态并通知驱动回收。

应用调用 `send()` 返回，并不一定意味着数据已经到达对端。它通常只表示数据已经被内核接受，后续还可能停留在 socket 缓存、网卡队列或网络链路中。

## 8. DMA 完成后如何通知 CPU

### 8.1 中断

最常见的机制是设备触发硬件中断：

```text
DMA 完成
  ↓
设备更新描述符或完成队列
  ↓
设备触发中断
  ↓
CPU 进入驱动的中断处理路径
  ↓
驱动处理完成的数据
```

网卡通常使用 MSI-X 为不同的接收队列分配不同的中断向量，便于将队列和 CPU 核心绑定。

### 8.2 中断合并

如果每个小数据包都触发一次中断，中断开销可能很高。设备可以在满足以下条件之一后再触发中断：

- 累积若干个数据包；
- 经过一段时间；
- 完成队列达到一定数量。

这称为中断合并，通常以增加少量延迟换取更低的 CPU 开销。

### 8.3 轮询和 NAPI

高吞吐场景下，Linux 网卡驱动常使用 NAPI：

1. 收到中断后，驱动暂时减少或关闭该队列的进一步中断；
2. 内核安排 NAPI 轮询；
3. CPU 一次处理一批完成的描述符；
4. 队列清空后再恢复中断。

因此，“DMA 完成后通知 CPU”不一定意味着“每个数据包都对应一个中断”。也可以由中断唤醒处理流程，再由 CPU 批量轮询完成队列。

## 9. 缓存一致性和内存顺序

DMA 设备和 CPU 可能同时访问同一块内存，因此需要处理两个问题。

### 9.1 Cache 一致性

在缓存一致的平台上，硬件通常会维护设备写内存和 CPU Cache 之间的一致性，驱动仍然需要遵守平台和内核规定的 DMA API。

在非一致性平台上，驱动可能需要显式执行同步操作：

- 设备写内存后，CPU 读取前，需要让 CPU 看到最新数据；
- CPU 写内存后，设备读取前，需要将最新数据同步给设备；
- 缓冲区回收和复用时，需要按方向执行相应的同步。

如果忽略这些规则，CPU 可能读到旧缓存，设备也可能读到旧数据。

### 9.2 内存顺序

描述符本身也需要满足可见性和顺序要求。例如，驱动必须先写好 DMA 地址和长度，再把描述符的所有权交给设备：

```text
先写描述符字段
    ↓
内存屏障
    ↓
再通知设备
```

否则设备可能已经看到“描述符可用”，却还没有看到描述符中的完整内容。

## 10. DMA 地址、物理地址和虚拟地址

这三个概念不要混为一谈：

| 地址 | 谁使用 | 含义 |
|---|---|---|
| 虚拟地址 | CPU 和程序 | 进程或内核访问内存时使用的地址 |
| 物理地址 | 内存系统 | 实际内存位置的地址 |
| DMA 地址 | 设备 | 设备发起 DMA 请求时使用的地址 |

在简单的平台上，DMA 地址可能与物理地址相同；启用 IOMMU 或存在地址转换时，DMA 地址可能不同。

用户态指针也不能直接交给设备做 DMA。用户态内存可能被换出、分页或在系统调用返回后继续变化，驱动需要使用操作系统提供的安全映射和固定机制。

## 11. DMA、零拷贝和 CPU 拷贝

DMA 的目标是让设备和内存之间的数据传输不需要 CPU 逐字节搬运，但它不自动等于零拷贝。

普通网络接收中，可能存在以下阶段：

```text
网卡 DMA 写入内核内存
    ↓
内核网络栈处理
    ↓
recv() 将数据复制到用户内存
```

这里至少有一次 DMA 和一次内核到用户空间的 CPU 拷贝。所谓零拷贝，通常是减少其中某一次数据拷贝，或让用户态直接访问由设备填充的内存，但仍然需要处理：

- 内存生命周期；
- 权限和隔离；
- 缓存一致性；
- 数据包边界；
- 缓冲区回收和复用。

## 12. DMA 与中断的关系

DMA 和中断是两个不同的机制：

- **DMA**：解决数据如何在设备和内存之间搬运；
- **中断**：解决设备完成工作后如何让 CPU 及时知道。

它们经常一起使用，但并不是绑定关系：

- 没有 DMA 时，设备也可以通过中断通知 CPU，再由 CPU 搬数据；
- 有 DMA 时，也可以通过轮询完成队列发现传输完成；
- 设备可以先 DMA，再中断；
- 设备也可以批量 DMA 后统一中断。

## 13. DMA 与不同设备的关系

### 13.1 网卡

网卡使用 RX/TX 环形队列和 DMA 描述符持续收发数据。相关硬件组成见[NIC](nic.md)。

### 13.2 存储设备

磁盘控制器或 NVMe 控制器通过 DMA 将读取的数据写入内存，或者从内存读取待写入磁盘的数据：

```text
读取：磁盘 → 控制器 DMA → 内核内存
写入：内核内存 → 控制器 DMA → 磁盘
```

### 13.3 音频和采集设备

声卡、摄像头和 ADC 等设备通常使用 DMA 连续写入或读取环形缓冲区，CPU 按块处理数据。

## 14. 性能和工程权衡

DMA 通常能提高大块 I/O 的效率，但最终性能还受到多个因素影响：

- DMA 描述符和队列管理开销；
- PCIe 或其他互连带宽；
- 内存带宽和 NUMA 位置；
- CPU 处理协议和中断的开销；
- Cache miss 和缓存一致性开销；
- 中断合并带来的额外延迟；
- 缓冲区分散导致的 scatter-gather 处理；
- IOMMU 地址转换和映射开销。

评估 DMA 性能时，需要同时观察吞吐量、延迟、CPU 使用率、队列深度和丢包或重试情况，不能只看单个带宽数字。

## 15. 常见误区

### 15.1 “DMA 就是不经过 CPU”

不准确。DMA 的含义是数据搬运不需要 CPU 逐字节执行，但 CPU 仍然要配置、管理和处理结果。

### 15.2 “DMA 一定由独立 DMA 芯片完成”

不准确。DMA 引擎可以集成在网卡、磁盘控制器、显卡或 SoC 外设内部。

### 15.3 “DMA 一完成就一定产生一次中断”

不准确。设备可以使用中断合并、轮询、NAPI 或完成队列批处理。

### 15.4 “socket 缓冲区一定是另一份数据”

不准确。socket 缓冲区是内核中的队列和资源管理抽象，底层数据可能由 DMA 缓冲区或内核数据页直接支撑，不一定发生一次额外完整复制。

### 15.5 “DMA 直接把数据写到应用的普通指针”

通常不可以。设备使用 DMA 地址，驱动需要确保内存已经固定、映射、具备正确权限，并满足设备的地址和对齐限制。

### 15.6 “DMA 就等于零拷贝”

不准确。DMA 减少的是设备与内存之间由 CPU 完成的数据搬运；应用和内核之间仍可能存在复制。

## 16. 总结

可以用下面这条主线理解 DMA：

```text
CPU/驱动准备缓冲区和描述符
    ↓
设备取得 DMA 地址
    ↓
DMA 引擎在设备和内存之间搬运数据
    ↓
设备更新描述符或完成队列
    ↓
中断、轮询或 NAPI 让驱动发现完成
    ↓
驱动和操作系统处理数据
    ↓
必要时复制到用户空间
```

最重要的区分是：

- DMA 解决“设备和内存之间怎么搬数据”；
- 中断或轮询解决“CPU 怎么知道搬完了”；
