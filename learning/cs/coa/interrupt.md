# 中断

中断是计算机系统中暂停当前程序执行、转去处理特定事件，处理完成后再恢复执行的机制。它连接了处理器、设备和操作系统。

## 1. 中断的分类

### 1.1 硬件中断

硬件中断由处理器外部的硬件设备触发，例如：

- 键盘输入
- 网卡收到数据
- 磁盘 I/O 完成
- 定时器到期

设备通过中断控制器向处理器发送中断请求。处理器响应后，保存必要的执行现场，转去执行对应的中断处理程序。

### 1.2 软件中断

软件中断由正在执行的程序主动触发，常见方式是执行专门的中断或陷阱指令。它可以用于：

- 请求操作系统提供服务，即系统调用
- 从用户态进入内核态
- 调试程序
- 报告某些需要内核处理的事件

软件中断虽然由软件触发，但处理器仍然按照预先定义的中断入口和权限规则进行响应。

### 1.3 异常

异常通常由处理器执行当前指令时检测到，例如：

- 除零
- 缺页
- 非法指令
- 访问权限错误

异常与硬件中断都可能导致处理器转入内核处理流程，但异常通常与当前正在执行的指令有直接关系，而硬件中断通常来自当前程序之外的设备事件。

| 类型 | 触发来源 | 与当前指令的关系 | 示例 |
|---|---|---|---|
| 硬件中断 | 外部硬件设备 | 通常无直接关系 | 网卡收包、定时器到期 |
| 软件中断 | 程序执行指令 | 由程序主动触发 | 系统调用、调试陷阱 |
| 异常 | 处理器检测到执行错误或特殊条件 | 通常有直接关系 | 缺页、除零、非法指令 |

## 2. 中断处理的基本过程

中断发生后，处理器通常经历以下步骤：

1. 接收中断请求或检测到异常。
2. 保存程序计数器、状态寄存器等必要现场。
3. 根据中断号或异常类型查找处理入口。
4. 切换到相应的特权级和处理程序。
5. 执行中断处理逻辑。
6. 恢复被中断程序的执行现场并继续运行。

具体的寄存器、保存现场范围和入口机制取决于处理器架构。

## 3. 中断与操作系统

计算机组成原理主要关注中断的硬件机制，例如中断请求、响应过程、中断向量和优先级。操作系统则负责组织和管理中断处理，例如：

- 注册设备的中断处理程序
- 分发不同类型的中断
- 处理中断上下文与进程上下文的切换
- 屏蔽或开启部分中断
- 通过时钟中断实现调度和时间管理

### 3.1 软件中断与 Linux softirq

“软件中断”通常指由处理器指令主动触发的中断或陷阱；Linux 的 `softirq` 是内核中的一种延后处理机制。`softirq` 通常不是通过处理器的“软件中断指令”触发，而是内核在硬件中断处理的后半部分安排工作，之后在合适的上下文中执行。

因此，两者名称相近，但不是同一个概念：

| 概念 | 所属层次 | 作用 |
|---|---|---|
| 软件中断指令或陷阱 | 处理器中断机制 | 让程序进入预定义的特权处理入口 |
| Linux `softirq` | 操作系统内核机制 | 延后执行不适合在硬件中断上半部完成的工作 |
