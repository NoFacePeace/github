### 1.4 访问控制模型

#### 1.4.1 RBAC（基于角色的访问控制）

RBAC（Role-Based Access Control）是基于角色的访问控制模型：把权限分配给角色，再把角色分配给用户。

| 概念 | 含义 | 示例 |
| --- | --- | --- |
| 用户 | 谁在操作 | 张三、李四 |
| 角色 | 一组职责对应的身份 | 管理员、编辑、读者 |
| 资源 | 权限作用的对象 | 文章、订单、文件、API |
| 操作 | 对资源执行的动作 | 查看、创建、修改、删除 |
| 权限 | 允许对资源执行的操作 | 查看文章、创建文章、删除文章 |

它们的关系可以表示为：

```text
用户 → 角色 → 权限（对资源执行某种操作）
```

资源可以按类型或具体实例描述：

- **资源类型**：例如“文章”，对应“允许修改文章”这类权限。
- **资源实例**：例如“文章 123”，对应“允许修改指定文章”这类权限。

例如，给张三分配“编辑”角色，该角色拥有创建和修改文章的权限；给李四分配“读者”角色，该角色只拥有查看文章的权限。一个用户可以拥有多个角色。

权限检查流程：

1. 完成身份认证，确定当前用户。
2. 获取用户的角色及其对应权限。
3. 确定当前请求访问的资源及操作，检查权限是否覆盖，不允许则拒绝请求。

通过角色集中管理权限，可以避免逐个为用户配置权限；修改角色的权限后，该角色对应用户的授权结果也会随之调整。若系统缓存权限或将角色写入令牌，需要考虑更新何时生效。

RBAC 负责授权，不负责登录认证。权限检查必须在服务端执行，不能只靠前端隐藏按钮；如果要求“只能修改自己的文章”，通常还需要检查资源归属。
